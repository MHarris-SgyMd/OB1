## Record

The evals' run comments name another brain's network too (SMD-2971)

**What changed.**
- **The run comments** of `evals/build-longdoc-corpus.ts`, `eval-propose-recall.ts`, `eval-reference-windows.ts`, `eval-stated-status.ts` and `eval-transitive-freshness.ts` give `--network <project>_data`, and `<project>_egress` where the run reaches a model. Each says `open-brain_data` (and `open-brain_egress`) is the default project's, as `deploy/tier.sh`'s header does.
- **evals/README.md's two `eval-jev-gate.ts` commands** set `project=open-brain`, marked as the default project, with a note that another brain's is its env file's `COMPOSE_PROJECT_NAME`. They join `"${project}_data"` and `"${project}_egress"`. A `<project>` placeholder in a shell block would run as a redirect.
- **Three of the README's prose records** (eval-thought-kinds, eval-calibration and eval-projection-replay) mark `open-brain_data` and `open-brain_egress` as the default project's, and give `<project>_data` and `<project>_egress` for another brain.

No code or assertion changed.

**Why.** Since SMD-2873 a brain's networks carry its project's name, read from its env file's `COMPOSE_PROJECT_NAME`. `open-brain_data` is only the default project's, so the comments named one brain's network as every brain's. This is the last edge left from SMD-2873 PR 1's review passes. The ticket's other items, for `deploy/tier.sh` and `deploy/canary.sh`, were done by SMD-2875 PR 2, are moot, or are SMD-3033's (the ticket's 2026-10-27 rescope).

**Held.** `git grep -n 'open-brain_data' evals/` finds only lines that mark the name as the default project's.
