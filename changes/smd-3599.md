## Changelog

Every read that returns a thought — `search`, `search_thoughts`, `search_thoughts_keyword`, `list_thoughts` and `fetch` — now says who holds a ticket it names: a `claimed` field with each live work claim's ticket, piece, holder, label and times, a `⚠ Claimed: …` line in the text, and a `[claimed: …]` title prefix on `search` and `fetch`. An answer to "what should we work on next" sees held work without calling `list_claims` (SMD-3599).

## FORK

A result naming a claimed ticket says who holds it — `claimed` beside `moved` on every read of a thought (SMD-3599)

**What changed.**
- **The label.** `core/reads.ts`'s `claimedOf`, beside `movedOf`, reads the live claims on the tickets each result names, in one call to migration 115's `list_work_claims` per page (store `listClaims` now takes the page's tickets as `issues`). None is made when no result names a ticket.
  - A result's tickets: the ones its metadata files it under (a ticket row's `issue`, a note's `ticket`), then the first 50 its text mentions (`keysInOrder`, `MOVED_READ`); `claimedNotRead` counts the rest, and the tickets a read cut at 115's clamp of 1,000 left unread.
  - Each claim: its id, ticket, piece, holder, `ownKey` when the holder is the caller's key, label, and when it was claimed and runs out. The first ten per result, `claimedMore` the rest.
  - Unlike `moved`, a ticket's own row and a superseded thought are labelled: who holds a ticket is a fact about now, not about when the thought was written.
  - Best-effort, as `moved`: a brain before 115, or a read that fails, gives `claimed: null` and the read goes on; a result naming no held ticket `[]`. It never moves a rank.
- **The surfaces.** `search_thoughts`, `search_thoughts_keyword` and `list_thoughts` carry `claimed`, `claimedMore` and `claimedNotRead` on every hit; `search` and `fetch`, the ChatGPT pair, carry them only where a ticket is held, as `moved` is carried, so every other result keeps the shape exactly. The claims read runs beside `movedOf`'s and `supersededAmong`'s, not after them.
- **The words.**
  - Over MCP the three text tools print `⚠ Claimed: SMD-3379 piece "PR 1b-2" by codex since …, until … (claim …, label "…")`, as the claim tools say a claim in the way; the piece and label quoted, cut and on one line, being the holder's words.
  - `search`'s and `fetch`'s titles start `[claimed: SMD-3379 piece "PR 1b-2" by codex, since …]` after any moved prefix — never the label, which every ChatGPT surface hands the model.
  - The MCP structured values keep each claim's id, ticket, holder, `ownKey` and times; the piece and label ride the text, as `WORK_CLAIMED`'s value keeps them out. The REST answer carries every field.
- **The descriptions** of the five tools say what `claimed` is; the OpenAPI document and the rest-client are regenerated; server-portable/README.md has a section beside the moved label's.

**Why.** On 2026-10-29 a "what next" answer recommended SMD-3379 PR 1b-2 while another session held it: the brain's search results named the ticket and gave no sign it was taken (SMD-3596). Claims now work end to end (SMD-3597, 3598, 3602, 3654), but a claim only behind `list_claims` is seen only by an agent that thinks to ask.

**Held.**
- `test-rest-sql.ts` `[11]`, against Postgres, through both doors: a claim on a ticket a thought names is on all five reads — REST fields with the label as 115 cleaned it, `search`'s and `fetch`'s titles with no label and no lease end, the three text tools' line with the label quoted on one line, the MCP values without piece or label; the caller's own claim said so; a released claim, and a lapsed one, on no read; a thought naming 60 tickets reads the first 50, a claim on its 56th unnamed and 10 counted.
- `test-server.ts` `[33c]`: `claimedOf` over a store that answers as told — one read of the page's keys, filed keys first and a hit's first 50; live claims only; the caller's own; ten named and the rest counted; a ticket row labelled; no read for a page naming no ticket; a failed read null; a read cut at 1,000 counted — and the words, titles and structured values.
- `test-store-sql.ts` `[20b]`: `listClaims` with `issues` returns those tickets' claims alone, keys cleaned as 115 cleans them.
- Twenty mutants, each killed (listed in the commit).

**Measured after.** On Postgres with 2,000 ended claims and 40 live ones, a page of 10 hits naming 50 tickets each: `claimedOf`'s read 1.06 ms median, `movedOf`'s 1.90 ms, the two in parallel 2.42 ms — about 0.5 ms on a search that takes around 10 ms (200 runs each, after 20 warm).

**Not taken.**
- **A migration or a new SQL function.** 115's `list_work_claims` already takes a list of tickets and the server role already runs it.
- **The label in a title.** The maintainer chose the field and the text, quoted; a title is what every ChatGPT surface hands the model as the result's own words.
- **The operator GUI's search page.** It shows `moved` from the REST answer; showing `claimed` there belongs with SMD-3601's claims page.

**Follow-ups.** None filed.
