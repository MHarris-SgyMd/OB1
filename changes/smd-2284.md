## Changelog

A REST core, `bun server-portable/api.ts`, answers every operation the MCP tools expose as JSON over the same core: resource routes from the tools' own schemas, an OpenAPI document at `/openapi.json`, `/v1/whoami`, header keys only with 401/403/503 by scope and registry, refusals as their code and declared facts, and a log with no query, key or content; a contract suite holds that the MCP reply is what the REST answer renders to. The MCP server's process root moved to `root.ts` and its keepalive to `sse.ts` first, so both servers build on one copy (SMD-2284).

**PR 2 — the REST app.** `server-portable/api.ts` builds the core under its own
door (`open-brain-api`, thought_audit.origin) over `root.ts`'s readers and
serves `rest/`:
- `rest/routes.ts` — one route per tool in the manifest (`{ [K in ToolName] }`,
  so a tool without one does not compile): its method, its path, its success
  status and the core call. A GET or DELETE reads the query string, a POST or
  PATCH a JSON body; a search's text always rides a body.
- `rest/app.ts` — keys from `x-brain-key`, `x-access-key` or a bearer token,
  never `?key=`; 401 `UNAUTHORIZED`/`REVOKED`, 503 `BUSY` with `Retry-After`,
  403 `FORBIDDEN` naming the scope `UNLOCKS` says the operation needs. The
  input is `z.object(spec).strict()` over the path's fields and the query
  (read as the field's JSON-schema type) or body; a refused one is 400
  `REFUSED_INPUT`, each field and zod's reason, never its value. A refusal is
  `refusalValue` at `REFUSAL_STATUS[code]` (one per code); a fault 500
  `FAILED`. A capture is 201 with `Location` and `embeddingAttached`; a save
  whose vector did not attach is that 201 with `false`, not a refusal (the
  maintainer's call). A scan's handle points at `/v1/jobs`, whose stream is
  kept alive by `sse.ts`. One log line per request: method, route template,
  status, time.
- `rest/openapi.ts` — OpenAPI 3.1 from the specs and the routes, with each
  operation's scope as `x-ob1-scope`.
- check 25 holds `api.ts` and `rest/*.ts` as it holds `index.ts`; the image
  copies `rest/`; CI and `db/ci-parity.sh` run both new suites.
