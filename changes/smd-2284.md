## Changelog

The MCP server's process root — the environment it reads, the store it builds and closes, the agent registry — moves out of `server-portable/index.ts` into `root.ts`, and its event-stream keepalive into `sse.ts`, so the REST core (SMD-2284) builds on the same wiring rather than a copy; no behaviour changes (SMD-2284).

## FORK

The server's process root and its stream keepalive move out of index.ts, ahead of the REST core (SMD-2284)

**What changed.** PR 1 of SMD-2284 is a move, so the REST core's process can
share what the MCP server's is built on.
- `server-portable/root.ts` — `type Env` (the one list of what the
  container's process reads), `initEnv()` and `env()`, the store's wiring
  (`db()` builds it and wires the durable job sink, `closeStore()` closes it
  at a stop), and `agents()`, moved from `index.ts` by script. The job sink
  was wired when `index.ts` was Bun's entry; `root.ts` cannot know its
  importer is the entry, so the entry says so with `serveHere()` before its
  first request.
- `server-portable/sse.ts` — `withSseKeepalive`, its two bounds, the stall
  line and `labelPart`, moved byte for byte; `index.ts` re-exports what the
  suites import from it.
- `scripts/check-fork-consistency.ts` check 14 reads `type Env` from
  `root.ts`. Check 25 holds `index.ts` and `root.ts` each to its own import
  list; the store's wiring is allowed in `root.ts`'s `db()` and
  `closeStore()` alone (the factory in `db()`), and a second `db()` or
  `closeStore()` anywhere is a hit. Its probes run each case as the file it
  describes.
- `test-server.ts` [2] reads `root.ts` for the runtime-neutrality checks and
  the `OB1_TIER` guard's order; [15] imports a fresh `root.ts` and reads its
  store twice, where it re-imported `index.ts` — the module that builds the
  store is now the root, and a fresh `index.ts` shares the cached one.
- `test-e2e-sql.ts` [18] (new): `bun index.ts` run as the entry against
  Postgres reconciles a job row a prior process left running to `lost` on
  its first keyed request. Nothing held the wiring before; the move changed
  how it is switched on.

**Why.** SMD-2284's REST core is a second serving process over the same core.
Its root — the environment, the one store per process, the job sink, the
registry — is the MCP server's, line for line; a copy in the new entry would
be two to keep in step until SMD-2287 retires the MCP half.

**Held.** test-server 396 (six more: the neutrality rows of `root.ts` and
`sse.ts`), test-e2e-sql 414 (two more: [18]); the consistency checker, the
Workers dry-run build (355 KiB gzipped) and `db/ci-parity.sh` pass. Six
mutants, each killed: the entry never calling `serveHere()` ([18]); a store
built in `index.ts`, a second `db()` there, and `root.ts` importing the egress
gate (check 25); `root.ts`'s `db()` building on every call ([15]); `OB1_TIER`
left out of `type Env` (check 14).
