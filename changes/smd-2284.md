## Changelog

A REST core, the stack's `api` service (`bun server-portable/api.ts`), answers every operation the MCP tools expose as JSON over the same core: resource routes from the tools' own schemas, an OpenAPI document at `/openapi.json`, `/v1/whoami`, header keys only with 401/403/503 by scope and registry, refusals as their code and declared facts, and a log with no query, key or content; a contract suite holds that the MCP reply to every success is what the REST answer renders to. It is internal (`api.ob1.internal` on the mesh) unless the operator names `deploy/compose.api-public.yaml`, which routes `/api` to it. Migration 078 records which server started a job, so each server's restart marks only its own jobs lost. The MCP server's process root moved to `root.ts` and its keepalive to `sse.ts` first, so both servers build on one copy. A fourth key scope, `forward` (`bun keygen.ts --scope forward`), grants nothing — every server refuses it as a caller — and is the MCP server's own key for forwarding a client's to the REST core (SMD-2284).

**PR 2 (#296) — the REST app.** `api.ts` builds the core under its own door
(`open-brain-api`, thought_audit.origin) and serves `rest/`:
- `rest/routes.ts` — one route per tool in the manifest (`{ [K in ToolName] }`),
  its method, path, success status and core call; a GET or DELETE reads the
  query, a POST or PATCH a JSON body, a search's text always a body.
  `REFUSAL_STATUS`, one status per refusal code.
- `rest/app.ts` — header keys only, never `?key=`; 401 `UNAUTHORIZED`/`REVOKED`,
  503 `BUSY` with `Retry-After`, 403 `FORBIDDEN` naming the scope. Input held
  to `z.object(spec).strict()`, input sent the other way refused (a GET whose
  headers announce a body too — Bun drops it). A refusal is `refusalValue` at
  its status; a fault 500 `FAILED`, capture's 503 `STORE_UNAVAILABLE` as MCP
  gives it. A capture is 201 with `Location` and `embeddingAttached` (whether
  this capture wrote its vector; a save whose vector did not attach is that 201
  with `false`, the maintainer's call); a capture-only key is told MCP's fields
  alone. `POST /v1/scans` answers a handle on `/v1/jobs`. HEAD answers standing
  and input, never the operation; a wrong method is 405 with `Allow`. One log
  line per request: method, route template, status, time.
- `rest/openapi.ts` — OpenAPI 3.1 from the specs and the routes, every status
  each route answers, each operation's scope as `x-ob1-scope`.

**PR 3 — the service, its route, its jobs.**
- `deploy/compose.yaml` — the `api` service: the server's image, run by the
  server's name (`pull_policy: never`, no build of its own; the release
  overlay pins it to the release's server image), with `command: ["api.ts"]`, the server's environment and
  preflight, no port, on `mesh` as `api.ob1.internal` and on the default
  network (Postgres, the providers) until the network move (SMD-2294), its
  liveness a GET of `/health`. The image's entry is now its command
  (`exec bun "$@"`, `CMD ["index.ts"]`), so one image serves both.
- The proxy reads a directory (`TRAEFIK_PROVIDERS_FILE_DIRECTORY`); its base
  table answers `/api` with a bodyless 404 (`api-off`: `noop@internal`, whose
  418 an errors middleware rewrites — measured on the pin), so a POST there
  never falls to `legacy` and the MCP server. `deploy/compose.api-public.yaml`
  adds `api.yaml` beside it — a router at 36 that strips `/api` and forwards
  to `api.ob1.internal` — and its label, so dropping the file recreates the
  proxy without it. The REST core puts the stripped `X-Forwarded-Prefix` back
  on its `Location` and job links (a plain path prefix only).
- Migration 078 — `jobs.door`, the server that started a job (`open-brain`
  by default, the one serving process before it; `open-brain-api` for the REST
  core); `store.jobSink(door)` stamps it and reconciles only its own, and each
  entry names its door to `serveHere()`, which also builds the store at
  start-up so the reconcile runs then, not at the first keyed request.
  Refused by name without 069. The served OpenAPI document names its base
  (`servers`: `/api` behind the proxy, `/` on the mesh); the keyless
  `/health` 200 is not logged.
