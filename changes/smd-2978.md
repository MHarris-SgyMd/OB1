## Changelog

A command run from `db/`, `server-portable/`, `rest-client/`, `mcp-server/`, `dashboard/`, `evals/`, `jev/`, `deploy/auth/`, `compat/supabase-sql/` or `dashboards/open-brain-dashboard/` no longer has Bun install a missing package at run time. Each directory has a `bunfig.toml` setting `[install] auto = "disable"`, as `extensions/` already did. A script whose packages its installs do not hold now fails at import, naming the package, instead of running on whatever npm serves. `test-live.ts` and `test-search-path.ts` need `bun install` in `server-portable/` as well as `db/`, since both run its preflight (SMD-2978).

## FORK

Bun's auto-install is off in every directory CI runs a script from, and db-live installs server-portable (SMD-2978)

**What changed.**
- **Ten `bunfig.toml` files**, one in each package directory a Fork Checks step runs a script from: `db/`, `server-portable/`, `rest-client/`, `mcp-server/`, `dashboard/`, `evals/`, `jev/`, `deploy/auth/`, `compat/supabase-sql/` and `dashboards/open-brain-dashboard/`. Each sets `[install] auto = "disable"`, as `extensions/bunfig.toml` has since SMD-1991. Bun reads the file in the working directory alone, not a parent's: measured on Bun 1.4.3, with the file in a parent, a script run from the child still fetched `zod`. So each directory needs its own. A script a suite spawns reads the file of the directory it runs from, which is how `server-portable/preflight.ts` is covered when `db/`'s suites run it.
- **db-live installs `server-portable/`**, a step after `db/`'s. test-live's [9], in the long cell, and `test-search-path.ts`, in the rest cell, run `server-portable/preflight.ts` from `server-portable/`, and preflight's imports reach `zod` through `core/plugins.ts`. The job installed `db/` alone, so Bun fetched `zod` at run time. With no egress, a run hung for over 30 minutes (SMD-3392's review pass 2). Every cell installs it, so a section moved between cells needs no change here.
- **Check 44** of `scripts/check-fork-consistency.ts` reads fork-checks.yml with check 34's reader, `scriptRunsIn`. Each directory a step may run a script from, its working-directory or a `cd` it names, that holds a `package.json` must have a `bunfig.toml` whose `[install] auto` is `"disable"`. Its probes pin which files turn it off: another mode, a commented-out line, the key outside `[install]` or under another table, a file that does not parse, and no file all fail. It fails loudly if its reading misses `db/`, `server-portable/` or `extensions/`. The header docblock and the workflow's comment name it among the checks that parse YAML.
- **db/README.md:** the prerequisite for `test-live.ts` names `server-portable/`'s install, and why. `extensions/bunfig.toml`'s comment names check 44.
- **fork-checks.yml, data-layer:** the comment on the REST client's and MCP server's installs said Bun would otherwise fetch their packages; it now says the imports would fail.

**Why.** The ticket: a CI step whose imports cross into a directory its job did not install still passed, with Bun auto-installing the packages from its cache or npm, unpinned. SMD-2287 PR 3b's review found it for `../mcp-server/stack.ts`, and SMD-3392's for preflight in db-live.

**Held.** On two copies of the tree with no `node_modules` (tracked and untracked files copied, the two committed `node_modules` links kept as links), Bun 1.4.3 on macOS:
- **The ticket's first Verify.** With `server-portable/` installed alone, `test-auth.ts` fails at import, `Cannot find package 'openapi-fetch' from '…/rest-client/index.ts'`. With `rest-client/` and `mcp-server/` installed too, it passes 191 of 191, and `test-client.ts` and `test-mcp.ts` pass. `test-rest.ts` (490 of 490), `test-thoughts.ts` and `test-jobs.ts` pass on `server-portable/`'s install alone, as CI runs them before the other two installs.
- **Preflight.** Run from `server-portable/` with no install, `preflight.ts` exits 1 at once: `Cannot find package 'zod' from '…/server-portable/core/plugins.ts'`. With the `bunfig.toml` moved aside, it loads `zod` from the cache and runs to its own report.
- **db-live's rest cell, without the new install:** with `db/` installed alone, `test-search-path.ts` fails 17 of its 35 assertions, its preflight cases. The failure is loud but does not name `zod`, since the suite does not print the child's stderr. With `server-portable/` installed too, it passes 35 of 35, and the long shard, [9] among its sections, passes 280 of 280, each on a throwaway Postgres 16 container.
- **replay-gate and db-schema,** with `db/` installed alone: each suite and self-check their steps run passes, among them `test-schema.ts` (3063), `test-connect.ts` (889), `test-engines.ts` (656) and `test-cli.ts` (461), which spawn every `db/` script.
- **portable-server's later steps,** each after the installs CI performs before it: the GUI's check and `test-oauth.ts`, `test-plugins.ts`, `test-server.ts`, `test-jev.ts`, the thirteen evals self-checks, orchestration's two, the authorization server's five and `extensions/test-auth.ts` all pass.

The typecheck and the consistency checker pass.

**Mutants** on check 44: each of the eleven `bunfig.toml` files removed in turn fails the check, naming that file, and `auto = "fallback"` in one fails it too. So the check reads exactly the eleven directories that have one.

**Not taken.**
- *A `bunfig.toml` at the repo root.* changes/291 turned it down: it would reach every command run from the root, recipes with installs of their own included. The steps CI runs from the root, `deploy/` and `deploy/orchestration/` hold no `package.json`, so nothing there resolves from an install, and the static import graphs of their scripts reach no package.
- *`scripts/`.* CI runs only `bunx tsc` from it. `bunx` ignores the setting: under it, `bunx --bun @commitlint/cli@19.6.1 --version` still fetched and ran.
- *`--no-install` on each step.* It would not reach the scripts a suite spawns, which run as plain `bun <file>` and read their own directory's `bunfig.toml`.
- *The images.* Their Dockerfiles copy named files, never a `bunfig.toml`, and compose already runs the `mcp` and `app` services under `bun --no-install`.
