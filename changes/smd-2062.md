Preflight's `write privileges` row reads `ob1_config` schema-qualified, as its privilege test was, so a role with `public` off its search path no longer takes 27 later rows down as "not checked"; that row and `chunk context` each get their own try/catch, and the `schema` row stops saying to migrate a brain whose `thoughts` table exists but does not resolve for the role (SMD-2062).

## FORK

Preflight reads a table off the role's path in one row, not the block — `write privileges` qualified and bounded, `chunk context` too, and the `schema` row names the path (SMD-2062)

**What changed.** `server-portable/preflight.ts`, three rows of the direct-connection block and one before it:

- **`write privileges`** tested `has_table_privilege('public.ob1_config', 'SELECT')`, then read the extraction key from a bare `ob1_config`. The read is now `public.ob1_config`, as the test was. The row also gets its own try/catch, like every other row in the block: a raise inside it is its own `could not verify` warning. The role's name, which the `transaction isolation` remedy uses later, is read before the try.
- **`chunk context`** read a bare `thought_chunks`, and had no try/catch of its own. It now reads `public.thought_chunks`, its column check reads `information_schema.columns` for schema `public` only, and a raise is its own warning.
- **`schema`**, when `countThoughts` fails with "does not exist" on the SQL store, asks `pg_class` where `thoughts` is. If it exists somewhere, the row says so, and the remedy is the role's search path or a `GRANT USAGE`, not `migrate.ts`.

**Why.** A role granted SELECT on every table with `search_path = nowhere` passed the privilege test and then raised `relation "ob1_config" does not exist` on the read. The raise reached the block's catch, which reported the 27 rows after it as "not checked — the direct connection failed before it", `migration ledger` and `schema version` among them. The `schema` row above them said "Apply the migrations" for a brain that was migrated. SMD-2041's third review pass found it. test-preflight's limited role had no grant on `ob1_config`, so the read never ran.

With the read qualified, the next raise was `chunk context`'s bare `thought_chunks`, which took the ten rows after it. With no USAGE on `public`, `to_regclass('public.…')` itself raises (checked on PG16), so qualifying alone does not keep the rest of the block running; the try/catch does.

**Held.** test-preflight's `pf_reader` leg, 456 → 460:

- the role with SELECT on every table and `public` off its path: `write privileges` fails naming what the role lacks; no row says "not checked — the direct connection failed before it"; `chunk context` is ✓; `migration ledger` and `schema version` report in their own words; the `schema` row names the path and not the migrate command;
- the same role with no USAGE on `public` (`PUBLIC`'s revoked too, and restored only if it was held): `write privileges` and `chunk context` each warn `permission denied for schema public`, and no row says "not checked".

**Measured after.** Six mutants: five killed, one survived as equivalent here.

- Killed: the key read unqualified again; the chunk read unqualified again; the `schema` probe finding nothing; either row's try/catch dropped (the catch rethrowing).
- Survived: the column check reading every schema. No other schema on the test database has a `thought_chunks`, so the mutant can't be told apart there.

**Not taken.** The extraction key is still read in the row, not from `readDatabaseFacts`, the ticket's other option. The facts resolve tables through the search path, while this row tests every privilege on `public.`. Reading the key from the facts would put the row's read and its test on two different rules again, and add an extraction-key field to what `brain_info` reads.

**Follow-ups.** SMD-2236: the rows that resolve tables through the search path (`re-embed pass`, `consolidate pass`, `embedding contract`, `vector models`, `updated_at trigger`, `tier`, `audit events`) still call an off-path table absent, "migration 015 not applied" among them. Each already has its own try/catch; only the wording is wrong.
