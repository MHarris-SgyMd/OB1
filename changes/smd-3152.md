## Changelog

The PostgREST store and the Cloudflare Workers target it was kept for are gone: no brain ran them. The SQL store is the only store, and `OB1_STORE=postgrest` is refused at start and by preflight, naming the fix. `wrangler.toml`, the Workers build in CI, supabase-js and wrangler in `server-portable/`, and the over-PostgREST preflight probes went with them (SMD-3152).

## FORK

The PostgREST store and the Workers target are retired — the SQL store is the only one, and a postgrest selection is refused by name (SMD-3152)

**What changed.**
- **Deleted:**
  - `server-portable/store-postgrest.ts` and `test-store-postgrest.ts`;
  - `wrangler.toml`, `.dev.vars.example`, and `shims/` (the `bun` and `otel-setup.ts` stubs the Workers bundle aliased);
  - `@supabase/supabase-js`, `wrangler` and the `cf:*` scripts in `package.json`, and their lockfile entries.
- **`store.ts`:**
  - `OB1_STORE=postgrest` is refused with `POSTGREST_RETIRED`, which names the fix (unset it, set `DATABASE_URL`). Any other name than `sql` is refused as unknown, naming `sql` as the only store.
  - Gone: `postgrestOnBunNotice`, `postgrestOverPostgresUrl` and `DIRECT_CHECK_SKIP_OVER_POSTGREST`.
  - `missingDatabaseUrl` no longer offers PostgREST as a way out of an `https://` `SUPABASE_URL`; it says the URL is not a connection string.
  - `StoreEnv` loses `SUPABASE_SERVICE_ROLE_KEY`, and `ThoughtStore.kind` is `"sql"`.
  - The comments that described two stores describe one. The normalisers stay.
- **`preflight.ts`:**
  - The `store selection` row fails a postgrest selection with that refusal (it was a warning naming Workers).
  - Gone: the over-PostgREST block (the six probes through the store's calls, the five catalog skips, the loop naming every catalog-only check as a PostgREST skip), its `APPLY_0xx_POSTGREST`/`RELOAD_HINT`/`CATALOG_HINT` remedies, the PostgREST `SUPABASE_URL` rows, the plugins row's PostgREST failure and the chunk-context warning.
  - The direct-connection block runs whenever there is a connection string.
- **Runtime branches kept only for Workers or that store:**
  - root.ts logs no retired notice, and its agent registry always shares a lookup (`AgentResolver` loses `shareLookups`);
  - the vector mender no longer checks for the PostgREST store;
  - brain_info's in-flight read is shared on any built store;
  - the user-facing remedies no longer say "or PostgREST has not reloaded its schema cache", and `labelReadFailed` no longer treats `PGRST202` as expected.
  - telemetry's SDK still loads only where a collector is named, and the env shim stays (tests seed it).
- **CI and the ruleset:** the "Cloudflare Workers build" step, "The Worker bundles no OpenTelemetry SDK" and "PostgREST store argument shapes" are gone. The job "Portable server (Bun + Workers)" is "Portable server", in `fork-checks.yml` and `.github/rulesets/main.json`, and `db/ci-parity.sh` drops the suite.
- **Docs:**
  - `server-portable/README.md` loses the Workers target, the store table's second row, the Workers configuration, the cf build line and three Caveats;
  - SETUP.md loses its Workers row;
  - `db/README.md`, `deploy/README.md`, `deploy/compose.yaml`, `docs/operator-surface-tiers.md` (the row now reads retired), `docs/open-brain-assistant-gpt-context.md` and `docs/mcp-sdk-v2-migration.md` are updated, and so are the comments in `db/` and `scripts/gen-version.ts`.
  - The migrations' comments are left as written (append-only).
- **Other:** the runner image's bundle check loses `--external @supabase/supabase-js`; it bundles no npm package without it.

**Why.** The maintainer said on 2026-10-20 that there are no live users, and backwards compatibility is owed only to upgrading the stable and canary brains. Both run the compose stack on the SQL store (`deploy/compose.yaml` sets no `OB1_STORE`). Keeping the PostgREST store had a cost:
- it kept JS copies of SQL logic: `statsSummary`'s capped page walk copying 024, `listThoughts`' filters as `.contains()` chains, and `supersededAmong` reduced in JS;
- preflight kept a second set of probes;
- a Workers bundle built in CI;
- it kept supabase-js 2.47.10 and wrangler pinned.

SMD-2288 step 1 held the removal until the MCP v2 cutover, a wait that protected Workers deployments, and there were none. SMD-1336, SMD-1245 item 1 and SMD-2605, cancelled on the expectation that the file would go, go with it.

**Not taken.**
- **Dropping `OB1_STORE` altogether.** A selection left set would then be silently ignored. Refusing `postgrest` by name says what happened.
- **Removing `EMBEDDING_NOT_ATTACHED`.** It has no producer once the store's two-step is gone, but it is in the REST/MCP contract and the generated client. Ticketed as SMD-3153.
- **Removing the runtime-neutral shape.** The env shim, the `fetch` export and test-server [2]'s no-`Bun.*` rule stay: they cost nothing and the suites lean on them.
