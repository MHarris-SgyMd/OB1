## Changelog

The session hook (1.11.0) says its version: `--version` prints `session-capture 1.11.0` and exits 0, `--check` and `--dry-run` name it on their first line, and each summary it captures carries it as `metadata.hook_version`, so an operator can confirm an upgrade and the brain can tell which hook's rules wrote a summary's header (SMD-4378). **Upgrading:** pull the hook's checkout, or copy the script where your hook command points; no settings change. Summaries captured before 1.11.0 carry no version.

## Record

The session hook says its version, by `--version`, on `--check` and `--dry-run`, and on each summary as `metadata.hook_version` (SMD-4378)

**Problem.** The hook's version was written in `metadata.json` alone. The script printed none: no `--version`, and nothing in `--check`, `--dry-run`, the log or a payload. The installed hook is a copy of the script alone (`~/.local/share/open-brain/session-capture.mjs` on the maintainer's Mac), so an upgrade could be confirmed only by comparing the copy's checksum with the merge commit's, as 1.10.1's and 1.10.2's installs were, or by dry-running a transcript whose header the upgrade changes. Nothing in a summary said which hook wrote it, so the brain's team guard in `sessionHeaderTickets`, kept for hooks before 1.8.1, cannot be relaxed for later ones (SMD-4291's third Work item). Found by SMD-4291's review pass 6.

**Change** (`recipes/session-capture-hook/session-capture.mjs`, 1.11.0).
- **One source:** `HOOK_VERSION`, a constant in the script. It is not read from `metadata.json` at run time because the installed copy has none beside it. The suite fails if the two differ.
- **`--version`** prints `session-capture <version>` and exits 0. It is read before every other flag and before stdin, so it needs no config, no brain and no transcript, and a piped hook input captures nothing.
- **`--check`'s first line** is the same, printed before anything can fail. **`--dry-run`'s** is `--- session-capture <version>: what it would send; nothing is sent`.
- **`metadata.hook_version`.** `prepare` stamps each payload with the version, and `postCapture` sends it as `metadata.hook_version`, beside `summary_model`, `redactions` and `tickets_from`, a model's summary included. A payload carries the version of the hook that prepared it, so one queued while the brain was away and sent by a later hook keeps it. A payload queued by a hook before 1.11.0 is sent with none. A server that refuses metadata gets the summary without it, as before. The server reserves no such key (`RESERVED_META`).
- The README (what is sent, step 3's check and dry run, Testing) and `metadata.json` (1.11.0) say so.

**Held.** The hook's suite:
- the script's version equals `metadata.json`'s, and has three numbers;
- `--version` with stdin closed, with a hook input piped (nothing captured), and beside `--check`, a bad `--harness`, a misspelt `OB1_CAPTURE_ON_SECRET` and no config: each prints the one line and exits 0;
- `--check`'s first line, on a passing check and on one that fails at once on a misspelt mode; `--print-hook`'s JSON carries no version line;
- `--dry-run`'s first line, before the summary and before the segmentation;
- the stamp on a prepared payload and on the capture it posts, on the end-to-end derived capture (its metadata the version alone) and on the model's;
- a queued payload without a stamp sent with no metadata, and one stamped `1.10.9` sent with that, not the current version.

**Left as it is.**
- **The log's `captured` line** names no version. The ticket asked for none, and the summary's metadata now carries it.
- **The brain's team guard** (`sessionHeaderTickets`) still sends a header naming another team's ticket to the judge model for every summary. Relaxing it reads this stamp, and is SMD-4291's third Work item. Only summaries from 1.11.0 on carry a stamp, so summaries from 1.8.1 to 1.10.2 stay under the guard.
- **The version is kept by hand:** a release of the hook bumps the constant and `metadata.json` together, and the suite fails a commit that bumps one alone.
