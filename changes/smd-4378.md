## Changelog

The session hook (1.11.0) says its version: `--version` prints `session-capture 1.11.0` and exits 0. `--check` and `--dry-run` name it on their first line, and each summary it captures carries it as `metadata.hook_version`. So an operator can confirm an upgrade, and the brain can later tell which hook release prepared a summary (SMD-4378). **Upgrading:** pull the hook's checkout, or copy the script where your hook command points; no settings change. Then `bun <that copy> --version` prints `session-capture 1.11.0`; a copy before 1.11.0 refuses `--version`. Summaries prepared before 1.11.0 carry no version, including ones queued then and sent after the upgrade. So do summaries a hook before 1.11.0 sends after a rollback.

## Record

The session hook says its version, by `--version`, on `--check` and `--dry-run`, and on each summary as `metadata.hook_version` (SMD-4378)

**What changed** (`recipes/session-capture-hook/session-capture.mjs`, 1.11.0).
- **One source:** `HOOK_VERSION`, a constant in the script. It is not read from `metadata.json` at run time because the installed copy has none beside it. The suite fails if the two differ.
- **`--version`** prints `session-capture <version>` and exits 0. It is read before every other flag and before stdin, so it needs no config, no brain and no transcript, and a piped hook input captures nothing. With stdin a pipe or a socket, as a harness hands a hook its JSON, it also writes a log line: nothing was captured, renewed or copied, and if this is a hook command it stops every run. On a terminal or `/dev/null`, as an interactive shell or Claude Code's Bash tool runs it, it writes no file and makes no state dir.
- **`--check`'s first line** is the same, printed before the mode and config checks (a bad `--harness` is refused before it). **`--dry-run`'s** is `--- session-capture <version>: what it would send; nothing is sent`.
- **`metadata.hook_version`.** `prepare` stamps each payload with the version, and `postCapture` sends it as `metadata.hook_version`, beside `summary_model`, `redactions` and `tickets_from`, a model's summary included.
  - A payload carries the version of the hook that prepared it, so one queued while the brain was away and sent by a later hook keeps it. A payload queued by a hook before 1.11.0 is sent with none. A hook before 1.11.0 sending one a later hook queued (a rollback) drops it.
  - A model's summary is written when its payload is sent, which a later hook may do, so its stamp names the hook that prepared the model's input.
  - A stamp not shaped as three dot-separated numbers, as in a hand-edited or corrupt payload, is not sent: a long one the server refused would have cost the summary all its metadata, the redaction count among it.
  - `--dry-run`'s `would send` line names the stamp. A server that refuses metadata gets the summary without it, as before. The server reserves no such key (`RESERVED_META`).
- The README (what is sent, step 3's check and dry run, Expected Outcome, Testing) and `metadata.json` (1.11.0) say so.

**Why.** The hook's version was written in `metadata.json` alone. The script printed none: no `--version`, and nothing in `--check`, `--dry-run`, the log or a payload. The installed hook is a copy of the script alone (`~/.local/share/open-brain/session-capture.mjs` on the maintainer's Mac), so an upgrade could be confirmed only by comparing the copy's checksum with the merge commit's, as 1.10.1's and 1.10.2's installs were, or by dry-running a transcript whose header the upgrade changes. Nothing in a summary said which hook wrote it, so the brain's team guard in `sessionHeaderTickets`, kept for hooks before 1.8.1, could not be relaxed for later ones (SMD-4291's third Work item). Found by SMD-4291's review pass 6.

**Held.** The hook's suite:
- the script's version equals `metadata.json`'s, and has the shape `postCapture` sends;
- `--version` with stdin from `/dev/null`, with a hook input piped (nothing captured), and with `--check`, a bad `--harness`, a misspelt `OB1_CAPTURE_ON_SECRET` and no config all in one run: each prints the one line and exits 0. Only the piped run writes the log line, and on `/dev/null` with no state dir none is made;
- `--check`'s one version line, first, on a passing check, on one that fails at once on a misspelt mode, and untagged before each brain's lines with two brains; `--print-hook`'s JSON still parses whole;
- `--dry-run`'s first line, before the summary, the segmentation, a skip and the model's status line, and each `would send` line ending in `metadata.hook_version`;
- the stamp on a prepared payload and its capture, on each episode of a four-episode session (beside `tickets_from`), on a redacted one (beside its count), on a checkpoint, on the end-to-end derived capture (its metadata the version alone) and on the model's;
- `postCapture` sending a payload's own stamp or none; payloads drained from the queue, one with no stamp and one stamped `1.10.9`, sent with none and with `1.10.9`; seven stamps not in a version's shape sent as none, the redaction count still sent.

The suite also passes on Linux (Bun 1.4.3), as CI runs it, where a spawned child's piped stdin is a pipe or a socket as on macOS.

**Not taken.**
- **The log's `captured` line** names no version. The ticket asked for none, and the summary's metadata now carries it.
- **The brain's team guard** (`sessionHeaderTickets`) still sends a header naming another team's ticket to the judge model for every summary. Relaxing it reads this stamp, and is SMD-4291's third Work item. Only summaries from 1.11.0 on carry a stamp, so summaries from 1.8.1 to 1.10.2 stay under the guard.
- **A pipe the hook cannot tell from a harness's:** `echo | bun session-capture.mjs --version`, `ssh host cmd`, cron, or a tool spawning it with a piped stdin writes the log line too, worded "if this is a hook command". A hook handed a regular file as stdin (an operator's own `< file` wrapper) writes none; no harness does so.
- **`--dry-run` prints its version line, then fails on a missing transcript;** and a misspelt `OB1_CAPTURE_ON_SECRET` is refused before `--dry-run`'s version line but after `--check`'s. Both are cosmetic, and no doc promises otherwise.
- **`--version` at a terminal** writes nothing, as on `/dev/null`, but the suite runs no terminal: the usage text naming `--version`, printed at a terminal alone, is unasserted.
- **A brain from before `capture_thought` took `metadata`** (SMD-2014) now refuses every capture's first call, not only a redacted or model one, and the hook retries without it. Stable and the canary are on v2.2.0.
- **The version is kept by hand:** a release of the hook bumps the constant and `metadata.json` together, and the suite fails a commit that bumps one alone.
