## Changelog

The session hook (1.11.0) says its version: `--version` prints `session-capture 1.11.0` and exits 0, `--check` and `--dry-run` name it on their first line, and each summary it captures carries it as `metadata.hook_version`, so an operator can confirm an upgrade and the brain can tell which hook's rules wrote a summary's header (SMD-4378). **Upgrading:** pull the hook's checkout, or copy the script where your hook command points; no settings change. Then `bun <that copy> --version` prints `session-capture 1.11.0`; a copy before 1.11.0 refuses `--version`. Summaries prepared before 1.11.0, including ones queued then and sent after the upgrade, carry no version, and so do summaries a hook before 1.11.0 sends after a rollback.

## Record

The session hook says its version, by `--version`, on `--check` and `--dry-run`, and on each summary as `metadata.hook_version` (SMD-4378)

**What changed** (`recipes/session-capture-hook/session-capture.mjs`, 1.11.0).
- **One source:** `HOOK_VERSION`, a constant in the script. It is not read from `metadata.json` at run time because the installed copy has none beside it. The suite fails if the two differ.
- **`--version`** prints `session-capture <version>` and exits 0. It is read before every other flag and before stdin, so it needs no config, no brain and no transcript, and a piped hook input captures nothing. With stdin a pipe or a socket, as a harness hands a hook its JSON, it also writes a log line saying nothing was captured, renewed or copied, since in a hook command it would stop every run. On a terminal or `/dev/null`, as an agent's or a script's shell runs it to confirm an upgrade, it writes nothing and makes no state dir.
- **`--check`'s first line** is the same, printed before the mode and config checks (a bad `--harness` is refused before it). **`--dry-run`'s** is `--- session-capture <version>: what it would send; nothing is sent`.
- **`metadata.hook_version`.** `prepare` stamps each payload with the version, and `postCapture` sends it as `metadata.hook_version`, beside `summary_model`, `redactions` and `tickets_from`, a model's summary included. A payload carries the version of the hook that prepared it, so one queued while the brain was away and sent by a later hook keeps it. A payload queued by a hook before 1.11.0 is sent with none, and a hook before 1.11.0 sending one a later hook queued (a rollback) drops it. A model's summary is written when its payload is sent, which a later hook may do, so its stamp names the hook that prepared the model's input. `--dry-run`'s `would send` line names the stamp. A stamp not in a version's shape, three numbers (a hand-edited or corrupt payload), is not sent: a long one the server refused would have cost the summary all its metadata, the redaction count among it. A server that refuses metadata gets the summary without it, as before. The server reserves no such key (`RESERVED_META`).
- The README (what is sent, step 3's check and dry run, Testing) and `metadata.json` (1.11.0) say so.

**Why.** The hook's version was written in `metadata.json` alone. The script printed none: no `--version`, and nothing in `--check`, `--dry-run`, the log or a payload. The installed hook is a copy of the script alone (`~/.local/share/open-brain/session-capture.mjs` on the maintainer's Mac), so an upgrade could be confirmed only by comparing the copy's checksum with the merge commit's, as 1.10.1's and 1.10.2's installs were, or by dry-running a transcript whose header the upgrade changes. Nothing in a summary said which hook wrote it, so the brain's team guard in `sessionHeaderTickets`, kept for hooks before 1.8.1, cannot be relaxed for later ones (SMD-4291's third Work item). Found by SMD-4291's review pass 6.

**Held.** The hook's suite:
- the script's version equals `metadata.json`'s, and has three numbers;
- `--version` with stdin from `/dev/null`, with a hook input piped (nothing captured), and beside `--check`, a bad `--harness`, a misspelt `OB1_CAPTURE_ON_SECRET` and no config: each prints the one line and exits 0; only the piped run writes the log line, and on `/dev/null` with no state dir none is made;
- `--check`'s one version line, first, on a passing check, on one that fails at once on a misspelt mode, and untagged before each brain's lines with two brains; `--print-hook`'s JSON still parses whole;
- `--dry-run`'s first line, before the summary, the segmentation, a skip and the model's status line, and each `would send` line ending in `metadata.hook_version`;
- the stamp on a prepared payload and its capture, on each episode of a four-episode session (beside `tickets_from`), on a redacted one (beside its count), on a checkpoint, on the end-to-end derived capture (its metadata the version alone) and on the model's;
- `postCapture` sending a payload's own stamp or none; payloads drained from the queue, one with no stamp and one stamped `1.10.9`, sent with none and with `1.10.9`; seven stamps not in a version's shape sent as none, the redaction count still sent.
