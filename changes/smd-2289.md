## Changelog

The import runner's emitters get no network. Rules keyed on the emitter uids, set as the runner's container starts and then beyond its reach, refuse every packet an emitter sends: DNS, loopback, the host's Ollama, Postgres, n8n, the internet. A live-API pipeline names its hosts in `pipelines.json` (`network`), and its emitter reaches only those, through a proxy the runner keeps for it that tunnels HTTPS to them and refuses anything else; the run's report lists what it refused. The runner refuses to start if an emitter uid can reach its port, or while it holds the capability to change the rules (SMD-2289).

## FORK

Emitter egress — an import emitter has no network unless its pipeline names a host, and then only that host, through the runner's proxy (SMD-2289)

**What changed.** SMD-2212's review pass 7 measured an emitter as its uid in
the kit's runner. It reached the host's Ollama through the host alias,
unauthenticated, admin API included (pull and delete models); Postgres; n8n;
the brain's and the runner's `/health`. On a VPS, a cloud metadata endpoint
would be reachable too. An emitter an export had taken over could take
embedding down for the whole brain, or fill the disk. File emitters need no
network, and live-API ones one vendor host each. This is the ticket's first
part; the runner's own database role is its second.

**The rules** (`deploy/orchestration/runner.ts` `egressRules`,
`runner.Dockerfile`, compose `orchestration-runner`):
- The image's command runs in two steps. `runner.ts --egress` loads the
  allowlist and gives `nft -f -` a table of its own: every packet from an
  emitter uid (20000–59999) goes to a chain that refuses it, TCP with a reset
  and the rest with an ICMP error, so a connect fails at once (measured: a
  drop left it waiting for its timeout). Before the refusals, each networked
  pipeline's uid may reach 127.0.0.1 on its own port, the uid's number, where
  its proxy listens. Then `setpriv` drops NET_ADMIN and SETPCAP from the
  bounding and inheritable sets (an engine before Docker 20.10.14 or podman
  4.0.3 filled the inheritable one) and runs the runner, which keeps KILL,
  SETGID and SETUID alone (measured: CapEff `e0`, and nft refused).
- Compose adds NET_ADMIN and SETPCAP to `cap_add` for that first step.
- It refuses to start (30 s, exit 2, the restart policy retries):
  - `--egress`, without both capabilities, before it sets anything;
  - the runner, as root while holding either: it was started another way
    than the image's command;
  - the runner, if an emitter uid reaches a listener of its on 127.0.0.1,
    asked as that uid before the service listens, or if it cannot ask: the
    rules are not in place.
- The ingester and reembed run as `bun`, outside the range, and keep the
  network: Postgres and the model provider.

**A pipeline's `network`** (`pipelines.json`): absent or `false`, none;
otherwise the hosts its emitter needs, each `"host"` (port 443) or
`"host:port"`. Refused: `true` (a pipeline cannot ask for the whole network),
an empty list, a malformed host or port, a name twice, a loopback or
link-local name (`localhost`, `127.0.0.1`, `169.254.169.254`), and an
address in any spelling but a dotted quad (`127.1`, `0x7f.1`).

**The proxy** (`startProxy`), one per networked pipeline, on 127.0.0.1 at
the uid's port. The emitter finds it in `HTTPS_PROXY` and `https_proxy`,
which Python's urllib and requests and Bun's fetch read; a pipeline naming
no host gets neither.
- It answers `CONNECT host:port` for a named host on its named port. It
  resolves the name itself, refuses one resolving to a loopback, link-local,
  IPv4-compatible or cloud metadata address, in any IPv4-mapped spelling
  (the runner's own ports on loopback, a metadata endpoint), and dials the
  address it checked. A private address is not refused: a compose service
  has one.
- The tunnel's first bytes must be a TLS ClientHello whose server name is
  the named host (for a named IPv4 address, that address or none), or it is
  closed before anything reaches the host. A vendor behind a CDN that routes
  by server name is then not a way to every site on that CDN. A client that
  shuts its write side still gets the answer.
- Anything else is refused: another host or port 403, a request that is not
  CONNECT 405, headers past 8 KB 431, a host that refuses the dial 502, one
  that does not answer it within 10 s 504. A connection has 30 s to send its
  request and its ClientHello, and a proxy holds 64 connections at once.
- The run's report lists what it refused under `egress`, 20 at most and the
  rest counted, each run its own.
- SMD-2211's egress checkpoint governs the hosts a pipeline names.

**The kit** (`evals/orchestration/runner/`, check I):
- `snoop` also fails if it gets a DNS answer, or reaches the host alias's
  Ollama, Postgres, n8n, 1.1.1.1 or the runner's own port. The alias, the
  address and the port are refused by address, not by a failed lookup.
- `vendor`, a fourth pipeline, names `server:8000`. Its emitter must reach
  that host through its proxy with TLS naming it (the brain answers a
  ClientHello in plain HTTP, which is proof enough), be cut off when TLS
  through the same tunnel names another server, have a CONNECT to Postgres
  refused, and open no direct connection, the runner's own port included.
  The report must name the two refusals.

**Verified** live (`--verify n8n`, SQLite), plain and sealed: every check
passes. I: `snoop` reached nothing, `vendor` reached its host with Postgres
refused, and E, sealed, saw n8n dial only the brain and the runner. With the
rules deleted in the running container, `snoop` reached all six targets and
`vendor` a direct connection. The runner refused each wrong start: its plain
command holding the two capabilities, or without the rules, and the image's
command missing either capability. Started as compose starts it, its process
holds KILL, SETGID and SETUID alone. The self-check's new cases each fail
under a drop-the-mechanism mutant (33 killed).

**Review.** Each pass paired a cold reader with a run-it reviewer.
