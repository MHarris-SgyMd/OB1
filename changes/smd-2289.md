## Changelog

The import runner's emitters get no network. Rules keyed on the emitter uids, set as the runner's container starts and then beyond its reach, refuse every packet an emitter sends: DNS, loopback, the host's Ollama, Postgres, n8n, the internet. A live-API pipeline names its hosts in `pipelines.json` (`network`), and its emitter connects to those alone, through a proxy the runner keeps for it that tunnels TLS naming them (the ClientHello's server name, no encrypted inner hello) and refuses anything else; the run's report lists what it refused. The runner refuses to start if an emitter uid can reach a port of its on loopback, asked before it listens, or while it holds the capability to change the rules (SMD-2289). The runner also reaches Postgres as a role of its own, `ob1_orchestration_runner`, not the superuser: a LOGIN role that owns nothing and holds the grant groups its ingester and reembed run (capture, worker, structure, extraction), made on every start by a one-shot (`db/login-role.ts`, then `migrate.ts --grant --groups --exact`) from `OB1_RUNNER_DB_PASSWORD`, which `provision.ts --init` writes. Its environment holds only the knobs those two read. `migrate.ts --grant` gains `--groups`, and the worker group gains `SELECT` on the migrator's ledger, which reembed reads on every start and without which no `--grant` role could run it.

## FORK

The import runner's hardening — an emitter has no network unless its pipeline names a host, and then only that host through the runner's proxy; and the runner writes as a database role of its own (SMD-2289)

**What changed.** SMD-2212's review pass 7 measured an emitter reaching the
host's Ollama (admin API and all), Postgres, n8n and every `/health`, and on
a VPS a metadata endpoint; the runner connected as the superuser with every
server knob. The ticket's first part (egress, #243) and its second (the
runner's role) follow.

**The rules** (`deploy/orchestration/runner.ts` `egressRules`,
`runner.Dockerfile`, compose `orchestration-runner`):
- The image's command runs in two steps. `runner.ts --egress` loads the
  allowlist and gives `nft -f -` a table of its own: every packet from an
  emitter uid (20000–59999) goes to a chain that refuses it, TCP with a reset
  and the rest with an ICMP error, so a connect fails at once (measured: a
  drop left it waiting for its timeout); a name lookup still waits out the
  resolver's own timeout, about 5 s. Before the refusals, each networked
  pipeline's uid may reach 127.0.0.1 on its own port, the uid's number, where
  its proxy listens. Then `setpriv` drops NET_ADMIN and SETPCAP from the
  bounding and inheritable sets (an engine before Docker 20.10.14 or podman
  4.0.3 filled the inheritable one) and runs the runner, which keeps KILL,
  SETGID and SETUID alone (measured: CapEff `e0`, and nft refused).
- Compose adds NET_ADMIN and SETPCAP to `cap_add` for that first step.
- It refuses to start (30 s, exit 2, the restart policy retries):
  - `--egress`, without both capabilities, before it sets anything;
  - the runner, as root while holding either: it was started another way
    than the image's command;
  - the runner, if an emitter uid reaches a listener of its on 127.0.0.1,
    asked as that uid before the service listens, or if it cannot ask: the
    rules are not in place.
- The ingester and reembed run as `bun`, outside the range, and keep the
  network: Postgres and the model provider.

**A pipeline's `network`** (`pipelines.json`): absent or `false`, none;
otherwise the hosts its emitter needs, each `"host"` (port 443) or
`"host:port"`. Refused: `true` (a pipeline cannot ask for the whole network),
an empty list, a malformed host or port, a name twice, a loopback or
link-local name (`localhost`, `127.0.0.1`, `169.254.169.254`), and an
address in any spelling but a dotted quad (`127.1`, `0x7f.1`).

**The proxy** (`startProxy`), one per networked pipeline, on 127.0.0.1 at
the uid's port. The emitter finds it in `HTTPS_PROXY` and `https_proxy`,
which Python's urllib and requests and Bun's fetch read; a pipeline naming
no host gets neither.
- It answers `CONNECT host:port` for a named host on its named port. It
  resolves the name itself, refuses one resolving to a loopback, link-local,
  IPv4-compatible or cloud metadata address, in any IPv4-mapped spelling
  (the runner's own ports on loopback, a metadata endpoint), and dials the
  address it checked. A private address (a compose service's) passes.
- The tunnel's first bytes must be a TLS ClientHello whose server name is
  the named host (for a named IPv4 address, that address or none), read as
  servers read it, with no encrypted inner hello (ECH), or it is closed
  before anything reaches the host. A CDN that routes by server name then
  takes the tunnel to that vendor alone. What travels inside TLS is not
  read: a CDN that honours an HTTP Host unlike the server name (domain
  fronting, which the large CDNs refuse) could still carry it elsewhere.
- Every address a name resolves to is screened, and IPv4 is dialled first.
- A client that shuts its write side still gets the answer, and a tunnel
  lasts while both sides are open and 30 s of quiet after either ends, so a
  host that never closes cannot hold the proxy's connections.
- Anything else is refused: another host or port 403, not CONNECT 405,
  headers past 8 KB 431, no address or a refused dial 502, no answer in 10 s
  504. A connection quiet for 30 s before its tunnel opens is closed; a proxy
  holds 64. The run's report lists each under `egress`, 20 and a count.
- A named host must speak TLS; a plain-HTTP one is cut off at its first
  bytes. The hosts are the operator's to choose: nothing reviews them yet
  (SMD-2211's checkpoint covers n8n's credentials, not these).

**The kit** (check I): `snoop` also fails on a DNS answer, or on reaching the
host alias's Ollama, Postgres, n8n, 1.1.1.1 or the runner's port. `vendor`
names `server:8000` and must reach it by TLS through its proxy, be cut off
naming another server, have Postgres refused, and open no direct connection.

**CI** starts the runner's image as compose runs the service, without its
dependencies: the rules go into a real nft, the runner listens only once its
probe as an emitter uid is refused, and then, as an emitter uid, the
internet and the runner's port are refused and the runner holds KILL,
SETGID and SETUID alone.

**Verified** live (`--verify n8n`), plain and sealed, every check passing.
With the rules deleted, `snoop` reached all six targets and `vendor` a direct
connection. Each wrong start was refused. 56 mutants are killed. Pass 2's
leak (70 half-closed tunnels to a silent host) recovered in 35 s.

**The runner's database role** (part 2; compose `orchestration-runner-role`,
`db/login-role.ts`, `migrate.ts --grant --groups --exact`):
- `ob1_orchestration_runner` is a LOGIN role that is not a superuser, a
  member of no role, owns nothing and names no schema; an existing one has
  its settings (every database's) cleared, or is refused. It sends the password (24+ of
  `[A-Za-z0-9_-]`, from a named variable) as a SCRAM verifier.
- It holds capture, worker, structure and extraction, measured as the role
  in the kit's runner until items with links and mentions were inserted,
  updated and embedded; not the server group, whose `ob1_agent_keys` writes
  could clear a revocation. The worker group gains `SELECT` on `ob1_config`
  (the server group's until now) and on `schema_migrations`, which reembed
  reads on every start: no `--grant` role could run it.
- `--groups a,b` grants those groups alone; `--exact`, in the grant's
  transaction, refuses a member or an owner, revokes object by object what
  an ACL grants the role here (schema USAGE, CONNECT and TEMP stay) and
  refuses what it cannot, naming it. Every `--grant` holds one lock.
- The one-shot runs `migrate`'s image before the runner on every `up`, so a
  rotated `OB1_RUNNER_DB_PASSWORD` (`--init`) and new grants land; in the
  image the runner refuses a URL with no password.
- Its environment is an allowlist of what the ingester and reembed read.
- CI runs the one-shot, plants leftovers, runs it again and holds the role
  to exactly the four groups' privileges; asks as the role over the compose
  network (a wrong password refused); refuses by name each role the two
  steps refuse; clears a leftover privilege and setting. Check I asserts the
  role and environment.
