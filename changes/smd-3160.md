## Changelog

A migration that changes which ticket status types the brain knows can now rebuild only the rows that change: `ob1_rebuild_source_gate_for_types(text[])`, added by migration 107, reconciles the dependency gate's rows for the status types given. Both it and the full `ob1_rebuild_source_gate()` hold every write to thoughts and their source rows until the migration commits; the full one runs for as long as it takes to reconcile every source row, the keyed one only for the rows of the types given. `ob1_refresh_set_readers()`, also new, makes the brain's own functions use the changed set at once in every open session rather than the one they had cached; a server's own cached statements take it when the server restarts (SMD-3160, migration 107).

## FORK

A keyed rebuild of 071's gate mirror for a status-set change — the cost follows the moved rows, not the table (SMD-3160)

**What changed** (migration 107).
- **`ob1_rebuild_source_gate_for_types(text[])`**, beside the full rebuild:
  - refuses outside READ COMMITTED and takes SHARE on `thoughts`, then `thought_sources`, as the full rebuild does (a writer working from the old set could otherwise move a status after the scan);
  - finds the sourced thoughts whose `status_type` is one of the types given, one probe of 001's GIN index on `thoughts.metadata` per type (`metadata @> {"status_type": <type>}`);
  - reconciles those alone with 071's `ob1_source_gate_reconcile(ids)` and returns what it wrote and deleted;
  - takes no advisory lock: SHARE holds off every writer whose triggers could touch the mirror, as the full rebuild relies on;
  - an empty, NULL or all-NULL array touches nothing and takes no lock.
- **The full rebuild stays**, for repair after a write made with the tables' triggers disabled. Its comment now names the keyed form for a set change; 071's header is not edited (append-only), and 107's supersedes that note.
- **`ob1_refresh_set_readers()`**, 105's `DO $touch$` block as a call: it alters each of the brain's own functions that name a set to the volatility it has, dropping every session's plans built on it, and returns how many. Without it a pooled session keeps the old set — its searches, its node_state, 071's gate triggers, and `drift()` itself, which in a warmed session reported 12 phantom rows when the next author's walk left it out.
- **For the next set change**, after redefining `node_lifecycle_types()`: `SELECT ob1_refresh_set_readers();` then `SELECT * FROM ob1_rebuild_source_gate_for_types('{<each type it adds or drops>}');`. A change to `node_settled_types()` alone needs only the first. Each set's comment, re-made by 107 with 058's and 105's tags, says so where the next change is made, and how to list every copy that follows it by hand: they all name canceled or unstarted, so `git grep -nwE 'canceled|unstarted' -- ':!db/migrations' ':!changes' ':!CHANGELOG.md' ':!integrations'` lists them — code, prose and the tests that pin them (about 140 lines, fixtures among them). It names the code's copies that must equal it (graph-centrality's `LIFECYCLE_TYPES` and `LIFECYCLE_FILTERS`, stated-status's `TYPE_WORDS`, render's `DEMOTIONS`, the stated-status eval's `TYPES`, appended to) and 105's probes of `duplicate` alone. An inventory went there first; three review passes running each found it short (the walks of passes 3 and 4, the audit of pass 5), so pass 5 made it a grep and took out the four sentences that counted the types ("seven"), the one kind of copy the grep cannot see. test-schema [94] and test-live [41] re-apply 105 and now put the shipped sets back after, where they put 105's: a later set change would have been undone for every section after them.
- **Check 39** (`scripts/check-fork-consistency.ts`) holds both for a lifecycle change and the refresh for a settled one, reading canonical forms only on the comment-stripped text with every literal's inside blanked ('…', E'…', "…", $tag$…$tag$). Every `CREATE [OR REPLACE] FUNCTION [schema.]node_lifecycle_types` or `node_settled_types`, and every `RENAME TO` one, anywhere — a string, a body, an EXECUTE — must be a line starting `CREATE OR REPLACE FUNCTION node_lifecycle_types()` (or `node_settled_types()`) outside any literal, whose body is exactly `SELECT '{…}'::text[]` or a plpgsql `BEGIN RETURN '{…}'::text[]; END` (a set built from the literal, `|| ARRAY['c']`, is not read as it); else the file is reported unreadable, with the form to write. After the file's last definition, as lines outside any literal: `SELECT ob1_refresh_set_readers();` (from the file that defines it on) and `SELECT * FROM ob1_rebuild_source_gate();` or `SELECT * FROM ob1_rebuild_source_gate_for_types('{…}');` lines naming exactly the types the change adds and drops. Two passes of a statement parser each drew a seam, and pass 5's adversary found a canonical line hiding another definition, a built set read as its literal and `$$` in a string flipping the body blanking; a loud refusal costs an author a rewrite where a quiet miss costs every brain. Each rule is the only catch of one of its probes; with 105's call removed it names 105 and the line to add.
- **Each type once:** the list is deduplicated before the probes, so a type named a thousand times is probed once (it took 8 s under the locks before).
- **Not here:** a `status_type` stored as a JSON number or boolean (the probe matches a JSON string, as every writer stores it); a common type (40% of rows) is scanned rather than probed, at about the full rebuild's cost.
- **Refuses by name** without 071; a re-apply is a no-op. No table, column or grant.

**Why.** 071 asked a migration that changes `node_lifecycle_types()` to run the full rebuild, which joins every source row to its thought under SHARE locks held to the migration's commit. 105 (SMD-2935) did. Measured in SMD-2935's review pass 5 on PG 16 at compose defaults, writes waited 26 ms at 10,000 source rows, 221 ms at 100,000 and 3.3–4.4 s at a million (2M thoughts), and the cost grows with the thoughts table, an hour or so at the 1B horizon if it stays linear (SMD-2754, SMD-2758). A set change moves only the rows of the types it adds or drops; stable had 16.

**Held.**
- **test-schema [95]:**
  - a set change that adds a type: the keyed form reconciles that type's rows and no other, so a wrong gate row it was not asked about stays wrong and drift() names it, which the full rebuild then fixes;
  - a set change that drops the type: the same call takes the rows back;
  - a type named twice and one no row holds are read with the rest; an empty, NULL or all-NULL array touches nothing and takes no lock (it answers under REPEATABLE READ); on an exact mirror the call writes nothing;
  - refused under REPEATABLE READ, naming the level;
  - the refresh alters each of the brain's readers of the sets and returns how many;
  - a re-apply is a no-op, and the four comments say what each function is for — the keyed form's, the full rebuild's, and each set's own, which says what a change to it runs and gives the grep that lists its copies.
- **Measured** (PG 16 at compose defaults, 2M thoughts and 1M source rows, 70% Linear tickets; each call in a migrate.ts-shaped transaction, a capture issued as it took its locks; warm medians):

  | source rows | rows of the moved type | full rebuild: call / capture waits | keyed: call / capture waits |
  |---|---|---|---|
  | 10k | 212 | 32 / 35 ms | 14 / 20 ms |
  | 100k | 2,122 | 388 / 393 ms | 76 / 82 ms |
  | 1M | 21,212 | 8.8 / 8.9 s | 1.39 / 1.39 s |
  | 1M | 16 (stable's count) | 6.2 / 6.2 s | 14 / 29 ms |

  After every run (20) a full reconcile wrote and deleted nothing and drift() was empty. The keyed scan is a bitmap scan of `thoughts_metadata_idx` into `thought_sources_pkey`. The host was busy, so the full rebuild ran about 1.4–2.7× SMD-2935 pass 5's times; the ratio is what holds. At tens of thousands of moved rows most of the keyed cost is 071's reconcile itself, whose delete arm then scans the whole mirror rather than its key (16 rows take the key) — a cost for a set change that moves a large share of a 1B brain, not for this one.
- **test-upgrade [20ay]:** refused without 071; onto a populated brain at the file before it, no thought, audit or gate row moved; a status write and a source-row write each wait for the keyed form's locks to its transaction's end (55P03 at a 1 s lock timeout) and go through after — without the lock on `thought_sources` a source row recorded meanwhile would take its gate from the old set; a set change run by the recipe (the set, the refresh, the keyed rebuild) reaches a session that searched eight times before it; a re-apply is a no-op. The window guard (seventy-eight) and both enumerations name 107.
