## Changelog

Fork Checks' Portable server job type-checks its seven directories in one step, side by side, where it ran seven steps one after another (SMD-3202).

## FORK

Portable server's seven typechecks run side by side, in one step (SMD-3202)

**What changed.**
- **`.github/ci/typecheck.sh DIR…`**, new. It refuses the run if any directory named has no tsconfig.json, before starting anything. Then it runs `bunx tsc --noEmit` in each directory, side by side, each run's output to a log of its own. It prints every log in the order named, a passing one folded and a failing one open with its directory named, and exits 1 if any failed. Each directory is relative to the repository root, whatever the caller's directory.
- **`.github/workflows/fork-checks.yml`:** Portable server's seven tsc steps are gone: server-portable, rest-client, mcp-server, db, evals, jev and deploy/auth. One step runs the script over all seven, after the authorization server's install, the last install they need. Each directory's install and tests stay where they were. The scripts' and the compat shim's typechecks, one directory in other jobs, are unchanged.
- **`scripts/check-fork-consistency.ts`**, check 18:
  - **Its reader `tscStepsIn`**, which check 35 shares, reads a step whose whole `run:` is `.github/ci/typecheck.sh DIR…` as a tsc step for each directory named. A block scalar and a trailing `/` read as written. So check 18 still holds every type-checked directory to exactly one typecheck, and check 35 holds each to db/ci-parity.sh's `typecheck` line. A probe pins what the reader reads.
  - **When a step names directories to the script, check 18 runs the script** against a stub `bunx`, over a scratch tree. The directories are named relative to the repository root, as the step names them, from a working directory nested deeper than the root, so they resolve only through the script's own `cd`.
    - **The stub:** where a directory fails, it prints on stdout (where tsc prints its diagnostics) and on stderr, and exits with that directory's own code: 2, 137 or 1. One failing directory waits until another's tsc has started, so the two run side by side and finish in a known order.
    - **Three runs:** fail, pass, fail, pass; pass, pass; and pass, fail.
    - **Check 18's promise, held for each run:** a tsc in each directory, once, exactly `tsc --noEmit`; the run failing if any fails, and passing if none does.
    - **What the step's log is for, held for each run:**
      - each failing directory's line carries its own exit code, in the order named;
      - under it, both of its output streams and no other directory's;
      - not folded into a group.
    - **Side by side:** a script that runs them one after another is refused.

    The step's directories count as type-checked only while the script does what the step relies on. Without bash on PATH, check 18 says so rather than throwing.
  - **A step that runs the script in a form the reader does not take** is named once, first, with the form it takes. Such forms are a `\` continuation, `bash` or `./` in front, or a comment. Otherwise every directory it names would read as untype-checked, and check 35 would say to take their lines out.
  - **Its messages say what to do:**
    - a flag on the tsc is refused once, with why (the command is held exactly, as a step of its own is; options belong in tsconfig.json);
    - a failure line the probe cannot read is shown with the line it expects;
    - an unlisted directory may be taken out of its step;
    - check 35's message names both ways to type-check a directory.
  - The header says so.
- **`db/ci-parity.sh`**, comments only: every directory CI runs `bunx tsc --noEmit` in is a `typecheck` line, by a step of its own or one the script names. Its lines run one after another locally.
- **Not joined:** the operator GUI's `svelte-check` (SMD-2280, `bun run check` in dashboard/) stays a step of its own. It is not tsc, and needs `svelte-kit sync` first.

**Why.** Portable server is one of the run's two slowest jobs, with "Full stack, no Supabase". In the five green runs on main since SMD-3195, Portable took 256–316 s and Full stack 282–295 s, and each was the slowest in some of them. Its seven tsc steps took 25–49 s one after another, on two kinds of runner: about 47–49 s on the slower, 25–28 s on the faster. Each tsc is a single process, and the runner has four CPUs.

In a 4-CPU Linux container (`podman --cpus 4`, the worktree mounted, warm), the seven took 39.6 s one after another and 21.6–25.2 s side by side. Expected: about 17–21 s off Portable server on the slower runners, 9–13 s on the faster. The run's wall time falls only by Portable's lead over Full stack, which is nothing where Full stack leads.

**Not taken.**
- Project references and `tsc -b`, the larger follow-up the ticket names. It would cut the work all seven programs repeat: each loads the same libraries and types, and the six that import server-portable's files check them again. Side by side, seven runs on four CPUs take about half the serial time, not a quarter. Each tsc runs about twice as slowly beside the others: memory, garbage collection and reading files, not shortage of CPU. On an 18-CPU Mac they took 61% of their serial time.
- Starting the typechecks in the background at the job's start, as SMD-3195 did for the data layer's pair. That would hide nearly all of them behind the job's tests, at their CPU's cost; it is a change of its own.
- Running db/ci-parity.sh's typechecks side by side too. Its lines are what check 35 compares, and locally the time costs nothing CI waits on.

**A type error now fails the job later.** Four typechecks (rest-client, mcp-server, evals, jev) ran before their directory's tests and now run after them. server-portable's ran after its own tests but before its three runs through the MCP server, and now runs after those. deploy/auth's still runs before its rules. So a PR with both a failing test and a type error shows the test first.

  It passes a renamed loop variable, a dropped `exec`, a line printed per directory, and the tsconfig pre-check dropped (tsc then fails on its own). It refuses `tsc --noEmit -p .`, holding the command to `tsc --noEmit` exactly, so a flag such as `--noCheck` cannot pass. It passes with a TMPDIR holding a space, and leaves nothing in it.
