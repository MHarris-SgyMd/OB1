## FORK

n8n's brain calls go to the REST core, and the orchestration ADR follows SMD-2282's decision 1 (SMD-2295)

**What changed.**
- **`deploy/orchestration/credentials.template.json`:** "OB1 brain — capture key" carries SMD-2211's domain pin, `allowedDomains: api`, the REST core's name on `egress`. It still sends `x-brain-key`. n8n refuses the credential on any other host; the eval measured that refusal for a pinned credential on the HTTP Request node, the node a brain call now uses.
- **`deploy/orchestration/provision.ts`:**
  - its self-check holds that the profile's one brain credential is pinned to `api` alone;
  - `--init`'s note for the optional capture key names the REST core and recreates `api` alone;
  - the `?key=` case's URL is the REST core's.
- **`docs/orchestration-tool.md`:** an "Amended by SMD-2295" block, and decision 4, posture step 2 and "Not decided here" each say it. A template's brain call is an HTTP Request node against the REST core's routes with `x-brain-key`. The key discipline is unchanged: a capture-scope key, attributed and revocable, in a credential pinned to one host. n8n stays on `egress` alone, and its own MCP endpoint (the act tool) is untouched. Decision 1's C2 and C3 stay the POC's record of 2026-09-25.
- **SMD-2287 PR 5b's wording, corrected.** It called `server` "n8n's" and planned "PR 6 moves n8n to the MCP server". Nobody decided either. No shipped template calls the brain at all:
  - `act-linear-file-issue` calls Linear;
  - `import.per-pipeline` calls `orchestration-runner:8090`;
  - `act-mcp` is n8n's own trigger.

  `server` is called by nothing now, and retires in SMD-2287 PR 6. The comments and docs that said otherwise now say this: `deploy/compose.yaml`, `deploy/README.md` (the services table, the v2.0.0 URL table's n8n row, the logs, `OTEL_SERVICE_NAME`, "Orchestration"), `deploy/.env.example`, `SETUP.md`, `docs/01-getting-started.md`, `docs/operator-surface-tiers.md` (the as-built notes and its n8n row), three Fork Checks comments, `mcp-server/index.ts` and check 28's comment.

**Not here.** The orchestration eval (`evals/orchestration/`) still dials `server:8000` over MCP from n8n, Windmill and Activepieces. SMD-2295's second PR re-aims all three to the REST core, rewording C2 to "the tool's own HTTP client" (the maintainer's choice). That PR also adds the rule to provisioning, refusing a brain credential pinned anywhere but `api`. Here it would refuse the eval kit's own unpinned read credential.
