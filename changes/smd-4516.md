## Changelog

The agent runner's hand-back comment says when a branch was not reviewed, and no longer names a branch, bundle and diff for a run that imported none (SMD-4516).

## Record

The hand-back comment says only what the run left, and says when its branch was not reviewed (SMD-4516)

**Problem.** `handbackComment` in `scripts/agent-runner/live.ts` writes the Linear comment that ends every live run. Publishing is not wired into the live run yet, so the comment is all a person reads of a run. Two things in it were wrong:

- A run whose review session did not finish goes on to the gate (SMD-4490). When the gate passed, the comment said "The run passed the gate — handed over for you to publish from the bundle". The only sign of no review was "(ended api-error)" beside the review's turns.
- Every comment said "Branch … is in the runner's bare repository … The bundle and diff are kept with the run's record." A run that ended before the import has none of the three: an environment failure at prepare, a worker that ended on an API error or its limit, a worker that left no bundle. The claim's release reason named the branch the same way.

**Change.**

- **`live.ts`:** `bundleKept` reads whether the run kept its bundle, which `run.ts` does only once the import landed. The comment names the branch and the bundle only then, and the diff only when one was kept. Otherwise it says the run kept nothing to publish from. The release reason follows the same test.
- **`publish.ts`:** the sentence for an unreviewed branch is one function, `unreviewedLine`, which the PR body and the hand-back comment both call. The PR body is as it was.
- **`live-check.ts`:** two sections, 12 cases (54 in all, from 42). The fake run's directory is now one the case makes, holding what that run kept.
- **The runner's README** says what the comment tells.

**Verify.**

- A gate pass whose review ended `api-error` gives a comment that says the branch was not reviewed.
- An environment failure at the work step gives a comment that names no branch, bundle or diff.
- Each case fails with its rule removed: twelve mutants of `live.ts` and `publish.ts`, each killed by an assertion (caught: mutant).
- The twelve runner self-checks pass.

**The probe stamp.** Neither `live.ts` nor `publish.ts` is hashed into it. The stamp holds.

**Review pass 1.**

- Without a kept bundle the comment and the release reason said nothing was imported. `run.ts` imports the bundle and then copies it beside the record, so a copy that fails leaves a branch and no bundle, and the sentence would be false. Both now say the run kept nothing to publish from, which holds either way, and the function is named for what it reads, `bundleKept` (caught: cold-read).
- The same sentence ended "What its sessions left is in the run's record", which a run that failed at prepare, with no session, did not fit. It says the record tells where the run stopped (caught: cold-read).

**Not done here.** No live run was made: the comment was read from the function's output on fixtures. A directory with a diff and no bundle is told as nothing kept; `run.ts` never leaves one.
