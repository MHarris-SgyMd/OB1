## Changelog

Two maintainer scripts for CI-efficiency work. `scripts/ci-step-times.ts` prints a CI job's time and its steps' over a window of runs, with each one's median, p90, min and max. `scripts/suite-sections.ts` runs a suite and prints its sections by wall time, slowest first (SMD-3305).

## FORK

Two maintainer scripts: a job's step times over a window of runs, a suite's sections by time (SMD-3305)

**What changed.**
- **`scripts/ci-step-times.ts --job <name> [--step <regex>] [--workflow] [--branch] [--days 7] [--runs <ids>] [--repo]`** reads runs through `gh`, six at a time.
  - For each run it prints the job's wall time and the steps chosen, marking a re-run's attempt.
  - Then, over the runs where the job succeeded, it prints each one's median, p90, min and max.
  - Steps are chosen by name across all runs: those `--step` matches, or with no pattern those that took a second or more in some run. So each step's figures read every run it ran in.
  - A skipped step is left out, rather than read as 0 s. A failed or cancelled job is listed and not counted. A run `gh` can't read is retried once, then passed over and said.
  - The window is the last `--days` × 24 hours, and a list that fills `gh`'s limit is said to be cut short. `--runs` refuses the window's options.
  - A job name that no run has is refused (exit 1), with the names the runs do have.
- **`scripts/suite-sections.ts [--top n] [--cwd dir] -- <command …>`** runs a suite and stamps each stdout line as it arrives.
  - Each section, a line that starts with a bracketed number or name (`[12]`, `[8e2]`, `[file]`), gets the time from its header to the next. The launch to the first header is `(start)`.
  - It prints the tally, the sections slowest first and the total, and says when there is no header at all.
  - The command's stderr and exit code pass through, and a command that can't start is refused (exit 2).
  - The command may follow without `--`, since Bun drops a leading one.
  - Times are only as good as the child's flushing, which the docblock says.
- Both follow `scripts/`' conventions: a header docblock, a known-flags table that refuses an unknown flag with exit 2, and `--self-check` fixtures for the parsing and the figures. CI typechecks them with the rest of `scripts/`. Neither is a gate.

**Why.** Eight CI-efficiency tickets wait on a step's time over a week of main's runs: SMD-3170, 3193, 3194, 3195, 3198, 3201, 3202 and 3263. Each check so far was a /tmp loop over `gh run view`, and SMD-3201's hardcoded one job and four steps. Finding what to cut was likewise a /tmp script, which found test-rest [12]'s 38 of its 44 s for SMD-3263.

**Measured**, the Verify's own cases:
- `bun scripts/ci-step-times.ts --job "Portable server" --step "REST core's routes"` over main's last 7 days took 21 s for 61 successful runs, where one run at a time took 1 min 42 s. The REST core step reads 57–58 s up to 8fe05eaa, 43–44 s from 31a74e8c (SMD-3201) and 16–17 s from 08fe0372 (SMD-3263), through 4594c369. A review checked two runs' job and step times by hand against `gh run view`.
- `bun scripts/suite-sections.ts --top 4 --cwd server-portable -- bun test-rest.ts` names [12] at 10.0 s of the suite's 15.1 s. test-auth's named sections and test-mcp's lettered ones read too.
- Both `--self-check`s pass, and `scripts/`' typecheck passes.

The same /tmp scripts gave two local tools that need no stack and stay out of the repo, in the maintainer's scratch kit: a suite mutant runner and a Linux CI-like suite runner.

**Review pass 1.** A cold read, and a run against real runs and four suites with 21 mutants on the self-checks.

- **Fixed:**
  - Bun drops a leading `--`, so `suite-sections.ts -- <command>`, the form its usage gives, was refused; the command now starts at the first word that is not an option (caught: cold-read);
  - a skipped step starts and ends at once, so a sometimes-run step read 0 s in its figures; skipped steps are left out (caught: cold-read);
  - `(start)` began at the first line of output, so the time before it, an import or with-postgres.sh's Postgres, fell in no section; it begins at the launch (caught: cold-read);
  - a command that could not start, or a missing `gh`, gave a stack trace and exit 1; both are refused (caught: cold-read);
  - one `gh run view` that failed, a TLS timeout among 50, lost the whole report; it is retried once, then passed over and said (caught: cold-read);
  - the window was a UTC day's start, up to a day longer than `--days`, and `gh`'s 500-run limit cut it silently; both fixed, and `--runs` refuses the window's options (caught: cold-read);
  - the section pattern missed `[8e2]` and every named header (`[file]`, `[end]`), lumping their time into the section before (caught: run-it);
  - with no `--step`, the one-second filter was applied per run, so a step's run count varied and its median leaned high; steps are chosen by name across runs (caught: run-it);
  - a job name no run had printed a line per run and exited 0; it is refused with the names the runs have (caught: run-it);
  - reading runs one at a time took about 2 s each; six at once (caught: run-it);
  - a re-run was not marked; its attempt is (caught: run-it);
  - the self-checks let p90 off by one at a count where 0.9n is not whole, a step of exactly one second, and too-loose header patterns through; fixtures for each (caught: mutant).
