## Changelog

Preflight's `walk index` remedy no longer offers "039's file alone against the direct connection", then 074's: both are templates only the migrator fills in, and 039 run through psql as shipped fails, telling the operator to drop a good staging index. It now gives the statements to run first, filled in at the column's width and grouped by table, with where to run them and how to size their memory, then 039 through the migrator as the ledger calls for — or, where those statements already leave 039 nothing to do, preflight again, and where the ledger is locked, a wait rather than a stopped server.
The `vector index memory` row's warning shares the steps and the wording while a staging index is left out (SMD-2880).

## FORK

Preflight's walk index remedy runs 039 through the migrator, after the steps 039's own decisions call for — no migration file by hand (SMD-2880)

**What changed.**
- `db/config.mjs` gains three pure helpers. test-schema holds the wording of each, word for word.
  - **`apply039(ledger)`:** how a remedy has 039 applied, by `ledger.state`.
    - `pending` (read, recording neither 039 nor a later file): a plain run.
    - `none`: a plain run, which with no ledger runs and records every file. It is not `--baseline`, which records 039 unrun.
    - `recorded`: the re-apply (server and workers stopped, `REAPPLY_COMMAND`, started again).
    - `hole` (a later file recorded without 039): the re-apply, since a plain run would apply 039 alone after 074 and leave two `match_thoughts` forms.
    - `unread`: the re-apply, which applies 039 either way, with preflight's `whyUnread`.
    - `locked` (the read timed out): nothing run — preflight again once released, since 039 itself may hold it.
  - **`plan039({ pairs, dim })`:** what 039's index swap does on each table that exists, decided as its DO block decides, from the indexes under the shipped and staging names (`{ def, valid }` or null).
    - 039's shape under the shipped name: skipped.
    - A valid halfvec index of another shape there (039's `LIKE '%halfvec%'`), which 039 stops on: first, on any brain, replaced. The staging index is built (or one of 039's shape kept), then, once that build finishes without error, the shipped one is dropped and the staging one renamed.
    - A valid staging index of another shape: first, dropped.
    - A free shipped name: first, filled. A staging index of 039's shape is renamed onto it, or one is built under it (after an INVALID staging index is dropped). A re-apply, or a run with no ledger, re-runs 001's and 007's `CREATE INDEX` ahead of 039 and would build a vector index there, then 039 its own.
    - Otherwise 039 swaps the staging index in. It adopts one of its shape. Where it would build one inside its transaction on a table past a million vectors, that build goes first, CONCURRENTLY, after an INVALID staging index is dropped.
    - The text says where to run the statements: psql, as the tables' owner, one at a time, since CONCURRENTLY refuses a transaction block. It sizes `maintenance_work_mem` before each CREATE, and the migrating role's for a build left to the migrator. Steps are grouped by table, each with its reason, and numbered.
    - `first`, `large` and `swaps` are returned too.
  - **`walkRemedy({ ledger, plan, bodyCasts })`:** the plan's steps, then `apply039`.
    - A locked ledger is waited out, steps and all.
    - Under a casting body, where the steps leave 039's shape under every name, it says "preflight again" and stops no server.
- `residentIndexes` and `memorySizing` lose SMD-2871's `builds`. `memoryRows(s, { ledger, plan })` leads its warning with why — 039 swaps the staging index(es) in, which changes the size — then the plan's steps and `apply039`.
- `server-portable/preflight.ts`:
  - `readPairs` reads both indexes on each table (valid or not), which tables exist, and the column's width (configured width as fallback). The walk index check reads it every run. The memory row reads it only while a staging index is left out, in its own `try`.

  - The old remedy string, its hand-applied 074 step and "the file alone against the direct connection" are gone.
- `db/config.d.mts` follows.
- `db/README.md`'s note on 039's by-hand path says the header's statements carry the placeholder, gives the width query, and says which remedies print the statements filled in.

**Not taken.**
- **Migration headers that say the same:** 004's "by hand in any SQL client", 035's "the file by hand", and 039's "re-applying it alone" and placeholder statements stay. The migrator compares each applied file's sha256 on `--reapply` and refuses a changed one.
- **A `migrate.ts --only <file>`:** no remedy left asks for a file alone.
- **The memory row's warning with nothing staged** still prints no steps. Its 039 lead is for a staging index left out, as SMD-2871 made it.
- **A halfvec index of another shape under the shipped name:** `plan039` replaces it, dropping its own settings. That is what 039's refusal asks for, and it is needed before the next `--reapply`.
- **The statements are unqualified,** as 039 writes them. With pgvector off the operator's search path they fail loudly (`type "halfvec" does not exist`); the re-apply then builds in its transaction, or stops on a shape it refuses.
