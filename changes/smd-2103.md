## Changelog

`recipes/brain-smoke-test` is retired: the harness needed a Supabase project to start, and `deploy/smoke.sh` now has the one check of its that applies here and that smoke.sh lacked. smoke.sh's check 1 sends no key and then a wrong key, and requires the JSON-RPC Unauthorized error (-32001) both times, not just an HTTP 200. No schema change (SMD-2103).

## FORK

brain-smoke-test retires into deploy/smoke.sh, whose first check now reads the refusal instead of trusting the 200 (SMD-2103)

**What changed.**
- `deploy/smoke.sh` check 1 is now two rows, each an `initialize` the server must refuse with JSON-RPC error -32001 (`JSON_RPC_UNAUTHORIZED_CODE`, `server-portable/index.ts`):
  - one sent with no key;
  - one sent with `x-brain-key` set to a key the server does not hold.
- A new `refusal()` helper prints the error code, or what came back instead: an HTTP status, "a result, not an error", or no envelope. The run is eleven rows instead of ten.
- `recipes/brain-smoke-test` (four files) is deleted.
- Check 24's `POSTGREST_EXCEPTIONS` loses the recipe's entry, and its three comments now count nineteen files.
- `docs/vendored-disposition.md`:
  - the rollup is now keep 77, remove 10;
  - the PostgREST class is 21 files in 14 recipes, a count that also catches up SMD-2239's retirement;
  - both of the recipe's rows read retired;
  - the `smart-ingest-tables` drift note is resolved, because its last instance was in `smoke-all.js`.

**Why.** `smoke-all.js` exited 2 before running anything unless `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` and `MCP_ACCESS_KEY` were all set. Of its seven categories:

| Category | On the fork |
|---|---|
| DB Schema | Needed PostgREST and a service-role key. `server-portable/preflight.ts`, the server's start gate, reads the schema in far more depth, and smoke.sh check 10 reports the ledger. |
| Access Key Enforcement | Needed PostgREST. Not applicable. |
| Row-Level Security | Needed an anon key. Not applicable. |
| REST API | Dialled `open-brain-rest`, which retires under SMD-1931. The opt-in `/api` through the proxy is SMD-2284's, and smoking it is SMD-2296's. |
| MCP Server | Already smoke.sh checks 5 and 6. |
| Core Features | Wrote rows. smoke.sh is read-only by design, and the suites and the full-stack job cover capture. |
| Auth | Partly covered: the header form is on every keyed check, and `?key=` is in `server-portable/test-auth.ts` in CI. It is left out of smoke.sh because the key would sit in URLs against production. The wrong-key refusal was not covered. |

Check 1 also had no teeth before: it compared the status alone, and a server with no key check answers `initialize` with HTTP 200 too.

**Held.** Run against stubs:
- a server that answers every request with a result fails both rows of check 1 ("a result, not an error"), which the old check 1 passed;
- a server that refuses only a missing key fails the wrong-key row;
- nothing listening fails both rows with HTTP 000;
- `server-portable/index.ts` with no database passes both rows.

The full-stack job runs smoke.sh against the real stack on every PR.

**Not taken.**
- Porting the harness to the fork's shape. Its REST target retires, and its schema category would duplicate preflight.
- A `?key=` row in smoke.sh, because of the URL-logging risk the recipe's own README spelled out.

**Upstream status.** Fork-only.
