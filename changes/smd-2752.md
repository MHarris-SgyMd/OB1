## Changelog

A database restart while the sleep scheduler starts a pass no longer ends it. Every statement an extraction or consolidation follower makes before its first claim now waits out a database that is not answering, on the same schedule as the follower's own outage waits, and so does the worker key's lookup, which used to carry on with the rows unattributed (SMD-2752).

## FORK

A follower's start outlasts the database going away, so the sleep scheduler survives a restart at any sleep (SMD-2752)

**What changed.**
- `db/worker-bootstrap.ts` gains `throughOutage(run, { check, wake, said, out, err })`, moved from `db/sleep.ts`'s `readThrough`, which the scheduler's own reads now call. It runs a statement again once the caller's `SELECT 1` answers, on `waitOut`'s schedule (SMD-2599: 5 s, doubling, at most 5 min). It reports the outage once and its end once, and returns null when `wake` ends the wait. Any other error is thrown.
- `db/extract-entities.ts` and `db/consolidate.ts` run every statement before the first claim through it under `--follow` (`atStart`):
  - extract: the tables check, the worker key's lookup, the `entity_extraction_key` read and write, and the `--retry-failed`, `--retry-partial` and `--retry-left-out` statements;
  - consolidate: the tables check, the worker key's lookup, 079's check, the relations grant read (`relationsOff`), and `--retry-failed`.

  A stop during the wait returns 130 before the pass begins, so a wake during it stops the pass as one that never started. A run without `--follow` is unchanged: the error still rejects.
- `workerIdentity` gains an `outage` option, which the followers set to `databaseUnavailable`. An error from `resolve_agent` that matches it is thrown for the caller to wait out. Before this, a database down there was a warning, and the run went on with no agent id on its rows.

**Why.** The scheduler starts its passes afresh at every sleep, about 16 a day on stable, so a database restarting at any of those starts reached a start statement outside every wait. That threw, the pass's rejection ended the scheduler, and the compose service spent one of its three restarts. A standalone follower meets that window once.

**Held.**

Each waits out all three outages, reports them, reaches its pass and fails nothing.
- test-live [38]: each engine, with a worker key whose lookup dials a closed port, waits rather than warning, and a stop then ends it with 130.

- Mutants: 10 of 10 killed, one for each of the six wrapped sites, each engine's `outage` option, `workerIdentity`'s rethrow, and `throughOutage`'s "answers again" line.
