## FORK

test-preflight's [9] moved to the rest shard: the first shard is [5] alone (SMD-3710)

**What changed.** In `server-portable/test-preflight.ts`, `SHARDS.first` is `["5"]`, where it was `["5", "9"]`; [9] now runs in the rest shard, in the preflight-rest job. The two shards still run every section once between them.

**Why.** Since SMD-3691 the rest shard runs in a job of its own, so the split no longer evens two legs. The first shard is the data layer's, beside `db/test-upgrade.ts`. Over the 16 newest green main runs to 87240d21:
- **on an AMD EPYC 7763** (eight runs), the first shard ended 16.3–25.6 s after test-upgrade, the job's floor. [9] took 17.2–19.0 s of it, almost all endpoint timeouts waited out, which don't shorten with CPU;
- **on the faster CPUs** (EPYC 9V45 and 9V74, five runs), the first shard already ended 2–15 s before test-upgrade, so the move takes nothing off there. The Xeon 8370C (two runs, 23–27 s) and 6975P-C (one run, 14 s) are like the 7763;
- **preflight-rest's job** ended 26–91 s before the data layer on the 7763, and 12–107 s before it on the other CPUs.

So the first shard should end about at test-upgrade on a 7763, and preflight-rest runs about 18 s longer. On the fastest runners (an EPYC 9V45 at 13 and 23 s ahead, a Xeon 6975P-C at 12 s) preflight-rest may now end after the data layer. Neither job is the run's critical path: in those runs the data layer ended 127 s or more before the run's last job, a schema-against-Postgres cell. So, as the ticket says, this buys the data layer headroom against the next creep, not run time.

**What [9] reads.** One case in [9] reads the database: a provider that is down, beside a reachable migrated brain, exits 0 with only a warning. It needs a brain that preflight passes. In the rest shard [9] now runs after [5b], as in a full run. [5b] ends with a brain preflight passes (`--json reports ok:true`), and [6], [7] and [8] between them never touch the database. [5]'s own end check stays, since it still shows that [5]'s fixtures clean up after themselves; only its words change.

**Comments.** The `SHARDS` docblock, [5]'s and [5b]'s end comments, the data-layer start step's comment, and preflight-rest's comment have the figures. The README's two shard lines name `SHARDS`, not its sections, so they still read right and are unchanged.

**Held.**
- **Every section runs once.** Main's last run (41955804078) counted 454 in the first shard and 573 in the rest, 1,027 in all. Here, each shard run locally under a `with-postgres.sh` of its own: first 396 of 396 ([5] alone, `[doc]`'s "1 listed"), rest 631 of 631, 1,027 in all. [9]'s 58 assertions moved.
- **[9]'s database case ran in the rest shard**, after [5b]: "a provider not up yet beside a reachable, migrated database exits 0", with no check failed.
