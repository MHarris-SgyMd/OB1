## Changelog

A scratch MCP server, `evals/mcp-clients/`, records which protocol revision a client offers and what makes it fetch the tool list again, and `docs/mcp-client-refresh.md` holds what it measured for Claude Code 2.1.325 (SMD-4344). No migration, and nothing the brain serves changes.

## Record

A probe for what makes an MCP client fetch the tool list again — Claude Code 2.1.325 measured: it refreshes on `subscriptions/listen`, not on `ttlMs`, and today's `/mcp` leaves it stale (SMD-4344)

**Why.** A key's tool list changes without the client's doing (a plugin enabled, a scope changed, a release that adds a tool), and a connected client keeps the list it fetched at connect. The MCP revisions offer several ways for a server to prompt a new `tools/list`: a notification on a 2025-era session's stream, a 404 to a session id, and in 2026-07-28 a `ttlMs` on the list or a notification on a `subscriptions/listen` stream. Which one works depends on the client, and none of it was measured. The brain's request log could not say even which revision a client offers: it records neither the version a request names nor the client's name.

**What changed.**

- `evals/mcp-clients/probe.ts`: a scratch MCP server on `@modelcontextprotocol/server` 2.4.0, bound to loopback, with no auth and two dummy tools. `/mcp` serves 2026-07-28 and stateless 2025-era traffic through the SDK's `createMcpHandler`; `/legacy` is 2025-era only, built per request with no session and POST only, as `mcp-server/app.ts` wires `/mcp` today; `/session` is 2025-era with sessions and a GET stream. It logs each request's HTTP method, MCP headers, JSON-RPC method, the revision named and the client's stated name and capabilities. Control routes add or remove one tool with a notification (`toggle`) or without one (`toggle-quiet`), forget every session (`expire`), cut every listen stream (`drop`) and set the `ttlMs` answered on `tools/list` (`ttl`).
- `evals/mcp-clients/selfcheck.ts`: the SDK's own client against each path, 20 rows, exit 1 when one fails.
- `evals/mcp-clients/run-claude-code.sh`: one headless Claude Code session that calls a tool, calls a control route itself, waits, and says whether the new tool is available; then the probe's log of that run, printed by `show.py`. The result is read from the log, not from the model's report.
- `evals/mcp-clients/run-claude-code-turns.sh`: one session of two user turns, the control route called from outside between them, for whether a new turn alone makes the client list again.
- `docs/mcp-client-refresh.md`: the table for Claude Code 2.1.325, what it means for the brain, what is not measured and how the measuring was done.

**What it found.** Claude Code 2.1.325 sends `server/discover` first and uses 2026-07-28 where that is answered; otherwise it initializes at 2025-11-25. On 2026-07-28 it opens `subscriptions/listen` with `toolsListChanged` unasked, lists again 4 ms after a notification, and opens the stream again 6 s after it is cut, listing at once. A `ttlMs` of 3 s and then 2 s made it list again in neither run (13 s and 51 s, a tool call after each wait), nor at the start of a new turn. On a 2025-era session it lists again 4 ms after a notification on the GET stream, and after a 404 to its session id it initializes again at its next call. Against a 2025-era server with no session and no stream, a new tool never appears, in the same turn or in a new one.

**Not changed.** Nothing the brain serves. The probe is not part of the stack, no suite or CI job runs it, and `evals/tsconfig.json` does not include it. Its SDK pin, 2.4.0, is the version the measurements were made with; the brain's own pin stays 2.1.0 until SMD-4342, and the pin guard holds `mcp-server/` and `server-portable/` alone.

**Not measured.** Claude Desktop, the claude.ai custom connector and the ChatGPT connector: each needs the probe at a public HTTPS URL, and the maintainer decided on 2026-11-14 not to put it at one. Interactive Claude Code, a `ttlMs` or a wait longer than the two runs', and paged lists.

**Held.**
- `bun selfcheck.ts` beside a running probe: 20 rows pass, twice in a row.
- The probe and the self-check type-check clean under `evals/tsconfig.json`'s options (`tsc --noEmit`, TypeScript 5, run outside the tree: the directory has no tsconfig of its own).
- `./run-claude-code.sh mcp toggle` from the committed directory reproduces the first row measured: `subscriptions/listen` opened at connect, `tools/list` sent again 3 ms after the toggle, the new tool called in the same session.
- Each one-turn case in the doc's table was run once, the `ttlMs` case twice; the two two-turn cases once each.
- The stateless 2025-era result is the probe's copy of the brain's wiring on SDK 2.4.0. The brain's own server, on 2.1.0, was not run.
- `bun scripts/check-consistency.ts` passes.
