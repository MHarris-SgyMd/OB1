## Changelog

The ingestion adapter contract: every capture source maps to a stable identity, a byte-for-byte canonical, a clean text, typed links and structured mentions (`db/ingest-contract.ts`), with a Linear adapter (`db/ingest-linear.ts` — the board sync and the ingester now render a ticket one way, autolink markup gone from the text, cross-references, parent and relations as edges, project and labels as mentions, no model call) and a Markdown/Obsidian adapter (`db/ingest-markdown.ts`, round-trip proven, lossy cases enumerated); migration 053 adds `thought_sources` (the canonical beside the thought), the `link` facet kind written as a set, `source_thought()`, and the structured-wins rule in `record_thought_entities`; `ingest-records.ts` merges metadata, clears a moved text's vector for `reembed.ts`, reports `held` for a source item another thought already is, gains a `markdown` source and a default-nothing allowlist for external content (`--allow` / `OB1_INGEST_ALLOW`) (SMD-1867).

## FORK

Every capture source maps to the same five things, the source form is kept and the text and edges are derived from it — the ingestion adapter contract, a Linear and a Markdown adapter, migration 053 (SMD-1867)

**What changed.** `db/ingest-contract.ts` is the one interface an adapter
implements: a pure map from one source item to an **identity** that survives a
rename on the source side (SMD-1813's rule), the **canonical** form byte for
byte with its media type, the clean **text** that is stored and embedded, the
**links** the source's structured layer states (`references | child_of | blocks
| blocked_by | relates_to | duplicate_of`, each naming its target by identity,
never by thought id), the **mentions** it names (entities, no model call) and
the **facets**; plus a `scope` the allowlist clears. The pipeline
(`db/ingest-records.ts`) owns what is common: the row on a deterministic id, the
fingerprint, metadata **merged** rather than replaced, a moved text's vector,
label and chunk rows cleared so `reembed.ts` pools it, and — in the record's own
transaction — the canonical, the links as a set and the mentions under
`source:<system>`. Two adapters implement it: `db/ingest-linear.ts` (the
reference: `renderIssue`, `issueFacets`, `stripAutolinks` moved here from
`sync-linear.ts`, which re-exports them, so the sync and the ingester render a
ticket one way; autolinks → `references`, parent → `child_of`, `relations` and
`inverseRelations` → the four relation links, project and labels → mentions;
the canonical is the issue as fetched, as JSON with keys in one order) and
`db/ingest-markdown.ts` (canonical = the file's bytes, decoded strictly; text =
frontmatter dropped, `[[wikilinks]]` flattened to alias or name, embeds, block
ids, callout markers, `%%comments%%` and highlights flattened; wikilinks →
`references`, tags → mentions; identity = the note's name, which is what a
wikilink names — a frontmatter `id` is a facet). The board sync gains a
`structure` hook on its Writer, called with the head row after every capture,
adoption, patch or edit; its fetch asks Linear for `relations` and
`inverseRelations` (a 50-issue batch still one request, ~1 s measured). The
ingester gains a `markdown` source, `--allow` / `OB1_INGEST_ALLOW` (exact
scopes, default nothing, the refusal counted and naming the knob — the fork's
own `fork`, `commit`, `memory` records are not external and not gated) and a
`patched` outcome.

**Migration 053.** `thought_sources` — one row per sourced thought: system,
identity, canonical, media type, sha256, ingest run; `UNIQUE (system,
identity)`; `record_thought_source()` writes it once (unchanged / updated /
inserted; `IDENTITY_HELD` names the holder rather than re-pointing);
`source_thought(system, identity)` resolves a target — the table first, then
for `linear` the board sync's `metadata.issue` claim at the head of a twin
chain, so links resolve on the dogfood brain the sync filled before 053. The
`link` facet kind, registered in `thought_facets_validate` (042's citation
branch verbatim beneath it): relation in the six, system one word, target a
non-empty identity, never the thought's own; the validator writes `origin:
structured`. `record_source_links(thought, system, links)` has SET semantics —
added / kept / closed (`valid_until = now()`, history, never deleted) / dropped
(malformed, unknown, self, duplicate after normalisation) — and a partial
unique index holds one active row per (thought, system, relation, target), so
no writer can double an edge. And the **resolution rule** in
`record_thought_entities`: a `source:<system>` key is a structured pass that
keeps its own rows as a set — the same set twice writes nothing; an `extract:*` pass replaces only extracted rows
(before, wholesale — the import would have vanished on the extractor's next
run); on the same (thought, entity) or (thought, from, to, relation) the
structured row stands, an extracted insert onto it does nothing and a
structured insert onto an extracted row takes it over.

**Why.** SMD-1865: the board load stored Linear's `<issue …>SMD-x</issue>`
autolinks verbatim — ~80 bytes per cross-reference, a cause of SMD-1864's
capture failures and of ~19% extraction failures — and threw away the
structure they carried, leaving 016's model to re-infer from prose what Linear
had stated. Every wiki-like source (SMD-949) carries the same two things, and a
text cleaned before it is stored cannot be written back: the round-trip rule
had to be settled before any connector.

**Held.** `test-schema.ts` [48]: the canonical round-trips and writes once,
`IDENTITY_HELD`, `source_thought` through the table, the claim and the chain
head, links as a set (close, re-add, other-system isolation, the validator's
refusals, the index), the resolution rule on mentions and edges in both
orders, re-apply. `test-live.ts` [19]: merge, `patched`, vector and chunks
cleared on an edit, a structured record end to end, `held`. `--self-check` on
each adapter and the two writers (markup out and one link per target; every
`MARKDOWN_LOSSY` case round-trips, invalid UTF-8 and NUL refused; the corpus
path and the exact-scope allowlist; the sync's hook once per head row, never
on a dry run or an outside holder, its import closure inside the container's
mounts). A read-only probe against Linear: 50 issues with relations in 1.1 s,
404 links, 0 texts holding markup.
