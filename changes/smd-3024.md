## FORK

db/bench-live.ts — what a running pass costs a live call, measured end to end and per model call (SMD-3024)

**What changed.**
- **What it times.** `db/bench-live.ts` times `search_thoughts` and `capture_thought` end to end through a brain's MCP endpoint, with one client in a closed loop. It also times a query embedding and a capture's metadata call directly, through the server's own `getEmbedding` and `extractMetadata`, against the same provider.
  - The call kinds are interleaved and never overlap.
  - One untimed call of each kind loads the models first.
- **What counts as ok.** A call counts as ok only when the JSON-RPC answer to its own request id carries a result and no error (`answerTo`, `outcomeOf`).
  - A capture whose tagging fell back, or that saved without a vector, is degraded, not ok. A capture saves without one when the gate refuses the call, or when the call is made and the provider fails (SMD-2888's `vectorFailed`).
  - A capture's id comes from `structuredContent.id`.
- **Probes.** Captures are real writes, each starting `SMD-3024 latency probe`. The run deletes its own at the end (`--keep-probes` keeps them).
- **Output and flags.** p95 prints only from 20 samples up. Flags are strict: a missing value, a repeated flag, or a count that isn't digits is refused before any call.
- **Docs.** `db/README.md`'s "bench-live.ts" says how to run it, against which brain, and what its columns don't mean.

**Why.** The sleep scheduler (SMD-1794) hard-stops its passes on any live call, to protect live latency on shared hardware: on the dogfood Mac, one Ollama on one GPU serves both the passes and the server. Nothing had measured that latency with a pass running, though SMD-1794's Verify owed it.

**Held.**
- **The check:** `bun db/bench-live.ts --self-check`, in fork-checks.yml ("Latency harness rules") and `db/ci-parity.sh`.
- **What it covers:**
  - The answer reader and the ok rule, against the failing inputs the first run's review found: an empty 200, a keepalive-only stream, an HTML page, an answer to another request, and a capture saved without a vector (refused, or its provider failed) or with its tagging failed.
  - Percentiles at n = 1, 12 and 40.
  - The schedule: every owed call once, in order, spread to the end of the run.
  - The flags, and the two query lists being disjoint.
- **Mutants:** eight, each undoing one of those, all fail it.

**Measured after.**
- **When and where:** 2026-10-15, on the canary at 2,211 thoughts, with qwen2.5:7b at `-np 3` and qwen3-embedding:4b on one Apple-silicon GPU.
- **States:** the canary's sleep was stopped, then the `workers` profile's never-yielding `extract` follower ran at one and two containers, with a baseline before and after.
- **Analysis:** paired against both baselines, with bootstrap 95% intervals.

| beside | capture | the 7B metadata call | search |
|---|---|---|---|
| one extraction stream | +15% (12–25%) | +21% (19.5–26%) | +27 ms (24–30) |
| two | +58% (54–64%) | +90% (71–120%) | +22 ms (20–25) |

- A capture is its metadata call plus 10–12 ms, and everything but the model stayed within ±2 ms across states.
- The harness's own calls decoded at 51, 43 and 30 tokens/s beside none, one and two streams.
- That run predates the fixes below, and none of them touched its numbers: all 160 searches are in the query log with results, and all 48 captures were tagged.

**Review passes.**

| pass | finding | caught | fix |
|---|---|---|---|
| 1 | a 200 whose body held no answer to this request counted as ok | cold read | the answer is read by request id (`answerTo`, `outcomeOf`) |
| 1 | the searches' and the direct embeds' queries rotated in step, so five embeds a run re-sent a prompt the provider had cached | cold read, walkthrough | `EMBED_QUERIES`, disjoint |
| 1 | a capture whose tagging fell back counted as ok | cold read | degraded captures fail |
| 1 | p95 at 12 samples is the slowest call, and baseline's was a cold model load | walkthrough | p95 from 20 samples up; a warm-up |
| 1 | the direct embeds are not a search's model cost (prefix cache) | walkthrough | stated in the header and README |

**Not taken.**
- **A database column.** The first run timed one of a search's three statements inside Postgres, a weak stand-in. End to end minus the model's time is the measure (±2 ms).
- **A reader for Ollama's log** giving per-request model time. The log already has it, and the split didn't change a conclusion.

**Follow-ups.** SMD-3034: each brain's sleep yields only to its own traffic, so one brain's passes slow the other's live calls on a shared model server. The consolidation state and the decision on the yield stay with SMD-3024 and SMD-1794.
