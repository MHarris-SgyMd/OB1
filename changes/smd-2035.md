## Changelog

The session capture hook lets a checkpoint's post land before the session's end posts, so the end supersedes the checkpoint instead of standing beside it (SMD-2035).

## FORK

A session's end steps aside for the checkpoint its child is still posting, and supersedes it (SMD-2035)

**What changed.** `recipes/session-capture-hook/session-capture.mjs`: before a
run posts a payload, `aheadOf` looks under `inflight/<pid>/` for a payload of
the same session that another live child holds and that is older than its own
— a payload's name leads with the millisecond it was prepared, so the names
order them. If there is one, the payload steps aside at once: back under
`pending/`, with one more look as it goes and the payload taken back if the
claim cleared meanwhile. After its run, the child that clears a session's
claim — by landing its payload, dropping it as obsolete, or failing on it —
follows up with the payloads of the sessions it cleared that wait under
`pending/`, a session's newest first, never one it has itself just returned
there, round after round while a round yields something and up to five in
all, and posts them with the pointer the state carries; failing that, the
next hook run does. Payload and state files are written beside, under the writer's
pid, and renamed into place, since sibling runs read them; a temp file a
child left mid-write is unlinked by the sweep, not swept. The follow-up
shares its five in rounds across the sessions it cleared. Every reader of a
session's files asks the file whose it is, not the tail two ids can share. The
pointer is the session's newest landed thought by the time its payload was
prepared — `pointerFor`: what the state records, or a landed payload whose
bookkeeping is still owed under `pending/` (`landedBefore` reads its
`captured_id`), as the seventh and eighth passes of SMD-1298 decided the
pointer at post time; a state whose time is unusable stands. A payload's own moment is
clamped to now, so a clock that ran ahead never ranks it over the state.
Whether a newer
summary of the session exists anywhere — in this run's hands, in the state,
landed and owed its bookkeeping (`landedAfter`), or in another live child's
hands about to post (`newerInFlight`) — is one predicate, asked before
stepping aside and before posting; an outdated payload is obsolete and steps
aside for nothing. A deferred outcome is neither a capture nor a failure.
Only the newer of two steps aside, so two children never wait on each other;
a child that is gone holds no one. The claim directory's mtime moves at every
payload, so the fifteen-minute sweep judges a run by its last step. The log
names what a run deferred and the pid holding the claim, and what it followed
up. `sessionPayloads` says which child holds each payload; the request
timeout has a name, `POST_TIMEOUT_MS`.

**Why.** SMD-2012 put PreCompact beside SessionEnd on the default path, and
its second review pass (cold read) found the case SMD-1989's record had named
as a gap the server would arbitrate: `/compact` then `/exit`, or an automatic
compaction on the last turn. The compaction's child posts A (an embedding
takes seconds; a `derived_from` refusal adds a retry); the end prepares B
meanwhile, with `supersedes` from a state that does not yet name A; B's child
lands first and writes the state; A lands after it, sees the state newer and
leaves it — right for the state — but A is a live thought whose `Checkpoint:`
line says "continuing" of a session that has ended, with no successor, beside
the final summary. Two current summaries, one of them wrong about its own
state.

**Held.** `test-session-capture.mjs` (in CI's repo-consistency job), a
section of its own: two compactions' payloads posted by one child against the
fake endpoint's 2.5 s answer, both sessions' ends prepared meanwhile and
posted in-process — each steps aside at once; three later ends of one session
reach `pending/` under names a hash-ordered directory reads out of order, and
the child follows up with all five: the newest of each session posted
superseding its checkpoint, the rest obsolete, `pending/` and `inflight/`
empty. The predecessor landing
with its state write failing (the state path a directory): the deferred end
supersedes the id read from the payload under `pending/`, and the next run
finishes both bookkeepings without posting. The pointer by the rule alone
over planted owed payloads: the newest by time, by `summary_at` not
`captured_at`, the state standing on a future or garbage time and against a
payload from a clock an hour ahead, a name's millisecond for a missing
`prepared_at`, the newest found in any directory order; the landed payload's
own id write failing, the follow-up still pointing at it. A run whose checkpoint post
failed following up with the end that stepped aside for it. A chained
compaction: the end stepping aside behind a checkpoint the child is itself
following up with, posted by the child's second round. Six ends of one
cleared session and two of another: the room shared in rounds, each

Two children finishing one session's owed bookkeepings together, no failed
rename. Temp files: a dead child's unlinked, a failed rename's gone, a stale
one pruned. Three sessions of three ends under the cap. An older
checkpoint whose end has landed in another child's hands, owed its
bookkeeping, or is in another live child's hands unposted: obsolete. The
follow-up leaving alone a failed post and a deferral of the run's own. A
deferred payload back under `pending/` while its run still posts another
session's slow one. A checkpoint its session's landed end outdates: obsolete,
not deferred. One run over five payloads against claims that never clear, at
once. A run that dropped a session's older payload for a newer one in
another child's hands following up with that session's payload once it
reaches `pending/`. The rules alone: what is ahead, what is newer in flight,
against a newer payload, another session's, a pid proven dead, `pending/`,
the run's own hands.

**Not taken.** Waiting, bounded, as the ticket's first option said and the
first cut did: a poll over the claims for up to a request's timeout under a
budget the run shared. It posted the end no sooner than the follow-up does,
and four review passes found their defects in the budget — an obsolete
payload spending it, a spent budget posting past a live predecessor, a
remainder of one poll tick, the by-hand form waiting inside a harness's
hook timeout. Server-side arbitration (the ticket's option 2): it needs a
session identity the server can see, which today is only in the content;
it pairs with the structured checkpoint field SMD-2013's design note should
settle. A per-session lock: the claim protocol already serialises by file,
and stepping aside is the loser's half of a lock. A shared read of the landed
payloads for the obsolete rule and the pointer: a few file reads in a
detached child. Dropping an older payload for a newer one in flight only
once it has landed (eighth review pass): that reopens the sweep race; a
summary is cumulative, and a newer post that fails is retried. Held by reading, not by a test: the take-back after stepping
aside (its window is the gap between two looks), the follow-up's cap of five,
and the by-hand forms' exit 0 on a deferred outcome, which the run-it review
drove against a copy with a two-second timeout while the wait stood.

**Boyscout.** After the stop signal, what the passes cut for space:
`lastAttemptMs`'s docblock, stranded above `sessionPayloads` since before
this branch, sits above its function; the clock rule — a recorded time,

and `momentOf`; the request timeout's comment no longer names the wait; the
