On the server, a forget takes every thought its name is: the id, standing or deleted, the thought keeping it as its `client_key`, and each deleted one whose tombstone kept it. No migration. **Upgrading:** upgrade the brains' servers before the hook: a v2.1.0 server takes the one thought a name resolves to, finding a deleted copy by its id alone, so a copy deleted there by its key answers `NOT_FOUND`, and a second thought under the name is left, each keeping its text. A fan-out hook pasted before 1.9.0 needs its matcher replaced to copy forgets.

## Record

Forget fan-out — the session hook copies a forget to the other brains, and a forget takes every thought its name is (SMD-1723)

**What changed.** The write fan-out (SMD-3314) copies `forget_thought` (session hook 1.9.0); SMD-1723's earlier record, migrations 139 and 144, is the forget itself.
- **The copy:** a forget through the connector's brain is repeated on each brain with a write key, by the id the first brain answered and `confirm` the same. It always detaches citations there (the maintainer's choice: a copy copies the text), and is retried by the thought's own `client_key`, which the reply names, where a brain knows it by that alone.
- **The queue:** a forget drops that brain's queued and given-up copies of the thought (pending/ and dead/), by its id or its key, an earlier forget kept.
- **The answers:** a copy forgotten there already is done; one the brain no longer knows is skipped, said so. A brain whose server has no `forget_thought` holds the copy until it is upgraded, and `--check` warns rather than fails. A copy whose reply names a thought not forgotten is kept and sent again.
- **The server:** a forget takes every thought its name is there: the id, standing or deleted; the thought keeping it as its `client_key`; each deleted one whose tombstone kept it. The others are listed (`alsoForgotten`, MCP's values `alsoForgottenIds`) and the thought's own key named (`clientKey`). A refusal or fault after the first thought is named in `notForgotten` (its id and code, a fault's `FAILED` with its SQLSTATE), the first staying forgotten; a `CITED` before the first stops the rest. Before the first, a refusal that leaves a text outranks `FORGOTTEN`, so the call sent again after a partial forget answers what still holds the text.

**Limits.**
- A capture whose own hook run queues it after the forget's is not dropped: the two runs are asynchronous.
- `--check` cannot tell a v2.1.0 server, which has `forget_thought` but takes one thought a name resolves to, from a current one: hence the upgrade order.
