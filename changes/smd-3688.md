## Changelog

`db/ci-parity.sh` runs `db/test-live.ts`'s four shards side by side, each on a Postgres of its own as Fork Checks' db-live cells are, and starts every lane once the installs are done, so a run holds six Postgres containers at once (the shared one, four shards, test-upgrade and test-preflight's). Before, the shards ran one after another on the shared Postgres, and the other lanes waited for the rest shard. A full run takes about 390 s on the maintainer's Mac, where it took about 1,140 (SMD-3688).

## FORK

ci-parity's test-live shards side by side, every lane from the start — ~1,140 → ~390 s (SMD-3688)

**What changed.**
- **Live lanes.** Each test-live shard is a lane of its own: the script runs itself again as `--live <shard>` under a `with-postgres.sh` per shard, as its pair lane already did with `--pair`. One Postgres per shard, not one Postgres with four databases: roles and backends are the cluster's, and the suite makes roles and counts connections (SMD-3617).
- **Every lane starts once the installs are done:** the four live lanes, the pair lane (test-upgrade, then test-preflight's two shards) and the database-free lane. The pair and database-free lanes used to wait for the rest shard, whose [2] edited the tracked `db/migrations/002` until SMD-3639. The shared Postgres keeps the data-layer job's suites, test-search-path to extensions' test-tools, in CI's order, so state one leaves behind is still caught.
- **Which shards start, held three ways:**
  - `LIVE_SHARDS` is read by sed from the file's rows of one shape, `OB1_LIVE_SHARD=<shard> run db test-live.ts`;
  - check 35 (`scripts/check-fork-consistency.ts`) holds each test-live row it reads to that shape, each shard once, and the sed line itself to its text;
  - a live lane fails unless it ran its own shard's row, which catches a row bash never reaches (dead code, after an `exit`, in a heredoc) or reaches in another shard's branch, which no line reader sees.
- **Reporting** is a block for each lane, in the order rest, sleep, long, extract, pair, database-free. A lane still running when the shared rows are done says which row it has in hand (SMD-3647). A Ctrl-C stops every lane and waits, within one 30 s deadline, for each lane's with-postgres.sh to remove its container.
- **Docs:** ci-parity's header and comments, test-live's header, db/README.md's shard lines and FORK.md say the shards run side by side; never two in one Postgres.
