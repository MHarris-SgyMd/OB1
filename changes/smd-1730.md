## FORK

`thought_audit` becomes the log of record — who from the key, the door, the ceiling on the content, stance, cites and the valid window on every write; immutable by rule; migration 045 (SMD-1730)

**Premise.** 008 made `thought_audit` the one row every capture, update and delete leaves, written by a trigger inside the mutating transaction, UPDATE and DELETE refused by a second trigger; 010 put a stable agent id beside the key's name; SMD-1541 made the five vendored servers pass an actor at all. SMD-1729 makes this table the log the rest of the program derives its views from, and for that it lacked the fields those views read and one rule. Nothing said whether the key belongs to the operator, to an agent or to an importer copying external text, so a read that wants "what the operator said" (SMD-1726) or "how far to trust this" (SMD-1724) had nothing to filter on. The door a write came through lived in `actor_context.via`, a key in the blob 008 declares "analytical only". Nothing recorded what a write claimed to rest on, its stance, or when the fact it states was true in the world. And "derived from the key, never the payload" was a sentence in the epic and nothing in the schema.

**Two columns for the two questions.** `actor_kind` is *who holds the key*; `trust` is *the ceiling on the content* — the same three words, `operator | agent | ingested`, ranked in that order. The case that settles it, from SMD-1724: the operator's key handing in an ingested web page is actor `operator`, trust `ingested`, which one column read two ways cannot say. trust is never above the kind: undeclared, it *is* the kind; declared lower, the declaration stands; declared higher, it is clamped to the kind and the attempt is recorded on the same row under `actor_context.claimed`. A key of unknown kind supports no claim above the floor — only a declared `ingested`, a lowering nobody can abuse, is kept. SMD-1724 and SMD-1726 are label-and-filter work on these two columns; both said the decision was this ticket's.

**The kind lives in the registry, and the function is the enforcer.** `ob1_agents` (010) gains `kind`, set by `set_agent_kind(label, kind)` — an upsert by label, so a key can be classified before its first request; `resolve_agent` then meets a known label with an unknown digest, its rotation branch, and attaches the hash. The audit trigger reads the kind by the envelope's `agent_id` (010), or by the key's name for a writer that never resolved one (SMD-1541's five servers, the workers), and never from the payload: the database never sees the key, so the row the operator classified is the one thing a claim can be checked against. Declined: a fourth field on `MCP_ACCESS_KEYS`' `name:scope:sha256`. 010's rule is that the environment authenticates and the table records who; a kind in the env would be a claim the env does not enforce, parsed by seven byte-identical `auth.ts` copies and quoted by every README that shows the grammar. Declined too: a second environment variable keyed by name — two lists to keep aligned. NULL is the honest value for a key nobody has classified, and preflight's `audit events` counts the keys and the rows waiting on one, naming `set_agent_kind` and the backfill as the remedy. The server changes nothing about how it authenticates.

**`origin` is a second column, and `source` becomes one vocabulary.** `origin` is the door — SMD-1541's `via`, promoted from `actor_context` on 008's own reasoning for promoting a key ("promoting a column is a migration, promoting a JSON key is an archaeology exercise"); the trigger strips it from the blob as 010 strips `agent_id`. `source` keeps its name and its meaning narrows to the row's own `metadata.source`: the trigger no longer reads an actor's `source`. Until now the column carried three vocabularies, as SMD-1541 noted on this ticket — the main server passed `"mcp"` (a transport), the workers their own names (a door), the five vendored servers nothing (the row's origin) — so `WHERE source = 'mcp'` found the main server's edits and missed every MCP door under `integrations/`. Every in-repo writer now passes `via`: `server-portable` sends its MCP server name, `open-brain`, from one constant; `consolidation-bio`, `db/consolidate.ts` and `db/reembed.ts` moved their names from `source` to `via`. An out-of-tree actor still sending `source` sees it land in `actor_context`, visible, rather than silently interpreted. The main server's captures still carry `source: "mcp"` in the row's own metadata, so that column reads as before for them.

**The event rides one envelope key.** `p_payload.event` on both inserting `upsert_thought` forms (the 4-argument form delegates), and a tenth, defaulted `p_event` on `update_thought` — 032's mechanism for a new parameter, carried one form further: the ACL of whichever older form is there (9-, 8- or 7-argument) is captured, all three are dropped, the ACL is replayed onto the new form, so the last definer leaves one function whatever state it meets. The shape: `{stance, cites, valid_from, valid_until, trust, actor_kind}`, validated by `validate_write_event` — stance one of three words; cites an array of UUID strings naming thoughts that exist, canonicalised as `validate_derived_from` does; the window two timestamps in order; trust and actor_kind one of three words; a key the shape does not have refused, so a misspelling cannot vanish. A bad *shape* is refused as 025 refuses a bad `derived_from` — the write is the choke point or it is an untrusted-input hole. A *claim* the key cannot support is clamped and recorded, not refused — the write is legitimate, the label is not. The functions set `ob1.event` unconditionally, an empty string when none, so a write in the same transaction cannot inherit the previous call's event; `delete_thought` is not redefined — a tombstone declares nothing and the trigger reads no event on DELETE — but its rows gain `actor_kind`, `trust` and `origin` from the actor it has set since 009.

**Immutable by rule.** `thought_audit_refuse_mutation` (008) gains the one lawful amendment this migration needs: under the transaction-local setting `ob1.audit_amend = 'backfill'`, an UPDATE may fill a NULL `actor_kind`, `trust` or `origin` and stamp `backfilled_at` — every other column byte-equal (`to_jsonb(OLD)` against `to_jsonb(NEW)` with the four removed), a set value never changed, DELETE never. The trigger itself knows which change is lawful, so nothing outside it — no grant, no `DISABLE TRIGGER` in a script — has to, and a test can assert that an UPDATE of `diff` is refused even under the setting. SMD-1723's redaction — the audit rows' content replaced by a marker and a hash, with its own event row — is the second named amendment and arrives with that ticket; it goes in this function.

**The backfill is a function.** `backfill_thought_audit_events(p_limit)` fills `origin` from `actor_context->>'via'` and `actor_kind` and `trust` from `ob1_agents` by `canonical_agent_id`, else by `actor_name`, stamping `backfilled_at` — 023's shape, callable again as kinds are set, `p_limit` bounding a pass. The migration calls it once: every SMD-1541 row gains its origin now; no row gains a kind at apply time, because no agent has one yet. Each backfilled row says so itself — that is the backfill's record; no sentinel audit row is written, because an audit row names a thought. Trust on a backfilled row is the kind (the undeclared rule; a row from before 045 declared nothing).

**Not here, said so.** MCP tool arguments for stance, cites, the window and trust: SMD-1733 (stance and cites, the grounding rule), SMD-1725 (the window, the `as_of` read) and SMD-1724 (trust, the label) give them semantics and add them; the store gains the argument with the first tool — plumbing with no caller is the pattern 025 declined for `thought_edges`. Facet events (042's comment on this ticket): a facet is a derived sidecar and SMD-1731's derivations table records its lineage; the event's `cites` is the record of what a *write* claimed to rest on, 042's rows the per-statement projection. Indexes on `origin`: no reader yet. The partition key is chosen and not applied — RANGE on `created_at` by month, the table being append-only so a closed month is cold; the table's COMMENT says so and SMD-1697's hundred-million bench decides when. Two partial indexes, on `actor_kind` and on `trust`, for the reads SMD-1724 and SMD-1726 build; the trigger's cost gains one primary-key lookup on `ob1_agents` per row.

**Version.** MINOR under the version rules: the columns are additive behind `IF NOT EXISTS`, and `update_thought`'s added parameter is defaulted, so every 9-argument call — the servers' by name, `reembed.ts`'s positional — resolves as before. The migration is the first past the planned first cut's range (`001..044`); the release step decides where it lands.
