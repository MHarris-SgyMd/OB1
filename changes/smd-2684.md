## Changelog

A new read tool, `plan_context` (REST: `POST /v1/plan-context`), hands an agent starting a request what the brain holds on it in one call, so the agent can judge whether and how to do the work before it plans. It doesn't plan or judge anything itself. `knowledge` is a search of the request with current work ranked first, each hit labelled as `search_thoughts` labels it. `board` lists the tickets those hits name, in agenda order, each with its status, blockers, claims and priority, with settled and not-yet-startable ones listed separately. `specs` and `procedures` say they aren't available yet and name the tickets they wait on. `tools` lists what your key may call. `gaps` lists what the read couldn't find. The agenda's scope gains `keys`, those tickets alone, and query_log gains a `plan_context` row (SMD-2684, migration 126). A measurement of whether one call helps an agent plan found the benefit not shown: plans after it cited more relevant rows on 11 of 20 requests and fewer on 5 (p 0.21), and the utilization report now reads a logged call as a search.

## Record

plan_context, PR 1: what the brain holds for a request, in one read (SMD-2684)

An agent starting a request asked the brain one search at a time, with no way to know what it didn't ask for, and the brain never said "I have little on this". The maintainer chose, on 2026-11-09, to read the board through the agenda with a new `keys` scope, so one ranking serves both reads. They also chose to log the call as its own query_log kind, with the board's tickets. PR 2 measures whether the read helps a plan, and turning it on by default waits on that number.

**What changed.**
- **Migration 126:**
  - `agenda`'s scope gains `keys`: 1 to 500 ticket keys, read as those tickets alone under every other rule, and refused beside another scope or a holder. The answer gains `keyed`: the named tickets the agenda doesn't rank (`others`: settled, or a status type the brain doesn't know, with their status), those a not_before ahead keeps out (`waiting`), and the keys no thought records whose prefix some ticket carries (`missing`: UTF-8 is no ticket), so each named key is said once. It is null without keys.
  - The function keeps 124's signature, and 123's eight-argument agenda is dropped as 124 drops it, so the file stands alone.
  - query_log's kind gains `plan_context`, and a CHECK requires such a row's query and its items array. The table, `result_items` and `filter` comments name the new row.
- **`core/plan.ts`:**
  - **knowledge:** the shared search (`runSearch`, hybrid with `prefer_current`, unlogged), labelled by `labelHits`, which is search_thoughts' labelling moved into a function both reads call.
  - **board:** `boardOf`, one agenda call with every flag on, given what is left of the deadline as its statement timeout. The store's `agenda` takes a `timeoutMs` ceiling, set in the call's own transaction.
  - **specs and procedures:** "not available", naming SMD-2683/1715 and SMD-1721.
  - **tools:** `toolsFor`, the manifest's tools and the enabled plugins' operations this key's scope unlocks.
  - **gaps:** values (`knowledgeGaps`, plus the board's).
  - **Bounds:** one deadline of 10 s holds the two waits. The query's embedding is stopped 2 s before it, leaving the board a reserve (`runSearch` takes a caller's signal) and answered by exact matches alone, without marking the provider down. The board's agenda call gets what is left; a board past it, an agenda before 126, or any other failure is a gap, not a failed read, and the log row's `filter` says which.
- **The tool:** schemas (`request`, `limit` 1 to 20), the manifest, REST `POST /v1/plan-context`, the MCP reply (`renderPlanContext`, reusing search_thoughts' hit blocks and the agenda's line, both now shared helpers), the regenerated REST client and tools.json.
- **Docs:** db/README.md (126, the count, the map), server-portable/README.md's tool table, SETUP.md and deploy/.env.example (the query log's new row).

**PR 2, the measure** (the ticket's last Verify bullet; the maintainer's choices, 2026-11-10; preregistered on the ticket before any measured run, hash `7815fb2226cf`):
- **`evals/eval-plan-context.ts`:**
  - the draw: 20 Backlog tickets of the board's own projects, filed 2026-09-01 to 11-09, ordered by a seeded hash (638 eligible);
  - the runs: headless Claude Code (`claude-sonnet-5-5`), each arm shown only its own brain tools, a run on another model or tool set invalid;
  - the blind sheets: every cited thought and 8 seen-but-uncited ones per request, naming no arm or cite;
  - the score: gold where both raters agree, κ, a sign test and the verdict rule, with SMD-1719's utilization computed by `utilization.ts`;
  - a `--self-check` of 72 probes, in CI.
- **The utilization report** (`evals/utilization.ts`, `eval-utilization.ts`): `SEARCH_KINDS` reads a logged `plan_context` call as a search, and `export-queries.ts` attributes over the same rows, labelling no query from a `plan_context` request. test-schema [39] holds every kind query_log allows to `SEARCH_KINDS` or to `NOT_SEARCH_KINDS`, and the literal both readers select with.
- **Result: not shown.**
  - A (one `plan_context` call) cited 56 relevant rows and B (free searching, up to 10 calls) 42.
  - A did better on 11 requests and worse on 5, with 4 tied: sign test p 0.21 against a bar of 0.10, mean +0.70.
  - Two blind raters, on Opus and Sonnet, agreed at κ 0.933 over 307 rows.
- **The arms cite differently.** A cites most of what its one call returned (126 of 160 hits), and 43% of its cites are relevant. B cites few, and 84% of its cites are relevant. SMD-1719's utilization, over the rows query_log would hold for the runs, is 78.8% for A and 22.9% for B. Cost was $0.92 for A and $1.33 for B.
- **Runs:** no run broke the experiment's rules. In 16 of B's 20 runs the planner first called a bare tool name, which was refused before the brain and is not counted. evals/README.md has the table and the caveats.
- **PR 2's review pass 1:** utilization was misfed: every ID a reply printed counted as a result, and every call as a search, so it read 29.6% and 13.7%. It now follows query_log's rows, a search's returned results and a fetch as an opened use; the verdict didn't change. The export now attributes over the report's rows. The draw's passing-over, an inline-only cite, the uncited sample's definition and the hash were held by no probe, and now are. `--draw` read one page per flag.
