## Changelog

The sleep scheduler wakes on a live write alone: a search no longer wakes it or holds it awake, whatever `OB1_QUERY_LOG` says, so its passes go on through a session of searches, which a running pass slows by 24–33 ms. It reads no `query_log`; its start says "a search does not wake it", and preflight's `sleep` row says "a live write wakes it; a search does not" and no longer warns about the query log being off or unreadable.
The `sleep` grant group, which only gave the scheduler's role that read, is retired, and the heartbeat row's `reads` word is gone from `brain_info`'s and keyed `/health`'s worker heartbeats (one an older scheduler wrote is ignored).
**Upgrading:** `migrate.ts --grant … --groups …,sleep` is refused by name (exit 2, nothing granted), so drop `sleep` from `--groups`; a role granted the group before keeps `SELECT` on `query_log` until it is taken back with `REVOKE SELECT ON query_log FROM <role>` or a re-grant with `--exact` (SMD-3315).

## FORK

A search no longer wakes the sleep scheduler, and the `sleep` grant group is retired (SMD-3315)

**What changed.**
- `db/sleep.ts`:
  - `newestLive` reads `thought_audit` alone. The wake, the quiet before a sleep, the wait after a budget stop and the dry run all count a live write and nothing else.
  - `readsQueryLog`, the start's three `query_log` lines and the "last read" go.
  - The header defines the quiet by writes. It notes that the 14-day replay behind the 300 s default counted reads, so its figures are the floor on writes alone.
- `db/pass-stamp.ts` and `server-portable/brain-info.ts`: `watching`, `LogReads` and the row's `reads` go. A `reads` word from an older scheduler's row is left off the parsed heartbeat.
- `server-portable/preflight.ts`: the `sleep` row no longer probes `query_log`, reads `OB1_QUERY_LOG` or offers its two remedies. What wakes the scheduler is one phrase, and nothing about it warns.
- `db/config.mjs`:
  - The `sleep` group, `OPT_IN_GRANT_GROUPS` and `DEFAULT_GRANT_GROUPS` go. A plain `--grant` issues every group in `ROLE_GRANT_GROUPS`.
  - `RETIRED_GRANT_GROUPS` names `sleep` with why. `migrate.ts --groups` refuses a retired name with that reason, apart from an unknown word, and grants nothing.
- Docs:
  - `db/README.md`: the grants table loses the **sleep** row; "What wakes it" defines "a live call" as a live write; the `--exact` paragraph says how a role loses the old read; the heartbeat paragraph covers `reads`.
  - `deploy/README.md`, `deploy/compose.yaml`'s `sleep` comment and `deploy/.env.example` follow.

**Why.** On 2026-10-25 the maintainer decided reads don't wake sleep (SMD-1794's last Verify item). SMD-3024 measured that a running pass costs a search 24–33 ms, against +20–240% for a capture, so stopping the passes for a search spent the sleep for little. Item 2's default, that a search doesn't count toward the quiet either, gives one rule for starting and waking. Then nothing reads `query_log`, so the group whose only grant was that read has no use. On 2026-10-26 the maintainer chose to drop it with v2.0.0. Refusing an unknown `--groups` name breaks a `--groups …,sleep` call on the `ob1-migrate` image, so this is a major change and rides v2.0.0.
