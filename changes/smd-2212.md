## Changelog

The `orchestration` profile ships its first n8n templates. An import runner (Bun and python3, no published port, its own key) runs an allowlisted pipeline's emitter as a user of its own over a read-only imports directory, refuses a batch with a line of another source, runs the ingestion pipeline under its own actor, and succeeds when the pipeline's rows all have a vector. A generic import template is loaded per pipeline, on a schedule and through an on-demand door that saves no runs. An act tool, `linear_file_issue`, is a multi-step Linear flow on its own MCP endpoint, loaded only when its Linear key is set. `db/ingest-records.ts` gains `--actor`. Provisioning skips an optional credential's workflows, unloads what a run no longer produces, refuses one of OB1's keys in any other credential, and resolves one template's reference to another (SMD-2212).

## FORK

The first n8n templates — the import runner and a generic import template, and an act tool on its own MCP endpoint (SMD-2212)

**What changed.** The ticket's Gmail and Linear templates moved to
SMD-2257 and SMD-2258, each behind its gate. This builds what nothing blocks.

**The import runner** (`deploy/orchestration/runner.ts`, image
`runner.Dockerfile`, compose `orchestration-runner` under the profile). The
ADR decided it in SMD-2210, and this builds it:
- `POST /run/<pipeline>` with `x-runner-key` (401 without, 403 wrong). A
  pipeline not in `pipelines.json` is 404, and a second run of one going is
  409.
- The emitter runs over `/imports/<pipeline>/`, a read-only mount of
  `deploy/imports/` (`IMPORTS_DIR`). It runs as `ob1-emitter`, with no
  secret in its environment, and it cannot read the runner's; the pipeline
  runs as `bun`.
  - The runner starts as root and keeps only the capabilities to change user
    and to signal a step (`su-exec`, `cap_drop: [ALL]`, `init`).
  - It refuses to start as root without `su-exec`.
- Every line must carry the pipeline's one source and scope, or the batch is
  refused whole before the ingester runs.
- Then `db/ingest-records.ts --source items --items - --allow <scope>
  --actor orchestration-runner`, then `db/reembed.ts`.
- The run succeeds when every row of the pipeline's source has a vector.
  reembed's exit code, which is 1 for any old failed row or another pass's
  leases, does not decide it.
- One deadline bounds the run (`OB1_RUNNER_TIMEOUT_S`). A step past it gets
  SIGTERM, then SIGKILL. Its pipes are abandoned once it exits, stdout is
  capped, and stderr keeps only a tail.
- The request names the pipeline only, so the export never passes through
  n8n. The ADR's "items in the request body" is amended to this.
- The allowlist ships empty. It is mounted from the checkout, so the runner
  and provisioning read one file. A line whose emitter the image lacks stops
  the runner at start. Each recipe's ticket (SMD-2147–2150, SMD-2021) adds
  its line, its emitter and its packages.
- The image copies the pipeline's import graph file by file, and its build
  resolves every import. (A bundle ran `scripts/fork-index.ts`'s main block,
  which writes `FORK.md`, measured.) `deploy/imports/` is kept out of git and
  of every build context.

**The import template:** two per-pipeline templates.
- `import.per-pipeline.json` is the import itself. Its schedule or a call
  runs the runner, and a Report step fails the run with the runner's reason.
- `import-on-demand.per-pipeline.json` is the door at
  `/webhook/ob1-import-<pipeline>`. It saves no runs and drops the request,
  so the run key never lands in n8n's store. It answers the report, or the
  reason with a 500.
- n8n waits for the runner for its deadline plus a minute.

**The act tool** (`templates/act-mcp.json`, `act-linear-file-issue.json`).
`/mcp/ob1-act` lists one tool, `linear_file_issue`, under `N8N_MCP_KEY`. The
tool calls a sub-workflow:
1. find the team, and the label among the team's and the workspace's;
2. create the label if missing;
3. create the issue, and answer its identifier and URL.

Its credential is `N8N_LINEAR_API_KEY`, pinned to `api.linear.app`, and
optional. No brain tools (decision 7).

**Provisioning** (`provision.ts`):
- `--init` writes `OB1_RUNNER_KEY`.
- A credential marked `optional` whose value is unset is skipped, with every
  workflow that needs it or names a skipped one.
- **Unloading:** a run unpublishes each workflow skipped that way, and each
  import instance whose pipeline is gone, and deletes a skipped optional
  credential. The key's scopes go from eight to ten (`workflow:deactivate`,
  `credential:delete`).
- None of OB1's own keys may sit in another credential of any type, or
  inside a longer value (`sharedSecrets`).
- `"ob1wf:<template>[:<pipeline>]"` names another workflow, which loads
  first. A reference to no template, and a cycle, are refused.
- `instanceFor` fills `{{pipeline}}`, `.everyHours`, `.webhookId` and
  `.timeoutMs`, and refuses any other `{{pipeline…}}`.

**`db/ingest-records.ts --actor <name>`** names the envelope. The door stays
`ingest-records` (test-live [19]). `db/ingest-items.ts` exports its scope
rule, which the runner applies to `pipelines.json`.

**The kit** loads the profile's templates, instanced for its own
`runner/pipelines.json` (`fixture`, `stray`, `snoop`). Two checks join K, P
and E:
- **A:** the act endpoint lists exactly `linear_file_issue`, refuses a
  missing and a wrong key, and runs to Linear's "no Linear team" for an
  absent team.
- **I:** five rows once, under `orchestration-runner`, each with a vector.
  A rerun writes nothing. `stray` is refused with the runner's reason,
  nothing written. `snoop`'s emitter cannot read the runner's environment.
  Neither key appears in n8n's saved import runs.
- **E** admits the runner's `:8090` and nothing else of it (39 cases).

**CI** runs `runner.ts --self-check`, builds the runner's image in the full
stack job, and pins the runner to no published port.

**Verified** live on pass 1's code (`--up n8n`, `--verify n8n --wait-schedule`,
SQLite):
- Every check passes: C1–C3, K, A and I, C1s (the schedule seen after
  601 s), and P (gone after 51 s).
- I: five rows with vectors, then a rerun that inserted nothing. `stray`
  was answered with its reason, `snoop` found the runner's environment
  unreadable, and the run key was in 0 of 23 saved import runs.
- The runner uses 11–12 MiB.
- The self-checks pass, `test-live` is 756/756, and 44 drop-the-mechanism
  mutants were killed across both commits.
