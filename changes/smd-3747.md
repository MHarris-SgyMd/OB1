## Changelog

The vendored servers' suites and shared install move from `extensions/` to `integrations/`, where most of those servers live, and what the extension servers left behind retires: the `_shared/sse.ts` keepalive copy, the core's `mcpReply` and `vendoredStalledLine` that only it used, `extensions/_shared/auth.ts`, and test-auth's MCP server checks, since no vendored MCP server is left on the shared install (the Vercel recipe's route runs on its own) (SMD-3747).
**Upgrading:** run `bun install` in `integrations/` in place of `extensions/` (`(cd integrations && bun install)`), and delete a leftover `extensions/node_modules`; a recipe resolves that install through `recipes/node_modules`, which now links to `../integrations/node_modules`. Checking out a commit from before this one deletes `integrations/node_modules`, an ignored directory to git, and puts back the links to `extensions/node_modules`: run `bun install` in `extensions/` there.

## FORK

The vendored servers' suites and install move to `integrations/`, and the MCP-only leftovers of the extension servers retire (SMD-3747)

**What changed.** SMD-3747 is two PRs (decided 2026-11-04): PR 1 here, the code and suites; PR 2 the extension template and the two remote-MCP primitives.
- **The suites and the install move.** `test-auth.ts`, `test-writes.ts`, `package.json` (renamed `ob1-vendored-tests`), `bun.lock` and `bunfig.toml` go from `extensions/` to `integrations/`. The integrations resolve the install from under it; `recipes/node_modules` is a committed link to `../integrations/node_modules`; `integrations/node_modules` is the install, no longer a link. `sync-auth` names the three copies left, and `sync-sse` goes. test-writes' scan of the vendored files for the tickets they name leaves out the suites now beside the install. CI's four steps, `db/ci-parity.sh`'s two runs and its install list, check 44's known directories and the checker's exceptions name `integrations/`.
- **What the extension servers left goes.**
  - `extensions/_shared/sse.ts`, the byte copy of `server-portable/sse.ts` every vendored MCP server's reply went through (SMD-2001), and with it the core's `mcpReply`, `vendoredStalledLine` and `withSseKeepalive`'s `stalledLine` option, which only the copy used.
  - `extensions/_shared/auth.ts`: no file under `extensions/` imports it. `server-portable/auth.ts`'s list of copies says so, and its three copies are rewritten from it.
  - test-auth's `mcp` kind and every check that held only it: the MCP servers' loop (scoped tool lists, three overlapping requests, revocation by tools/list), the keepalive probe and `mcpReply`'s edges, the live probe's MCP branch, the drift rules for a registered tool's block, a server built per request, a reply kept alive, the Accept patch and the browser allow-list, and the pinned SDK and `@hono/mcp` sections that held those servers' shapes at the runtime.
- **What replaces the checks that still matter.** The "each form a key may travel in" check asked an MCP server's tools/list; it now asks the HTTP API: under each of `x-access-key`, `x-brain-key`, a bearer and `?key=`, a read key passes the read probe and is told a write route writes. The same loop runs at each worker: a read key's dry run passes and its real run is refused, through every form. Each loop also sends a wrong key in each form and wants 401. A new guard fails any script under the three category directories that imports an MCP server package or builds a server transport (Streamable HTTP, SSE or stdio, in the spellings its own probe lists; the Vercel route, on its own install, named as the one exception), so a vendored MCP server brings the kind back before it lands. The byte-copy check also fails a `_shared/sse.ts` under those directories, and `sync-auth`'s command is held, not only the directories it names.
- **Which side of the version contract.** Vendored code and its test tooling, outside the contract (MAINTAINING.md, "Versioning"): a minor, with the Upgrading line above. The core's removed `sse.ts` exports were no route or setting of a shipped image.
- **Docs** name the new paths: CONTRIBUTING's dependency and vendored-server rules, `compat/supabase-sql`'s run section, the integrations' and editorial-policy's READMEs and code comments, `server-portable/README.md` and `package.json`, `db/test-support.ts`, `docs/mcp-sdk-v2-migration.md`, `docs/connector-taxonomy.md`, `docs/vendored-disposition.md`'s present-tense list, `extensions/README.md`, the shared-mcp primitive's note on its sample's imports, troubleshooting's install line and `deploy-remote-mcp`'s install paragraph. PR 2 rewrites the template and the two primitives.

**Why.** SMD-2311 made all six extensions plugins and deleted the last extension server; it left the suites, the install and the MCP-only machinery in `extensions/`, which now holds no server (filed as SMD-3747 with SMD-2311 PR 4b).
