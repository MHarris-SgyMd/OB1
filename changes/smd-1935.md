## Changelog

The entity graph no longer stores a migration number, a port, an address or a type word as an entity, and a person or place that is an identifier — a ticket id, a package, a path, a host, a branch glob — is stored as a project or a tool instead; migration 056 applies the rule at `record_thought_entities` for every pass and once over the rows already written (on the dogfood brain: 116 entities refused, 8 retyped, 4 merged into the entity of their new type). The capture-time `people` facet applies the same rule, so a package name or a ticket id is no longer a person (SMD-1935).

## FORK

The entity graph refuses a number or a type word as a name and retypes an identifier-shaped person or place, at the writer and over the rows before it; the people facet takes the same rule (SMD-1935)

**What changed.** Migration 056 and a JavaScript twin:

- **`entity_type_gate(name, type)`**, IMMUTABLE and STRICT, is the rule. It
  returns the type the graph stores a name under, or NULL to refuse it:
  - refused: a name whose `normalize_entity_name()` is digits, then any run of
    digits, dots, colons and spaces (`NUMERIC_NAME_RE`; `10/8` and
    `127.0.0.1:11434` fold into it), or a type-vocabulary word (`person`,
    `people`, `tools`, `entity` …);
  - retyped, for a `person` or `place` only: a ticket id to `project`; a URL,
    package or path, host, domain or file, snake_case name or glob, or
    host:port to `tool`, read on the name as written in ASCII classes;
  - otherwise the type given.
- **`record_thought_entities`** is redefined on 053's body. Each entity is
  written under the gate's type; a refused one is not written, and a relation
  naming it is dropped and counted as a relation to any unlisted entity is.
  The result gains `refused_entities` and `retyped_entities`, one per (type,
  name). An extraction is gated; a `source:` pass is not, since it states its
  names on the source's authority (a Linear label `2024`). Sentinel
  `ob1:name-gate`.
- **`apply_entity_type_gate()`** applies the rule to the rows written before
  it, each entity judged on its name and none a structured pass names. A
  refused entity's edges, mentions and row are deleted. A retyped one moves
  to its new type, or merges into the entity already holding that (type,
  name) by `merge_entities`' steps (016's function refuses a merge across
  types): the mentions the target lacks move, edges are re-pointed (a
  symmetric relation re-ordered, a duplicate or self-edge dropped), aliases
  and the seen-at pair fold in, and `merged_from` — a human's merge within
  the old type — crosses less any name the new type holds. The file runs it
  once and reports the counts as a NOTICE; it is idempotent, and a writer
  call already running 053's body at the commit is why it can be run again.
  A guard refuses a schema without 016 or 053 by name.
- **`server-portable/entity-gate.ts`** is the twin: `entityTypeGate`,
  `normalizeEntityName` (016's rule), the shapes and the vocabulary, with no
  imports so the server can load it. `NUMERIC_NAME_RE` moves here;
  `entities.ts` re-exports it.
- **`metadata.ts`**: `extractMetadata` drops a `people` name the gate refuses
  or that has a shape the ticket names (a ticket id, a URL, a package, a
  host:port) — not a dotted or underscored handle, since the facet has no type
  to retype to. The capture path and the board sync (`sync-linear.ts`) both
  get it.
- **`extract-entities.ts`** sums the two counts into its closing line.

**Why.** On the dogfood brain at 053, 107 of 3,384 entities were numbers
(17 of the 58 persons), 9 were type words, and 12 persons and places were
identifiers. SMD-1937 measured the ticket's proposed gate on 201 blind-graded
mentions first: the number and vocabulary rules are right, but refusing an
identifier-shaped person or place dropped 7 real entities — code artifacts,
which the maintainer decided are entities, typed `place` — for 1 junk mention.
So a shape corrects the type. A ticket id becomes a project because the graph
types 376 of them `project`. The URL shape is one step past SMD-1937's
measured shapes, for `http://127.0.0.1:65536/v1` typed `place`.

**Held.** One definition, in the database, as 016 keeps resolution there. The
twin is held to it by test-schema [51]: 53 probes asked of both engines, both
normalisers compared, and the SQL body checked to spell every pattern, the
trim and every word `entity-gate.ts` does and no other. Every class is spelled
out, whitespace included (`[^ \t\n\r\f\v]`, never `\S`), since Postgres reads
`\w` and `\s` by locale; the normaliser may still part on non-ASCII
whitespace, which only the people facet's refusal reads.

**Measured after.** 056 applied to a copy of the dogfood brain: 116 refused
(165 mentions, 153 edges), 8 moved, 4 merged (`hono/mcp` the person into the
tool, `SMD-1804` the person into the project, two hosts); 3,384 → 3,264
entities, persons 58 → 30, places 25 → 12, no numeric name left, and a second
run changes nothing.

**Not taken.**
- *Binding "migration 021" to a `migration:021` reference.* No such type; the
  ticket allows dropping it.
- *A prompt change, or an `ENTITY_PROMPT_VERSION` bump.* The gate sits at the
  writer, so a p2 answer stores what a p3 would; a prompt change needs
  eval-entities' measurement.
- *Rewriting stored `metadata.people`.* Every row write is an audit event;
  the facet is clean from the next capture or retag (SMD-1975).
- *Retiring graph-centrality's read-side numeric rule (`--keep-numeric`).* It
  still serves a brain from before 056.
- *Generic words, roles, and names no window holds* (SMD-1937's remaining
  junk): no shape rule reaches them.
- *Narrower rules for a general brain.* The shapes were measured on an
  engineering corpus: a place `Route-66` becomes a project and `St.Louis` a
  tool, and a topic `1984` or `9/11` is refused — the ticket's own rule
  (no bare-numeric entity). A retype loses nothing; the refusal does.
- *Keeping a structured row in a merge.* `merge_entities` keeps the target's
  row, and the pass follows it; a structured pass names no person or place,
  and the pass skips what one names, so no structured row is merged.
