## Changelog

The sleep scheduler no longer runs re-embed under an embedding model name the heartbeat rows cannot carry: a character outside ASCII letters, digits and `. _ : @ / + -`, or a name and width longer than 120 characters as `<name>@<width>`, which a hand follower's row holds. It ran re-embed under such a name, and every reader of its row read it as running none, so preflight offered a hand run beside it. It now keeps re-embed out of sleep and says so once at its start, as it already did for a width that forms no key, and `db/reembed.ts --follow` refuses such a name, since no reader would see its row. Preflight's `sleep` row names the cause. A backlog under such a name is re-embedded by a one-shot run by hand (SMD-3486).

## FORK

The sleep scheduler runs re-embed only under a key its row carries, and one alphabet for model names serves the writer and every reader (SMD-3486)

**What changed.**
- **`server-portable/brain-info.ts`:**
  - `NAME_CHARS`, a model name's alphabet as one character class. `shellWord`, `REEMBED_OWN_KEY`, `modelName`, `HEARTBEAT_KEY` and `JOB_TOKEN` are built from it, and so is sleep.ts's `FOLLOWER_KEY`. These were six copies of one class; the SQL that reads `FOLLOWER_KEY.source` gets the same text.
  - `reembedKeyUnfit(model, dim)` returns `"width"` or `"model"` where a model and width form no re-embed key the rows carry, and null where they do. It is null exactly where the parse keeps both the scheduler's `reembedJob` and a hand follower's row under that key (`heartbeat:reembed:<model>@<dim>`, the shorter bound), so the scheduler sees, and refuses beside, any follower of the key it runs.
  - `reembedRunner`: a stopped scheduler, judged by this configuration, runs no re-embed where that configuration's key is one no row carries, since started again it would run none.
- **`db/sleep.ts`:** `REEMBED_OK` is `reembedKeyUnfit(...) === null`, where it had checked the width alone. A model name outside the alphabet keeps re-embed out of sleep, said once at the start, without printing the name, and the asleep line no longer promises re-embed. The width's message names its bound (at most nine digits).
- **`db/reembed.ts`:** a follower of its own (`--follow`, no caller's stamper) whose heartbeat key no reader takes is refused, exit 2, writing no row; a one-shot run writes none and is the way. The commands it prints with a model name or key in them — the model-switch refusals, `--retire`'s, the backfill hint — quote them (`shellWord`), so they paste under any name. Its header says so.
- **`server-portable/preflight.ts`:**
  - The `sleep` row, on a row with no re-embed key, or a stopped one, under a model name that forms none, says re-embed does not run in sleep and why. It is not a warning: the vector models and re-embed pass rows warn when a backlog waits. It names a hand re-embed follower there too, which that scheduler still refuses beside.
  - The `workers` row: beside a scheduler that takes re-embed, a stopped hand follower's row is retired, as before. Under such a name and no scheduler that takes re-embed — one that refuses beside a follower, or none at all — it is retired too, since started again it would be refused: a one-shot run for the backlog, a backfill finished under its own key, a pass to another model left to the re-embed pass row. Never "start it again".
  - A stopped `sleep` row's set-down is no fix under such a name: started again, nothing sets re-embed down.
  - The `vector models` row's own key follows the same rule.
- **`db/README.md`:** the heartbeat paragraph says such a scheduler keeps re-embed out and says so, and states the alphabet and the bound; the `--follow` line names its refusal. **`deploy/README.md`:** a model change under such a name is finished by hand, not by a sleep.

**Why.** Held by SMD-2679 PR 4b-2's review pass 7: a scheduler whose model name or width its row cannot carry was read as running no re-embed. The writer ran re-embed under any name, and its readers took only names in the alphabet. With rows pending, the re-embed pass row offered "Finish it" by hand, and a one-shot run writes no heartbeat, so nothing refused it beside the scheduler. The alphabet is a safety bound (preflight prints these names inside commands to paste), so the writer moved to it rather than the readers widening.
