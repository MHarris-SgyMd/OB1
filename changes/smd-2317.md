## Changelog

A command that drops a schema asks the server which database it reached: `dropSchema` and `tier.ts --refresh` refuse when an exported `PGDATABASE` beat the URL's database, or the URL names none, and every `db/` script refuses a database URL that Bun and libpq read as different targets (a query key other than `sslmode`, `application_name` and `options`, a fragment, a stray `@`, a host list), whatever `OB1_ALLOW_REMOTE_DB` says (SMD-2317).

## FORK

The reset guards ask the connection, not the URL — a URL two clients read as two databases is refused, and PGDATABASE no longer picks what is dropped (SMD-2317)

**What changed.** `db/connect.ts`'s resolver and reset rule, and their two
destructive callers.
- `databaseUrlProblem`, in the resolver every script uses (`databaseUrl`,
  `openSql`), refuses a URL that Bun and libpq take to different places:
  - a query key other than `sslmode`, `application_name` and `options` (`URL_QUERY_KEYS`),
    or one given twice;
  - a fragment, an `@` other than the one ending the user, a `,` in the host;
  - leading or trailing whitespace, a tab or newline inside, or a scheme that
    is not an exact `postgres://` or `postgresql://`.

  The reason names a query key when it is a plain word, and nothing else of
  the URL.
- The reset rule has a part no override lifts. `identityRefusal` refuses,
  before connecting, a URL the resolver refuses or one naming no database.
  `reachedDatabaseRefusal` asks the live connection for `current_database()`
  and refuses one that is not the URL's. `socketRefusal` refuses a unix-socket
  connection unless `OB1_ALLOW_REMOTE_DB=1`, which still lifts the loopback
  host rule as before.
- `test-support.ts`: `assertThrowawayDatabase` is async and asks the server
  too. `dropSchema` asks on the connection that drops. A refusal no override
  lifts says so instead of offering `OB1_ALLOW_REMOTE_DB`. The five callers
  (`bench-hnsw.ts`, `test-bench-reuse.ts`, three evals) await it.
- `tier.ts --refresh` checks both sides' URLs before opening either, asks
  each side's server for its database at the guard, and asks `--to` again on
  the connection that marks and drops.

**Why.** SMD-2302's review measured three readers of one URL disagreeing:
the rule, Bun 1.4.0, and libpq 17's `pg_dump`/`pg_restore`.
- Bun forwards `?database=`/`?user=` to the server, which keeps the last
  value, and connects over a unix socket for `?path=`. Its `options` still
  name the URL's database.
- An exported `PGDATABASE` beats the URL's database in Bun.
  `dropSchema(".../canary")` with `PGDATABASE=stable` dropped stable's
  `thoughts`, `schema_migrations` and `ob1_config`.
- libpq has no fragment, ends the user at the first `@`, and follows
  `?host=`/`hostaddr=`/`port=`/`dbname=`/`service=`. With
  `--to …/canary?host=stable-host`, every guard judged canary and
  `pg_restore` restored into stable-host.

Two passes of that review reconciled the readers by parsing the URL, and
both leaked. This asks the server instead, and refuses what cannot be
reconciled.

**Where the ticket's sketch moved.** The ticket proposed refusing a server
address outside 127.0.0.0/8, and building `pg_restore`'s target from the
server's reported address and port. Through a container's published port,
a connection to `127.0.0.1:55062` reached a server reporting
`inet_server_addr()` 10.88.11.140, port 5432 (podman, measured). So that
rule would refuse every `with-postgres.sh` run and CI's service container,
and that target is unreachable from the host. From the server, a port
forward and an ssh tunnel look the same. The address answers "is this
machine" for neither; the database name answers "is this the database you
named" for both. The loopback rule stays on the hostname. The ticket's
allowlist of `sslmode` and `application_name` rested on a grep for literal
URLs; `test-upgrade` failed on it, because the fork documents `options=`
(`-c search_path=…`) as the route for a path pgvector sits off (SETUP.md,
preflight's advice, SMD-2238), and suites build such URLs at run time.
`options` names no host, database or user, and both readers send it to the
server alike, so it is on the allowlist.

**Held.**
- `test-connect.ts` (684 checks, hermetic):
  - the resolver's refusal table (eighteen shapes, each with the override set);
  - accepted shapes and `databaseOf` decoding;
  - the connected half against a stand-in connection;
  - a startup packet read off a listener: an accepted URL sends user, database
    and `application_name` beside Bun's own `client_encoding` and `DateStyle`,
    and `?database=`/`?user=`/`?path=`/`?options=` open no connection;
  - both `tier.ts --refresh` sides refused before connecting;
  - zero connections to a reachable listener under the override;
  - every `assertThrowawayDatabase` call in `db/` and `evals/` awaited.
- `test-live` [34] (real server, two scratch databases, each with a
  `thoughts` marker):
  - `dropSchema` with `PGDATABASE` diverted refuses, with or without the
    override, and drops neither database. Controls: a `PGDATABASE` equal to
    the URL's, and none, drop the URL's database only.
  - `refresh()` with `PGDATABASE` diverted refuses a diverted `--from`, and a
    diverted `--to`.
  - A stand-in `pg_dump` holds the refresh while `PGDATABASE` changes after
    the guard: the dropping connection refuses, and the other database is
    neither marked nor dropped.
- 24 mutants, each removing or weakening one check, all killed: 19 by
  `test-connect` (each resolver shape, the override's reach, decoding, the
  refusal's wording, `tier.ts`'s identity loop, an unawaited call), and 5 by
  [34] (`dropSchema`'s connected check, removed whole or its database half, and
  each of `tier.ts`'s three connected checks).

**Not taken.**
- Pinning the URL's database in `openSql` (SMD-2302 pass 3 split a run
  across two databases).
- Comparing `inet_server_addr()` with loopback (above).

**Follow-ups.** SMD-2317's second PR: the environment-borne libpq redirects
(`PGHOSTADDR`, `PGSERVICE`) that reach `pg_dump`/`pg_restore` when the URL
itself is clean. The plan: a keyword connection string with the password in
`PGPASSWORD` and redirecting `PG*` variables removed, and a `pg_dump` identity
probe of `--to` before the drop.
