## FORK

Preflight's `schema` row prints the exact search-path statement — the role's path parsed as Postgres parses it, rebuilt quoted, public added (SMD-2242)

**What changed.** SMD-2062 left the `schema` row a template: `ALTER ROLE r IN DATABASE d SET search_path = <the schemas it has>, public`. With no USAGE on `public`, it offered the path fix only "if public is not on the role's search_path". Now:

- **`server-portable/search-path.ts`** (new) parses a search_path setting as Postgres's `SplitIdentifierString` does:
  - names separated by commas;
  - around them, only space, tab, newline, CR and FF count as whitespace;
  - a quoted name is kept as written, `""` inside it a quote;
  - an unquoted name is folded A–Z only;
  - the empty name a `''` path reads back as is dropped.

  `withPublic()` rebuilds the path with every name quoted and `public` last.
- **The probe** also reads `current_setting('search_path')` and its `pg_settings.source`, and names each cause that holds, each with its statement:
  - no USAGE: `GRANT USAGE ON SCHEMA public TO <role>;`
  - `public` off the path: `ALTER ROLE <role> IN DATABASE <db> SET search_path = <its schemas, quoted>, public;`.
  - Where the connection string sets the path (source `client`), which outranks every `ALTER ROLE`, the row says to set it there instead.
  - With USAGE held, a table that exists and does not resolve is off the path whatever the parse says, so a migrated brain never falls back to "Apply the migrations".

**Why.** The template made the operator work out the role's path and quote it. SMD-2062's review passes 2–4 built the exact statement, then split it out of that PR for size. They also found what an exact statement has to get right:
- echoing the setting printed invalid SQL for an empty path (`""`) and for a raw `$user`;
- worse, it pasted a raw path a role had stored (`set_config`, then `SET search_path FROM CURRENT`) into the remedy. A reviewer stored `x;drop/**/table/**/…;--`, and piping the printed line into psql as postgres ran the DROP.
- A parser using `/\s/` read an NBSP before `public` as whitespace, bringing "Apply the migrations" back on a migrated brain.
- `toLowerCase()` folded `Ü`, naming a different schema.

**Held.** test-preflight, 463 → 483:

- **[4b]** fourteen settings read as Postgres reads them: quotes, doubled quotes, `""`, case, a quoted comma, tab/newline/CR/FF, an NBSP and a `\v` that are not whitespace, `Ü`, and an injection-shaped name. Also `withPublic`'s order and quoting.
- **The ticket's role** gets `ALTER ROLE pf_reader IN DATABASE … SET search_path = "nowhere", public;`.
- **An empty path:** the row says so and sets `public` alone.
- **A raw path stored `FROM CURRENT`:** `"$user", "Odd ""x", NoWhere,<NBSP>public, x;drop/**/table/**/pf_sentinel;--` becomes `"$user", "Odd ""x", "nowhere", "<NBSP>public", "x;drop/**/table/**/pf_sentinel;--", public`. Run as printed, as the owner, it makes `thoughts` resolve for the role, and the sentinel table stands.
- **A path from the connection string** is fixed there.
- **No USAGE with the path at `nowhere`:** both statements.
- **No USAGE with `PUBLIC` in the connection string:** the GRANT alone, since an unquoted `PUBLIC` is `public`.

**Measured after.** A fuzz against PG16: random raw settings through `set_config`, mixing quoted and unquoted names with odd cases, commas, quotes, `Ü`, NBSP, BOM, U+2028, U+3000 and `\v`. For each accepted setting:
- the parser matched `current_schemas(false)`;
- `SET search_path = <withPublic(parsed)>` resolved to the old path with `public` last.

Result: 0 divergences and 0 round-trip failures in 3,125 accepted settings. The same fuzz with `/\s/` gave 822 divergences in 1,223, and with `toLowerCase()` 91 in 1,275.

Ten mutants against test-preflight: nine killed, one equivalent.

- **Killed:**
  - the whitespace class widened to `\s`;
  - non-ASCII folded;
  - unquoted names not folded;
  - `""` kept as a name;
  - a doubled quote not unescaped;
  - names echoed unquoted;
  - `public` not moved last;
  - only the first cause named;
  - the connection string not told apart.
- **Equivalent:** "USAGE held is taken as off the path". It acts only where the parse disagrees with Postgres, and the fuzz found no such setting.

**Not taken.**

- **Aligning the `vector extension` row's statement** (plain `ALTER ROLE`, `public` twice): SMD-2238 owns that row's remedy.
- **Terminal escapes:** a quoted schema name carrying ESC sequences reaches the screen raw, as role names, database names and Postgres error text already do. That belongs to preflight's printer, not to this row.
- **Truncating a name over 63 bytes:** Postgres truncates the rebuilt statement's names the same way, and no truncation can yield `public`.
