## Changelog

From 2.0.0 the fork's version is plain `MAJOR.MINOR.PATCH`: the `+upstream.<sha>` build metadata 1.0.0 to 1.9.0 carried is dropped, since the upstream pin is frozen. A release still records the pin, as data, in `releases.json`'s `upstream` key and the release notes. A brain stamped in the old form orders by its core, so `1.9.0+upstream.9543c29` reads as behind a `2.0.0` server. FORK.md's "Cutting a release" section is back: the two-commit cut, the canary soak (24 hours for the cutover) and the deprecation window. **Upgrading:** a client that parses the version a brain reports (`brain_info`, `GET /health`, the MCP `initialize` reply) and expects the `+upstream.` suffix stops finding it from 2.0.0 (SMD-3317).

## FORK

The version drops its +upstream suffix from 2.0.0, and FORK.md's "Cutting a release" section is restored (SMD-3317)

**What changed.**
- `scripts/assemble-release.ts`: `bumpVersion` and `nextVersion` return plain `MAJOR.MINOR.PATCH`, dropping build metadata from the version they bump; the release entry's `upstream` key stays the pin. Its dry run on main proposes `2.0.0`.
- `db/version.mjs`: the scheme's comment says plain from 2.0.0. `FORK_VERSION` is the last cut's string as written (`"1.9.0+upstream.9543c29"`), not built from `UPSTREAM_PIN`, so the 2.0.0 cut writes `"2.0.0"` there; `UPSTREAM_PIN` stays, the data a release records. `db/version.d.mts` matches.
- FORK.md:
  - "Versioning" states the plain form, the 1.x form as history, the pin as data and the cores' ordering.
  - The stamp paragraph adds that a stamp is plain from 2.0.0.
  - "A release is a tag naming three things" keeps the pin, as data.
  - **"Cutting a release" is restored.** It covers the bump; the two commits in order (the version and its stamp migration, then `--write`); rebuilding on a moved `main`; the tag and the release job; and the soak on the canary as it is (an in-place writer fed stable's inputs; the cutover soaks at least 24 hours).
  - The MAJOR rule's deprecation sentence gains the two-week window.
  - The section resolves the citations in CONTRIBUTING.md, db/README.md, `db/version.mjs` and the nine frozen stamp migrations (051…103).
- CONTRIBUTING.md, db/README.md and deploy/README.md state the format plainly, with the 1.x form as history.

**Why.** The maintainer froze the pin on 2026-10-25 (SMD-1256 canceled) and decided v2.0.0 ships plain. On 2026-10-26 they decided a release keeps the pin as data. The cut is no earlier than 2026-11-03, so this lands first. The "Cutting a release" section went missing with an earlier rewrite while ten files still cited it, and no doc stated the soak rule.
