## Changelog

CI shift gives a read GitHub fails three times a late try, three more tries 60 s later, before a gap fails the run, so a passing 502 from GitHub no longer turns main red; the report names the runs read on that late try (SMD-3690).

## FORK

CI shift gives a read GitHub fails a late try before a gap fails the run (SMD-3690)

**What changed** in `scripts/ci-step-times.ts`, with `--shift` alone:
- **A late try, `LATE_MS` (60 s).** A call that fails all three of `gh()`'s tries, 3 s apart, gets a late try: `gh()` again, three more tries, 60 s on.
  - **A run's read** gets it after the window's other runs are read, through the new `readRuns`. One pause covers every run that needs one.
  - **Only the runs a gap among fails the job** get it (`lateTried`): the window's newest 26 and the run reported on. An older run not read is still a warning with no late try. This bounds a wide outage's time. The run reported on is the window's newest today, so already among the 26; it is named as a guard, so the set holds gapVerdict's early check whatever a window's end becomes.
  - **A run that came back with no status** gets the same late try. It was a gap like a failed read before.
  - **The list** (`gh run list`) gets it at once, through `ghLate`, since nothing else can run while it waits.
  - **A run where every read succeeds** pays nothing.
- **The gap rule is unchanged.** A counted run still not read fails the run as before, and its note now says the late try was made too ("not read on its late try either"). So does "none of the 40 runs could be read" when every read fails.
- **The report names the late reads.** The log says each run read late, and the shift report gives a line listing them, in the step summary too. A run whose late read finds it re-run is a re-run gap, as before, not a late read.
- **The per-job report is unchanged:** no late try and no pause, so a typo in `--workflow` costs no extra 60 s on a laptop. With `--shift` a typo still waits out the list's late try (about 66 s), as any failure of the list does.
- **`selfCheck` is async,** to await `readRuns` and `ghLate` on stub readers. `ghLate` takes its call and its pause as arguments for that.
- **`.github/workflows/ci-shift.yml`:** `timeout-minutes` 10 → 20, and its header comment says why. Stubbed wide outages of slow 502s (see Held) took 566 s, and 670 s with the list's late try too. A run named further back lists twice, about 2.5 min more. A run cut off at the limit would say nothing of why.
- **The script's header** says so. FORK.md's file list is left alone: the line would take the front door 32 bytes over its cap.

**Why.** 33 of CI shift's 35 runs on main were green from SMD-3467's merge to 11-02. Both failures were GitHub answering `HTTP 502` to a run's jobs on all three tries, with the run among the window's newest 26:
- run 41108715664 (10-30): six runs failed, and the step took 80 s;
- run 41156298413 (10-31): one run failed, run 40923234493, and the step took 48 s.

Green steps take 11–20 s, so the 502s came slowly, about 12 s a try, and each read failed for at least 36 s, not the ~6 s the ticket supposed. Run 40923234493 failed in both runs, seven hours apart. It was read fine by every green run between them, including one 20 min before the second failure and one 40 min after. So the failures were intermittent, on single reads, not a run GitHub can't serve. Each failure was a red run on main, and a failure notice, for a slowdown that never happened.

**Departures from the ticket.**
- **The pause is 60 s, not ~30.** The failures lasted 36 s or more.
- **Older runs get no late try.** The ticket said each unread run would get one. Only the runs a gap among fails the job get one, to bound an outage's time under the job's limit.
- **The list gets the late try.** The ticket left the list and the other single calls to the build. A 502 on the list fails the run the same way. The repository's name and the compares stay as they were, since their failure is said in the report and fails nothing.
- **The per-job report and `--runs` without `--shift`** stay as they were, as the ticket's scope was CI shift.
- **A run with no status** is retried too.
