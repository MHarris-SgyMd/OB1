## Changelog

CI shift tries a read GitHub fails three times once more, 30 s later, before a gap fails the run, so a passing 502 from GitHub no longer turns main red; the report names the runs read on that late try (SMD-3690).

## FORK

CI shift gives a read GitHub fails a late try before a gap fails the run (SMD-3690)

**What changed** in `scripts/ci-step-times.ts`:
- **A late try, `LATE_MS` (30 s).** A read `gh()` fails on all three of its tries, 3 s apart, gets one more:
  - **A run's read** comes after the window's other runs are read, through the new `readRuns`. One pause covers every run not read, so six runs failing cost one 30 s pause, not six.
  - **A run that came back with no status** gets the same late try. It was a gap like a failed read before.
  - **The list** (`gh run list`, by `--last` or `--days`) is tried once more at once, through `ghLate`, since nothing else can run while it waits.
  - **A run where every read succeeds** pays nothing.
- **The gap rule is unchanged.** A run still not read after its late try fails the run, as before, if it is among the window's newest 26 or is the run reported on. An older one is still a warning.
- **The report names the late reads.** The log says each run as it is read late, and the shift report gives a line listing them, in the step summary too. The per-job report counts them in its "Over the runs where the job succeeded" line.
- **`selfCheck` is async,** to await `readRuns` on a stub reader. It has one new case for the late try and one for no pause.
- **The script's header and `.github/workflows/ci-shift.yml`'s header comment** say so. FORK.md's file list is left alone: the line would take the front door 32 bytes over its cap.

**Why.** 33 of CI shift's 35 runs on main were green from SMD-3467's merge to 11-02. Both failures were GitHub answering `HTTP 502` to a run's jobs on all three tries, with the run among the window's newest 26:
- run 41108715664 (10-30): six runs failed;
- run 41156298413 (10-31): one run failed.

The same reads succeeded later, so the 502s were transient but outlasted the three tries' ~6 s. Each failure was a red run on main, and a failure notice, for a slowdown that never happened.

**Departures from the ticket.** The ticket left the list and the other single calls to the build. The list gets the late try: a 502 there fails the run just the same. The repository's name and the compares stay as they were, since their failure is said in the report and fails nothing.

**Held.**
- **The self-check, the scripts' typecheck and the consistency checker** pass.
- **Each of three mutants fails the new case:**
  - no late re-read;
  - the pause inside each re-read, so once per run;
  - a run with no status not retried.
- **End to end, on main's real runs.** The script ran `--shift --last 40 --through 41520536823` with a stub `gh` ahead of the real one. The stub answered 502 to `run view 41488639756`, the fifth newest:
  - **502 for its first 35 s,** covering all three tries: the run was read on the late try. The run passed, exit 0, in 50 s, with no gap, and the log and summary named the run.
  - **502 throughout:** the run failed its late try. The run failed, exit 1, in 54 s, with the gap note as before.
  - **`run list` answering 502 for its first 10 s:** the list was read on its late try. The run passed, in 50 s.
- **Real slowdowns in that window.** Both stub runs named the two slowdowns real at that run: the extract cell (244.5 s → 351, 328, 398 s) and its suite step. They landed in ae8559dd..30bd9637 and are the shift working, nothing of this change.
