## Changelog

`preflight --deep`'s telemetry row now decides ok, warn or skip from what each telemetry line says, not from how it is worded, so rewording a start or loss line no longer flips the row (SMD-2909).

## FORK

Preflight's telemetry row judges each line by its kind, never its words (SMD-2909)

**What changed.**
- **`server-portable/telemetry.ts`:**
  - `planTelemetry` returns its reasons as data (`reasons`: each a line and its kind, in place of `lines`): `off` (OTEL_SDK_DISABLED or an exporter's `none`), `no-url`, `query` or `unread`.
  - `startTelemetry`'s log callback gets a kind beside each line, always: the plan's, `goes` (from `goesLines`, now shared), `not-started` (the SDK would not load or set up), `not-sent` (an export's loss or the anonymous budget's) and `note` (a setting held to its bound, or not read and its default used). The servers pass no callback, and the default (`console.warn`) ignores the kind, so their output is unchanged.
  - `telemetryRow` takes `Said` lines (`{ line, kind }`) and reads the kinds alone: `goes`, `unread` and `off` are no problem, and any other kind is what the server would share, a warning. The skips still come from what goes (no collector, nothing carried, no probe), not from a kind. The words make the detail only.
- **`deploy/README.md`** lists every warning the row gives: a query string and a held or defaulted setting were missing (they warned before too).
- **`otel-setup.ts`:** a setting held to its bound, or read as its default, goes to the collector report's `note`, where the caller gives one, instead of the losses' `warn`.
- **`preflight.ts`** keeps each line with its kind.
- **test-server:**
  - [27] builds its cells from `planTelemetry` over an environment and `goesLines`; the few that stand for what only a running exporter says (a loss, a note, a failed start) are written with their kind.
  - A row rewords every line of every cell adversarially, the kind-only cells' too, (a warning's line in the old regex's fine words, a fine line as a problem) and holds every status the same.
  - Cells where only the kind can warn: a loss beside a flush that sent, a setting held to its bound, a start that failed, and a shared endpoint with a query string.
  - The plans' rows hold each reason's kind (off, no-url, query, unread), and the start passes the plan's kind on with its line.
  - The setup that throws is passed as `not-started`, and the anonymous budget's line as `not-sent`.
  - A setting read as its default goes to the note sink.
  - A real start (a real `setUpTelemetry`, a one-span queue, an interval read as its default) passes where its signals go as `goes`, the setting as `note` and the queue's drop as `not-sent`.

**Why.** SMD-1849 PR 2d's review (a maintainer read) found the row's status read by regex over other modules' prose: `go to`, ` is not read`, `OTEL_SDK_DISABLED=true`, `_EXPORTER=none`. A reworded line would flip ok, warn or skip. test-preflight's real runs would catch a flip, but [27]'s cells, written as strings, would not.

**Held.** test-server 1174 in both modes, 7 more than main. Ten mutants each fail a row:
- a kind swapped (`unread` → `note`; an exporter's `none`, OTEL_SDK_DISABLED and a query string each as another kind);
- the row ignoring `not-sent`, `note` or `not-started`, or warning on `off`;
- notes sent as losses;
- a failed start passed with no kind.

Review pass 4 swapped every kind a site assigns or routes for every other (110 mutants): each swap that crosses between the kinds the row passes and the kinds it warns on fails a row, and only swaps within one side survive. test-preflight's real `preflight --deep` runs hold the row end to end (254). In 16 real `--deep` states the row prints word for word what main's does, and the servers' output is byte for byte main's.
