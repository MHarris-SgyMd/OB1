## Changelog

A keyed, read-only `list_thought_ids` MCP tool returns a brain's thought-id set — ids only, in id order, paged by a keyset cursor, with the corpus total and (on the SQL store) an md5 digest of all ids on the first page — and `db/tier.ts --compare` uses it to report the EXACT id-set difference between two brains (which thoughts one holds and the other does not), no longer the thought-count stand-in, so a same-count corpus that has drifted is now caught (SMD-2244).

## FORK

`list_thought_ids` — a read surface for a brain's id set, so the cross-brain compare reports the exact id-set difference (SMD-2244)

**What changed.** `tier.ts --compare` (SMD-2109) is HTTP-only, and no read tool
returned a corpus's ids cheaply (`list_thoughts` pages prose, capped and
content-heavy), so the compare reported a thought-COUNT delta as a stand-in and
named the exact id-set difference as out of reach. This adds the surface and
consumes it.

- **`list_thought_ids`** (new read tool, `server-portable/index.ts`; scope `read`
  in `server-portable/tools.ts`, so a capture-only key never sees it). Ids only —
  no content, no vectors. Keyset-paginated by `id` (`after` cursor + `limit`,
  default 1000, max 10000); a malformed cursor is refused before any store read.
  Returns one JSON object per page, `{total, digest, ids, cursor}`: `total` and a
  `digest` (an md5 of every id in id order) ride the first page so a caller can
  tell two corpora apart without enumerating either. `tools.json` regenerated.
- **`ThoughtStore.listThoughtIds`** on both stores:
  - SQL (`store-sql.ts`): keyset `WHERE id > $after ORDER BY id`, and on the first
    page `count(*)` + `md5(string_agg(id::text, ',' ORDER BY id))` in one extra
    statement (skipped while paging).
  - PostgREST (`store-postgrest.ts`): the same keyset read; `digest` is null (the
    shim has no server-side aggregate, and a second full walk just to hash would
    be wasteful), `total` from the exact count. The caller enumerates when a
    digest is absent.
- **`db/brain-compare.ts`** — `corpusIdDiff(a, b)`: read each brain's first page;
  when both digests are present AND equal, the corpora are identical and neither
  is enumerated (the fast path); otherwise page both in full and diff the sets.
  Two null digests (the shim, or two empty corpora) are enumerated, never read as
  a match. A brain that predates the tool degrades to `unavailable` — the
  count stand-in holds — rather than aborting the compare. The report's Freshness
  section gains an `id-set:` line (`identical` / `N only in a; M only in b` with
  example ids / `unavailable`), the exit code counts an id-set difference as a
  delta, and the "exact id-set difference … out of reach" note is gone (the
  board-sync watermark note remains, SMD-2109 / SMD-2245).

**Why.** The count catches the motivating stale-canary case, but "597 vs 597 with
different ids" — a same-size corpus that drifted — read as no delta. The exact
difference needs the ids; the digest keeps the common (identical or near) case one
round-trip per brain.

**Not taken.**
- A corpus fingerprint on `brain_info` instead of a tool. The digest lives on the
  enumeration tool's first page instead, so the one surface both decides *whether*
  to enumerate and gives the *which*, and `brain_info` (bundled into the Workers
  build) is untouched.
- Computing the digest on PostgREST by fetching and hashing all ids. That is a
  second full walk for a shim that is not the performance path; `digest: null` and
  the caller enumerates.
- `structuredContent` for the success payload. No success return uses it yet
  (SMD-1978 is error-only); JSON in the text body needs no `outputSchema` and
  parses the same, and the tool is machine-facing.

**Tested.**
- `server-portable/test-store-sql.ts` [5c]: the id set, the digest recomputed in
  JS (`md5(sorted ids)`), keyset paging (total/digest first page only, strictly
  increasing, no repeats), a non-uuid cursor read as the start.
- `server-portable/test-store-postgrest.ts` [8c]: ids in id order matching a raw
  `SELECT id ORDER BY id`, `digest` null, paging.
- `server-portable/test-e2e-sql.ts` [6b]: the tool over HTTP+DB — the JSON shape,
  ids-only uuids, paging, a refused non-uuid cursor.
- `server-portable/test-server.ts` [9]/[10] and `test-auth.ts` [7]/[7b] cover the
  manifest, the `readOnlyHint` and the capture-only invisibility from `tools.ts`.
- `db/test-brain-compare.ts`: identical corpora (fast path), a same-count drift
  (exact only-a/only-b), paged enumeration (forced page cap), equal digests
  short-circuiting enumeration, two null digests (differing sets) enumerated not
  matched, a first-page and a mid-walk failure → failed-with-reason (compare still
  prints), a brain without the tool → unavailable, and `runCompare` exiting 1 on a
  same-count id-set drift.
