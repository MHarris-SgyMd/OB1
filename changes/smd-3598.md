## Changelog

Agents can now claim work through the brain, over REST or MCP: `claim_work` claims a ticket, or one piece of it, and returns a token once; `renew_claim` and `release_claim` act on your own claim with that token, and an operator key may force-release a stuck claim with a reason; `list_claims` shows who holds what. A claim another agent holds is refused with an answer naming the holder and when its lease ends (HTTP 409 over REST). Keep the token private: anyone holding it under your key acts as the holder, and the session-capture hook now blanks one before a summary leaves. Preflight's `work claims` row is now called `worker claims`, beside a new `ticket claims` row that checks the claim functions, the `claims` grant and whether statement logging would print a token (SMD-3598, SMD-3615).

## FORK

Work-claim tools over REST and MCP, and the hook's scan for their token (SMD-3598 / 3615)

**Why.** Migration 115 (SMD-3597) gave every brain work claims in SQL, but no client could reach them. Every agent reaches the brain through the REST core or `/mcp`, so the claim operations belong in the shared contract (SMD-2133's rule).

**What changed.**
- **Four tools** in the manifest (`tools.ts`), their specs (`core/schemas.ts`), the operations (`core/claims.ts`), the calls, routes and MCP words. `tools.json`, the OpenAPI document and the rest-client are regenerated.
  - `claim_work`: `POST /v1/claims`, write scope. It answers `{outcome: claimed|renewed, claim, token?}`; the token comes on `claimed` alone.
  - `renew_claim`: `POST /v1/claims/{id}/renew`, write scope. It answers `{claim}`.
  - `release_claim`: `POST /v1/claims/{id}/release`, write scope, with `force` and `reason`. It answers `{outcome: released|already_released, claim}`.
  - `list_claims`: `GET /v1/claims`, read scope, with `ticket`, `holder`, `include_ended` and `limit`. It answers `{claims, truncated}`: it reads one more than the limit, so `truncated` says the limit cut the list (at 115's clamp of 1000 a full page is said cut).
- **The store** (`store.ts`, `store-sql.ts`): one statement per call, every value a bind parameter. A 22023 from 115 becomes `ClaimRefused` with the argument it names; a 42501 for an ingested key becomes `ClaimRefused` too; any other raise stays a fault. The normalisers never print what they read, since a writer's answer may carry the token.
- **Seven refusal codes** (`core/refusal.ts`, `rest/routes.ts`):
  - `WORK_CLAIMED` 409, whose facts are the claims in the way (id, holder, kind, times and `ownKey`, never a label or piece);
  - `CLAIM_NOT_YOURS` 403, with `forced` and `ownKey`;
  - `CLAIM_RELEASED` 409, with `takenOver`;
  - `CLAIM_NOT_FOUND` 404;
  - `REFUSED_CLAIM_INPUT` 400, with `problem`;
  - `REFUSED_CLAIM_KEY` 403;
  - `CLAIM_UNATTRIBUTED` 503, with `cause` and `forced`, while the registry cannot give the caller's agent id. 115 matches a claim made under an agent id by that id alone, so without this a holder renewing or releasing with its own token was told `CLAIM_NOT_YOURS`. It answers so only when the token given is that claim's, read against its hash (`claimTokenIs`, one more statement on this path alone): a wrong token stays `CLAIM_NOT_YOURS`, and the holder's own ended claim `CLAIM_RELEASED`. A forced release while the id is away answers it with `forced: true`, since the id is what classifies an operator. `registry_away` is retryable and carries Retry-After; the other causes need an operator and carry none, since every other 503 refusal is retryable. `claim_work` with the token while the id is away stays `WORK_CLAIMED`: telling exact work from overlapping work would copy 115's piece rule; `renew_claim` is the renewal.
- **The words** (`render.ts`): each reply's value is its JSON, so `claim_work`'s token reaches the caller past the guard. The token is in the `claimed` text alone, with the rule for keeping it. Another key's piece and holder are kept to one line, the piece quoted. A claim id that is no uuid is not echoed, and a token in 115's words is masked, so an agent that passes its token in the wrong argument never sees it printed back. A refusal's `holder` keeps a key's name, an OAuth principal's included (no space, at most 200 printable characters), where the enum guard nulled it.
  - When the holder is the caller's own key — another session of it, or this one without its token — the words say "your own key" and the way back: list_claims' labels tell sessions apart, and a lost token is recovered after the lapse or by an operator's force. Before, a session that lost its token read "not by this key".
  - A renewal of a claim taken over after it lapsed says who took it and "stop work on it"; a plain release says by whom and why; a release that finds it taken over says so. Before, both said only "ended".
  - A claim id given as the token, or a piece inside the ticket, is refused with a hint naming the swap. A token a model upper-cased is read as the lower-case token it is.
- **Inputs:** `piece`, `label` and `reason` are capped at 115's own limits (100, 500, 500), so the schema refuses what 115 would, before a token is bound into a statement that fails. The descriptions say to renew about hourly on the default lease, that a shorter `lease_seconds` shortens it, to give the merged PR as a release's reason, and how a new session finds its key's claims.
- **REST:** `claim_work`'s answer carries `Cache-Control: no-store`.
- **Preflight:**
  - 015's row is renamed `work claims` → `worker claims`.
  - A new `ticket claims` row checks 115's four functions (fail if missing) and the server role's `claims` grant (warn, naming the calls each missing privilege fails).
  - It also warns, with the superuser's statements, for each logging setting that prints a claim call's bind values: statement logging (`log_statement=all`, a duration or sampled duration, transaction sampling) while `log_parameter_max_length` is not 0, `log_parameter_max_length_on_error` not 0 (its parameters ride the ERROR report's CONTEXT, so only `log_min_messages` at log, fatal or panic, which rank above ERROR in the server's log, spares it), auto_explain with parameters or `log_verbose` (a verbose plan prints a custom plan's constants whatever the cap), `debug_print_plan`, and `pgaudit.log_parameter` where pgaudit logs anything. Each is read with `current_setting(name, true)`, so an extension not loaded reads as nothing. `log_statement=mod` logs no SELECT, so it does not warn.
  - The row's own read is caught, so a role with no USAGE on public warns this row alone.
- **The session-capture hook** (SMD-3615): a `work-claim token` pattern, `wc_` and 64 hex digits in either case, read on the raw text. An underscore beside it (markdown's `_…_`, a `claim_` prefix) does not excuse it. The 64-hex rule never matched it (its lookbehind refuses a run after `_`), and the entropy rule skips hex. A token in an episode is blanked as `[redacted:work-claim token]`, as every single-line secret is (SMD-2127).
- **Docs:**
  - server-portable/README.md gains a Work claims section and updates where the tools' logic lives.
  - db/README.md's 115 paragraph now names the tools.
  - The session-capture hook's README lists the new pattern.
  - The suite counts quoted in the server, mcp-server and rest-client READMEs are set to measured totals; most had drifted on main.

**Decided.**
- **Forced release is a flag on `release_claim`, on both doors** (the maintainer, 2026-10-30). The MCP server registers every operation a key may call, so keeping one off agents' tools would be a new contract concept. 115 already restricts force to an operator by agent id, and per-session agent keys (SMD-3602) keep agents from holding that kind.
- **The hook's fix rides this PR** (the maintainer, 2026-10-30): the release that first hands agents tokens also stops the hook capturing them.
- **A refusal's facts carry no other key's free text.** `WORK_CLAIMED`'s `heldBy` gives ids, holder names, kinds and times. The piece is in the text, bounded to one line; the label is in `list_claims`, as data.
- **`list_claims` takes one ticket.** SMD-3599's label reads the store directly for a page of tickets.
- **A refusal for held work names no piece over REST, and an input refusal no message.** Both are another key's or the caller's free text, and 115's words can quote the caller's argument. A REST client reads pieces from `list_claims`.
- **A token passed as the claim id still reaches a proxy's access log** on a direct REST call, since the id is in the path. Only a misused argument puts it there; the MCP server's call goes over the stack's internal network.

**Upgrade.** MINOR: new tools, routes and refusal codes; nothing existing changes shape. Preflight output reads `worker claims` where it read `work claims`. A server whose brain lacks 115 skips the `ticket claims` row; the ledger row already says the brain is behind.
