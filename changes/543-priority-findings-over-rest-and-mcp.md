# 543. Priority findings over REST and MCP — an operator lists and decides sleep's findings, and brain_info and preflight count them; PR 2 (SMD-3671)

**Why.** PR 1 (change 533, migration 142) has sleep propose findings and gives the operator a decision in SQL alone: no door reached either, and nothing said how many waited.

**What changed.** No migration. 142's list and decision as operations of the core (`core/findings.ts`), each over REST and MCP; server-portable/README.md has the shapes.
- **`list_priority_findings`** (read scope): `status` (pending by default, accepted, rejected, moot, all), `kind`, `limit` 1 to 200, `after` (a cursor). It answers `{status, kind, total, before, findings, cursor}`, the pending oldest found first, then the rest most recently decided or mooted first; each finding's `statements` read from its evidence, and an `outcome` stored in a shape this server does not read null with `outcomeUnread`. A brain before 142 faults, the MCP text naming the migration.
- **`review_priority_finding`** (write scope): `decision`, `level` 0 to 5, `due_at` (a date due by its day's end, as `set_priority` reads one), `clear`, `note` up to 2000. The schema refuses each field's shape; the rest passes to 142 with the caller's envelope, its scope stated, and 142 asks who may decide before whether the arguments go together. The operator gate is `set_priority_weights`' (`REFUSED_NOT_OPERATOR`, `PRIORITY_UNATTRIBUTED`). 142's `NOT_WRITE_SCOPE` is `WRITE_SCOPE_REQUIRED`, `NOT_FOUND` is `NOT_FOUND`. Two new codes: `REFUSED_FINDING_INPUT` (400) for the arguments, and `REFUSED_FINDING_DECISION` (409) for `NOT_PENDING` (with `status`), `NOTHING_TO_CLEAR` and `WRITER_REFUSED` (with `writerCode`). Each carries 142's error as `problem`; a refusal needs one status, so the two are split by it.
- **`brain_info`** gains `database.priorityFindings` (`pending`, `oldestPendingS`, `byKind`, `decided30d`) and a Priority findings row. **Preflight** gains a `priority findings` row: ok with the pending by kind and the oldest's age, a skip before 142, a warning with the priority group's grant when the role cannot read the table. A queue is not a fault, so pending findings never warn.
- The REST client is regenerated.
