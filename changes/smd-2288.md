## Changelog

`integrations/kubernetes-deployment` is gone: the brain deploys as the compose stack only, which leaves a Kubernetes deployment of its own server and Postgres no target, and no brain ran it. Its image steps in CI, its checker exceptions, its suite rows and `integrations/`' copy of `_shared/sse.ts`, which it alone imported, went with it. `server-portable/README.md` names the compose stack as the one way to run the server, and FORK.md's rebase runbook no longer builds the retired Workers target. CLAUDE.md's guard rail, `SETUP.md`, getting-started and `primitives/deploy-remote-mcp/` now say the brain deploys as the compose stack alone, with SETUP's "Where to run it for real" the same stack on a host you keep, and the consistency checker fails a doc that starts one of the brain's servers outside it, runs its image alone, or deploys it to a cluster or a platform it names (SMD-2288).
