## Changelog

`integrations/kubernetes-deployment` is gone: the brain deploys as the compose stack only, which leaves a Kubernetes deployment of its own server and Postgres no target, and no brain ran it. Its image steps in CI, its checker exceptions, its suite rows and `integrations/`' copy of `_shared/sse.ts`, which it alone imported, went with it. `server-portable/README.md` names the compose stack as the one way to run the server, and FORK.md's rebase runbook no longer builds the retired Workers target (SMD-2288).

## FORK

The Kubernetes deployment is retired, and the server's README and FORK.md's runbook name the compose stack alone, PR 1 (SMD-2288)

**What changed.** SMD-2288 PR 1, the half of the ticket that does not touch the files SMD-2287 PR 5b edits:
- `integrations/kubernetes-deployment/` (its server, Dockerfile, lockfile, `k8s/` manifests and README) is removed, with `integrations/.dockerignore`, which existed for its image, and `integrations/_shared/sse.ts`, which only it imported. `extensions/package.json`'s `sync-sse` writes the two copies left.
- `.github/workflows/fork-checks.yml`: the deploy-stack-auth job loses "The Kubernetes image builds" and "The Kubernetes image stops on SIGTERM, finishing a call in flight".
- `extensions/test-auth.ts`:
  - The server's row goes, with its two probes of its own: SMD-2001's search slower than the idle timeout and SMD-2692's provider deadlines. It was the one vendored server that called a provider.
  - The environment it read at import (`DB_*`, `EMBEDDING_API_BASE`, `CHAT_API_BASE`, `OB1_LLM_TIMEOUT`) goes, and so does its install's exact pin hold.
  - mcpReply's edges keep their own header. Their mid-upload probe now runs at ob-graph's route and transport.
  - SMD-1668's allow-list rule reads no list now, since no MCP server publishes one. It asserts that, asserts that no MCP server names the header in any spelling, and holds its pattern to the last list's shape on a probe of its own.
- `extensions/test-writes.ts`: the servers that own their database are two.
- `scripts/check-fork-consistency.ts`: check 7's exceptions for `k8s/init.sql` and `openbrain.yml`, and the `index.ts` entries in check 10's and the trust check's, go.
- `server-portable/sse.ts`, with its two copies: the vendored stall line says a stuck call is stuck on a query, since no vendored MCP server calls a provider.
- Comments and docs:
  - `db/test-support.ts`'s stack notes and the two `package.json` comments;
  - README.md: the integrations row goes, the contribution-history row is marked retired, and the section intro changes;
  - the landing page's card;
  - `docs/vendored-disposition.md` and `docs/operator-surface-tiers.md` (retired);
  - `docs/mcp-sdk-v2-migration.md`'s outliers and pin sites;

- `server-portable/README.md`: "Pick a target" (Bun, a container, Node) becomes "Run it": the compose stack, with `bun index.ts` for tests and a local run, not a deployment. Its Related list loses the Kubernetes port.
- FORK.md's rebase runbook loses `bunx wrangler deploy --dry-run`, the Workers build SMD-3152 retired.

**Why.** SMD-2282's decision 6 makes the compose stack the only deployment. SMD-1931 recorded this integration's disposition as retire, with SMD-2288 doing the removal. The maintainer said on 2026-10-20 that there are no live users, and that backwards compatibility is owed only to upgrading stable and the canary, which run the compose stack. The maintainer chose (2026-10-21) to do this half now and the guard rail, `SETUP.md`, getting-started, `primitives/deploy-remote-mcp/` and the checker rule after SMD-2287 PR 5b merges, since 5b edits those files.
