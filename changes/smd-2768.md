## Changelog

The plugin SDK gains `onceById`, the webhook delivery-id memory the example plugin's `capture` hook carried by hand: a claim before the run, a resend answered with the first's thought, a failed run's claim given back, a lease after which a retry takes a claim left unfinished. The lease now follows the brain's own `OB1_LLM_TIMEOUT` (one capture's model calls and a minute, twice over with `OB1_CHUNK_CONTEXT` on): 180 s as shipped, as before, and longer where the timeout is raised, where it used to stay 180 s and let a slow capture run twice (SMD-2768).

## FORK

The webhook delivery-id memory is the SDK's `onceById`, its lease sized from the core's own model-call deadline (SMD-2768)

**What changed.**
- `server-portable/plugin-sdk.ts` gains `onceById(ctx, id, run, { keepSeconds, leaseSeconds? })`, `isDeliveryId` and their types, `OnceOptions`, `OnceRun` and `Once`. It is SMD-2755's claim, lifted from `plugins/example/index.ts` with its SQL unchanged, over the plugin's own `deliveries` table (the example's `002_deliveries.sql` is the shape):
  - `run` hands back `{ value, thoughtId }`; the answer is `{ ran: value }`, `{ duplicate: thoughtId }` or `{ inFlight: true }`.
  - A `run` that throws, or hands back no thought, gives its own claim back (matched on `claimed_at` as text); a thought is recorded by upsert, and a record that fails is swallowed.
  - An id `isDeliveryId` refuses (not 1 to 200 printable ASCII characters), a window that is no positive number or `Infinity`, or a lease that is no positive number, is thrown: the plugin's fault, before any claim. A `thoughtId` that is no uuid is thrown once its claim is given back: its record would fail unseen, and the id run on every resend.
  - `keepSeconds: Infinity` prunes nothing, for a sender that signs no time and may resend an id for good (a Readwise highlight's).
  - One table per plugin, and each claim prunes every row in it by its own options, so two hooks that remember ids prefix them and pass the same options, the longest either needs; the docs say so.
- The lease defaults to `ctx.captureSeconds` and a minute, rounded up to whole seconds. `HookContext.captureSeconds` is new: the core's `captureSeconds()`, read when a hook asks, from `core/writes.ts`'s `captureCallSeconds` — `OB1_LLM_TIMEOUT` once, twice with `OB1_CHUNK_CONTEXT` on (a long text's windows are blurbed, then embedded), or the genre tier's 31 s if that is longer. A plugin cannot read the environment (check 31), so before this the example's lease was a constant, 180 s.
- The prune keeps a claim still inside its lease when the lease outlives the window (`keepSeconds`): pruned, its id would run again beside a capture still running. A captured id is pruned at the window, as before.
- `plugins/example/index.ts`'s hook calls `onceById`, and a delivery without an id runs the same tail: one answer for both. Its `LEASE_S` is gone.
- `plugins/README.md`'s "It remembers ids" names the helper, its answers and its lease; the example's README says the lease follows the timeout.

**Why.** SMD-2755 left the pattern in the example while it had one consumer. SMD-2101 (Slack, Telegram) and SMD-2690 (Readwise) would each have copied about fifty lines that took four review passes to get right, so a later fix would have had to reach every copy by hand. And the lease was sized for `OB1_LLM_TIMEOUT`'s default: an operator who raised it for slow local models got captures that ran twice past 180 s, and could not tune it.

**Not taken.**
- *A check that a plugin calling `onceById` has a `deliveries` migration.* Check 31 cannot read the SDK's SQL; a plugin without the table fails on its first delivery with an id, loudly, in its own tests.
- *A cap on a window or lease past Postgres's interval range*: only an absurd constant or `OB1_LLM_TIMEOUT` reaches it, and every delivery then fails as plainly.
- *`onceById` for an operation.* Its context has no `captureSeconds`; an operation has a caller to answer, not a sender that resends.

**Follow-ups.** SMD-2101 and SMD-2690's ports call `onceById`; SMD-2767 (a hook that answers before its capture finishes) is unchanged.
