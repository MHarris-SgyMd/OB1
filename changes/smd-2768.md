## Changelog

The plugin SDK gains `onceById`, the webhook delivery-id memory the example plugin's `capture` hook carried by hand: a claim before the run, a resend answered with the first's thought, a failed run's claim given back, a lease after which a retry takes a claim left unfinished. The lease now follows the brain's own `OB1_LLM_TIMEOUT` (one capture's model calls and a minute, twice over with `OB1_CHUNK_CONTEXT` on): 180 s as shipped, as before, and longer where the timeout is raised, where it used to stay 180 s and let a slow capture run twice (SMD-2768).

## FORK

The webhook delivery-id memory is the SDK's `onceById`, its lease sized from the core's own model-call deadline (SMD-2768)

**What changed.**
- `server-portable/plugin-sdk.ts` gains `onceById(ctx, id, run, { keepSeconds, leaseSeconds? })`, `isDeliveryId` and their types, `OnceOptions`, `OnceRun` and `Once`. It is SMD-2755's claim, lifted from `plugins/example/index.ts` with its SQL unchanged, over the plugin's own `deliveries` table (the example's `002_deliveries.sql` is the shape):
  - `run` hands back `{ value, thoughtId }`; the answer is `{ ran: value }`, `{ duplicate: thoughtId }` or `{ inFlight: true }`.
  - A `run` that throws, or hands back no thought, gives its own claim back (matched on `claimed_at` as text); a thought is recorded by upsert, and a record that fails is swallowed.
  - An id `isDeliveryId` refuses (not 1 to 200 printable ASCII characters), or a window or lease that is no positive number, is thrown: the plugin's fault, before any claim.
- The lease defaults to `ctx.captureSeconds` and a minute, rounded up to whole seconds. `HookContext.captureSeconds` is new: the core's `captureSeconds()`, read when a hook asks, from `core/writes.ts`'s `captureCallSeconds` — `OB1_LLM_TIMEOUT` once, twice with `OB1_CHUNK_CONTEXT` on (a long text's windows are blurbed, then embedded), or the genre tier's 31 s if that is longer. A plugin cannot read the environment (check 31), so before this the example's lease was a constant, 180 s.
- The prune keeps a claim still inside its lease when the lease outlives the window (`keepSeconds`): pruned, its id would run again beside a capture still running. A captured id is pruned at the window, as before.
- `plugins/example/index.ts`'s hook calls `onceById`, and a delivery without an id runs the same tail: one answer for both. Its `LEASE_S` is gone.
- `plugins/README.md`'s "It remembers ids" names the helper, its answers and its lease; the example's README says the lease follows the timeout.

**Why.** SMD-2755 left the pattern in the example while it had one consumer. SMD-2101 (Slack, Telegram) and SMD-2690 (Readwise) would each have copied about fifty lines that took three review passes to get right, so a later fix would have had to reach every copy by hand. And the lease was sized for `OB1_LLM_TIMEOUT`'s default: an operator who raised it for slow local models got captures that ran twice past 180 s, and could not tune it.

**Held.**
- `bun test-plugins.ts` (213, from 199): [11]'s stand-in cases pass on the helper unchanged, and the claim binds an eleven-minute window and the core's deadline and a minute (180 s). [13]: the core's deadline is 120 s by default, 600 at `OB1_LLM_TIMEOUT=600`, 1200 with chunk context on, the tier's 31 s when it is longer; with `OB1_LLM_TIMEOUT=600` the lease is 660 s, longer than one capture's model calls; a fractional deadline rounds up; a run with no thought gives back its claim by the text the claim returned; a plugin's own lease is used; an in-flight id never calls `run`; a bad id, window or lease is thrown; `isDeliveryId`'s edges.
- `../db/with-postgres.sh bun test-plugins-sql.ts` (98, from 95): [6b]'s cases pass unchanged through the live REST core. Through `runHook` over the real table: under a core whose captures may run 600 s, a claim four minutes old is 409 and one past 660 s is taken; under one whose captures may run 1200 s, a claim twelve minutes old outlives the window and is 409 while a captured id that old is pruned.
- Twenty-eight mutants killed, none hanging a suite:
  - SMD-2755's eighteen, now in the SDK and the example: the release dropped on a thrown run or a run with no thought, or not matched to its own claim; the dedupe dropped; the claim bypassed; the thought not recorded, recorded by update alone, or its record's failure thrown; the lease dropped, taking a finished claim, or keeping the old time; `claimed_at` returned as a Date; the prune window in milliseconds; the id check held to length alone, dropped from the example or from `onceById`; the NUL check dropped; a retryable refusal as 422;
  - SMD-2768's ten: the default lease fixed at 180 s, not rounded up, or ignoring the plugin's; the prune ignoring the lease, or keeping captured ids to it; the window and lease check dropped; one round with chunk context on; the genre tier ignored; the timeout not read; `runHook` passing a constant.

**Follow-ups.** SMD-2101 and SMD-2690's ports call `onceById`; SMD-2767 (a hook that answers before its capture finishes) is unchanged.
