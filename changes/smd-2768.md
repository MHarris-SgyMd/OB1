## Changelog

The plugin SDK gains `onceById`, the webhook delivery-id memory the example plugin's `capture` hook carried by hand: a claim before the run, a resend answered with the first's thought, a failed run's claim given back, a lease after which a retry takes a claim left unfinished. The lease now follows the brain's own `OB1_LLM_TIMEOUT`: one capture's model calls (the timeout, or twice it with `OB1_CHUNK_CONTEXT` on) and a minute, 180 s as shipped, as before, and longer where the timeout is raised, where it used to stay 180 s and let a slow capture run twice (SMD-2768).

## FORK

The webhook delivery-id memory is the SDK's `onceById`, its lease sized from the core's own model-call deadline (SMD-2768)

**What changed.**
- `server-portable/plugin-sdk.ts` gains `onceById(ctx, id, run, { keepSeconds, leaseSeconds?, scope? })`, `isDeliveryId(id, scope?)` and their types, `OnceOptions`, `OnceRun` and `Once`. It is SMD-2755's claim, lifted from `plugins/example/index.ts` with its claim, release and record SQL unchanged and its prune changed (below), over the plugin's own `deliveries` table (the example's `002_deliveries.sql` is the shape):
  - `run` hands back `{ value, thoughtId }`; the answer is `{ ran: value }`, `{ duplicate: thoughtId }` or `{ inFlight: true }`.
  - A `run` that throws, or hands back no thought, gives its own claim back (matched on `claimed_at` as text); a thought is recorded by upsert, and a record that fails is swallowed.
  - An id `isDeliveryId` refuses (a string of 1 to 200 characters from `!` to `~`, less a scope and its space), a scope that is not lower-case words and hyphens of at most 32 characters, a window that is no number above 0 and at most 10^9 s or `Infinity`, or a lease that is no number above 0 and at most 10^9 s, is thrown: the plugin's fault, before any claim. Past about 2 × 10^11 s Postgres's timestamps overflow and every claim would fail. A `thoughtId` that is no uuid is thrown with its claim kept: its record would fail unseen, and a resend is 409 until the lease.
  - `keepSeconds: Infinity` prunes nothing, for a sender that signs no time and may resend an id for good (a Readwise highlight's).
  - `scope`: one table per plugin, and a hook's ids kept as `<scope> <id>` (a space no id holds), each claim pruning its own scope's rows alone, so two hooks keep their own windows and the same id from two senders is two deliveries. The scope is the SDK's to add, so a sender's empty id is refused rather than made an id by its prefix. It is part of the key, so it is chosen before a hook first runs. A plugin with a scope kept for good beside one that prunes adds the index the prune reads, which `onceById`'s doc comment gives; without it each claim scans every kept row (100k kept rows: 8.5 ms a prune, measured).
- The lease defaults to `ctx.captureSeconds` and a minute, rounded up to whole seconds. `HookContext.captureSeconds` is new: the core's `captureSeconds()`, read when a hook asks, from `core/writes.ts`'s `captureCallSeconds` — `OB1_LLM_TIMEOUT` once, twice with `OB1_CHUNK_CONTEXT` on (a long text's windows are blurbed, then embedded), or the genre tier's 31 s if that is longer. A plugin cannot read the environment (check 31), so before this the example's lease was a constant, 180 s.
- The prune keeps a claim still inside its lease when the lease outlives the window (`keepSeconds`): pruned, its id would run again beside a capture still running. A captured id is pruned at the window, as before, and only in the claim's own scope.
- `plugins/example/index.ts`'s hook calls `onceById`, and a delivery without an id runs the same tail: one answer for both. Its `LEASE_S` is gone.
- `plugins/README.md`'s "It remembers ids" names the helper, its answers, its lease and `scope`, and that a numeric id is passed as a string; the window is no shorter than the sender retries. Its Slack paragraph keeps `409 IN_FLIGHT` as the answer (a 2xx to an in-flight retry loses the delivery if the first fails) and no longer reads as leave to detach work, and a new bullet answers a sender that retries any non-2xx with a 2xx for what its plugin will not capture. The example's README says the lease follows the timeout.

**Why.** SMD-2755 left the pattern in the example while it had one consumer. SMD-2101 (Slack, Telegram) and SMD-2690 (Readwise) would each have copied about fifty lines that took four review passes to get right, so a later fix would have had to reach every copy by hand. And the lease was sized for `OB1_LLM_TIMEOUT`'s default: an operator who raised it for slow local models got captures that ran twice past 180 s, and could not tune it.

Then the tidy-ups the passes had cut for space, while the files were open: `onceById`'s uuid check reads `store.ts`'s `UUID_RE` rather than a second copy of it, and the example hook's comment says its 4xx answers suit a sender that reads them.

**Not taken.**
- *A check that a plugin calling `onceById` has a `deliveries` migration.* Check 31 cannot read the SDK's SQL; a plugin without the table fails on its first delivery with an id, loudly, in its own tests.
- *`onceById` for an operation.* Its context has no `captureSeconds`; an operation has a caller to answer, not a sender that resends.
- *The scope index in the example's migrations.* The example has one hook and no scope; its rows are all in the one unscoped set the index would not narrow.
- *A table per hook.* `PluginSql` binds values, not names, so a table option would build SQL text from a string; a scope in the key needs neither.

**Follow-ups.** SMD-2101 and SMD-2690's ports call `onceById`. SMD-2101 gains the walkthrough's port-level findings: a plugin of hooks alone is refused for having no operations, a hook cannot set Slack's `x-slack-no-retry` header, capture's answer has no SDK type, Readwise's updated events share the created one's id, and Telegram's `update_id` restarts from a random value after a week with no updates. With a leaked bearer secret, ids a forger sends first answer the real deliveries `duplicate`; a digest of the body beside the id would tell them apart (SMD-2101's to weigh). SMD-2767 (a hook that answers before its capture finishes) is unchanged.
