## Changelog

`bun db/ingest-records.ts --source items --items <file.jsonl>` (`-` for stdin) ingests ingestion-contract items a parser in any language emitted, one JSON object per line, through the pipeline's own write path; the new `db/ingest-items.ts` validates each line in the contract's terms and a malformed line refuses the whole file with its line number and field, exit 2, before any write — so the four import recipes the class decision routes onto the contract keep their parsers and need no database client (SMD-2136).

## FORK

The pipeline takes ingestion-contract items from a file — a parser in any language emits them as JSONL, `db/ingest-items.ts` validates each line in the contract's terms and refuses a malformed file whole, and the import recipes keep their parsers with no database client (SMD-2136)

**What changed.** `db/ingest-items.ts` is the contract's third adapter, and
not a map: the file adapter. A line is one JSON object with exactly the keys
`Ingested` names for an item — `identity {system, key}`, `scope`,
`canonical {form, mediaType}`, `text`, `links`, `mentions`, `facets`, and
optionally `createdAt` and `watermark {key, value, asOf?}` — and `parseItems`
turns a JSONL text into items, throwing `ItemsRefusal {label, line, field,
reason}` at the first line that is not one. The rules are the contract's own
(`SYSTEM_RE`, `IDENTITY_MAX`, `LINK_RELATIONS`, `ENTITY_TYPES`,
`normaliseLinks` / `normaliseMentions`) plus what the columns cannot hold: a
NUL or a lone surrogate anywhere in the line (a `text` or `jsonb` cast would
abort the run on line N of M with N−1 written), a `createdAt` or `asOf` that
is not an instant a `timestamptz` cast accepts — `Date.parse` takes February
the 30th as March the 2nd, so the calendar date is round-tripped as the Linear
adapter's `isCalendarDate` does — a `system` that is one of the pipeline's own
record sources (`fork`, `commit`, `memory`, which no adapter writes), a
watermark under a key the pipeline overwrites (`source`, the actor keys). Two
lines of one identity are refused together: they would land on one row, the
second silently over the first. `derived` is not taken from a file — a part
that is a thought of its own is a line of its own. Blank lines are skipped
and still counted, so the line a refusal names is the line an editor shows.

`db/ingest-records.ts` gains the source `items`: `--items <file.jsonl>`
(`-` reads stdin), `--source items` to take the file alone. Each item becomes
a `Doc` through `docOf` on `recordId(system, key)` — the row labelled with the
item's OWN system (`metadata.source`), not `items` — and `Doc.source` widens
from the five names to any system. The write path is untouched: the row with
003's fingerprint under the ingester's envelope, the metadata merged, the
watermark judged, the canonical in `thought_sources` byte for byte (the round
trip holds by construction — the canonical IS the line's `form`), 053's links
as a set, the mentions under `source:<system>`, the vector left for
`reembed.ts`. The items carry a structure, so `applyAllowlist` gates them as
it gates the two adapter sources: `--allow <scope>` / `OB1_INGEST_ALLOW`,
default nothing, the refusal counted under `items` and said once per scope. A
malformed file is a wrong input, as a missing file is: exit 2 with the flag,
the line and the field, the file refused whole — the gather precedes every
write, so no row of a refused file is ever half in. `db/README.md`'s sources
table has the row and a section with the six-line Python emitter
(`json.dumps(item)` per line) an import recipe copies.

**Why.** SMD-2126 decided the class: an import recipe becomes an adapter of
the ingestion contract, and three of the four (`chatgpt-conversation-import`,
`perplexity-conversation-import`, `readwise-import`) are Python with parsers
worth keeping — a ChatGPT export's tree walk, an `.xlsx` reader, the Readwise
API's paging; the fourth is a standalone `.mjs`. The contract had two
adapters, both TypeScript inside `db/`, and the pipeline read a fixed list of
sources: without a seam each port would have been a TypeScript rewrite under
`db/` or a database client of its own, the shape SMD-2126 is retiring.

**Held.** `bun db/ingest-items.ts --self-check` (CI's "Ingestion adapters"
step): a good line carried field for field, the optional keys absent staying
absent, `normaliseLinks` counting the self link, the duplicate and the empty
target; thirty-eight malformed kinds, each refused on the line given naming
its field in the flag's own words; blank lines skipped without shifting
numbers; two lines of one identity refused together, the same key under
another system not; the instant rule over the shapes it takes and the eight
it refuses. `bun db/ingest-records.ts --self-check`: a file's items as Docs
on their systems' id spaces, the structure, scope, createdAt and watermark
carried, the allowlist gating them by scope, a malformed third line refusing
the file naming the flag. `db/test-live.ts` [19] drives the CLI end to end
against the suite's server (the pipeline's write path is Bun SQL, which
`test-schema.ts`'s PGlite cannot run): `--dry-run` counts by system and
writes nothing; two items write two bare rows labelled with their system,
dated by their `createdAt`, under the ingester's envelope, two canonicals
byte for byte, one active link by identity, one mention under
`source:<system>`; the same file again writes nothing; a file with a bad
third line exits 2 naming line 3 and the field with nothing on stdout and
zero rows for it; an item whose scope is not cleared is counted as refused
under `items` with the knob named, and not written.

**Not taken.** The REST gateway as the Python recipes' target — decided
against in SMD-2126 (`open-brain-rest`'s `/capture` embeds at 1536, which the
fork's default brain refuses). A TypeScript adapter per recipe under `db/`:
the parsers are the recipes' value and Python. `derived` from a file: a
recursive shape for a case no import needs — each extracted thought is its
own line. Skipping a malformed line and writing the rest: a file half written
cannot be re-run cleanly, where a file refused whole is fixed and run again.
A file-level `scope` or `system` header: each line is complete, so a file can
be concatenated from several runs and a line read on its own.

**Follow-ups.** The four import ports SMD-2147–2150 and `pull-gmail.ts`
(SMD-2021) emit items for this flag and each removes its
`POSTGREST_EXCEPTIONS` entry when it lands.
