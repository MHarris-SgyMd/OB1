## Changelog

`--profile observability` runs two more containers and a one-shot: Grafana's otel-lgtm image pinned by digest: an OpenTelemetry collector and Prometheus, Tempo, Loki, Pyroscope and Grafana on the stack's own machine, which the MCP server and the REST core send their spans, metrics and log records to once `deploy/.env` names it. Grafana is behind its own sign-in, anonymous access off, on a loopback port of its own with the new `compose.grafana-port.yaml`, or at `/grafana` on the stack's origin with the new `compose.grafana-public.yaml`, both release assets. The two servers now take the standard `OTEL_*` settings from `deploy/.env`, a pipeline tier's brain names its tier on its telemetry, and a request the server did not accept sends its span and log record within 60 a minute per server. Postgres now starts with `pg_stat_statements` on every stack and tier (migration 094 creates it where offered), and the profile's `pg-exporter` reads each statement's calls and times, and the connections in use, into the collector as a role of its own (SMD-1849).

Upgrading without the profile: the servers now read the standard `OTEL_*` settings from `deploy/.env` and the shell compose runs in, so an `OTEL_EXPORTER_OTLP_ENDPOINT` already exported there starts sending; a stack already sending to its own collector has requests the server did not accept held to that budget; `/grafana` is a 404; Postgres restarts once, to load `pg_stat_statements`, its command now outranking a `shared_preload_libraries` of your own, which goes in `POSTGRES_PRELOAD_LIBRARIES`, and turning `track_io_timing` on (SMD-1849).

## FORK

An `observability` compose profile — a collector, Prometheus, Tempo, Loki, Pyroscope and Grafana on the stack's machine, Grafana opt-in at `/grafana`, and requests the server did not accept traced within a budget, and Postgres's own numbers from pg_stat_statements (SMD-1849)

**PR 3a: the collector.** PR 2's spans, metrics and log records had nowhere to go in the stack: the servers' compose environments took no `OTEL_*` variable, and an operator had to bring a collector and a second `-f` file. Now:
- **`lgtm`** (`deploy/compose.yaml`, `--profile observability`): `docker.io/grafana/otel-lgtm:0.36.0` by its multi-arch digest — Grafana 13.2.3, Prometheus 3.15.0, Tempo 3.1.0, Loki 3.7.8, Pyroscope 2.3.1, collector 0.162.0 — on the internal `mesh` (and, since PR 3b, `telemetry`) as `lgtm.ob1.internal`, one named volume (`lgtm-data`), `unless-stopped`, `init`, no capability and no new privileges (measured: it starts on a fresh volume so), its health each backend's own ready URL beside the image's ready file, five minutes to start (a backend that dies leaves it unhealthy; neither Docker nor Podman restarts that by default).
  - **Only Grafana (3000), OTLP (4317, 4318) and the collector's health check (13133) answer on `mesh`.** Prometheus, Loki, Tempo and Pyroscope listen on the container's loopback — server, gRPC and gossip ports alike — by the image's `*_EXTRA_ARGS`; Tempo takes no listen address by flag, so the command writes its config from the image's with the server on loopback, and refuses unless that leaves exactly its two addresses.
  - **Grafana:** anonymous access off — the image's own default signs anyone in as Admin — and the command refuses `GRAFANA_ADMIN_PASSWORD` under 12 characters or `admin` (spaces aside, in any case, counted as characters under `C.UTF-8`), at every start, saying why and exiting 30 s later. Root URL `OB1_PUBLIC_ORIGIN` (a trailing slash dropped; unset, the stack's loopback origin) at `/grafana/`, its cookie `Secure` where that is https in any case, its Content-Security-Policy on, its data-source proxy held to its own four backends. Off: plugin preinstall, signing keys and the plugin admin, usage reports, update checks, the news feed, gravatars, cloud migration, snapshots (local and external), public dashboards and Grafana's `/metrics`; the backends' usage reports too. No outward network on `mesh` and `telemetry`, both internal; `compose.grafana-port.yaml`'s port network reaches out, as Postgres's does in `compose.host-ports.yaml`, and the switches keep it quiet. A data source's own queries reach every name on `mesh` (and, since PR 3b, `pg-exporter` on `telemetry`, SMD-3023), where the servers ask for a key and the authorization server for the operator's password.
  - **Loki's retention** is on, 14 days, as Tempo's default is: the image's Loki keeps every record for ever. Prometheus keeps its default 15 days.
- **`/grafana` is opt-in.** Base `compose.yaml` routes it to a bodiless 404 (`grafana-off`); **`deploy/compose.grafana-public.yaml`** (new, a release asset with its own line in the release notes) adds the router over it, dialling `lgtm.ob1.internal.:3000` path kept, a 502 a bare 404 (`grafana-absent`). **`deploy/compose.grafana-port.yaml`** (new, a release asset too) publishes Grafana on `${GRAFANA_BIND:-127.0.0.1}:${GRAFANA_PORT:-3000}` on a network of its own, an origin of its own, and names that port Grafana's root URL (`LGTM_ORIGIN`) unless `GRAFANA_ORIGIN` names a TLS proxy's, so its links name the port and its cookie is not `Secure` over the plain http; reaching Grafana publishes and recreates nothing else.
- **`x-otel-env`**, merged by the MCP server and the REST core alone: the endpoint, headers, resource attributes, the three exporter switches, `OTEL_SDK_DISABLED`, the sampler and its argument, the metric interval, each `${VAR:-}` — empty, which the servers read as unset. Not `OTEL_SERVICE_NAME`, which would give both servers one name, nor `OB1_OTEL_TRUST_TRACEPARENT`.
- **A request the server did not accept** — no key, one it refused (revoked, busy, outside the door's scopes), a webhook delivery its plugin refused — sends its span and log record within 60 a minute per server, each start of the SDK a fresh count (`telemetry.ts`, `ANONYMOUS_PER_MINUTE`); past it, its point and its line still count it (the line naming a trace not sent), and one line says how many sent neither, at the minute's end, the next minute's first or the stop's flush. A key accepted, or a delivery its plugin accepted (`hookAccepted`, `rest/app.ts`), is never held; a request begun before the SDK loaded sends nothing and spends nothing. The log record is held whether the span was sampled or not. Only the request's own span is held: work it ran under it still sends its spans. At most about 1.2 GB per server over Loki's and Tempo's 14 days.
- **`deployment.environment.name`** on the resource for a pipeline tier's brain (`OB1_TIER` trimmed, held to `PIPELINE_TIERS`), over `OTEL_RESOURCE_ATTRIBUTES`, which a canary's env file copies from stable's (`otel-setup.ts`); `compose.canary.yaml`'s rule on the names a canary dials, and the two ADRs, say so.
- **`deploy/canary.sh`** leaves `GRAFANA_*` out of the canary's env file, and a canary on a port of its own says when stable's collector is its endpoint. **`deploy/.env.example`** gains the profile's five settings, commented.
- **`deploy/README.md`:** "The observability profile" — the lines and the `-f` file that turn it on, turning it off, rolling back, the sign-in and the password's life, the two places Grafana may be reached and what sharing the origin with `/auth` means, what each backend holds, disk per request and the anonymous budget, retention, memory, what answers on `mesh`, what calls out and what an admin reaches, a canary's signals — the budget in "Traces, metrics and log records", and `lgtm` in the networks, services, paths and "After a reboot". **`docs/operator-surface-tiers.md`**, **`docs/one-brain-per-stack.md`:** Grafana's route among the path obligations, the canary's one stable name, port 3000.

**PR 3b: the database's numbers.** The servers' spans name each store operation, never its SQL; what each statement costs inside Postgres, and the connections the pool holds, were nowhere. Now:
- **`pg_stat_statements` on every stack and tier:** `deploy/compose.yaml`'s `postgres` and `compose.tiers.yaml`'s start with it preloaded (`POSTGRES_PRELOAD_LIBRARIES`, which an operator's own libraries join), `track_utility` off, so a utility statement — `login-role.ts`'s `ALTER ROLE … PASSWORD` among them — is never recorded with its text, and `track_io_timing` on; **migration 094** creates the extension, in public, where `pg_available_extensions` lists it (a managed Postgres without it, or a migrator that is no superuser, migrates on without it), its views and their functions revoked from `PUBLIC` and granted to `pg_monitor` alone — readable by `PUBLIC`, they were core relations the plugins' login role held (test-plugins-sql's "plugin tables" row named them). **`migrate.ts`** reads those grants on every plain run and runs 094 again where a restore gave `PUBLIC` them back.
- **`pg-exporter`** (`--profile observability`): `postgres_exporter` v0.20.1 by its multi-arch digest, read-only, no capability, no new privileges, publishing nothing; `pg_stat_statements`' top 100 statements by time, labelled by `queryid`, `user` and `datname`, each `queryid`'s normalized text (cut to 120) on `pg_stat_statements_query_id`, its own queries left out; `pg_stat_activity_count` by database and state (the servers' pool among them); the default collectors.
- **`ob1_monitor`**, a member of Postgres's read-only `pg_monitor` alone: **`pg-monitor-role`** sets it from `OB1_MONITOR_DB_PASSWORD` at each `up` (`db/login-role.ts --member-of`, whose allow-list names `pg_monitor` alone; any other membership, that one WITH ADMIN OPTION, or a role with members of its own is refused); unset, it refuses and the exporter never starts. The password stays out of the canary's env file; the release overlay pins the step to the release's migrator. **`deploy/.env.example`** gains `OB1_MONITOR_DB_PASSWORD` and `POSTGRES_PRELOAD_LIBRARIES`, commented.
- **A new internal network, `telemetry`:** lgtm and the exporter alone; the exporter is also on `data`. lgtm's collector scrapes `pg-exporter.ob1.internal.:9187` every 30 s through `OTELCOL_EXTRA_ARGS` (an inline second config, the image's two metrics receivers and this one), so the series land in Prometheus under `job` `postgres`. Open (SMD-3023): the exporter's `/probe` dials any target its caller names, and `data` reads its `/metrics`.
