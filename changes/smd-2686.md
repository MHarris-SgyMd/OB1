## Changelog

The session-capture hook's `--check` now warns when its url answers through the proxy's deprecated legacy route, which v2.0.0 closes. Before, it printed `ok` for the root as for `/mcp`, so the check gave no sign that a hook was left on the root; only the server's log named its key. The warning names the `/mcp` url to set and where to set it (the config file, or `OB1_BRAIN_URL`). The check still exits 0, since the root works until v2.0.0 (SMD-2686).

## FORK

The session-capture hook's --check warns while its url is on the deprecated root (SMD-2686)

**What changed.**
- `recipes/session-capture-hook/session-capture.mjs`: `rpc()` records an answer's `Deprecation` header on the config. Every answer through the proxy's legacy route carries that header (SMD-2306). After `tools/list`, `--check` prints `warning: <url> answered through the proxy's deprecated legacy route (Deprecation: …), which stops answering at v2.0.0 — set the url to <origin>/mcp in <config file | OB1_BRAIN_URL> …` to stderr. A url off the root is told to move to "its /mcp". The ok line and the exit code are unchanged.
- The recipe's README (step 3) and `deploy/README.md`'s "Moving a client to /mcp" row for the hook say `--check` warns there.

**Why.** SMD-2686 moves stable's two root clients on the dogfood Mac, the `open-brain` Claude Code connector and the session-capture hook, to `/mcp` before SMD-2532 closes the root. The move's step 2 is "set the url, then run `--check`", and `--check` said `ok` whichever url it was given. So it could not show that the move was needed, or that it was done. Only the server's log could, and it names each key once per process.

**Held.**
- *The suite.* `test-session-capture.mjs` puts a stand-in for the legacy route in front of its fake endpoint, adding `Deprecation: @1790899200` to each answer. Three new assertions:
  - at the root: `ok` on stdout, and a warning naming `<root>mcp` and the config file;
  - off the root, given by `OB1_BRAIN_URL`: "its /mcp", and the variable named rather than the file;
  - no warning on the existing capture-key and write-key checks.

  677 assertions pass. Dropping the one line that records the header fails exactly the first two.
- *The dogfood move* (stable v1.7.0 on this Mac, 2026-10-09 03:00Z):
  - **Connector, before.** The connector's key answered 20 tools at the root with `Deprecation: @1790899200`, and 20 at `/mcp` with none.
  - **Connector, move.** `claude mcp remove --scope user open-brain`, then `claude mcp add --transport http --scope user open-brain http://127.0.0.1:8010/mcp --header "x-brain-key: …"` with the same key. The URL uses `127.0.0.1`, not the old `localhost`, as the README says.
  - **Connector, after.** `claude mcp list` says Connected, and `brain_info` over `/mcp` answers tier stable, 1.7.0.
  - **Hook, before.** The new `--check` against the old `http://localhost:8010/` printed the warning, naming `http://localhost:8010/mcp` and the config file.
  - **Hook, after.** The `url` is now `http://127.0.0.1:8010/mcp`, still mode 600. `--check`, from both this tree and the installed copy, says ok with no warning.
  - **Server.** Stable's server was restarted after the move, so a key still on the root is named again. Since the restart the log has no `old root URL` line.

**Review passes.**
- Pass 1, a cold read: no code defect. Fixed: the warning called the legacy route "the root route", though it carries every path no other route takes (the suite's `/sub` case is one); and the changelog said a root hook showed no sign, though the server's log named it.
- Tidy, behaviour unchanged: the script's usage line for `--check` and the suite's two descriptions of it name the warning, and `rpc()` reads the header once.

**Not taken.**
- *Judging the header's source.* Any front may send `Deprecation`; the warning names the proxy's legacy route because the hook's endpoint is an Open Brain, whose proxy is the one that sends it.
- *A warning from the hook's own runs.* A SessionEnd capture on the root works until v2.0.0. The server already names the key in its log, so the hook's log does not repeat it.
- *Moving the url for the user.* `--check` writes nothing, and the url is the operator's to change.
