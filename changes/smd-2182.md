## Changelog

`tier.ts --diff` no longer passes a window it replayed nothing from. Both `--diff` and `--replay` print the window and how many searches were replayed and skipped. A `--diff` that compared nothing says `nothing to compare` and exits 3, where it used to say the canary reproduces stable's rankings and exit 0. A database that does not answer is named as `--from` or `--to` with its host and port (SMD-2182).

## FORK

`tier.ts --diff` exits 3 on a window it replayed nothing from, and says which side failed to connect (SMD-2182)

**What changed.**
- `printSummary` prints, on both verbs, `replayed N of M logged searches <window> (K skipped)` and the skip reasons. The window is named with its source: `(--since)`, `(the canary's last refresh)`, or all of stable's log when the canary records no refresh. It returns a verdict:
  - `empty` when nothing was replayed: `nothing to compare`, with the reason. Either stable logged nothing in the window (it logs only with `OB1_QUERY_LOG=on`; an earlier `--since` widens the window, offered only when the window has a start) or every row was skipped;
  - `unmoved`: `what moved: nothing` names what it covers, `on the N replayed (K skipped, not compared)` when rows were skipped;
  - `moved`: the list, as before.
- `--diff` exits 0 on `unmoved`, 1 on `moved` and 3 on `empty`: not a pass, and not a move, so a caller can tell the two apart. A failed step is still 1 and a usage error or refusal 2. `--replay` is the report and still exits 0. `deploy/tier.sh` passes the status through.
- `reach()` runs `SELECT 1` on each side before anything else, in `--replay`/`--diff`, `--refresh` and `--promote`. A failure is `could not connect to --to (canary) at HOST:PORT/DB: <driver message>`. `where()` prints the host, port and database from the URL, never the user or password.

**Why.** SMD-2038's pass-4 walkthrough ran `--diff` on a default stack right after `deploy/canary.sh up`. Three things emptied the window without a word:
- `OB1_QUERY_LOG` is off by default;
- the default window starts at the refresh `up` had just done;
- without `OB1_EVAL_EMBED` every hybrid row is skipped.

`--diff` printed `what moved: nothing — the canary reproduces stable's rankings.` and exited 0 each time, even at `replayed 1 of 4 (3 skipped)`, because it printed no counts. A stale container name in `--to` surfaced as Bun's bare `Failed to connect` (`ERR_POSTGRES_CONNECTION_REFUSED`, measured on Bun 1.4), which names neither side nor host.

**Held.**
- test-live [20], through the CLI on the identical canary:
  - `--diff --since 1970` passes with `replayed 2 of 2 … (--since)`;
  - with the canary's `last_refresh` set to the server's now and no `--since`, `--diff` exits 3 with `replayed 0 of 0 … (the canary's last refresh)`, and `--replay` says the same and exits 0;
  - a hybrid row with no `OB1_EVAL_EMBED` is `skipped 1: hybrid needs a provider`, and the pass covers `the 2 replayed (1 skipped, not compared)`;
  - a window holding only that row exits 3, `every search in the window was skipped`;
  - a window that is all of an empty log (the canary as its own `--from`, no refresh recorded) exits 3 and offers no `--since`;
  - an unreachable `--to` on `--diff`, and an unresolvable `--from` on `--refresh`, are named with their hosts, and their passwords never appear.
- Eight cells: 733 → 741. The CLI runs with `OB1_ENV_FILES=off`, `--no-env-file` and a working directory outside the checkout, so no env file hands it a model.
- The deploy-stack tier step runs a `--diff` over the empty window after the refresh, through `tier.sh`, and requires exit 3 and `nothing to compare`.

**Not taken.**
- Failing a `--diff` whose window was mostly skipped hybrid rows. The ticket asks for them to be reported, and they are; making skips fail is the canary CI job's policy (SMD-1805, commented).
- A code of its own for a failed step. 1 has meant "a failed step" since slice 2, so only the docs changed.
