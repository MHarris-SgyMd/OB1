## Changelog

A tool's scope is stated once, in the manifest: the MCP server registers a tool and the REST core admits its route through the same gate, and a test holds MCP `tools/list` and the REST core's OpenAPI document to one contract — names, titles, descriptions, input fields and which keys reach each (SMD-1931).

## FORK

The MCP tools and the REST core's operations are two projections of one contract, held by a test that reads both surfaces as a client does (SMD-1931)

**What changed.**
- **One gate.** `tools.ts` gains `scopeOf` and `mayCall`, moved from `rest/app.ts`: whether a key's scope unlocks a tool's group (`UNLOCKS`). `index.ts` registers each MCP tool only where `mayCall` holds, in place of a hand-written `canRead`/`canCapture`/`canWrite` beside each registration, so a tool's scope is stated once, in the manifest, for both surfaces. The surface each scope sees is unchanged: read tools for a read or write key, `capture_thought` for a capture or write key, the write tools for a write key alone.
- **One contract, tested.** `test-server.ts` [10a] lists the tools from the running MCP server with a write, a read and a capture-only key, and compares them with the OpenAPI document `rest/openapi.ts` serves: the same names one for one, and per tool the same title, the same description (bar the one rewrite of a job's poll link to `/v1/jobs/`), the same input fields schema for schema, the same required fields, a body required exactly when a body field is, and each scope's `tools/list` the operations whose `x-ob1-scope` it unlocks.

**Why.** SMD-2283 and SMD-2284 already drew both surfaces from `core/schemas.ts`'s specs and the manifest, and a tool missing a spec or a route does not compile. What was left was the gate, stated twice, and the agreement itself, which held only by name through two separate suites.

**Verify.** `bun test-server.ts` (812), `bun test-rest.ts` (272), `bun test-auth.ts` (165), `bunx tsc --noEmit` in `server-portable/`, `bun scripts/check-fork-consistency.ts`. Eight mutants, each killed by [10a]: a tool's MCP registration dropped, the scope gate removed, and in `openapi.ts` a description, a title, the input/output side of the schema, one input field, the required set and every scope changed.
