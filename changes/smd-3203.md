## Changelog

`evals/eval-mediated-pairs.ts` measures whether the consolidation pass can ask the subject-anchored ADR's mediated-pair test: the typed-decision tier and the pass's chat model, against two blind raters' labels of 100 canary pairs. Neither meets its bar. The chat model's first step finds mediated pairs (κ 0.64), but no model tells a third subject's state from its name. So decide version 4 will cap mediated pairs at related, and the ADR's test is now version 2 (SMD-3203).

## FORK

Can the pass ask the mediated-pair test? Measured in two rounds before decide mode changes (SMD-3203)

**What changed.**
- **`evals/eval-mediated-pairs.ts`** (new). It asks the pass's own models the test's question about the same 100 pairs, rendered as prompt 4 renders them (`pairContext`).
  - **Version 1, one question:**
    - the tier (H2O-Lightning-4B, ob1-jev/1) gets one choice of the six labels, worded from the test;
    - the writer (the pass's chat model) gets the test's text, read word for word from the ADR, and answers in strict JSON.
  - **Version 2, two steps:** the link (D, H, F or N), then, for an H or F link, whether the subject's state is given. It runs three ways:
    - the tier for both steps;
    - the writer's link with the tier's yes or no on the subject the writer names;
    - the writer for both steps.
  - **Scoring:** against the pairs both raters agree on, with the bar fixed on SMD-3203 before each round.
  - **Its `--self-check`** holds the mapping of labels to rows 2 and 3, both versions' questions (the writer's read from the ADR), the gold, κ, the scoring and the bar.
- **`.github/workflows/fork-checks.yml` and `db/ci-parity.sh`** run that self-check, next to the other decide-mode evals.
- **`docs/subject-anchored-claims.md`:** the test is now version 2. That is version 1, word for word, plus five rules for the points its raters flagged. Rule 1 defines a state as an explicit status or a current or measured value. The ADR records both rounds and the maintainer's choice.
- **`evals/README.md`:** the eval's section, with both rounds' results.

**Why.** Decide version 4 is to apply rows 2 and 3, which act on the test's labels. A pass that labels pairs unlike the raters would cap, or make distinct, the wrong relations. The measurement comes first, as the ADR's path asks.

**What it found.** No candidate meets all three bars:
- κ ≥ 0.6 on mediated or not;
- F-state precision ≥ 0.8, with at least 5 predicted;
- F-state recall ≥ 0.5.

| Round | Candidate | Mediated κ | F-state predicted / right (of 11) |
|---|---|---|---|
| version 1 | tier, one choice of six | 0.04 | 1 / 0 |
| version 1 | writer, the test's text | 0.51 | 0 / 0 |
| version 2 | tier, both steps | 0.21 | 1 / 0 |
| version 2 | writer's link, tier's state | **0.64** | 10 / 4 |
| version 2 | writer, both steps | **0.64** | 5 / 0 |

The writer's link step finds mediated pairs. No state step tells F-state from F-name: version 1's writer called 10 of the 11 gold F-state pairs F-name.

So the maintainer chose to build the cap (2026-10-22). Decide version 4 will ask the writer's link step of a pair it would store as evolves or propose as outdates. An H or F link is then related at most, with no supersession. Row 2's distinct waits for a state step that meets its bar.

**Not taken.**
- **Building the pass on version 1's numbers.** Its best mediated κ was 0.51, under the bar.
- **Re-rating the gold under version 2.** The raters' working definition of a state was already rule 1's, and the other four rules settle points as both raters had.
- **Reading the test from the ADR inside the pass.** The pass runs in a container without `docs/`, so decide version 4 embeds the text and holds it equal to the ADR's.

**Held.**
- Each round's candidates, prompts (by hash), gold and bar were posted on SMD-3203 before any model was asked: comments 56465f32 and 691632d2.
- The self-check passes. Mutants that call F-name distinct, or make every F link F-state, fail it.
- `bunx tsc --noEmit` passes in `evals/`.
- The test's text the writer read was unchanged between the runs and the commit (sha256 `3ecd5f97…`).
- The pairs, answers and labels stay in `/private/tmp`: brain text.
