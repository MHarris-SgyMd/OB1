## Changelog

`main` merges through GitHub's merge queue: every one of `fork-checks.yml`'s twelve jobs runs on the merge result the queue builds, and a PR that changes `db/migrations/`, `server-portable/` or `evals/` beyond tests and docs ships a `changes/smd-NNNN.md` fragment or the `Repo consistency` job refuses it by file name (SMD-1857).

## FORK

`main` merges through a queue — the twelve checks judge the tree that lands, and a landing that changes the fork records itself (SMD-1857)

**What changed.** The ruleset record `.github/rulesets/main.json` carries a
fifth rule, `merge_queue`: merge method `MERGE`, grouping `ALLGREEN`, one PR
per group at minimum, five at most, a sixty-minute check timeout. What GitHub
documents for that rule: a PR is not merged but queued, GitHub builds the
merge of `main` and the PR on a `gh-readonly-queue/main/…` ref, the workflow's
`merge_group` trigger runs the twelve jobs on that ref, and the queue merges
what passes and removes what fails, the reason on the PR's timeline — observed
here only as far as *Measured after* says. `check-fork-consistency` check 20
holds the rule's parameters as it holds the other four rules' decisions. The
`Repo consistency` job gains one step, `scripts/check-landing.ts`: given the
event's range — the PR's base and head, or the merge group's — it lists each
landing (one for a PR, from the merge base; one per first-parent commit for a
group, which under `MERGE` is each PR's merge commit, so `git diff c^1 c` is
exactly what that PR added — a first-parent commit with one parent stops the
run, since the live queue is then not merging as the record says) and refuses
one whose changes touch `db/migrations/`, `server-portable/` or `evals/`, test
files and Markdown aside, with no `changes/smd-NNNN.md` added or modified
among them, naming the files that asked. The diff is read `--name-status -z
--no-renames`, so a non-ASCII path is not C-quoted past the prefix and a file
moved out of a directory shows as its deletion there. The job's checkout
fetches history so the range can be diffed; the step runs on `merge_group`
and on a `pull_request` into `main` — a PR into another branch is asked when
it reaches `main`.

**Why.** CI ran on a PR's head against the `main` of its trigger time, so two
PRs each green on their own could together break the tree; SMD-1856's strict
rule closed that by making the author merge `main` and run again, and three
branches carried a migration 047 each while it was off. The queue is
documented to close it without the author's hand — the tree the checks judge
is the tree that lands; whether strict still gates a PR's *entry* to the queue
is a thing to observe, not assume. The fragment rule was CONTRIBUTING.md's sentence and nothing held it — of the
PRs on `main`'s first-parent line before the fragment machinery, PR #93
changed four `server-portable/` files and recorded itself only as a
hand-numbered section; run over that merge, the landing check refuses it and
names the four. The migration-number rule (5b) and the rest of
`check-fork-consistency` needed no merged-tree copy: on `merge_group` the
checkout is the group's head, so they already run on the merged result.

**Held.** Check 20: the `merge_queue` rule present once, its seven parameters
each equal to `MERGE_QUEUE`'s (five new mutants — no rule, no parameters, a
squashing queue, a head-green queue, a queue waiting for a second PR — each
reporting one problem that names the field; a parameters-string non-probe
throws nothing; twenty-five mutants, nine non-probes in all).
`check-landing.ts`: `landingProblem` is one pure function over a status-and-
path list, eighteen probes — a migration, a server file, an eval, a deleted
migration, two asking files both named; a fragment added beside a migration
passes, one modified beside a server change passes (a ticket landing in
slices extends its fragment), one deleted does not, a numbered change file
does not; tests, a test helper, Markdown, `db/` outside migrations, a
look-alike directory pass; a lockfile and an eval fixture ask — and the `-z`
parser reads a status, a path with a space and a non-ASCII path. The script
runs its probes before the range on every CI run; a probe failure, a range it
cannot read, a PR range that changes nothing, an empty group or a group whose
first-parent commit is not a merge exit 2 — the script's or the setting's
fault, never read as the PR's. The CI step runs on `merge_group` and on a
`pull_request` into `main`; on `push` there is no landing.

**Measured after.** Over `main`'s history before the change: the merge-group
range 509a4b19..6d12413d reads as three landings (PR #110, #112, #111), each
with its fragment, and passes; the PR range baed5e4d...632754fa reads as one;
PR #93's merge alone fails naming `server-portable/embed.ts`, `index.ts`,
`preflight.ts` and `store-sql.ts`; the pre-fork range ad7b9eaf..71dd543e,
whose first-parent commits are plain, stops with exit 2 naming the first of
them; an empty group, an empty PR range and a bad event exit 2.

**Not taken.** Exemption by label, as the ticket wrote it — the merge group's
run carries no pull request and the workflow's token (`contents: read`) reads
none, so a label is a rule enforced on the PR run alone and by whoever applies
it; test files and Markdown are exempt by path instead, and a change that
wants no fragment for another reason writes a `changed`/`patch` one. A
thirteenth job for the landing check — a job is a context the record must
name and a re-apply; a step inside `Repo consistency` keeps the list.
`HEADGREEN` — a red group would not say which PR; at this rate a group is one
PR and `ALLGREEN` costs nothing. Dropping strict from the record — GitHub
documents the queue as not needing the author to update the branch; the
record keeps strict for the day the queue is turned off, and what strict
still does to a queued PR is *Measured after*'s to say. Holding the
fragment's ticket to the branch name — a branch carries no ticket the check
can trust. Refusing a modified fragment of another ticket beside a server
change — the same shape as a ticket's second slice, which the fork lands.
A duplicate-migration check of the queue's own — 5b runs on the group's tree.

**Review passes.** A cold read by an independent reviewer over the commit,
with a scratch repository for the git shapes.
