## Changelog

`main` merges through GitHub's merge queue: every one of `fork-checks.yml`'s twelve jobs runs on the merge result the queue builds, and a PR that changes `db/migrations/`, `server-portable/` or `evals/` beyond tests and docs ships a `changes/smd-NNNN.md` fragment or the `Repo consistency` job refuses it by file name (SMD-1857).

## FORK

`main` merges through a queue — the twelve checks judge the tree that lands, and a landing that changes the fork records itself (SMD-1857)

**What changed.** The ruleset record `.github/rulesets/main.json` carries a
fifth rule, `merge_queue`: merge method `MERGE`, grouping `ALLGREEN`, one PR
per group at minimum, five at most, a sixty-minute check timeout. A PR is no
longer merged by the button or by `gh pr merge`; it is queued, GitHub builds
the merge of `main` and the PR on a `gh-readonly-queue/main/…` ref, the
workflow's `merge_group` trigger runs the twelve jobs on that ref, and the
queue merges what passes and drops what fails with the reason on the PR's
timeline. `check-fork-consistency` check 20 holds the rule's parameters as it
holds the other four rules' decisions. The `Repo consistency` job gains one
step, `scripts/check-landing.ts`: given the event's range — the PR's base and
head, or the merge group's — it lists each landing (one for a PR; one per
first-parent commit for a group, which under `MERGE` is each PR's merge
commit, so `git diff c^1 c` is exactly what that PR added) and refuses one
whose files touch `db/migrations/`, `server-portable/` or `evals/`, test files
and Markdown aside, with no `changes/smd-NNNN.md` among them, naming the files
that asked. The job's checkout fetches history so the range can be diffed.

**Why.** CI ran on a PR's head against the `main` of its trigger time, so two
PRs each green on their own could together break the tree; SMD-1856's strict
rule closed that by making the author merge `main` and run again, and three
branches carried a migration 047 each while it was off. The queue closes it
without the author's hand: the tree the checks judge is the tree that lands.
The fragment rule was CONTRIBUTING.md's sentence and nothing held it — of the
PRs on `main`'s first-parent line before the fragment machinery, PR #93
changed four `server-portable/` files and recorded itself only as a
hand-numbered section; run over that merge, the landing check refuses it and
names the four. The migration-number rule (5b) and the rest of
`check-fork-consistency` needed no merged-tree copy: on `merge_group` the
checkout is the group's head, so they already run on the merged result.

**Held.** Check 20: the `merge_queue` rule present once, its seven parameters
each equal to `MERGE_QUEUE`'s (four new mutants — no rule, no parameters, a
squashing queue, a head-green queue, a queue waiting for a second PR — each
reporting one problem that names the field; a parameters-string non-probe
throws nothing). `check-landing.ts`: `landingProblem` is one pure function
over a file list, fifteen probes — a migration, a server file, an eval, two
asking files both named; a fragment beside a migration passes, a numbered
change file does not; tests, a test helper, Markdown, `db/` outside
migrations, a look-alike directory pass; a lockfile and an eval fixture ask.
The script runs its probes before the range on every CI run and exits 2 on an
unreadable or empty range rather than passing it. The CI step runs on
`pull_request` and `merge_group` only; on `push` there is no landing.

**Measured after.** Over `main`'s history before the change: the merge-group
range 509a4b19..6d12413d reads as three landings (PR #110, #112, #111), each
with its fragment, and passes; the PR range baed5e4d...632754fa reads as one;
PR #93's merge alone fails naming `server-portable/embed.ts`, `index.ts`,
`preflight.ts` and `store-sql.ts`; an empty range and a bad event exit 2.

**Not taken.** Exemption by label, as the ticket wrote it — the merge group's
run carries no pull request and the workflow's token (`contents: read`) reads
none, so a label is a rule enforced on the PR run alone and by whoever applies
it; test files and Markdown are exempt by path instead, and a change that
wants no fragment for another reason writes a `changed`/`patch` one. A
thirteenth job for the landing check — a job is a context the record must
name and a re-apply; a step inside `Repo consistency` keeps the list.
`HEADGREEN` — a red group would not say which PR; at this rate a group is one
PR and `ALLGREEN` costs nothing. Dropping strict from the record — the queue
makes it moot for a queued PR, and the record keeps it for the day the queue
is turned off. Holding the fragment's ticket to the branch name — a branch
carries no ticket the check can trust. A duplicate-migration check of the
queue's own — 5b runs on the group's tree.

**Follow-ups.** SMD-1981: the queue's run lints commit messages for real, so a
bad message cannot land; the entry gate — the PR run, where the `siggymd/**`
push run's skipped check may be the one read — is still that ticket's.
