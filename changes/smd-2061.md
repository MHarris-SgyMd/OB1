## Changelog

`db/graph-centrality.ts --startable` reads the board's `blocks` / `blocked_by` link facets (migration 053) and weighs an unsettled thought whose ticket has an open blocker 0 in every count, so `--status open --startable` ranks the graph as the tickets you could start now build it; a completed or canceled blocker does not block, a Done ticket is settled rather than blocked, a parent is not blocked by its children, and without the flag every mode renders unchanged byte for byte (SMD-2061).

## FORK

graph-centrality reads the dependency edges 053 already stores — `--startable` weighs a blocked open thought 0, a settled blocker blocks nothing, and every other mode is unchanged (SMD-2061)

**What changed.** SMD-1994 made `db/graph-centrality.ts` lifecycle-aware: a
per-thought weight every count sums, `--status open` dropping Done tickets. It
still could not answer "what can I start now". A ticket blocked by an open one
ranked like a startable one, although migration 053 (SMD-1867) stores the
board's relations as `link` facets on the row holding a ticket's identity —
`blocks` on the blocker, `blocked_by` on the blocked. `--startable` reads both
directions (an edge the sync stated on one side only still counts) and
multiplies a second factor into the same weight: an **unsettled** thought whose
ticket has an **open blocker** weighs 0. Unsettled, because Linear keeps a
relation after a ticket completes: a Done ticket whose blocker is still open is
settled, not blocked, and weighs what its lifecycle says, so `--status done`
and `--decay-done` read it as without the flag. A blocker is open unless its
own lifecycle, resolved through `source_thought()` (053's resolver) to a thought
and read through SMD-1994's ticket-head rule, is completed or canceled: a
settled blocker is not a blocker. A blocker the brain does not hold, or one with
no status_type the file knows, still blocks — the source said "blocked" and
nothing says it is settled — and the output counts such blockers. A row derived
from a ticket (`ticket`) or carrying one (`issue`) takes its ticket's blockers,
as it takes its ticket's status. Only an active link counts (053 closes a
relation the source dropped), and only `blocks` / `blocked_by`: `child_of`
makes nobody a blocker. A thought whose ticket no dependency names counts as
unblocked. Under the flag the whole-graph lists hold only the entities a kept
thought mentions, as under a `--status` filter. A dependency caveat line (and
`coverage.dependencies` in the JSON) gives the active dependency facets and when
the latest was written or closed, how many thoughts belong to a ticket a
dependency names on either side, how many the flag **held** back in the run
(took from a weight above 0 to 0), and how many blockers are in force only for
want of a known status. The flag composes with `--status` and `--decay-done`:
the weights multiply. Without it the dependency read is not in the SQL, so
every other mode renders byte for byte SMD-1994's report (the JSON's `options`
carries one more key, `startable: false`) and a brain without 053 still runs
them; with it, a brain without 053 is exit 2. `dependencySql` is the seam,
beside `LIFECYCLE_CTE`: when SMD-2074's node-state projection holds
startability, it reads that and the callers see the same weight.

**Why.** Measured 2026-09-24: of the three unstarted open High-priority Open
Brain issues, two were blocked (SMD-1997 by SMD-1999, SMD-1999 by SMD-1998),
and priority-only ranking put the least actionable, SMD-1997, on top. SMD-1994
closed the status half of that divergence; this closes the dependency half. The
three have since completed, so the case is a fixture. On the dogfood brain
(2026-09-25: 775 thoughts, 165 active dependency facets naming 123 thoughts'
tickets, 0 unresolved targets), `--status open --startable` over the whole
graph holds back 28 thoughts and lists 430 of the 458 `--status open` lists; an
independent query written from the definitions finds the same set, thought by
thought. The dropped are the blocked tickets — the wiki connectors
SMD-1814–1818 behind the open SMD-1812/1813, the claim-log phases
SMD-1732/1734/1794 behind the open SMD-1731, SMD-2116–2118, SMD-2147–2150 and
the rest. SMD-1731 stays (its one blocker, SMD-1730, is completed), and so do
SMD-1806 (started, every blocker completed), SMD-1812 and SMD-1813. Under
`--status done --startable` nothing is held (479 weigh in either way), though
SMD-1713 and SMD-1809 are Done with an open blocker. The read adds 60–180 ms
to a whole-graph report of about 700 ms.

**Held.** `test-schema.ts` [44], 22 assertions over tickets with 053's own
source rows and link facets: the 2026-09-24 board as tP (backlog) blocked by
tQ (unstarted) blocked by tR (started), with tS startable under the open tP
(`child_of`). `--status open` lists all of them; `--startable` drops tP and tQ
and keeps tR and tS. A section derived from tP is blocked with it. A `blocks`
stated on tR's side alone blocks its target tV, which holds no facet and is
counted among the thoughts a dependency names. A closed `blocked_by` blocks
nothing. A blocker not in the brain blocks and is counted. Hand captures and
tickets no dependency names pass. tD, Done with a `blocked_by` to the open tQ,
is listed by `--status done --startable`, which weighs in exactly what
`--status done` does and holds nothing back, and weighs 0.25 under
`--decay-done --startable`. `held` counts what the flag did in the run: five
under `open`, one under `active` (tQ; the backlog ones already weigh 0).
Once tR completes, tQ and tV are free and tP still waits on tQ. The control:
the default and `--status open` reports rendered before the links were written
are byte-identical after, `weightsSql` without the flag carries no
`thought_facets`, and `coverage.dependencies` is absent. Plus the coverage
numbers, the dependency line and header text, the no-neighbour line naming the
flag, and `parseArgs`. Mutants, each killed: a settled blocker still blocking
(fails and crashes the section); the `blocks` direction dropped (4); closed
links read (4); `child_of` read as `blocked_by` (fails and crashes); derived
rows not given their ticket (5); an unknown blocker not blocking (5); the
blocked factor dropped from the weight (8); a settled ticket still blocked (2);
`held` counting every blocked row (2).

**Not taken.** *Down-weighting a blocked thought instead of dropping it*
(Work item 3, a pre-registered `BLOCKED_WEIGHT` behind `--decay-blocked`):
cut at the plan stage as its own PR, to be judged on this read's numbers.
*Treating an unresolved or lifecycle-less blocker as settled*: it would make
startability depend on what the brain happens to hold; the count is printed
instead. *Linear's `duplicate` state type* (five tickets on the brain carry
it; a blocker closed as Duplicate would block forever): it is missing from
SMD-1994's `LIFECYCLE_TYPES`, and adding it changes `--status` output, so it
is SMD-2158. *A column naming each thought's blockers*: under the filter a
blocked thought is not listed, so the column would be empty; it belongs with
the down-weight. *Reading `child_of` as a gate*: an epic's children are its
work, not its blockers. *The shared node-state projection* every ranking
surface reads: SMD-2074.
