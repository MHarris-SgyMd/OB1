## Changelog

The claim workers and the scheduler read their numeric options through one reader in `db/cli.ts` (SMD-4308, PR 1). No behaviour changes: every default, rule and refusal is as it was.

## Record

One reader for the engines' numeric options — `optionReader` in db/cli.ts, in place of the copy each `numbers()` held, the ticket's PR 1 (SMD-4308)

**Problem.** `consolidate.ts`, `extract-entities.ts` and `sleep.ts` each defined the same `read(flag, value, absent, rule)` closure inside `numbers()`, and `reembed.ts` held it as `readOption`: the option given, held to its flag's rule by `numberProblem`, the CLI's default when absent, and a refusal with the script's flag list under it. Four copies of five lines, differing only in whether the rule had a default and whether its type named `fraction`.

**Change.** `db/cli.ts` exports `optionReader(spec, hints)`, which returns that reader bound to a script's flags. The four `numbers()` functions, and reembed's `leaseNumbers()`, call it. The rule defaults to a whole number >= 1, as three of the four copies had it; `sleep.ts` passes a rule at every call, so the default changes nothing there. The flag list is still built only when a rule is broken.

**Verify.** `test-engines.ts` gains two rows on the reader itself: the default for an absent option and the option when its rule holds; and a broken rule refused in `numberProblem`'s words with the flag list under them. The engines' refusals were already pinned through each worker: with the flag list dropped from the reader, 40 of test-engines' rows fail (caught: mutant).

This is the first of the ticket's PRs. The claim loop itself, which the workers still each hold, is PR 2.
