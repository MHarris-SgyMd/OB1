## Changelog

The proxy's route tables in `deploy/compose.yaml` and `deploy/compose.api-public.yaml` carry no comment lines: their notes are YAML comments above each table, since Traefik renders a route file as a Go template before it reads it, so a comment line in a table could add a router. The tables route exactly as before; their label copies change, so the next `up -d` recreates the proxy once. The fork's checks now hold each one byte for byte, and hold that no overlay changes the proxy beyond its own table (SMD-2658).

## FORK

The proxy's route tables carry no comment and are held byte for byte — a comment line in one can no longer add a router, nor an overlay change what the proxy loads (SMD-2658)

**What changed.**
- **The comment lines moved out of the tables.** compose.yaml's `x-proxy-routes` had 44 and compose.api-public.yaml's `x-api-route` had one. They are now YAML comments above each block, which compose drops.
  - The router list in compose.yaml's header comment gains an `api-off` entry, a list of the middlewares and a note on the rooted mesh names, which were in the table.
  - What each in-table note added to the header's entries (the origin's Host on `resource`; the reasons for `tier-off`'s missing boundary) is merged in.
  - The tables themselves are unchanged, byte for byte, less those lines. compose renders main's files and these identically, under every profile, once main's comment lines are dropped.
- **Check 28** (`scripts/check-fork-consistency.ts`) reads every compose file directly in deploy/ (`compose*.yaml`/`.yml` and `docker-compose*`, in any case, and any file whose name is not printable ASCII) but compose.tiers.yaml, which is check 27's. A contributor's local, untracked `deploy/compose.override.yaml` now fails it; a local overlay named with `-f` (say `compose.local.yaml`) that leaves the proxy alone passes.
  - **`table`:** as Bun.YAML parses each file, two values must each equal the table built in the checker (`PROXY_ROUTE_TABLE`, `API_ROUTE_TABLE`), byte for byte: the config compose mounts (`configs.proxy-routes.content`, its only key) and the proxy label that copies it (`ob1.proxy-routes`). The anchor itself is not compared, since compose ignores it. The built table has no comment in it, so a router changed on purpose is changed there too, as check 13's `PUBLISHES` is.
  - **`proxy`:** what each file may do to the proxy.
    - compose.yaml defines it, and mounts only its table on it.
    - compose.api-public.yaml sets only its own table's mount, label and `depends_on` on it.
    - Any other overlay sets nothing on it. No overlay redefines a network it joins (`default`, `mesh`) or names the project, which renames them.
    - Each file defines only its own table's config, and none has `secrets` or `include`.
    - The proxy names no `$`, its ports aside: CI renders with its own settings, so `target: ${X:-…}` would pass there and move the table under a deploy/.env.
    - No file directly in deploy/ has a name compose takes for its own with no `-f` (`compose.override.yaml`, `docker-compose.override.yml`, or a default name a checkout could put in compose.yaml's place), which CI never renders. Names match in any case: on macOS compose read `Compose.Override.yaml` with no `-f` (measured). No file name directly in deploy/ leaves printable ASCII: macOS folded `docKer-compose.override.yml`, with U+212A, onto the override name (measured).
  - **`characters`:** no file carries a control, format or separator character other than the space and the line feed.
  - **`tags`:** no file carries a `!!` or named `!x!` tag handle, a verbatim `!<…>` or percent-escaped (`!%21binary`) tag, or a `%` directive: the ways to write a tag that resolves to `!!binary`. Bun.YAML refuses a percent-escaped tag today, so `parse` catches that one too; the rule holds it if Bun.YAML stops refusing. compose decodes a `!!binary` key and Bun.YAML keeps its base64 text, so an overlay hid a `proxy`, `name` or `mesh` key from every rule above (measured, review pass 6). A plain local tag Bun.YAML reads past as compose does; what `!reset` and `!override` do, the CI step renders. A shell `[!0-9]` in one of main's block scalars is none of these.
  - **`parse`:** each file parses as one YAML mapping.
  - The tables are built from the same parts as check 27's `TIER_ROUTE_TABLE` (`routeRouter`, `routeErrors`, `routeService`, and the canary, working, `tier-off` and `/health` routers). So the tier routes of compose.yaml and compose.tiers.yaml cannot drift apart. `oddCharacters` is check 27's character rule, now shared.
- **CI** has a new step in the full-stack job, "The proxy loads only the held route tables". It renders with `docker compose config`, which merges overlays as no Bun.YAML read can (`!override`).
  - compose.yaml's own proxy, every profile on, reads routes from `/etc/traefik/dynamic` and no other provider, with no command, entrypoint, volume or `env_file`. A command makes Traefik drop every `TRAEFIK_*` setting: measured on the pin in review pass 2, `TRAEFIK_ACCESSLOG=true` read as true in `/api/overview` alone and as false beside any flag.
  - Then for compose.yaml (every profile), with compose.api-public.yaml, with compose.host-ports.yaml, with both, with compose.canary.yaml under the canary's project name, with the release's overlay alone and with compose.api-public.yaml (rendered twice: as a rehearsal renders it, `release-artifacts.ts compose --rehearsal`, and as a tag's run does, `renderComposeOverlay` with a tag and digests, which the CLI refuses on a tree that is not the cut), and compose.tiers.yaml, the proxy must:
    - equal compose.yaml's key for key — image, environment, user, ports, volumes, hooks, secrets, hosts — except for its `configs`, labels and `depends_on`;
    - mount exactly the held tables, each copied into its label and equal, by `cmp`, to its file's as Bun.YAML reads it, and define no config but those tables, each its content and name alone, so no table waits for a file order CI does not render. An unmounted config shows only in the `--no-interpolate` render: compose drops it from a substituted one;
    - in each overlay combination, keep the project's name, and the definitions of the networks the proxy joins, as the first file alone renders them under the same `-p`. That is compose's reading, so a key Bun.YAML reads otherwise (`!!binary`) cannot hide a renamed mesh. For compose.yaml alone and compose.tiers.yaml it compares a file with itself and holds nothing.
  - Each holds twice: with variables substituted, and with none (`--no-interpolate`), the tables' text included. A value that matches under CI's settings and moves under an operator's (`${OPENROUTER_API_KEY:+evil-}proxy-routes`, or `priority: ${…:+5}1` in a table) fails the second. Labels are held on the first alone: `--no-interpolate` leaves two files' labels a list.
  - A compose file in deploy/ that no combination renders fails the step, so a new overlay gets one.
- **release.yml** holds the overlay a release ships, before it brings the stack up or creates the GitHub release (a tag's images are already pushed by then, as for the job's other checks): with it, compose's project name, networks, configs and proxy equal compose.yaml's own, with and without compose.api-public.yaml, substituted and raw. fork-checks renders the generator's rehearsal and tag forms; only this holds the file built from the real tag and digests, whatever branch rendered it.
- **The orchestration runner's imports mount is written in long form** (`type: bind`, `source: ${IMPORTS_DIR:-./imports}`, `read_only`, `bind.selinux: z`). The CI runner's Compose (2.38.2 on ubuntu-24.04, and every release measured through 2.40.0) reads the short `${IMPORTS_DIR:-./imports}:/imports:ro,z` as "too many colons" when it renders with `--no-interpolate`, so both new checks failed there; the long form renders the same mount, substituted, as before (compared on v5.5.0).
- **CI's url scan of compose.yaml's table** ("Every published port binds loopback") is gone: check 28 holds the whole table, and the new step holds it as compose renders it. The tier-route step's comment, which cited it, now cites `PROXY_ROUTE_TABLE`.
- **deploy/README.md**'s "Adding a service" names the third edit, and says a note on a route goes above the block.

**Why.** Traefik v3.7.13's file provider runs each dynamic file through Go's `text/template`, with sprig, before it decodes the YAML (SMD-2294, review pass 7, from its source). No check read compose.yaml's table: CI scanned only its `url:` values and that the label equals the config. Measured on the pinned image (`traefik:v3.7.13@sha256:24841fe2…`), handed compose.yaml's table with one line added:
- **A template on a comment line** (the ticket's): `# {{ "\n    all:\n      rule: \"PathPrefix(`/`)\"\n      priority: 100\n      service: canary" }}` loaded as `all@file`, `PathPrefix(/)`, priority 100, to the canary. Every request on the origin went to another tier.
- **A no-break space before `#`:** a line that reads as a comment loaded as a router named `" #nbsp"` with the same catch-all.

A third gap came up while writing the check. compose breaks a line at U+2028 and Bun.YAML does not. So a comment line holding U+2028, then `x-shadow: &proxy-routes "http: {}"`, is a comment to Bun.YAML and a second anchor of the same name to compose. Measured with `docker compose config` (v5.5.0): the config and the label both became `http: {}`. Bun.YAML still read the right table, and CI's label-equals-config line still passed.

**Not taken.**
- **Another service taking the proxy's traffic:** a mesh-name alias, a sidecar in the proxy's PID namespace, a second network into stable's mesh from compose.canary.yaml (review pass 3, measured). Check 27 refuses the first for the tiers file. Generalizing it is SMD-2685, which also takes compose.yaml's own proxy beyond its table and mounts (its image, a hook, `extra_hosts`).
- **A live `COMPOSE_FILE` or `COMPOSE_PROJECT_NAME` line in deploy/.env.example**, which an operator copies to deploy/.env (pass 4, measured): an edit in view, in a template, left to review.
- **A `$` in a table.** `docker compose config` writes a `$` back as `$$`, so a table that needed one would be `$$` to both checks and `$` to Traefik. No table has one, and adding one edits the checker's table, in view.
- **A YAML 1.1 number rule,** as check 27 has for the tiers file: a number in compose.yaml's proxy that compose read otherwise changes its render, which compose.yaml's own reviewers hold (SMD-2685).
- **A committed `deploy/.env`,** gitignored, so it takes a force-add; and **a variable in compose.yaml's own top-level `name:` or networks**, which its reviewers hold (SMD-2685).
