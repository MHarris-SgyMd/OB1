## Changelog

The canary is a brain of its own on a port of its own: `deploy/canary.sh` no longer stands it at `/canary/mcp` on stable's origin with its servers on stable's mesh, and `deploy/compose.canary.yaml` is gone. `up` takes the canary's port from `--port` the first time and from the canary's env file after, which now holds the canary's own port, loopback address, tier and profiles; a `--port` that differs is written there, as are the canary's own settings into a file made before this, and stable's port is refused. A canary standing on stable's origin moves to its port at its next `up --port N`, on the same volume (SMD-2874).

## FORK

The canary is a brain on a port of its own — path mode and `compose.canary.yaml` retired, PR 1 of SMD-2874 (SMD-2874)

**What changed.**
- `deploy/canary.sh`:
  - one mode: the canary's own proxy and forwarder on `127.0.0.1:<port>`, at `/mcp`. Gone: the mode switch, `compose.canary.yaml`, `CANARY_STABLE_MESH`, the checks of stable's proxy (its `/canary` route, its mesh, its forwarder's port), the notes on stable's bind address and public origin reaching the canary, and the step that removed a canary's own proxy once it answered on stable's origin;
  - the port is `--port`, else the canary's env file's `SERVER_PORT`, read only from a file holding the canary's own tier, which `up` writes with the port: a file made before this holds stable's tier and the port stable had then. With neither, or with a file naming stable's port, `up` refuses with exit 2, naming `--port`. So it does when the port is stable's (its env file's `SERVER_PORT`, else 8000, or the port its forwarder publishes). Where the file holds another port, address, tier or profiles than the canary's own (a `--port` that differs, or a file made before this, which holds stable's), `up` appends the canary's own to a copy of the file, since compose reads the last setting of a name (measured, Compose 5.5.1), reads the copy back through compose, and puts it in the file's place, written mode 600, the rest of the file unchanged; it says what it wrote;
  - the canary's env file, when `up` makes it, holds the canary's own `SERVER_PORT`, `SERVER_BIND="127.0.0.1"`, `OB1_TIER="canary"` and `COMPOSE_PROFILES=""`, not stable's, so compose given that file alone is the canary. canary.sh still hands compose these four in the shell. The file is checked as it is made, these four included;
  - a connector counts as the canary's on one of its ports: `--port`, the file's, the one its forwarder published when the run began and the one it publishes now, never stable's (its env file's port or the one its forwarder publishes) (a file made in path mode names stable's port: review pass 1). One left at `/canary/mcp` on stable's origin, or at stable's `/mcp`, is stable's URL. `up` names one at `/canary/mcp`, `up --connect` refuses it with the command that removes it, and `down` leaves both. One left at a port the canary moved off is named with the command that removes it, since from the next run that port is not the canary's;
  - the telemetry note (stable's collector, `lgtm.ob1.internal`, unreachable from the canary) is said whenever the endpoint names it, since no canary is on stable's mesh;
  - `bound_ip` and `host_of`, which read stable's bound address for path mode, are gone. Check 30's hint now points at `deploy/instance.ts`'s `portsFromBindings` for reading a binding's address from its JSON.
- `scripts/check-fork-consistency.ts`, check 28: `compose.canary.yaml`'s `OVERLAYS`, `FILE_NETWORKS` and `SERVICE_NETWORKS` entries are gone. Its eight probes are kept against `compose.grafana-port.yaml`, so each rule they caught keeps its catch: U+2029, a verbatim `!<…binary>` key, a `%TAG` directive, two `!!binary` flow keys, a second network key external by another's name with a shadow answering as `mcp.ob1.internal`, a second key alone, and a `!override` on a service's networks.
- `.github/workflows/fork-checks.yml`:
  - "Every published port binds loopback" renders the canary as canary.sh runs it, `compose.yaml` alone under `open-brain-canary`: every network its own and none external, one port, its forwarder's, on `127.0.0.1:8011`. With every profile, nothing is on a default network, and every network is the canary's;
  - "The proxy loads only the held route tables" renders `compose.yaml` under the canary's project with no overlay;
  - the refusals step drops the old-stable-proxy and proxy-off-mesh refusals. It adds no port, stable's port, and a canary file naming stable's port. It refuses a connector left at `/canary/mcp`, naming it, with no canary file and with one naming stable's port, and a `down` on that file leaves connectors at stable's `/canary/mcp` and `/mcp` alone. Its other refusals pass `--port 8011`;
  - the canary's life:
    - `--port 8011 up --connect`: the file holds the canary's own four settings. The connector is at `127.0.0.1:8011/mcp`. Every canary container is on `open-brain-canary_*` networks alone, and stable's mesh holds no canary container;
    - an `up` with no `--port` runs on the file's port;
    - the root connector's note says `--connect`;
    - a fourth `up`, on `--port 8012`: the port is written to the file (mode 600, compose reading 8012), the forwarder moves, 8011 is freed, and a connector left there is named. Then 8013 is edited into the file by hand, and an `up` with no `--port` moves there and names the connector left at 8012;
    - teardown leaves a connector at `/canary/mcp` alone, and its last `down` finds the canary's connector by the file's port.
- `deploy/compose.yaml`: Postgres's and the networks' comments no longer name the overlay.
- `deploy/README.md`:
  - "A canary beside the stack" describes the canary on its own port: its env file's four settings, the port rules, the move of a canary from stable's origin, connectors, and CI's four `up`s;
  - the networks list and the telemetry paragraph say no canary joins stable's mesh.
- `db/README.md`: `--compare` against a canary names its own port, with a key per side.
- `docs/one-brain-per-stack.md` and `docs/operator-surface-tiers.md` say what is built and what it supersedes.

**Why.** SMD-2872's ADR: each brain is self-contained, and brains never join each other's networks. In path mode, names resolved across the two brains: `mcp.ob1.internal`, `api.ob1.internal` and `auth.ob1.internal` reached stable from the canary. Stable's proxy carried the canary's route. The canary was reached wherever stable was, and check 28 spent eight probes and three tables policing the join. Port mode already ran the canary behind its own proxy. Stable's tier routes (PR 3) and the canary's own keys (PR 2) follow.

**Held.**
- Local, against a scratch stable env file naming a project with no stack (`ob1zz`):
  - `up` with no port and no file is refused, and so is `--port` set to stable's port. A file naming stable's port, or no port, is refused too;
  - `--port 8091`, and a file naming its own port, each pass the port rules and stop at the missing stack. No refusal makes a file.
- The env-file functions, lifted out of canary.sh, on scratch files:
  - the made file holds the canary's port, loopback, tier and empty profiles. It carries stable's other settings and no Linear key, has one `SERVER_PORT` line, is mode 600, passes the guard, and drifts on nothing;
  - `set_canary_own` appends 8092 past a last line with no newline, and says so. Compose reads 8092, the line before is kept, the file is mode 600, and no temporary file is left;
  - on a file made before this (stable's port, `0.0.0.0`, `stable`, `sleep`), it writes all four of the canary's own, and a second run writes nothing.
- A file with a port and no canary tier (made before this) is refused without `--port`, and a `down` on one naming a port stable left leaves the connector there; with the tier check dropped, both fail (mutant).
- Stable's port is never the canary's: `down` with a file naming stable's port, under a stub `claude`, leaves connectors at stable's `/canary/mcp` and `/mcp`, and removes one at `--port`. With the filter dropped from `canary_ports`, both leaves fail (mutant).
- The CI render's `jq` holds on Compose 5.5.1, for the canary alone and with every profile.
- The checker passes, retargeted probes included; tsc in scripts/; shellcheck on canary.sh; actionlint on the workflow.

**Not taken.**
- Writing the canary's own settings in place with `deploy/env-file.ts`'s `setEnvValues`, which keeps a symlinked file's link and one line per name, where `set_canary_own` appends and renames: PR 2 rewrites the same writes for the canary's keys, and takes it up there.
- A MAJOR bump: no released URL stops answering. Stable's proxy still routes `/canary/mcp` (PR 3 is where that question is argued), a standing path-mode canary keeps answering until its operator runs `up --port N`, and its connector at `/canary/mcp` moves when the operator removes it (`claude mcp remove --scope user open-brain-canary`) and runs `up --connect`, which refuses to replace it until then. An `https://` connector at `/canary/mcp` gets the generic refusal without that note (accepted: canary.sh registers `http://` alone).
