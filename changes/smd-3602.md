## Changelog

AGENTS.md and CLAUDE.md now tell every coding agent to claim its ticket on the stable brain when it creates the branch, keep the token in a git-ignored `.work-claims/` file, renew while working, release at merge or abandon, and read `list_claims` before recommending or starting work. The session-capture hook, given a claim key, renews those claims at each compaction and session end, and with its new `--claims` hook every quarter lease while a Claude Code session works. It never claims or releases (SMD-3602).

## FORK

Agents claim their work, and the session hook keeps the claims alive — the rule for every agent in AGENTS.md and CLAUDE.md, renewal in the hook (SMD-3602)

**What changed.**
- **The rule** (AGENTS.md and CLAUDE.md, "Claim your work", under "Parallel Agent Worktrees", one text in both). The claim domain is the stable brain, the one sessions capture on; a canary is another domain. An agent:
  - reads `list_claims` before recommending or starting a ticket, and leaves held work alone;
  - claims at branch creation with a label naming its tool, machine and branch, then moves the ticket to In Progress;
  - keeps the token in `.work-claims/<claim id>.json` at the worktree's root, mode 600;
  - renews about hourly, and stops work on a claim that ended or was taken over;
  - releases at merge or abandon with the PR as the reason, and deletes the file.

  It also covers a lost token (claim again once the claim lapses, or ask an operator), a brain without the claim tools, and keys: sessions get an agent-kind key, and the operator key, which can force-release, is the person's.
- **`.gitignore`** ignores `/.work-claims/`. `git worktree remove` takes ignored files with the worktree, so the token goes with it.
- **The hook** (`recipes/session-capture-hook/session-capture.mjs`, recipe 1.7.0):
  - **Config.** A brain's `claim_key` or `claim_key_file` (and `OB1_CLAIM_KEY` for the one-brain shape) is the agent's key, or a write key under its name. A claim belongs to the key's agent id. Giving both forms, an empty key, or a claim key beside a `brains` list is refused.
  - **What it renews.** The claims in the session's worktree, the nearest directory up from the hook's `cwd` with a `.git`. Each token file's `server` picks the brain by its `connector`; without one, the brain is the one with a claim key.
  - **When.** A claim is due a quarter of its lease after the last attempt: hourly on the default lease, never more often than every minute or less often than every hour. A compaction and a session's end renew whatever wasn't renewed in the last minute. A Stop turn renews only what is due. The new `--claims` hook (`--print-hook claude-code --claims`: async `PostToolUse` on every tool and `UserPromptSubmit`) renews what is due and captures and copies nothing. Each claim is stamped before its call, and the call runs in a detached child, as a capture's does.
  - **It never claims or releases.** A branch for a ticket and a scratch branch look alike, and a session can end with its PR open.
  - **Outcomes.** A claim released, or taken over after it lapsed, has its file rewritten as `<name>.ended.json`: the work, the code and the brain's words, without the token. Anything else keeps the file and is retried when next due: the brain or its registry away, a token the brain does not match, a claim key that is not the holder's (the log names which key it must be), or a claim this brain does not have (the log suggests `server`). Log lines name the work and claim id, never the token. A token file others can read is renewed with a note to `chmod 600` it.
  - **By hand.** `--renew-claims [--cwd <dir>]` renews now and prints what happened. `--check` says whether the claim key can call `renew_claim`.

**Why.** Claims (SMD-3597, SMD-3598) help only if agents make them and read them. The repo's one convention was a Linear status, which an agent on another machine or client without a hook cannot see (SMD-3596). A claim nobody renews lapses in four hours, and a session working past that would lose its work to the next agent. Claude Code fires no event while waiting on its user, but fires one at every tool call and every prompt, so a throttled renewal on those keeps a working session's claim. A session waiting overnight lets its claim lapse, and its next prompt renews it, unless another agent has taken the work. Migration 115 renews a lapsed claim nothing covers.

**Held.** `test-session-capture.mjs` `[13]`, 41 assertions against a fake brain answering `renew_claim` as 115 does. Ten drop-the-mechanism mutants, each killed:
- a checkpoint waiting the quarter lease;
- no interval;
- an ended claim's file left as it was;
- the ended file keeping its token;
- `--claims` falling through to the fan-out;
- renewal on every event;
- the token in the log;
- a session's end releasing;
- the file's lease not sent;
- a not-yours refusal ending the claim.

The first run's mutants left two gaps, each closed in the tests. Leaving an ended file as it was crashed the suite rather than failing a row, since the test read the file unguarded. Renewing on every event survived, since its case ran inside the checkpoint's minute.

On a scratch stack of this branch (`ob1-3602`, its own `/mcp` and write key), the rule's steps ran as a Codex agent would follow them:
- `list_claims`, `claim_work`, a second claim refused `WORK_CLAIMED` naming the holder, `list_claims` showing the label, and `release_claim` with the PR as reason.
- The hook's `--renew-claims` turned the released claim's leftover file into `.ended.json`, without the token.
- A claim on a 120 s lease, with the `--claims` hook firing every 10 s, was renewed each minute and live past its first lease end.
- A claim nothing renewed lapsed.
- The hook's log named no token.

**Not taken.**
- **Stamping before the call is not held by a test.** It guards two events starting at the same moment, and a test of it would race the two processes' start-up. A miss costs one duplicate renewal, which is idempotent.
- **The hook doesn't record the token itself** (a `PostToolUse` on `claim_work` writing the file). One rule for every agent keeps a Codex or Cursor session, following AGENTS.md alone, in the same shape as Claude.
- **No release at session end.** The ticket's choice: a session ends with its PR open as often as merged.
- **Codex gets no `--claims` hook.** It has no async hook; its agent renews by the rule, and its session hook renews at each event it fires.

**Follow-ups.**
- SMD-3599, the `claimed` label on results, so a "what next" answer sees held work without the separate call the rule asks for.
