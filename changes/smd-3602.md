## Changelog

AGENTS.md and CLAUDE.md now tell every coding agent how to claim its ticket on the stable brain: check `list_claims` (lapsed claims included) before recommending or starting work, claim before creating the branch, keep the token in a git-ignored `.work-claims/` file, renew at commits, pushes and resumes, hold the claim for a week once the PR is open, and release at merge or abandon. The session-capture hook, given the agent's own key as its claim key, renews those claims at each compaction and session end, and with its new `--claims` hook every quarter lease while a Claude Code session works. It never claims or releases (SMD-3602).

## FORK

Agents claim their work, and the session hook keeps the claims alive — the rule for every agent in AGENTS.md and CLAUDE.md, renewal in the hook (SMD-3602)

**What changed.**
- **The rule** (AGENTS.md and CLAUDE.md, "Claim your work", under "Parallel Agent Worktrees", one text in both). The claim domain is the maintainer's stable brain, the one sessions capture on. A canary is another domain, and a brain that isn't this repo's has none. An agent:
  - reads `list_claims` with `include_ended` before recommending or starting a ticket. It leaves live claims alone and treats a lapsed, unreleased claim whose branch or PR exists as paused work, asking the user before claiming;
  - claims before creating the branch, with a label naming its tool, machine and branch and a piece spelled as the plan spells it, then moves the ticket to In Progress. It reads a `WORK_CLAIMED` refusal by whose claim is in the way: its own, another session of its key, or another key;
  - keeps the token in `.work-claims/<claim id>.json` at the worktree's root, mode 600, in a directory of mode 700 with its own `.gitignore` of `*`. The token is never written anywhere else, and `git stash -a` and `git clean -X` are never run over it;
  - renews at each commit, push, long test run and resume, and reads `.work-claims/` after a resume or compaction. It stops on a refusal saying the claim ended, on an `.ended.json` the hook left, or on `WORK_CLAIMED` at a renewal;
  - renews for a week when it opens the PR, so the claim holds through review;
  - releases at merge or abandon, before removing the worktree, with the PR as the reason. A reply that the claim had already been taken over means telling the user before merging.

  It also covers a lost token and a brain without the claim tools: name the cause, then check worktrees, branches and Linear instead. On keys: the claiming key alone renews, sessions get an agent-kind key (`set_agent_kind`), and the operator key belongs to the person. The Rules bullet on removing a merged worktree now says to release its claims first.
- **`.gitignore`** ignores `.work-claims` at any depth, and the root `.dockerignore` keeps it out of the build context. `git worktree remove` takes ignored files with the worktree, so the token goes with it.
- **The hook** (`recipes/session-capture-hook/session-capture.mjs`, recipe 1.7.0):
  - **Config.** A brain's `claim_key` or `claim_key_file` (and `OB1_CLAIM_KEY` for the one-brain shape) is the very key the agent claims with: a claim belongs to the key's agent id, and a server takes one key per name. Giving both forms, an empty key, or a claim key beside a `brains` list is refused. `--check` warns about an `OB1_CLAIM_KEY` no brain reads.
  - **What it renews.** The claims in the session's worktree: the directory found by walking up from the hook's `cwd`, symlinks resolved, to the nearest `.git` that keeps a `.work-claims/`. A token file's `server` picks the brain by its `connector`. Without one, the config's one brain; with several, a file must name its server.
  - **When.** A claim is due a quarter of its lease after the last attempt: hourly on the default lease, and on a week's. It is never renewed more often than every minute or less often than every hour. A compaction and a session's end renew whatever wasn't attempted in the last minute. A Stop turn renews only what is due. The new `--claims` hook (`--print-hook claude-code --claims`: async `PostToolUse` on every tool and `UserPromptSubmit`) renews what is due and captures and copies nothing; on a session hook's own event the flag still captures. Each claim is stamped before its call, and the call runs in a detached child told the claims by id.
  - **It never claims or releases.** A branch for a ticket and a scratch branch look alike, and a session can end with its PR open.
  - **Outcomes.** A released claim (by its holder, an operator, or a takeover after a lapse) has its file rewritten as `<id>.ended.json`: the work, the code and the brain's words, without the token. It is written to a fresh file and renamed into place. Anything else keeps the file and is retried when next due:
    - the brain or its registry away;
    - a token the brain does not match;
    - a claim key that is not the holder's;
    - a claim this brain does not have;
    - `WORK_CLAIMED`: lapsed while another claim covers the work, which 115 renews once that claim ends.

    An ended claim whose file can't be rewritten keeps a stamp.
  - **What it won't read.** A file not named `<claim id>.json`, one whose id its name does not match, a symlinked token file, and a symlinked `.work-claims`.
  - **Secrets.** Log lines name the work and claim id, code first, and never the token; a token-shaped run in a brain's words, a ticket or a file name is masked. A token file others can read is set to 600 and its directory to 700. The capture's secret scan also catches the markdown-escaped `wc\_…`.
  - **By hand.** `--renew-claims [--cwd <dir>] [--claim <id>]` renews now and prints what happened. `--check` says whether the claim key can call `renew_claim`.

**Why.**
- **Claims only help if used.** Claims (SMD-3597, SMD-3598) help only if agents make them and read them. The repo's one convention was a Linear status, which an agent on another machine, or a client without a hook, cannot see (SMD-3596).
- **Renewal is what keeps a claim.** A claim nobody renews lapses in four hours, and a session working past that would lose its work to the next agent. Claude Code fires no event while it waits on its user, but it fires one at every tool call and every prompt, so a throttled renewal on those keeps a working session's claim.
- **Waiting outlasts four hours.** A PR waits for review longer than four hours, so the rule holds an open PR's claim for a week. A session waiting overnight on a shorter lease lets its claim lapse, and the next agent reads that lapsed, unreleased claim as paused work. Migration 115 renews a lapsed claim nothing covers.

Review pass 1's reviewer ran 21 more on a copy. The survivors became tests in pass 1: `WORK_CLAIMED` and the other kept codes, the Stop turn when due, the detached checkpoint, the stamp before the call, `--claim`, `OB1_CLAIM_KEY`, and a `server` naming a brain without a key.
- **Scratch stack.** On a scratch stack of the first commit (`ob1-3602`, its own `/mcp` and write key), the rule's steps ran as a Codex agent would follow them:
  - `list_claims`, `claim_work`, a second claim refused `WORK_CLAIMED` naming the holder, `list_claims` showing the label, and `release_claim` with the PR as reason;
  - the hook's `--renew-claims` turned the released claim's leftover file into `.ended.json`, without the token;
  - a claim on a 120 s lease, with the `--claims` hook firing every 10 s, was renewed each minute and was live past its first lease end;
  - a claim nothing renewed lapsed;
  - the hook's log named no token.
- **The claim key, on a real database.** Review pass 1's operator reviewer, on a throwaway Postgres, showed that a second key under the connector's name shares its agent id and renews its claims. It also showed that `MCP_ACCESS_KEYS` refuses the name twice, so preflight fails: the first commit's advice to mint one would have kept the REST core down.

**Not taken.**
- **The hook doesn't record the token itself** (a `PostToolUse` on `claim_work` writing the file). One rule for every agent keeps a Codex or Cursor session, following AGENTS.md alone, in the same shape as Claude.
- **No release at session end.** The ticket's choice: a session ends with its PR open as often as merged.
- **Codex gets no `--claims` hook.** It has no async hook. Its agent renews by the rule, and its session hook renews at SessionEnd, or on Stop turns if that hook is pasted.
- **A token split across two lines** in a summary is not scanned for. No agent writes it so.
- **Keeping tokens under the git directory** (`$(git rev-parse --git-dir)`) would be out of git's reach entirely. But a sandboxed agent (Codex's workspace-write) may not write there, and the directory's own `.gitignore` gives the same protection on any branch.
