## Changelog

AGENTS.md and CLAUDE.md now tell every coding agent how to claim its ticket on the stable brain: check `list_claims` before recommending or starting work, claim for a day before creating the branch, keep the token in a git-ignored `.work-claims/` file, renew at commits, pushes and resumes with the file's lease, hold the claim for a week once the PR is open, and release at merge or abandon. The session-capture hook, given the agent's own key as its claim key, renews those claims at each compaction and session end, and with its new `--claims` hook every quarter lease while a Claude Code session works. It never claims or releases (SMD-3602).

## FORK

Agents claim their work, and the session hook keeps the claims alive — the rule for every agent in AGENTS.md and CLAUDE.md, renewal in the hook (SMD-3602)

**What changed.**
- **The rule** (AGENTS.md and CLAUDE.md, "Claim your work", under "Parallel Agent Worktrees", one text in both). The claim domain is the maintainer's stable brain, the one sessions capture on. A canary is another domain, and a brain that isn't this repo's has none. An agent:
  - reads `list_claims` for each ticket it considers before recommending or starting one. It leaves a live claim's work alone. A lapsed claim is free, since its holder went a day without renewing, or a week with a PR open. A live claim whose PR merged, or whose ticket is Done, is reported to the user as stale;
  - claims for a day (`lease_seconds: 86400`) before creating the worktree and branch, with a label naming its tool, machine and branch and a piece spelled as the plan spells it, then moves the ticket to In Progress. It reads a `WORK_CLAIMED` refusal by whose claim is in the way: its own, another session of its key, or another key. When a ticket splits into PRs, it moves from a whole-ticket claim to a claim per piece;
  - writes the token, as its very next step, to `.work-claims/<claim id>.json` at the new worktree's root: mode 600, with the lease and server, in a directory of mode 700 with its own `.gitignore` of `*`. The token is never written anywhere else, and `git stash -a`, `git clean -x`/`-X` and `git worktree remove --force` are never run over it;
  - renews at each commit, push, long test run and resume, always passing the file's `lease_seconds`, since a renewal without it shortens the lease to four hours. It reads `.work-claims/` after a resume or compaction, releasing a merged PR's claim and renewing the others. It stops on a refusal saying the claim ended, on an `.ended.json` the hook left (deleting it once the user has decided), or on `WORK_CLAIMED` at a renewal, and never claims again without asking, whatever a reply suggests;
  - renews for a week, and records it, when it opens the PR or hands over the command that opens it, so the claim holds through review;
  - renews before asking for the merge, telling the user instead if the claim was taken over. It releases after the merge or abandon, before removing the worktree, with the PR as the reason; if the merge came after its session, the next session in the worktree releases first.

  The claim domain is a connector named `open-brain` reaching `127.0.0.1:8010` alone; a canary syncs the same board and is no claim domain. It also covers a lost token, and a brain without `claim_work`: name the cause (old release, read-only key, connector down), keep using `list_claims` if it's there, else `git fetch` and check worktrees, branches and Linear, asking the user when Linear can't be read. On keys: the claiming key alone renews, sessions get an agent-kind key (`set_agent_kind`), and the operator key belongs to the person. The Rules bullet on removing a merged worktree now says to release its claims first.
- **`.gitignore`** ignores `.work-claims` at any depth, and the root `.dockerignore` keeps it out of the build context. `git worktree remove` takes ignored files with the worktree, so the token goes with it.
- **The hook** (`recipes/session-capture-hook/session-capture.mjs`, recipe 1.7.0):
  - **Config.** A brain's `claim_key` or `claim_key_file` (and `OB1_CLAIM_KEY` for the one-brain shape) is the very key the agent claims with: a claim belongs to the key's agent id, and a server takes one key per name. With `OB1_BRAIN_URL` set only `OB1_CLAIM_KEY` is read, so the file's key and tokens never go to the variable's brain. Giving both forms, an empty key, or a claim key beside a `brains` list is refused. `--check` warns about an `OB1_CLAIM_KEY` no brain reads.
  - **What it renews.** The claims in the session's worktree: the nearest directory up from the hook's `cwd`, symlinks resolved, with a `.git`. A config of one brain renews every file there, whatever its `server` says. With several brains, a file's `server` picks the brain by its `connector`, and a file without one is skipped.
  - **When.** A claim is due a quarter of its lease after the last attempt: hourly on the default lease, and on a week's. It is never renewed more often than every minute or less often than every hour. A compaction and a session's end renew whatever wasn't attempted in the last minute. A Stop turn renews only what is due. The new `--claims` hook (`--print-hook claude-code --claims`: async `PostToolUse` on every tool and `UserPromptSubmit`) renews what is due and captures and copies nothing; a mistyped capture secret mode doesn't stop it, and on a session hook's own event the flag still captures. Each claim is stamped before its call, so a run that starts after the stamp finds it not due (hooks fired in the same instant can both renew it, harmlessly). The call runs in a detached child told the claims by id.
  - **It never claims or releases.** A branch for a ticket and a scratch branch look alike, and a session can end with its PR open.
  - **Outcomes.** A released claim (by its holder, an operator, or a takeover after a lapse) has its file rewritten as `<id>.ended.json`: the work, the code and the brain's words, without the token. It is written to a fresh file and renamed into place. Anything else keeps the file and is retried when next due:
    - the brain or its registry away;
    - a token the brain does not match;
    - a claim key that is not the holder's;
    - a claim this brain does not have;
    - `WORK_CLAIMED`: lapsed while another claim covers the work, which 115 renews once that claim ends.

    An ended claim whose file can't be rewritten keeps a stamp. The fresh file is created exclusively, so a symlink planted at its temporary name is refused.
  - **What it won't read.** A file not named `<claim id>.json`, one whose id its name does not match, a symlinked token file, a symlinked `.work-claims`, and a file or directory it can't read (named `unreadable`).
  - **Secrets.** Log lines name the work and claim id, code first, and never the token; a token-shaped run in a brain's words, a ticket or a file name is masked. A token file or directory others can read is set to 600 or 700 through a handle opened without following links, and the line names which. The capture's secret scan also catches the markdown-escaped `wc\_…`.
  - **By hand.** `--renew-claims [--cwd <dir>] [--claim <id>]` renews now and prints what happened, exiting 1 when a claim was kept or skipped. `--check` says whether the claim key can call `renew_claim`.

**Why.**
- **Claims only help if used.** Claims (SMD-3597, SMD-3598) help only if agents make them and read them. The repo's one convention was a Linear status, which an agent on another machine, or a client without a hook, cannot see (SMD-3596).
- **Renewal is what keeps a claim.** A claim nobody renews lapses in four hours, and a session working past that would lose its work to the next agent. Claude Code fires no event while it waits on its user, but it fires one at every tool call and every prompt, so a throttled renewal on those keeps a working session's claim.
- **Waiting outlasts four hours.** A session waits overnight on its user, and a PR waits days for review, so the rule claims for a day and holds an open PR's claim for a week. A lapsed claim is then free: its holder went a day without renewing, or a week with its PR open. Review pass 1 had instead read a lapsed, unreleased claim with a live branch or PR as paused work. Pass 2's walkthrough showed a merged PR's claim would read that way to every later agent, since a merged PR always exists, and the longer leases replaced it. Migration 115 renews a lapsed claim nothing covers.

- **Scratch stack.** On a scratch stack of the first commit (`ob1-3602`, its own `/mcp` and write key), the rule's steps ran as a Codex agent would follow them:

  - the hook's log named no token.

It also showed that `MCP_ACCESS_KEYS` refuses the name twice, so preflight fails: the first commit's advice to mint one would have kept the REST core down.

**Not taken.**
- **The hook doesn't record the token itself** (a `PostToolUse` on `claim_work` writing the file). One rule for every agent keeps a Codex or Cursor session, following AGENTS.md alone, in the same shape as Claude.
- **No release at session end.** The ticket's choice: a session ends with its PR open as often as merged.
- **Codex gets no `--claims` hook.** It has no async hook. Its agent renews by the rule, and its session hook renews at SessionEnd, or on Stop turns if that hook is pasted.
- **A token split across two lines**, or spelled `wc\\_` or `wc%5F`, is not scanned for. No agent writes it so, and transcripts are JSON-decoded before the scan.
- **A lock against two hooks renewing in the same instant.** The extra renewal is harmless; the README says so instead.
- **Rate-limiting the config-error line** the claims hook writes per tool call. A broken config breaks capture loudly too.
- **Keeping tokens under the git directory** (`$(git rev-parse --git-dir)`) would be out of git's reach entirely. But a sandboxed agent (Codex's workspace-write) may not write there, and the directory's own `.gitignore` gives the same protection on any branch.
