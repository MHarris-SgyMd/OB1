## FORK

The authorization server step: the refusal's 30 s sleep in the background (SMD-3200)

**What changed** (`.github/workflows/fork-checks.yml`, "The authorization server starts, refuses a bad setting, and keeps its state across a restart").
- **Built and created first:** `auth up --no-start --build --no-deps auth` builds the image and creates the volume first. The refusal's `run` and the server's `up` then race to build or create neither; the auth-data volume didn't exist before the step. The container it makes beside them the server's `up` recreates, and the one-off never touches it.
- **The refusal in the background:** started as before, with one setting blanked, the origin given a path and the profiles without auth. Its output goes to a file while the rest of the step runs.
- **Waited for at the end:** the step waits for the refusal just before the server's stop, by which time its 30 s are long past, and asserts it as before: exit 2, naming all three settings.
  - A one-off `run` takes no alias on the networks, so it never answers for the server.
  - Compose's `up`, `restart`, `logs` and plain `ps` pass it over. `exec` would not: it sorts by container number, the one-off has none and reads 0, so it comes before the server's 1. Every `auth exec` in the step names the server's container with `--index 1` (compose v2.38.2's source).
  - The wait is bounded: a refusal still alive a minute after the rest of the step fails it.
  - A failure before the wait removes the refusal's container by name (`ob1-auth-refusal`), so the teardown meets no one-off holding the volume.
- **One container:** after the wait, compose lists exactly one auth container even with `-a`, which counts one-offs.

**Why.** The step took a median of 70 s over 36 runs. The refusal's 30 s sleep before its exit (deploy/auth/server.ts, so a crash loop doesn't spin) is independent of the rest. A one-off `run` container joins the project's networks without the service's alias (compose's `--use-aliases` is off), so it never answers for `auth` while it sleeps.

**Held.** The refusal's assertions are the step's, as before: exit 2 and the three settings named. The new check holds that compose sees the server's container alone after it.

**Measured.** actionlint 1.7.7 and its shellcheck pass, and so does the consistency checker. The step's run on a stack, and the ticket's mutant (a server that starts on the bad origin), are the review pass's.
