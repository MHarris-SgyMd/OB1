## Changelog

The session hook (1.11.8) finds a bare 64-hex key on its own line followed by a line break, such as `Your key is:⏎<64 hex>⏎⏎Use it well.` or a CRLF line end, which its `sha256sum` exemption read as a digest: a blank line, a CRLF, or a newline and a tab passed for the two spaces before a file name (SMD-4546). The key went to the brain in the outcome and to the model in the excerpt. The brain's sensitivity table (`db/sensitivity.ts`) reads it the same way. **Upgrading:** replace the script and its `lib/` together; no config changes.

## Record

The sha256sum exemption's gap is spaces or tabs, not a blank line (SMD-4546)

**What changed** (`recipes/session-capture-hook/lib/secrets.mjs` and `db/sensitivity.ts`, the same literal; 1.11.8).
- **The 64-hex rule's `sha256sum` exemption** reads its gap as `[ \t]{2}`, two spaces or tabs, where `\s{2}` took any two whitespace characters: a blank line, a CRLF line end, a newline then a tab, a line separator pair.
- **What it keeps:** every digest the suite holds clean is still exempt: `sha256sum` output (an actionlint download's line, `a.tgz: OK` lines), `SHA256=`, `--sha256`, `sha256:`, `SHA-256 =`. So is a `sha256sum` line followed by a blank line, and one with two tabs for its gap, as on main.
- **1.11.8**, in `lib/hook.mjs` and `metadata.json`; the README's Testing list names the cases.

**Why.** SMD-3656's review pass 3 found a key on its own line, followed by a blank line, read as `sha256sum` output. Since 1.11.4 the model's excerpt scans each message on its own, which closed the case where the joiner's blank line did it; a blank line inside one message still did. The outcome is blanked as written, with its lines, so the same shape in the assistant's last message reached the brain. A prompt was already safe: the summary flattens a prompt onto one line, so its key is no longer at a line's start.

**Held.**
- **The suite** passes under Bun: 1,096 assertions, one new.
  - **Bare keys:** three shapes (after a label line before a blank line, at the text's start before one, and before a CRLF line end) are found in a prompt, blanked in the outcome with the gate passing the blanked text, and withhold the model's excerpt.
  - **Digests:** a `sha256sum` line before a blank line, and one with two tabs for its gap, are still exempt.
- **Three mutants each fail the suite:** the gap read as any whitespace again, the gap spaces only, and the gap a single space.
- **A differential against main** (ba3b1fd9), through the episode path, over 1,728 texts in a prompt and in the outcome, each holding one 64-hex run (two runs a blank line apart are under Not taken): 64 hex after twelve kinds of prefix, with eighteen kinds of gap and eight kinds of text after it. No finding main makes under refuse is lost, nothing main does not send is sent, no episode main's gate passes under redact is refused, and no excerpt main withholds is sent. What the branch newly blanks is, every time, an outcome whose 64 hex is followed by a gap holding a line break: a blank line, a CRLF, a newline then a tab, `\r\r`, or a line separator pair (review pass 1 found the last four; the first count had only the blank line). A prompt is flattened onto one line, so nothing there changes.
- **The brain's copy:** the table equals the hook's; the near-miss samples `db/test-live.ts` holds standard keep their tiers.
- `tsc --checkJs --noUnusedLocals` and `scripts/check-consistency.ts` pass.

**Not taken.**
- **A digest on its own line before a blank line** is now read as a key, as any bare 64-hex run is: `The sha256 is:⏎<hex>⏎⏎Done.` is blanked, and refused under refuse, where main exempted it through the same gap. Without a file name after it, a digest's line is a key's line.
- **Two such lines a blank line apart** grow into one multi-line block, as any key material across lines does, and the episode is refused even under redact: `Digests:⏎⏎<hex>⏎⏎<hex>⏎⏎Both match.`, which main sent (review pass 1). Nothing tells such a line from a key's.
- **Windows `certutil -hashfile` output** (`…:⏎<hex>⏎CertUtil: …`, CRLF line ends) is read as a key, where main read the CRLF as the gap (review pass 1).
- **`sha256sum`'s binary-mode line** (`<hex> *file`, one space and a star) is read as before: a key, as on main.
