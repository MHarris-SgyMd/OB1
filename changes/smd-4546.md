## Changelog

The session hook (1.11.8) finds a bare 64-hex key on its own line followed by a line break, such as `Your key is:⏎<64 hex>⏎⏎Use it well.` or a CRLF line end, which its `sha256sum` exemption read as a digest: a blank line, a CRLF, a newline and a tab, or a form feed passed for the two spaces before a file name (SMD-4546). A gap on its line, a non-breaking space's included, is a digest's as before. The key went to the brain in the outcome and to the model in the excerpt. The brain's sensitivity table (`db/sensitivity.ts`) reads it the same way. **Upgrading:** replace the script and its `lib/` together; no config changes.

## Record

The sha256sum exemption's gap is whitespace on its line, not a line break (SMD-4546)

**What changed** (`recipes/session-capture-hook/lib/secrets.mjs` and `db/sensitivity.ts`, the same literal; 1.11.8).
- **The 64-hex rule's `sha256sum` exemption** reads its gap as `[^\S\r\n\u2028\u2029\v\f]{2}`, two whitespace characters on the line, where `\s{2}` took any two, line breaks among them: a blank line, a CRLF line end, a newline then a tab, a line separator pair, a form feed or vertical tab pair. The ticket proposed `[ \t]{2}`; review pass 3 found that refused a non-breaking or other Unicode space gap too, a digest on main and in the brain, which folds those spaces.
- **What it keeps:** every digest the suite holds clean is still exempt: `sha256sum` output (an actionlint download's line, `a.tgz: OK` lines), `SHA256=`, `--sha256`, `sha256:`, `SHA-256 =`. So is a `sha256sum` line followed by a blank line, one indented, one `0x`-led, and one with two tabs, two non-breaking spaces or any other two spaces on its line for its gap, as on main.
- **1.11.8**, in `lib/hook.mjs` and `metadata.json`; the README's Testing list names the cases.

**Why.** SMD-3656's review pass 3 found a key on its own line, followed by a blank line, read as `sha256sum` output. Since 1.11.4 the model's excerpt scans each message on its own, which closed the case where the joiner's blank line did it; a blank line inside one message still did. The outcome is blanked as written, with its lines, so the same shape in the assistant's last message reached the brain. A prompt was already safe: the summary flattens a prompt onto one line, so its key is no longer at a line's start.

**Held.**
- **The suite** passes under Bun: 1,096 assertions, one new.
  - **Bare keys:** seven shapes (after a label line before a blank line, at the text's start before one, before a CRLF line end, `\r\r`, a line separator pair, a newline then a tab, a form feed pair) are found in a prompt, blanked in the outcome with the gate passing the blanked text, and withhold the model's excerpt. So are a key's lines whose gap is not exactly two on its line (review pass 4): three spaces before a line break, one space then text, three spaces then a name, two at the text's end, and `sha256sum`'s binary mode, `<hex> *file`, as on main.
  - **Digests:** a `sha256sum` line before a blank line, with two tabs, two non-breaking spaces or two ideographic spaces for its gap, indented, and `0x`-led, are still exempt.
- **Fifteen mutants each fail the suite:** the gap read as any whitespace again; the ticket's `[ \t]{2}`, and spaces, tabs and non-breaking spaces only; a CR, a line separator, a paragraph separator, a vertical tab, or a vertical tab or form feed allowed in the gap; a one-character gap, one or two, and two or more; any character after the gap, and the text's end as one; and the exemption's lookbehind without its `0x` or its indent. Two mutants of the lookbehind pass the suite, as main's rule would: its indent read as any whitespace, and a line started by a lone CR. Neither changes a realistic line.
- **A differential against main** (ba3b1fd9), through the episode path, over 2,400 texts in a prompt and in the outcome, each holding one 64-hex run (two runs a blank line apart are under Not taken): 64 hex after twelve kinds of prefix, with twenty-five kinds of gap and eight kinds of text after it. No finding main makes under refuse is lost, nothing main does not send is sent, no episode main's gate passes under redact is refused, and no excerpt main withholds is sent. What the branch newly blanks is, every time, an outcome whose 64 hex is followed by a gap holding a line break: a blank line, a CRLF, a newline then a tab, `\r\r`, a line separator pair, or a form feed or vertical tab pair (review pass 1 found the middle four; the first count had only the blank line). A trailing space or tab before the line break is newly withheld from the model's excerpt only: the outcome path drops it before the scan, so main blanked that outcome already (review pass 4). A gap of non-breaking, ideographic, thin or BOM spaces reads as on main. A prompt is flattened onto one line, so nothing there changes.
- **The brain's copy:** the table equals the hook's; the near-miss samples `db/test-live.ts` holds standard keep their tiers. The hook and the brain read every gap alike, as main did, but for a gap holding a BOM, which the brain drops, or a character the brain's NFKC fold turns into a space and a mark (`´`, `¨`); main's two read those apart as well (review pass 4).

**Not taken.**
- **A key followed by two spaces and text on its line** reads as a digest, as on main: `Your key is:⏎<hex>  Use it well.`, `<hex>  # prod key`, or two non-breaking spaces from a rich-text paste. The exemption cannot tell a file name from other text after the gap (review pass 4).
- **A digest on its own line before a blank line** is now read as a key, as any bare 64-hex run is: `The sha256 is:⏎<hex>⏎⏎Done.` is blanked, and refused under refuse, where main exempted it through the same gap. Without a file name after it, a digest's line is a key's line.
- **Two such lines a blank line apart** grow into one multi-line block, as any key material across lines does, and the episode is refused even under redact: `Digests:⏎⏎<hex>⏎⏎<hex>⏎⏎Both match.`, which main sent (review pass 1). Nothing tells such a line from a key's.
- **Windows `certutil -hashfile` output** (`…:⏎<hex>⏎CertUtil: …`, CRLF line ends) is read as a key, where main read the CRLF as the gap (review pass 1).
- **The agent runner's gate** (`scripts/agent-runner/gate.ts`) scans a commit's added lines, its messages and the worker's report with the hook's scanner. A report or message holding a bare digest line before a blank line (`SHA256 digest:⏎⏎<hex>⏎⏎Verified.`) now fails the gate, and the run ends as a work failure with nothing published, its branch and record kept (review pass 2). It fails closed, as the rule intends. The PR body's model sections (`publish.ts`) are withheld for the same shape; the gate has passed by then.
- **The brain's backfill.** `db/backfill-metadata.ts --apply` raises a thought's stored tier and never lowers it, so a run now marks restricted, for good, an old thought holding such a line (`Digest:⏎<hex>⏎Done.`, CRLF). The weekly digest and the lint sweep hold such rows back at read time already, through the same table (review pass 2).
- **`sha256sum`'s binary-mode line** (`<hex> *file`, one space and a star) is read as before: a key, as on main.
