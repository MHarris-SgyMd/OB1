## Changelog

The session hook (1.11.4) scans the model summary's input whole before cutting it to its last 12,000 characters (SMD-3656). Before, a cut through a key's prefix hid the key from the scan, and the rest of it went to the model. Only the opt-in `summary: "model"` is affected, through an endpoint the egress gate lets by. As before, a secret anywhere in the assistant messages keeps them from the model, and the derived summary is sent; the log now says why. The summary's own scan now judges a run its 200- or 120-character clip cuts as the whole prompt's scan judged it. Before, such a run could be blanked in the listed prompt while the header named a ticket in it, and under refuse it refused the episode (SMD-4502). **Upgrading:** replace the script and its `lib/` together, as for 1.11.1; no config changes.

## Record

The session hook scans before it clips: the model's input, and the runs the summary's clips cut (SMD-3656, SMD-4502)

**What changed** (`recipes/session-capture-hook/`, 1.11.4).
- **The model's input (SMD-3656).** `assistantExcerpt` joins the episode's assistant messages and scans them whole. A hit anywhere withholds them: it returns `{ withheld }`, naming the rule and the offset, and never the match. Clean messages are cut to their last 12,000 characters and returned as `{ text }`. `prepare` leaves a withheld excerpt off the payload and logs `model summary withheld for <chain>: …`, and `modelSummary` sends the derived summary, as for any payload without an excerpt. Main's rule is kept: any hit kept the messages from the model, read then on the cut excerpt. `modelSummary`'s own scan stays as the net under this one.
- **A run a clip cuts (SMD-4502).** `clipCuts` finds, in a rendered summary, the run that the title's 120-character clip and each listed prompt's 200-character clip cut, only where the clip falls between two of its characters. The rendered text's redaction (`redactEpisode`'s second pass) and the gate's scan (`scanSummary`) leave those runs to the whole prompt's verdict. `scanForSecrets` and `redactSecrets` take a `skip` of `[at, end)` spans: a hit wholly inside one is passed over, and the rule's next match outside it is still found. The rest of each line is read as before.
- **1.11.4**, in `lib/hook.mjs` and `metadata.json`. The README's model section, its redaction paragraph and its Testing list say so.

**Why.**
- **SMD-3656:** SMD-3602's review pass 4 (its secrets adversary) cut a work-claim token at `w|c_` and at `wc|_`. The `wc_` rule needs `wc`, the 64-hex rule refuses a run after `_` or `-`, and the entropy rule skips hex. So the cut excerpt scanned clean, and its POST to the model carried the token's body. Any prefixed key cut the same way went alike. SMD-2127's third review pass had fixed this straddle for the summary's own clips. The excerpt never got it.
- **SMD-4502:** SMD-4292's review pass 2 (secrets adversary) gave a key-like run with a long lowercase tail. The whole prompt's scan cleared it. Cut at 200, the entropy rule blanked it in the line, while the header, read from the whole prompt since 1.10.2, named its ticket-shaped part. The Google key's trailing `\b` matches at a clip's `…` the same way.

**Held.**
- **The suite** passes under Bun: 1,086 assertions, five new ones among them.
  - **The excerpt cut at `w|c_`, at `wc|_` and inside `sk-ant-`:** each is withheld, the secret found in the whole messages.
  - **Withholding:** each of these withholds the excerpt, while clean messages are sent as they are:
    - a key block, and a one-line secret;
    - each of pass 1's blanking residues, found by the scan whole.

    `prepare` writes a payload without the excerpt for a key block, and for a token the cut would have cut at `wc|_`, and logs why.
  - **The adversary's entropy run cut at 200, and the Google key cut at 39 by the prompt's clip and by the title's:** the header names the ticket, the line and the title show it unblanked, and the gate refuses nothing under redact or refuse.
  - **SMD-2127's rule still holds:** a key the clip cuts is blanked whole in the line by the whole prompt's scan.
- **The backstop's cases pass unchanged.** A URL's blanked password exposes a digest, which the rendered text's pass blanks and the gate refuses. They first failed under a broader rule, which treated the last run before any `…` as cut. That is why a run counts as cut only where the clip falls inside it.
- **Seven mutants each fail the suite:**
  - `clipCuts` finding nothing; the redaction skipping nothing; the gate skipping nothing;
  - every last run counted as cut, which fails the three backstop assertions;
  - the excerpt scanned after its cut, not before;
  - a hit withholding nothing; `prepare` attaching a withheld excerpt.
