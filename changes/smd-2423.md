## Changelog

Preflight no longer calls a running re-embed or consolidation pass "stopped before it finished": a key a worker holds a live lease under reads as running, with no remedy that would start a second worker, and one whose only leases expired names a worker that died holding them, which the next pass reclaims (SMD-2423).

## FORK

Preflight's pass rows read the leases and the heartbeats (SMD-2423)

**What changed.** `server-portable/preflight.ts`'s `re-embed pass` and `consolidate pass` rows count each key's claimed rows by lease: live, and expired by the rule `release_stale_leases` and `worker_status` use (`ttl_expires_at < now()`), so the three cannot disagree on what a stale lease is.
- **Running:** a live lease. The row is ok, unless failed rows sit beside it: a worker never retries those (a follower's `--retry-failed` runs once, before it follows), so then it warns, naming them and the `--retry-failed` that puts them back. Otherwise it reads — "a pass under this key is running: N in flight (leases live until HH:MM UTC), M pending" — with no "Finish it", the remedy that would have started a second worker. For consolidation, a fresh, not-ended `heartbeat:<key>` (SMD-2261's PR 2) reads running too: "a follower is running this key (stamped N ago): M pending between its polls", since a follower between polls holds no lease. That is SMD-2261's item 7.
- **A worker died holding claims:** claimed rows whose leases expired, none live. The row warns, names the expired claims, and says the next pass reclaims them (a row on its third expiry is marked failed) or the `release_stale_leases` tool returns them now, before today's remedy.
- **Stopped:** pending or failed rows and no claimed one. Today's sentence and remedy, unchanged.
- **The re-embed row's other branches** (an abandoned switch, the configured key, another width) keep their wording, but a live lease reads running there too, and the configured key — every `--switch-model`'s pass, the common case — names a worker that died beside its own words.

**Why.** Measured 2026-10-01 on the stable brain: with `consolidate.ts --workers 1` running and its lease live, preflight printed "a consolidation pass under this key stopped before it finished" as a warning, and its remedy started a second worker on the same job. Both rows counted claims by status alone and never read `ttl_expires_at`, so a running pass, a pass with no worker and a pass whose worker died read the same.
