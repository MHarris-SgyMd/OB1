## FORK

The claim, priority and item operations share one helper — one rule for a caller whose agent id the registry did not give (SMD-3780)

**What changed.** `server-portable/core/caller.ts` holds four pieces that `core/claims.ts`, `core/priority.ts` and `core/items.ts` each had a copy of:
- `unattributedAs(code, principal, facts?)`: the registry's failure to give the caller's agent id (`agentUnresolved`) as CLAIM_UNATTRIBUTED, PRIORITY_UNATTRIBUTED or ITEM_UNATTRIBUTED, retryable while the registry is unreachable and final when it is set up wrong or refuses. It answers null when the caller has its id, or no registry was asked (a plugin hook's principal). The caller says what follows then: claims.ts and items.ts say `registry_unknown` where they did, and items.ts keeps ITEM_UNOWNABLE for a hook. A claim's refusal names its id and whether a force was asked; the types require those for CLAIM_UNATTRIBUTED and refuse them for the other two.
- `asked(Refused, run)`: a store call, the store's own refused-argument class (ClaimRefused, PriorityRefused, ItemRefused) returned and any other throw left a fault.
- `writerScope` and `readOnly`, the scope 116 and 117 read off the envelope and their READ_ONLY_KEY, from priority.ts and items.ts.

Each file keeps its own docblock on why its refusal is said where it is, on a one-line `unattributed`.

**Why.** The copies drifted once. SMD-3665 PR 2's review pass 1 exempted a plugin's call in items.ts and not in priority.ts, and pass 2 moved the check after the database call in both. SMD-3705 would have added a fourth copy in claim_work.

**Held.** No behaviour change: test-server (1455), test-auth (201), test-e2e-sql (700) and test-rest-sql pass with no row changed. Five mutants in `caller.ts`, run against test-rest-sql, are all killed: away said final, misconfigured said refused, a principal no registry was asked for treated as a failure, a refused argument rethrown, and the capture scope dropped.
- The away, misconfigured and rethrown mutants each fail a row in all three families: [10] claims, [11] priority, [13] items.
- [13] gains one assertion, in its plugin row: the hook key's own item with the registry set up wrong answers ITEM_UNATTRIBUTED, final. Before it, no items row read the final branch, and the misconfigured mutant failed claims and priority alone.

**Not taken.** The ticket's optional wrapper for the five item writers' shared opening and closing. Each writer picks its own value off 117's answer, and the wrapper's type parameters would read worse than the four lines it saves.
