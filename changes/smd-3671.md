## Changelog

An operator lists and decides the priority findings sleep proposes, over REST and MCP (SMD-3671 PR 2, no migration; the findings are migration 142's): `list_priority_findings` (`GET /v1/priority-findings`, any key that reads; pending by default, oldest first, by status and kind, `total` counted in full, paged by a cursor) and `review_priority_finding` (`POST /v1/priority-findings/{id}/review`, an operator key's alone: accept with a level or clear, or reject). `brain_info` counts the pending by kind, and preflight's `priority findings` row says them. Every read that shows a priority — `search`, `fetch`, `search_thoughts`, `search_thoughts_keyword`, `list_thoughts`, the agenda and `plan_context`'s board — marks an item sleep holds a pending stale finding on, and a level's source (an open item it is read from, a ticket it inherits from) alike: `unreviewed` (the finding's id, its newest statement's time, age in days, level and maker, its window; false for none, null when not checked), the items past the read's reach named in `unreviewedUnchecked`, and over MCP `…, medium (2) by "codex", stated 75 days ago, unreviewed` after its priority. The compact MCP values carry a mark only where one is present, and a failed read once, as `unreviewedRead: false`; `search` and `fetch` say what the mark means in `unreviewedNote`; `plan_context` gains `notes`, saying marks not read for its time. A mark, never a weight: it moves no order or rank (SMD-3671 PR 3, no migration).
