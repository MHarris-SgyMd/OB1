## Changelog

`db/test-live.ts`'s append-only check, [2], no longer edits the tracked `db/migrations/002_match_thoughts.sql`. It copies the migrations to a temporary directory, edits the copy, and points both migrator runs at it: in-process through a new `migrationsDir` option of `migrate.ts`'s `run()`, and spawned through `OB1_TEST_MIGRATIONS_DIR`. A run killed mid-check leaves the checkout unchanged, a second run from the same tree no longer sees drift, and the suite runs from a read-only checkout (SMD-3639).

## FORK

test-live [2] edits a copy of the migrations, never the tracked tree (SMD-3639)

**What changed.**
- **`db/migrate.ts`:**
  - `MigrateOptions.migrationsDir`: where the core migrations are read from, the tree's `db/migrations` unless a suite names another. It sits beside `pluginsDir`, which suites already use the same way.
  - The command line reads it from `OB1_TEST_MIGRATIONS_DIR`, blank meaning unset. That's for a spawned run; there is no flag, so it isn't an operator's option. The name follows `OB1_TEST_COUNTS`, the suites' other environment setting.
  - A run given a directory says so on stderr before it reads one: `Migrations read from <dir>, not db/migrations: a suite's directory (OB1_TEST_MIGRATIONS_DIR).` A stray setting can't pass unnoticed. `--grant` runs return before the load and say nothing.
  - The plugin loader's own `migrationsDir` local is untouched; the core's is `coreDir`.
- **`db/test-live.ts` [2]:**
  - It copies `db/migrations` with `cpSync` into a `mkdtemp` directory and appends `-- edited after being applied` to the copy's 002.
  - The spawned run gets this process's environment plus `OB1_TEST_MIGRATIONS_DIR`, and the in-process run gets `{ migrationsDir: copy }`. The copy is removed in a `finally`.
  - One assertion is new: the spawned run names the copy as the directory it read. The last assertion now reads "the tree's own migrations, never written, show no drift", where it said the restore cleared it.
- **Docs that said [2] edits the tracked file:**

  - `db/ci-parity.sh`'s comment on when the other lanes start now says why they start after rest no longer holds, and leaves moving them to SMD-3688.
