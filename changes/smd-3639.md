## Changelog

`db/test-live.ts`'s append-only check, [2], no longer edits the tracked `db/migrations/002_match_thoughts.sql`. It copies the migrations to a temporary directory, edits the copy, and points both migrator runs at it: in-process through a new `migrationsDir` option of `migrate.ts`'s `run()`, and spawned through `OB1_TEST_MIGRATIONS_DIR`. A run killed mid-check leaves the checkout unchanged, a second run from the same tree no longer sees drift, and the rest shard, [2] among it, runs from a read-only checkout. `deploy/orchestration/provision.ts --self-check` likewise writes its scratch env files in a temporary directory, not the checkout (SMD-3639).

## FORK

test-live [2] edits a copy of the migrations, never the tracked tree (SMD-3639)

**What changed.**
- **`db/migrate.ts`:**
  - `MigrateOptions.migrationsDir`: where the core migrations are read from, the tree's `db/migrations` unless a suite names another. It sits beside `pluginsDir`, which suites already use the same way.
  - The command line passes `OB1_TEST_MIGRATIONS_DIR` to it. `run()` takes a blank or whitespace value as unset, and resolves a relative one against the working directory. That's for a spawned run; there is no flag, so it isn't an operator's option. The name follows `OB1_TEST_COUNTS`, the suites' other environment setting.
  - A run given a directory says so on stderr, once, before it reads one: `Migrations read from <dir>, not db/migrations: a suite's directory (OB1_TEST_MIGRATIONS_DIR).` A stray setting can't pass unnoticed. `--grant` runs return before the load and say nothing; that is by reading the code, as no row runs `--grant` with the setting.
  - A directory it can't list (missing, a file, under a file, or unreadable) is refused by name with the error's code and exit 2, as an empty one already was (`No .sql files in …`), not thrown with a stack.
  - The plugin loader's own `migrationsDir` local is untouched; the core's is `coreDir`.
- **`db/test-live.ts` [2]:**
  - It copies `db/migrations` with `cpSync` into a `mkdtemp` directory and appends `-- edited after being applied` to the copy's 002.
  - The spawned run gets this process's environment plus `OB1_TEST_MIGRATIONS_DIR`, and the in-process run gets `{ migrationsDir: copy }`. The copy is removed in a `finally`.
  - Three assertions are new:
    - the spawned run names the copy it read, once;
    - a blank `OB1_TEST_MIGRATIONS_DIR` reads the tree's migrations and names no directory;
    - a directory that is gone is refused by name, exit 2, with no stack.
  - The last run's assertion now also wants no directory named, so a note printed on every run fails it, and the tracked 002 as [2] found it. It reads "the tree's own migrations, 002 as [2] found it, show no drift", where it said the restore cleared it. That the tree is never written mid-[2] is the read-only run's to show, not a row's.
  - The copy's 002 is made writable before the append: `cpSync` keeps a read-only checkout's file modes.
- **Docs that said [2] edits the tracked file:**
