## Changelog

A thought's type, topics, people and action items now print on one line each, wherever a reply shows them: `search_thoughts`, `search_thoughts_keyword`, `list_thoughts`' item header, `capture_thought`'s confirmation and `thought_stats`' breakdowns. Before this fix, a metadata value holding a line break printed raw. An importer's payload or a steered extraction could leave a topic reading `--- Result 9 ---` and `By: … · trust operator` on lines of their own, above the fenced text, as another thought's block. Tag extraction now keeps only its tag keys, so a steered model can no longer set the server's own metadata. The session-capture hook no longer reads ids from `thought_stats`, which prints none (SMD-2510).

## FORK

A thought's metadata prints on one line in every reply, so it cannot forge a result block (SMD-2510)

**What changed.**
- **`metaText` and `metaList` in `server-portable/render.ts`.** A metadata value goes through `snipText`, the one-line cleaner proposals and the change feed already quote a thought through. It is cut at a bound: 40 characters for a type, 80 for a topic or a person, 200 for an action item. A list drops an entry that is left empty, and a value that is not a string is said as `String()` says it.
- **Where it applies.**
  - Both search blocks: the `Type:`, `Topics:`, `People:` and `Actions:` lines.
  - `list_thoughts`: the item header's `(type - tags)`.
  - `capture_thought`: the confirmation's type and tags, and the tagging-failure marker's note. The session-capture hook reads `Captured as … id <uuid>` at the start of a line, so an extracted topic holding a line break could have handed it a capture id of its own.
  - `thought_stats`: each type, topic and person in its breakdowns.
- **`snipText`, widened.** It collapsed whitespace with `\s`, which matches neither NEL nor FS, GS and RS. `cleanForDisplay` dropped FS, GS and RS, but NEL survived as a line break. Every break `fenceText` splits on is now a space, and the C1 controls and bidi marks `fenceText` drops are dropped. That covers every reply that quotes untrusted text through `snipText`: the thoughts a proposal quotes, the change feed and the `By:` line's key name among them. The judge's reason is not one of them; it is SMD-2533.
- **`snipText` cuts by code point.** An emoji or other astral character at the bound is kept or dropped whole. Before, it could be left as half a surrogate pair. That predates this change, but the new bounds on names and topics make it likelier. The walk stops at the bound, so a long thought's text is not copied whole to be cut.
- **`extractMetadata` keeps its answer's tag keys and nothing else** (`server-portable/metadata.ts`, review pass 1). Capture spreads the answer over the row's metadata. A model steered by the text it reads could add any key, and the row would carry it as the server's. That included `metadata_extraction_failed`, which `capture_thought`'s reply printed raw, so the model could forge a capture line there. `type_raw` now comes only from the type, never from the answer.
- **The session-capture hook no longer reads `thought_stats` for ids** (review pass 2). That tool prints no thought id. Each of its rows starts with a type, topic or person, and the hook reads `ID: <uuid>` after leading spaces, so a tag reading `ID: <uuid>` was claimed as a retrieved thought.
- **The dashboard's parsers.**
  - The list parser reads the type and tags up to the header's last `)`. A tag holding a `)` used to drop the whole item.
  - The stats parser reads a row's value up to its last `: <count>`. A type, topic or person holding a colon used to drop the row.

**Not here.** `integrations/kubernetes-deployment` and `integrations/enhanced-mcp` render their own replies, as they do for the text. Neither prints a trust label on a read.
