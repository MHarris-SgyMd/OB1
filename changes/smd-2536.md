## Changelog

The consolidation pass now stores the judge's reason as one line: every line break is a space, the C1 controls and bidi marks are dropped, and the cut at 400 characters never splits a character in half (an emoji is kept or dropped whole, though a sequence of several, a flag or a family, can still be cut between its parts). Before this fix, a NEL, a C1 control or a bidi mark in the model's reason was stored and written to `consolidate.ts --dump`'s JSON lines. `evals/eval-consolidate.ts`'s grading sheet prints the reason and both thoughts' text on one line each by the same rule (SMD-2536).

## FORK

The judge's reason is stored on one line, by the rule the replies print it with (SMD-2536)

**What changed.**
- **The rule moved.** `LINE_BREAK`, `UNSHOWN`, a `oneLine(text)` cleaner and a `cutByCodePoint(text, max)` helper now live in `server-portable/consolidate.ts`, beside `cleanForDisplay`. They were `render.ts`' private regexes and `snipText`'s body. `render.ts` imports `cleanForDisplay`'s module, so `parseJudgement` could not use `snipText` without an import cycle. `snipText` is now `oneLine`, then `cutByCodePoint`, then an ellipsis when it cut. `fenceText` uses the moved regexes. Neither changes behaviour; test-server's [16h]–[16j] pass unchanged.
- **`parseJudgement`.** The reason was `cleanForDisplay`, then a `\s+` collapse, then `.slice(0, 400)`. `\s` does not match NEL, and `cleanForDisplay` deletes VT, FF, FS, GS and RS rather than spacing them, so the words on either side ran together. The slice could leave half a surrogate pair. It is now `cutByCodePoint(oneLine(reason), REASON_MAX)`, still with no ellipsis. `REASON_MAX` (400) is exported, and `render.ts`' `PROPOSAL_TEXT_MAX` is now defined as it.
- **`--dump`** writes `parseJudgement`'s reason, so it gets the one-line text with no change of its own. Its readers, `eval-consolidate.ts` and test-live, split on `\n` alone and were never broken by a NEL inside a JSON string. test-live does not read the reason.
- **`evals/eval-consolidate.ts`' grading sheet.** It reads the queue from the database, so a reason any caller of `record_supersession_proposal` recorded can hold anything. The `judge:` line and both thoughts' text lines go through `oneLine` and `cutByCodePoint`, at 400 and 700. Before, the reason printed raw and the texts went through `\s+` and `.slice(0, 700)` alone. A `--replay` run can read a dump written before this fix, so the line breaks and controls in its reasons are cleaned as the file is read. That covers the verdicts it replays and the proposals it records from them again. What the old rule already lost stays lost: words it glued, and half a surrogate pair its UTF-16 cut left. The terminal's per-pair line cuts the reason at 90 by code point, where it used `.slice`.

**Not here.** Rows already stored are not rewritten. Both printers, `list_supersession_proposals` and `consolidate.ts --list`, clean the reason on the way out (SMD-2533).
