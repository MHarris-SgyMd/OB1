## FORK

The third layer measured — what survives capture into a later deliverable, and which planted errors are caught, by which mechanism; a keyless gate in the data-layer job (SMD-1713)

**What changed.** `evals/eval-write-path.ts` runs `evals/write-path-corpus.ts` — twenty fictional sessions, thirty-six captures by an operator's key and an agent's over twelve fictional subjects, with 27 salient facts, three stale decisions each reversed later, three numbers the operator later mistyped and three unsourced inferences by the agent planted among them, plus the cases where a mechanism should hurt — through the real `server-portable/index.ts` booted in-process against a throwaway Postgres, the provider scripted as `test-chunking.ts` scripts it: one `Bun.serve` answering `/embeddings` (an axis per subject named, a hashed tie-break) and the three chat prompts the write path sends (the capture's metadata, the extractor's entities, the consolidation judge's verdict by one blunt rule: digit runs that differ under one subject conflict). Four arms, one process each — `default`, `-supersedes` (the newer decision never names the older), `-judge` (no extraction, no consolidation pass), `-actor` (the keys never classified) — then a fixed reader searches each deliverable's subjects (k=5), leaves out a hit marked superseded, leaves out an agent's word where the operator's stands, writes a hit in a pending conflict proposal as *contested*, and captures each deliverable with `derived_from` naming the ids it used. `evals/write-path.ts` holds every rule pure: the stub's answers, the parsers, the reader, the scorer, the pairing, the comparison. `baselines.json` gains `write_path`; `.github/workflows/fork-checks.yml` gains `--self-check` in the portable-server job and `--gate` in the data-layer job.

**Why.** Every number under `evals/` was retrieval, or since SMD-1719 use; nothing measured layer three, and change 90 pointed here for it. The full form the ticket names — a deliverable carrying citations — needs SMD-1715's `capture_deliverable`, not built, and 042's `record_citation`, which no tool calls (SMD-1733); so the reduced form the ticket's Notes allow ran, with a deliverable as what SMD-1719 already scores as a citation: a capture whose `derived_from` names its sources. The corpus is code, not a fixture: check 9 reads every committed fixture as an allowlist with no exception, and an exception would have had to tell fiction from an export by file name; the rule stays whole and the corpus is source, typechecked with the evals.

**Measured** (the committed corpus, 2026-09-23; deterministic, three gate runs identical): default arm survival 17/27 (63.0%), catch 9/9, coverage 26/26; `-supersedes` catch 6/9; `-judge` survival 23/27, catch 6/9, nothing contested; `-actor` survival 19/27, catch 7/9; the blind reader survival 25/27, catch 0/9. Paired against default: supersedes helped 3 / hurt 0 (p 0.250), judge 3 / 6 (0.508), actor 2 / 2 (1.000). Each stale decision rests on the supersedes pointer, each slip on the judge, two inferences on the actor mark and the numbered one on either. Ten facts did not survive: two to the k cut, six contested by the judge (the slips' true twins, the two true facts with different numbers, the fact whose agent inference carried a number), two the agent's true facts dropped where the operator spoke. The judge's hurt is the read's design, not the rule's alone: a pending proposal contests both sides until a reviewer decides (029's never-apply-unreviewed), so the read returns a question where SMD-1735's belief-state read would return the reviewed value plain. Labels are what the catch costs: the blind reader states 25 facts and catches nothing.

**Held.** `--self-check` (portable-server job, no database): the corpus's shape rules probed with broken copies; the stub's three answers against the real prompt builders — both prompts name their own delimiters in their rules before the wrapped text, and the first draft read the rule as the text and extracted nothing; the parsers on rendered blocks, a forged `ID:` line in content included; the reader's five rules; the scorer's partitions (plain / contested / dropped / unseen; an unseen error beside the rate); the pairing and McNemar on hand-known values; the comparator, with the ticket's mutant — one planted fact dropped from its deliverable fails the survival floor — and the record's presence. `--gate` (data-layer job, keyless): the default arm at or above the recorded floor, exact ratios; the blind reader below the catch floor. Live mutants, restored by copy: the reader dropping the first hit of every subject fails survival; a deliverable captured with no `derived_from` fails coverage; the reader ignoring the superseded mark fails catch.

**Not taken.** A `capture_deliverable` tool or a `cites`/`stance` argument (1715, 1733). A fixture under `evals/fixtures/` with a counted check-9 exception. A separate CI job (the write path needs the server and the data-layer job's database; a step in a required job gates a merge with no new ruleset name, SMD-1856). A tolerance below the floor (the run is deterministic; a change that moves a rate re-records, as `bench.ts --rebaseline` asks). A real judge's catch rate — `eval-consolidate.ts`'s question; this arm measures the plumbing from verdict to deliverable and the stub rule's false positives, and says so. Sessions dated by hand, one calendar day apart, after capture — 029's candidate rule wants a day between a pair and a run takes a second; the text is not touched, so 050's mark stays.

**Follow-ups.** Proposal issues 06 (proactive recall) and 09 (portable export) are judged by this number and may be filed now. SMD-1737 reads this rate as its third column.
