# 222. The entity name gate as a good-shape allowlist: a high-precision identifier shape (migration 065) overrides the model's type for any type, not just a person or place (SMD-2300)

**Why.** The 2026-09-27 decider-vs-live-graph run measured the cost of SMD-1935's narrow scope. The generative extractor typed `SMD-1549` and `worker_status` a `topic`, not a `person` or `place`, so the gate never reached them; and a Jev-class typed-decision model is a coin-flip on those shapes (it rejected eight `SMD-####` and accepted ten of the same shape). An identifier is a shape a regex recognises with certainty, so it should not depend on either model getting the type right.

**What changed.**

- **`entity_type_gate(p_name, p_type)` (065, redefined on 056's body).** A `scope` per shape now says which of the model's types it overrides: `any` (a three-or-more-digit ticket id `→ project`; a package, path or host:port `→ tool`), `notPerson` (snake_case or a glob `→ tool`), `personPlace` (the looser ticket id `→ project`, a URL `→ tool`), and `place` (a host, domain or file `→ tool`). The `any` and `notPerson` shapes are read before the person/place door, so they correct a `topic`, `project` or `organization` too; the `personPlace` and `place` shapes stay where SMD-1935 put them.
- **Precision, not coverage.** The ticket shape requires three or more digits, so `SMD-1549` is a project but `GPT-4`, `Llama-3` and `COVID-19` are left as the model typed them. The dotted shape stays `place`-only, so `Nature.com` and `openrouter.ai` an org or place are not forced to `tool`. A person's handle (`john.smith`, `@john_doe`) is still never retyped.
- **`apply_entity_type_gate()` re-run (065).** The pass reads `entity_type_gate` by name, so re-running it applies the widened rule to the rows written before it — the SMD-1935 person/place corrections stand; the new work is the identifiers the extractor stored as `topic`/`project`. Idempotent; the first run's counts are kept in `ob1_config` under `identifier_allowlist_065`.
- **The twin.** `server-portable/entity-gate.ts` carries the same shapes and scopes; test-schema [52] holds the two to one answer over a probe list and to the same patterns spelled in both.
