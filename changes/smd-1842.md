## Changelog

The supersession grading report from `evals/eval-consolidate.ts` prints each proposal thought's date as `2026-09-09`, not `Wed Sep 09`. An infinity-dated thought prints `infinity` and an undated one `undated`, not `Infinity` and `null`. The report and `db/consolidate.ts --list` now use one helper, `isoDay` in `server-portable/store.ts` (SMD-1842).

## FORK

The grading report's proposal dates go through one day renderer, `isoDay`: `2026-09-09`, not `Wed Sep 09` (SMD-1842)

**Why.** `evals/eval-consolidate.ts` reads proposals with raw Bun SQL (`SELECT * FROM list_supersession_proposals(...)`), not through `normaliseProposal`. So `older_created_at` and `newer_created_at` are the driver's own values, and `String(d).slice(0, 10)` printed the head of each one's `toString()`. On pg16 through Bun: a `Date` printed `Wed Sep 09`, `infinity` printed `Infinity` (Bun returns the number) and NULL printed `null`. That is every row of the report. It does not throw and does not make up the epoch, so SMD-1328's and SMD-1803's fixes did not reach it.

**What changed.**

- **`isoDay(v)` in `server-portable/store.ts`**, next to `isoTimestampOrNull`, and built on it. It returns null for SQL NULL and `YYYY-MM-DD` for a finite timestamp. It returns a sentinel (`infinity`) or a value with no ISO form unchanged, since those have no `T` to cut at. A missing column still throws.
- **`db/consolidate.ts`'s `day`** (SMD-1803) is now `isoDay(d) ?? "undated"`, with the same output as before. The rule lives in one place and is no longer copied into each tool.
- **`evals/eval-consolidate.ts`** prints both dates in the report heading with `isoDay(v) ?? "undated"`. The rest of the file has no other `String(<timestamp>)` render. The judge-prompt dates go through `server-portable/consolidate.ts`'s `dateOf`, which already handles a `Date`, null and infinity.

**Held.** `server-portable/test-store-postgrest.ts` [3] runs `isoDay` over a `Date` (the driver's form and the ticket's case), a timestamptz string, `±Infinity` and `"infinity"`, null, and a missing column. Changing the body back to `String(v).slice(0, 10)` fails four of those five asserts, with the Date assert printing `Wed Sep 09`. `db/test-live.ts`'s SMD-1803 block still checks `--list` on an infinity-dated and an undated proposal thought (`older [infinity]`, `newer [undated]`).

**Measured after.** Through Bun on pg16, a probe runs the eval's own read over proposals between a thought dated 2026-09-09 and one dated infinity or NULL. It printed `(Wed Sep 09) → (Infinity)` and `(Wed Sep 09) → (null)` before the fix and `(2026-09-09) → (infinity)` and `(2026-09-09) → (undated)` after.

**Upstream status.** Fork-only: upstream has no consolidation pass.
