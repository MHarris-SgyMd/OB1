## Changelog

The supersession grading report from `evals/eval-consolidate.ts` prints each proposal thought's date as `2026-09-09`, not `Wed Sep 09`. An infinity-dated thought prints `infinity` and an undated one `undated`, not `Infinity` and `null`. The report, `db/consolidate.ts --list` and the judge prompt now print a day through one helper, `isoDay` in `server-portable/store.ts`, which returns a BC or extended-year date whole where the CLI had cut it to a wrong day or a stub (SMD-1842).

## FORK

The grading report's proposal dates go through one day renderer, `isoDay`: `2026-09-09`, not `Wed Sep 09` (SMD-1842)

**Why.** `evals/eval-consolidate.ts` reads proposals with raw Bun SQL (`SELECT * FROM list_supersession_proposals(...)`), not through `normaliseProposal`. So `older_created_at` and `newer_created_at` are the driver's own values, and `String(d).slice(0, 10)` printed the head of each one's `toString()`. On pg16 through Bun: a `Date` printed `Wed Sep 09`, `infinity` printed `Infinity` (Bun returns the number) and NULL printed `null`. That is every row of the report. It does not throw and does not make up the epoch, so SMD-1328's and SMD-1803's fixes did not reach it.

**What changed.**

- **`isoDay(v)` in `server-portable/store.ts`**, next to `isoTimestampOrNull`, and built on it. It returns null for SQL NULL. It cuts only `toISOString`'s own form (`…THH:MM:SS.sssZ`) to its UTC day, an extended year's `+275760-09-13` included. Anything else comes out unchanged: `infinity`, JS's `Invalid Date`, and PostgREST's `0044-03-15T00:00:00+00:00 BC`. A missing column still throws.
- **Three renderers print through it.** `db/consolidate.ts`'s `day` (SMD-1803) is `isoDay(d) ?? "undated"`. The judge prompt's `dateOf` (`server-portable/consolidate.ts`) is `isoDay(d) ?? "an unknown date"`. The eval's report heading uses `isoDay(v) ?? "undated"`. The rest of the eval has no other `String(<timestamp>)` render. For an ordinary date, an infinity date and NULL, all three print what they printed before. The difference is the BC text and the extended year (see Review passes).
- **Not unified.** The MCP `list_supersession_proposals` tool prints through `displayDate`, the viewer's local date (SMD-1328), so the tools can differ from it by a day near midnight. The bio worker (`integrations/consolidation-workers/bio`) slices its PostgREST string itself.

**Held.** `server-portable/test-store-postgrest.ts` [3] runs `isoDay` over a `Date` (the driver's form and the ticket's case), a timestamptz string, `±Infinity` and `"infinity"`, the BC text, an extended-year `Date`, `Date(NaN)`, null, and a missing column. Changing the body back to `String(v).slice(0, 10)` fails the Date assert, which prints `Wed Sep 09`. `server-portable/test-thoughts.ts` still checks the prompt's `an unknown date` for a NULL. `db/test-live.ts`'s SMD-1803 block still checks `--list` on an infinity-dated and an undated proposal thought (`older [infinity]`, `newer [undated]`).

**Measured after.** Through Bun on pg16, a probe runs the eval's own read over proposals between a thought dated 2026-09-09 and one dated infinity or NULL. It printed `(Wed Sep 09) → (Infinity)` and `(Wed Sep 09) → (null)` before the fix and `(2026-09-09) → (infinity)` and `(2026-09-09) → (undated)` after.
