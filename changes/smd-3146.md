## Changelog

Preflight has a `thought indexes` row: it warns when an index on `thoughts` that a read is planned around is INVALID or of another shape, or missing on a brain whose ledger records its migration, naming what reads slower and the statements that mend it — or, for an INVALID one while an index operation runs on it or holds `thoughts`, the pid to wait for (SMD-3146). It covers `thoughts_vectorless_idx` (100), `thoughts_trust_rank_idx` (074), the fingerprint's unique index (003) and five others, and names an INVALID index left on `thoughts`: a cancelled `REINDEX CONCURRENTLY`'s copy to drop, anyone else's to rebuild. The `trigram index` row now also says when its index is INVALID, and waits out an index operation holding `thoughts`.

## FORK

Preflight names an index on thoughts that a read is planned around and that is missing, INVALID or of another shape (SMD-3146)

**What changed** (`server-portable/preflight.ts`, no migration).
- **A `thought indexes` row**, after `trigram index`, reads `pg_class`, `pg_index`, `pg_locks` and `pg_stat_progress_create_index` for eight indexes on `thoughts`, by the migration that builds each:

  | Index | Migration | Slower without it |
  |---|---|---|
  | `thoughts_created_at_idx` | 001 | list_thoughts' newest-first page |
  | `thoughts_metadata_idx` | 001 | list_thoughts' filters, match_thoughts' narrow-filter branch (014) |
  | `idx_thoughts_fingerprint` | 003 | every capture's lookup of its own text; gone or not ready, a record ingest or raw write can add a second row of one text (captures and edits still merge under the fingerprint lock) |
  | `idx_thoughts_derived_from` | 025 | find_derivatives |
  | `idx_thoughts_supersedes` | 025 | every search's superseded-by label, the node projection's triggers |
  | `thoughts_issue_key_idx` | 068 | ticket_status_inputs (searches whose hits name a ticket), the node projection's triggers |
  | `thoughts_trust_rank_idx` | 074 | match_thoughts' min_trust |
  | `thoughts_vectorless_idx` | 100 | the vector mender's page and brain_info's vectorless count |

- **Whatever holds one of the names is judged**, and each state gets its own remedy — statements to run in psql one at a time, `CONCURRENTLY` so writes carry on:
  - missing: its `CREATE INDEX CONCURRENTLY` (`UNIQUE` for the fingerprint's — with fingerprints held twice counted, under a 2 s timeout, and resolved first through `reembed.ts --status` and `delete_thought`, since the build fails on them); with no ledger read, and for 100, whose migration brings nothing else to check, "if migration 100 has not run here, apply it instead";
  - missing, or held by something else, while the column, table or function its migration also brings is absent (`--baseline` over an older schema): the name cleared, then the migrator's `--reapply` naming the migrations — never a CREATE naming what is not there;
  - INVALID: `REINDEX INDEX CONCURRENTLY` (or a drop and a build), and what its file does with one — the others' `IF NOT EXISTS` keep it, 100 refuses it; the fingerprint's, still ready, still refuses a second row, and the row says so;
  - an operation on it running now (its progress row, or a lock on it only a build, reindex, ALTER or drop takes, read in this database), or, for an INVALID one, a session holding `thoughts` for an index build or reindex (a progress row whose pid holds SHARE UPDATE EXCLUSIVE — a CONCURRENTLY one's — or SHARE — a plain CREATE INDEX's — on the table; the same for every role, and the only sign of a build a role without `pg_read_all_stats`, the server's `--grant` role, has): the pid to wait for, the session that pid itself waits on, then preflight again — never a REINDEX into the queue behind it (a VACUUM or ANALYZE has no progress row and is not seen); a missing or misshapen index gets its statements, which queue behind such a session and then run;
  - of another shape (`UNIQUE` counts): `DROP INDEX CONCURRENTLY`, then the build — "the reads may not take it", since some other shapes serve them;
  - another table's index, or a relation that is no index, under the name: renamed out of the way to the first free `<name>_moved`, `_moved2`, … (`ALTER TYPE` for a composite type), never dropped, then the build;
  - beside a valid index of its shape under another name, or one being built now: that one renamed into place (after waiting it out), no build; slower reads said only while it is being built — unless its migration's schema is absent, which the re-apply comes first for.
- **INVALID indexes on `thoughts` under other names:** a REINDEX's copy (`_ccnew`, `_ccold`, its base beside it) or a copy of one of the eight shapes is dropped; anything else is someone's index, rebuilt (`REINDEX`, or a drop if it is not wanted). One being reindexed or dropped now (a routine `REINDEX` of a valid index runs through one) is said as running, not warned of; one while a session holds `thoughts` for a build — the build's own index, which locks only the table, and a stale one alike — is said to be judged once that ends. The walk index's and the trigram index's are their own rows'; the trigram row reads its index's validity now (on `thoughts` only, by name, needing no USAGE), and waits out an index operation holding `thoughts`, in a boundary of its own.
- **Looked up by name in `thoughts`' schema**, as 100 looks for its own; the shape is the definition after the name and table, `public.` read as bare.
- **Not looked for:** a name nothing holds whose migration the ledger does not record (a plain migrate run applies it, a hole too), and, with no ledger read, one whose migration's schema is not here. The detail says which.
- **A warning, never a refusal to start:** the reads answer right, only slower. Over PostgREST it is the catalog-only skip.

**Why.** An index the ledger records can be gone: `--baseline` over a hand-built schema records files it never ran, a `CONCURRENTLY` build or drop that does not finish leaves an INVALID index the planner ignores (and an `IF NOT EXISTS` re-run keeps), an operator drops or renames one. Each read above is then slower and nothing says so; for the vectorless index, 2–4 ms at 100,000 thoughts against 0.005–0.04 ms with it, every tick on each server (SMD-3056). Preflight read only the HNSW indexes' validity (thoughts' and thought_chunks').

**Not taken.**
- **`ob1_fp_backfill_idx` (023) missing:** read only by 023's backfill, while unfingerprinted rows remain, and no row names it missing; INVALID, it is named and rebuilt like anyone's index.
- **Indexes on other tables** (`thought_audit_thought_id_idx`, `thought_chunks_thought_id_idx`, the facets'): the ticket's reads are on `thoughts`.
- **Accepting other shapes that serve a read** (ASC for `created_at DESC`, a whole-table `supersedes` btree): one shape per name, as 100 keeps; the warning says such an index may serve the reads, and the drop and build is harmless.
- **074 given 100's refusal in a new migration:** the row says an INVALID `thoughts_trust_rank_idx` is kept by a re-run, with the statement that mends it.
- **A build queued on `thoughts`' table lock** (behind another CONCURRENTLY operation) holds nothing on the index yet, so it reads as not running; the row it gets is the state the index is in.
- **An INVALID HNSW staging index beside a healthy shipped one** (a hand pre-build for 039, interrupted) is named by no row: the walk index row's to judge, not this one's.
- **A build holding `thoughts` read in any lock mode** (review pass 4's M2): a session holding only ACCESS SHARE (a read) while it builds elsewhere is no index operation a REINDEX on `thoughts` would queue behind; SHARE UPDATE EXCLUSIVE and SHARE are a CONCURRENTLY and a plain build's.
- **Locks and builds of another database** (a template clone shares oids) are filtered out but untested here: a clone needs the source database to itself. A plain REINDEX or DROP INDEX holding ACCESS EXCLUSIVE on an index blocks preflight on earlier rows first, on main too.
- **Other rows' remedies on an older schema** (`search signatures`' apply-074, `schema version`'s plain run) disagree with `--reapply`; they predate this change.
