## Changelog

Preflight has a `thought indexes` row: it warns when an index on `thoughts` that a read is planned around is missing, INVALID or of another shape on a brain whose ledger records its migration, naming what reads slower and the statements that mend it — or, when a build, reindex or drop of it is running, the pid to wait for (SMD-3146). It covers `thoughts_vectorless_idx` (100), `thoughts_trust_rank_idx` (074) and five others, and names any INVALID index left on `thoughts`, such as a cancelled `REINDEX CONCURRENTLY`'s copy.

## FORK

Preflight names an index on thoughts that a read is planned around and that is missing, INVALID or of another shape (SMD-3146)

**What changed** (`server-portable/preflight.ts`, no migration).
- **A `thought indexes` row**, after `trigram index`, reads `pg_class`, `pg_index`, `pg_locks` and `pg_stat_progress_create_index` for seven indexes on `thoughts`, by the migration that builds each:

  | Index | Migration | Slower without it |
  |---|---|---|
  | `thoughts_created_at_idx` | 001 | list_thoughts' newest-first page |
  | `thoughts_metadata_idx` | 001 | list_thoughts' filters, match_thoughts' narrow-filter branch (014) |
  | `idx_thoughts_derived_from` | 025 | find_derivatives |
  | `idx_thoughts_supersedes` | 025 | every search's superseded-by label, the node projection's triggers |
  | `thoughts_issue_key_idx` | 068 | ticket_status_inputs (searches whose hits name a ticket), the node projection's triggers |
  | `thoughts_trust_rank_idx` | 074 | match_thoughts' min_trust |
  | `thoughts_vectorless_idx` | 100 | the vector mender's page and brain_info's vectorless count |

- **Each state is named with its own remedy**, statements to run in psql one at a time, `CONCURRENTLY` so writes carry on:
  - missing: its `CREATE INDEX CONCURRENTLY`; with no ledger to read, "or apply migration NNN";
  - missing with the column, table or function its migration also brings (`--baseline` over an older schema): the migrator's `--reapply`, never a CREATE naming what is not there;
  - INVALID: `REINDEX INDEX CONCURRENTLY` (or a drop and a build), and what its file does with one — 074's and the others' `IF NOT EXISTS` keep it, 100 refuses it;
  - a build, reindex or drop of it running now (its progress row, or a lock on it only those take): the pid to wait for, never a REINDEX that would queue behind it;
  - of another shape (`UNIQUE` counts): `DROP INDEX CONCURRENTLY`, then the build — said as "the reads may not take it", since some other shapes serve them;
  - another table's index, or a relation that is no index, under the name: renamed out of the way to `<name>_moved` (`ALTER TYPE` for a composite type), never dropped, then the build;
  - missing, INVALID or of another shape beside a valid index of its shape under another name: that one renamed into place, no build, and no slower reads claimed;
  - an INVALID index on `thoughts` under any other name — what a build, reindex or drop that did not finish leaves (a cancelled REINDEX's `_ccnew`), served by no read and, while ready, still written: `DROP INDEX CONCURRENTLY`, or the pid to wait for while it is being built.
- **Looked up by name in `thoughts`' schema**, as 100 looks for its own; the shape is the definition after the name and table, `public.` read as bare.
- **Not looked for:** an index whose migration the ledger does not record (a plain migrate run applies it, a hole too), and, with no ledger to read, one whose migration's schema is not here. The ok detail says which.
- **A warning, never a refusal to start:** the reads answer right, only slower. Over PostgREST it is the catalog-only skip.

**Why.** An index the ledger records can be gone: `--baseline` over a hand-built schema records files it never ran, a `CONCURRENTLY` build or drop that does not finish leaves an INVALID index the planner ignores (and an `IF NOT EXISTS` re-run keeps), an operator drops or renames one. Each read above is then slower and nothing says so; for the vectorless index, 2–4 ms at 100,000 thoughts against 0.005–0.04 ms with it, every tick on each server (SMD-3056). Preflight read only the HNSW pair's validity.

**Held.** test-preflight [12], a real Postgres, every migration applied and recorded:

- all seven missing, all seven INVALID (`indisvalid` flipped), all seven of another shape: each named, each remedy run as printed, statement by statement, the row ok again;

**Not taken.**
- **`idx_thoughts_fingerprint` (003):** a capture's `ON CONFLICT` arbiter. Without it every capture fails outright rather than reading slower, a refusal's case, not this warning's.
- **`ob1_fp_backfill_idx` (023):** read only by 023's backfill, while unfingerprinted rows remain; the `fingerprint backfill` row covers that path.
- **Indexes on other tables** (`thought_audit_thought_id_idx`, `thought_chunks_thought_id_idx`, the facets'): the ticket's reads are on `thoughts`.
- **Accepting other shapes that serve a read** (ASC for `created_at DESC`, a whole-table `supersedes` btree): one shape per name, as 100 keeps; the warning says such an index may serve the reads, and the drop and build is harmless.
- **074 given 100's refusal in a new migration:** the row says an INVALID `thoughts_trust_rank_idx` is kept by a re-run, with the statement that mends it.
- **A build queued on `thoughts`' table lock** (behind another CONCURRENTLY operation) holds nothing on the index yet, so it reads as not running; the row it gets is the state the index is in.

**Upstream status.** Fork-only: upstream has no preflight.
