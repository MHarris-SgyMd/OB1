## Changelog

Preflight has a `thought indexes` row: it warns when an index on `thoughts` that a read is planned around is missing, INVALID or of another shape on a brain whose ledger records its migration, naming what then scans every thought and the statements that mend it (SMD-3146). It covers `thoughts_vectorless_idx` (100), `thoughts_trust_rank_idx` (074) and five others.

## FORK

Preflight names an index on thoughts that a read is planned around and that is missing, INVALID or of another shape (SMD-3146)

**What changed** (`server-portable/preflight.ts`, no migration).
- **A `thought indexes` row**, after `trigram index`, reads `pg_class` and `pg_index` for seven indexes on `thoughts`, by the migration that builds each:

  | Index | Migration | Scans every thought without it |
  |---|---|---|
  | `thoughts_created_at_idx` | 001 | list_thoughts' newest-first page |
  | `thoughts_metadata_idx` | 001 | list_thoughts' filters, match_thoughts' narrow-filter branch (014) |
  | `idx_thoughts_derived_from` | 025 | find_derivatives |
  | `idx_thoughts_supersedes` | 025 | every search's superseded-by label |
  | `thoughts_issue_key_idx` | 068 | the node projection's triggers, on each write of a ticket's row |
  | `thoughts_trust_rank_idx` | 074 | match_thoughts' min_trust |
  | `thoughts_vectorless_idx` | 100 | the vector mender's page and brain_info's vectorless count |

- **Each state is named with its own remedy**, the statements to run in psql one at a time, `CONCURRENTLY` so writes carry on:
  - missing: its `CREATE INDEX CONCURRENTLY`; with no ledger to read, "or apply migration NNN";
  - one of its shape under another name: `ALTER INDEX … RENAME TO` it, no second build;
  - INVALID: `REINDEX INDEX CONCURRENTLY` once `pg_stat_progress_create_index` lists no build of it (or a drop and a build), and what its file does with one — 074's and the others' `IF NOT EXISTS` keep it, 100 refuses it;
  - of another shape: `DROP INDEX CONCURRENTLY`, then the build;
  - another table's index or a relation that is no index under the name: renamed out of the way, never dropped, then the build.
- **Looked up by name in `thoughts`' schema**, as 100 looks for its own; the shape is the definition from `USING` on, `public.` read as bare.
- **A migration the ledger does not record yet is not looked for**, and the ok detail says which. With no ledger, or one this role cannot read, every index is.
- **A warning, never a refusal to start:** the reads answer right, only slower. Over PostgREST it is the catalog-only skip.

**Why.** An index the ledger records can be gone: `--baseline` over a hand-built schema records files it never ran, a `CONCURRENTLY` build or drop that does not finish leaves an INVALID index the planner ignores (and an `IF NOT EXISTS` re-run keeps), an operator drops or renames one. Each read above then scans every thought and nothing says so; for the vectorless index that is 2–4 ms at 100,000 thoughts against 0.005–0.04 ms with it, every tick on each server (SMD-3056). Preflight read only the HNSW pair's validity.

**Held.** test-preflight [12], a real Postgres, every migration applied and recorded:
- a healthy brain: the row ok, no remedy; read with `public` off the connection's path too (074's function then prints qualified);
- all seven missing, all seven INVALID (`indisvalid` flipped), all seven of another shape: each named with its migration and what scans, each with its remedy; then the remedy run as printed, statement by statement, and the row ok again;
- another table's index, a table, and an index of the shape under another name: named, the two renamed out of the way, the third renamed back with no build, the row ok after; the rename alone a warning that says nothing of slower reads;
- a ledger without 100: its index dropped is no warning, said "not looked for"; no ledger: looked for, the remedy naming 100 as the other way;
- [1]'s PostgREST count: twenty-seven catalog-only skips.
- Mutants, each failing [12]: the ledger gate dropped, the INVALID test, the rename twin, the on-`thoughts` test, the shape test, the `public.` strip, the no-ledger clause, "only slower" said of a rename alone, and one index left out of the table.

**Measured after.** The row's two catalog reads: 0.18 and 0.15 ms median (EXPLAIN ANALYZE, 20 runs, 571 `pg_class` rows, PG 16).

**Not taken.**
- **`idx_thoughts_fingerprint` (003):** a capture's `ON CONFLICT` arbiter. Without it every capture fails outright rather than reading slower, a refusal's case, not this warning's.
- **`ob1_fp_backfill_idx` (023):** read only by 023's backfill, while unfingerprinted rows remain; the `fingerprint backfill` row covers that path.
- **Indexes on other tables** (`thought_audit_thought_id_idx`, `thought_chunks_thought_id_idx`, the facets'): the ticket's reads are on `thoughts`.
- **074 given 100's refusal in a new migration:** the row now says an INVALID `thoughts_trust_rank_idx` is kept by a re-run, with the statement that mends it.

**Upstream status.** Fork-only: upstream has no preflight.
