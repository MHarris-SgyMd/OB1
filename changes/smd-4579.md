## Changelog

A run of `extract-entities.ts` no longer reads again a thought whose entities another model wrote outside the extraction pools, such as an eval's corpus. The rule a run applies at its first pass would have, unattended, on both dogfood brains (SMD-4579).

## Record

The every-run rule keeps to the other key's claim row (SMD-4579)

**What changed.**

- `db/extract-entities.ts`: the rule that runs at a run's first pass returns a finished row only when another extraction key's finished claim row for the thought is the later one. Its second sign, the other key's lineage row on the thought's entities, is gone.
- A switch is as it was. `--switch-key` to a key used before still returns a finished row with no lineage row of that key at the thought's fingerprint, so it returns a thought another model wrote outside the pools. The operator has then asked for the brain under that key.
- `db/test-live.ts`, section [10]: one new row, and the row for a key moved back by hand changed. `deploy/README.md` and `db/README.md` say what a run leaves.

**Why.** The lineage sign was added in SMD-2607's review pass 2 for a brain switched back before that fix, with a thought read under the other key and then edited. It is true as well of any thought another model was run over on purpose with no pool. Both dogfood brains hold such thoughts.

**Given up.** On a brain switched back before SMD-2607, a thought the other key's pool read and that was then edited (its row there pending again) is returned by no run. A switch made since returns it. Neither dogfood brain was ever switched back, and no other brain is known to be in that state.

**Not taken.** Keeping both signs with a way to mark a reading as meant to stand. It needs a new mark and a writer for it, to protect a case no brain is in.
