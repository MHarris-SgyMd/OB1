## Changelog

Fork Checks skips its eleven code jobs on a pull request whose every changed path is documentation. A new first job, `changes`, says whether the change can affect them. It fails open: if it fails, every job runs. "Fork Checks passed" lets the jobs skip only when that job succeeded and said the change was docs (SMD-2435, PR 1).

## FORK

PR 1 of 4: a docs-only pull request skips Fork Checks' code jobs (SMD-2435)

**What changed.**
- **A first job, `changes`** ("What the change can affect"):
  - **On a pull request** it checks out `.github/ci` alone, shallow and blobless. It then runs the **base branch's** copy of `.github/ci/changes.sh` (`git show HEAD^1:…`), so a PR that edits the classifier is judged by the copy already on its base, which denies `.github/`. A base with no copy, or a fetch that fails, says `code=true`.
  - **Any other event** has no checkout and says `code=true`.
  - **The classifier** reads `HEAD^1..HEAD` of the merge commit, NUL-separated with `--no-renames`. It says `code=false` only for a PR into the default branch whose every path is on its allowlist. A PR stacked on another branch is kept from a green that would survive its retargeting to main.
  - **Anything else says `code=true`:** a HEAD with no second parent (not the merge commit, or a shallow fetch), a change that's empty or unreadable, or one path off the list.
  - **The allowlist** is Markdown anywhere, and images under `docs/`, except:
    - files a gated job reads: the ADR an eval pins by its wording, four contribution READMEs the auth and writes suites assert over, and `changes/`, which the full-stack job's release rehearsal reads;
    - whole directories that reach an image, the stack or CI: `dashboard/`, `plugins/`, `server-portable/`, `deploy/`, `db/migrations/` and `.github/`.
  - **`why` loses its control characters, and `code` is `true` unless exactly `false`.** A path's own newline would otherwise be a line of its own in `GITHUB_OUTPUT`, and a crafted name could set `code`.
- **Eleven gated jobs** need `changes` and run under `${{ !cancelled() && (needs.changes.result != 'success' || needs.changes.outputs.code != 'false') }}`: portable-server, db-schema, replay-gate, db-live, data-layer, the four full-stack jobs, auth-poc and compat-shim. A `changes` job that fails or is cancelled runs them all, and so does any answer but exactly `false`.
- **repo-consistency, commit-lint and workflow-lint always run.** repo-consistency also runs the classifier's own cases, `changes.sh --self-check`.
- **"Fork Checks passed"** needs `changes` too. Its `MAY_SKIP` adds the gated jobs only when `changes` succeeded and said `code=false`, so a cancelled run's unstarted jobs fail it. Its step is unchanged.
- **Check 20** holds this shape:
  - the `changes` job present, with no `if:`, and as written: its keys, its one output from the decide step, its checkout's `if:` and inputs, and the decide step's env and `run:` verbatim (`CHANGES_RUN`). A pinned `EVENT`, a literal output, a `continue-on-error` or a `|| true` each fail;
  - repo-consistency's step running the classifier's cases;
  - each gated job (`AGGREGATE_GATED`) needing it, under exactly `GATED_IF`;
  - `MAY_SKIP` as `gatedMaySkip()`'s expression;
  - a job that needs a gated job running under `!cancelled()`, as `publish-test-counts` does.

  Its probes add a gated workflow, two accepted shapes and eighteen mutants.
- **Check 47** (new) holds the allowlist to the code. Any tracked Markdown or image file that code names is either denied by the classifier, or listed in `NAMED_NOT_READ` with exactly the files that name it and the reason none reads it for a gated job (18 today). A new namer of a listed file fails until it's added with its reason. A path token counts as naming a file when, read from the root or from the naming file's directory, it is that file. A stale entry or namer fails, and so does a reading that stops seeing the pinned ADR as named and denied. Its probes pin the token reading and which files count as code.

**Why.** Every Fork Checks run used every job, whatever changed. One run is about 18 of the Free plan's 20 concurrent jobs, and queueing is the run's p90. Docs-only pull requests were 6 of the last 100 merged; each of their runs now skips about 2,000 runner-s and ~15 slots, finishing at about repo-consistency's length. A code PR's run gains the `changes` job, about 5–8 s, on its critical path: about even in wall time per PR, about 110 runner-s a run fewer on average, which is the queueing lever (the 10-28 simulation). PRs 2–4 make it pay widely:
- PR 2: per-job ownership of fork-checks.yml;
- PR 3: a path map derived from what each job runs;
- PR 4: per-area skips.

**Departures from the ticket.**
- **`db/README.md` is on the allowlist,** where the ticket kept it off: no gated job reads it since SMD-3614 moved the suites' counts to the wiki. So the ticket's Verify line "a PR touching only `db/README.md` runs db-schema and db-live" no longer applies. Check 47 lists why.
- **Wider than the ticket's start, and narrower:**
  - Markdown anywhere rather than `docs/**` and `*.md`;
  - `changes/` denied, not allowed, since the rehearsal reads it;
  - images under `docs/` alone.
- **Check 47 is added in PR 1** rather than waiting for the path map. A hand-kept deny list goes stale the day a suite starts reading a README, which the survey found five times over.
- **The `changes` job is bash on a blobless checkout,** not `scripts/check-landing.ts`'s classification: a Bun setup would add seconds to every code PR's critical path.
- **The base's classifier decides, and only PRs into the default branch skip:** both added in review (pass 1), beyond the ticket.

**Gaps left.**
- **A PR can still skip its own code jobs by editing `fork-checks.yml`,** the aggregate or the checker, as it always could, since all of them run from the PR's tree. The ruleset asks no review. What review pass 1 closed is the subtler one-line edit to `changes.sh`.
- **`db/ci-parity.sh` doesn't run `changes.sh --self-check`.** Its rows run Bun files, and check 35 reads only those, so the bash step is CI's alone.

**Held.**
- **`changes.sh --self-check`:** 23 decisions, then 10 runs in scratch repositories shaped as a PR's merge commit, with the base moved after the branch. Each run must write one `code=` line, and the right one:
  - docs alone gives `false`;
  - code, a mix, a rename into `docs/`, a PR into another branch, a push, and a HEAD with no second parent give `true`;
  - a code file named `server-portable/x<newline>code=false` gives one line, `true`. With the control-character line removed, it gives two, the last `false can affect the code jobs`, and the gated jobs would skip;
  - a docs name holding a newline gives `false`, one line.
- **Seven mutants of the classifier** that only an out-of-tree harness caught before each now fail its self-check: no sanitising, no `-z`, no `--no-renames`, no second-parent check, `HEAD^2` diffed, no base-branch rule, and `*.md` matched first.
- **Check 20 on the real workflow, mutated in a scratch tree:** these each fail with check 20's own message:
  - a gated job's `if:` without fail-open, an unconditional `MAY_SKIP`, a gated job without `needs: changes`, and the `changes` job given an `if:`;
  - from review pass 1: a literal `'false'` output, the step writing `code=false`, `EVENT` pinned, depth 1, `|| true`, the step's `continue-on-error`, the self-check step deleted, and the PR's own classifier deciding.
- **Check 47 in the worktree** (each file backed up outside and restored): each of these fails:
  - the ADR or a telegram README taken off the deny list;
  - a `NAMED_NOT_READ` entry removed, a stale one added, or one the classifier denies;
  - a gated suite that starts naming a listed README, a namer dropped from an entry, or a non-namer added to one.
- **The checker, the scripts' typecheck, actionlint 1.7.7 with shellcheck, and shellcheck** on `changes.sh` (against a positive control) pass.
- **On GitHub:** this PR changes the workflow, and main has no classifier yet, so its own run gates nothing (`code=true`). The skip path's first run is a throwaway draft PR with a Markdown change alone, into a temporary base branch. That branch is this one, plus a commit taking out the base-branch rule, which would otherwise keep any PR not into main at `code=true`.
