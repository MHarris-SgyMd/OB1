## Changelog

Brain Checks skips its code jobs on a pull request into the default branch whose every changed path is documentation. A new first job, `changes`, says whether the change can affect them. It fails open: if it fails, every job runs and "Brain Checks passed" is red. "Brain Checks passed" lets the jobs skip only when that job succeeded and said the change was docs (SMD-2435, PR 1).

An edit of `brain-checks.yml` now runs only the code jobs whose own part of the file it changes, when the rest of the pull request is documentation; an edit outside the jobs, or of the `changes` job, still runs every job (SMD-2435, PR 2).

A change record, the checker, a CI script or another workflow now runs only the code jobs that read it, by a map the consistency checker holds; any other code path still runs every job (SMD-2435, PR 3a).

## FORK

Brain Checks skips what a change cannot affect, PRs 1, 2 and 3a of 4: a docs-only pull request skips the code jobs, a workflow edit runs only the jobs it edits, and a mapped path only the jobs that read it (SMD-2435)

### PR 3a: an explicit map of the paths a gated job reads

**What changed.**
- **`CHARGES` in `.github/ci/changes.sh`:** a pattern, a tab, then the gated jobs it can affect, none for a path no gated job reads.

  | Pattern | Jobs |
  |---|---|
  | `changes/*` | deploy-stack (its release rehearsal reads every record) and db-schema (it runs `ingest-records.ts`, which can) |
  | `scripts/check-consistency.ts` | data-layer (`integrations/test-writes.ts` asserts over its text) |
  | `.github/ci/typecheck.sh` | portable-server |
  | `.github/ci/full-stack-up.sh`, `auth-settings.sh` | the four full-stack jobs |
  | `.github/ci/held-cases.sh` | deploy-stack |
  | `.github/ci/test-counts-page.ts` | compat-shim (its codemod walks `.github/` by content) |
  | `.github/ci/changes.sh`, the other three workflows, `db/ci-parity.sh` | none |

- **The classifier:**
  - A pull request whose every path off the docs allowlist is a `CHARGES` path, or a workflow edit read by job (PR 2), gets `skip=`: every gated job no path charged and no edit reached. Any other path still runs every job.
  - **Beside a workflow edit, the checker or `changes.sh` runs every job** (`HOLDS_THE_CUT`). The checker's check 51 holds the cut. The decision applies the base's cut to the head's workflow, which check 51 doesn't validate when a PR changes both.
  - `--charges` prints the table. The gates and `MAY_SKIP` are unchanged, since they already read `skip`.
- **Check 53** (new) holds each `CHARGES` entry to what names its path:
  - **The workflow:** a gated job whose block names the path in a code line (blanked as shell) must be one it charges.
  - **The files:** every tracked file whose code names it must be in `JOB_MAP_READERS`, as a reader that opens it or one that only names it, with why. A new namer fails, and so does a stale one. It reads code, Svelte and HTML, shell and YAML, SQL, JSON, and a shebang script with no extension, with comments blanked. A name is an anchored path token:
    - for a directory: its name and a slash; after `./` or `../` anywhere (`$HERE/../changes`, `join(dir, "../changes")`), a variable (`$ROOT/`, `${ROOT}/`) or `${{ … }}/`, also the name alone; its name as a quoted string; or `cd` or `working-directory:` to it. Never a URL's `/changes`;
    - for a file: its name, or its stem as an import's specifier.
  - **Readers that open the path, or only name it** (review pass 6): each `JOB_MAP_READERS` entry is `reads` (it opens the path) or `names` (the path is a word, a key or a message in it). A gated job whose block runs a `reads` reader must be charged, with no exceptions (one hop, review pass 1). This is what holds `changes/*` to deploy-stack (`release-artifacts.ts`) and db-schema (`ingest-records.ts`), and the checker to data-layer (`test-writes.ts`).
  - **compat-shim's content walks:** a mapped code file must charge compat-shim if `scripts/migrate-to-sql-shim.ts` reads it by content (its `CODE`, outside `SKIP_DIRS`, both read from its source; review pass 1). It must also charge compat-shim if it holds `MIGRATED OFF SUPABASE` outside `scripts/`, which compat-shim's parse step builds; check 53 holds that step to the marker and its `grep -v scripts/` (review pass 4).
  - **The map's home and the checker** aren't listed as namers. Both read every path (the checker reads the records and runs `typecheck.sh` and `changes.sh`), so a gated job running either must be charged by every row (review pass 7); only repo-consistency and the changes job run them, and neither is gated.
  - **Paths that must exist** (review pass 3): a row naming no tracked file fails, since after a rename the new path would run every job unseen. `HOLDS_THE_CUT` must name the checker and `changes.sh`, so a rename of either can't leave a workflow edit beside it read by job.
  - 26 entries over 22 files today, 9 that open the path and 17 that only name it.

**Why.** A read-only study of main's last 80 merged PRs (960 gated job-runs) estimated today's rule at 12 job-runs skipped, this map at about 128 across 12 PRs (somewhat fewer now that a record runs db-schema too), and the derived map of PRs 3b and 3c at about 215–328. 71 of the 80 touched `changes/`, which ran every job.

**Gaps left.**
- **The reading is lexical,** as check 47's is. A path built from pieces isn't seen; PR 3b's derived closure replaces the hand-kept map.
- **A path no gated job reads (charged none) skips every gated job** when nothing else charges one.
- **One hop deep.** A reader reached through an import or a script isn't held. test-live (db-live) and `db/tier.ts` (deploy-stack-brains) import `ingest-records.ts`, a reader that opens the records, and test-live and test-cli (replay-gate) spawn it; none reaches its fork source (each passes `--source items` or `markdown`, or is refused first), and nothing but this record says so. A `.sh` or a `package.json` script running a reader is unseen too. PR 3b's closure follows these.
- **A reader's run is matched by its file name,** so a same-named file's run charges too: a false charge, which only runs more.
- **Whether a reader opens the path or only names it is said by hand,** in its entry's kind and reason.

**Held.**
- **`changes.sh --self-check`** under bash 3.2 and under ubuntu 24.04's bash 5.2, mawk and GNU sed.
  - Each map path charges its jobs, together their union, and a path off the map runs every job.
  - A record beside a workflow edit gives both. The checker or the classifier beside a workflow edit runs every job.
  - In merge-commit repositories with a gated `data-layer` job: a record skips every gated job, the checker every one but data-layer, and a record beside a code file none.
- **The real workflow, in scratch merge commits:**
  - a record and a doc run deploy-stack and db-schema; the checker data-layer alone; `test-counts-page.ts` compat-shim alone; `full-stack-up.sh` and a record the four full-stack jobs and db-schema;
  - `release.yml` and `ci-parity.sh` run no gated job; a record and db-live's timeout run db-live, deploy-stack and db-schema;
  - the checker beside a workflow edit, and a record beside `server-portable` code, run every job.
- **Main's last 300 merged pull requests, replayed** (review pass 8; fork-checks.yml read as brain-checks.yml before the rename): 20 would skip a job today's rule runs, most a record beside CI-only files, and none of those jobs failed on its pull request but once, a SIGPIPE in deploy-stack-auth's own step that passed on the next push.
- **Mutants, each killed:**
  - the classifier: the map ignored, charged jobs not subtracted, `HOLDS_THE_CUT` dropped, a path off the map charged nothing;
  - check 53: its workflow rule, its namer rule, its stale rule and a directory's quoted name unread;
  - on the real tree: data-layer gaining a step running `full-stack-up.sh`, and `db/test-replay.ts` reading `changes/`, each named by check 53;
  - on the real tree: `changes/*` or the checker charged to no job, records no longer charging db-schema, deploy-stack-auth running `release-artifacts.ts`, `test-counts-page.ts` charged to no job, the checker taken off `HOLDS_THE_CUT`, a row for a renamed file, compat-shim's parse step losing its `scripts/` filter, and gated suites reading `` `${ROOT}/changes` `` or `../changes`, each named by check 53;
  - the reads/names rule: every reader read as `names`, every reader read as `reads`, and the homes dropped from the one-hop rule, each failing its probe;
  - each token form and file kind unread (`./`, the line-end flag, `working-directory:`, `import()` and `require()`, Dockerfile, Python, SQL), and the codemod's walk read as skipping `.github` or matching no code.

### PR 2: brain-checks.yml read by job

The full record: `95b4d04f:changes/smd-2435.md`.

**What changed.**
- **The cut:** `cut_blocks` cuts the base's and head's workflow at their job keys, each heading comment with the job below it. `skip=` names the gated jobs whose block is byte for byte the same. An edit outside the jobs, or of a `RUN_ALL_JOBS` job (`changes`, repo-consistency), or a file the cut refuses runs every job.
- **The gates:** each gated job runs under `gatedIf(<its name>)`, and `MAY_SKIP` takes `skip` only when `changes` succeeded.
- **The checks:**
  - **Check 20** holds the gates, both outputs and `MAY_SKIP`, and a gated job needing `changes` alone.
  - **Check 51** holds the cut to Bun.YAML: each block parses alone to its job, and `.top` to the rest, so no alias, merge key or flow style crosses a block. It also holds `RUN_ALL_JOBS`.

**Why.** Of main's last 60 merged PRs that touched the workflow, none changed docs alone beside it, so PR 2 alone skipped nothing. It is the structure this map fills in (the maintainer's call, 11-04).

**Gaps.** The cut is stricter than YAML. That GitHub's parser reads the file as Bun's does is assumed. Nothing yet holds that no gated job reads the workflow itself (PR 3b).

**Review passes:** two, finding the measured worth, a new gated job untested, repo-consistency's edit not running every job, a heading said wrongly and a `:#` key. CI's older shellcheck named SC2317 where the image named SC2329.

### PR 1: a docs-only pull request skips the code jobs

The full record: `95b4d04f:changes/smd-2435.md`.

**What changed.**
- **The `changes` job:** it runs the base branch's `changes.sh` on a shallow, blobless `.github/ci` checkout. It reads `HEAD^1..HEAD` with `--raw -z --no-renames`, so a symlink or submodule is code. It says `code=false` only for a PR into the default branch whose every path is on the allowlist: Markdown anywhere and images under `docs/`, minus the files a gated job reads and `dashboard/`, `plugins/`, `server-portable/`, `deploy/`, `db/migrations/`, `.github/`.
- **The gates:** each gated job runs unless `changes` succeeded and said `code=false`. "Brain Checks passed" allows the skips only then. repo-consistency, commit-lint and workflow-lint always run.
- **The checks:** check 20 holds the `changes` job verbatim. Check 47 holds the allowlist: a doc that code names is denied, or listed in `NAMED_NOT_READ` with its namers.

**Why.** One run is about 18 of the Free plan's 20 concurrent jobs, and queueing is the run's p90; a docs-only run skips about 2,000 runner-s.

**Gaps.** A PR can still skip its own jobs by editing the workflow, the aggregate or the checker. Check 47 is lexical.

**Review passes:** three. They found a stacked PR's green surviving its retargeting, the PR's own classifier deciding, the `changes` job unheld, symlinks read as docs, a pathless record ending the read, the old mode untested, and an unquoted summary.

**Verify.**
- [ ] A docs-only pull request skips the gated jobs, "Brain Checks passed" green, its run about repo-consistency's length.
- [ ] The same PR with a one-line `server-portable/` change runs every job.
- [ ] A `changes` job that exits 1 on a docs-only PR runs every gated job, and "Brain Checks passed" fails.
