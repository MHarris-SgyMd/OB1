## Changelog

Fork Checks skips its code jobs on a pull request into the default branch whose every changed path is documentation. A new first job, `changes`, says whether the change can affect them. It fails open: if it fails, every job runs and "Fork Checks passed" is red. "Fork Checks passed" lets the jobs skip only when that job succeeded and said the change was docs (SMD-2435, PR 1).

An edit of `fork-checks.yml` now runs only the code jobs whose own part of the file it changes, when the rest of the pull request is documentation; an edit outside the jobs, or of the `changes` job, still runs every job (SMD-2435, PR 2).

## FORK

Fork Checks skips what a change cannot affect, PRs 1 and 2 of 4: a docs-only pull request skips the code jobs, and a workflow edit runs only the jobs it edits (SMD-2435)

### PR 2: fork-checks.yml read by job

**What changed.**
- **The classifier** (`.github/ci/changes.sh`, still the base branch's copy) reads a pull request whose one path off the allowlist is an edit of `fork-checks.yml`, a regular file before and after, by job:
  - `cut_blocks` cuts the base's and the head's text at their job keys, `  <id>:` alone on a line under `jobs:` alone on its. Comment and blank lines go with the key below them, so a job's heading is its own; what lies outside the jobs is one region, `.top`. It refuses a line opening with a tab, a second `jobs:`, a column-0 line that is no key, a line two spaces in that is no job key alone (a comment after a key needs its space, as YAML reads one), a job's line before any job, and a job named twice.
  - A region that differs byte for byte is edited. An edit of `.top`, or of a job in `RUN_ALL_JOBS` (the `changes` job, and repo-consistency, whose checker runs check 51: review pass 2), a file the cut refuses or git cannot show, runs every job, as before.
  - Otherwise it writes `skip=`, the gated jobs whose block is unchanged: a block holding its own gate, `' <id> '` beside `needs.changes.outputs.skip`. Its characters are job names' alone.
  - A workflow added, deleted, made executable or a symlink, any other `.github/` file, and a code path beside the edit stay code for every job.
- **The workflow:** the `changes` job's second output, `skip`. Each gated job runs under `gatedIf(<its name>)`: unless `changes` succeeded and said `code=false`, or named it in `skip` (`contains(format(' {0} ', …skip), ' <id> ')`, so a name inside another doesn't match). `MAY_SKIP` is `format('commit-lint publish-test-counts {0}', …)`, the gated jobs on `code=false`, the ones `skip` names otherwise, and only when `changes` succeeded.
- **Check 20** holds that form per job, the two outputs, the new `MAY_SKIP`, and a gated job needing `changes` alone: it skips on its own block, so it may read nothing another job's block decides. Its probe gains seven mutants, and the step's run three cases.
- **Check 51** (new) holds the cut to Bun's reading of the file, since a textual cut is sound only while a job's block alone says what the job is. It runs `changes.sh --blocks` on the workflow and requires that:
  - the cut's jobs are Bun.YAML's, in order;
  - each block, parsed alone, equals the job as parsed in the whole file;
  - `.top`, parsed alone, equals the rest.

  So no alias, merge key or flow style reaches across a block, and a file the cut refuses fails here as well as running every job. Its probe has seventeen cases. It also holds `RUN_ALL_JOBS` to the `changes` job and the job running the checker (six cases), so a rename can't drop either.
- **FORK.md:** a skipped job may now be "a job the PR can't affect", not only a docs-only PR's code job (the same length; FORK.md is 6 bytes under its cap, SMD-3768).

**Why.** `fork-checks.yml` was changed by 21 of 40 merged PRs in the 10-22 review, and any edit of it ran every job. The review put per-block ownership at about 150 runner-s per PR run for db-live alone. That counted the workflow, not what came with it. Of main's last 60 merged PRs that touched it, none changed docs alone beside it; 5 changed docs and their `changes/smd-*.md` record (code, since deploy-stack's rehearsal reads `changes/`), and 55 other code: the checker, `.github/ci`, product code. So this PR alone skips nothing yet. It is the structure PR 3's path map fills in: a record charged to deploy-stack alone, the checker to repo-consistency, a `.github/ci` script to the jobs that run it (the maintainer's call, 11-04: ship it as the foundation).

**Departures from the ticket.** The ticket asked for Bun.YAML in the `changes` job. The cut is bash, to keep Bun off every code PR's critical path (PR 1's reason), and check 51 proves it reads the file as Bun does.

**Gaps left.**
- **The cut is stricter than YAML.** A file it refuses runs every job, and check 51 fails on it, so a style change that breaks the cut is seen at once.
- **A heading comment counts against the job below it,** one above the first job against the `changes` job: such an edit runs that job, or every job.
- **Nothing holds that no gated job reads `fork-checks.yml` itself.** None does today (the checker and `db/ci-parity.sh` alone read it); PR 3's map of what each job reads is to hold it.
- **Check 51 holds the cut to Bun's YAML;** that GitHub's parser reads the file as Bun does is assumed.
- **This PR's own run gates nothing by job:** its base's classifier is PR 1's, for which `.github/` is code.

**Held.**
- **`changes.sh --self-check`,** under the Mac's bash 3.2, BSD awk and sed, and under ubuntu 24.04's bash 5.2, mawk and GNU sed, CI's, where the cut of the real workflow is byte for byte the Mac's: eight decisions on the workflow's path and modes, fourteen runs in merge-commit repositories on a five-job workflow, and four lines the cut refuses. The edited job runs, an unedited gated job skips and the ungated ones are never named; a docs file beside the edit, a new job, a new gated job (which runs), and a heading reworded (its job's) skip as they should; `.top`, the `changes` job and its heading, the checker's job, a code file beside, an uncuttable line, a stacked PR and a push run every job.
- **The real workflow, in scratch merge commits on this branch's file:** db-live's timeout edited skips the other eleven gated jobs; the aggregate's heading, all twelve; two jobs and a doc, the other ten; a comment above `concurrency:`, none.
- **Fourteen mutants of the classifier, each failing its self-check:** `.top`'s rule, the `changes` job's rule, the edited jobs listed, the gate unread, any mode, any workflow file, headings going with the job above, a non-key line cut through, a workflow beside code read by job, a refused cut read as no change; and from review pass 2, blocks compared from the base's side alone, the checker's job off `RUN_ALL_JOBS`, and a comment with no space before its `#` after a key and after `jobs:`.
- **Mutants of the checks, each failing the checker:** check 51's per-block reading, its `.top` reading, a refused cut passing, check 20's needs rule and its gate without `skip`. Check 51 names the real `changes.sh` with the checker's job off `RUN_ALL_JOBS`, and on the real workflow an anchor in db-schema's block aliased in db-live's, and a job in flow style.

### PR 1: a docs-only pull request skips the code jobs

**What changed.**
- **A first job, `changes`** ("What the change can affect"):
  - **On a pull request** it checks out `.github/ci` alone, shallow and blobless. It then runs the **base branch's** copy of `.github/ci/changes.sh` (`git show HEAD^1:…`), so a PR that edits the classifier is judged by the copy already on its base, which denies `.github/`. A base with no copy, or a fetch that fails, says `code=true`.
  - **Any other event** has no checkout and says `code=true`.
  - **The classifier** reads `HEAD^1..HEAD` of the merge commit with `--raw -z --no-renames`, so each path comes with its modes. A symlink or submodule anywhere is code (review pass 2). A record not in that shape, or with no path after it, is code too. Its answer also goes on the run's summary page, the path in a code span; so does the fallback's, when the base has no classifier or another event runs. It says `code=false` only for a PR into the default branch whose every path is on its allowlist. A PR stacked on another branch is kept from a green that would survive its retargeting to main. The strict up-to-date rule already makes a retargeted PR run again, so this is defence in depth.
  - **Anything else says `code=true`:** a HEAD with no second parent (not the merge commit, or a shallow fetch), a change that's empty or unreadable, or one path off the list.
  - **The allowlist** is Markdown anywhere, and images under `docs/`, except:
    - files a gated job reads: the ADR an eval pins by its wording, four contribution READMEs the auth and writes suites assert over, and `changes/`, which the full-stack job's release rehearsal reads;
    - whole directories that reach an image, the stack or CI: `dashboard/`, `plugins/`, `server-portable/`, `deploy/`, `db/migrations/` and `.github/`.
  - **`why` loses its control characters, and `code` is `true` unless exactly `false`.** A path's own newline would otherwise be a line of its own in `GITHUB_OUTPUT`, and a crafted name could set `code`.
- **Eleven gated jobs** need `changes` and run under `${{ !cancelled() && (needs.changes.result != 'success' || needs.changes.outputs.code != 'false') }}`: portable-server, db-schema, replay-gate, db-live, data-layer, the four full-stack jobs, auth-poc and compat-shim. A `changes` job that fails or is cancelled runs them all, and so does any answer but exactly `false`.
- **repo-consistency, commit-lint and workflow-lint always run.** repo-consistency also runs the classifier's own cases, `changes.sh --self-check`.
- **"Fork Checks passed"** needs `changes` too. Its `MAY_SKIP` adds the gated jobs only when `changes` succeeded and said `code=false`, so a cancelled run's unstarted jobs fail it. Its step is unchanged.
- **Check 20** holds this shape:
  - the `changes` job present, with no `if:`, and as written: its keys, its one output from the decide step, its checkout's `if:` and inputs, and the decide step's env and `run:` verbatim (`CHANGES_RUN`). A pinned `EVENT`, a literal output, a `continue-on-error` or a `|| true` each fail;
  - repo-consistency's step running the classifier's cases;
  - each gated job (`AGGREGATE_GATED`) needing it, under exactly `GATED_IF`;
  - `MAY_SKIP` as `gatedMaySkip()`'s expression;
  - a job that needs a gated job running under `!cancelled()`, as `publish-test-counts` does.

  Its probes add a gated workflow, two accepted shapes and eighteen mutants.
- **Check 47** (new) holds the allowlist to the code. Any tracked Markdown or image file that code names is either denied by the classifier, or listed in `NAMED_NOT_READ` with exactly the files that name it and the reason none reads it for a gated job (19 today). A new namer of a listed file fails until it's added with its reason. A path token counts as naming a file when, read from the root or from the naming file's directory, it is that file. A stale entry or namer fails, and so does a reading that stops seeing the pinned ADR as named and denied. Its probes pin the token reading and which files count as code.

**Why.** Every Fork Checks run used every job, whatever changed. One run is about 18 of the Free plan's 20 concurrent jobs, and queueing is the run's p90. Docs-only pull requests were 6 of the last 100 merged; each of their runs now skips about 2,000 runner-s and ~15 slots, finishing at about repo-consistency's length. A code PR's run gains the `changes` job, about 5–8 s, on its critical path: about even in wall time per PR, about 110 runner-s a run fewer on average, which is the queueing lever (the 10-28 simulation). PRs 2–4 make it pay widely:
- PR 2: per-job ownership of fork-checks.yml;
- PR 3: a path map derived from what each job runs;
- PR 4: per-area skips.

**Departures from the ticket.**
- **`db/README.md` is on the allowlist,** where the ticket kept it off: no gated job reads it since SMD-3614 moved the suites' counts to the wiki. So the ticket's Verify line "a PR touching only `db/README.md` runs db-schema and db-live" no longer applies. Check 47 lists why.
- **Wider than the ticket's start, and narrower:**
  - Markdown anywhere rather than `docs/**` and `*.md`;
  - `changes/` denied, not allowed, since the rehearsal reads it;
  - images under `docs/` alone.
- **Check 47 is added in PR 1** rather than waiting for the path map. A hand-kept deny list goes stale the day a suite starts reading a README, which the survey found five times over.
- **The `changes` job is bash on a blobless checkout,** not `scripts/check-landing.ts`'s classification: a Bun setup would add seconds to every code PR's critical path.
- **The base's classifier decides, and only PRs into the default branch skip:** both added in review (pass 1), beyond the ticket.

**Gaps left.**
- **A PR can still skip its own code jobs by editing `fork-checks.yml`,** the aggregate or the checker, as it always could, since all of them run from the PR's tree. The ruleset asks no review. What review pass 1 closed is the subtler one-line edit to `changes.sh`.
- **`db/ci-parity.sh` doesn't run `changes.sh --self-check`.** Its rows run Bun files, and check 35 reads only those, so the bash step is CI's alone.
- **Check 47's reading is lexical.** A path built from pieces (`join(ROOT, "docs", "x.md")`), a template, or a directory walk isn't seen. No gated code reads an allowed doc that way today; a future suite could, and check 47 would not notice.
- **Check 47 will fail some unrelated PRs,** perhaps 1–3%: one that adds or drops a message naming a listed README. That is by design, and the failure says which file and what to do.

**Held.**
- **`changes.sh --self-check`:** 31 decisions and a malformed-record case, then 15 runs in scratch repositories shaped as a PR's merge commit, with the base moved after the branch. Each run must write one `code=` line, and the right one:
  - docs alone gives `false`;
  - code, a mix, a rename into `docs/` or out of it into code, a symlink at a docs path, the base's symlink made a regular file or deleted, a PR into another branch, a push, and a HEAD with no second parent give `true`;
  - a rename from one docs file to another gives `false`;
  - a code file named `server-portable/x<newline>code=false` gives one line, `true`. With the control-character line removed, it gives two, the last `false can affect the code jobs`, and the gated jobs would skip;
  - a docs name holding a newline gives `false`, one line.
- **Mutants of the classifier, each now failing its self-check:** no sanitising, no `-z`, no `--no-renames`, no second-parent check, `HEAD^2` diffed, no base-branch rule, `*.md` matched first, no mode check, a mode check of the new mode alone, no raw-shape guard, and `--name-only` in place of `--raw`.
  - Without `--no-renames`, a rename's last record used to swallow its new path. A docs-to-code rename then read as docs; review pass 2 made such a record code.
- **Check 20 on the real workflow, mutated in a scratch tree:** these each fail with check 20's own message:
  - a gated job's `if:` without fail-open, an unconditional `MAY_SKIP`, a gated job without `needs: changes`, and the `changes` job given an `if:`;
  - from review pass 1: a literal `'false'` output, the step writing `code=false`, `EVENT` pinned, depth 1, `|| true`, the step's `continue-on-error`, the self-check step deleted, and the PR's own classifier deciding.
- **Check 47 in the worktree** (each file backed up outside and restored): each of these fails:
  - the ADR or a telegram README taken off the deny list;
  - a `NAMED_NOT_READ` entry removed, a stale one added, or one the classifier denies;
  - a gated suite that starts naming a listed README, a namer dropped from an entry, or a non-namer added to one.
- **The checker, the scripts' typecheck, actionlint 1.7.7 with shellcheck, and shellcheck** on `changes.sh` (against a positive control) pass.
- **On GitHub:** this PR changes the workflow, and main has no classifier yet, so its own run gates nothing (`code=true`). The skip path's first run is a throwaway draft PR with a Markdown change alone, into a temporary base branch. That branch is this one, plus a commit taking out the base-branch rule, which would otherwise keep any PR not into main at `code=true`.
