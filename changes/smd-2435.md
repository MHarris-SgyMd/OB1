## Changelog

Each gated Brain Checks job records the tracked files it read, by `.github/ci/reads.sh`, and main's runs keep the lists; nothing skips on them yet (SMD-2435). No behaviour changes: CI only.

## Record

Each gated job records what it read: a marker after its checkout, the list at its end — the map's raw material, with nothing skipping on it yet (SMD-2435)

**What changed.** PR 3b's first cut: record, and use nothing.
- **`.github/ci/reads.sh`.** `mark` makes a marker straight after a job's checkout. `list JOB [CELL]`, the job's last step but its own upload, writes `$RUNNER_TEMP/reads/JOB[.CELL].txt`: a header line (job, cell, commit, how the job stood, counts), then a row for each tracked file whose access time is later than the marker's (`f`), each tracked folder's (`d`), and each tracked file gone by the job's end (`g`), read or not, since its access time went with it. It says the counts by top-level folder and a digest. It exits 0 whatever it finds, a job or cell name's odd characters written `_`, so no job fails for its list.
- **In each of the twelve gated jobs:** the marker step after the checkout, then, last, the list and an upload of it, `reads-<job>`, kept for 14 days from a push to main alone. On a pull request the list is made and said, not kept. Both run after a failed step too, but only where the marker step succeeded: after a checkout that failed there is no script to run. An upload that fails does not fail its job, as the list does not.
- **Check 55** holds the placement, since the record is only as good as it: one checkout, the marker straight after it and nowhere else, however the script is reached; the list as the job's last step but its own upload, named for the job and its matrix cell.
- **`reads.sh --self-check`** runs in repo-consistency, on a fresh clone of a scratch repository made inside the checkout's git directory, so on the filesystem the jobs' lists rest on. On a runner it fails if that filesystem records no access times. It drops git's exported environment and the caller's `JOB_STATUS` first, makes its scratch commits under no setting of the caller's that could stop one (a signature asked of every commit, a hook), and removes its scratch directory however it ends.
- **`changes.sh --self-check`** drops git's exported environment too. Under an exported `GIT_DIR` its scratch commits landed on the caller's branch, nine of them in a scratch repository; so did the first form of `reads.sh`'s. Its scratch commits are made the same way as `reads.sh`'s, and with no scratch directory it stops, where it went on at the filesystem's root.

**Why.** PRs 1 to 3a skip a job only for a path named by hand. A map precise to the file would let 25 to 44 of main's last 100 merged pull requests skip a gated job, about 8 to 15% of gated runner time, against 2 today; rows a directory deep, 5 to 11.
- **Deriving it from the code was the plan, and imports are not the read set.** Traced under strace, `test-schema.ts` opened 208 tracked files where its imports reach 38: 147 migrations, 25 `.sql` files under folders it walks, four scripts read as text. Each would be a declaration kept by hand.
- **A runner records the read itself.** OB1 PR 835, a probe never merged: the checkout is on ext4 mounted `relatime`, where a file's first read after it is written moves its access time. `cat`, `Bun.file`, `readFileSync`, an `import` and a listed folder all showed; a file left alone did not.
- **So the jobs' own reads are the map** (the maintainer, 2026-11-20): main's run records them, and PR 3b-2 has a pull request's jobs skip by the newest record. That rests on a job reading the same files from run to run, which this cut is here to measure.

**Held.**
- **The self-check,** in the Linux image on an ext4 mounted `relatime` from a loop file, as a runner's checkout is, and on macOS (APFS):
  - in the list: a file read, one read at the top, one two folders down, one whose name opens with `-`, the script's own copy, a folder listed, and as `g` rows a file deleted unread and one read then deleted;
  - not in it: a file in a listed folder, a folder passed through, a path with a tab in its name (counted);
  - no marker gives an empty list that says so; so does a sight file removed, or written after the marker; a cell named `a/b c` is written `a_b_c`; no job named is refused;
  - a file copied is in the list;
  - the cases again under an exported `GIT_DIR` and `JOB_STATUS`, from a repository of one commit that is still of one commit.
  - Its first form ran in the repository that made the files, where `git add` had read each: nothing showed, which is the second-read rule below, and why the cases run in a clone.
- **Twelve mutants of `reads.sh`,** each run through the self-check in the Linux image on ext4, after a control that survives. Eleven fail it: paths given to `find` bare, the own row dropped, the `g` rows dropped, modification time for access time, folders not recorded, the sight test always ok, a cell's characters kept, the marker made before the sight file, the newer-than-marker guard removed, git's exported environment kept, the caller's `JOB_STATUS` kept. The twelfth, an empty sight file, is no mutant on Linux, where a read of no bytes moves the time; on APFS it does not, and there the self-check says the filesystem is blind.
- **Copies, on ext4.** `cp`, `cat a > b`, `dd`, and Bun's `copyFileSync`, `cpSync` (a file and a folder) and `Bun.write` each moved their source's access time on the ext4 mount, and on tmpfs. On the image's own overlay, which makes a copy as a clone, only `cat` to nowhere, `dd` and `cp --reflink=never` did. `db/test-live.ts` copies fixture folders with `cpSync`, so this is what db-live's lists rest on.
- **Under a global git config** that asks a signature of every commit from a signer that fails, and names a hooks folder whose `pre-commit` fails: both self-checks pass, where both failed before.
- **Interrupted,** by INT and by TERM a second in: the self-check exits 130 and 143 and leaves no scratch directory, where its first form left one each time.
- **The list's cost.** Each path goes to `find` behind `./`, by a loop that makes its arguments again for each one: a whole batch of 2,000 paths took 0.94 s in dash, and batches of 200 take 0.13 s. A list reads the tracked files and the folders, so about two of those a job cell.
- **Against strace, on a real suite.** In the Linux image, on a fresh clone: marker, installs, `test-schema.ts`, list. The list holds 217 tracked files and 97 folders: every one of the 208 files strace saw the suite open, and nine more that the installs and Bun's own start read (`package.json`, `bun.lock`, `tsconfig.json`, `bunfig.toml`). strace saw 96 folders listed.
- **Check 55's probe,** 35 cases, each refusal by its words, and seven mutants of the real workflow: portable-server's marker removed, db-live's list with no cell, an action after db-schema's upload, a second marker in replay-gate run from the script's folder, auth-poc's marker with no id, compat-shim's list run where no marker was made, deploy-stack's upload failing its job.
- **shellcheck** v0.9.0, v0.10.0 and stable on `reads.sh` and `changes.sh`, each after a positive control: nothing. **actionlint** on the workflow: nothing.

**Tidied while the files were open.** `reads.sh`'s self-check makes its fresh clone by one helper and leaves its scratch directory to the trap; a local joins its function's others; eleven workflow comments and one of check 55's messages name the list's place as it now is.

**What a list does not hold.**
- **A read through a container's read-only bind mount,** which moves no access time (the probe). The jobs that run a compose stack read more than their lists say; PR 3c's.
- **A second read.** `relatime` moves the time once, so a list says "read at all". A file something read before the marker would never show. One thing does run between a job's checkout and its marker: the bash that reads `reads.sh` to make it. So that file's row is added by rule, and check 55 keeps every other step after the marker.
- **A file asked after and never opened.** `existsSync`, `[ -f x ]`, a size or a mode read move no access time. A path added, removed or made executable can matter to a job whose list has neither it nor its folder; PR 3b-2's comparison has to count that.
- **A path with a tab or a newline in its name,** counted in the header's `odd=` and left out.
- **A file copied as a clone.** Where the filesystem clones a copy (btrfs, xfs, APFS by `cp -c` and `Bun.write`) no byte is read and no time moves. A runner's ext4 clones nothing, and the self-check copies a file and fails on a runner if it does not show.
- **A checkout whose files are on another filesystem than its git directory,** a linked worktree on another volume: the sight test and the self-check see for the git directory's. No runner's checkout is one.
- **More than the job meant to read, sometimes.** `git diff` re-reads a file written in the same second as the index. The probe's compat-shim job accessed 1,230 of 1,934 tracked files that way. It only adds.

**Not taken.**
- **The derived closure, with a witness checking it.** Chosen first, an hour before the probe; about 170 files to declare for one suite.
- **Deriving in the `changes` job.** Every gated job would start some 8 to 10 s later on every run.
- **A generated file checked in.** 28 of the last 100 pull requests add or delete a code file and 68 change an import line.
