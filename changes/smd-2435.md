## Changelog

Each gated Brain Checks job records the tracked files it read, by `.github/ci/reads.sh`, and main's runs keep the lists; a pull request's database and server jobs skip when nothing they read on main's newest green run has changed since; three jobs that run containers also watch what is opened through a mount, towards skipping by it (SMD-2435). No behaviour changes: CI only.

## Record

Each gated job records what it read, and six jobs skip by it: a pull request runs the database and server jobs only when something they read on main has changed (SMD-2435)

Three cuts so far. PR 3b-1 records; PR 3b-2 puts the lists to use; PR 3c-1, at the end of this record, has three jobs that run containers watch their opens as well.

**What changed in PR 3b-1.** Record, and use nothing.
- **`.github/ci/reads.sh`.** `mark` makes a marker straight after a job's checkout. `list JOB [CELL]`, the job's last step but its own upload, writes `$RUNNER_TEMP/reads/JOB[.CELL].txt`: a header line (job, cell, commit, how the job stood, counts), then a row for each tracked file whose access time is later than the marker's (`f`), each tracked folder's (`d`), and each tracked file gone by the job's end (`g`), read or not, since its access time went with it. It says the counts by top-level folder and a digest. It exits 0 whatever it finds, a job or cell name's odd characters written `_`, so no job fails for its list.
- **In each of the twelve gated jobs:** the marker step after the checkout, then, last, the list and an upload of it, `reads-<job>`, kept for 14 days from a push to main alone. On a pull request the list is made and said, not kept. Both run after a failed step too, but only where the marker step succeeded: after a checkout that failed there is no script to run. An upload that fails does not fail its job, as the list does not.
- **Check 55** holds the placement, since the record is only as good as it: one checkout, the marker straight after it and nowhere else, however the script is reached; the list as the job's last step but its own upload, named for the job and its matrix cell.
- **`reads.sh --self-check`** runs in repo-consistency, on a fresh clone of a scratch repository made inside the checkout's git directory, so on the filesystem the jobs' lists rest on. On a runner it fails if that filesystem records no access times. It drops git's exported environment and the caller's `JOB_STATUS` first, makes its scratch commits under no setting of the caller's that could stop one (a signature asked of every commit, a hook), and removes its scratch directory however it ends.
- **`changes.sh --self-check`** drops git's exported environment too. Under an exported `GIT_DIR` its scratch commits landed on the caller's branch, nine of them in a scratch repository; so did the first form of `reads.sh`'s. Its scratch commits are made the same way as `reads.sh`'s, and with no scratch directory it stops, where it went on at the filesystem's root.

**Why.** PRs 1 to 3a skip a job only for a path named by hand. A map precise to the file would let 25 to 44 of main's last 100 merged pull requests skip a gated job, about 8 to 15% of gated runner time, against 2 today; rows a directory deep, 5 to 11.
- **Deriving it from the code was the plan, and imports are not the read set.** Traced under strace, `test-schema.ts` opened 208 tracked files where its imports reach 38: 147 migrations, 25 `.sql` files under folders it walks, four scripts read as text. Each would be a declaration kept by hand.
- **A runner records the read itself.** OB1 PR 835, a probe never merged: the checkout is on ext4 mounted `relatime`, where a file's first read after it is written moves its access time. `cat`, `Bun.file`, `readFileSync`, an `import` and a listed folder all showed; a file left alone did not.
- **So the jobs' own reads are the map** (the maintainer, 2026-11-20): main's run records them, and PR 3b-2 has a pull request's jobs skip by the newest record. That rests on a job reading the same files from run to run, which this cut is here to measure.

**Held.**
- **The self-check,** in the Linux image on an ext4 mounted `relatime` from a loop file, as a runner's checkout is, and on macOS (APFS):
  - in the list: a file read, one read at the top, one two folders down, one whose name opens with `-`, the script's own copy, a folder listed, and as `g` rows a file deleted unread and one read then deleted;
  - not in it: a file in a listed folder, a folder passed through, a path with a tab in its name (counted);
  - no marker gives an empty list that says so; so does a sight file removed, or written after the marker; a cell named `a/b c` is written `a_b_c`; no job named is refused;
  - a file copied is in the list;
  - the cases again under an exported `GIT_DIR` and `JOB_STATUS`, from a repository of one commit that is still of one commit.
  - Its first form ran in the repository that made the files, where `git add` had read each: nothing showed, which is the second-read rule below, and why the cases run in a clone.
- **Twelve mutants of `reads.sh`,** each run through the self-check in the Linux image on ext4, after a control that survives. Eleven fail it: paths given to `find` bare, the own row dropped, the `g` rows dropped, modification time for access time, folders not recorded, the sight test always ok, a cell's characters kept, the marker made before the sight file, the newer-than-marker guard removed, git's exported environment kept, the caller's `JOB_STATUS` kept. The twelfth, an empty sight file, is no mutant on Linux, where a read of no bytes moves the time; on APFS it does not, and there the self-check says the filesystem is blind.
- **Copies, on ext4.** `cp`, `cat a > b`, `dd`, and Bun's `copyFileSync`, `cpSync` (a file and a folder) and `Bun.write` each moved their source's access time on the ext4 mount, and on tmpfs. On the image's own overlay, which makes a copy as a clone, only `cat` to nowhere, `dd` and `cp --reflink=never` did. `db/test-live.ts` copies fixture folders with `cpSync`, so this is what db-live's lists rest on.
- **Under a global git config** that asks a signature of every commit from a signer that fails, and names a hooks folder whose `pre-commit` fails: both self-checks pass, where both failed before.
- **Interrupted,** by INT and by TERM a second in: the self-check exits 130 and 143 and leaves no scratch directory, where its first form left one each time.
- **The list's cost.** Each path goes to `find` behind `./`, by a loop that makes its arguments again for each one: a whole batch of 2,000 paths took 0.94 s in dash, and batches of 200 take 0.13 s. A list reads the tracked files and the folders, so about two of those a job cell.
- **Against strace, on a real suite.** In the Linux image, on a fresh clone: marker, installs, `test-schema.ts`, list. The list holds 217 tracked files and 97 folders: every one of the 208 files strace saw the suite open, and nine more that the installs and Bun's own start read (`package.json`, `bun.lock`, `tsconfig.json`, `bunfig.toml`). strace saw 96 folders listed.
- **Check 55's probe,** 35 cases, each refusal by its words, and seven mutants of the real workflow: portable-server's marker removed, db-live's list with no cell, an action after db-schema's upload, a second marker in replay-gate run from the script's folder, auth-poc's marker with no id, compat-shim's list run where no marker was made, deploy-stack's upload failing its job.
- **shellcheck** v0.9.0, v0.10.0 and stable on `reads.sh` and `changes.sh`, each after a positive control: nothing. **actionlint** on the workflow: nothing.

**Tidied while the files were open.** `reads.sh`'s self-check makes its fresh clone by one helper and leaves its scratch directory to the trap; a local joins its function's others; eleven workflow comments and one of check 55's messages name the list's place as it now is.

**What a list does not hold.**
- **A read through a container's read-only bind mount,** which moves no access time (the probe). The jobs that run a compose stack read more than their lists say; PR 3c's, and since PR 3c-1 the three that watch have those reads.
- **A second read.** `relatime` moves the time once, so a list says "read at all". A file something read before the marker would never show. One thing does run between a job's checkout and its marker: the bash that reads `reads.sh` to make it. So that file's row is added by rule, and check 55 keeps every other step after the marker.
- **A file asked after and never opened.** `existsSync`, `[ -f x ]`, a size or a mode read move no access time. A path added, removed or made executable can matter to a job whose list has neither it nor its folder; PR 3b-2's comparison has to count that.
- **A path with a tab or a newline in its name,** counted in the header's `odd=` and left out.
- **A file copied as a clone.** Where the filesystem clones a copy (btrfs, xfs, APFS by `cp -c` and `Bun.write`) no byte is read and no time moves. A runner's ext4 clones nothing, and the self-check copies a file and fails on a runner if it does not show.
- **A checkout whose files are on another filesystem than its git directory,** a linked worktree on another volume: the sight test and the self-check see for the git directory's. No runner's checkout is one.
- **More than the job meant to read, sometimes.** `git diff` re-reads a file written in the same second as the index. The probe's compat-shim job accessed 1,230 of 1,934 tracked files that way. It only adds.

**Not taken.**
- **The derived closure, with a witness checking it.** Chosen first, an hour before the probe; about 170 files to declare for one suite.
- **Deriving in the `changes` job.** Every gated job would start some 8 to 10 s later on every run.
- **A generated file checked in.** 28 of the last 100 pull requests add or delete a code file and 68 change an import line.

**Measured, before PR 3b-2** (main's six runs after PR 3b-1, 2026-11-20). Two runs on one tree wrote the same list in 16 of 17 cells. Across five pairs of commits, 15 cells never gained or lost a row without a cause in the diff. compat-shim and deploy-stack-brains flip hundreds of rows a run: each has git read the tree back (`git diff --quiet`; `git describe --dirty` in `canary.sh`).

**What changed in PR 3b-2.** A path off every list above ran every job. Now six jobs may skip it.
- **`changes.sh`'s `by_map`.** It fetches the lists of main's newest green push run, the `reads-<job>` artifacts, and counts everything that differs between that commit and the checkout: main's own commits since, with the pull request's. A job skips when none of it is among what the job read.
- **`MAP_LISTS`:** portable-server, db-schema, replay-gate, data-layer, preflight-rest and db-live, by its six cells together. The four deploy-stack jobs and auth-poc stay out (their containers read through mounts no list sees; PR 3c's), and compat-shim (it greps the whole tree).
- **A job runs** when a file its list holds is modified or deleted; when a path comes, goes or changes mode in a folder the job listed or read a file in; when a name its tools look for (`package.json`, `tsconfig.json`, an `.env` and the like) comes or goes above a file it read, or a `.gitattributes` there differs at all; when a file comes or goes that is named for a folder it read through; when `CHARGES` gives it a path that differs; or when its block of the workflow differs.
- **A job runs too** when its list is missing, cut short (fewer rows than its header counts, or a last row left unended), short of a path it could not write, or from a run that failed or saw no access times; for a matrix job, any one cell's.
- **Every job runs** with no lists at all, lists of two commits, a commit that cannot be fetched, a symlink or a submodule in the change, or a workflow that differs outside its jobs.
- **`CHARGES` counts beside a list, unless its row says the list decides** (the maintainer, 2026-11-20). A job written `job:list` in a row is charged with no lists, and left to its list where there is one. `changes/*` marks db-schema: its list never held a record over main's runs, and it ran for every pull request with one.
- **The changes job** hands the classifier its token, the workflow's `contents: read` and no more. Check 20 holds the token there and the job to no permissions of its own.
- **Check 56** holds `MAP_LISTS`: gated jobs alone, a matrix job by every cell, every gated job in it or in `MAP_ALWAYS_RUN` with its reason, and no job in it that runs compose, builds an image or mounts a path into a container, or reads the event that started the run: the lists are a push run's. Both by allowlist, after three review passes each found another way to write a mount or a condition: the dozen things a mapped job may ask of docker, the three actions it may use, the `github` names that say nothing of the event, and the two conditions that run a step on a push to main alone. A mapped job asks git only which commit it is at and what it is set to, since git names the tracked files from its index and reads them from its own store; it reads no secret, which a pull request from another repository lacks; and the workflow's token is held to `contents: read` alone.

**What changed in PR 3c-1.** Three jobs watch, and nothing skips by it yet.
- **`reads.sh mark --watch`** starts a watch beside the marker: one inotify watch on each tracked folder, which the kernel tells of each open, to read or to write, of the folder or of a file in it, through whatever mount and by whatever process. It is some eighty lines of python3, started with `-I`, held in `reads.sh` itself, and is the watch only while a file holds the name its marker gave it: a later marker, or one that stopped waiting for it, takes the name away and it ends itself.
- **`list` ends the watch and adds what it saw:** a tracked file opened is an `f` row and a tracked folder opened a `d` row, whether or not its access time moved; every tracked file under a folder that is another folder by the end is a row, since the watch stayed with the first, the folder known by its number or by its watch having ended; and so is a tracked file whose name, links or mode changed since the marker, since one given a second name elsewhere, or moved out and back, can be read where neither witness is told. The header then ends `watch=ok`; `watch=lost` where the watch ended early, was not heard from again, lost events to a full queue, could not read all that was queued in five seconds or was refused a watch on a folder; `watch=none` where none began in the ten seconds the marker waits. Lost or none, the rows are the access times' alone and a warning says so. The log names the rows the watch alone gave. A job that does not watch writes the header it wrote before. Watched or not, a list is `sight=broken` and holds no row, where it was only shorter, when git could not name the paths, a find died, the rows could not be written or sorted, or the marker went meanwhile. A find that only fails takes its paths for gone, as it does a path that is.
- **deploy-stack-auth, deploy-stack-observability and auth-poc watch** (the maintainer, 2026-11-23). **Check 55** holds it by name, `READS_WATCHED`: a named job's marker runs `mark --watch` and no other job's does.

**Why.** PR 3b-2 left out the six jobs that run containers or grep the tree. Looked into before any code:
- **An image build is already in the lists.** It reads its context on the runner, so those reads move access times.
- **What is missed is a read through a read-only bind mount:** today `db/test-coordinator.ts` and `deploy/federated/broker.ts` in deploy-stack, and `deploy/orchestration/pipelines.json` in deploy-stack-auth.
- **Every one of the six lists all 275 folders.** `.dockerignore` has two exceptions with a wildcard, and with one the build's walk passes over no excluded folder. So a file added or deleted anywhere would run them.
- **Worth,** over main's last 100 merged pull requests: the five container jobs as mapped jobs take 20.4% of gated runner-seconds skipped to 22.4%, and to 23.8% with folder rows cut to a walk that passes over excluded folders. deploy-stack and deploy-stack-brains would skip 3 and 2 of the hundred, so they stay as they are, with compat-shim.
- **Decided:** these three jobs; and the two `.dockerignore` lines written out as file lists in a later cut of its own. The three join `MAP_LISTS` in PR 3c-2, once main's lists show the watch holding.

**Held, for PR 3c-1.** In the Linux image on ext4 mounted `relatime`, as a runner, and on macOS, where no watch can start and the list says so.
- **The self-check's new cases:** a file read and a folder listed before the marker and again after it are rows, by the watch alone; a file read through a read-only bind mount in another mount namespace is a row, by the watch alone; an untracked file or folder opened is none, nor is the checkout's top; a watch killed, one that said nothing, one whose events the kernel dropped, one refused a folder, one that could not start, one that came up after its marker stopped waiting and one beside another watch's word each say so and exit 0; a folder swapped for another, one removed and made again and one made after the marker are each known as another, and a file in one is a row; a file given a second name in a folder no watch is on is a row; opens that go on while the list is made do not lose the watch; a list whose paths git could not name, one made while a find died and one whose rows could not be sorted are each broken and empty; opens still queued when the watch is told to stop are read; a plain marker over a live watch ends it and names none, and a second watched marker takes the watch over; the watch is gone once its list is written.
- **49 mutants of `reads.sh`** through it, after a control that survives: 47 fail it. Of the other two, an empty sight file is no mutant on Linux, as before; and no case can hold the watch up for five seconds with opens queued, so that limit is held by a run under strace with one read delayed six seconds: `ok` and a row short before, lost now. Three guards against races no case can time are in no mutant: a stop acted on in the turn it is seen (its window widened by 0.15 s lost the last open in 11 of 30 lists, and as now written in none), and the watch's two last looks at its name.
- **On the repository itself,** cloned as a runner checks it out: 275 folders watched in 0.2 s, the list in 0.5 s, and after a grep of every `.ts` file, a read of every migration (619 of 1,974 files opened) and one read through a read-only bind mount, one row by the watch alone, that file.
- **Check 55's probe** of the jobs that watch, six cases, and three mutants of the real workflow's markers; shellcheck at three versions and actionlint: nothing.

**Not yet seen on a runner.** This pull request's own run is the first: its three jobs say how their watch stood and which rows it alone gave.

**What the watch does not change.** It sees an open, not a read, so a file opened and only asked after is a row, and a file opened then deleted is an `f` row beside its `g` row. A watched list still holds every folder, until `.dockerignore`'s exceptions are written out. Through a read-only mount three things stay unseen, by the watch as by access times: a tracked symbolic link that is followed (the file it leads to is a row, and a changed link runs every job), a file read by a descriptor opened before the marker, which no step is, and a file opened by its handle with no name, which asks a capability no container has unasked.
