## Record

The agent runner's copied helpers have one definition each, and the two that differed take the stricter rule (SMD-4325)

**Problem.** `scripts/agent-runner/` carried the same small helpers written out in several files: `isObject` in four, the hidden-text printer in three, the no-follow file read and write in two, `jsonOf` and `NOT_JSON` in two, the one-line cut in five, the checks' `developerGit` in four, and the claim-token mask in four places. These decide what untrusted text reaches a terminal, a record or a PR. Two had already drifted: `claims.ts`'s `isObject` let an array pass where the other three refused it, and three of the four masks hid `wc_…` alone where `publish.ts` also hid the markdown-escaped `wc\_…`.

**Decided.** The maintainer chose to remove the copies inside the files hashed into the probe stamp too, and to give the differing copies the stricter rule everywhere.

**Change.** Three commits, the moves apart from each behaviour change, as the ticket asks.

- **The moves, no behaviour changed.**
  - `guard.ts` exports `isObject`, a new `printable`, and `shownText`, which `gate.ts` and `dry-run.ts` now call. `session.ts` and `mock-api.ts` import `isObject`.
  - `session.ts` keeps `readNoFollow` and `writeNoFollow`; `record.ts` imports them and hands them on.
  - `facts.ts` exports `jsonOf` and `NOT_JSON` for `claims.ts`.
  - A new `text.ts` has `oneLine`, which `bundle.ts`, `clone.ts`, `claims.ts`, `board.ts` and `run.ts` call.
  - A new `fixture-git.ts` has `fixtureGit`, over `probes.ts`'s `developerGit`, for the four checks that carried a copy.
- **One mask.** `maskTokens` moves from `publish.ts` to `text.ts` with its wider pattern. A claim reply's detail (`claims.ts`), the hand-back comment and the release's reason (`live.ts`) now hide the escaped form too.
- **One object rule.** `claims.ts` imports `guard.ts`'s `isObject`. Three things a caller could see change, each for a body the core never sends:
  - `GET /v1/brain` answering an array is refused as "JSON that isn't an object", where it was "tier is unset";
  - a 200 claim reply that is an array is the error "the brain answered 200", as for any body that isn't an object, where it was "a shape the runner doesn't know";
  - a renewal whose `lapsed` field is an array reads as no lapse, as a string there already did, where it read as a lapse at no time. The publish decision is the same either way: it stops only for another claim named, an unreadable list or a count of more.

**The probe stamp.** `guard.ts`, `session.ts` and `mock-api.ts` are three of the six files hashed into it (`profile.ts`'s `PROFILE_FILES`), so this change voids a stamp made before it. The probes must be run again before a real session. `text.ts` and `fixture-git.ts` are outside the hashed set, and nothing hashed imports them.

**Verify.**

- **The moves change no case.** The twelve self-checks were run on main and on the first commit: the same 903 cases pass on each, step by step (caught: run-it).
- **The mask's cases have teeth.** `claims-check` gains one case and `live-check` two, whose fetch stub now records a request's body so the release's reason can be read. With the mask narrowed back to the plain form, those three fail, and `publish-check`'s escaped-form case with them (caught: mutant).
- **The object rule's cases have teeth.** `claims-check` gains two cases and sharpens one. With `claims.ts` back on the lenient rule all three fail (caught: mutant).
- The scripts typecheck is clean and `scripts/check-consistency.ts` passes.

**Not checked here.** The probes were not re-run against the real CLI from this branch; that is the step above, before the runner's next real session.
