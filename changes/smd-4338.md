## Changelog

The session hook (1.11.1) is its script and the modules in `lib/` beside it. Its secret scan, work-claim renewal, MCP client, config and state directory each sit in a module of their own, and it behaves as 1.11.0 did (SMD-4338). **Upgrading:** a hook command that names the script in a checkout needs nothing but a pull. One that names a copy elsewhere needs `lib/` copied with the script, now and at every upgrade, not linked. Without it the hook fails as it loads: it captures nothing, renews no work claim (which then lapses) and copies no write, and its log says nothing. Then `bun <that copy> --version` prints `session-capture 1.11.1`.

### PR 1: state, the MCP client, config, the secret scan and the claims renewal move to `lib/`

**Not taken.**
- **`STATE_DIR` read through a function,** as the ticket's third Work item put it. ESM already makes `lib/state.mjs` its one owner: an importer cannot assign an imported binding, and every read of it is live, so a function would add a call and nothing else.
- **A version check across the files.** A new script beside an old `lib/` fails to load or runs old code, and `--version` names the script's version. A version constant in each module, checked at start, would make every release edit every module. The README says to copy the two together instead.
- **`SELF` per entry file.** It lives in `lib/state.mjs`, so two entry files loading one `lib/` in a process would share the last one's. No caller loads two: each hook run is one process, and the importers load one entry. Its comment says so.
- **The suite's split** along the same modules is the ticket's last Work item, after PR 3.
