## Changelog

The session hook (1.11.1 to 1.11.3) is its script and the modules in `lib/` beside it. Its secret scan, work-claim renewal, MCP client, config and state directory (1.11.1), its transcript parsing, episodes, model summary and capture posting (1.11.2), and its write fan-out and command line (1.11.3) each sit in a module of their own. The script keeps the exports and the entry point, and the hook behaves as 1.11.0 did (SMD-4338). **Upgrading:** a hook command that names the script in a checkout needs nothing but a pull. One that names a copy elsewhere needs `lib/` copied with the script, now and at every upgrade, not linked. Without it the hook fails as it loads: it captures nothing, renews no work claim (which then lapses) and copies no write, and its log says nothing. Then `bun <that copy> --version` prints the version, which `lib/hook.mjs` holds from 1.11.2.

- **`STATE_DIR` read through a function,** as the ticket's third Work item put it. ESM already makes `lib/state.mjs` its one owner: an importer cannot assign an imported binding, and every read of it is live, so a function would add a call and nothing else.
