## Changelog

Every brain can now record who is working on what. An agent claims a ticket, or one piece of it (`PR 1b-2`), under a lease, and gets back a token that proves the claim. Another agent's claim on the same work, even under the same key, is refused with an answer naming the holder's key and since when. A whole ticket and any of its pieces count as the same work; two different pieces don't. A claim lapses unless renewed with its token, and an operator key can release a stuck one with a reason. This release adds the database side: the `work_claims` table and the `claim_work`, `renew_work_claim`, `release_work_claim` and `list_work_claims` functions, with a new `claims` grant group. No client calls them yet: the REST and MCP operations and the label on search results come in later releases. If your server connects as a `--grant` role, re-run `migrate.ts --grant` after upgrading so the role gets the `claims` group (SMD-3597, migration 113).

## FORK

Work claims in the core: who holds a ticket, or one piece of it, under a lease (SMD-3597)

**Why.** On 2026-10-29 a session recommended SMD-3379 PR 1b-2 while another session had its worktree open: the ticket had been In Progress since its first PR, the branch was unpushed, and nothing an agent could read said the piece was taken. The maintainer decided every brain should be able to track claimed work, so this is a core migration, not a plugin. It is the first child of SMD-3596.

**What changed** (migration 113).
- **`work_claims`**, one row per claim, kept after it ends.
  - The work: `issue`, a ticket key (an ASCII team key of at most 16 letters and digits, a hyphen, at most 10 digits with no leading zero), upper-cased; `piece`, optional, cleaned as free text is (below), compared case-folded by the database's collation through the generated `piece_key` (`''` for the whole ticket).
  - The holder: `holder_name`, `holder_agent_id` and `holder_kind`, from the call's actor envelope (`p_actor`, set as `ob1.actor`, 029's shape) through 046's registry lookup, never from an argument. A call whose envelope names nobody, or from an `ingested` key, raises. Sentinel `ob1:work-claim-holder-from-the-envelope`.
  - `token_hash`: the SHA-256 of the token `claim_work` returns once (`wc_` and 64 hex digits, two `gen_random_uuid()` values, 244 random bits).
  - `label`, free text for people.
  - Free text (a piece, a label, a reason): control characters made spaces, the soft hyphen, zero-width space, word joiner and byte-order mark deleted, every run of white space (Unicode's included) made one space, trimmed. The joiners in emoji are kept.
  - The lease (`claimed_at`, `renewed_at`, `expires_at`) and the end (`released_at`, `released_by` / `_agent_id` / `_kind`, `release_reason`). Ten CHECKs hold the shapes.
  - `work_claims_one_unreleased`, a partial unique index: one unreleased row per ticket and piece. Sentinel `ob1:work-claim-one-per-work`.
- **Four calls**, each writer returning jsonb `{outcome, code, message, claim, held_by, token}`:
  - `claim_work(p_issue, p_piece, p_label, p_lease_seconds, p_token, p_actor)`: `claimed` with the token; `renewed` when `p_token` is the caller's own unreleased claim on exactly this work; or `refused` with `WORK_CLAIMED`, a message naming the work asked for, the first holder's key and the times, and every live claim in the way, the caller's own on overlapping work included.
  - `renew_work_claim(p_claim, p_token, p_lease_seconds, p_actor)`: `renewed`, or refused with `CLAIM_NOT_FOUND`, `CLAIM_NOT_YOURS`, `CLAIM_RELEASED` or `WORK_CLAIMED`.
  - `release_work_claim(p_claim, p_token, p_reason, p_force, p_actor)`: `released`, `already_released`, or refused with `CLAIM_NOT_FOUND` or `CLAIM_NOT_YOURS`.
  - `list_work_claims(p_issues, p_holder, p_include_ended, p_limit)`: the live claims, or every claim with its state (live, lapsed, released). Never a token or its hash.
  - Ten helpers (`ob1_work_claim_*`): free-text cleaning, the key, the lease, the token's hash, the envelope, the isolation check, the lock, the holder test, the claims in the way, and a claim as jsonb.
- **The `claims` grant group** (`db/config.mjs`): SELECT, INSERT and UPDATE on `work_claims`, no DELETE. `--grant` issues it.
- **Docs:** db/README.md (the migration's paragraph, the map, the count, the grants paragraph and table).

**Decided.**
- **A claim is the caller's own only when the key and the token both match.** The dogfood's Claude Code sessions share one brain key, so the key alone would read the 2026-10-29 sessions as one holder. The first draft used a client-given session string for this; review pass 1 showed a refusal printed that string, so any agent could copy it and act as the holder. A token is returned once, kept only as a hash, and useless to another key; nothing a refusal, a claim or a list shows proves ownership. To its own key it is a bearer secret: it travels as a bind parameter, never in a statement's text. That keeps it out of `pg_stat_activity` and error lines; statement logging prints bind values whole unless `log_parameter_max_length = 0` (review pass 4). A claim made with an agent id is matched by that id; one made by name alone by the name, whatever id the caller has since resolved (review pass 2: otherwise the key was locked out of its own claim).
- **No two live claims cover one work, whoever holds them.** Pass 1's first form left every claim the token matched out of the conflict check, so a holder of the whole ticket passing its token could claim a piece too, and then renew neither. The check now leaves out only the one claim being renewed, by id.
- **A refusal is an answer, not an exception**, so a caller branches on it without losing its transaction. A malformed argument (22023), and a call that can't claim at all (no holder or an ingested key, 42501; a transaction above READ COMMITTED, 0A000), raise by name. A role missing the `claims` grant also gets 42501, naming `work_claims`: a deployment's error, not the client's.
- **Free text stays data.** A refusal's `message` names the work the caller asked for, the holder's key and the times: no text another key wrote (its piece, its label, a release reason) reaches the sentence an agent reads as the brain's answer, and none advertises `p_force`. The rest is in `held_by`, as data.
- **Folding follows the database.** Case folding is `lower()` under the database's collation, so a C-collated brain folds ASCII letters alone. Blank-looking characters beyond the invisible marks and Unicode's spaces (a Hangul filler) are kept: lookalikes are not this migration's to judge.
- **Lapse needs no reaper.** A claim past `expires_at` counts as free everywhere; the next claim on exactly its ticket and piece closes it as `lapsed; taken over`, naming the taker, its own key's included: claiming again without the token is how a lost token is recovered. A lapsed claim the next claims only overlap stays unreleased and free. A lapsed claim nothing covers can still be renewed with its token; one another live claim now covers is refused and stays lapsed, renewable once that claim ends.
- **A piece blank once cleaned raises** (22023; review pass 3), never read as the whole ticket, the broadest claim.
- **Default lease four hours**, 60 seconds to a week per call. An agent's session waits on a person for hours, and a worker's fifteen minutes (015) would lapse under it.
- **One advisory lock per ticket, READ COMMITTED only**, checked before a writer reads anything (068's rule). The unique index holds the exact-work half for a write made without the lock. Make one writer call (claim, renew or release) per transaction, or take tickets in key order: two transactions writing two tickets in opposite orders deadlock (40P01), and nothing enforces it.
- **Not the event log.** Claims change no thought, and `thought_audit` is the thoughts' log; the table keeps its own history. SMD-2608 took the same line for a reject.
- **An operator's forced release needs its agent id** and the registry's kind for that id: a name is anyone's to write in an envelope, so it lends no kind (SMD-2608's rule). Board-sync's release when a ticket closes (SMD-3600) will need an envelope carrying an agent id.

**Not taken.**
- **The server.** Preflight checking the `claims` group, write scope for the writers, rate limits, and the REST and MCP operations are SMD-3598; the `claimed` label on results is SMD-3599; board-sync's release when a ticket closes is SMD-3600.
- **A cap on one key's claims**, a list cursor and a release of everything one holder has: filed as a follow-up, since one key claiming every ticket for a week is possible today.
- **Enforcement against the table.** A role holding the `claims` group can write `work_claims` directly, as with every core table its group writes; the rules hold for callers of the functions.
- **Lookalike characters** in pieces (a Unicode hyphen for a hyphen) and pruning ended rows.

**Tidied while the files were open.** claim_work derives the piece's key from the piece it already cleaned, not by cleaning it twice; a header rule says a live claim refuses every other claim on the work, as it has since review pass 2; two README lines rewrapped.

**Upgrade.** MINOR: a new table, an index, fourteen functions and a grant group. Nothing existing changes. A server connecting as a `--grant` role needs `migrate.ts --grant` again before SMD-3598's operations work, and nothing fails meanwhile.
