## Changelog

The session hook (1.10.1) gives up a queued write copy that parses but is no copy, such as `null`, `{}`, a copy with no `args` or a misspelt `tool`, as it gives up one that does not parse, so the copies behind it land (SMD-4412). Before, such a file threw on every drain and stopped its brain's queue for good, or held it a week. A copy whose answer makes the hook fail as it reads it is now kept, as a fault is, and given up after the week, rather than ending the drain. **Upgrading:** a queue stuck on such a file lands at its first drain on 1.10.1, and the file is in that brain's `writes/dead/`, where it can be mended and moved back into `writes/pending/`.

## Record

A queued write copy that is no copy goes to `writes/dead/`, and a throw on one copy keeps it, so neither stops its brain's queue for good (SMD-4412)

**Problem.** The session hook's write fan-out keeps one queue per receiving brain (`writes/pending/`), drained in order (SMD-3314). `drainWrites` moved a file that does not parse to `writes/dead/`. A file that parsed to `null`, or to an object with no `args`, threw on every drain, in `opLabel` or `postWrite`. The throw came before the week's give-up, so the file was never moved aside, and every copy queued behind it waited for good. SMD-1723 PR 3's review pass 9 confirmed it: 3 drains, 3 exits of 1, and the queue behind the file never moved. Only a hand edit or a corrupt file makes such a file: the hook writes every copy whole, through a temp file and a rename.

**Change** (`recipes/session-capture-hook/session-capture.mjs`, 1.10.1).
- **`isCopy`:** a copy as the hook writes one is an object whose `tool` is one of the four the fan-out copies (`FANOUT_TOOLS`), with an object `args` (not a list), an `at` that parses as a date, and `args.client_key`, `args.id` and `alt` each a string or absent. `drainWrites` gives up any other parsed file as it gives up one that does not parse: moved to `writes/dead/`, and logged `not copied (given up): <name> is not a copy`, with a forget's "its text stays on this brain until forgotten there by hand".
  - **The date** is beyond the ticket's list. A copy with no date that a fault kept was never given up, since its age read as no number, so it stopped the queue for good too.
  - **The names** are beyond it too (review passes 1 and 2). A name that is no string (`{"toString":1}`) threw wherever a template or `String()` met it: in the log's label, in the catch below, in a landed forget's note and its drop of `writes/dead/` copies.
  - **The tool** too (review pass 2). A misspelt one was held a week, its line telling the operator to mint a write key that was fine, while `--check` said the key was ok.
  - Every copy the hook has written since the fan-out began passes: each writer sets `at`, builds `args` as an object, and gives these names as strings or not at all. The review read the 1.7.3, 1.8.0 and 1.9.0 writers to check.
- **A throw from `postWrite`** keeps its copy, as a fault does, rather than ending the drain with an exception. It is marked `sent`, since the send may have reached the brain. Every throw that reaches it follows an answer, since nothing before the send can throw on parsed JSON. Its line says `the brain's answer could not be read (<error>)` and what to check: that the url is the brain's `/mcp`, and that its server and the hook are current. After a week it is given up like any other kept copy.
- **The README's "What is skipped" bullet** says what a copy is, and how to mend a file in `writes/dead/` and move it back. It also says what the throw's line means, and that the log names a file it cannot read by its file name. `metadata.json` is 1.10.1.

**Held.** The hook's suite [12]:
- **Fifteen queued files that parse but are no copy,** ahead of a valid capture:
  - `null`, `{}`, `[]`;
  - a capture with no `args`, one whose `args` is a list, an edit whose `args` is `null`;
  - a `tool` that is a number, and a misspelt `tool`;
  - no date, a date that does not parse, a date as a number;
  - a `client_key`, an `id` or a forget's `alt` that a template cannot print;
  - a held forget with no date.

  One drain moves the fifteen to `writes/dead/`, each logged `is not a copy` (the two forgets with their text-stays warning), with no error printed. It lands the capture behind them, its one call to the canary. The file names are padded, so the capture drains after all fifteen.
- **A capture the fake canary answers with `content` that is not a list,** which throws in `textOfResult`. The drain exits 1 and prints no error. The copy stays queued, marked `sent`, its line naming the answer and the url to check. The same copy queued eight days ago is given up after a week, into `writes/dead/`.
- **Mutants:** each of these fails the case that holds it:
  - no shape check;
  - no date in the shape, the date by presence alone, the date by `new Date()`;
  - `args` allowed to be a list, or `null`;
  - no name check, or one that leaves `alt` out;
  - any string `tool`;
  - a forget that is no copy logged without its warning;
  - no `try` around `postWrite`;
  - a throw not marked as maybe sent;
  - a throw given up at once.

  `args` allowed `null` survived the first run, which seeded no such file.

**Review pass 1.** A cold reader with a claims audit, and a run-it reviewer who drove real drains against a fake brain with about 25 malformed files and odd answers.
- **A copy whose name a template cannot print** passed `isCopy`. It threw in `opLabel`, once in `postWrite` and again in the catch that keeps a throw's copy, so it escaped the drain and stopped the queue for good. This pass printed such a name as JSON; pass 2 refused it in `isCopy` instead (caught: run-it).
- **The date rule was held only for a copy with no date:** a check for presence alone, or by `new Date()`, survived the suite (caught: mutant).
- **The README and the Changelog said a copy whose answer the hook cannot read is kept.** Only an answer that makes the hook throw is; one that reads as empty is taken as landed (below). The README also named a file that does not parse as logged `is not a copy` (caught: cold-read).
- **The throw case's check for no exception could not see one.** It looked for "TypeError", which the hook's printed error, `session-capture: <message>`, never carries (caught: cold-read).

**Review pass 2.** An operator walkthrough, run on real drains, `--check` and an upgrade from 1.10.0 with copies queued, and a reader of the seams with the drain's existing rules, as a decision table.
- **A forget whose `alt` a template cannot print** threw in its drop of `writes/dead/` copies once it landed, the third such name. So the rule moved into `isCopy`, before anything reads a name, and pass 1's JSON printing went (caught: run-it).
- **A misspelt `tool`** held the queue a week with the wrong advice (caught: walkthrough).
- **The throw's line blamed the hook** and showed JavaScript internals with no next step; it names the answer and what to check now (caught: walkthrough).
- **A forget that is no copy** was logged without its text-stays warning (caught: cold-read).
- **The test's "behind" capture** drained before most of the files it was behind, since `-15` sorts before `-2`. The names are padded now (caught: cold-read).
- **The README** did not say a file in `writes/dead/` can be mended and moved back, and said the log names each copy by its tool and id, which a file it cannot read is not. The Changelog gains an Upgrading line (caught: walkthrough).
- **Found sound:** no copy any hook version wrote goes to `writes/dead/`. A thrown copy and a forget behind it reach the same end as a fault and a forget. A file in `writes/dead/` that carries a thought's string name is still found by that thought's forget (caught: walkthrough, run-it).

**Left as it is.**
- **A copy dated in the future,** which only a hand edit or a clock set wrong makes, is never given up if kept: its age reads below a week. Refusing such a date would send to `writes/dead/` a copy the hook wrote under a clock later set back, which is worse.
- **An answer that reads without a throw but says nothing,** such as `{"result":{}}` or a `content` of `null`, is still taken as landed, as before this change. Only an answer that makes the hook throw is kept.
- **`--check`** says how many copies are queued and how old the oldest is, not which copy holds the queue or why. That is in the receiving brain's own log, as before this change.
