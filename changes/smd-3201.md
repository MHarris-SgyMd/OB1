## Changelog

Fork Checks' Portable server job is about 20 s faster: extensions/test-auth no longer waits past Bun's idle timeout, and test-rest's idle-timeout measurement overlaps its other sections. test-server now checks that the MCP server's stop waits for a tool call whose client has left (SMD-3201).

## FORK

Suites stop waiting where nothing waits on them (SMD-3201)

**What changed.**
- **extensions/test-auth's mcpReply probe** waits SSE_KEEPALIVE_MS + 600 ms, where it waited 13 s, and asserts one or more `: keepalive` frames. That proves mcpReply wraps its reply. Its sse.ts is a byte-for-byte copy, held by the same suite, of the file whose frames test-server [17] carries past Bun's last idle sweep at the default timing. Its header and query no longer say "slower than the idle timeout".
- **test-rest [16]'s two 14 s idle probes** start before section [1], and [16] awaits them. Their wait now overlaps every other section.
- **test-server [13d] holds the MCP server's stop to its count of tool calls.** A new child pair, the MCP server's entry over a REST core of its own with no store, takes a `search_thoughts` call whose client leaves while its embedding is held. SIGTERM lands with the call running, and the entry must exit 0 after the call is answered, its stop line counting the call. Before, the count could be dropped from the entry's drain with every suite passing; now this row fails, at 154 ms. The row runs on the call's events, not the clock: the provider stub says when the embedding arrives and answers no sooner than 1.5 s after it nor 500 ms after the signal.
- **Tidied:** test-server's tierProblem section, numbered [17] beside SMD-1864's, is [16a]. No assertion changed.

**Why.** Fork Checks runs 39707442097 and 39706512002 measured four waits of 13–14 s past Bun's idle timeout a run. test-rest's probes ran after every other section, with nothing else waiting on them.

**Superseded by main while this was in review.** SMD-2287 PR 6a (OB1 PR 491) deleted test-server's index pass and its `OB1_MCP_UNDER_TEST` switch, the ticket's item 4. With it went two of this change's own parts:
- a suite of its own, test-entry.ts, for test-server's sections that read no server under test, which saved time only while test-server ran twice;
- a [17] at the MCP server's timing knob for the second pass. With one pass left, [17] at the default timing is the only row holding SSE_KEEPALIVE_MS against Bun's idle sweep, and 6a kept it.

The stop row this change's review found missing is kept, moved from index.ts, which SMD-2287 PR 6b deletes, to the MCP server's entry.
