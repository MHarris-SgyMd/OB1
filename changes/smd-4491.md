## Changelog

The agent runner's setup makes the two things its probe stamp names: its own copy of the pinned Claude Code (`setup.ts claude`) and its own checkout (`setup.ts checkout`) (SMD-4491).
`setup.ts verify` and `live-run.ts --plan` say when the stamp's binary or install is gone or no longer as probed.

## Record

setup.ts makes the agent runner's copy of Claude Code and its install, and the stamp's state is said before a run is tried (SMD-4491)

**Problem.** A run starts only under a probe stamp that matches the pinned Claude Code binary and the checkout the probes ran from. Nothing made either path, and both were lost between 2026-11-13 and 2026-11-20 without a word. The binary lived in Claude Code's versions directory, which its updater prunes. The checkout was a worktree removed when its branch merged. SMD-4489 copied the binary by hand and left the stamp naming a working worktree.

**Change.**

- **`install.ts`**, new, hashed into no stamp:
  - `copyClaude` puts a binary at `<state>/claude/<version>`, 0500 in a 0700 directory, never through a link. The same bytes again are left alone. Other bytes under a version already there are refused, since a stamp may name the copy.
  - `makeInstall` makes `<state>/install`, a clone of the runner's bare repository on a detached HEAD, or moves the one there to a newer commit. It names each probed file the move changed. A checkout with changes of its own is refused.
  - `stampReport` reads the stamp and says, a line each: the binary gone or changed, or outside the runner's directory; the install gone, each probed file that differs, a run started from another checkout; a new Bun, git or macOS build. It changes nothing. `stampProblem` stays the check a run makes.
- **`setup.ts`:** `claude <path>` asks the binary its version, copies it and prints the three flags; `checkout [--commit <sha>]` brings the bare repository to the main checkout's `origin/main` and makes or moves the install; `verify` prints the stamp's report after the identities, and counts each bad line as not ready.
- **`live-run.ts --plan`** prints the same report. It covers the binary, the install and the host, not every check a run makes: the flags a run is given, and the stamp's own list of probes, are `stampProblem`'s alone.
- **`README.md`** gives the two commands in place of the hand copy. **`docs/agent-runner.md`** says the binary is beside the install, not in it.

**Decided here.** The install is a clone, not a git worktree: nothing ties it to a checkout a task works in, and no `git worktree` command of the maintainer's lists or removes it. The binary stays in `claude/`, where SMD-4489 put it and the present stamp names it, so a move of the install does not touch it. The design doc had it inside the install.

**Verify.**

- **The self-check.** `setup.ts --self-check` passes 56 cases, from 19: the version parse (2), the copy (6), the checkout made and moved and the command whole (18), the stamp's report (11). It runs git on fixtures, off macOS too.
- **Each rule has a case.** Sixteen mutants of `install.ts`, each dropping one rule, all fail the self-check (caught: mutant).
- **On the real repository.** `makeInstall` was run against the runner's bare repository into a scratch directory: made at `main~40` in 1 s, moved to `main` in 0.4 s, naming `probes.ts` and `session.ts` as changed, HEAD detached (caught: run-it).
- **On this machine.** `setup.ts claude` on the 2.1.329 binary answers "already at" with the stamp's checksum, and `setup.ts verify` prints three good stamp lines (caught: run-it).

**Review pass 1.**

- A first `checkout` whose commit the source didn't have left a clone with HEAD and no files. The next try read it as a checkout with changes of its own and refused, for good. A clone just made is removed when its checkout fails; one there before stays as it was. Without the removal, the case that tries again fails (caught: cold-read).
- The README's sweep from the install gave no `--main-checkout`. It defaults to the checkout the probes run from, so the probe that a session can't read the maintainer's checkout would have tested the install (caught: cold-read).
- `setup.ts checkout` had never run: the self-check and the rehearsal called `makeInstall`. The command is a function now, its paths the caller's, and the self-check runs it whole: made at the main checkout's `origin/main`, moved after main moved, put at a commit, refused with no config (caught: cold-read).
- `hostNow` was written out in `setup.ts` and in `live-run.ts`. It is `install.ts`'s (caught: cold-read).
- The record said `--plan` shows what `--execute` would be refused for. The report covers three things, as above (caught: cold-read).

**Review pass 2.**

- `--commit` took any commit the bare repository holds, and it holds the branches agent sessions wrote. The install is the code that holds a session. `makeInstall` now refuses a commit that is not an ancestor of main (caught: cold-read).
- After a move, the command said "a stamp made from it still holds" whenever that one move changed no probed file, though an earlier move might have gone unswept. It prints the stamp's report of the install, read from the files (caught: cold-read).
- The case "a checkout there before a failed move stays as it was" ran on a fixture an earlier case had edited, so it was refused for its changes and never reached its rule. It runs on a clean install now, and fails if the removal is made unconditional (caught: cold-read).
- A fetch the bare repository refuses says nothing under `--quiet`, so the error ended at its colon. It names the likely cause (caught: run-it).

**Not done here.** The install was not made on the maintainer's machine: `setup.ts checkout`, then the probe sweep from it, moves the stamp there, and is the maintainer's step after this merges. `live-run.ts --plan`'s new lines have no self-check case of their own; `live-run-check.ts` does not drive `main`.
