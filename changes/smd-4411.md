## Changelog

The session hook (1.10.0) reaches a forget's text on every brain this machine copies to (SMD-4411). A forget drops the thought's queued copies from every brain's queue: the first brain's own in a two-way fan-out, and that of a brain with no write key at the forget's run. Such a brain, once copied to, is held the forget in its queue, so it lands once a key is set, and `--check` warns of copies waiting so. `bun session-capture.mjs --copy-forget <id> [--brain <name>] [--client-key <uuid>]` copies a forget the hook never queued (its config unreadable at that run, or the hook not run), which the first brain refuses again as `FORGOTTEN`, so a repeat through the connector copies nothing. **Upgrading:** pull the hook's checkout; no settings change.

## Record

The session hook's forget reaches every brain's queue, and a missed forget can be copied again (SMD-4411)

SMD-1723 PR 3's review passes 7 and 9 named three ways a forget's text stays on a brain this machine copies to: a forget the hook never queued, which the first brain then refuses as `FORGOTTEN`; a brain with no write key at the forget's run, which got neither the forget nor the drop, so a capture queued for it earlier landed once its key came back; and the first brain's own queue in a two-way fan-out, never dropped.

**What changed** (`recipes/session-capture-hook/session-capture.mjs`, 1.10.0).
- **`queueForget`:** a forget's queueing, shared by the hook and the new command. It runs `dropCopiesOf` over every configured brain's state root: the targets', the first brain's own, and a keyless brain's. Then it queues the forget for each target. With `hold`, it also queues it for each brain with no write key whose `writes/` exists (it has been copied to before). There nothing drains it until a key is set, and then it lands behind whatever was sent first. The `sent`/`sending` rule is unchanged: a copy that may have reached the brain stays, and the forget behind it reaches it.
- **`fanOutPlan`:** a forget with no target brain goes on to `queueForget`, rather than being skipped before its drop. If no brain is held it either, the log says nothing was copied, as before.
- **`--copy-forget <id>`:** builds the op the hook would have (`confirm` the id, `detach_citations: true`, `--client-key` as its `alt`, `from: "--copy-forget"`) and queues it through `queueForget`. The targets are every brain with a write key, holding it for keyless ones; or `--brain`'s alone, holding nothing. It drains each queue in-process, printing every outcome under the brain's name. Exit 0 when every copy is done; 1 when one is kept, or the forget stays queued (said so); 2 for an id or key that is no uuid, an unknown brain, one with no write key, or a config where no brain has one.
- **`--check`:** for a brain with no write key whose queue holds copies, it warns how many wait, and how many are forgets.
- The README's fan-out section and `metadata.json` (1.10.0) say so.

**Held.** The hook's suite [12]:
- In a two-way fan-out (stable with a write key too), a forget through stable drops stable's own queued capture and edit of the thought, by its own key. A sent copy and another thought's copy are kept.
- A canary with no write key at the forget's run: its unsent copy of the thought is dropped, two forgets are held behind a sent copy, and `--check` warns of three copies, two of them forgets. Once the key is back, the drain sends the sent copy, then both forgets, and the thought is forgotten there.
- A keyless brain never copied to gets no `writes/`, and the log says nothing was copied.
- `--copy-forget`: an upper-case id is lower-cased, confirmed and detaching, and forgets the canary's copy; a repeat is skipped. `--brain canary --client-key` reaches a thought the canary knows by its own key alone. A queued unsent copy of the thought is dropped before the send. With the canary away the forget stays queued, said so, exit 1, and the next drain sends it. Six bad command lines exit 2 with nothing queued.
- Mutants, eleven, each failing the case that holds it:
  - the first brain's queue not dropped;
  - a keyless brain's queue not dropped;
  - no hold;
  - a hold without `writes/`;
  - the plan skipping a forget with no target;
  - no `--check` warning;
  - the command without `--client-key`'s `alt`, or without the drop;
  - no "stays queued";
  - no uuid check;
  - a keyless `--brain` taken.

**Not here.** The automatic route the ticket also named, a repeated forget's `FORGOTTEN` read as "forgotten here; copy it", needs the hook on `PostToolUseFailure`, which the fan-out does not install; the command is the explicit route. A forget held for a keyless brain waits there until a key is set; if one never is, it stays in `pending/`, and `--check` keeps warning.
