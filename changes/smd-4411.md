## Changelog

The session hook (1.10.0) reaches a forget's text on every brain this machine copies to (SMD-4411). A forget drops the thought's queued copies from every brain's queue: the first brain's own in a two-way fan-out, a brain's with no write key at the forget's run, and a queue a brain no longer in the config left on disk. A brain with no write key that has been copied to is held the forget, which lands once a key is set, and `--check` warns of copies waiting so. The first brain is queued the forget too, behind any copy it kept for having maybe landed, and a forget a brain answers as forgotten already is sent again by the thought's own `client_key`, which reaches a copy that landed there again. `bun session-capture.mjs --copy-forget <id> --from <brain> [--client-key <uuid>] [--brain <name>]` copies a forget the hook never queued: its config unreadable at that run, which the hook's log now names with this command, or the hook not run. The first brain refuses a repeat as `FORGOTTEN`, so a repeat through the connector copies nothing. A forget is not undone, so the command prints what it would do and does it only when run again with `--yes`, and it sends the `--from` brain nothing unless its queue carries a copy. **Upgrading:** pull the hook's checkout; no settings change. If a brain is without its write key now and you forgot thoughts meanwhile on 1.9.0, copies of them may have landed there before its key went, or wait in its queue, and 1.9.0 neither dropped them nor held a forget for them. Before setting the key back, run `--copy-forget <id> --from <brain> --brain <name> --yes` for each thought forgotten meanwhile, whatever `--check` says: it warns only of queued copies.

## Record

The session hook's forget reaches every brain's queue, and a missed forget can be copied again (SMD-4411)

SMD-1723 PR 3's review passes 7 and 9 named three ways a forget's text stays on a brain this machine copies to:
- a forget the hook never queued, which the first brain then refuses as `FORGOTTEN`;
- a brain with no write key at the forget's run, which got neither the forget nor the drop, so a capture queued for it earlier landed once its key came back;
- the first brain's own queue in a two-way fan-out, never dropped.

**What changed** (`recipes/session-capture-hook/session-capture.mjs`, 1.10.0).
- **`queueForget`:** a forget's queueing, shared by the hook and the new command.
  - Each brain it covers first loses its queued and given-up copies of the thought (`dropCopiesOf`). It covers every configured brain, or the `--brain` one alone, and with every brain also the queues on disk of brains no longer in the config.
  - Then the forget goes in: queued where the brain has a write key, held (`held: true`) where it has none but its `writes/` exists.
  - The brain the forget was made on is queued it too where it has a write key, whatever its queue shows, since a drain racing the drop can write a kept copy back after the drop read the queue. Where it has none, it is held the forget only if its queue still carries a copy. By hand (`sourceAlways` false) it is sent one only where its queue carries a copy, keyed or not, since the command cannot tell a forgotten id from a wrong one (review pass 2).
  - Each brain is its own step: one whose queue cannot be written is logged with the `--copy-forget` that redoes it, and the others still get theirs (review pass 2). A stray queue still carrying a copy that may have landed is logged with the command to run once its brain is back.
  - The `sent`/`sending` rule is unchanged: a copy that may have reached the brain stays, and the forget queued behind it reaches it.
- **`postWrite`:** a forget answered `FORGOTTEN` is sent again by the thought's own `client_key` (`alt`): a kept copy sent again ahead of it lands as a new thought under that key, which a forget by the brain's own id no longer reaches. `FORGOTTEN` then `NOT_FOUND` is done. A plain `NOT_FOUND` carries `notFound`.
- **`drainWrites`:** a held forget is re-dated at its first send, so a key set back after a week doesn't give it up at its first fault. A forget that lands removes the given-up copies of its thought from `writes/dead/`, where one sent again ahead of it and refused for good holds the text. Each outcome carries its file's name.
- **`fanOutPlan` and `fanOutHook`:** a forget with no target goes on to `queueForget`, and each queue it was queued into is drained, the first brain's included; a held one waits for a key.
- **`kickWriteDrains`:** at each session event, the forgets in a keyless brain's queue are marked held, so a forget queued while the brain had its key restarts its week too (review pass 2).
- **`--copy-forget <id> --from <brain>`:** builds the op the hook would have and queues it through `queueForget`. The op's `confirm` is the id, `detach_citations` is true, `--client-key` becomes its `alt`, and its `from` is `--copy-forget`. `--from`, the brain it was forgotten on, is required. `--brain` narrows it to one brain other than `--from`'s, which may be keyless if it has been copied to. It drains each queue in-process and prints every outcome under the brain's name.
  - Without `--yes` it prints, per brain, what it would do, and a warning to check the id and key against the forget's own reply, and does nothing (review pass 2: a wrong id pasted forgot a kept thought on every brain, exit 0, the command having built the `confirm` echo itself).
  - It says "nothing was forgotten" with what to try for a name that found nothing, unless a forget of that name landed ahead of it in the same drain. It says when a held forget, a kept one, one queued behind a running drain, or one a brain's queue could not take has not landed (all exit 1).
  - Exit 2 for an id or key that is no uuid, no `--from`, `--brain` the same as `--from`, an unknown brain, a `--brain` with no write key never copied to, or a config with no other brain to reach.
- **The hook's run whose config does not load:** it logs the forget it could not copy, with the `--copy-forget` (and `--client-key`) that copies it. An unreadable `key_file` or `write_key_file` is named by its setting and path.
- **`--check`:** for a brain with no write key whose queue holds copies, it warns how many wait and how many are forgets. It also names the `--copy-forget --brain` to run, before setting the key back, for a thought forgotten meanwhile on 1.9.0.
- **Review pass 3, what an operator sees:**
  - A brain whose queue cannot be written, and a stray queue's dropped or kept copy, are named in the first brain's log too, the one the README tails; a stray queue's own log is left alone. Under sync a lost forget is exit 1.
  - A forget whose name a forget landed for earlier in the same drain says "forgotten by the forget of it above", not "never copied … its text kept".
  - `--copy-forget`'s plan names a forget of the name already queued for a brain, and what this machine's logs record of a forget of it, or that they record none: the one check there is against a wrong id. Its "nothing was forgotten" line leads with `--client-key`, and says "forgotten already" last.
  - The commands the hook logs give the script's full path, and the lost forget's `--from` is named from the config where its JSON still reads.
- The README's fan-out section and `metadata.json` (1.10.0) say so.

**Not here.**
- **The automatic route the ticket also named,** a repeated forget's `FORGOTTEN` read as "forgotten here; copy it": it needs the hook on `PostToolUseFailure`, which the fan-out doesn't install. The command is the explicit route.
- **A brain out of the config at the forget's run:** its queue on disk loses its unsent copies, but it is held no forget; a sent copy there is logged with the `--copy-forget --brain` to run once it is back.
- **A wrong id or `--client-key` given by hand:** it forgets the thought it names on each brain the forget is sent to. Nothing here can check it (a brain answers whether a name is forgotten only by forgetting it); the plan before `--yes` and the `--from` rule bound it.
- **A forget held for weeks then landing on a thought captured again on purpose** under the same key: the forget wins, by design.
- **A forget queued while its brain had a key, the key then taken away:** it is marked held at the next event the hook captures on (a turn's Stop, a compaction, a session's end), so with none before the key is set back its week runs from when it was queued, and a first fault after a week gives it up (pass 2's adversary, its harness running no such event).
- **A held forget for a brain whose key is never set back:** it stays in `pending/`, and `--check` warns while the brain is in the config.
