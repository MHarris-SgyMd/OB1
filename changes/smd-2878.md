## Changelog

**Breaking:** `deploy/compose.tiers.yaml`, the three-brain stack (stable, canary and working as one compose project behind one proxy, each tier a path), is retired. Each brain is a stack of its own: a canary on its own port through `deploy/canary.sh`, the edge in front where one origin is wanted (`deploy/edge/`). **Upgrading:** a stack brought up with that file keeps running until you take it down with the file from a v1.x checkout (`docker compose -f deploy/compose.tiers.yaml down`, which keeps its volumes); stand each tier you still want as a brain of its own. The forwarder's script lost two lines of its header comment, so the next `up` recreates the forwarder (SMD-2878).

## FORK

`compose.tiers.yaml` and check 27 retired (SMD-2878)

**Decided** by the maintainer on 2026-10-22, while planning SMD-2287 PR 6, and recorded as the answer to `docs/one-brain-per-stack.md`'s open question 5:
- PR 6 deletes `server-portable/index.ts`, which served each tier's `/mcp` in the file. Keeping the file would have meant a `<tier>-mcp` per tier through check 27's generator.
- Nothing ran it: the dogfood Mac doesn't, and CI only rendered it.
- A canary already runs as its own instance (SMD-2874), with the edge in front where one origin is wanted (SMD-2876). A launcher of N instances, the ticket's other option, would have been a fourth shape to hold.
