## Changelog

`update_thought` settles the tags' lineage row when a re-tag comes out the same (migration 148, SMD-2298 PR 1a). When the envelope names the tags' recipe and the row the call would leave is not the row standing — there is none, it is marked stale, or it names another fingerprint or recipe — the row is recorded, with no event. So a row `rebuild_derived` marked stale clears, and a thought tagged before 061 gains its row, once the extractor runs on its text again. A re-send under the recipe the row already names, on its text, still records nothing, and a row whose metadata is SQL NULL (which takes no patch) is never settled. **Upgrading:** `bun db/migrate.ts`; nothing else changes until SMD-2298's re-tag worker (PR 1b) runs.
