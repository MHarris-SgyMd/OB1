## Changelog

`update_thought` settles the tags' lineage row when a re-tag comes out the same (migration 148, SMD-2298 PR 1a). When the envelope names the tags' recipe and the row the call would leave is not the row standing — there is none, it is marked stale, or it names another fingerprint or recipe — the row is recorded, with no event. So a row `rebuild_derived` marked stale clears, and a thought tagged before 061 gains its row, once the extractor runs on its text again. A re-send under the recipe the row already names, on its text, still records nothing, and a row whose metadata is SQL NULL (which takes no patch) is never settled. **Upgrading:** `bun db/migrate.ts`; nothing else changes until SMD-2298's re-tag worker (PR 1b) runs.

`bun db/retag.ts` re-tags every thought whose tags are behind its text (SMD-2298 PR 1b, SMD-3318 PR 3b): tagged with no tags row (before 061), its tags row marked stale or at other text, or a capture that fell back. It runs the capture's own extractor through the egress gate and writes through `update_thought` with the extractor's recipe, so the row is re-recorded and the mark cleared, with no event when the tags came out the same. It takes `--status`, `--dry-run`, `--limit`, `--retry-failed` and `--switch-key`, and records its key in `ob1_config.retag_key`; each run pools the backlog itself until `rebuild_derived` feeds it. thought-enrichment's `enrich-thoughts.mjs`, the last of that recipe's scripts on the SQL shim, is retired for it: its summary, importance and confidence fields are not the core's. **Upgrading:** run `bun db/retag.ts --url … --status` to see the backlog, then `bun db/retag.ts --url …`; a job that ran `enrich-thoughts.mjs` runs `db/retag.ts` instead.

## Record

The tags get a re-run path — migration 148 settles the tags' row when a re-tag comes out the same, and `db/retag.ts` re-tags the thoughts behind their text, retiring thought-enrichment's enrich-thoughts (SMD-2298 / 3318)

**What changed.** Decided 2026-11-19 (maintainer): a re-tag whose tags come out the same settles the row through `update_thought`, the one write path, not a settling function of its own and not left for a later PR. Migration 148 carries 099's `update_thought` whole, under its signature and with its grants, and widens one condition: beside 061's two cases (the event moved the metadata; the text moved), the tags' row is recorded when the row the call would leave is not the row standing. A new sentinel, `ob1:tags-row-settled-by-its-recipe`, names the rule. It is the first of SMD-2298's four PRs: 1b the worker (SMD-3318 PR 3b), 2 `rebuild_derived`'s metadata arm requeueing under the worker's key, 3 preflight's rows, 4 the sleep pass.

**Evidence.** test-schema [133]: 148's one form and sentinel, its DDL 099's verbatim but for the rule and the comment's sentence; a thought with no tags row re-tagged the same gets its row at its text and recipe, with no event and no `updated_at` moved; a re-send under the row's own recipe records nothing (`produced_at` unmoved); a row marked stale is settled; another recipe and another fingerprint are taken; a call naming no tags' recipe settles nothing; a patch that moves the tags records them with its event, as before; 099 re-applied leaves the mark, and the shipped file restored settles it; a re-apply a no-op. 061's section now holds the new rule for a no-move patch under another recipe. test-upgrade [20ck]: at 147 a same-tags re-tag records nothing; 148 refused by name without 063's `stale_since`; applied, it records and settles; a re-apply a no-op.

**PR 1b (SMD-3318 PR 3b): the worker.** `db/retag.ts` on the shared claim loop (`db/claim-loop.ts`), one worker by default, no `--follow` (PR 4's, on the shared follower). Its backlog uses preflight's predicates over the tags rows alone, the whole table: tagged with no row and no failure marker; the row marked or at other text; every capture that fell back, the egress refusal's marker included, since nothing else re-tags a thought the policy kept from the model. Each run enqueues the backlog not pooled and requeues a thought re-tagged before and due again; a failed row waits for `--retry-failed`, a claimed one is its holder's. A claimed thought no longer due is released with no call. The patch is `tagsOverExisting`'s less a null for a key the row does not hold (`metadata_extraction_failed: null` on every answer made each same-tags re-tag an event, which 148 settles with none). The answer's markers map to the claim workers' rule: the policy's refusal fails the thought naming the rule, nothing sent; a 408, 429 or 5xx is paused for, a timeout is the thought's, any other 4xx but 400 stops the run (exit 2); a 400 or an answer that is not tags fails the thought and writes nothing. The run refuses a brain before 148. `recipes/thought-enrichment/enrich-thoughts.mjs` and its `lib/` are removed; the recipe's README points at `db/retag.ts` and `db/backfill-metadata.ts`.

**Evidence, PR 1b.** test-live [29] (rewritten: it drove enrich-thoughts on the shim), against a stub chat endpoint: A's row marked by `rebuild_derived` after a raw move, M's marked by hand, S's at other text, B tagged with no row, E and F captures that fell back (F the egress refusal's marker); `--status` and `--dry-run` write nothing and call nothing; another recorded key refused without `--switch-key`; `--limit 1`; under a deny term one thought fails naming it and nothing of it is sent, the rest re-tagged and every row settled at its text under the recipe, B's tags, `updated_at` and audit events unmoved; a thought edited while its call is out meets `STALE_READ`, is requeued and re-tagged from its new text in the same run; a current thought and one with no tags never pooled; `--status` after, and a thought moved and marked again read as due again; `--retry-failed` revisits the refused one. Mutants, each caught: the write without the lineage envelope, a re-tagged thought due again not requeued, the backlog ignoring the mark, every null of `tagsOverExisting` sent, the worker's own egress check dropped. test-cli and test-connect cover the new entry point.

**Not taken.** Preflight does not read the new sentinel: a 099 re-applied by hand over 148 passes its edit-signature check, as 088 over 099 did (`--reapply` restores every file). `worker_status` and preflight do not name the `retag:` keys yet (PR 3). `tagsOverExisting` does not clear an old `type_raw` when a new answer has none (shared with board-sync; left as it is). `extractMetadata` writes its own stderr lines, past the run's Writer.
