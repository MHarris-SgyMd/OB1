## Changelog

`db/consolidate.ts` is an importable engine, as `db/migrate.ts` and `db/extract-entities.ts` became in 1.4.0: importing it does nothing until its `run(opts)` is called, the CLI's run returning its exit code, with its output going to the writer it is given; its review flags' rules are an exported pure function, and a pass's hard stop aborts the judge's call in hand (SMD-2304, SMD-2134).

## FORK

consolidate.ts is an engine: import it and call run() — PR 3 of 5 (SMD-2304 / 2134)

**What changed.** SMD-2134's fourth cut, PR 3; change 240 has PRs 1–2 (the
migrator and extract-entities.ts, the Writer, `PassStop`, `stopOnSignals`,
`sleepUnless`).
- `run(opts: ConsolidateOptions): Promise<number>` is the CLI's run: the
  pass, --status, --dry-run and the review modes (--list, --accept,
  --reject, --stale). Numbers (`k`, `minSim`, `minConfidence`, `stale` beside
  extract's) are held to the CLI's rules in its order and words, the lease
  pair between them; `env` is read for the judge model, endpoints, egress and
  key.
- The review flags' own rules — which combine, a --list word, a proposal id,
  the pass's note marker — are `reviewProblem`, an exported pure function the
  CLI (before it opens its client, where the script refused them) and run()
  both refuse through.
- A caller's `sql` needs workers + 1 connections and is refused as a
  reserved connection or a transaction's handle; a run or a decision with a
  worker key needs `url` beside it, naming the database `sql` is on (nothing
  checks that; a URL for another registers the agent there).
- The body moved into `consolidateWith` with extract's stop wiring: `onPass`
  where `process.on` was; a caller's AbortSignal a first stop, and aborted
  before the pass, a stop before its next write; the hard stop abandoning the
  thought in hand, waking a paused worker and a follower, 130. New over
  extract: the judge takes an AbortSignal, so the hard stop also aborts the
  call in hand and run() returns at once. A decision writes, and stops under
  an aborted signal as a run does ("stopped before the decision was
  written"); --list and --stale only read, and read on. A Writer's throw
  inside a thought's work (the "not settled" line of a raced stale row) is
  marked and rethrown, so run() rejects rather than record it as the
  thought's failure.
- `cli.ts`'s `numberProblem` judges an in-process number by value in the
  scanner's words, and readNumber builds its refusal through it (320 inputs
  measured the same as before); extract's numbers use it too, so in-process
  a string "3" is refused and 1e21 is "too large to read exactly".
  `lease.ts` holds STOPPED_EARLY for both engines. The Writer contract says
  its calls are synchronous: a promise it returns is not awaited.

**Behaviour against main's CLI.** Measured with timings and ids masked: the
same on 83 of 90 stub-judge cases (the rest races on both sides and an
unmasked timestamp), 47 edge cases, all 120 flag pairs and 447 of 462
pre-connection cases. The 15 are `?sslmode=bogus` beside flags that refuse
nothing: exit 1 with connect.ts's refusal and no banner, where main printed
the banner and exited on the egress gate — change 240's case for extract.
As there: the hard stop's grace writes nothing, a follower's first signal
exits at once, and a signal after run() settles ends the process by it; the
hard stop now races stopOnSignals' exit, and the exit wins, output main's.
