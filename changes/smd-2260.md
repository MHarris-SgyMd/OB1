## Changelog

`db/extract-entities.ts` writes a windowed thought's parsed windows when the model answers others with something other than JSON of the expected shape, and records it succeeded with a `partial:` caveat naming the windows left out, where one malformed window failed the whole thought; `--status` and the run's summary count and list these rows apart from a prefix, `--retry-partial` returns both kinds and the new `--retry-left-out` these alone (SMD-2260).

## FORK

A malformed window is left out of a windowed thought, not the thought — the windows that parsed are written and the claim names the rest (SMD-2260)

**What changed.** `server-portable/entities.ts`: `mergeExtractions` makes a
thought's answer malformed only when every window's was, where one malformed
window made it so; a malformed window's answer is empty, so the merge is the
parsed windows'. `extractEntities` names the windows left out on the answer's
`coverage` — `malformed`, their indices from 0, beside SMD-2240's
`{windows, of, cut}` — so `coverage` now means "less than the whole thought",
set for a prefix, for windows left out, or for both. `partialCaveat` writes
the second kind: `partial: 2 of 3 windows extracted; the model's answer for
window 2 was not JSON of the expected shape, and its text is not in the graph`,
or with a prefix `partial: 15 of 28 windows extracted; the model's answers for
windows 13, 15–21, 23 of the 24 sent were not JSON of the expected shape, and
the thought is over OB1_EXTRACT_MAX_WINDOWS (24); the rest of the thought is
not in the graph` — the count is of windows in the graph (a cut one that
parsed "the last of them in part"), the windows are numbered from 1, a run of
three or more as a range — and a prefix's caveat is unchanged, so the rows
SMD-2240 wrote read as they did. Every caveat naming windows left out holds
`MALFORMED_WINDOWS_MARK` and no prefix's does, which is how
`db/extract-entities.ts` tells the kinds apart: `partialRow` still selects
every partial row, `leftOutRow` those holding the mark — a row of both kinds
among them — and `prefixOnlyRow` the rest, so `--status` and the run's end read
`13 extracted (1 over a prefix only, 1 with windows left out as malformed), 1
failed` — with `, 1 of those also over the bound` when a row of both kinds is
among them, counted by `OVER_BOUND_MARK`, the knob every prefix's caveat names —
and list each kind under its own heading, and the run's summary counts both
(and the windows left out). `--retry-partial` returns every partial row and
the new `--retry-left-out` the `leftOutRow` ones alone; each, and its
`--dry-run`, counts what it returns by kind, and the run says what each gets —
a prefix, the bound in force, a row of both kinds included; a row with windows
left out, another reading by the model in force. The heading over the rows
with windows left out prints the command that re-reads them under another
model: `OB1_METADATA_MODEL=<model> … --job <this pool's key>
--retry-left-out --limit N`, since a changed model is another extraction key,
which the worker refuses without `--switch-key` and whose pool holds none of
these rows (SMD-2000's escalation), and the workers claim pending rows by
queue time, a returned row keeping its own, so `--limit` — with no other worker
of the pool running — keeps the larger model to the returned ones, and the
heading names a pending backlog that could be claimed in their place. Either
retry's message says what a fresh reading risks: a window timing out, or none
parsing, records the row failed, and the earlier reading's entities stay in
the graph until a later reading succeeds, since a failure writes nothing. A thought none of whose windows parsed, a one-window
thought's one answer included, is failed as malformed as before, a windowed
one's error naming its windows (in ranges, as the caveat does); the run's
closing line counts those as thoughts whose every answer was malformed. A run
that leaves partial rows and no failure exits 0, the rows listed on stdout, where
the same answers made a failed row on stderr and exit 1; `db/README.md` says so. `evals/eval-extract-windows.ts` marks a
row's windows left out and counts them per arm — its malformed column plus
those is the column before this change — and `evals/linear-corpus.ts`'s dump
reader warns of dump lines with windows left out, as of a prefix's.

**Why.** SMD-2240 made the worker record partial readings on purpose — a
thought over the bound keeps its prefix — while SMD-1879's rule, "a thought is
never recorded terminal on a partial reading", still failed a thought for one
malformed window, its parsed windows with it. After SMD-2240's re-run of the
2026-09-25 pool on the stable brain, three research papers still sat failed
with no mention: 15, 15 and 22 of their 24-window prefixes parsed, and the
windows the model could not answer were almost all reference lists. Escalating
them to a 27B model mangled the same windows, so a retry does not reach them;
keeping what parsed does.

**Retry.** A row with windows left out has its own flag because its lever
is not a prefix's: a prefix gains from a raised bound, windows left out from
a changed model (the answer budget is `db/config.mjs`'s, not a knob), and
`--retry-partial` under a larger model
would re-read every prefix to the place it already reached, up to the bound's
calls each for nothing (review pass 1). Either flag re-extracts a row as a
fresh reading — whole, or to the bound in force — and `record_thought_entities`
replaces its rows. `--retry-failed` no longer sees these rows; the summary's
and `--status`'s count of them, and `--retry-left-out`, replace it. The converse
flag, prefixes alone, is not added: `--retry-partial` after a raised bound
re-reads the rows with windows left out within it under the same model too —
a second chance at those windows, bounded by the rows' count, where a larger
model re-reading every prefix costs the bound's calls each.

**Not taken.** A column for the windows left out: 028's caveat already means
"the write stands, and this is what the worker could not do", so no
migration, as for SMD-2240. Bumping `ENTITY_PROMPT_VERSION`: the prompt and a
whole extraction's rules are unchanged. Naming a runaway among the windows
left out: the failed row's error names a stream-aborted runaway for SMD-2000's
escalation, and a window left out by one is named only as malformed — escalation
was measured not to rescue these papers' windows, and the per-window record in
`--dump` keeps `abortedMs`. Treating reference-list windows (a larger answer
budget, or skipping a bibliography): optional in the ticket and to be measured,
not assumed; it belongs with SMD-1961's long-document corpus. A floor on how
much must parse (a thought with 1 of 24 windows parsed is succeeded, and a run
that breaks most answers exits 0 on partial rows where it exited 1 on failed
ones): the ticket's rule is any window parsed, and the summary and `--status`
count these rows apart; left for the maintainer to set if wanted.
