## Changelog

`db/extract-entities.ts` writes a windowed thought's parsed windows when the model answers others with something other than JSON of the expected shape, and records it succeeded with a `partial:` caveat naming the windows left out, where one malformed window failed the whole thought; `--status` and the run's summary count and list these rows apart from a prefix, `--retry-partial` returns both kinds and the new `--retry-left-out` these alone (SMD-2260).

## FORK

A malformed window is left out of a windowed thought, not the thought — the windows that parsed are written and the claim names the rest (SMD-2260)

**What changed.** `server-portable/entities.ts`: `mergeExtractions` makes a
thought's answer malformed only when every window's was (a malformed window's
answer is empty, so the merge is the parsed windows'), and `extractEntities`
names the windows left out on `coverage.malformed`, indices from 0 — so
`coverage` means "less than the whole thought": a prefix, windows left out, or
both. `partialCaveat` writes the second kind — `partial: 2 of 3 windows
extracted; the model's answer for window 2 was not JSON of the expected shape,
and its text is not in the graph`, or with a prefix `partial: 15 of 28 windows
extracted; the model's answers for windows 13, 15–21, 23 of the 24 sent were not
JSON of the expected shape, and the thought is over OB1_EXTRACT_MAX_WINDOWS
(24); the rest of the thought is not in the graph` — counting windows in the
graph (a cut one that parsed "the last of them in part"), numbering from 1, runs
of three or more as ranges; a prefix's caveat is unchanged, so SMD-2240's rows
read as they did. Every caveat naming windows left out holds
`MALFORMED_WINDOWS_MARK` and every prefix's `OVER_BOUND_MARK`, the knob it
names. `db/extract-entities.ts` partitions by them: `leftOutRow` (a row of both
kinds among them) and `prefixOnlyRow`, so `--status` and the run's end read `13
extracted (1 over a prefix only, 1 with windows left out as malformed), 1
failed`, with `, 1 of those also over the bound` when a row is both, and list
each kind under its own heading. `--retry-partial` returns every partial row and
the new `--retry-left-out` the `leftOutRow` ones; each, and its `--dry-run`,
counts by kind, and the run says what each gets and that a reading which fails
outright (a window timing out, none parsing) records the row failed, the
earlier reading's entities left in the graph until a later one succeeds. The
left-out heading prints the escalation that works — `OB1_METADATA_MODEL=<model>
… --job <this pool's key> --retry-left-out --limit N`, with no other worker of
the pool running — since a changed model is another key, refused without
`--switch-key` and empty with it (`OB1_EXTRACT_ESCALATE_MODEL`, SMD-2000,
remakes only a call that ran away, not a window answered in prose), and the workers claim by
queue time, so it names a pending backlog that could take the returned rows'
place. A thought none of whose windows parsed, a one-window thought's one answer
included, is failed as malformed as before, its windows named in ranges. A run
that leaves partial rows and no failure exits 0, the rows on stdout, where the
same answers made a failed row and exit 1; `db/README.md` says so. The evals
mark and count windows left out — `eval-extract-windows.ts`'s malformed column
plus those is the column before — and `linear-corpus.ts`'s reader warns of them.

**Why.** SMD-2240 made the worker record partial readings on purpose — a
thought over the bound keeps its prefix — while SMD-1879's rule, "a thought is
never recorded terminal on a partial reading", still failed a thought for one
malformed window, its parsed windows with it. After SMD-2240's re-run of the
2026-09-25 pool on the stable brain, three research papers still sat failed
with no mention: 15, 15 and 22 of their 24-window prefixes parsed, and the
windows the model could not answer were almost all reference lists. Escalating
them to a 27B model mangled the same windows, so a retry does not reach them;
keeping what parsed does.

**Retry.** A row with windows left out has its own flag because its lever is
not a prefix's: a raised bound helps a prefix, a changed model helps windows
left out (the answer budget is `db/config.mjs`'s, not a knob), and
`--retry-partial` under a larger model would re-read every prefix to where it
already reached, up to the bound's calls each (review pass 1). `--retry-failed`
no longer sees these rows; the counts and `--retry-left-out` replace it. No
prefix-only flag: `--retry-partial` after a raised bound re-reads the rows with
windows left out too, under the same model — bounded by their count.

**Held.** `server-portable/test-local-provider.ts` [10]: a four-window thought
two of whose windows the stub answers in prose is the other two's answer, not
malformed, its coverage `{windows: 4, of: 4, cut: false, malformed: [2, 3]}`
and its caveat exact; every window in prose, and a one-window thought's prose,
are malformed with no coverage; a prefix of three with its second window in
prose carries both on one coverage and says both; the stable pool's windows
read `13, 15–21, 23` and `23, 24`; a cut window left out says the cut, and one
that parsed is counted in part; each mark is in the caveats of its kind and no
other's (137 → 148). `server-portable/test-thoughts.ts`: one malformed window
beside a parsed one merges to the parsed one's answer, and two malformed to a
malformed one (the first had held the old rule). `db/test-live.ts` [10], under
a bound of two: a two-window thought whose second window the stub answers in
prose is succeeded with that window named, the other's entities and edge in
the graph and its entity not; a three-window one so is succeeded naming the
window and the bound; a two-window thought in prose throughout is failed,
naming both windows; the run's summary and `--status` count and list the two
kinds apart beside a prefix, the row of both among the windows left out; both
`--dry-run`s count their rows, one of both kinds also over the bound;
`--retry-left-out`, run as `--status` prints it — another model, `--job`,
`--limit` — with a capture pending, takes the two rows and not the prefix or
the capture, its calls naming the other model, the recorded key unchanged,
saying one is a prefix too, clears their caveats and lands their windows'
entities, and `--retry-partial` then takes the prefix (754 → 765). The comment
above the SMD-2240 fixture said every window after the first carries
the opening line as its header; the header is off by default
(`EXTRACT_WINDOW_HEADER`), so it now says each key reaches only its own window.

**Measured after.** Through the worker against a stub model, every flag an
operator would type: the first run under a bound of two reads `3 extracted (1
over a prefix only — …; 2 with 2 window(s) left out, …), 0 failed`; `--status`
lists each kind under its heading; `--dry-run` with both retry flags returns
all three rows, `--retry-left-out` with `--retry-failed` the two; the printed
escalation, run as printed beside a pending capture, re-reads the two rows in
five calls under the other model and leaves the capture pending.
`extractEntities` fuzzed end to end over 250 random thoughts of 1 to 9 windows
under random bounds, a random third of the windows answered in prose — 151
with windows left out, 52 of both kinds, 18 with none parsed — and
`partialCaveat` over 20,000 random coverages read back to their counts, window
lists and number: no invariant broken. On the tree merged with `main` at
8e371694 every suite is green, `test-live` at 777. 25 mutants, every one
killed.

**Not taken.** A column for the windows left out: 028's caveat already means
"the write stands, and this is what the worker could not do", so no
migration, as for SMD-2240. Bumping `ENTITY_PROMPT_VERSION`: the prompt and a
whole extraction's rules are unchanged. Naming a runaway among the windows
left out: the failed row's error names a stream-aborted runaway for SMD-2000's
escalation, and a window left out by one is named only as malformed — escalation
was measured not to rescue these papers' windows, and the per-window record in
`--dump` keeps `abortedMs`. Treating reference-list windows (a larger answer
budget, or skipping a bibliography): optional in the ticket and to be measured,
not assumed; it belongs with SMD-1961's long-document corpus. A floor on how
much must parse (a thought with 1 of 24 windows parsed is succeeded, and a run
that breaks most answers exits 0 on partial rows where it exited 1 on failed
ones): the ticket's rule is any window parsed, and the summary and `--status`
count these rows apart; measured and decided on SMD-2266.
