## Changelog

`thought_changes`, a read-scoped MCP tool over `thought_audit`: what changed since a time or a cursor — every capture, edit and deletion, oldest first, who made it, the thought's id, what moved and whether it now supersedes another thought — paged by a keyset cursor that never repeats a row; migration 049 adds the SQL function both stores call (SMD-1296).

## FORK

A resuming agent asks what changed since it was last here — `thought_changes` over the audit log, migration 049 (SMD-1296)

**What changed.** Migration 049 adds `thought_changes(p_since, p_after, p_agent,
p_not_agent, p_actions, p_limit)`: one page of `thought_audit` (008), oldest first,
from a time (rows at or after it) or a cursor (the audit id a page ended with; rows
strictly after it in `(created_at, id)`), or with neither the newest `p_limit` rows
still oldest first. The page is chosen first — ids by the bounds and the filters over
008's `created_at` index — then rendered once: at most 240 characters of the text the
row is about (a capture's current content, gone with a deleted thought; an update's
new content when it moved; a delete's previous content), an update's diff keys and the
metadata keys whose value moved, the `supersedes` pointer before and after for every
action (a capture that superseded, an update that set or cleared it — 025's
`ON DELETE SET NULL` included — a delete's prior pointer), whether `derived_from`
moved, who (`actor_name`, 046's `actor_kind` and `origin`), and whether the thought
still exists. A cursor naming no row, an unknown action and a time beside a cursor
are refused by name. Both stores call it (`store-sql.ts` direct, `store-postgrest.ts`
over rpc) through `ThoughtStore.listChanges`, and one `normaliseChange` maps the row.
The tool, `thought_changes` (`server-portable/tools.ts`, read scope, `readOnlyHint`),
takes `since` — an ISO-8601 time or the cursor the previous reply ended with, decided
before any call and refused naming both forms when neither — `others_only` (the
server passes the caller's key name as `p_not_agent`, so "everyone but me" needs no
name; a row with no actor stays), `agent`, `actions` and `limit` (1–200; it asks for
one more to say whether more follow). Every entry's first line carries `ID:` (SMD-1248)
and the reply ends with `Cursor: <audit id>`. `ROLE_GRANTS.server` gains
`thought_audit SELECT` (049), documented in the grants table; the tool names the grant
when a role lacks it and the migration when the function is missing.

**Why.** 008 records every mutation and no tool read it. An agent back after a break
could `list_thoughts` by date — new rows, not edits or deletions, and never who — so
every resumed session re-searched. The board sync (SMD-1954) now writes dozens of
status changes a day into the dogfood brain; the first question a second session asks
is what the other keys did.

**Held.** test-schema [45] under PGlite: seven rows from two keys and a raw write in
order, the boundary of a page falling on two rows that share a `created_at` (one
transaction: the delete and the pointer it cleared) with the pages joined equal to the
whole, `p_since` at-or-after, the tail, the clamp, the three refusals, the rendering
of each action, a planted row with a non-object metadata side and non-uuid pointers.
test-audit [8]–[10] over MCP with two keys: the importer captures, edits, supersedes
and deletes; the laptop reads five entries in order, each `by importer (agent)` with
its `ID:`, the deleted capture marked, the cleared pointer reported; `others_only`
from each side; `agent`; `actions`; three pages of two joined equal to one call; a
`since` that is neither form refused before any call; a ghost cursor refused by the
function. test-store-sql and test-store-postgrest [14]: the store method on each
path, the `text[]` binding of `actions`. test-upgrade [20d] drives both guards (no
008; 008 without 046). test-auth [7] and test-server [9]/[10] read the manifest, so
the read key sees the tool and it is annotated read-only.

**Not taken.** A sequence column for true same-transaction order and for the
in-flight-writer window above: `created_at` is transaction-fixed and the id random,
so two rows one transaction wrote read in id order; every MCP call is its own
transaction, and SMD-1726 (in flight) adds `thought_audit.seq` — when it lands, the
`ORDER BY` can prefer it. A hold-back margin on the cursor walk for that window:
one write's duration on this server; a reader who must not miss it re-reads from a time. A composite
`(created_at, id)` index: 008's btree serves the range and the tie is a filter over
the few rows sharing a timestamp; revisit if the log outgrows it. A server-side
"last seen per agent": the caller keeps its cursor (SMD-950's recall-trace territory).
Logging the call to `query_log`: the read tools that list do not, and this is one.

**Upstream status.** Not sent — upstream has no audit log to read; the function, the
store method and the tool are the fork's.
