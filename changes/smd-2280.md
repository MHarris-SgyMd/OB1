## Changelog

The stack serves an operator GUI at `/dashboard`: `dashboard/`, a SvelteKit server and a client of the REST core, run as compose's `app` service from the server image. Sign in with a read or write access key to see the brain's counts and newest thoughts, browse every thought a page at a time with filters, search by meaning or exact text, and see its status and any thought; the key stays on the server (SMD-2280).

## FORK

**What changed in PR 1.**
- **`dashboard/`** (new), the GUI SMD-2282's decision 2 names: SvelteKit with `paths.base` `/dashboard` (absolute paths), built by adapter-node into one server with every package bundled.
  - `serve.ts` starts it on 8000, its body limit 64 kB. A stop drains within `OB1_STOP_GRACE` less 2 s (a bad value warned of), then exits at its own deadline, a second later and inside the grace, should a request outlive the drain; a second signal exits at once. It sets the origin SvelteKit judges a form's post and the cookie's Secure by: `OB1_PUBLIC_ORIGIN` when it is sound (`server-portable/oauth-edge.ts`'s rule; an unsound one is warned of), else each request's `Host` with the proxy's `X-Forwarded-Proto`. A bad `OB1_REST_URL` exits 2.
  - Every page is a server-side load through `rest-client/` under the visitor's own key, with no forwarder key and no browser-side API or proxy:
    - `/` reads `thought_stats` and `list_thoughts` (the ten newest, sent to the browser as their first lines alone);
    - `/status` reads `brain_info` and lays out the core's own rows, `brainInfoRows` (split out of `renderBrainInfo`, whose text is unchanged), so every judgement is worded as the tool words it;
    - `/thoughts/<id>` reads `fetch`, server-rendered with no client script (the overview's links to it reload), and shows the ingested notice (`ingestedNotice`, moved beside the trust words in `core/filter.ts`, `render.ts` re-exporting it);
    - `/health` asks nothing.
  - A 401 from the core ends the session; any other refusal is the page's error with the core's status and code.
  - **Sign-in** is by key: `GET /v1/whoami` must name `thought_stats`, so a capture-only key gets a 403. Key sign-in is off while `COMPOSE_PROFILES` names `auth` (ADR decision 16).
  - **The session is server-side** (`session.ts`): the cookie (`Path=/dashboard`, httpOnly, Lax, a day, Secure on https) carries 32 random bytes. The key and its scope live in a map capped at 1,000 sessions, 20 per key. Sign-out deletes the entry, and so does a sign-in over it.
  - `hooks.server.ts` walls every path but `/signin` and `/health`. Pages are `no-store`, `DENY`-framed and `Referrer-Policy: same-origin`, with a CSP of `self` plus SvelteKit's inline script by nonce, and no web font. Times are UTC, labelled. The overview's thought links are not preloaded (each `fetch` is a click-through). `+error.svelte` keeps the layout.
  - The nav links to Grafana where an overlay reaches it (`GRAFANA_LINK`, else `GRAFANA_ROUTE`).
  - Also `smoke.ts` and `README.md`.
- **`server-portable/Dockerfile`:** a `dashboard-build` stage (the REST client's and the GUI's installs, `vite build`) on the builder's own platform (`--platform=$BUILDPLATFORM`): it runs JavaScript, which the release's QEMU cross-build crashed and hung on, and its output is the same on either architecture. **For SMD-2287 PR 6**, which retires `server`: `app` runs the image `server` builds. `release.yml` now holds `app` against `mcp`'s image, not `server`'s; the rest that names both are fork-checks.yml's exact service list, pinned-Bun loop, daemon-restart list and the configured step's `server mcp app`, canary.sh's `server --build` and failure stop, and check 28's `APP_SERVICE` image name if the image is renamed.

**Not taken.**
- **The sealed-cookie session** of the SvelteKit dashboard: the ADR keeps tokens server-side, and the Verify line asks that no cookie hold a key. The cost is that a restart signs everyone out.
- **An image of its own:** a release install has no checkout to build one from. The server image already carries the MCP server the same way.
- **A browser-side API route** (the old `/api/mcp` proxy): every page loads on the server, so the analysis's open question (an open proxy or a per-screen allow-list) does not arise.
- **`dashboard/` in check 18's tsc list:** it is checked by svelte-check, which loads SvelteKit's generated types.
- **A password manager kept off the key field** (`autocomplete="current-password"` stays): it is the right store for a secret the visitor pastes.
- **Hiding the Grafana link while its profile is off:** the operator named the overlay, and the route's 404 says the rest.
- **A rate limit on wrong-key sign-ins:** each is one whoami on the core, as each refused `/mcp` call is; abuse controls on the public edge are SMD-2309's.
- **A shape guard on the core's answers:** a field missing (an `app` and an `api` of two builds) renders SvelteKit's bare 500, which says nothing of the brain.
- **PR 2a: a browse page count or "page N of M":** a keyset has no position; a count is a second read per page (SMD-2994's filtered counts).
- **PR 2a: a typed filter applied on leaving its field** (Next's #131): the submit raced the click that left it — Next dropped the filter, and a thought's link landed on the list in WebKit — and Enter after it read twice.
- **PR 2a: search's facts when nothing matched** (the literals' counts, why each was not found): the MCP tool's text says them; the page says only that nothing matched.
- **A loopback sign-in beside a public origin:** the origin is the one every redirect names (ADR decision 16); the loopback door is PR 4's break-glass listener.

**Follow-ups.** SMD-3212: a GUI open of a thought is logged as a click-through, since the core's `fetch` has no read that is not one; that read also carries the thought's supersession, which the thought page cannot show from `fetch`.
