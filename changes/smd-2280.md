## Changelog

The stack serves an operator GUI at `/dashboard`: `dashboard/`, a SvelteKit server and a client of the REST core, run as compose's `app` service from the server image. Sign in with a read or write access key to see the brain's counts and newest thoughts, browse every thought a page at a time with filters, search by meaning or exact text, read what changed, the supersession proposals, the worker queue and the query log, see its status and any thought, and use the pages of the plugins `OB1_PLUGINS` turns on (the example plugin's Notes); the key stays on the server (SMD-2280).

## FORK

**What changed in PR 1.**
- **`dashboard/`** (new), the GUI SMD-2282's decision 2 names: SvelteKit with `paths.base` `/dashboard` (absolute paths), built by adapter-node into one server with every package bundled.
  - `serve.ts` starts it on 8000, its body limit 64 kB. A stop drains within `OB1_STOP_GRACE` less 2 s (a bad value warned of), then exits at its own deadline, a second later and inside the grace, should a request outlive the drain; a second signal exits at once. It sets the origin SvelteKit judges a form's post and the cookie's Secure by: `OB1_PUBLIC_ORIGIN` when it is sound (`server-portable/oauth-edge.ts`'s rule; an unsound one is warned of), else each request's `Host` with the proxy's `X-Forwarded-Proto`. A bad `OB1_REST_URL` exits 2.
  - Every page is a server-side load through `rest-client/` under the visitor's own key, with no forwarder key and no browser-side API or proxy: `/` reads `thought_stats` and `list_thoughts` (the ten newest, sent to the browser as their first lines alone); `/status` reads `brain_info` and lays out the core's own rows, `brainInfoRows` (split out of `renderBrainInfo`, whose text is unchanged), so every judgement is worded as the tool words it; `/thoughts/<id>` reads `fetch`, server-rendered with no client script (the overview's links to it reload), and shows the ingested notice (`ingestedNotice`, moved beside the trust words in `core/filter.ts`, `render.ts` re-exporting it); `/health` asks nothing.
  - A 401 from the core ends the session; any other refusal is the page's error with the core's status and code.
  - **Sign-in** is by key: `GET /v1/whoami` must name `thought_stats`, so a capture-only key gets a 403. Key sign-in is off while `COMPOSE_PROFILES` names `auth` (ADR decision 16).
  - **The session is server-side** (`session.ts`): the cookie (`Path=/dashboard`, httpOnly, Lax, a day, Secure on https) carries 32 random bytes. The key and its scope live in a map capped at 1,000 sessions, 20 per key. Sign-out deletes the entry, and so does a sign-in over it.
  - `hooks.server.ts` walls every path but `/signin` and `/health`. Pages are `no-store`, `DENY`-framed and `Referrer-Policy: same-origin`, with a CSP of `self` plus SvelteKit's inline script by nonce, and no web font. Times are UTC, labelled. The overview's thought links are not preloaded (each `fetch` is a click-through). `+error.svelte` keeps the layout.
  - The nav links to Grafana where an overlay reaches it (`GRAFANA_LINK`, else `GRAFANA_ROUTE`). Also `smoke.ts` and `README.md`.
- **`server-portable/Dockerfile`:** a `dashboard-build` stage (the REST client's and the GUI's installs, `vite build`) on the builder's own platform (`--platform=$BUILDPLATFORM`): it runs JavaScript, which the release's QEMU cross-build crashed and hung on, and its output is the same on either architecture. The image gets `dashboard/build`, `serve.ts` and `package.json`. `.dockerignore` keeps the GUI's build output and smoke out. `release.yml`'s job gets a 60-minute timeout.
- **`deploy/compose.yaml`:** the `app` service (the server image, `bun --no-install ../dashboard/serve.ts`, mesh alone as `app.ob1.internal`, read-only with a tmpfs `/tmp`, no capability, `no-new-privileges`, a healthcheck on `/dashboard/health`); the `dashboard` router (priority 30, path kept), and the proxy waits on `app`.
- **The Grafana overlays** each set one key on `app`: `compose.grafana-port.yaml` `GRAFANA_LINK` (`/grafana/` on its loopback origin, Grafana's root URL whenever it is named, so it wins whatever the `-f` order), `compose.grafana-public.yaml` `GRAFANA_ROUTE` (`/grafana/`).
- **`deploy/canary.sh`** recreates `app` after `mcp`, on the build just made, stops it with the servers when the canary does not come up, and hands every compose call an empty `OB1_PUBLIC_ORIGIN` (in `CANARY_SET`, so the canary's file never carries stable's): stable's origin would have the canary's GUI refuse every sign-in as cross-site.
- **`scripts/release-artifacts.ts`:** the release overlay pins `app` to the release's server image; `release.yml` holds it.
- **`scripts/check-fork-consistency.ts`:** check 28's `PROXY_ROUTE_TABLE`, `PROXY_SERVICE` (the wait), `CONFINEMENT`, `SERVICE_NETWORKS` and `OVERLAYS` learn `app`, `APP_SERVICE` holds it whole as `MCP_SERVICE` holds `mcp`, and `GRAFANA_APP_ENV` holds the overlays' one key each by value; check 32's `RESTART_POLICIES` holds `unless-stopped`.
- **`rest-client/index.ts`** exports `DEFAULT_REST_URL`, which `mcp-server/index.ts` defined; both servers read it.
- **`.github/workflows/fork-checks.yml`:** the portable-server job installs and svelte-checks `dashboard/`. The full-stack job captures one thought over `/mcp` and drives `smoke.ts --require-thought` through the proxy right after `smoke.sh`, on the stack configured for no authorization server; the next step recreates `app` configured for one and holds key sign-in off (no key field; the write key's post refused 403 by the GUI's own words, no cookie). Its exact service list, mesh membership, pinned-Bun and daemon-restart checks name `app`; the release overlay, in both modes, may leave no service on a local build's image. `declared()` names the overlays' two keys; `release.yml`'s paths name `dashboard/**`.
- **Docs:** `SETUP.md` (eight services, step 5 "Open the dashboard", with where to sign in once a public origin is set), `deploy/README.md` (the service, its reach, the `/dashboard` route, the upgrade, restart and canary lines), `CONTRIBUTING.md` (`dashboard/` asks a fragment) and the ADR's As built line.
