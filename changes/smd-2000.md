## Changelog

`OB1_EXTRACT_ESCALATE_MODEL` remakes a runaway entity-extraction call once on a larger local model with no penalty, instead of the penalised same-model retry (SMD-2000); unset, the retry is unchanged. The row's pass key stays the first model's and the dump line records `escalated: <model>`; the worker banner, preflight's `extraction window` row and `--deep` probe name the model, and `evals/eval-extract-windows.ts` gains a `w1200e` arm.

## FORK

A runaway extraction call escalates to a larger local model instead of the penalised retry — one knob, the escalation model, spent only where the small model failed (SMD-2000)

**What changed.** The runaway retry (`ExtractWindowing.retryRunaway`) gains an
escalation target. `ExtractWindowing.escalateModel`, from
`EmbedConfig.extractEscalateModel` (`OB1_EXTRACT_ESCALATE_MODEL`, else `""`),
names a larger model a call that ran to its answer budget — or was aborted on
the stream as a runaway — is remade once on, with the same messages and **no**
`frequency_penalty`, rather than once more on `metadataModel` under
`RUNAWAY_PENALTY`. `windowingFor` sets it only when reasoning is off (there is a
runaway only under a budget) and it differs from `metadataModel` (a same-model
unpenalised retry is strictly weaker than the penalised one it would replace).
`extractOnce`'s second-call argument became `{ penalty?, model? }`, so the
retry dials the escalation model unpenalised or the metadata model under the
penalty; `extractCall` branches on `escalateModel` and returns `escalated: <model>`
beside `retried: true` (a second call was made either way, so `callsOf` counts
it unchanged). The merged `Extraction` and each `ExtractionWindow` carry
`escalated`. `describeExtractWindow` — the one sentence the worker banner and
preflight's `extraction window` row both print — names the model and says the
retry is unpenalised; preflight's `--deep` probes it for JSON mode as a third
row when it is a third distinct model. `db/extract-entities.ts` counts escalated
thoughts apart from penalised retries, names the model in the summary line and
the failed-row note (an operator sorting the failed rows for a larger model is
told the larger model already ran), and writes `escalated: <model>` on the
`--dump` line in place of `retried: true`. `evals/eval-extract-windows.ts` gains
the `w1200e` arm (`--escalate <model>` or `OB1_EXTRACT_ESCALATE_MODEL`), refused
by name when no model is given so it never measures as a same-model retry.

**Why.** The penalised retry reaches the thoughts one call cannot finish, but at
a cost measured twice (`evals/README.md`): the penalty taxes the JSON's repeated
keys as it taxes the loop, so a rescued answer is thinner (12.0 mentions against
17.1 for windows that converged first time), and some thoughts run away twice
under every budget and window size. `qwen3.8:27b` never looped on the thoughts
`qwen2.5:7b` could not finish — a live drain of the p2 backlog on 2026-09-25
left nine hard failures, eight of them runaways, and escalating exactly those to
the 27B extracted every one, 0 runaways, and dropped no relation for an unlisted
entity where the 7B passes dropped hundreds. A whole-pass 27B run is no faster
than the 7B's (44–47 s a call against 33), so it is not the default model; the
escalation spends the large model only where the small one has proven it cannot
do the work.

**Provenance — Option A (the pass key stays the first model's).** An escalated
thought's rows keep the pass key of the first model (`extract:qwen2.5:7b@p2`):
the pass is the small model's and the escalation is its retry mechanism, so the
pool, the enqueue trigger and idempotency are untouched. Which model actually
answered is recorded on the dump line, `escalated: <model>`. Durable per-row
model lineage — `record_thought_entities`'s `extraction_key` naming the
escalation model per row — is **SMD-1731's** (Phase 1b, a `derivations` table
with prompt hash + model + version for every derived artifact), not this
ticket's: `thought_entities` and `ob1_entity_edges` rows have no free-form
metadata jsonb, so their only per-row provenance slot is the pool key itself, and
honest per-row attribution needs that table rather than an overload of the key.
This mirrors the fork's existing precedent (021's `embedding_model` column for
vectors, SMD-1254's `metadata.extractor_model` key for tags): the producing
model is provenance in a dedicated field, never the operational pool key. The
decision is grounded in a research pass captured to the brain — FrugalGPT
(2305.05176), AutoMix (2310.12963) and "Is Escalation Worth It?" (2605.06350),
ingested under `arxiv:llm-cascades` — where a cascade treats the small model's
attempt as the pass and escalation as a deferral the cascade owns.

**Held.** `server-portable/test-local-provider.ts` [10]: with the knob set a
runaway's second call names the escalation model, carries no penalty, and the
answer's `escalated` names the model; a converged first answer is never escalated
(one call on the metadata model — the mutant the ticket names); an escalation
model equal to the metadata model is ignored. The existing unset case is
unchanged (the retry is the penalised same-model one). `server-portable`, `db`
and `evals` typecheck; `test-local-provider` 143 assertions pass.

**Not taken.** A per-call timeout for the slower model: the worker's `--timeout`
is 300 s (the passes ran at 120), and the 27B's 44–47 s sits well inside, so the
escalation reuses the same deadline. A separate escalation budget/penalty knob:
the ticket's shape is the same messages, no penalty; the budget bounds the large
model as it does the small one. The failed-row note names an escalation that
still failed only when the runaway was stream-aborted (it reads `abortedParts`,
which need `abortedMs`) — pass 1 LOW: this mirrors the pre-existing penalised-retry
note exactly, and the shipped config always streams (`EXTRACT_STREAM_ABORT`), so
the note fires in practice; making it escalation-aware in the non-streaming path
is a widening of a pre-existing gap, left for whoever revisits that note.

**Measurement (operator).** The `w1200e` arm against a live 27B and SMD-1961's
labelled corpus is the operator's — ~45 s a call, ~1 h for a brain's ~80
runaways, and the 27B beside the 4B embedder is 28 GB with
`OLLAMA_MAX_LOADED_MODELS=2` (a capture mid-pass can evict the embedder and pay
its reload). The precision of escalated answers against penalised ones is the
one number pending SMD-1961's corpus.

**Follow-ups.** SMD-1731 carries the durable per-row lineage; SMD-2016 (the
Jev-class runaway router — predict which thoughts loop and route them first) and
SMD-2045 (a larger per-model window for the 27B) build on this escalation path.
