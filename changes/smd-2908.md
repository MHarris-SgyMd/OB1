## Changelog

No call that sends a thought's text, to a model provider, Telegram or Linear, follows a redirect any more (SMD-2908). The egress gate judges an endpoint's base, but Bun's fetch followed a 307 with the request's body to wherever it pointed. So an endpoint declared local could send captured text to another host. A 3xx now fails the call where it lands, as a 4xx does, naming where it pointed: set the base there, and the gate judges it. Preflight's `--deep` probes fail on one, and the start's provider row warns.

## Record

No call follows a redirect: a provider's 3xx is refused where it lands, so a base the egress gate judged cannot bounce brain text to another host (SMD-2908)

**What changed.**
- **Every dialler of brain text** passes `redirect: "manual"`. Each refuses a 3xx through `refuseRedirect` (`server-portable/embed.ts`): a `ProviderError` of kind `http` with the status. The diallers:
  - `providerCall`'s exchange: embeddings and chat, the digest's synthesis included;
  - the consolidation judge (`judgeRequest`);
  - extraction (`entities.ts`);
  - decide mode's writer (`consolidate-decide.ts`);
  - the digest's Telegram post (`db/weekly-digest.ts`);
  - the Linear client (`db/linear-api.ts`), which board-findings posts brain rows through under the gate. It refuses a 3xx with its own error, naming only the target's host.
- **The target is printed by `shownLocation`:**
  - resolved against the URL it answered for, so a relative or protocol-relative one parses;
  - userinfo as `***@`, a query as `?…`;
  - capped at 200 characters.

  The Telegram post's target prints as its host alone: its path carries the bot token, which a server may spell any way it likes. `jev.ts`, which already followed no redirect, prints its target the same way as the others now.
- **The probes follow none either, and read a 3xx as refused:**
  - a worker's chat probe (`probeChat`) says `refused`, not `up`, which its fall-through for an unnamed status said;
  - the model list (`modelListed`) says `unknown`;
  - the decide tier's probe says `refused`, not an outage waited out.
- **A worker stops its pass on one.** `classifyError` reads a 3xx as fatal, as it reads a 4xx: the base redirects every call. `providerDown` reads it as no outage. A follower's probe then reads it as refused, so no row is failed one by one.
- **Re-embed halts on one too.** When its probe gate refuses the probe, the first row stands in for it, and that stand-in now halts the run on a redirect as on a 400–404. No suite reaches that stand-in, for this rule or its 400–404 one.
- **Preflight:**
  - the `--deep` probes fail by name, with the knob to set;
  - the start's reachability row warns, naming where `/models` points. It doesn't fail, since `/models` may redirect where the calls do not, and `--deep` tells.

**Why.** SMD-1849 PR 2d's adversarial review found it, and I measured it again here on Bun 1.4.3.
- An endpoint at 127.0.0.1, declared local, answered 307 to another origin. Bun re-sent the POST there with its body, dropping only `Authorization`.
- So the gate's promise, that an endpoint not declared local gets the text only under the policy, did not hold past the first hop.
- The provider span named the declared host, so the trace said the call stayed local.

**Upgrading.** A base that redirects, such as `http://` to a provider that answers on `https://`, worked before. Now every call to it fails, naming where it points.
- **On the embeddings endpoint:** a capture is refused and its text is not stored, as with a 4xx, and so is a search that needs a vector.
- **On a chat endpoint of its own:** the capture is stored untagged, as a 4xx there leaves it.
- **Before upgrading:** the start's warning covers only an endpoint it can probe, a local one. Run `preflight.ts --deep` before upgrading a brain on a hosted provider.
- **The fix:** set the base to the address the error names.
- **Stable and the canary:** their endpoint is Ollama on the host. Its embeddings and chat paths answer an empty POST with 400 and no redirect (checked 2026-11-06 evening, local time).
