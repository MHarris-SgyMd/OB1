## Changelog

The import runner's self-check (`bun deploy/orchestration/runner.ts --self-check`) can no longer fail "a named host that refuses the dial is 502" because another listener was handed the port it dials. That port is now picked below the kernels' default ranges for port 0, so no listener the self-check binds at port 0 can be handed it. The runner itself is unchanged (SMD-3475).

## FORK

The import runner's self-check dials its refused port below the kernels' port-0 ranges — no listener of its own can be handed it (SMD-3475)

**What changed.**
- **`deploy/orchestration/runner.ts`'s self-check:** `gonePort`, the port the loose proxy is told to dial for "a named host that refuses the dial is 502", is picked as the suites' `quietPort` picks one (`server-portable/test-support.ts`, SMD-3296).
  - The port is chosen at random in 20000–29999, below the kernels' default ranges for port 0 (Linux 32768–60999, macOS 49152–65535), and taken only if it binds free on 127.0.0.1 and on 0.0.0.0.
  - It was a port bound at port 0 and freed. Of the listeners bound at port 0 after that pick, those still open at the dial could each be handed it: three as SMD-2289 merged (the main, strict and loose proxies), eight since SMD-3198 ran the self-check's groups side by side.
  - The pick is written into the self-check, not imported. The root `.dockerignore` keeps every `test-*.ts` out of the runner image's build context, so the image build would refuse the import; `test-support.ts` is the suites' helper.

**Why.** Fork Checks run 40258485407 on main (`eed85bb3`, 2026-10-26) failed the image build's self-check with `FAIL a named host that refuses the dial is 502, named (HTTP/1.1 200 Connection Established)`: something answered at the freed port. Its re-run passed. It is the one such failure after PR 476's own merge run, through 2026-10-28: 84 main runs, 86 attempts, 85 image builds (one attempt stopped before its build). The host's run of the self-check passed in all 86 attempts.

**Held.**
- The self-check passes on the host (about 12 s, unchanged) and in the runner image's build, and the checker passes.
- Mutants, each killed by that case:
  - another listener taking `gonePort` before the dial, which gives the CI failure's own line, `HTTP/1.1 200 Connection Established`;
  - the pick handing back a port in use;
  - the proxy answering 503 for a refused dial;
  - the proxy ignoring a refused dial, which then waits out its 10 s dial bound and is cut at the session's 3 s.

**Measured after.** Linux: the runner image's base, `oven/bun:1.4.3-alpine`, under this Mac's podman machine, `ip_local_port_range` 32768–60999. CI builds on the Ubuntu runner's kernel.
- **A probe:** each trial picked a port, then made 30 listeners at port 0 and 30 dials to a listener. The old pick lost its port to a listener in 11 of 2000 trials. The quiet pick lost it in 0 of 2000. No dial's source port was the picked port. Under the quiet pick none can be: it is below the range. Under the old pick none was, since Linux prefers odd ports for `bind()` at port 0 and even ones for `connect()` when the range starts even, as 32768 does.
- **Under pressure:**
  - with port-0 binds kept going until one took `gonePort`, the old pick lost it within 271, 3608 and 5347 binds, and each run failed the case with the CI line;
  - the quiet pick, beside 12000 listeners at port 0, kept it in 3 of 3 runs.

**Not covered.** A process on the same host that binds the picked port by number during the self-check's 12 s can still take it. On CI the job's steps run one after another, and the image build runs in a network namespace of its own.
