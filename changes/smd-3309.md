## Changelog

The Next.js dashboards `dashboards/open-brain-dashboard-next` and `-pro` retire, with the dashboard snippets written for them and the Agent Dashboard walkthrough that drove one. Neither had run on this fork since the `open-brain-rest` gateway they spoke to retired. The operator GUI at `/dashboard` serves what they did on the core, and the record lists, feature by feature, what it took from them and what it dropped. **Upgrading:** nothing deployed either; a copy deployed by hand keeps calling a gateway that no longer exists (SMD-3309).

On main's run at a5725575 the two Next builds took 16 s and 11 s, in the background, with 0 s of waiting: that's about 27 s of runner time, not wall-clock.

**The harvest list** (SMD-2280's Work 4). One line per feature: whether the GUI has it, takes it here, or drops it, and why.
- **Next's mobile drawer (SidebarShell): it has it another way.** The GUI has no sidebar. Its header nav wraps at a phone's width, because eight views pushed it 218 px past one (SMD-2280 PR 2b, review pass 1). The drawer is dropped.
- **Next's accessible modal (DeleteModal; dialog role, Escape, focus trap): dropped here.** The GUI has no destructive verb to confirm yet. An accessible confirm comes with the write verbs (SMD-3322).
- **Next's sidebar extension registry (`extensions.config.ts`): it has it.** The nav lists each enabled plugin's pages from `GET /v1/plugins` (SMD-2280 PR 3). The nav entry comes from the plugin's manifest, and the page's route lives in the GUI tree, because a plugin's directory holds no Svelte (check 31). Enabling or disabling a plugin changes no GUI file. Next's registry was empty on this fork.
- **Next's filter that applies on blur or Enter, not on every keystroke (#131): it has it, without the blur.** Browse applies a typed filter on Enter or Apply. Applying on blur raced the click that left the field (SMD-2280 PR 2a, review pass 1).
- **Pro's settings page that shows no made-up figures: it has it.** `/status` renders the core's `brainInfoRows`, so the GUI never re-words or invents a fact. Pro's `apiKeyPrefix`, which it sent to the browser, is not carried.
- **Pro's ingest ItemCard and its item normalization: moved to SMD-2690.** Smart-ingest becomes a plugin there, and its jobs page a plugin page. The card's map from the reason codes to plain words is the part worth taking: `a5725575:dashboards/open-brain-dashboard-pro/components/AddToBrain.tsx`.
- **Pro's server-side guards (a bulk-delete cap of 50, re-checking each thought before deleting it, the restricted flag from the session): not a GUI's.** The ADR puts destructive-verb guards in the REST core, so every client gets them (`docs/operator-surface-tiers.md`). They come with the write verbs (SMD-3322).
- **Next's kanban board: dropped.** It needs `schemas/workflow-status`'s `status` column, which no operation serves. It would return as a plugin's page.
- **The enhanced-thoughts features (importance, quality audit, duplicates, connections, the restricted lock): dropped.** They read columns the core table doesn't have, through gateway routes that retired with SMD-1931. The GUI's `/proposals` page is the core's own duplicate review.
- **Agent memory and recall traces:** agent-memory-api's plugin pages (SMD-2690), not this ticket's.
- **Reflections: dropped.** No `reflections` table exists in any `.sql`.
- **The three snippets: deleted, none ported.** None of their contributions is a plugin, so there is no page to port them to. The CRM page called PostgREST with a service-role client, and the wiki pages ran a Node subprocess from a Next server action. A GUI page for any of them would come with that contribution's plugin (SMD-2310).

**A minor, not a patch.** The two dashboards, the snippets and the walkthrough are vendored code, outside the version contract, so deleting them is a minor with an upgrade line (FORK.md, "Versioning").
