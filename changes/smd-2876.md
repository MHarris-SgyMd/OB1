## Changelog

An edge proxy puts several brains behind one port, each at a host of its own (`http://<name>.localhost:8090/mcp`). `deploy/edge/` is its own compose project, `ob1-edge`, and reaches each brain through the brain's published port, never its networks. Run it with `bun --no-env-file deploy/edge/edge.ts up`, after naming the brains and their ports in `deploy/edge/brains.local.yaml` (copy `brains.example.yaml`). The edge holds no key: a client's own passes through. Under podman machine the edge is a container that publishes its port; on Docker Engine on Linux it runs on the host's network; other runtimes need `--shape` (SMD-2876).

## FORK

The edge proxy, its own project in front of several brains: routed by host, reaching each brain's published port, in one shape per runtime (SMD-2876)

**What changed.**
- **`deploy/edge/compose.yaml`**, project `ob1-edge`:
  - It runs `compose.yaml`'s proxy's Traefik, by digest, with the same access log (no query string, no header, no userinfo).
  - It runs read-only as 65534, with every capability dropped and `no-new-privileges`. Its only provider is the file provider, reading the rendered table mounted read-only.
  - It holds no key, trusts no PROXY line and has no engine socket.
  - It has two services, one under each profile. Each is labelled with the table's digest and the host ports it holds (`ob1.edge-ports`).
    - **`edge` (profile `bridge`)** is on a network of its own and publishes `127.0.0.1:${EDGE_PORT:-8090}`.
    - **`edge-host` (profile `host`)** runs with `network_mode: host`. It listens on `127.0.0.1` and `[::1]` at `EDGE_PORT` (entrypoints `web` and `web6`), with its ping on `127.0.0.1:EDGE_PING_PORT`.
- **`deploy/edge/edge.ts`** has the commands `check`, `render`, `up`, `down` and `--self-check`.
  - **The registry** is `deploy/edge/brains.local.yaml` (ignored by git) or `--registry`. It holds `edge.port` (8090), `edge.ping_port` (one above), `edge.domain` (`localhost`), and each brain by name with its published port.
  - **Refused in the registry:**
    - an unknown key;
    - a name that is not one lower-case host label, or is a word YAML reads as a boolean or a null;
    - a domain that is not `localhost` or a name under it;
    - a port that is not a port;
    - two brains on one port;
    - a brain on the edge's own port.

    A Go template or a backtick therefore never reaches the table, and a name that another resolver answers never carries a client's key off the machine.
  - **The table** has, per brain:
    - a router on `Host(<name>.<domain>)`, on `web` in the bridge shape and on `web` and `web6` in the host shape;
    - `edge-strip`, which deletes `X-Brain-Forwarder` and `X-OB1-Legacy-Route`;
    - `brain-absent`, which turns any 502 into a bare 404 through `noop@internal`, whether from a brain that is down or from a brain's own proxy;
    - a service at the shape's dial address and the brain's port. The bridge shape dials `host.containers.internal.`, written rooted.

    It carries no comment.
  - **The shape** comes from the runtime: podman machine, rootful on macOS, is `bridge` (the docker CLI on podman's engine counts); Docker Engine on Linux, rootful, is `host`. Anything else is refused until `--shape` is given. The JSON-to-facts step (`factsFrom`) is a pure function, tested against `podman info` and `docker info` shapes.
  - **`check` and `up`:**
    - They refuse an edge address something other than the edge answers on, naming the registry key: `127.0.0.1` and `[::1]` at `edge.port`, and the host shape's ping. A port the running edge holds, read from its label, is its own. The bridge shape never holds `[::1]`, so anything there is refused.
    - For each brain they name the container that publishes its port, or say that a host process answers there or that nothing does.
    - They refuse any file in `deploy/edge/dynamic/` other than `routes.yaml`, since Traefik would load it.
  - **`up` itself:**
    - It first removes the other shape's edge.
    - It writes the table into `deploy/edge/dynamic/` (ignored by git) in place, and only when it changed. Both the directory and the file are chmod-ed, so the table is readable whatever the umask.
    - It runs compose with no env file, as `-p ob1-edge`, with none of the shell's `COMPOSE_*` or `EDGE_*` variables. The table's sha256 is a label, so a changed table recreates the container.
    - It then asks the edge for the first brain's host. If the answer is Traefik's router miss, the table didn't load; if nothing answers, the edge is unreachable. Either way `up` fails, naming the log. In the bridge shape it checks `[::1]` once more.
  - Without `--no-env-file`, `check`, `up` and `down` refuse, naming the command.
- **Check 36** of `scripts/check-fork-consistency.ts` holds `deploy/edge/compose.yaml` whole as `EDGE_COMPOSE`.
  - The image is `PROXY_SERVICE`'s. The environment is named key by key, so a trust the brain's proxy gains is never the edge's by inheritance.
  - It also holds the table `edge.ts` renders for the example registry, in each shape, byte for byte, as `EDGE_ROUTE_TABLE`.
  - It refuses another compose file in `deploy/edge/`, and applies check 28's character and tag rules.
  - There are thirteen probes, and each rule is the sole catch of one.
- **CI:**
  - `edge.ts --self-check` runs in the repo-consistency job and in `db/ci-parity.sh`.
  - The new deploy-stack step "The edge proxy reaches both brains through their published ports" uses the stack on 8010 and `ob1b` on 8040. The step before it now leaves `ob1b` up for it, and this step removes it. The key is masked in the log.
    - `check` names each brain's forwarder.
    - Each brain answers at its host through the edge, on 127.0.0.1 and `[::1]`, and on its own port.
    - `tools/list` goes through with a header key and with `?key=`. A call with no key gets the server's own refusal: HTTP 200, JSON-RPC -32001, with no tool list.
    - An unknown host gets a 404.
    - The edge is on the host's network and on no network of either brain, and its log holds no key.
    - Refused: `edge.ts` run without `--no-env-file`, and, while the edge runs, a new edge port that a host process holds. The running edge keeps serving.
    - A changed registry is served after `up`: `ob1b`'s port under the name `ob1c`, while `ob1b` gets the router miss.
    - With the brain's forwarder stopped, its host gets a bare 404 and the stack's still answers.
- **`deploy/README.md`:** a new section, "Several brains behind one edge".

**The maintainer's choices (2026-10-15)**, on the four questions the ticket left open:
1. **Binding: one edge per runtime, with brains kept on loopback.** This was chosen over a network shared by the forwarders and the edge (it amends the ADR's rows 1 and 6), brains on every interface (it exposes them on the LAN), and an edge run as a host process.
2. **Routing by host.** It keeps each brain's OAuth and its own authorization server: row 4 holds, and ADR open question 3 is answered. It was chosen over routing by path, which breaks a brain's OAuth.
3. **The edge counts as one client** to the authorization server's per-address limits. Row 7 holds; the alternatives were a PROXY line or `X-Forwarded-For` from the edge.
4. **Two PRs.** OAuth through the edge, meaning `*.localhost` as a loopback origin, and the ADR's write-up come in PR 2.

**Measured (2026-10-15, adding to the ADR's 2026-10-09 table).** The setup was as in the ADR: scratch Bun targets, with Docker Engine 29.9 run in a throwaway `docker:dind`.
- **Docker Engine on Linux:**
  - a host-network container reaches a brain published on `127.0.0.1`, and the host reaches a host-network listener on `127.0.0.1`;
  - a bridge container reaches a host-network listener on the bridge gateway through `host-gateway`, which is the way a brain could reach the edge (SMD-2877).
- **podman machine:**
  - a host-network container reaches a brain published on `127.0.0.1`;
  - the Mac does **not** reach a host-network listener on the VM's loopback, so the host shape is Linux's alone.
- **`*.localhost`** resolves to `::1` and `127.0.0.1` in Bun with no hosts entry, and Bun's fetch falls back to 127.0.0.1 when `::1` refuses. curl resolves it too.
- **podman machine and `[::1]`:**
  - it publishes one host port on one loopback only, and refuses to publish `127.0.0.1:P` and `[::1]:P` together;
  - a `127.0.0.1:P` publish leaves `[::1]:P` free for any Mac process to bind, and a client asking `<name>.localhost` reaches that process first;
  - Traefik in a podman container dials the rooted `host.containers.internal.` (200).

**Review pass 1** (four reviewers: cold read, CI walkthrough, run-it with 64 mutants, secrets adversary with an operator walkthrough).
- **High, fixed:**
  - The CI step expected a keyless call to get a 401. The stack has no OAuth there, so the server answers 200 with JSON-RPC -32001, as `smoke.sh` holds, and the step would have been red on every run. (caught: walkthrough)
  - Three CI lines of the form `[ A ] && [ B ] || {…}` fail shellcheck's SC2015 in the Workflow lint job, as they did once before (435e4557). (caught: walkthrough)
  - A process on `[::1]:<edge.port>` took every client's key, since a `*.localhost` name resolves to `::1` first, and `check`/`up` didn't notice. The host shape now listens on both loopbacks. podman machine can't publish both, so the bridge shape refuses to run beside anything there, before `up` and after it. (caught: run-it)
  - On podman machine, renaming the table into place raced the container's recreate. Traefik's file provider never started; the edge was healthy, `up` exited 0, and every host got a 404 (3 runs in 10). The table is now written in place, and only when it changed, and `up` asks the edge whether the table is served. (caught: run-it)

  - Switching shape left the old shape's container holding the port. It is removed first. (caught: run-it)
