## Changelog

An edge proxy puts several brains behind one port, each at a host of its own (`http://<name>.localhost:8090/mcp`). `deploy/edge/` is its own compose project, `ob1-edge`, and reaches each brain through the brain's published port, never its networks. Run it with `bun --no-env-file deploy/edge/edge.ts up`, after naming the brains and their ports in `deploy/edge/brains.local.yaml` (copy `brains.example.yaml`). The edge holds no key: a client's own passes through. Under podman machine the edge is a container that publishes its port; on Docker Engine on Linux it runs on the host's network; other runtimes need `--shape` (SMD-2876).

## FORK

The edge proxy, its own project in front of several brains: routed by host, reaching each brain's published port, in one shape per runtime (SMD-2876)

**What changed.**
- **`deploy/edge/compose.yaml`**, project `ob1-edge`:
  - It runs `compose.yaml`'s proxy's Traefik, by digest, with the same access log (no query string, no header, no userinfo).
  - It runs read-only as 65534, with every capability dropped and `no-new-privileges`. Its only provider is the file provider, reading the rendered table mounted read-only.
  - It holds no key, trusts no PROXY line and has no engine socket.
  - It has two services, one under each profile:
    - **`edge` (profile `bridge`)** is on a network of its own and publishes `${EDGE_BIND:-127.0.0.1}:${EDGE_PORT:-8090}`;
    - **`edge-host` (profile `host`)** runs with `network_mode: host`, listens on `127.0.0.1:EDGE_PORT` and puts its ping on `127.0.0.1:EDGE_PING_PORT`.
- **`deploy/edge/edge.ts`** has the commands `check`, `render`, `up`, `down` and `--self-check`.
  - **The registry** is `deploy/edge/brains.local.yaml` (ignored by git) or `--registry`. It holds `edge.port` (8090), `edge.ping_port` (one above), `edge.domain` (`localhost`), and each brain by name with its published port.
  - **Refused in the registry:** an unknown key; a name that is not one lower-case host label; a domain that is not a host name; a port that is not a port; two brains on one port; and a brain on the edge's own port. A Go template or backtick can therefore never reach the table.
  - **The table** has, per brain:
    - a router on `Host(<name>.<domain>)`;
    - `edge-strip`, which deletes `X-Brain-Forwarder` and `X-OB1-Legacy-Route`;
    - `brain-absent`, which turns Traefik's 502 into a bare 404 through `noop@internal`;
    - a service at the shape's dial address and the brain's port.

    It carries no comment.
  - **The shape** comes from the runtime: podman machine, rootful on macOS, is `bridge` (the docker CLI on podman's engine counts); Docker Engine on Linux, rootful, is `host`. Anything else is refused until `--shape` is given.
  - **`up`:**
    - it refuses an edge port that something other than the edge already answers on, naming the registry key;
    - it notes each brain that is not answering;
    - it writes the table into `deploy/edge/dynamic/` (ignored by git) by rename;
    - it runs compose with no env file, as `-p ob1-edge`, with none of the shell's `COMPOSE_*` or `EDGE_*` variables, and with the table's sha256 as a label, so a changed table recreates the container.
  - Without `--no-env-file`, `check`, `up` and `down` refuse, naming the command.
- **Check 36** of `scripts/check-fork-consistency.ts` holds `deploy/edge/compose.yaml` whole as `EDGE_COMPOSE`. Its environment is built from check 28's `PROXY_SERVICE`, so the pin and the access log move with the proxy's. It also holds the table `edge.ts` renders for the example registry, in each shape, byte for byte, as `EDGE_ROUTE_TABLE`. It refuses another compose file in `deploy/edge/`, and applies check 28's character and tag rules. There are eleven probes, and each rule is the sole catch of one.
- **CI:**
  - `edge.ts --self-check` runs in the repo-consistency job and in `db/ci-parity.sh`.
  - The new deploy-stack step "The edge proxy reaches both brains through their published ports" uses the stack on 8010 and `ob1b` on 8040. The step before it now leaves `ob1b` up for it, and this step removes it.
    - Each brain answers at its host and on its own port.
    - `tools/list` goes through with a header key and with `?key=`, and a call with no key gets a 401.
    - An unknown host gets a 404.
    - The edge is on the host's network and on no network of either brain, and its log holds no key.
    - With `ob1b`'s forwarder stopped, its host gets a bare 404 and the stack's still answers.
- **`deploy/README.md`:** a new section, "Several brains behind one edge".

**The maintainer's choices (2026-10-15)**, on the four questions the ticket left open:
1. **Binding: one edge per runtime, with brains kept on loopback.** This was chosen over a network shared by the forwarders and the edge (it amends the ADR's rows 1 and 6), brains on every interface (it exposes them on the LAN), and an edge run as a host process.
2. **Routing by host.** It keeps each brain's OAuth and its own authorization server: row 4 holds, and ADR open question 3 is answered. It was chosen over routing by path, which breaks a brain's OAuth.
3. **The edge counts as one client** to the authorization server's per-address limits. Row 7 holds; the alternatives were a PROXY line or `X-Forwarded-For` from the edge.
4. **Two PRs.** OAuth through the edge, meaning `*.localhost` as a loopback origin, and the ADR's write-up come in PR 2.

**Measured (2026-10-15, adding to the ADR's 2026-10-09 table).** The setup was as in the ADR: scratch Bun targets, with Docker Engine 29.9 run in a throwaway `docker:dind`.
- **Docker Engine on Linux:**
  - a host-network container reaches a brain published on `127.0.0.1`, and the host reaches a host-network listener on `127.0.0.1`;
  - a bridge container reaches a host-network listener on the bridge gateway through `host-gateway`, which is the way a brain could reach the edge (SMD-2877).
- **podman machine:**
  - a host-network container reaches a brain published on `127.0.0.1`;
  - the Mac does **not** reach a host-network listener on the VM's loopback, so the host shape is Linux's alone.
- **`*.localhost`** resolves to `::1` and `127.0.0.1` in Bun with no hosts entry, and Bun's fetch falls back to 127.0.0.1 when `::1` refuses. curl resolves it too.

**Held.**
- `deploy/edge/edge.ts --self-check` passes 20/20.
- The live run under podman machine passes 22/22 (bridge shape). It used two scratch upstreams that echo what reaches them, each published on loopback in a network of its own.
  - **Routing:**
    - each host reaches its brain;
    - path, `?key=`, `x-brain-key` and `Host` pass through unchanged;
    - both headers are deleted;
    - unknown hosts and the bare address get a 404;
    - a brain that is down gets a bare 404 on its own host while the other answers, and its host answers again once it is back.
  - **Isolation:** the edge is on its own network alone, and is read-only as 65534. Its log holds neither form of the key.
  - **`up`:**
    - a re-up on the same table keeps the container;
    - a changed registry is served;
    - an edge port that is held elsewhere is refused;
    - running without `--no-env-file` is refused.
- The live run under Docker Engine 29.9 on Linux (dind) passes 12/12 (host shape). `check` picks the host shape, and routing, the strip, unknown hosts and a down brain behave as above. The edge is in host network mode, on neither brain's network, healthy on its ping port, does not answer on the bridge gateway, and is removed by `down`.
- Eight hand mutants of `deploy/edge/` are each caught by check 36. Check-fork-consistency passes, the scripts typecheck passes, and actionlint passes with shellcheck.
