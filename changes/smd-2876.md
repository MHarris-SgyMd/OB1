## Changelog

An edge proxy puts several brains behind one port, each at a host of its own (`http://<name>.localhost:8090/mcp`). Clients that send an access key work through the edge; sign-in through it waits for TLS at the edge, since MCP clients refuse a plain-HTTP token endpoint at `<name>.localhost`. `deploy/edge/` is its own compose project, `ob1-edge`, and reaches each brain through the brain's published port, never its networks. Run it with `bun --no-env-file deploy/edge/edge.ts up`, after naming the brains and their ports in `deploy/edge/brains.local.yaml` (copy `brains.example.yaml`). The edge holds no key: a client's own passes through. Under podman machine the edge is a container that publishes its port; on Docker Engine on Linux it runs on the host's network; other runtimes need `--shape` (SMD-2876).

## FORK

The edge proxy, its own project in front of several brains: routed by host, reaching each brain's published port, in one shape per runtime (SMD-2876)

**What changed.**
- **`deploy/edge/compose.yaml`**, project `ob1-edge`:
  - It runs `compose.yaml`'s proxy's Traefik, by digest, with the same access log (no query string, no header, no userinfo).
  - It runs read-only as 65534, with every capability dropped and `no-new-privileges`. Its only provider is the file provider, reading the rendered table mounted read-only.
  - It holds no key, trusts no PROXY line and has no engine socket.
  - It has two services, one under each profile. Each is labelled with the table's digest and the host addresses it holds (`ob1.edge-addresses`: the bridge `127.0.0.1:P`, the host `127.0.0.1:P,[::1]:P,127.0.0.1:PING`).
    - **`edge` (profile `bridge`)** is on a network of its own and publishes `127.0.0.1:${EDGE_PORT:-8090}`.
    - **`edge-host` (profile `host`)** runs with `network_mode: host`. It listens on `127.0.0.1` and `[::1]` at `EDGE_PORT` (entrypoints `web` and `web6`), with its ping on `127.0.0.1:EDGE_PING_PORT`.
- **`deploy/edge/edge.ts`** has the commands `check`, `render`, `up`, `down` and `--self-check`.
  - **The registry** is `deploy/edge/brains.local.yaml` (ignored by git) or `--registry`. It holds `edge.port` (8090), `edge.ping_port` (one above), `edge.domain` (`localhost`), and each brain by name with its published port.
  - **Refused in the registry:**
    - an unknown key;
    - a name that is not one lower-case host label, or is a word YAML reads as a boolean or a null;
    - a domain that is not `localhost` or a name under it;
    - a port that is not a port;
    - two brains on one port;
    - a brain on the edge's own port.

    A Go template or a backtick therefore never reaches the table, and the domain is one that RFC 6761 resolvers answer with loopback themselves: a public name would carry a client's key off the machine over HTTP.
  - **The table** opens with a probe router, `_edge-probe`: `Host(_edge.<domain>)`, which no brain's name can take, to `noop@internal`, which answers 418. Then, per brain:
    - a router on `Host(<name>.<domain>)`, on `web` in the bridge shape and on `web` and `web6` in the host shape;
    - `edge-strip`, which deletes `X-Brain-Forwarder` and `X-OB1-Legacy-Route`;
    - `brain-absent`, which turns any 502 into a bare 404 through `noop@internal`, whether from a brain that is down or from a brain's own proxy;
    - a service at the shape's dial address and the brain's port. The bridge shape dials `host.containers.internal.`, written rooted.

    It carries no comment.
  - **The shape** comes from the runtime: podman machine, rootful on macOS, is `bridge` (the docker CLI on podman's engine counts); Docker Engine on Linux, rootful, is `host`. Anything else is refused until `--shape` is given, and `--shape host` under podman machine, measured unreachable from the Mac, is refused outright. The JSON-to-facts step (`factsFrom`) is a pure function, tested against `podman info` and `docker info` shapes.
  - **`check` and `up`:**
    - They refuse an edge address something other than the edge answers on, naming the registry key: `127.0.0.1` and `[::1]` at `edge.port`, and the host shape's ping (`addressesToAsk`). An address a running edge's label holds, of either shape, is skipped, since up removes or recreates that edge. The bridge shape never holds `[::1]`, so anything there is refused. In the host shape they refuse a host with no `[::1]` at all (IPv6 off).
    - For each brain they name the container that publishes its port, or say that a host process answers there or that nothing does.
    - They refuse what Traefik's file provider would load beside the table in `deploy/edge/dynamic/`: another `.yaml`, `.yml` or `.toml` file in any case, or a directory. A `.tmp` or a `.DS_Store` it skips (measured).
  - **`up` itself:**
    - It first removes the other shape's edge, in any state, since compose treats it as no orphan.
    - It writes the table into `deploy/edge/dynamic/` (ignored by git) in place, and only when it changed. Both the directory and the file are chmod-ed, so the table is readable whatever the umask.
    - It runs compose with no env file, as `-p ob1-edge`, with none of the shell's `COMPOSE_*` or `EDGE_*` variables. The table's sha256 is a label, so a changed table recreates the container.
    - It then asks the edge for the probe host, never a brain, up to ten seconds. 418 means served. A 404, Traefik's router miss, means the table didn't load; no answer means the edge is unreachable. When it isn't served, `up` recreates the edge once (`--force-recreate`, since an unchanged table never would) and asks again, then fails naming the log. In the bridge shape it checks `[::1]` once more.
  - Without `--no-env-file`, `check`, `up` and `down` refuse, naming the command.
- **Check 36** of `scripts/check-fork-consistency.ts` holds `deploy/edge/compose.yaml` whole as `EDGE_COMPOSE`.
  - The image is `PROXY_SERVICE`'s. The environment is named key by key, so a trust the brain's proxy gains is never the edge's by inheritance.
  - It also holds the table `edge.ts` renders for the example registry, in each shape, byte for byte, as `EDGE_ROUTE_TABLE`.
  - It refuses another compose file in `deploy/edge/`, and applies check 28's character and tag rules.
  - There are thirteen probes, and each rule is the sole catch of one.
- **CI:**
  - `edge.ts --self-check` runs in the repo-consistency job and in `db/ci-parity.sh`.
  - The new deploy-stack step "The edge proxy reaches both brains through their published ports" uses the stack on 8010 and `ob1b` on 8040. The step before it now leaves `ob1b` up for it, and this step removes it. The key is masked in the log.
    - `check` names each brain's forwarder.
    - Each brain answers at its host through the edge on 127.0.0.1 (`curl -4`) and on `[::1]`, and on its own port.
    - `tools/list` goes through with a header key and with `?key=`. A call with no key gets the server's own refusal: HTTP 200, JSON-RPC -32001, with no tool list.
    - An unknown host gets a 404.
    - The edge is on the host's network and on no network of either brain, and its log holds no key.
    - Refused: `edge.ts` run without `--no-env-file`; while the edge runs, a new edge port that a host process holds on 127.0.0.1 or on `[::1]` (the running edge keeps serving); and a stray `.yaml` beside the table.
    - A changed registry is served after an `up` run under umask 077, with the table's directory made afresh: `ob1b`'s port under the name `ob1c`, while `ob1b` gets the router miss.
    - With the brain's forwarder stopped, its host gets a bare 404 and the stack's still answers.
- **`deploy/README.md`:** a new section, "Several brains behind one edge".
- **PR 2: the record, and what sign-in through the edge needs.**
  - The ADR marks rows 6 and 7 built, answers open questions 1–3 with the maintainer's choices, and adds the 2026-10-15 measurements. `deploy/README.md` and `docs/operator-surface-tiers.md` follow it.
  - PR 2 first made a name under `localhost` a loopback origin, in both copies of the rule, with a CI step signing a brain in at its host on the edge. Its review measured that MCP clients send a token request over plain HTTP only to exactly `localhost`, `127.0.0.1` or `::1`: SDK v2 refused the token endpoint at `http://ob1c.localhost` (`InsecureTokenEndpointError`), and Claude Code 2.1.301 holds the same rule. So no client could finish a sign-in there.
  - The widening, its tests and the step were reverted, the maintainer's choice. Sign-in through the edge needs `https://<name>.localhost` (SMD-3053, blocked by SMD-2286), which today's rule already accepts.

**The maintainer's choices (2026-10-15)**, on the four questions the ticket left open:
1. **Binding: one edge shape per runtime, with brains kept on loopback** (ADR open question 1). This was chosen over a network shared by the forwarders and the edge (it amends the ADR's rows 1 and 6), brains on every interface (it exposes them on the LAN), and an edge run as a host process.
2. **Routing by host.** It keeps each brain's OAuth possible, with its own authorization server: row 4 holds, and ADR open question 3 is answered. It was chosen over routing by path, which breaks a brain's OAuth.
3. **The edge counts as one client** to the authorization server's per-address limits (open question 2). Row 7 holds; the alternatives were a PROXY line or `X-Forwarded-For` from the edge.
4. **Two PRs.** PR 2 was to bring OAuth through the edge, with `*.localhost` as a loopback origin, and the ADR's write-up. Its review reverted the widening (above), and sign-in waits on SMD-3053.

**Measured (2026-10-15).** The host-network rows and the two loopbacks are in the ADR, `docs/one-brain-per-stack.md`, under "Host-network mode and the two loopbacks". So is podman machine's one-loopback publish. Also measured on Traefik v3.7.13:
- The file provider loads `.yml`, `.YAML`, dot-named and subdirectory files beside the table, and skips `.tmp`, `~` and `.DS_Store`.
- A router to `noop@internal` answers 418 once the table is loaded, and the router miss (404) before.
- A podman container dials the rooted `host.containers.internal.`.

**Not taken.**
- A duplicate brain key, which Bun.YAML resolves last-wins.
- The client's `Forwarded:` header, which passes through; nothing in the brain reads it.
- `holderOf`'s note for a container that publishes `[::]` alone.
- CI's network-membership loop, which can't fail in host mode but holds the Verify line.

**Follow-ups.** SMD-3053: TLS at the edge with a local CA, so a brain behind it can use `https://<name>.localhost` and sign in there. It is blocked by SMD-2286.
