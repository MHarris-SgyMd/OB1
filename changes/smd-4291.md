## Record

The session-capture hook reads a place's own ticket, not every ticket-shaped word of it (SMD-4291)

Found by SMD-3306 PR 7a-3b-2's review pass 3, through the real hook: on branch `smd-610-bump-node-22` the asks "bump node-22 to node-24 in the Dockerfile" and "run the tests" gave the header `Session summary — NODE-22, NODE-24 — …`, the branch's own ticket missing, sent with `tickets_from: asks`; "the image still pins node-22, see smd-610" put NODE-22 first. The hook's README said `node-22` is no ticket.

**What changed.** `recipes/session-capture-hook/session-capture.mjs`:
- **A place's own tickets** (`ownTickets`, `branchTickets`, `dirTickets`, `placeTickets`): the first ticket-shaped word is the place's ticket, and the other keys of its team are tickets beside it (`smd-610-and-smd-611` names both); a word of another team is the place's description. A branch is read whole (`smd-12/fix-node-22` is SMD-12's); a directory by its deepest part that names one (`~/aoc-2024/smd-55-day1/src` is SMD-55's).
- **Every reader of a place** reads that: `segment`'s team learning, `anchorOf` (the place's tickets, a header's fallback and an episode's home), `movesTo`, and the moves the open episode takes as its own.
- **A directory** is split at either slash, so a Windows path is read by its parts; a cd within the episode's checkout teaches no team, so `packages/node-22-compat` under it names nothing.
- **The cost:** a branch that puts another key before its ticket, `bump-node-22-for-smd-610`, names that key, as the brain's header rule reads a branch's team; an ask's `smd-610` is then no ticket, and an episode about it splits on the move there. An upper-case key asked on `main` before any team is known, then a move to a branch naming another ticket, now begins an episode there, the branch's place no longer naming the asked key.
- README (the episode rule and Expected Outcome), metadata.json 1.8.1; db/README and `server-portable/subject.ts` say the guard stays for summaries captured before.

**Held.** test-session-capture (994): on `smd-610-bump-node-22` the asks give a header naming SMD-610 alone, from the place, or from the ask that names `smd-610`, and a mention of `node-22` begins no episode; a branch naming two of its team's tickets names both; a directory's own ticket is its deepest part's; a branch read whole; a move to a branch whose first key is another team's; with no team known, an upper-case key still counts. Mutants: 7 on the place's reading (every word as teams, as tickets, the first ticket alone, a directory read whole or from its shallowest part, `movesTo` reading every word, a branch read by its last part), all killed, two by cases added for them.

**Review pass 1** (a cold read with 15 mutants, and the hook run on built transcripts and this machine's 3,962 Claude Code and 6 Codex sessions at both heads: 5 headers changed, each dropping a description word, none an episode): a Windows path was read whole, its parent's word winning (run-it); a cd into a ticket-shaped subdirectory taught its team (run-it); the docs said the guard stays only for older summaries, where 1.8.1 still needs it (cold read); the trade-off's consequences went unsaid (cold read); nine readers of a place were held by no case (mutant). **Not here.** A place with no ticket (`node-22-pin`) still names its first ticket-shaped word, and the session's teams outlast the place that taught them; a word cannot be told from a ticket by its shape. Relaxing the brain's team guard (`sessionHeaderTickets`) for summaries from the fixed hook: it would need the hook's version on the summary to tell them from older ones.
