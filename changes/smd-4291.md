## Changelog

The session-capture hook (1.8.1) learns a team, and names a place's tickets, from a branch's or a directory's own ticket alone, where it read every ticket-shaped word of them: on a branch named for a ticket and a Node version bump, an ask's `node-22` was a named ticket and headed the summary, and with none named the branch's place listed `NODE-22` beside the branch's ticket (SMD-4291).
**Upgrading:** pull the hook's checkout. Summaries captured before keep their headers, but a session that reaches a checkpoint after the pull (a compaction, its end, a resume) captures again each episode whose header changed, superseding its earlier summary. The brain's header rule keeps its team guard: 1.8.1 still reads a place with no ticket by its first ticket-shaped word and keeps the session's teams across its places.

## Record

The session-capture hook reads a place's own ticket, not every ticket-shaped word of it (SMD-4291)

Found by SMD-3306 PR 7a-3b-2's review pass 3, through the real hook: on branch `smd-610-bump-node-22` the asks "bump node-22 to node-24 in the Dockerfile" and "run the tests" gave the header `Session summary — NODE-22, NODE-24 — …`, the branch's own ticket missing, sent with `tickets_from: asks`; "the image still pins node-22, see smd-610" put NODE-22 first. The hook's README said `node-22` is no ticket.

**What changed.** `recipes/session-capture-hook/session-capture.mjs`:
- **A place's own tickets** (`ownTickets`, `branchTickets`, `dirTickets`, `placeTickets`): the first ticket-shaped word is the place's ticket, and the other keys of its team are tickets beside it (`smd-610-and-smd-611` names both); a word of another team is the place's description. A branch is read whole (`smd-12/fix-node-22` is SMD-12's); a directory by its deepest part that names one (`~/aoc-2024/smd-55-day1/src` is SMD-55's).
- **Every reader of a place** reads that: `segment`'s team learning, `anchorOf` (the place's tickets, a header's fallback and an episode's home), `movesTo`, and the moves the open episode takes as its own.
- **A directory** is split at either slash, so a Windows path is read by its parts. One rule says what a ticket-shaped directory within the episode's checkout is: a checkout of its own when it sits in a worktrees folder (a name ending `worktree` or `worktrees`, or `wt`, `.wt`: this repo's `.claude/worktrees/…`, the branch still `main`, a worktree named for no ticket among them), when the branch names its ticket (`~/Projects/smd-55-day1` on `smd-55-day1`), when it is the first ticket-shaped part below HOME off a ticket branch, or when it sits directly in a checkout naming no ticket by its directory or branch (`~/Projects/smd-55-day1`); else a folder of the checkout it is in (`packages/node-22-compat`, `docs/smd-500-notes`). It is decided once, when the session enters the directory, with the branch the session moves to on that line. A cd within the checkout into a folder teaches the team of the checkout the folder is in, not the folder's, and an episode a compaction, a new ticket or a branch move opens in a folder runs in that checkout, so `packages/node-22-compat` names nothing. A session that begins in such a folder still takes its name, having no checkout above it yet.
- **The brain's denied prefixes** (ES, CC, FY, GPL, CWE and the rest its shape can match) join the hook's, so no place or ask names a ticket the brain refuses; the brain's mirror of the hook's list (`HOOK_NOT_TICKETS`) follows.
- **The cost:** a branch that puts another key before its ticket, `bump-node-22-for-smd-610`, names that key, as the brain's header rule reads a branch's team; an ask's `smd-610` is then no ticket, and an episode about it splits on the move there. An upper-case key asked on `main` before any team is known, then a move to a branch naming another ticket first and the asked key after it, now begins an episode there, the branch's place no longer naming the asked key. A ticket-shaped folder directly in a checkout naming no ticket (`app/node-22-compat` on `main`) reads as a checkout of its own and teaches its team, as on main.
- README (the episode rule and Expected Outcome), metadata.json 1.8.1; db/README and `server-portable/subject.ts` say the brain's team guard stays, for summaries captured before and for 1.8.1's too.
