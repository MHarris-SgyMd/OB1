## Changelog

The suite holds re-embed's halt on a first row that fails as the configuration would, for each such failure, and that a rate limit or an outage there does not halt (SMD-4143). No behaviour changes: the rows are tests.

## Record

Re-embed's first-row stand-in held for each configuration-shaped failure and for the moment's, thirteen rows where one stood (SMD-4143)

**Problem.** When the egress gate refuses re-embed's start probe, the first row's call stands in for it. A failure there that `configShaped` reads as the configuration's halts the run: that row is recorded failed and the rest stay pending, so a wrong endpoint does not fail a pool one row at a time. SMD-2908's review found no suite reached the path. SMD-4352 PR 3 added one row, a 401, before this ticket was found. The other failures the rule names, the redirect SMD-2908 added, and the rule's other side, that a rate limit does not halt, had no row.

**Change.** test-live's [9f] row is a table, one one-shot run for each first answer, each under a deny policy whose allow term is the rows' own type, so the probe is skipped. The stub answers the rows' calls as the case says (`rowAnswer`). One line of the engine changes, with no behaviour: `configShaped`'s words lose "returned no embedding", below.

| The first row's call | Asserted |
|---|---|
| Refused 400, 401, 402, 403, 404 (five rows) | The run halts, said once. That row is failed, the batch's other three pending and said so, exit 1. |
| Redirected, a 302 | The same. |
| Answered a body that is not JSON | The same. |
| Answered a vector of another width | The same. |
| Answered no vector | The same. |
| Refused 408, 429, 500, 503, the first call alone (four rows) | No halt. That row is failed, the other three re-embedded, exit 1. |

**Verify.** Six mutants of `db/reembed.ts`, each run against test-live's long shard. Each fails the rows written for it and no other (caught: mutant).

| Mutant | Rows it fails |
|---|---|
| The halt dropped (the ticket's first) | The nine that halt |
| The redirect clause dropped (the ticket's second) | The 302 |
| The halt on any first failure | The 408, 429, 500 and 503 |
| The statuses cut to 401 alone | The 400, 402, 403 and 404 |
| The `body` clause dropped | The body that is not JSON, and no vector |
| The words never matching | The other width |

**A seventh mutant lived, and its words are gone.** `configShaped`'s regex read "Embedding width mismatch|returned no embedding". Taking the second alternative out failed no row, and was the same program: `server-portable/embed.ts` raises "returned no embedding" in one place, as a `ProviderError` of kind `body`, and `configShaped` returns on the `body` clause before it reads the words. The no-vector row is held by that clause, as the fifth mutant shows. The maintainer chose to remove the words, 2026-11-19; a comment in their place says where a reply with no embedding is read.

The long shard is at 386 assertions, 386 passed, twelve more than main. The twelve added runs cost a few seconds, not measured apart.

The 408 and the 500 were added in review: the rule's own comment names them beside the 429 and the 5xx, and the table had only the ticket's two (caught: cold-read).

The ticket's note on SMD-2636 no longer applies: the stand-in stayed in `reembed.ts`.
