## Changelog

The suite holds re-embed's halt on a first row that fails as the configuration would, for each such failure, and that a rate limit or an outage there does not halt (SMD-4143). No behaviour changes: the rows are tests.

## Record

Re-embed's first-row stand-in held for each configuration-shaped failure and for the moment's, eleven rows where one stood (SMD-4143)

**Problem.** When the egress gate refuses re-embed's start probe, the first row's call stands in for it. A failure there that `configShaped` reads as the configuration's halts the run: that row is recorded failed and the rest stay pending, so a wrong endpoint does not fail a pool one row at a time. SMD-2908's review found no suite reached the path. SMD-4352 PR 3 added one row, a 401, before this ticket was found. The other failures the rule names, the redirect SMD-2908 added, and the rule's other side, that a rate limit does not halt, had no row.

**Change.** test-live's [9f] row is a table, one one-shot run for each first answer, each under a deny policy whose allow term is the rows' own type, so the probe is skipped. The stub answers the rows' calls as the case says (`rowAnswer`). No engine changes.

| The first row's call | Asserted |
|---|---|
| Refused 400, 401, 402, 403, 404 (five rows) | The run halts, said once. That row is failed, the batch's other three pending and said so, exit 1. |
| Redirected, a 302 | The same. |
| Answered a body that is not JSON | The same. |
| Answered a vector of another width | The same. |
| Answered no vector | The same. |
| Refused 429, the first call alone | No halt. That row is failed, the other three re-embedded, exit 1. |
| Refused 503, the first call alone | The same. |

**Verify.** Seven mutants of `db/reembed.ts`, each run against test-live's long shard. Six fail the rows written for them and no other (caught: mutant).

| Mutant | Rows it fails |
|---|---|
| The halt dropped (the ticket's first) | The nine that halt |
| The redirect clause dropped (the ticket's second) | The 302 |
| The halt on any first failure | The 429 and the 503 |
| The statuses cut to 401 alone | The 400, 402, 403 and 404 |
| The `body` clause dropped | The body that is not JSON, and no vector |
| "Embedding width mismatch" out of the words | The other width |
| "returned no embedding" out of the words | None: it lived |

**The one that lived is the same program.** `server-portable/embed.ts` raises "returned no embedding" in one place, as a `ProviderError` of kind `body`. `configShaped` returns on the `body` clause before it reads the words, so the second alternative of its regex is never what decides. The no-vector row is held by the `body` clause, as the fifth mutant shows. The words are left in: taking them out is an engine change this ticket did not ask for.

The long shard is at 384 assertions, 384 passed, ten more than main. The ten added runs cost a few seconds, not measured apart.

**Not in this PR.** The ticket's note on SMD-2636 no longer applies: the stand-in stayed in `reembed.ts`.
