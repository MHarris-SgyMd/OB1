## Changelog

The proxy routes `/canary/mcp` and `/working/mcp` to that tier's MCP server, reached by name on the stack's mesh (`mcp.canary.ob1.internal`, `mcp.working.ob1.internal`), and answers a bodiless 404 while no such tier is up. Every other path under either prefix is a 404 too, never stable's server. The proxy now dials stable's own server by its mesh name, `mcp.ob1.internal`, so another project's container on the mesh, which compose also calls `server`, can never take stable's traffic (SMD-2294).

## FORK

The tier stack on proxy paths: stable's proxy routes /canary/mcp and /working/mcp to a tier on its mesh (SMD-2294)

SMD-2294 moves the canary and working tiers from host ports (8010–8012) onto
paths of stable's one origin. It lands in three cuts:
1. stable's proxy carries the tier routes (this cut);
2. `deploy/canary.sh` stands the canary at `/canary/mcp`;
3. `compose.tiers.yaml`, `--compare` and the docs.

Each tier's MCP server is today's server-portable, beside its own REST core. SMD-2287's server replaces it by changing only the service the routes name.

**PR 1 — the routes.** In `deploy/compose.yaml`'s `x-proxy-routes`:
- `canary` and `working` (priority 30, beside `mcp`) send `/canary/mcp` and
  `/working/mcp`, and everything under each, to `mcp.canary.ob1.internal.` or
  `mcp.working.ob1.internal.` on `mesh`. Along the way, `not-legacy` deletes a
  client's legacy marker, and `tier-absent` (an errors middleware, as
  `auth-absent`) turns Traefik's 502 into the bare 404 of a path nothing serves.
  That 502 comes from no such name on the mesh, or from a tier that is stopped
  or still starting.
- The prefix is not stripped. The server answers POST at every path and
  `/health` under any prefix, so `/canary/mcp/health` is the canary's liveness
  and its record.
- A tier's protected-resource path is not routed: it gets the proxy's 404, and a
  tier is reached with keys.
- `tier-off` (25) answers everything else under `/canary` or `/working` with
  `not-served`'s 404. Without it, `POST /canary/` fell to `legacy` and reached
  stable's server.
- The backends are named by rooted mesh names: `mcp.ob1.internal.` for stable's
  server, where `http://server:8000` used to be.
  - Compose aliases each container under its service name on every network it
    joins. With a canary of another project on stable's mesh, `server` resolved
    to both containers. Docker returns the addresses in no promised order, and
    podman returned them in creation order: with the canary's stand-in already
    on the mesh and stable's recreated after it, 20 of 20 `/mcp` requests
    reached the canary (measured, podman 6, the pinned Traefik).
  - With the mesh name, 20 of 20 reached stable, and `/canary/mcp` 20 of 20 the
    canary.
- The proxy's comments, `deploy/README.md`'s service and path tables, and the
  ADR's route row say so.
- Every "network move (SMD-2294)" now names SMD-2583: the network move is a
  ticket of its own, out of SMD-2294's scope.

**CI.**
- "Every published port binds loopback" holds that the route table's backend
  URLs are exactly the four rooted mesh names.
- A new full-stack step:
  - checks that `/canary/mcp`, `/working/mcp` and the rest under both prefixes
    are bodiless 404s with no tier up;
  - runs a stand-in per tier on `open-brain_mesh` (the server image's bun, under
    the tier's name and under `server`), each answering its own route, while
    stable's `/mcp/health` answers `ok` 20 times;
  - checks that each route is a 404 again once its stand-in is removed.

**Measured.**
- The route table on the pinned Traefik with stand-ins answered as designed:
  - `/canary/mcp/health` reached the canary, and an absent working tier was a
    bare 404;
  - `/canary`, `/canary/`, `/canary/x` and `/working/` were bare 404s;
  - `/canary/%6dcp/health` and `/canary//mcp` reached the canary;
  - `/canaryx` and `/CANARY/mcp` went to legacy, as `/MCP` does today.
- The new CI step passed against a scratch stack built from this checkout
  (`-p ob1-2294`, host Ollama).
- Seven mutants, each killed:
  - no `tier-off`;
  - no `tier-absent`;
  - the canary router sent to stable's server, to working, and working's to
    the canary;
  - working's router gone;
  - the bare `server` backend. The static check kills it; under podman's fixed
    address order the runtime step does not.
