## Changelog

The proxy routes `/canary/mcp` and `/working/mcp` to that tier's MCP server, reached by name on the stack's mesh (`mcp.canary.ob1.internal`, `mcp.working.ob1.internal`), and answers a bodiless 404 while no such tier is up. Every other path that starts with either word is a 404 too, in any letter case and whatever follows, never stable's server. The proxy now dials stable's own server by its mesh name, `mcp.ob1.internal`, so another project's container on the mesh, which compose also calls `server`, cannot take stable's traffic while it claims only its own tier's names (SMD-2294).

## FORK

The tier routes — stable's proxy reaches a canary or working tier on its mesh at /canary/mcp and /working/mcp, and never sends a tier's URL to stable (SMD-2294)

SMD-2294 moves the canary and working tiers from host ports (8010–8012) onto
paths of stable's one origin. It lands in three cuts:
1. stable's proxy carries the tier routes (this cut);
2. `deploy/canary.sh` stands the canary at `/canary/mcp`;
3. `compose.tiers.yaml`, `--compare` and the docs.

Each tier's MCP server is today's server-portable, beside its own REST core. SMD-2287's server replaces it by changing only the service the routes name.

**What changed.** In `deploy/compose.yaml`'s `x-proxy-routes`:
- `canary` and `working` (priority 30, beside `mcp`) send `/canary/mcp` and
  `/working/mcp`, and everything under each, to `mcp.canary.ob1.internal.` or
  `mcp.working.ob1.internal.` on `mesh`, prefix intact. Along the way:
  - `not-legacy` deletes a client's legacy marker;
  - `tier-absent` (an errors middleware, as `auth-absent`) turns Traefik's 502
    into the bare 404 of a path nothing serves. That 502 comes from no such name
    on the mesh, or from a tier that is stopped or still starting.
- `/canary/mcp/health` is the canary's liveness and its record: the server
  answers `/health` under any prefix.
- A tier's protected-resource path is not routed, so a tier is reached with keys
  (OAuth per tier is SMD-2286's).
- `tier-off` (25), ``PathRegexp(`(?i)^/(canary|working)`)``, answers every
  other path that starts with either word with `not-served`'s 404, in any case
  and whatever follows. There is no boundary after the prefix: the three tried
  each let some character through to stable (review passes 2–4), and nothing
  stable serves starts with either word. A typo of the prefix itself
  (`/canry/mcp`) still reaches legacy until SMD-2532.
- Every backend is a rooted mesh name: `mcp.ob1.internal.` for stable's server,
  where `http://server:8000` used to be.
- The proxy's comments, `deploy/README.md`'s service and path tables, and the
  ADR's route row say so.
- Every "network move (SMD-2294)" names SMD-2583, the network move's own
  ticket.

**Why.**
- Compose aliases each container under its service name on every network it
  joins. With a canary of another project on stable's mesh, `server` resolved
  to both containers. With the canary's stand-in already there and stable's
  server recreated after it, 20 of 20 `/mcp` requests reached the canary
  (podman 6, the pinned Traefik). With the mesh name, 20 of 20 reached stable.
- Without `tier-off`, `POST /canary/`, `POST /CANARY/mcp` and
  `POST /canary%2Fmcp` and a canary URL with an invisible space pasted after
  `canary` fell to `legacy` and wrote to stable's brain with the same key: a
  canary runs on stable's env file.

**Held.**
- "Every published port binds loopback" holds the backend URLs to exactly the
  four rooted mesh names, and `compose.api-public.yaml`'s to
  `api.ob1.internal.`.
- "The tier routes reach a tier on the mesh, and nothing else under its
  prefix":
  - With no tier up, `/canary/mcp`, `/working/mcp` and the rest of both prefixes
    are bodiless 404s (`/canary`, `/canary/`, `/canary/health`, `/canary/mcpx`,
    `/CANARY/mcp`, `/Canary/mcp/health`, `/canary%2Fmcp`, `/CANARY%2Fmcp`,
    `/canary;x`, `/canary%E2%80%8B/mcp`, `/canary%5Cmcp`, `/canaryx/mcp`,
    `/working`, `/working/`, `/working/x`, `/working/mcpx`, `/WORKING/mcp`).
  - The proxy logged no route-table or configuration error: a router whose rule
    does not compile is dropped, and its paths fall to the next router. An
    errors middleware's line about a client Host it cannot parse is excluded.
  - A stand-in per tier runs on `open-brain_mesh`, under its tier's name and
    under `server`. Each is reached by its own route with the client's Host and
    no legacy marker.
  - Its own 401, 404, 429, 500, 503 and 504 come back with their bodies and
    headers; only its 502 becomes the proxy's 404.
  - The rest of both prefixes stays a 404 beside the stand-ins.
  - An IPv4 lookup from the mesh shows `server` naming more than one container.
    That collision is what the static check guards.
  - Each route is a 404 again once its stand-in is gone.

**Measured after.**
- On the pinned Traefik:
  - `/canary/%6dcp/health` and `/canary//mcp` reach the canary;
  - `/%43anary/mcp` is decoded before matching and gets the 404;
  - an invalid escape (`/canary%zz`) is Go's 400 before any route;
  - `/canry/mcp` goes to legacy, until SMD-2532 closes that route.
- A real second compose project on stable's mesh (review pass 1, run-it):
  - `/canary/mcp/health` answered `tier: "canary"` keyed, and `tools/list`
    returned the tool list;
  - stable's server, recreated with the canary there, kept `/mcp` 20 of 20.
- The routes pass a client's `x-brain-forwarder`, `?key=` and Host. A stopped
  tier, an absent one, and one with nothing listening each get a bare 404 in
  about 3 ms.
- Server-sent events streamed live through `tier-absent` (measured, not held in
  CI; CI's streaming check runs on `/mcp`).
- `canary.sh`'s own proxy still reaches its own server by the mesh name, on the
  canary project's mesh (review pass 2, run-it).
- The step passes against a scratch stack from this checkout (`-p ob1-2294`)
  with a real key, three runs in a row, about 11 s each.
- Twenty-two mutants of the route table, each killed:
  - `tier-off` gone, case-sensitive again, without `working`, with pass 3's
    boundary `(/|%|;|\z)`, with a non-alphanumeric boundary, or with a regex
    that does not compile;
  - `tier-absent` gone, or widened to 500–599, to 404, to 504, to 401–403 or to
    429;
  - `not-legacy` gone from either tier;
  - the canary router sent to stable's server or to working, and working's to
    the canary;
  - working's router gone;
  - either prefix without its slash;
  - `passHostHeader: false`;
  - the bare `server` backend, which only the static check kills (podman returns
    the addresses in a fixed order).
- The `/api` overlay dialling `http://api:8000` is killed by the static check.

**Not taken.**
- A CI hold on the proxy's `dns_search: ["."]`. The rooted names the static
  check holds already skip search domains.
- A boundary after the prefix: `/canaryx` reaching stable is worth nothing,
  and every boundary tried leaked.

**Follow-ups.**
- SMD-2583: the network move. It also covers the upstream lookup of an absent
  name (fixed by a proxy on internal networks only, shown with a decoy
  resolver in review pass 2) and n8n's `server:8000`.

PR 2 must avoid the traps pass 1 found:
- the canary joins stable's mesh under a network key of its own, with only its
  tier's names (redefining `mesh` would split `/mcp`, `/api` and `/auth`);
- it resolves stable's `auth.ob1.internal`, so it must not advertise OAuth;
- stable's mesh name comes from stable's project; stable's `down` leaves the
  mesh while a canary is attached; the `--port` fallback needs its own port;
  the canary's route is a 404 for about 10 s while it migrates.
