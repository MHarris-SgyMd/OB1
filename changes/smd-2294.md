## Changelog

The proxy routes `/canary/mcp` and `/working/mcp` to that tier's MCP server, reached by name on the stack's mesh (`mcp.canary.ob1.internal`, `mcp.working.ob1.internal`), and answers a bodiless 404 while no such tier is up; every other path that starts with either word is a 404 too, never stable's server. The proxy dials stable's own server by its mesh name, `mcp.ob1.internal`, so another project's container on the mesh, which compose also calls `server`, cannot take stable's traffic. `deploy/canary.sh` stands the canary there: its MCP server and REST core join stable's mesh under the canary's names alone (`deploy/compose.canary.yaml`), its connector is `/canary/mcp` on stable's origin, and beside a stable from before this release, `--port N` gives it its own loopback proxy as before. `deploy/compose.tiers.yaml` serves its three tiers the same way, each tier's MCP server and REST core behind one proxy on `SERVER_PORT`: clients of its old ports (8010–8012) move to `/mcp`, `/canary/mcp` and `/working/mcp` there, and its `*_SERVER_PORT`/`*_SERVER_BIND` settings are gone. `--compare` labels a URL by host and path (SMD-2294).

## FORK

The tier stack on proxy paths — the canary answers at /canary/mcp on stable's origin, its servers on stable's mesh, and a tier's URL never reaches stable (SMD-2294)

SMD-2294 moves the canary and working tiers from host ports (8010–8012) onto
paths of stable's one origin, in three cuts. Each tier's MCP server is today's
server-portable, beside its own REST core; SMD-2287's server replaces it by
changing only the service the routes name.

**PR 1 (#314) — the routes.** In `deploy/compose.yaml`'s `x-proxy-routes`:
- `canary` and `working` (30) send `/canary/mcp` and `/working/mcp`, and
  everything under each, to `mcp.<tier>.ob1.internal.` on `mesh`, prefix
  intact, with `not-legacy`. `tier-absent` turns Traefik's 502 (no such name, a
  stopped or starting tier) into a bare 404. A tier's own 4xx and 5xx pass.
  A tier's protected-resource path is not routed: keys only (OAuth per tier is
  SMD-2286's).
- `tier-off` (25), ``PathRegexp(`(?i)^/(canary|working)`)``, answers every
  other path starting with either word, in any case and whatever follows,
  with a 404. Without it, `POST /canary/`, `/CANARY/mcp`, `/canary%2Fmcp` or
  an invisible space pasted after `canary` fell to `legacy` and wrote to
  stable with the same key. No boundary after the prefix: three were tried
  and each leaked (review passes 2–4). `/canry/mcp` still reaches legacy until
  SMD-2532.
- Every backend is a rooted mesh name, `mcp.ob1.internal.` for stable's server.
  Compose aliases a container under its service name on every network it
  joins: with a canary stand-in on the mesh and stable's server recreated
  after it, 20 of 20 `/mcp` requests reached the canary as `server` (podman 6).
- Held by CI: the backend URLs held to the rooted names (static); a full-stack
  step with a stand-in per tier (17 off-prefix 404s, Host, legacy marker,
  status pass-through, `server` naming several containers from the mesh, 404s
  again once gone); a guard on route-table errors in the proxy's log.
- Measured: 22 route-table mutants killed (the bare `server` backend by the
  static check alone); a real second project on stable's mesh answered
  `tier: "canary"` while stable kept `/mcp` 20 of 20; SSE streams live through
  `tier-absent` (not held in CI); an absent tier's name is forwarded upstream
  by the default network's resolver (shown with a decoy; SMD-2583).

**PR 2 (#316) — `canary.sh` at `/canary/mcp`.**
- `up` answers on stable's origin (`http://<stable's bound address>:<port>/canary/mcp`)
  when stable's running proxy carries the route (its `ob1.proxy-routes` label)
  and is on its mesh. Otherwise it refuses, unless `--port N` gives the canary
  its own loopback proxy as before. Moving back removes that proxy last, after
  the smoke and the connector step, so a failed run keeps the connector at its
  port the canary's to move.
- `deploy/compose.canary.yaml` joins the canary's `server` and `api` to
  stable's `<project>_mesh` (external), under a network key of its own, with
  only `mcp.canary.ob1.internal` and `api.canary.ob1.internal`; the REST core
  is always the canary's own. With no profiles it advertises no OAuth, and
  dials only `*.canary` names.
- A connector is the canary's at `/canary/mcp` on loopback or stable's bound
  address, or at a canary proxy's port, never at stable's `/mcp`; a mode switch
  without `--connect` names one left behind. `up` says when the canary is
  reached past loopback (stable's bind, `OB1_PUBLIC_ORIGIN`).
  `--stable-project` must be a compose project name (a blank one matched every
  project's containers).
- Held by CI:
  - the overlay rendered as the canary project;
  - the refusals: an old stable, its proxy off its mesh, empty and blank values,
    an invalid project name, and with `--port`, the port refusals;
  - three `up`s: path mode (tier `canary`, OAuth off, its names alone, the
    public-origin note), the `--port` fallback (smoke failing under the wrong
    model), and back (the proxy removed after the connector step, the old
    connector named).
- Measured on a scratch stable beside the dogfood: 11 of 11 with the vector
  probe; every mode switch; review pass 4 simulated both CI steps line for
  line, all passing.

**PR 3 — the three-brain stack, `--compare` and the docs.**
- `deploy/compose.tiers.yaml` gives each tier its MCP server (`<tier>-server`)
  and its REST core (`<tier>-api`, the server's image as `api.ts`, one
  environment block), behind one proxy, the stack's only port
  (`SERVER_BIND`/`SERVER_PORT`): `/mcp` to `mcp.ob1.internal.`, `/canary/mcp`
  and `/working/mcp` to the tiers' mesh names (404 while one is stopped), the
  rest under either prefix a 404, `/health` stable's. No legacy window,
  authorization server or `/api`: the root, `/.well-known` and `/api` are 404s.
  Nothing public routes to a REST core. The proxy waits on no tier, so a tier
  whose migration fails is a 404 while stable serves (`up` still exits 1). The
  `*_SERVER_PORT/BIND` knobs are gone.
- `db/brain-compare.ts` labels a URL brain by host and path, so `…/mcp` and
  `…/canary/mcp` on one origin no longer read alike.
- Docs: deploy/README.md, db/README.md, `.env.example`, the ADR. No
  `:8010`–`:8012` remains in `deploy/` or `db/`.
- Held:
  - check 13's inventory (the proxy alone);
  - test-server's grace check (eight servers);
  - test-brain-compare (125);
  - check 27: the file, parsed and x-* anchors aside, equals the stack
    generated from compose.yaml and the tier list (every value compose.yaml's,
    renamed to the tier where it names one, what it leaves out named; the
    route table byte for byte, with no comment in it, since Traefik renders it
    as a Go template), and its raw text is one file to compose and Bun.YAML
    (no control, format or separator character but space and line feed, no
    `!` or `%` directive outside a comment, no YAML 1.1 number); each rule the
    only catch of one of 29 probes;
  - CI's rendering: one loopback port on compose.yaml's pinned image.
- Measured on a scratch run (`-p ob1-2294-tiers`): each path answered its own
  tier's keyed `/health`; each REST core answered `whoami` on the mesh with its
  own agent; the other paths were 404s; `tier.sh --refresh` copied stable into
  canary on the stack's network; `--compare http://…/mcp http://…/canary/mcp`
  reported `tier: a=stable b=canary` under the two labels.
