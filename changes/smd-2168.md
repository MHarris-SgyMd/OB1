## Changelog

The session-capture hook marks a redacted summary's thought with `metadata.redactions` — the count of secrets blanked from it — riding in `capture_thought`'s `metadata` argument; a clean summary's row is unchanged, and a server that refuses the key gets the summary posted without it (SMD-2168).

## FORK

The session-capture hook records how many secrets it blanked on the thought itself, in `metadata.redactions`, where before the count lived only in the log and the text's markers (SMD-2168)

**What changed.** `recipes/session-capture-hook/session-capture.mjs`:
`postCapture` builds one `metadata` object for `capture_thought` — the
`summary_model` SMD-2014 already sent when a model wrote the summary, and now
`redactions`, the COUNT of secrets blanked from the text (`payload.redactions.length`),
never the reasons or offsets, which the text's `[redacted:…]` markers already
name. A summary with nothing blanked and no model carries no `metadata`, so its
row is exactly as before. `metadata.source` stays the harness, so a reader and
SMD-1297's per-source weight still tell a model summary from a derived one and,
now, a redacted one from a clean one. `verdictOf` learns one more mend: a
refusal naming `metadata` — a reserved-key clash, or a brain from before
SMD-2014 took the argument — is met by dropping `metadata` and posting the
summary anyway, as a refused pointer is dropped; the note says `metadata
dropped`. The count is a nicety; the summary is the point. The recipe README
says the thought carries the count now, where it said the marker was "not yet"
on the metadata.

**Why.** SMD-2127 blanks a single-line secret and sends the summary, but the
count lived only in the log line and in the text's markers; a reader, and
SMD-1297's per-source weighting, could not see from the row that content was
removed. `capture_thought` took no `metadata` when SMD-2127 landed, so the
count had nowhere to go — SMD-2127 filed this as a follow-up. SMD-2014 has
since added the `metadata` argument, so the count now rides on it.

**Held.** `recipes/session-capture-hook/test-session-capture.mjs`, 648
assertions (641 before). A redacted capture sends `metadata.redactions` as the
count alone — the arm asserts the object is exactly `{"redactions":2}`, with no
reason or offset in it; a clean capture sends no `metadata`, so its row is
unchanged; a model summary that was also redacted carries both `summary_model`
and `redactions`; a server that refuses the `metadata` key (a new
`[[refuse-metadata]]` on the fake, prose only as the real server's metadata
refusal is) is mended — the hook drops `metadata` and re-posts the same
summary, the note saying `metadata dropped`. Three mutants, each alone: the
count replaced by the reasons, `metadata` sent on a clean capture, the metadata
mend removed. `check-fork-consistency` PASS.

**Review passes.**

| Pass | Finding | Caught by | Fix |
|---|---|---|---|
| 1 | the metadata mend lived only on `verdictOf`'s prose path; a later server that CODED its metadata refusal (`structuredContent.code`) would fall through unmended and the summary be lost, not re-posted metadata-free — a forward-compat gap, not a live bug (today's server refuses metadata in prose alone) | cold read (independent reviewer) + run-it (verdictOf on a coded metadata refusal) | the structured path reads the same `/metadata/` from the prose beside the code, so both paths mend it; teeth in the verdictOf block |
| 2 | pass 1's structured `/metadata/` fallback was not gated on the refusal being FINAL, where the prose path gates on `isRefused` — a retryable transient whose prose merely mentioned metadata would be classified a metadata mend and drop metadata on a kept transient (forward-compat asymmetry, no live server transient says metadata) | cold read (second reviewer, and the author) + run-it (verdictOf on a retryable coded result with metadata prose) | the structured arm is gated on `sc.retryable !== true`, mirroring the prose path; a tooth pins a transient+metadata to mend null |

**Not taken.** Dropping only the offending metadata key rather than the whole
object: neither `redactions` nor `summary_model` is reserved and both pass the
shape check, so the only refusal the fork's server raises is a brain from before
the argument rejecting all of it — where dropping all is right; a partial-key
refusal cannot arise. Editing SMD-2127's landed fragment to strike its
"Follow-ups: SMD-2168" line (the ticket asked): a shipped record is history —
SMD-2127 did defer this — so it stays, and this record closes the loop instead.
A `redacted: true` flag beside the count: the count is `> 0` exactly when a
redaction happened, so the boolean is redundant.

**Upstream status:** not sent — the hook is the fork's (SMD-1989), and
`capture_thought`'s `metadata` argument is the fork's (SMD-2014).
