# 538. Thought-enrichment's backfills leave the SQL shim for `db/backfill-metadata.ts` — weekly-digest holds back what the sensitivity patterns rate (SMD-3318)

SMD-3216 retires `compat/supabase-sql`; its 2026-10-22 decision ports three maintenance scripts to `db/` scripts on Bun's Postgres client. SMD-3318's PR 1 (brain-backup's export, `db/backup.ts`) and PR 2 (lint-sweep's tiers 1 and 2, `db/lint-sweep.ts`) shipped in v2.1.0 as change 530. This is PR 3a: thought-enrichment's type and sensitivity backfills. Its enrichment is PR 3b's, as SMD-2298's re-tag worker, and lint-sweep's Tier 3 is PR 2b's.

**What changed.** Decided 2026-11-15 (maintainer): all three of thought-enrichment's scripts are ported, PR 3a the two backfills and PR 3b the enrichment as SMD-2298's re-tag worker, not a second re-tag path; and, after review pass 1 (2026-11-16), the tiers and types go where every reader looks: the metadata key, the column where `schemas/enhanced-thoughts` added it, and `db/weekly-digest.ts` filtering on the key when a brain lacks the column (it refused to run there, so the key protected nothing); and, after review pass 2, the digest holding back what the backfill's patterns (`db/sensitivity.ts`, shared) rate over each row's whole text, since the capture tags no tier; and, after review pass 3, those patterns hardened rather than the digest refusing again: the text read NFKC-folded with zero-width characters dropped, a password after `_`, in JSON or as `passwd`/`pwd`, hyphenated and other providers' keys, an SSN with spaces or dots, `financial_amount` linear; the digest reading the type, topics and tags it sends, holding back a row its second read misses, trimming any white space round a tier, and finding the column in the catalog (a column the role may not read refuses the run); a PIN four to eight digits; a card number one separator throughout; a `token:` no placeholder; a diagnosis the verb, not the word; the 64-hex rule reading the text with its URLs blanked, as the hook runs it; the Arabic letter mark and the tag characters dropped. `db/backfill-metadata.ts` reads `thoughts` by its primary key, a page (`--batch`, 500) a statement under `--statement-timeout` (60 s), and writes a row in one transaction: its keys in one `update_thought` call (one audit event; `if_unchanged_since` on `COALESCE(updated_at, created_at)` leaves a row written since its page was read for the next run), then its columns. Metadata that is not a JSON object has its keys counted, not written. The **type** pass writes a `metadata.type` the capture would have written otherwise (another case or spacing, or an alias) as the capture's type, by its rule, now `server-portable/thoughts.ts`'s `canonicalType` beside `normaliseType`, an alias's words in `type_raw`; a type naming none of the capture's, and a row an importer owns (trust `ingested`), are counted and left; the `type` column takes the old rule on the type as the capture names it (`reference` becomes one of the old eight; `Task` and `todo` now set it), an importer's row's included; a column's write alone records no audit event, as the old scripts' did not. The **sensitivity** pass reads a thought's text against the sensitivity patterns (`db/sensitivity.ts`), and each place takes the highest of their tier and the other place's when higher than what it says (absent, empty and `standard` lowest, in any case), so the key and the column agree; a tier is never lowered, an unknown one left, and no thought's text is printed (the recipe printed the first 80 characters of every restricted thought, and of the first 30 it scanned). Without `--apply` nothing is written; `--pass` runs one pass, `--limit` stops after that many rows written. `canonicalType` reads own keys alone: `normaliseType("constructor")` had returned `Object`'s own function as the type. The two scripts, `lib/sensitivity-patterns.mjs` and `sensitivity-patterns.json` are removed; the recipe's README points at the script; [29] keeps `enrich-thoughts.mjs`'s cases. The removed scripts are vendored code, outside the version contract, so this is a `minor` with an Upgrading line.

**Not taken.** An importer's re-import still lowers the metadata key it writes (the column, where it exists, keeps the tier). The patterns stay a denylist: a homoglyph, digits of another script or a secret in prose without a digit or a symbol gets past them, and a harmless line shaped like a secret is still held, with no per-row override; a check that proves a row safe is a design of its own. The hook's entropy rule is not copied: it reads any 32-character mixed run, ids and hashes included, and a backfill would make each hit permanent. The hook's own URL-with-a-password and 64-hex rules are left as they are, so the copy stays the hook's (review pass 5's measurer proposed narrowing both).
