## Changelog

The root connector URL (`http://127.0.0.1:8000/?key=…`, `https://host/?key=…`) is deprecated: `/mcp` replaces it. Through the proxy's legacy route the root still answers until **v2.0.0**, and no sooner than two weeks after this release. Every answer there carries a `Deprecation` header and a `Link` to the upgrade guide, `deploy/README.md` "Moving a client to /mcp". The server logs a line the first time each key name reaches it on the root, from an MCP client or a keyed REST call (`compose logs -t server | grep 'old root URL'`). `scan_thoughts` handles link under the endpoint the call came to (`/mcp/jobs/<id>`), and the proxy's `health` route takes `OPTIONS`. Removing the root is a MAJOR change, and FORK.md's versioning rules now say so. No schema change (SMD-2306).

## FORK

The root connector URL gets a compatibility window that closes with 2.0.0 (SMD-2306)

**What changed.**
- **The legacy router.** In `deploy/compose.yaml`'s `x-proxy-routes`, the `legacy` router gains a `legacy-window` headers middleware:
  - every answer gets `Deprecation: @1790899200` (RFC 9745: deprecated since 2026-10-02, the day it was decided, not this release's date) and `Link: <…/deploy/README.md#moving-a-client-to-mcp>; rel="deprecation"; type="text/html"`;
  - every request it forwards is marked with `X-OB1-Legacy-Route: 1`.
- **The marker elsewhere.** The `mcp` and `health` routers delete the marker (`not-legacy`), so a client cannot set it on `/mcp` and get logged.
- **OPTIONS on health.** The `health` router takes `OPTIONS` beside `GET`/`HEAD`. A browser's CORS preflight for a keyed `GET /health` is the server's, and must not reach the legacy route.
- **The server's line.** `server-portable/index.ts` `noteLegacyRoute` logs `legacyRouteLine` once per key name per process, for a marked request whose key passed its route's check and was not revoked. Every keyed route calls it: the MCP endpoint, `/health` under a prefix, `/worker-status`, the three worker actions and `/jobs/<id>`, so a script polling the root is named as an MCP client is. The line names the key, the method and the path: the raw, still-encoded path, JSON-quoted and cut at 200 characters, so a client cannot write a key's name into it (review pass 1: through Hono's decoded path, a `%22` did); never the key itself, never the query.
- **Job links.** `scan_thoughts` builds its handle's `poll` and `stream` under the raw path the call came to (`jobs.ts` `atEndpoint`), its repeated slashes collapsed at the call in `index.ts`: a `//x` path made a `//x/jobs/<id>` link, which a client resolves as host `x` (review pass 2). Behind the proxy that is `/mcp/jobs/<id>`; a root-relative link reached the server only through the route being retired. Its tool description says so. The server's CORS headers expose `Deprecation` and `Link` beside `Retry-After`, so a browser-hosted client can read the window off a legacy answer.
- **The upgrade guide.** `deploy/README.md` gains "Moving a client to /mcp":
  - the old URL and the new one for each kind of client;
  - finding the clients still on the root, from the server's line and from the access log's `RouterName`;
  - the sign-in prompt a revoked key meets once SMD-2382 lands;
  - the re-enrolment a change of public origin costs.
- **The smoke.** `deploy/smoke.sh` check 11 probes the root, keyless: the refusal carries both headers, and a keyed probe put the smoke key's name in the log an operator reads for clients still to move (review pass 1).
  - Run with no URL, so against this stack's own proxy, it expects 200 with both headers, or the proxy's 404 from a server at 2.0.0 or later.
  - Given a URL, it reports the root without counting it: any Traefik in front sends the same 404 body, and a server with no proxy in front rightly answers at every path.

**Why.** SMD-1846 (decided in SMD-2282) moved the MCP endpoint to `/mcp` behind one proxy, and every client configured before it holds the root. SMD-1846 kept the root answering through `legacy`. Without a deadline and a signal, that route stays a second MCP endpoint forever, and its removal breaks every client at once with no warning.

**The version decision.**
- The proxy landed as MINOR in 1.5.0, because the legacy route kept every URL answering.
- This window is MINOR: no schema change, but marking a public surface deprecated is MINOR under SemVer §7, and FORK.md's MINOR rule now names it.
- Closing it is MAJOR. FORK.md's MAJOR rule now names a URL or transport a configured client uses.
- The window lasts until 2.0.0, and at least two weeks after this release. At a release every two or three days, "N releases" would have been days.
- There is no `Sunset` header until 2.0.0 has a date. SMD-2532 removes the router.

**Detection by marker, not by path.** The server answers POST at every path, so a server with no proxy in front (SETUP.md's single container) serves its clients at `/`, correctly. Logging every non-`/mcp` request would have named all of them.

**Not done here: the onboarding docs.** SETUP.md, `docs/01-getting-started.md`, `docs/03-faq.md`, the GPT context file, `recipes/life-engine`, the session-capture hook's README and messages, `primitives/remote-mcp` and the SvelteKit dashboard's README still give a new client the root URL, so until they move the window gains clients. They are this ticket's PR 2, to land before the release that carries this one.

**Not done: a second entrypoint on the old host port.** The ticket offered one. The proxy publishes the same `SERVER_PORT` the server did, and the tier stack's 8010/8011 are unchanged, so no client's port moved.

**Measured.** On a scratch stack, six proxy mutants each failed smoke's default run or the step's lines: no window middleware, `/mcp` or `health` keeping the marker, `health` without `OPTIONS`, the `Link` dropped, the legacy router gone before 2.0.0. Twelve server mutants each failed their suite: no once-per-name set; the links left root-relative, decoded, or with `//` kept; no call on `/worker-status`, health, the worker actions or `/jobs`; the call before `canWrite`, before the identity check, or before the revoked refusal; the decoded path in the line. The `//` case is a raw request-target: `fetch` collapses a leading `//` itself, so through it the test passed with the collapse removed. Review pass 1 (cold read, run-it, walkthrough) also measured: SSE on the legacy route stays unbuffered under the headers middleware (keepalive 5.02 s, result 6.03 s), and no spelling of the marker (case, `_` alias, duplicate, padded) reaches the server on `/mcp` or `/health`.
