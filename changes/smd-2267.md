## Changelog

`node_state`'s dependency columns read the ids they are asked for: migration 069 stores `node_dependencies()`' gate as `ob1_source_gate` (each source row's system and whether its thought states a known status), fed by triggers on `thought_sources` and `thoughts`, reads a ticket's links by index from the ids, and has `source_thought()` find the board sync's claim by 068's issue index — so `node_state(<ids>)` costs its ids' links, not the brain, and a whole-brain read no longer pays a GIN scan per blocker the brain does not hold; signatures and rows unchanged, the capture group gains the writes on the new table, a source write or a status move between a known and an unknown `status_type` is refused under REPEATABLE READ; roles granted before 069 need `migrate.ts --grant` again (SMD-2267).

## FORK

node_state's dependency columns read the ids asked for: the gate stored, the links probed (SMD-2267)

**What changed.** `db/migrations/069_node_dependencies_keyed.sql`:
`ob1_source_gate` — one row per `thought_sources` row, its system and whether
its thought's own `status_type` is known (058's gate, per row; a mirror, not a
count per system, since a cascade delete cannot decrement a count), a partial
index on the system where it gates. Statement triggers keep it: on
`thought_sources`, an INSERT upserts in one statement reading each thought
under FOR SHARE, an UPDATE of the system or the thought locks FOR SHARE and
reconciles (a canonical-only re-record returns at once), a DELETE drops by key
and reads nothing else (a cascade's trigger runs as the caller, so a capture
role still deletes a sourced thought), TRUNCATE empties it; on `thoughts`, an
UPDATE moving a status between known and unknown sets the row, any other write
returns at once. A source write and a status move of one thought meet on its
row — no advisory lock, nothing ordered against 068's classes; REPEATABLE READ
is refused for either, SERIALIZABLE left to SSI. `ob1_rebuild_source_gate()`
(READ COMMITTED only) and drift()'s `source_gate` arm. `node_dependencies()`
joins the gating systems. `ob1_system_gates(text)` probes the partial index
(`SET enable_seqscan = off`, not inlined: inline, the planner hashed the whole
mirror, or scanned it per link for a system that never gates).
`source_thought()` keeps its results and finds the board sync's claim by 068's
issue index — jsonb equality of the two keys, which is what containment of a
top-level scalar is, a NULL identity keeping 053's form — not 001's GIN index.
`ob1_node_dependencies_of(ids)`: for ids, each ticket identity's links from
both ends by 053's indexes, the gate, each blocker by primary key behind
OFFSET 0; for NULL, 068's whole-brain read — two branches behind one-time
filters under one `GROUP BY thought_id`, dropped by a caller that reads none
of the columns. `node_state()` joins it once; signatures and rows unchanged.
The capture group gains the four privileges on the table (re-run `migrate.ts
--grant`); preflight's write-privileges and isolation rows name 069. The
README, the ADR, graph-centrality's comment and the bench's arm follow.

**Why.** After 068 the lifecycle and `superseded_by` were lookups and the
dependency columns — `blocked`, `blockers`, `unknown_blockers`,
`in_dependencies` and `node_dependencies()`' gate — were still whole-brain reads
on every call: `node_state(<40 ids>)` resolved every link and blocker of the
brain and kept forty rows. Of three shapes (every ticket's blockers stored, fed
by the links, the source rows and 068's heads; the gate alone stored and the
rest probed; SMD-1997's fold) the maintainer chose the second (2026-09-28): the
gate is the one answer that is not local to a few rows near the ids, a
blocker's status is already a lookup since 068, and a ticket's links are two
index probes, so nothing else needs invalidating when a blocker's head moves.
The resolver and the gate's helper were found by the bench: on a brain where
two links in three name a ticket it does not hold, 053's resolver made main's
keyed read take 6.5 s at 10,000 thoughts and 656 s at 100,000, and the keyed
read here 47 ms until the resolver moved to the issue index; a system that never
gates then cost 70 ms for forty of its ids until the gate became a probe.

**Not taken.** Every ticket's blockers stored (a trigger on the links, the source
rows and 068's heads, and a blocker's head moving fans out to every ticket it
blocks — the maintainer's choice, above). A count per system (a cascade delete
cannot decrement it without a mirror, and with one every source writer of a
system would queue on its row). An advisory lock class for the gate (it would
order against 068's three; the thought's row already serialises the two
writers). An `ORDER BY` on the gate's probe to steer the planner to the index
(it drops a sort key the WHERE fixes).
