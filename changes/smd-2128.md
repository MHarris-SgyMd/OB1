## Changelog

smart-ingest writes a thought through the fork's 3-argument `upsert_thought` — the vector as `p_embedding`, its model's label and the actor in the envelope, the enhanced columns beside it — where it called upstream's 2-argument form with the vector inside the payload, which the fork's function does not read, so every thought the server wrote had no vector, no label and none of the enhanced columns; `schemas/smart-ingest`'s `matched_thought_id` and `result_thought_id` are `uuid`, as `thoughts.id` is here, and `append_thought_evidence` takes one — against `bigint`, no item of a job with a match was ever persisted and no executed item recorded its thought; a revision sets the row's `supersedes` (SMD-2128).

**Not taken.** A foreign key from the two columns to `thoughts(id)`: a `KEY
SHARE` lock on the thought for every item write, and a deleted thought would
null or refuse the item's history — the columns are a record, not a
reference. A checker rule for a vector inside `upsert_thought`'s
payload: one file did it, and the suite's text guard holds that file; a rule
for every file is a ticket when a second does. Skipping the retype with a
NOTICE when a view depends on a column (review pass 1's other option): the
server would run against `bigint` columns with nothing said at the moment
the operator is watching; a named refusal with the fix in it is the cheaper
failure.
