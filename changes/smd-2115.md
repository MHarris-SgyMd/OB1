## Changelog

Migration 054 makes the capture event carry the payload — a capture's content and a backdating writer's `created_at`, an update's key move (`content_fingerprint` before/after) — so the log alone rebuilds every thought's text; 046's diff rule, its append and 050's two stamp arms become functions the triggers call (`ob1_thought_diff`, `ob1_append_thought_event`, `ob1_actor_stamp`, `ob1_actor_stamp_kept`); `backfill_thought_payloads()` fills the capture rows written before, under the third amendment the append-only trigger allows (`ob1.audit_amend = 'payload'`: a capture row's `diff.content` and `diff.created_at` where absent, with what the log and the row derive to, nothing else); preflight's `audit events` counts the rows still waiting and names the pass; the writable-projection prototype calls the shipped rules; step 1 of `docs/event-log-as-truth.md` (SMD-2115).

## FORK

The capture event carries the payload — content, a backdating writer's `created_at`, an update's key move — 046's rules become functions, and a backfill fills the rows already written: migration 054, step 1 of the event-log decision (SMD-2115)

**What changed.** `db/migrations/054_capture_event_payload.sql`: three additions to the audit trigger's diff and no other — a capture's `content` always and its `created_at` when the row's differs from the transaction's `now()` (a defaulted column is not carried; `db/ingest-records.ts`'s backdated record is), an update's `content_fingerprint` `{before, after}` when the key moved (018's NULL for a text another row holds, 023's fill of a legacy key, an edit's recomputation). The rules lifted out: `ob1_thought_diff` (046's diff with the additions; STABLE, since a timestamptz in jsonb renders in the session's TimeZone), `ob1_append_thought_event` (046's tail — the kind from the registry, the trust ceiling, the door, the claim filed, the late gate — returning the row's id or NULL), `ob1_actor_stamp` / `ob1_actor_stamp_kept` (050's new-text and same-text arms); `thoughts_write_audit` and `ob1_stamp_actor` redefined to call them and do nothing else new. The third named amendment: under `ob1.audit_amend = 'payload'` an UPDATE of a capture row may fill `diff.content` and `diff.created_at` where absent, each condition named when it fails (only a capture row; `diff` the fifth column removed from the byte-equal compare under this value alone; no other key of `diff`; a value once set never changed; something filled; the content what `ob1_capture_payload` derives — the first content-moving update's `before`, else the tombstone's `previous_content`, else the live row when no later capture re-took the id; the `created_at` the live row's own, only when it differs from the event's). `backfill_thought_payloads(p_limit)` is the pass (023's shape; candidates through a partial index on the capture rows still without content, in `(created_at, seq)` order; returns `{ok, rows, from_update, from_tombstone, from_row, with_created_at, unrecoverable, awaiting}`), called once by the file under `OB1_BACKFILL_LIMIT`. Preflight's `audit events` gains a rung (046 re-applied over 054 warns naming 054) and a census of the capture rows without content — bounded, each derived, so the line says how many the pass fills and how many nothing derives for (a thought gone without a tombstone: named in the ok line, not a warning carried on every start). The writable-projection prototype (`evals/writable-projection/common.sql`) calls the shipped rules and defines only what step 2 will ship; its baseline passes C1 now. `thought_changes` lists `content_fingerprint` in `changed` when a text moves — a diff key, like `embedding_present`.

**Why.** SMD-1998 measured that the log alone reproduced the text of 217 of 440 live thoughts — only those whose text later moved — and SMD-1999 that a projector needs three things beyond 046's event and nothing else. `docs/event-log-as-truth.md` (SMD-1997) decided the log is the write-side truth in three additive steps; this is the first, and makes the log complete in payload from the day it lands so step 2 (SMD-2116) and step 3 (SMD-2117) have a log to fold. Nothing about the write path moves: the row is still written first and the trigger describes it; no function changes what it returns.

**Measured** on a copy of the dogfood log (631 thoughts, 2,688 audit rows, 632 capture rows without content, 6.0 MB table and TOAST; Postgres 16.15): every row derives — 239 from the first moving update, 1 from a tombstone, 392 from the live row; 222 gain a `created_at`; the apply, the pass over all 632 included, 0.64 s; a second pass fills 0. A raw INSERT of 2,000 rows: 31 µs a row under 046's trigger, 36 µs under 054's (×1.15). The option the ticket left open — seed a replay from the row store — is declined on that measurement.

**Held.** `test-schema.ts` [49]: the shape and the sentinels; a capture's row carries the content and the stamped metadata; a backdated raw insert carries `created_at` and one at `now()` does not; an edit carries the key's move, a metadata edit and a re-embed none; 018's unchanged edit onto a held text records `{before: <stale key>, after: null}`; a raw content edit leaves the key stale and records no move; an identical re-capture writes nothing; 023's fill records the move; the differential — one scripted set of seven events under 046's trigger (re-applied by hand) and under 054's, equal on every column outside the three keys; the payload gate condition by condition on five planted rows (standing, moved, deleted, no row, re-captured id); the backfill bounded, by source, idempotent, its report exact; a re-apply a no-op. `test-upgrade.ts` [20h]: 054 onto a populated 053 fills every waiting row at apply from the right source, writes no event, moves no row; the guard refuses by name without 046 or 050. `test-preflight.ts`: the 054 rung, the payload census with its two counts, the pass as the remedy, the ok line after. `eval-writable-projection.ts --check`: the prototype on the shipped rules, the baseline's C1 recorded PASS. test-schema's `restoreShipped` takes the closure of what a re-applied file defines — a restore of `upsert_thought` re-applied 046 and put 046's trigger back over 054's silently until it did.

**Not here.** The write functions do not append before they write (SMD-2116, blocked on SMD-1723's redaction as well); no function passes a `created_at` (a function-borne backdating capture is SMD-2117's to decide); a row with no capture event is not synthesised (the fold reports the count, SMD-2117); the log's partitioning (SMD-1947); the redaction amendment (SMD-1723).
