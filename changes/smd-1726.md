## Changelog

Every read says who wrote a thought's current text, from the key that made the write: migration 050 stamps `actor_kind` (`operator | agent | ingested`, 046's registry) and `actor_name` into `thoughts.metadata` by trigger, never from the payload; `search_thoughts`, `search_thoughts_keyword` and `list_thoughts` gain `said_by` and `actor` filters on 014's route and print `By: <key> (<kind>)` under each hit; the consolidation judge hears who wrote each side (prompt version 3); `backfill_thought_actors()` marks the rows written before (SMD-1726).

## FORK

Retrieval tells what the operator said from what an agent concluded — the writer on the row, from the key; `said_by` and `actor` as indexed filters and a `By:` line; migration 050 (SMD-1726)

**Premise.** 046 records who holds the key on every audit row, but a read returns the `thoughts` row and its metadata, and nothing there said who wrote it: a hit an agent's summary pass wrote and a hit the operator typed looked identical, and "only what I said" could not be asked. SMD-1716 defers isolation *between* operators; this is the smaller thing — one operator, several keys.

**The writer lives on the row, in metadata, from the key.** Two reserved keys, `actor_kind` and `actor_name`, stamped by a BEFORE trigger (`thoughts_stamp_actor`) from the envelope 008's writers set, through 046's one registry lookup; whatever a payload carried under either key is overwritten or removed. Metadata rather than two columns because 014's route already exists and is measured: `match_thoughts` filters `metadata @> filter` inside the scan over 001's GIN index, and SMD-1490's `filter` argument already reaches it — so `said_by: operator` is `{"actor_kind": "operator"}` on a path with a route estimate, and two columns would have needed their own index and a sixth redefinition of a 700-line function. The column's COMMENT names the two keys the database owns.

**The actor follows the content** — 021's rule for the label. A capture stamps; an edit that changes the text re-stamps from the editor's key (the text is the agent's now, and the audit diff holds the handover); an edit that leaves the text keeps the mark whatever the patch said — a metadata-only edit, a re-capture's merge, a re-embed, 018's unchanged edit. "The same text" is 003's rule, the normalised fingerprint, so a re-spelling of case or whitespace is not a change of writer; the old text is always hashed (its `content_fingerprint` column may be stale after a raw update), the new one only when its column did not move to a value — one hash on an edit through `update_thought`, two on a raw one. A raw write with no envelope names nobody: the keys are removed, as 008 records "a mutation from outside the server". An unclassified key stamps its name and no kind. A metadata that is not an object — a raw writer's array or scalar — passes untouched. The ingester (`ingest-records.ts`) names itself in each record's own transaction (a session-level setting died with a reconnect), so its records carry `actor_name: ingest-records` and 046's door; the kind is the operator's one `set_agent_kind` away.

**Reads.** `said_by` (one of the three words) and `actor` (a key's name) on `search_thoughts`, `search_thoughts_keyword` and `list_thoughts` fold into the metadata filter, so the store, the query log and the plan see one filter, under the filter's own caps; a `filter` naming the same key with another value is refused as a contradiction. Every hit and item prints `By: <key> (<kind>)` — a name with no kind reads "kind not classified", a row with neither prints no line, as an undated row prints no `Captured:`. In `list_thoughts` the line sits under `ID:`, so the content-then-ID adjacency the repo's own e2e suite matched on holds — the ticket's "if something parses the id line positionally, that is a finding": the fork's suite did, and the placement keeps it true rather than breaking it. `fetch` already returns metadata, so the keys ride in it unchanged.

**The judge.** The pair header names who wrote each side when the row's mark says (`, written by the operator` / `an agent` / `ingested from an outside source`; nothing when it does not, so the header is byte-identical to prompt 2's) and a rule says an agent's summary, restatement or inference of what the operator stated is "agree", never a conflict in which the agent's thought supersedes the operator's. The mark is the one metadata value allowed on the trusted header line, because the database wrote it from the key. Prompt version 3: a new pool under a new key, so p2 verdicts are never mistaken for p3's. Not re-measured against evals/README's p1 numbers — the LongMemEval corpus is gone with /tmp (SMD-1898 rebuilds it); said here rather than pretended.

**The backfill** `backfill_thought_actors(p_limit)` reads, for every thought, the latest audit row that changed its text by the trigger's own rule (a capture, or an update whose before/after fingerprints differ) and sets both keys to what it derives — the registry's kind for its id or name *now*, else the `actor_kind` 046 stamped, and its name trimmed as the stamp trims it — wherever the row disagrees: an unmarked row takes its writer, a planted claim (a value, or the two keys as JSON null) is corrected or removed, a stamped row is left alone, a re-apply writes nothing, and a key reclassified by `set_agent_kind` reaches its rows on the next pass (046's audit rows keep the kind they were stamped with — that is history; the mark is a view). "Latest" is decided in three steps: first the update row whose after-text is the thought's current text (hashed from the row, not the `content_fingerprint` column, which a raw update leaves stale) — the row that wrote what stands; the capture stands for the text only when no update ever changed it, and update rows present with none matching means the text was written unaudited and nobody is stamped, as for a thought with no row at all; then `created_at`, newest first; then `seq`, a monotonic identity this file adds to `thought_audit`, for two rows one transaction wrote — `created_at` is `now()`, one value for a whole transaction, and `id` is a random uuid, so those two alone were a coin flip. `seq` is exact for rows written after 050 and heap order for the rows before, which is *not* insertion order once 046's backfill has amended rows and a VACUUM has let later inserts fill the freed pages — ordered by `seq` alone, an agent's rewrite took a smaller number than the operator's amended capture and the pass stamped the operator on the agent's text, 40 of 40 on two upgrade paths. Hence the text first and `created_at` before `seq`. It scans before it locks and re-checks each row under the lock — `updated_at` unchanged, the marks still disagreeing — and takes `thoughts IN EXCLUSIVE MODE` for the write, as 023 does: writers wait for the call, readers do not, and an edit in flight is waited for rather than deadlocked against; the updated_at trigger is held off for the write (a stamp is not an edit; needs the owner). Each row written is an UPDATE 008's trigger records — one audit row per thought, door `backfill_thought_actors`, actor nobody: the record the ticket asks for. Called once by the file under `OB1_BACKFILL_LIMIT`; `p_limit` bounds the rows written and the lock per call, not the scan (every call derives every thought: one probe of 008's `thought_id` index per thought, then two hashes per content-update row — 1.0 s at 100,000 thoughts with 40,000 short content updates; with a tenth of the thoughts at 100 KB the update rows' texts are the cost: 19–22 s a scan, 120 s a first pass, 29 s a second; a lazy anchor that skips capture-only thoughts would save a further quarter of the hashes and was left for a reader that needs it) nor the audit rows (one per row marked, whatever the batch). The identity column rewrites `thought_audit` once at apply, under ACCESS EXCLUSIVE — about a minute per million rows, captures waiting — and the file's locks on `thoughts` come after it, the reverse of a capture's order, so a capture in flight can deadlock the apply (migrate.ts renders 40P01; a re-run applies): apply in a quiet window. Returns `{rows, differing, awaiting}`, `awaiting` the rows whose writer nobody has classified yet — `set_agent_kind`, then run it again.

**Not here, said so.** No index beyond the GIN (the route is the filter's, 037's estimate decides). No preflight census over `thoughts` (SMD-1947's bound question), and no preflight row for a hand-disabled stamp trigger — the ledger names a missing 050, and the updated_at check's shape would cost the catalog-skip count a twentieth entry for a state only a hand can reach. The trust label on the hit: SMD-1724. A 9-argument `update_thought` caller passing no actor (the pre-SMD-1541 shape) erases the mark on a content edit — no envelope, no writer — as 008 records it. The trigger's cost, measured on 100,000-row bulk statements: INSERT +8% with no actor set (was +19% before the inline read), +82% with one (a registry probe per row, the second after 046's audit trigger's); a content edit through `update_thought` pays no hash (the fingerprint column moved between two values: −8% to +6%), a raw content UPDATE two (+83% to +110%); a re-embed or metadata touch +2%. A re-capture whose payload `metadata` is a JSON null or scalar turns the row's metadata into an array through 046's `||` merge (005 guards the payload, not its `metadata`) and the mark is lost with it — pre-existing, filed as SMD-1976 rather than patched into a trigger that is not the writer.

**Version.** MINOR: a trigger, a function and an identity column, additive; every existing call resolves as before; the tool arguments are optional. Migration 050: written as 047, renumbered to 048 when `main` took 047 for SMD-1492's query-log index during review, to 049 when the 1.0.0 cut took 048 for its schema-version file, and to 050 when SMD-1298's capture scope took 049 — the SMD-1749 trap, met three more times in one review. On a ledger-recorded brain, preflight's `schema version` row warns that the ledger reaches 050, past 1.0.0's range, until the next cut: the designed behaviour for a migration landed after a release.
