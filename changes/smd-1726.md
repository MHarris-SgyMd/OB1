## FORK

Retrieval tells what the operator said from what an agent concluded — the writer on the row, from the key; `said_by` and `actor` as indexed filters and a `By:` line; migration 047 (SMD-1726)

**Premise.** 046 records who holds the key on every audit row, but a read returns the `thoughts` row and its metadata, and nothing there said who wrote it: a hit an agent's summary pass wrote and a hit the operator typed looked identical, and "only what I said" could not be asked. SMD-1716 defers isolation *between* operators; this is the smaller thing — one operator, several keys.

**The writer lives on the row, in metadata, from the key.** Two reserved keys, `actor_kind` and `actor_name`, stamped by a BEFORE trigger (`thoughts_stamp_actor`) from the envelope 008's writers set, through 046's one registry lookup; whatever a payload carried under either key is overwritten or removed. Metadata rather than two columns because 014's route already exists and is measured: `match_thoughts` filters `metadata @> filter` inside the scan over 001's GIN index, and SMD-1490's `filter` argument already reaches it — so `said_by: operator` is `{"actor_kind": "operator"}` on a path with a route estimate, and two columns would have needed their own index and a sixth redefinition of a 700-line function. The column's COMMENT names the two keys the database owns.

**The actor follows the content** — 021's rule for the label. A capture stamps; an edit that changes the content re-stamps from the editor's key (the text is the agent's now, and the audit diff holds the handover); an edit that leaves the content keeps the mark whatever the patch said — a metadata-only edit, a re-capture's merge, a re-embed, 018's unchanged edit. A raw write with no envelope names nobody: the keys are removed, as 008 records "a mutation from outside the server". An unclassified key stamps its name and no kind.

**Reads.** `said_by` (one of the three words) and `actor` (a key's name) on `search_thoughts`, `search_thoughts_keyword` and `list_thoughts` fold into the metadata filter, so the store, the query log and the plan see one filter; a `filter` naming the same key with another value is refused as a contradiction. Every hit and item prints `By: <key> (<kind>)` — a name with no kind reads "kind not classified", a row with neither prints no line, as an undated row prints no `Captured:`. In `list_thoughts` the line sits under `ID:`, so the content-then-ID adjacency the repo's own e2e suite matched on holds — the ticket's "if something parses the id line positionally, that is a finding": the fork's suite did, and the placement keeps it true rather than breaking it. `fetch` already returns metadata, so the keys ride in it unchanged.

**The judge.** The pair header names who wrote each side when the row's mark says (`, written by the operator` / `an agent` / `ingested from an outside source`; nothing when it does not, so the header is byte-identical to prompt 2's) and a rule says an agent's summary, restatement or inference of what the operator stated is "agree", never a conflict in which the agent's thought supersedes the operator's. The mark is the one metadata value allowed on the trusted header line, because the database wrote it from the key. Prompt version 3: a new pool under a new key, so p2 verdicts are never mistaken for p3's. Not re-measured against evals/README's p1 numbers — the LongMemEval corpus is gone with /tmp (SMD-1898 rebuilds it); said here rather than pretended.

**The backfill** `backfill_thought_actors(p_limit)` reads, for every thought, the latest audit row that wrote its content (a capture, or an update whose diff carries `content`) and sets both keys to what it derives — 046's `actor_kind` else the registry's kind for its id or name now, and its name — wherever the row disagrees: an unmarked row takes its writer, a planted claim is corrected, a mark no audit row vouches for is stripped, a stamped row is left alone, a re-apply writes nothing. It re-checks `updated_at` on the locked row (018's guard) and holds the updated_at trigger for the write (a stamp is not an edit; needs the owner, as 023). Each row written is an UPDATE 008's trigger records — one audit row per thought, door `backfill_thought_actors`, actor nobody: the record the ticket asks for. Called once by the file under `OB1_BACKFILL_LIMIT`; returns `{rows, differing, awaiting}`, `awaiting` the rows whose writer nobody has classified yet — `set_agent_kind`, then run it again.

**Not here, said so.** No index beyond the GIN (the route is the filter's, 037's estimate decides). No preflight census over `thoughts` (SMD-1947's bound question). The trust label on the hit: SMD-1724. `ingest-records.ts` inserts raw with no envelope, so its rows name nobody until it passes one.
