## Changelog

A `migrate.ts` run now takes a session advisory lock, `ob1:migrate`, before it writes anything, and holds it until it returns: a pending file, a plugin's file or repair, 096's re-run, or `--reapply`. A second run meanwhile is refused by name, exit 2, writing nothing, and the refusal names the backend that holds the lock, with the `pg_terminate_backend` that ends a run that was killed. Before, two runs at once raced on the ledger's rows and the catalog's, and one failed at once on a duplicate key, sometimes as a stack dump. `--dry-run`, `--grant` and a run with nothing to write take no lock (SMD-3379).

The claim workers — `extract-entities.ts`, `consolidate.ts` and `reembed.ts` — take an `admit` gate in-process: awaited before each claim, at the start of each pass, between a long thought's windows and between a consolidation's pairs, so a caller can pause a pass without stopping it, and a stop reaches a waiting worker at once. Nothing passes one yet; a run without one behaves as before (SMD-3379 PR 1b-1). The claim workers' `onPass` now hands the caller `abortInHand(olderThanMs)` beside the pass's stop: it aborts each worker's model call in hand at least that old, puts the thought at the back of the queue — extraction keeping its answered windows and counting the stop — and the worker goes on with its next claim. Nothing calls it yet; a run whose caller does not behaves as before (SMD-3379 PR 1b-2). A worker mid-thought now also reads its claim again after a closure that opened again during its call or a provider pause, where a gate says so (`closedSince`), an extraction retry asking the gate first; `lease.ts`' `liveGate()` is the gate the scheduler is to close (SMD-3379 PR 1c-3a).

The sleep scheduler now waits out a migration in progress at its start, and ends with exit 75 when it sees one while it runs — the migration ledger moved, or `migrate.ts`' lock held at two polls — its passes stopped at once. Its supervisor runs a 75 again at once, no try counted, and the next process waits it out and reads its start again on the new schema; preflight says "restarting after a migration" (SMD-3379 PR 1c-1). Preflight and `brain_info` read a paused scheduler (`paused`) and the passes it holds (`holds`), which no scheduler writes yet (SMD-3379 PR 1c-2). Asleep, a live write now pauses the passes rather than stopping them: they wait between thoughts and go on once `OB1_SLEEP_CAPTURE` seconds (`--capture`, 20) pass with no live write, a model call in hand longer than 60 s aborted meanwhile and its thought set back; paused time is not the clock's, so a busy day's sleep runs longer. Under `--follow` a live write that finds the pools drained, the work it added aside, ends the sleep as before; a one-shot run a live write meets after its sweep pauses and exits 0, where it exited 1 (SMD-3379 PR 1c-3b).

### PR 1c-1: the scheduler restarted on a migration

**What changed.**

### PR 1b-1: the claim workers' admit gate

**What changed.**
- `db/lease.ts`: `Admit` and `admitted(admit, signal)`, the gate a worker waits at, a stop rejecting it; `claimAfterWait`, which reads a claim, its fingerprint and metadata again after a wait (deleted, requeued, lost or moved); `AdmitThrow`.
- `admit` on the three claim workers, awaited before each claim, at each pass's start, before each window sent (extraction, `StoppedBetweenWindows`) and before each pair (consolidation, `StoppedBetweenPairs`); woken by the first stop and by the pass ending for a reason of its own. - `db/README.md`: a paragraph after the four engines'. **Tests:** `db/test-support.ts`' `heldGate(openFor)`; test-local-provider [10], test-live [10], [16] and [9f] — each listed in the merged note (`git show 75d8d122:changes/smd-3379.md`).

**Why.** PR 1c's scheduler pauses the passes while the brain is live and resumes them after, rather than ending them (the maintainer, 2026-10-26: a live write pauses, it does not stop). It needs a place in each engine to pause, which a stop still reaches. 1b-1 is that place, with no caller yet (SMD-3379's design, draft 5, accepted 2026-10-27; its PR 1b's per-call abort is 1b-2). ### PR 1a: the migration lock

**What changed.** `db/config.mjs`' `MIGRATE_LOCK` (`ob1:migrate`) and `MIGRATE_LOCK_HOLDER_SQL`, which reads the holder (`pid`, `backend_start`) from `pg_locks` without taking it: a bigint key is `classid` (its high 32 bits, 4294967295 where `hashtext`'s int4 is negative) and `objid`. `db/migrate.ts`' `takeLock()` takes it once by `pg_try_advisory_lock` and sets `application_name` `ob1-migrate`; refused, it names the holder and the `pg_terminate_backend` remedy, exit 2. It is called before each first write of its kind: the ledger's `CREATE TABLE` when the ledger shows a core file pending or for `--reapply` (the read deciding what runs comes after, under the lock); each plugin write on a run whose core may have had nothing to apply (the plugin ledger, now made only where missing, the login role, a plugin's role, schema or grant, a hand-back, each plugin file); 096's re-run. Taken just now, it has the caller read again what it decided on. `run()` lets it go in its `finally`. `db/README.md` says when it is taken, what a second run sees, and the killed-run remedy.

**Why.** PR 1c must stop its passes while a migration writes, and nothing marked a run in progress (draft 3's choice 4). No lock for a no-op: the `migrate` service runs on every `up`. Measured on main, the second of two runs started 0–800 ms apart: at 0 ms one failed with a stack dump (`pg_type_typname_nsp_index`); at 100–400 ms the second failed on `schema_migrations_pkey`; from 600 ms it was a no-op. Now it is refused by name. A patch: no flag, value or schema change.

**Held.** test-live [1]: the lock not taken, taken after the ledger, not let go, taken by a no-op or a `--dry-run`, not by `--reapply`, or the holder not named. test-plugins-sql [11]: a plugin site's call dropped or moved after the file, the file's row not read again after a fresh take (a race case interleaves two runs), a settled run taking it. test-live [44]: 096's call dropped. 19 mutants killed ([OB1 PR 559](https://github.com/MHarris-SgyMd/OB1/pull/559)).

**Measured after.** ci-parity 89/90 after passes 1 and 2, the red SMD-2402's flake, then the sleep shard's [38] reset-wait case (a live write woke the sleep first); each shard passed alone. **Review passes.** Three, the last with nothing above Low; their table is the merged note's ([OB1 PR 559](https://github.com/MHarris-SgyMd/OB1/pull/559), `git show 19618679:changes/smd-3379.md`).

**Not taken.** A lock that waits (a run would hang with no word); widening the early check to every repair (it would copy each repair's own test of need); locking every run (a no-op on each `up` would pause the passes); naming the lock in the no-ledger refusal beside a `--reapply`; retrying when the holder has just let go; making `--dry-run` leave no ledger (as it always has, SMD-2291); tests needing a cluster role dropped in a shared cluster.

**Follow-ups.** PR 1c reads the lock with `MIGRATE_LOCK_HOLDER_SQL`. Where 096 cannot take PUBLIC's grant back every run takes the lock, so 1c should exit only for a new ledger row.
