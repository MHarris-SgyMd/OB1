## Changelog

A `migrate.ts` run now takes a session advisory lock, `ob1:migrate`, before it writes anything, and holds it until it returns: a pending file, a plugin's file or repair, 096's re-run, or `--reapply`. A second run meanwhile is refused by name, exit 2, writing nothing, and the refusal names the backend that holds the lock, with the `pg_terminate_backend` that ends a run that was killed. Before, two runs at once raced on the ledger's rows and the catalog's, and one failed at once on a duplicate key, sometimes as a stack dump. `--dry-run`, `--grant` and a run with nothing to write take no lock (SMD-3379).

The claim workers — `extract-entities.ts`, `consolidate.ts` and `reembed.ts` — take an `admit` gate in-process: awaited before each claim, at the start of each pass, between a long thought's windows and between a consolidation's pairs, so a caller can pause a pass without stopping it, and a stop reaches a waiting worker at once; a run without one behaves as before (SMD-3379 PR 1b-1). The claim workers' `onPass` now hands the caller `abortInHand(olderThanMs)` beside the pass's stop: it aborts each worker's model call in hand at least that old, puts the thought at the back of the queue — extraction keeping its answered windows and counting the stop — and the worker goes on with its next claim (SMD-3379 PR 1b-2). A worker mid-thought now also reads its claim again after a closure that opened again during its call or a provider pause, where a gate says so (`closedSince`); `lease.ts`' `liveGate()` is the gate the scheduler closes (SMD-3379 PR 1c-3a).

The sleep scheduler runs its passes in work periods: a period begins once a pass has work and no live write has landed for `OB1_SLEEP_CAPTURE` seconds (`--capture`, 20), and runs until its pools drain. The idle scheduler reads its passes' claims each poll, and its work whole at its start and every `OB1_SLEEP_RESCAN` seconds (`--rescan`, 3600, new), so a backlog no claim shows — re-embed's, the orphans a raw delete of a window or a replay leaves — begins a period too; a vector arriving — the vector mender's, a re-embed's — brings that read forward, within about a minute and a poll, since consolidation judges only a thought with a vector (SMD-3379 PR 1d). In a period a live write pauses the passes rather than stopping them: they wait between thoughts and go on once `OB1_SLEEP_CAPTURE` seconds pass with no live write, a model call in hand longer than `OB1_SLEEP_ABORT_AFTER` seconds (`--abort-after`, 60, new) aborted meanwhile and its thought set back. A statement past its timeout holds its pass until a restart, the other passes going on, where it stopped the sleep. A one-shot run with no work exits 0 at once. Its log says `working:`, `paused:`, `resumed:` and `the pools drained — the period ends`; its row writes `paused`, and `holds`, the passes held out of its work, which preflight and `brain_info` read, preflight's `sleep` row saying working, paused or idle (SMD-3379 PR 1c-2 to 1c-4b). It waits out a migration in progress at its start, and ends with exit 75 when it sees one while it runs, its supervisor running it again at once (SMD-3379 PR 1c-1). Its live reads keep the database's microseconds. **Upgrading:** `OB1_SLEEP_QUIET` and `OB1_SLEEP_BUDGET` (`--quiet`, `--budget`) are removed: the CLI refuses either with 2, naming what replaced it, and the coordinator no longer reads them, so delete them from `deploy/.env`. A period begins on work rather than after a quiet, and runs until its pools drain rather than to a clock, so a backlog drains in one period, paused by each live write (SMD-3379 PR 1c-4b).

### PR 2a: one seam for every model call

**What changed.**
- `server-portable/model-call.ts` (new): `modelCall(call, run)`, the one seam every model call goes through. `call` names the type (`embed`, `chat` or `decide`), the model, the model server's base URL, what the call is for, and live or background; `run` is the whole exchange, the request and the reading of its answer, a streamed one included, its deadline started inside it. With no hook set the seam runs `run` at once; `setModelCallHook` is where PR 2b's share will wait. A call is live inside `asLive` — the REST core runs each request so (`rest/app.ts`, through `core/`) — and background otherwise: the sleep scheduler's passes, board-sync, the CLI scripts, the servers' timers (the vector mender, the provider reprobe), and a detached job (`jobs.ts` runs it `asBackground`).
- Through it: `providerCall` (embeddings, capture blurbs, metadata, subject, the digest), the egress gate's refusal before it and the span inside it; extraction's call (`entities.ts`), the judge's (`consolidate.ts`, its retry without logprobs inside the one call), decide mode's writer (`consolidate-decide.ts`), the decide tier's `/decide` and `/info` (`jev.ts`), a worker's one-token probe (`db/worker-bootstrap.ts` `probeChat`), and preflight's probes. Each kept its own fetch, now inside an `…Exchange` function the seam runs.
- **Tests:** test-local-provider [11]: a capture's calls are live and name their model and server; outside a request a call is background, `asLive` live; extraction, the judge, a probe and the decide tier each go through the seam; a hook that refuses every call stops each before the provider sees one; a 600 ms wait in the seam before a call with a 300 ms deadline costs it nothing; every file that sends a model request imports the seam (bench-live.ts excepted: it measures the provider bare).

**Why.** Draft 5's PR 2 put a slot around each model call's fetch; five of those fetches sat outside both shared wrappers. The maintainer's cut (2026-11-05): the seam first, as a patch, so 2b's share is one hook.

**Version contract.** None: no setting, log line or behaviour changes. A patch.

**Held.** Eight mutants, each killed by its own row in [11]: a bypass of the seam in `providerCall`, extraction, the judge, the probe and the decide tier (the refusal row reaching the provider, or the call missing from the seam's list); the REST core's requests not marked live; background not the default; and the deadline started before the seam (the 600 ms wait timing the call out).

**Measured after.** `./db/ci-parity.sh`: every row passes; all suites in 311 s. test-local-provider runs 237 assertions in 7 s.

**Not taken.** **The writer's behavioural case**: reaching `askWriter` needs a decide tier that answers, so it is held by the source guard and the code; a bypass that kept the file's import would pass. **A job's background class**: no job makes a model call today (`scan_thoughts` reads); `asBackground` around the detached run is for the first that does. **A request deadline a caller starts before the call** (a pass handing in `AbortSignal.timeout(…)` as its signal) would still run while 2b's hook waits: 2b decides whether a wait counts against it. **bench-live.ts**, which measures the provider bare.

### PR 1d: a vector come brings the whole read forward

**What changed.**
- `db/sleep.ts`: idle, a vector come since the last whole read — a `thought_audit` row whose diff says `embedding_present` true, whoever wrote it (the vector mender, a re-embed, an edit) — makes the next poll read the work whole, where it waited for the rescan: consolidation judges only a thought with a vector (029's `consolidation_pool`), and its arrival queues no claim. `vectorMark` takes the mark before each whole read and before a period's end read (the database's now() less the 30 s slack, and the rows already visible after it); `vectorCome` is one statement against it — two range reads of `thought_audit_created_at_idx`, an update's diff alone read — each poll that no whole read has found work yet, consolidation may begin a period and `VECTOR_FLOOR_S` (60) has passed since the mark's read ended; with none come, it moves the mark on in the same snapshot. A vector read once is not read again, and a burst — the mender after an outage, a re-embed of vectorless rows by hand — reads whole once a minute at most. A read a vector brings forward leaves the rescan's clock, so the rescan, and its re-arm of a set-down re-embed, keeps its hour. `schedulerSession` sets `plan_cache_mode = force_custom_plan`, so the prepared `vectorCome` is planned for its values each poll, not by a generic plan that scans `thought_audit`.
- `db/README.md`, `deploy/README.md`, `deploy/.env.example`, the header: the trigger; db/README's `plan_cache_mode`; and "a delete's orphans" corrected — a thought's delete leaves none (below).
