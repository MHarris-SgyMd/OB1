## Changelog

A `migrate.ts` run now takes a session advisory lock, `ob1:migrate`, before it writes anything, and holds it until it returns: a pending file, a plugin's file or repair, 096's re-run, or `--reapply`. A second run meanwhile is refused by name, exit 2, writing nothing, and the refusal names the backend that holds the lock, with the `pg_terminate_backend` that ends a run that was killed. Before, two runs at once raced on the ledger's rows and the catalog's, and one failed at once on a duplicate key, sometimes as a stack dump. `--dry-run`, `--grant` and a run with nothing to write take no lock (SMD-3379).

The claim workers — `extract-entities.ts`, `consolidate.ts` and `reembed.ts` — take an `admit` gate in-process: awaited before each claim, at the start of each pass, between a long thought's windows and between a consolidation's pairs, so a caller can pause a pass without stopping it, and a stop reaches a waiting worker at once. Nothing passes one yet; a run without one behaves as before (SMD-3379 PR 1b-1).

### PR 1b-1: the claim workers' admit gate

**What changed.**
- `db/lease.ts`: `Admit`, `(signal) => Promise<void>`, and `admitted(admit, signal)`, which waits at it: true when it let the work through, false when it rejected after the signal aborted (a stop reaching a waiting worker). Any other rejection is thrown.
- `admit` on the three claim workers' options, awaited with the pass's first-stop signal:
  - before each claim. A worker waiting there holds no claim, and a stop ends it.
  - at the start of each pass, before its pool and counts (and consolidation's stale re-pool). A stop there ends the run with no pass; the summary's counts are read only for a summary. Re-embed's waits before the start's drain and each poll's pool. Its start's own pool is made before the pass's stop exists, and is not gated.
  - extraction, before each window of a windowed thought that is sent (`extractEntities`' new `admit`, after `progress`). The claim and lease are kept; the wait moves the thought's time held (`inHand.since`) on and is not the model's time. A stop throws `StoppedBetweenWindows`: the windows answered are kept, or with no keeping the claim goes back.
  - consolidation, before each pair. The claim and lease are kept. A stop throws `StoppedBetweenPairs`: the thought goes back to the pool unrecorded, its proposals so far standing.
- Re-embed claims one thought at a time under a gate unless `batch` is given (else 8), so a closed gate holds a worker after the thought in hand.
- `db/README.md`: a paragraph after the four engines'.
- **Tests:** `db/test-support.ts`' `heldGate(openFor)`, open for its first asks and then closed until opened, rejecting on its signal.
  - `server-portable/test-local-provider.ts` [10]: a gate closed before the second window holds it unsent; it is asked before each window sent, not before a kept one nor for a one-call thought; one that rejects rejects the extraction there, two windows kept.
  - `db/test-live.ts` [10]: closed from the start, a run writes no pool, and a stop ends it at once, 130. Closed at the claim, the pool is written and no claim held until it opens. Closed before a long thought's second window, the claim is held, and a stop ends it at once: one window kept, no stop counted, the claim pending.
  - [16]: closed before a thought's second pair, the claim is held, and a stop sends it back pending after one call. Closed at the claim, none is held, and both pairs are judged once it opens.
  - [9f]: a follower given a gate claims one at a time, waits at its claim holding none, and stops at once. Closed before a poll, a new thought is not pooled until it opens.

**Why.** PR 1c's scheduler pauses the passes while the brain is live and resumes them after, rather than ending them (the maintainer, 2026-10-26: a live write pauses, it does not stop). It needs a place in each engine to pause, which a stop still reaches. 1b-1 is that place, with no caller yet (draft 5's split; 1b's per-call abort is 1b-2). The gate sits wherever a pass starts new work: a claim, a pool, a window, a pair.

**Version contract.** `admit` is an in-process option of `db/` engines, outside the contract until SMD-2601 ships `ob1-workers`. No flag, setting or default changes for a run without one. A patch.

**Held.** Twelve mutants, each killed by its own rows:
- the gate dropped before extraction's claim, its pass, its windows (the worker's or `extractEntities`' own call), consolidation's claim or a pair, re-embed's claim or a poll;
- `admitted` reading a stop's rejection as through ([10]'s pass and window cases);
- a stop between pairs read as the thought's failure (the thought recorded failed);
- re-embed claiming eight under a gate;
- the first stop read before the window gate, not after (a stop that came while the gate held the window sent it).

**Measured after.** `./db/ci-parity.sh`: every row passes (89). test-live's extract shard is 341, rest 1025; test-local-provider 231.

### PR 1a: the migration lock

**What changed.** `db/config.mjs`' `MIGRATE_LOCK` (`ob1:migrate`) and `MIGRATE_LOCK_HOLDER_SQL`, which reads the holder (`pid`, `backend_start`) from `pg_locks` without taking it: a bigint key is `classid` (its high 32 bits, 4294967295 where `hashtext`'s int4 is negative) and `objid`. `db/migrate.ts`' `takeLock()` takes it once by `pg_try_advisory_lock` and sets `application_name` `ob1-migrate`; refused, it names the holder and the `pg_terminate_backend` remedy, exit 2. It is called before each first write of its kind: the ledger's `CREATE TABLE` when the ledger shows a core file pending or for `--reapply` (the read deciding what runs comes after, under the lock); each plugin write on a run whose core had nothing to apply (the plugin ledger, now made only where missing, the login role, a plugin's role, schema or grant, a hand-back, each plugin file); 096's re-run. Taken just now, it has the caller read again what it decided on. `run()` lets it go in its `finally`. `db/README.md` says when it is taken, what a second run sees, and the killed-run remedy.

**Why.** PR 1c must stop its passes while a migration writes, and nothing marked a run in progress (draft 3's choice 4). No lock for a no-op: the `migrate` service runs on every `up`. Measured on main, the second of two runs started 0–800 ms apart: at 0 ms one failed with a stack dump (`pg_type_typname_nsp_index`); at 100–400 ms the second failed on `schema_migrations_pkey`; from 600 ms it was a no-op. Now it is refused by name. A patch: no flag, value or schema change.

**Held.** test-live [1]: the lock not taken, taken after the ledger, not let go, taken by a no-op or a `--dry-run`, not by `--reapply`, or the holder not named. test-plugins-sql [11]: a plugin site's call dropped or moved after the file, the file's row not read again after a fresh take (a race case interleaves two runs), a settled run taking it. test-live [44]: 096's call dropped. 13 mutants killed.

**Measured after.** ci-parity 89/90 after passes 1 and 2, the red SMD-2402's flake, then the sleep shard's [38] reset-wait case (a live write woke the sleep first); each shard passed alone.

**Review passes.** Three ([OB1 PR 559](https://github.com/MHarris-SgyMd/OB1/pull/559)). Pass 1: the claim that main failed at `lock_timeout` was false (run-it); repairs wrote unlocked (run-it); the holder unnamed (run-it); the bump argued only as not a major (cold-read). Pass 2, Medium (run-it): pass 1's fix read the plugin state before the lock, and a run let in between failed on a duplicate key; now re-read after a fresh take. Also the pending case's teeth (mutant), 096's test (walkthrough), two wordings. Pass 3: four Lows, nothing above.

**Not taken.** A lock that waits (a run would hang with no word); locking every run (a no-op on each `up` would pause the passes); naming the lock in the no-ledger refusal beside a `--reapply`; retrying when the holder has just let go; making `--dry-run` leave no ledger (as it always has, SMD-2291); tests needing a cluster role dropped in a shared cluster.

**Follow-ups.** PR 1c reads the lock with `MIGRATE_LOCK_HOLDER_SQL`. Where 096 cannot take PUBLIC's grant back every run takes the lock, so 1c should exit only for a new ledger row.
