## Changelog

A `migrate.ts` run now takes a session advisory lock, `ob1:migrate`, before it writes anything, and holds it until it returns: a pending file, a plugin's file or repair, 096's re-run, or `--reapply`. A second run meanwhile is refused by name, exit 2, writing nothing, and the refusal names the backend that holds the lock, with the `pg_terminate_backend` that ends a run that was killed. Before, two runs at once raced on the ledger's rows and the catalog's, and one failed at once on a duplicate key, sometimes as a stack dump. `--dry-run`, `--grant` and a run with nothing to write take no lock (SMD-3379).

The claim workers — `extract-entities.ts`, `consolidate.ts` and `reembed.ts` — take an `admit` gate in-process: awaited before each claim, at the start of each pass, between a long thought's windows and between a consolidation's pairs, so a caller can pause a pass without stopping it, and a stop reaches a waiting worker at once; a run without one behaves as before (SMD-3379 PR 1b-1). The claim workers' `onPass` now hands the caller `abortInHand(olderThanMs)` beside the pass's stop: it aborts each worker's model call in hand at least that old, puts the thought at the back of the queue — extraction keeping its answered windows and counting the stop — and the worker goes on with its next claim (SMD-3379 PR 1b-2). A worker mid-thought now also reads its claim again after a closure that opened again during its call or a provider pause, where a gate says so (`closedSince`); `lease.ts`' `liveGate()` is the gate the scheduler closes (SMD-3379 PR 1c-3a).

The sleep scheduler runs its passes in work periods: a period begins once a pass has work and no live write has landed for `OB1_SLEEP_CAPTURE` seconds (`--capture`, 20), and runs until its pools drain. The idle scheduler reads its passes' claims each poll, and its work whole at its start and every `OB1_SLEEP_RESCAN` seconds (`--rescan`, 3600, new), so a backlog no claim shows — re-embed's, the orphans a raw delete of a window or a replay leaves — begins a period too; a vector arriving — the vector mender's, a re-embed's — brings that read forward, within about a minute and a poll, since consolidation judges only a thought with a vector (SMD-3379 PR 1d). In a period a live write pauses the passes rather than stopping them: they wait between thoughts and go on once `OB1_SLEEP_CAPTURE` seconds pass with no live write, a model call in hand longer than `OB1_SLEEP_ABORT_AFTER` seconds (`--abort-after`, 60, new) aborted meanwhile and its thought set back. A statement past its timeout holds its pass until a restart, the other passes going on, where it stopped the sleep. A one-shot run with no work exits 0 at once. Its log says `working:`, `paused:`, `resumed:` and `the pools drained — the period ends`; its row writes `paused`, and `holds`, the passes held out of its work, which preflight and `brain_info` read, preflight's `sleep` row saying working, paused or idle (SMD-3379 PR 1c-2 to 1c-4b). It waits out a migration in progress at its start, and ends with exit 75 when it sees one while it runs, its supervisor running it again at once (SMD-3379 PR 1c-1). Its live reads keep the database's microseconds. **Upgrading:** `OB1_SLEEP_QUIET` and `OB1_SLEEP_BUDGET` (`--quiet`, `--budget`) are removed: the CLI refuses either with 2, naming what replaced it, and the coordinator no longer reads them, so delete them from `deploy/.env`. A period begins on work rather than after a quiet, and runs until its pools drain rather than to a clock, so a backlog drains in one period, paused by each live write (SMD-3379 PR 1c-4b). `OB1_BACKGROUND_SLOTS` (new, off unless set) holds background model calls — the sleep passes', board-sync's, the vector mender's, the provider reprobe's and a detached job's, among them — to a share of each model server's slots, across every process of the brain, by Postgres advisory locks, so a live call finds one free: types with optional per-model overrides, e.g. `chat=1,embed=2,decide=1,chat:qwen3.8:27b=1`, a type left out unlimited, the decide tier shared per server alone; a live call never takes a slot. A semaphore whose database does not answer lets the call run without one, said once. Consolidation's per-pair `--timeout` no longer counts a wait for a slot (SMD-3379 PR 2b-1).

### PR 2b-1: background calls held to a share of the slots

**What changed.**
- `server-portable/slots.ts` (new): `installBackgroundSlots`, the model-call seam's hook, set once per process at its entry point, off unless `OB1_BACKGROUND_SLOTS` is set. A background call counts against its share — per normalised model server and model, the decide tier per server alone — and waits for one of its N slots: the two-key advisory lock `(hashtext(key), i)`, taken with `pg_try_advisory_lock`, polled every 250 to 500 ms, held for the call, let go after it; a process that dies lets its slots go with its session. In a process one of a share's calls polls at a time, the rest queued there in order, each polling and then holding its slot on a connection of its own (`application_name` `ob1-slots`), closed after its unlock: a connection per slot held and one per poller, none when idle. A poller holds the share's lock `(hashtext(key), -1)` shared, and a call about to make its first try that finds it held elsewhere sits out a poll, so one process's backlog does not keep the slots from the others. A live call, and a type left out, take none. A value that does not parse is said and the hook left off.
