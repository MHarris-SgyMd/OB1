## Changelog

A `migrate.ts` run now takes a session advisory lock, `ob1:migrate`, before it writes anything, and holds it until it returns: a pending file, a plugin's file or repair, 096's re-run, or `--reapply`. A second run meanwhile is refused by name, exit 2, writing nothing, and the refusal names the backend that holds the lock, with the `pg_terminate_backend` that ends a run that was killed. Before, two runs at once raced on the ledger's rows and the catalog's, and one failed at once on a duplicate key, sometimes as a stack dump. `--dry-run`, `--grant` and a run with nothing to write take no lock (SMD-3379).

The claim workers — `extract-entities.ts`, `consolidate.ts` and `reembed.ts` — take an `admit` gate in-process: awaited before each claim, at the start of each pass, between a long thought's windows and between a consolidation's pairs, so a caller can pause a pass without stopping it, and a stop reaches a waiting worker at once. Nothing passes one yet; a run without one behaves as before (SMD-3379 PR 1b-1). The claim workers' `onPass` now hands the caller `abortInHand(olderThanMs)` beside the pass's stop: it aborts each worker's model call in hand at least that old, puts the thought at the back of the queue — extraction keeping its answered windows and counting the stop — and the worker goes on with its next claim. Nothing calls it yet; a run whose caller does not behaves as before (SMD-3379 PR 1b-2).

The sleep scheduler now waits out a migration in progress at its start, and ends with exit 75 when it sees one while it runs — the migration ledger moved, or `migrate.ts`' lock held at two polls — its passes stopped at once. Its supervisor runs a 75 again at once, no try counted, and the next process waits it out and reads its start again on the new schema; preflight says "restarting after a migration" (SMD-3379 PR 1c-1). Preflight and `brain_info` read a paused scheduler (`paused`) and the passes it holds (`holds`), which no scheduler writes yet (SMD-3379 PR 1c-2).

### PR 1c-1: the scheduler restarted on a migration

**What changed.**
- `db/config.mjs`: `MIGRATION_EXIT` (75, sysexits' "try again").
- `db/sleep.ts`: at its start, before the passes' starts check the schema, it waits while `ob1:migrate` is held (1a's `MIGRATE_LOCK_HOLDER_SQL`), saying so once, then takes `schema_migrations`' newest name and row count as its baseline. A watcher beside its loops reads both each `--poll`: the ledger moved, or the lock held by one backend at two polls in a row (a no-op run that takes it, as every run does where 096 cannot take PUBLIC's grant back, is gone by then), and the passes stop at once — a stop on 093, as the second signal's, not a cut, then, their leases returned, any statement of the scheduler's or theirs waiting on a lock not one of their own cancelled until the run ends (every connection named `ob1-sleep <id>`), no pass started after — the row ends without the held read, and `run()` returns 75 for the stop's 130 or a `--follow` refusal that met it (a one-shot that ended of itself meanwhile keeps its code; a throw after it is said), a hand run told to run it again once the migration is done. A dry run neither waits nor watches.
- `db/supervise.ts`: the scheduler exiting 75 runs again at once, no try counted (the ends before a long run forgotten), its row's `restart` saying `in_s` 0 and code 75. Past `MIGRATION_RESTARTS` (3) such ends in a row, each within a minute of its start, it falls back to the clock, so a scheduler that saw a migration at every start cannot spin. Another follower's 75 is any end.
- `server-portable/preflight.ts` and `brain-info.ts`: such a row reads "restarting after a migration", at any age; past the overdue mark preflight adds that the coordinator may be gone, with its recreate command.
- `db/README.md`: the sleep section's "A migration", the exit codes, and the `restart` field.
- **Tests:** `db/test-live.ts` [37b]: the scheduler exiting 75 runs again at once three times, then on the clock; a slow 75 after three quick ones at once, its row `in_s` 0, code 75, tries 0; board-sync's 75 on the clock. [38]: a lock held at the start is waited out before the start's reads; a row added to the ledger then ends the run with 75, its row ended stopped; the lock taken mid-run ends a second run so; a pass's statement waiting on a table the migration locked, and the scheduler's own read on `thought_audit`, are cancelled, the run ending 75 while the lock is held, no thought failed. test-server and test-preflight: the 75 row's words.

**Why.** Draft 5's §6: a running scheduler's passes wrote across a migration, and its start's reads — the cuts, whether `rebuild_derived` exists — held the old schema's answers until the next restart. 1c-4 drops the clock that today ends a sleep within the hour. The restart runs the code the coordinator has: in compose a changed image comes with `up -d --build` recreating the coordinator, which stops the scheduler before the migrate service runs, so a 75 is seen when the server image did not change or the migrator runs beside the stack (`canary.sh up` stops the coordinator first). The lock is a signal, not a barrier (1a): until the passes stop a migration that needs a lock a pass holds may still fail, at its `lock_timeout` or at once on a deadlock (measured).

**Version contract.** A new exit status of the scheduler and a supervise rule for it: additive, no setting or flag changes. A minor.

**Held.** Fifteen mutants, each killed by its own rows: no wait at the start, or the wait after the start's reads (they ran beside the lock); the ledger's move, its count or the lock not watched (the run never ended); no cancel of a statement waiting on the migration's lock, the passes' connections untagged, or the scheduler's (the run waited for it); `run()` not returning 75 (130); supervise running the scheduler's 75 on the clock, any follower's at once, with no guard (2,107 runs in seconds), counting slow 75s, not stamping the at-once row, or keeping a long run's tries. Two survive, timings no case holds: the row ended before the passes return, and the cancel ending with them; nor does one hold the two-poll rule (a lock let go within a poll).

**Measured after.** `./db/ci-parity.sh`: every row passes, at the first commit and after passes 1–6. test-live's sleep shard is 121, extract 427.

**Review passes.** Six, then a boyscout tidy; pass 6 found nothing above Low. Passes 4 and 5 ran it for real against `migrate.ts`, and the cancel of a lock-waiting statement came from them (the maintainer: fold it in). Their table is the merged note's ([OB1 PR 590](https://github.com/MHarris-SgyMd/OB1/pull/590), `git show 16768fc8:changes/smd-3379.md`).

**Not taken.**
- **No guard on the immediate restart**, as the design had it. Three in a row, each quick, fall back to the clock; a migration does not end a scheduler three times a minute.
- **Watching more, or naming a stuck holder.** A plugin's run or a `--reapply` that holds the lock under two polls moves no core ledger row and is missed, and claim workers run outside the scheduler watch nothing; each would need a poll of its own for a rare case. A killed `migrate.ts` lets the lock go with its session; only a hung one holds it, and the scheduler waits; a second `migrate.ts` run names the holder and the `pg_terminate_backend` remedy.

**Follow-ups.** A deadlock or lock timeout on a pass's write before the stop records the thought failed, as its own (measured, before this PR too): read it as the database's moment, set back. 1c-4 removes the clock; a scheduler then reads its start again after a migration by the recreate an upgrade with a new image makes, or by this restart when the image did not change or the migrator ran beside it — 1c-4's premise rechecked on both.

### PR 1b-2: the claim workers' calls in hand, aborted

**What changed.**
- `db/lease.ts`: `InHandAbort`, `(olderThanMs?) => number`; `AbortedInHand`, the reason an abort carries; `setBack(sql, job, workerId, id)`, which puts a thought this worker holds behind every thought queued before it — pending, its attempt not counted (`release_claims_for_worker`'s rule), `enqueued_at` now, which `claim_thoughts` orders by — false when it is not the worker's, a database error thrown.
- `inHandCalls(inert)`, the one place the three engines keep each worker's call entry and `abortInHand`.
- Each claim worker's `onPass` takes it as a second argument beside the stop. Each worker's call for the thought it holds carries an abort of its own, joined with the hard stop's; `abortInHand(olderThanMs)` aborts every call at least that old — since the thought was taken up, the admit gate last passed or a provider pause ended, a worker with no call to abort (at the gate, in a pause, in the decider's call) passed over — and returns how many, inert once the pass is stopping. Extraction marks only an error the call raised (`AbortedInHand`), not a gate's or a stop's that lands while the flag is set. An abort that comes between a thought's calls sets it back at its next call — before the admit gate, at a window or pair, when one is given — and wins over a first stop that follows it.
  - extraction: the worker counts the stop on the thought once (093, as a wake's; out of `inHand` first, and a racing hard stop's release chained on the count), keeps the windows answered, sets it back, and goes on with its next claim;
  - a thought deleted, edited or reaped meanwhile is not the worker's to set back: counted deleted or lost, as `reportLost` says; a set-back the database refuses stops the worker, its finally returning the claim; `--limit` no longer counts one set back;
  - consolidation: the judge call aborted, the thought set back with its proposals so far standing, not counted judged;
  - re-embed: the embedding call aborted, the thought set back.
- Each summary counts the thoughts set back, said only when there are any.
- `db/README.md`: a paragraph after the admit gate's.
- **Tests:** `db/test-live.ts` [10]: a call younger than the bound left; the long note's second window aborted in hand, the first kept, its stop counted, the note set behind the short one; the worker goes on, both extracted, the summary counting it; a note deleted while its call is in hand, then aborted, counted deleted, not set back. [16]: a judge call aborted, the thought judged again in the same run. [9f]: a follower's embedding call aborted, the thought re-embedded.

**Why.** Draft 5's N12: while 1c's gate is closed, a pass's call that has run past `OB1_SLEEP_ABORT_AFTER` is aborted, so a long call does not hold the model through a live burst; the gate alone pauses only at the next claim, window or pair. The worker goes on rather than restarting: no start probe, no pool scan, no new heartbeat.

**Version contract.** A second argument to an in-process callback of `db/` engines, outside the contract until SMD-2601. No flag, setting or default changes. A patch.

**Held.** Nine mutants, each killed by its own rows: a failed set-back counted set back; the worker stopping after an abort (extraction, consolidation), no stop counted, `setBack` not moving the thought back, the bound ignored, and each engine's call not joined to its abort ([9f]'s slow call kept under its 2 s timeout, which otherwise ended the call and hid the last).

**Measured after.** `./db/ci-parity.sh`: every row passes, at the first commit and after passes 1, 2 and 3; the nine mutants run again on pass 3's `inHandCalls`. test-live's extract shard is 355, rest 1030.

**Review passes.** Four, then a boyscout tidy; pass 4 found nothing above Low. The Mediums fixed: a thought gone during the aborted call miscounted and its claim put back in the heartbeat's set; "the back of the queue" ahead of the scheduler's forward-dated stopped thoughts; and pass 3's Low-Medium, the hard stop not waiting for the abort's stop count. Their table is the merged note's ([OB1 PR 580](https://github.com/MHarris-SgyMd/OB1/pull/580), `git show 08ffd09b:changes/smd-3379.md`).

**Tidied while the files were open.** `lease.ts`' `idleWhile` marks a worker as holding no call to abort around the gate's wait, a provider pause and the decider's call, where five sites toggled the flag by hand; consolidation reads its call entry once a thought.

**Not taken.**
- **Aborting a thought past its last call, or the decider's call.** An abort that comes during the write finds no call in hand; the thought finishes as it was, and is counted aborted by the return. The decider's call takes no signal; the thought finishes it.
- **A worker with no call to abort.** At the gate, in a provider pause or in the decider's call it is passed over; no case holds the skip, nor extraction's mark sparing a gate's error, the set-back at the next gate, or the hard stop chaining on an abort's count — each a timing no stub fixes.
- **Counting the windows an aborted claim answered toward the malformed alarm.** They are counted at the claim that finishes, as a first stop between windows leaves them; 1c's aborts are rare against its passes.
- **A test that re-embed's worker goes on in the same drain.** A follower's next poll pools the set-back thought anyway, so the case holds the abort, the set-back and the re-embed, not which drain.

**Follow-ups.** PR 1c calls it at each poll while its gate is closed, with `OB1_SLEEP_ABORT_AFTER`, and logs the count; runs `stoppedLast` as the gate reopens, since `setBack` dates a thought now and lands after the call returns; keeps `OB1_SLEEP_ABORT_AFTER` at or above the stall floor (else aborts count as short stops); decides a cap on consolidation's aborts, which neither stall nor fail out; does not abort in a poll that may cut. And since SMD-3476 (main): 1c edits `db/coordinator.ts`' `CHILDREN.sleep` args (`--quiet`, `--budget`) and digit list, and compose's coordinator environment, for its new settings; the design's sleep-service references now name the coordinator.

### PR 1a: the migration lock

**What changed.** `db/config.mjs`' `MIGRATE_LOCK` (`ob1:migrate`) and `MIGRATE_LOCK_HOLDER_SQL`, which reads the holder (`pid`, `backend_start`) from `pg_locks` without taking it: a bigint key is `classid` (its high 32 bits, 4294967295 where `hashtext`'s int4 is negative) and `objid`. `db/migrate.ts`' `takeLock()` takes it once by `pg_try_advisory_lock` and sets `application_name` `ob1-migrate`; refused, it names the holder and the `pg_terminate_backend` remedy, exit 2. It is called before each first write of its kind: the ledger's `CREATE TABLE` when the ledger shows a core file pending or for `--reapply` (the read deciding what runs comes after, under the lock); each plugin write on a run whose core may have had nothing to apply (the plugin ledger, now made only where missing, the login role, a plugin's role, schema or grant, a hand-back, each plugin file); 096's re-run. Taken just now, it has the caller read again what it decided on. `run()` lets it go in its `finally`. `db/README.md` says when it is taken, what a second run sees, and the killed-run remedy.

**Why.** PR 1c must stop its passes while a migration writes, and nothing marked a run in progress (draft 3's choice 4). No lock for a no-op: the `migrate` service runs on every `up`. Measured on main, the second of two runs started 0–800 ms apart: at 0 ms one failed with a stack dump (`pg_type_typname_nsp_index`); at 100–400 ms the second failed on `schema_migrations_pkey`; from 600 ms it was a no-op. Now it is refused by name. A patch: no flag, value or schema change.

**Held.** test-live [1]: the lock not taken, taken after the ledger, not let go, taken by a no-op or a `--dry-run`, not by `--reapply`, or the holder not named. test-plugins-sql [11]: a plugin site's call dropped or moved after the file, the file's row not read again after a fresh take (a race case interleaves two runs), a settled run taking it. test-live [44]: 096's call dropped. 19 mutants killed ([OB1 PR 559](https://github.com/MHarris-SgyMd/OB1/pull/559)).

**Measured after.** ci-parity 89/90 after passes 1 and 2, the red SMD-2402's flake, then the sleep shard's [38] reset-wait case (a live write woke the sleep first); each shard passed alone.

**Review passes.** Three, the last with nothing above Low; their table is the merged note's ([OB1 PR 559](https://github.com/MHarris-SgyMd/OB1/pull/559), `git show 19618679:changes/smd-3379.md`).

**Not taken.** A lock that waits (a run would hang with no word); widening the early check to every repair (it would copy each repair's own test of need); locking every run (a no-op on each `up` would pause the passes); naming the lock in the no-ledger refusal beside a `--reapply`; retrying when the holder has just let go; making `--dry-run` leave no ledger (as it always has, SMD-2291); tests needing a cluster role dropped in a shared cluster.

**Follow-ups.** PR 1c reads the lock with `MIGRATE_LOCK_HOLDER_SQL`. Where 096 cannot take PUBLIC's grant back every run takes the lock, so 1c should exit only for a new ledger row.
