## Changelog

A `migrate.ts` run now takes a session advisory lock, `ob1:migrate`, before it writes anything, and holds it until it returns: a pending file, a plugin's file or repair, 096's re-run, or `--reapply`. A second run meanwhile is refused by name, exit 2, writing nothing, and the refusal names the backend that holds the lock, with the `pg_terminate_backend` that ends a run that was killed. Before, two runs at once raced on the ledger's rows and the catalog's, and one failed at once on a duplicate key, sometimes as a stack dump. `--dry-run`, `--grant` and a run with nothing to write take no lock (SMD-3379).

The claim workers — `extract-entities.ts`, `consolidate.ts` and `reembed.ts` — take an `admit` gate in-process: awaited before each claim, at the start of each pass, between a long thought's windows and between a consolidation's pairs, so a caller can pause a pass without stopping it, and a stop reaches a waiting worker at once. Nothing passes one yet; a run without one behaves as before (SMD-3379 PR 1b-1). The claim workers' `onPass` now hands the caller `abortInHand(olderThanMs)` beside the pass's stop: it aborts each worker's model call in hand at least that old, puts the thought at the back of the queue — extraction keeping its answered windows and counting the stop — and the worker goes on with its next claim. Nothing calls it yet; a run whose caller does not behaves as before (SMD-3379 PR 1b-2).

The sleep scheduler now waits out a migration in progress at its start, and ends with exit 75 when it sees one while it runs — the migration ledger moved, or `migrate.ts`' lock held at two polls — its passes stopped at once. Its supervisor runs a 75 again at once, no try counted, and the next process waits it out and reads its start again on the new schema; preflight says "restarting after a migration" (SMD-3379 PR 1c-1).

### PR 1b-2: the claim workers' calls in hand, aborted

**What changed.**
- `db/lease.ts`: `InHandAbort`, `(olderThanMs?) => number`; `AbortedInHand`, the reason an abort carries; `setBack(sql, job, workerId, id)`, which puts a thought this worker holds behind every thought queued before it — pending, its attempt not counted (`release_claims_for_worker`'s rule), `enqueued_at` now, which `claim_thoughts` orders by — false when it is not the worker's, a database error thrown.
- `inHandCalls(inert)`, the one place the three engines keep each worker's call entry and `abortInHand`.
- Each claim worker's `onPass` takes it as a second argument beside the stop. Each worker's call for the thought it holds carries an abort of its own, joined with the hard stop's; `abortInHand(olderThanMs)` aborts every call at least that old — since the thought was taken up, the admit gate last passed or a provider pause ended, a worker with no call to abort (at the gate, in a pause, in the decider's call) passed over — and returns how many, inert once the pass is stopping. Extraction marks only an error the call raised (`AbortedInHand`), not a gate's or a stop's that lands while the flag is set. An abort that comes between a thought's calls sets it back at its next call — before the admit gate, at a window or pair, when one is given — and wins over a first stop that follows it.
  - extraction: the worker counts the stop on the thought once (093, as a wake's; out of `inHand` first, and a racing hard stop's release chained on the count), keeps the windows answered, sets it back, and goes on with its next claim;
  - a thought deleted, edited or reaped meanwhile is not the worker's to set back: counted deleted or lost, as `reportLost` says; a set-back the database refuses stops the worker, its finally returning the claim; `--limit` no longer counts one set back;
  - consolidation: the judge call aborted, the thought set back with its proposals so far standing, not counted judged;
  - re-embed: the embedding call aborted, the thought set back.
- Each summary counts the thoughts set back, said only when there are any.
- `db/README.md`: a paragraph after the admit gate's.
- **Tests:** `db/test-live.ts` [10]: a call younger than the bound left; the long note's second window aborted in hand, the first kept, its stop counted, the note set behind the short one; the worker goes on, both extracted, the summary counting it; a note deleted while its call is in hand, then aborted, counted deleted, not set back. [16]: a judge call aborted, the thought judged again in the same run. [9f]: a follower's embedding call aborted, the thought re-embedded.

**Why.** Draft 5's N12: while 1c's gate is closed, a pass's call that has run past `OB1_SLEEP_ABORT_AFTER` is aborted, so a long call does not hold the model through a live burst; the gate alone pauses only at the next claim, window or pair. The worker goes on rather than restarting: no start probe, no pool scan, no new heartbeat.

**Version contract.** A second argument to an in-process callback of `db/` engines, outside the contract until SMD-2601. No flag, setting or default changes. A patch.

**Held.** Nine mutants, each killed by its own rows: a failed set-back counted set back; the worker stopping after an abort (extraction, consolidation), no stop counted, `setBack` not moving the thought back, the bound ignored, and each engine's call not joined to its abort ([9f]'s slow call kept under its 2 s timeout, which otherwise ended the call and hid the last).

**Measured after.** `./db/ci-parity.sh`: every row passes, at the first commit and after passes 1, 2 and 3; the nine mutants run again on pass 3's `inHandCalls`. test-live's extract shard is 355, rest 1030.

**Review passes.** Four, then a boyscout tidy; pass 4 found nothing above Low. - **Aborting a thought past its last call, or the decider's call.** An abort that comes during the write finds no call in hand; the thought finishes as it was, and is counted aborted by the return. The decider's call takes no signal; the thought finishes it.

### PR 1b-1: the claim workers' admit gate

**What changed.**
- `db/lease.ts`: `Admit`, `(signal) => Promise<void>`, and `admitted(admit, signal)`, which waits at it: true when it let the work through, false when it rejected after the signal aborted (a stop reaching a waiting worker). Any other rejection is thrown.
- `admit` on the three claim workers' options, awaited with the pass's stop signal:
  - before each claim. A worker waiting there holds no claim, and a stop ends it.
  - at the start of each pass, before its pool and counts (and consolidation's stale re-pool), after the leases a worker could not return are released. A stop there ends the run with no pass; the summary's counts are read only for a summary. Re-embed's waits before the start's drain and each poll's pool, the leases a worker could not return tried before the poll's. Its start's own pool is made before the pass's stop exists, and is not gated.
  - extraction, before each window of a windowed thought that is sent (`extractEntities`' new `admit`, after `progress`). The claim and lease are kept; the wait moves the thought's time held (`inHand.since`) on and is not the model's time. A stop throws `StoppedBetweenWindows`: the windows answered are kept, or with no keeping the claim goes back.
  - consolidation, before each pair. The claim and lease are kept. A stop throws `StoppedBetweenPairs`: the thought goes back to the pool unrecorded, its proposals so far standing, and every pair is judged again at its next claim but those it proposed.
- What the gate waits on is the first stop and the pass ending for a reason of its own: another worker's provider outage (`halt`), the provider's refusal or a worker's throw (a per-pass `passEnds`; re-embed's per drain, its outage, halt and record moving too). One signal a pass, so a follower's months of claims add no listener each.
- A rejection that is no stop ends the pass with the caller's error (`lease.ts`' `AdmitThrow` carries it out of a thought), never recorded as the thought's.
- A hard stop at the window gate counts the thought's time up to the wait (`inHand`'s `pausedAt`), so a long wait stalls nothing.
- When the gate held a worker mid-thought (`admitted` says "waited": its answer was still pending when asked), the worker reads its claim, the thought's fingerprint by its own rule and its metadata (which the egress gate reads, compared as `md5(metadata::text)` in SQL) again before it sends more (`lease.ts`' `claimAfterWait`): the live write that closed the gate may be a delete or an edit of that thought. Deleted, it counts as vanished; requeued by an edit, as edited (extraction's superseded); reaped, as lost (both engines' new `lost`); still its claim but edited or retagged, the worker requeues it for its new text (`requeue_thought_work`, as a stale write is, out of the heartbeat's set first) and counts it edited, or lost in consolidation, which counts none of these judged. A failed requeue is said, and the worker stops, its finally returning the claim. Consolidation reads every older side still to judge again too: a deleted one is skipped, an edited one judged as it now reads.
- `Admit`'s docblock states its contract: an open gate resolves whatever its signal says, with a promise already settled (else each window and pair reads the claim again); one a worker waits at rejects once its signal aborts, and takes its listener off when it resolves.
- Re-embed claims one thought at a time under a gate unless `batch` is given (else 8), so a closed gate holds a worker after the thought in hand. Its start and poll gates wait under the follower's stamp, so a long wait does not read as a stale row.
- `db/README.md`: a paragraph after the four engines'.
- **Tests:** `db/test-support.ts`' `heldGate(openFor)`; test-local-provider [10], test-live [10], [16] and [9f] — listed in the merged note (`git show 75d8d122:changes/smd-3379.md`).

**Why.** PR 1c's scheduler pauses the passes while the brain is live and resumes them after, rather than ending them (the maintainer, 2026-10-26: a live write pauses, it does not stop). It needs a place in each engine to pause, which a stop still reaches. 1b-1 is that place, with no caller yet (SMD-3379's design, draft 5, accepted 2026-10-27; its PR 1b's per-call abort is 1b-2). The gate sits wherever a pass starts new work: a claim, a pool, a window, a pair.

**Version contract.** `admit` is an in-process option of `db/` engines, outside the contract until SMD-2601 ships `ob1-workers`. No flag, setting or default changes for a run without one. A patch.

**Held.** Twenty-eight mutants, each killed by its own rows: the gate dropped before extraction's claim, its pass, its windows (the worker's or `extractEntities`' own call), consolidation's claim or a pair, re-embed's claim or a poll; `admitted` reading a stop's rejection as through ([10]'s pass and window cases); a stop between pairs read as the thought's failure (the thought recorded failed); re-embed claiming eight under a gate; the first stop read before the window gate, not after (a stop that came while the gate held the window sent it); the hard stop's count read through the wait (stalled 1), the refusal waking no waiter (still waiting), the broken gate's error read as the thought's (recorded failed); the claim not read again after a wait at the window gate or the pair gate (the deleted thought's next window or pair sent), and the wait not moving `since` on (stalled 1); consolidation reading again only the current pair's older side, or none, or judging a moved thought on; extraction reading the gate's claim error as the thought's (the edited thought recorded failed), counting a deleted thought superseded, not requeuing a moved one, counting an edit's requeue lost, not reading a retag as moved, or hashing the metadata after its JavaScript round trip; `admitted` never saying "waited".

- **An edited older side judged with its old candidacy.** Its new text is judged and its new fingerprint recorded, but its similarity and shared entities are the claim's; an edit racing a call had the same before the gate.

### PR 1a: the migration lock

**What changed.** `db/config.mjs`' `MIGRATE_LOCK` (`ob1:migrate`) and `MIGRATE_LOCK_HOLDER_SQL`, which reads the holder (`pid`, `backend_start`) from `pg_locks` without taking it: a bigint key is `classid` (its high 32 bits, 4294967295 where `hashtext`'s int4 is negative) and `objid`. `db/migrate.ts`' `takeLock()` takes it once by `pg_try_advisory_lock` and sets `application_name` `ob1-migrate`; refused, it names the holder and the `pg_terminate_backend` remedy, exit 2. It is called before each first write of its kind: the ledger's `CREATE TABLE` when the ledger shows a core file pending or for `--reapply` (the read deciding what runs comes after, under the lock); each plugin write on a run whose core may have had nothing to apply (the plugin ledger, now made only where missing, the login role, a plugin's role, schema or grant, a hand-back, each plugin file); 096's re-run. Taken just now, it has the caller read again what it decided on. `run()` lets it go in its `finally`. `db/README.md` says when it is taken, what a second run sees, and the killed-run remedy.

**Why.** PR 1c must stop its passes while a migration writes, and nothing marked a run in progress (draft 3's choice 4). No lock for a no-op: the `migrate` service runs on every `up`. Measured on main, the second of two runs started 0–800 ms apart: at 0 ms one failed with a stack dump (`pg_type_typname_nsp_index`); at 100–400 ms the second failed on `schema_migrations_pkey`; from 600 ms it was a no-op. Now it is refused by name. A patch: no flag, value or schema change.

**Held.** test-live [1]: the lock not taken, taken after the ledger, not let go, taken by a no-op or a `--dry-run`, not by `--reapply`, or the holder not named. test-plugins-sql [11]: a plugin site's call dropped or moved after the file, the file's row not read again after a fresh take (a race case interleaves two runs), a settled run taking it. test-live [44]: 096's call dropped. 19 mutants killed ([OB1 PR 559](https://github.com/MHarris-SgyMd/OB1/pull/559)).

**Measured after.** ci-parity 89/90 after passes 1 and 2, the red SMD-2402's flake, then the sleep shard's [38] reset-wait case (a live write woke the sleep first); each shard passed alone.

**Review passes.** Three, the last with nothing above Low; their table is the merged note's ([OB1 PR 559](https://github.com/MHarris-SgyMd/OB1/pull/559), `git show 19618679:changes/smd-3379.md`).

**Not taken.** A lock that waits (a run would hang with no word); widening the early check to every repair (it would copy each repair's own test of need); locking every run (a no-op on each `up` would pause the passes); naming the lock in the no-ledger refusal beside a `--reapply`; retrying when the holder has just let go; making `--dry-run` leave no ledger (as it always has, SMD-2291); tests needing a cluster role dropped in a shared cluster.

**Follow-ups.** PR 1c reads the lock with `MIGRATE_LOCK_HOLDER_SQL`. Where 096 cannot take PUBLIC's grant back every run takes the lock, so 1c should exit only for a new ledger row.
