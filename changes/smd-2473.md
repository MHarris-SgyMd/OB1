## Changelog

A capture-only key's `supersedes` no longer tells it anything about the thought it names. The pointer is written only when the target is the key's own thought, attributed to its agent id and still present (not deleted); any other target is dropped before the write, the capture lands, and the reply is the same either way. `REFUSED_SUPERSEDES_OWNERSHIP` is gone, and while the agent registry is unreachable every target gets the same `SUPERSEDES_UNJUDGED` retry. A server whose registry cannot attribute its keys (logged as `agent registry: … cannot attribute` or `… refused`) no longer links a capture key's summaries by name; fix the grant, the search_path or the migration the line names, which preflight also reports. One channel stays open, filed as a follow-up: a re-capture returns the id of the row now holding the text, so a key that has seen a thought's id can tell whether that thought was since deleted or edited. No schema change (SMD-2473).

## FORK

A capture-only key's supersedes is no existence oracle — a pointer it cannot prove its own is dropped, not refused (SMD-2473)

**What changed.**
- **One rule in `core/writes.ts` `capture`.** For a key that cannot read, the pointer stands only when the target's capture audit row carries the key's agent id and the thought still exists. Otherwise it is dropped before the write, as `derived_from`'s ids are trimmed (SMD-1298), and the reply says nothing of it. The row's `supersedes` is the record of what was kept. Both reads (the audit row and the thought) run for every target, so a deleted own thought costs no failed write the others don't.
- **The registry away.** With the key's id not to hand, no pointer of its can be proven, and the answer comes before the target is read:
  - `SUPERSEDES_UNJUDGED` (retryable, `registry_away`) for every target while a retry may heal it;
  - the pointer dropped when it cannot.
- **`misconfigured`.** `agents.ts` tells the two apart with a third outcome beside `unreachable` and `refused`. It covers a registry that cannot answer this server until an operator acts. Its line names the act, once per SQLSTATE, so a second misconfiguration after a first is said with its own remedy:
  - 42883 or 42P01: `resolve_agent`, a function it calls, or a registry table missing from the role's search_path (SMD-2242);
  - 23514: a CHECK refusing the key's scope, on a brain before 049;
  - 42501: the server role without the `server` grant group's privileges on `ob1_agents` or `ob1_agent_keys`. `resolve_agent` keeps PUBLIC's EXECUTE and runs as the caller, so it is the tables that refuse. Since 054 a known key's row is written only when its last use is five minutes old, so this can first show minutes after a clean start.

  PostgREST's PGRST202 stays `unreachable`, because it also means a schema cache that is stale after a migration, which heals on reload.
- **No ownership by key name.** A row written while the registry could not attribute it carries a name and no id. A later key minted under that name owned it while the registry was away; now no capture key does.
- **The race.** A key's own thought deleted between the check and the write meets the self-FK, and the write goes again without the pointer. Each pointer kind gets one mend of its own, so two source races cannot spend the pointer's.
- **One code fewer.** `REFUSED_SUPERSEDES_OWNERSHIP` leaves `core/refusal.ts`, `render.ts` and the REST status table (it was a 403 on main's REST core, which no release has served yet; with the registry answering, a foreign or missing target is now a 201). A reader's `supersedes` is unchanged: `REFUSED_SUPERSEDES_UNKNOWN` for an id that names no thought. The `check_failed` remedy names both tables the check reads.
- **What a client meets.** With the registry answering, the session hook lands where it did, one round trip sooner: it dropped a refused pointer and posted again. It keeps reading `REFUSED_SUPERSEDES_OWNERSHIP` from an older server. Elsewhere it lands later or links less:
  - **Registry away, a missing target or another key's row without an agent id:** this was a final refusal that the hook mended at once. It is now the retry, so the summary waits under `pending/` until the registry answers, or until the hook's last resort drops the pointer (four attempts, or a week). An attributed target already got the retry; the key's own deleted row without an id answered `UNKNOWN`, and the hook dropped the pointer.
  - **Both session ends during an outage:** the second summary superseded the first by name. Now it waits, then lands without the pointer, because the first row has no agent id.
  - **Registry `refused` or `misconfigured`:** every capture-key row is unattributed and no chain links. After the operator's fix, the first new summary can't supersede the last one from before it.
  - **What no client can learn now:** whether a pointer was written. That is by design. The hook's own log line `captured … supersedes=<id>` names the pointer it sent, not one the server kept; the row's `supersedes` is what was written, and the registry's warning says when capture keys' pointers are being dropped. PR 2 rewords the hook's line, and should ship in the same release.
- **What a capture key can still learn (SMD-2554).** `upsert_thought` returns the id of whichever row now holds the text. A key that once got id I for text T, its own capture or another key's row handed back by a re-capture, can send T again: the same id back means I still holds T, and a new id means I was deleted or edited. So the deleted-own-thought bit closed on `supersedes` is still learnable for any thought whose id the key has seen. A text it has never seen an id for stays clean: ids are random, and pass 4's 100 paired fresh-against-existing captures were identical. Each such re-send also brings a deleted text back as a new row. Closing it means an opaque per-key handle in place of the row id, which reaches into the hook's state, so it is its own ticket.
- **The version.** PATCH, type security. No schema changes, and refusal codes are not on FORK.md's MAJOR list. The argument's meaning ("this replaces that") is the same; only the answer to a request the key was never allowed to make changed. The rule's test, "a client written against N.x keeps working on N.y", holds for the tree's client: the hook still maps the old code, and lands one round trip sooner. The REST 403 never shipped.

**Why.** The check answered differently by target, through its code, its sentence and (since SMD-2283) `structuredContent`:
- with the registry away, a missing target or another key's unattributed row was refused, an attributed one retried, and the key's own unattributed row written by name;
- the key's own deleted thought passed on its audit row and reached the self-FK, so it alone answered `UNKNOWN`;
- a re-capture hands the key the existing row's id, so naming that id as `supersedes` succeeded only if the text had been new. Two calls answered whether any chosen text was already in the brain, the fact `existed` is withheld to hide.

Any answer that differs between "written" and "not written" carries that last bit. So the ticket's sketch of one bit ("mine and present", or a refusal) still leaked it, and the reply had to be the same in every cell. SMD-2283 PR 2's review pass 1 had given every unprovable target `UNJUDGED`. That kept a hook waiting on a registry that could never answer, and it was reverted so PR 2 stayed a move.

**Held.**
- `test-e2e-sql` [13b] is the table: eight targets × four registry states (answering, away, refusing, unmigrated).
  - **Targets:** missing, deleted own, deleted foreign, attributed own, attributed foreign, unattributed own, unattributed foreign, a re-captured foreign text's id.
  - **One cell writes:** attributed own, with the registry answering.
  - **Away:** every target is one `SUPERSEDES_UNJUDGED`, word for word, and writes nothing.
  - **The other 23 cells** land without the pointer, answering word for word as the writing cell does, ids masked.
  - **No insert naming the deleted own thought** is tried, in any state.
  - **The re-capture's own reply** matches a fresh capture's.
- **The races:**
  - a trigger refuses the first insert naming a pointer, and the capture lands without it;
  - two source races before the pointer's end in the persistent race's `DERIVED_FROM_MISSING`, not `UNKNOWN`.
- **Ownership and cites** ([13]):
  - a renamed key's pointer is read back as written, so ownership is the agent id, not the name;
  - a written pointer logs SMD-1719's cite row, and a dropped one logs none.
- **Beside the table** ([13b], inside the insert counter's window):
  - with a `derived_from` source riding along, its own thought is still written and none of the other seven targets is;
  - its own id in upper case is still its own;
  - with no `source` at all, its own thought is written and another key's is not, so no check gates on a caller's claim;
  - a thought with no capture audit row is no key's;
  - refused or unattributable with a source beside the pointer, it is still dropped, never retried;
  - a reader's pointer, to its own thought or another key's, is written with the registry away or unattributable, and a ghost stays `UNKNOWN`.
- **Pinned:** the table holds 23 quiet cells and 8 away, the FK race's trigger is shown to have fired, and the two source races make exactly two validator calls.

**Not taken.**
- **Timing.** The reply is the same in every cell, but its time is not quite:
  - with `OB1_QUERY_LOG` on, only the cell that writes the pointer awaits SMD-1719's cite row;
  - 068's superseder fold runs inside that write.

  A capture's two model calls dominate its time, the query log is opt-in, and a cite row sent without being awaited could be lost on Workers. So this change holds the reply's words and value, not its clock. The existence read is kept for a different reason: without it, a deleted own thought cost a whole failed write.
