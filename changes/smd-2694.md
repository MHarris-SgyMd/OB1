## Changelog

A long thought's extraction windows survive a hard stop: migration 093's `extraction_progress` keeps each window as it parses, so the next claim of the same text sends only the windows still to do, and the stop is counted on the thought (SMD-2694).

## FORK

A long thought's answered windows survive a stop — a document longer than every sleep advances by its windows at each, where it started again at its first (SMD-2694)

**What changed** (PR 1).
- **Migration 093, `extraction_progress`:** one row per extraction claim a worker took and did not finish.
  - It holds the parsed windows by index, each with the hash of the request it answered, under the thought's content fingerprint and the worker's windowing. A write under another fingerprint or windowing replaces the row. A window saved under another window count replaces the windows, since the old indexes are of other windows.
  - `stops` counts the hard stops that took the claim. `gained` counts the windows saved since the last stop. `stalled` counts the latest long stops in a row with none saved between: long when the worker had held the thought a minute (`STALL_FLOOR_MS`), provider pauses aside, so short sleeps stall nothing.
  - `save_extraction_window` and `note_extraction_stop` write it for the claim's holder only. Each locks the claim row `FOR SHARE` and writes nothing unless the caller holds it.
  - The row hangs off the claim (`ON DELETE CASCADE`). The worker deletes it at a succeeded release; a failed release keeps it.
  - The `extraction` grant group holds SELECT, INSERT, UPDATE and DELETE on it.
- **`server-portable/entities.ts`:** `extractEntities` takes an `ExtractProgress`.
  - A window kept for exactly its request is reused, marked `resumed`, and not sent.
  - A new window is saved once it parses; a malformed one is never kept.
  - The windows are walked in order either way, so the merge is an unbroken run's.
  - `callsOf` counts only the windows sent.
- **`db/extract-entities.ts`:**
  - It loads a claim's kept windows and saves each new one.
  - Its hard stop counts itself on the thought each worker has in hand before that worker's lease goes back. It waits at most 1.5 s for that count, and counts once however many hard calls land. The worker's own release waits for the count.
  - A succeeded release deletes the kept row in the same statement. Each run prunes, once, rows beside a succeeded claim and rows of text the thought no longer holds.
  - A first stop (a deploy's SIGTERM, the operator's first Ctrl-C) ends a windowed thought at its next window, the windows answered kept and the lease returned at once.
  - The summary's calls, answers, retries, escalations and aborts count only the windows sent in this claim.
  - `--status` lists the thoughts with windows kept or stops counted.
  - Without the table or the grant it keeps nothing and says so once.

**Why.** A hard stop aborted the window in hand and returned the claim, and every window already answered went with it.
- The sleep scheduler hard-stops extraction at every wake (SMD-1794).
- On the stable brain every extraction over ten minutes is a document of 17 to 74 windows, at 30 to 300 s each (8,411 s for 28 windows, 2,206 s for 24). Single-window thoughts top out at 346 s.
- So a document longer than every sleep was never finished while the brain kept waking. Consolidation, which joins only once extraction drains, never joined behind it.
- Keeping the windows makes the waste go away where it is made: per window.

**Not taken.**
- **A trigger that deletes the row when its claim finishes or is requeued.** Under 016 the editing role runs the requeue, so every content edit would have needed grants on this table. The row is read beside its fingerprint instead, so a stale one is replaced, never reused.
- **A soft stop for a long window** (the ticket's option 2). It trades the yield for progress on a one-slot model, where a live capture's metadata call would queue behind the window.

**Follow-ups.** PR 2: consolidation joins past a thought whose stops gained nothing (`stalled`), and preflight's `sleep` row names it.
