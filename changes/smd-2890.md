## Changelog

A local model provider that is not up yet no longer fails preflight and restart-loops the server: it warns, the server starts degraded (captures land without vectors, searches answer by exact matches), re-probes every `OB1_PROVIDER_REPROBE_INTERVAL` seconds (15), and leaves degraded when the provider answers; keyed `/health` and `brain_info` say `provider: unreachable since <t>` (SMD-2890).

## FORK

A provider not up yet starts the server degraded, re-probed until it answers, where preflight failed it into a restart loop (SMD-2890)

**What changed.**
- **Preflight's probe row is split** (`preflight.ts` `probeLocal`):
  - A name that resolves with nothing answering is a provider not up yet — an Ollama on the host started after the stack, the profile's container still starting. The `provider endpoint` row warns, so preflight exits 0. Nothing answering means refused, silent past the 2.5 s probe, or no route (`EHOSTUNREACH`, `ENETUNREACH`, which the runtime's `providerDown` already counted an outage). The rule is `startsDegraded` in `provider-health.ts`.
  - The row says what degraded costs (captures without vectors, and untagged when chat shares the base; searches by exact matches; a silent endpoint holds each capture and search up to `OB1_LLM_TIMEOUT` first) and names the re-probe interval. The `chat endpoint` row gets the same split, in its own terms: captures land untagged.
  - Still failures, exit 1:
    - a name that does not resolve (SMD-1875's case: the `ollama` service without its profile);
    - in a container (`/.dockerenv` or `/run/.containerenv`), a loopback host, which is the container itself, where nothing will start (SMD-1875's headline case; the maintainer's call);
    - a reset, or an untrusted certificate (something answers wrongly and will not fix itself);
    - anything unclassified;
    - any failure through a proxy, which is the route's before the provider's.
  - **The host aliases follow resolution.** `host.docker.internal` resolving, with nothing on the port, warns: the host's Ollama is not up. The alias not resolving fails: the runtime does not write it.
  - A set `OB1_PROVIDER_REPROBE_INTERVAL` gets its own row, as `OB1_VECTOR_MEND_INTERVAL` does; a value that does not read warns.
- **The provider's state** (`provider-health.ts`, new):
  - `createProviderHealth` keeps `unknown` / `answering {at}` / `unreachable {since, at, reason, detail, by}`, `by` being whether a call or the probe saw it.
  - Every embedding call feeds it through `heardFrom`: the capture's and the edit's (`core/writes.ts`), the search's (`core/reads.ts`), and a mender tick's (`core/mend.ts`). A 4xx is an answer. The tick counts as down only when its calls met outages and none was answered.
  - An outage seen by a call that began before the provider was last seen answering is passed over: a timeout that started before the provider came back says nothing about now.
  - Only a change is logged: once to degraded, once back.
- **The re-probe** (`startProviderReprobe`, started by `index.ts` and `api.ts` beside the mender, stopped in `endOpen`):
  - It probes once at start, then every interval while the provider is not answering. The probe is preflight's `GET /models`: no credential, no redirect followed, 2.5 s (one constant, shared). A 5xx, 408 or 429 is an outage.
  - **The probe ends only what it can see** (`probeClears`): its own outage, or a call's failed connection. A call's 5xx, timeout or broken body ends only with a call that is answered. A proxy whose backend is down answers `/models` and fails `/embeddings`, and a probe that cleared that flapped the state.
  - It probes only a local endpoint, by preflight's local rule. A hosted one would cost a credential, so its state moves with real calls alone.
  - Timers are unref'd and never overlap.
- **Reported:**
  - `ServerFacts.provider` (state and `reprobeS`) is in the keyed `/health` and in `brain_info`'s new `Provider` row, which follows `Embedding`.
  - The keyless `/health` stays `ok`, so a container health check never restarts a degraded brain.
- **The knob** `OB1_PROVIDER_REPROBE_INTERVAL` (1–3600, `0`/`off`) is in `compose.yaml`, `compose.tiers.yaml`, `.env.example` and `root.ts`.
- **Docs:** `server-portable/README.md` (the probe paragraph, a "serving degraded" paragraph, the env list), `deploy/README.md` (the profile paragraph, "Order is not kept"), `SETUP.md`.

**Why.** SMD-2887 measured a down provider at start as no start at all. SMD-2888 and SMD-2891 made capture and search survive a provider outage, and SMD-2889 mends what waited. But preflight still failed every refused or silent endpoint, so `unless-stopped` restarted the container until the provider came up. At boot, an Ollama on the host that starts after the stack meant a loop with no backoff under podman (SMD-2043), and nothing said a running brain was degraded, or when it stopped being.

**Not taken.**
- **Skipping the embedding call while degraded** (a circuit breaker). A silent provider still holds each capture up to `OB1_LLM_TIMEOUT` (120 s). The row says so, and SMD-3205 weighs it.
- **Probing a hosted endpoint.** It costs a credential and a billable call.
- **Re-probing the chat endpoint.** It holds no state: every capture calls it, so the first answered call ends its outage.
- **Probing the embeddings call itself** so the probe could see a 5xx behind a proxy. It would cost a model call (and a model load) per interval; the mender's tick is that call already.
- **A shared state across servers.** Each process keeps its own, so a restart starts at `unknown` and probes at once.

**Follow-ups.** SMD-3205: skip the embedding call to a silent provider the server already knows is unreachable.
