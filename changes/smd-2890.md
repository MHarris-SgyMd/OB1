## Changelog

A local model provider that is not up yet no longer fails preflight and restart-loops the server: it warns, the server starts degraded (captures land without vectors, searches answer by exact matches), re-probes every `OB1_PROVIDER_REPROBE_INTERVAL` seconds (15), and leaves degraded when the provider answers; keyed `/health` (`provider`) and `brain_info` (`Provider: unreachable since <t>`) say so (SMD-2890).

## FORK

A provider not up yet starts the server degraded, re-probed until it answers, where preflight failed it into a restart loop (SMD-2890)

**What changed.**
- **Preflight's probe row is split** (`preflight.ts` `probeLocal`):
  - A name that resolves with nothing answering is a provider not up yet — an Ollama on the host started after the stack, the profile's container still starting. The `provider endpoint` row warns, so preflight exits 0. Nothing answering means refused, silent past the 2.5 s probe, or no route (`EHOSTUNREACH`, `ENETUNREACH`, which the runtime's `providerDown` already counted an outage). The rule is `startsDegraded` in `provider-health.ts`.
  - The row says what degraded costs (captures without vectors, and untagged when chat shares the base; searches by exact matches; a silent endpoint holds each capture and search up to `OB1_LLM_TIMEOUT` first) and names the re-probe interval. The `chat endpoint` row gets the same split, in its own terms: captures land untagged.
  - Still failures, exit 1:
    - a name that does not resolve (SMD-1875's case: the `ollama` service without its profile);
    - in a container (`/.dockerenv` or `/run/.containerenv`), a loopback host, which is the container itself, where nothing will start (SMD-1875's headline case; the maintainer's call);
    - a reset, or an untrusted certificate (something answers wrongly and will not fix itself);
    - anything unclassified;
    - any failure through a proxy, which is the route's before the provider's.
  - An endpoint that answers `GET /models` with a 5xx, 408 or 429 is there and not ready yet: it warns too, as the runtime's probe reads it.
  - **The host aliases follow resolution.** `host.docker.internal` resolving, with nothing on the port, warns: the host's Ollama is not up. The alias not resolving fails: the runtime does not write it.
  - A set `OB1_PROVIDER_REPROBE_INTERVAL` gets its own row, as `OB1_VECTOR_MEND_INTERVAL` does; a value that does not read warns.
- **The provider's state** (`provider-health.ts`, new; its definition settled in review pass 4):
  - `unknown`; `answering {at, by, fault?}` — `by` a call (it embeds) or the probe (`GET /models` answered: reachable); `fault` an answered call refused or unusable (a 4xx, a body that is not JSON, the wrong width), where a capture fails outright; `unreachable {since, at, reason, detail, clears}` — `clears` what may end it: `probe` for an outage `GET /models` sees, `call` once a call failed where it is blind (a 5xx, 408, 429, a timeout). Set when it opens, escalated by a call, reset by an answer; the words always the latest.
  - Every embedding call feeds it: the capture's and the edit's (`core/writes.ts`) and the search's (`core/reads.ts`) through `heardFrom`; a mender tick (`core/mend.ts`) directly, down only when its calls met outages and none was answered, stamped with the start of the call that met the last, and a broken body a fault there too.
  - An outage seen by a call that began before the provider was last seen answering is passed over — before a call last answered, for one only a call can see — on the monotonic clock.
  - Only a change is logged: degraded ("does not answer" for a connection or a timeout, "fails its calls" for the rest), back, a fault.
- **The re-probe** (`startProviderReprobe`, started by `index.ts` and `api.ts` beside the mender, stopped in `endOpen`):
  - For a local endpoint, by preflight's local rule: `GET /models` at start (with the knob off too, then never again), then every interval while unreachable. No credential, no redirect followed, 2.5 s (one constant, shared); a 5xx, 408 or 429 an outage.
  - Its answer ends an outage whose `clears` is `probe`. For one whose `clears` is `call` it then spends one real call — an embedding of the word `probe` through the server's own embedder, as a query (preflight's `--deep` sends `preflight`) — and that call's answer ends it. A silent provider so costs the probe's 2.5 s a round, and each process ends its own outage, mender lock or not, with no traffic.
  - The egress gate is asked for that call once, at start; refused, it is not made, and the facts (`reprobeByCall`) and the `Provider` row say only an answered call ends such an outage, and why.
  - A hosted endpoint is not probed; its state moves with real calls alone. Timers are unref'd and never overlap.
- **Reported:**
  - `ServerFacts.provider` (the state, `reprobeS`, `reprobeByCall`) is in the keyed `/health` and in `brain_info`'s new `Provider` row, which follows `Embedding`: "answering (an embedding call answered …)", "reachable (GET /models answered …)", "answering, but refusing its embedding calls (…)", "unreachable / failing its calls since …", and what ends it.
  - The keyless `/health` stays `ok`, so a container health check never restarts a degraded brain.
- **The knob** `OB1_PROVIDER_REPROBE_INTERVAL` (1–3600, `0`/`off`) is in `compose.yaml`, `compose.tiers.yaml`, `.env.example` and `root.ts`.
- **Docs:** `server-portable/README.md` (the probe paragraph, a "serving degraded" paragraph, the env list), `deploy/README.md` (the profile paragraph, "Order is not kept"), `SETUP.md`, `docs/01-getting-started.md` ("Done when"), and the comments in `compose.yaml` and `release.yml`.
- **CI:** fork-checks' image step holds the split in the built image (below).

**Why.** SMD-2887 measured a down provider at start as no start at all. SMD-2888 and SMD-2891 made capture and search survive a provider outage, and SMD-2889 mends what waited. But preflight still failed every refused or silent endpoint, so `unless-stopped` restarted the container until the provider came up. At boot, an Ollama on the host that starts after the stack meant a loop with no backoff under podman (SMD-2043), and nothing said a running brain was degraded, or when it stopped being.

**Not taken.**
- **Skipping the embedding call while degraded** (a circuit breaker). A silent provider still holds each capture up to `OB1_LLM_TIMEOUT` (120 s). The row says so, and SMD-3205 weighs it.
- **Probing a hosted endpoint.** It costs a credential and a billable call.
- **Re-probing the chat endpoint.** It holds no state: every capture calls it, so the first answered call ends its outage.
- **Letting answered `GET /models` probes end a call's 5xx after a while.** A probe cannot see the call's failure, so any window would be a guess; the call-shaped probe asks the call itself.
- **Probing with a call always.** A model call (and a model load) each interval for an outage `GET /models` sees as well; the call is spent only where the cheap probe is blind.
- **A shared state across servers.** Each process keeps its own, so a restart starts at `unknown` and probes at once; with the call-shaped probe each also ends its own.

**Follow-ups.** SMD-3205: skip the embedding call to a silent provider the server already knows is unreachable.
