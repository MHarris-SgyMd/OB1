## Changelog

compat/supabase-sql refuses a value that is not a postgres:// URL by naming its scheme alone, where it quoted the value's first forty characters, so a mistyped scheme on a connection string no longer prints the role's password; the value is trimmed first (SMD-2263).

## FORK

The shim's refusal of a non-postgres URL names its scheme, never the value — a mistyped connection string no longer prints its password (SMD-2263)

**What changed.**
- **`createClient`** (`compat/supabase-sql/index.ts`) trims the value, then refuses one that is not `postgres://` or `postgresql://` by its shape alone:
  - `got a "mysql:" URL`;
  - `got a "postgres:" value without "//" after its scheme`;
  - `got a "POSTGRES:" URL whose scheme is not lower case`;
  - `got a value with no URL scheme`, where a bare `user:password@` is not read as a scheme;
  - `got nothing`.
- **The message keeps its prefix,** "expected a postgres:// connection URL", so the recipes' READMEs that quote it still match.
- **A value with a stray space or newline** is trimmed, not refused, and shares the pool of the same URL.
- **`compat/supabase-sql/README.md`**'s Safety section says the refusal never repeats the value.

**Why.** The refusal quoted `String(databaseUrl).slice(0, 40)`.
- For a codemod-ported server the value was a Supabase project URL, so the quote was harmless.
- The hand-ported recipes (brain-backup, lint-sweep) pass `SUPABASE_URL` as a `postgres://user:password@host/db` string. A one-slash `postgres:/user:pw@…`, a `mysql://…` or a quoting slip printed the password's first characters on stderr. SMD-2139's run-it review pass found it.
- Twenty-one vendored files reach the refusal.
- The maintainer chose to fix it in the shim now rather than wait for the shim's deletion (2026-10-26).

**Held.**
- **`compat/supabase-sql/test-compat.ts` [1], 302 of 302:**
  - a project URL names `https:` and not its host;
  - a `mysql:`, a one-slash `postgres:`, a capitalised `POSTGRES:`, a scheme-less `u:password@`, a blank and an unset value each give their shape, and no part of the value (the password, the host, the user) is in any message;
  - a URL with a leading space and a trailing newline is trimmed and shares the pool.
- **`db/test-live.ts` [26]:**
  - lint-sweep's refusal of a Supabase URL names `https:` and not the host;
  - brain-backup's, given `mysql://u:pw-not-real@…`, names `mysql:`, and its output never holds `pw-not-real`.
- **The ticket's Verify by hand:** lint-sweep and backup-brain.mjs with that value exit 1, name `mysql:`, and no line of their output holds the password.
- **Mutants:** the old quote restored fails seven of test-compat's assertions; the trim dropped fails it at the spaced URL.
