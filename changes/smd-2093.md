## Changelog

Both workflows name their runner image, `ubuntu-24.04`, where they had `ubuntu-latest`, which GitHub moves to Ubuntu 26 from 2026-10-19. Every action is pinned to a full commit SHA with its tag in a trailing comment, where it had a tag its owner could move (the release job runs its actions with `packages: write`), and moved to its current major, all on Node 24. `.github/dependabot.yml` moves the pins weekly, and check 23 refuses a tag, a `-latest` runner, or a SHA with no tag comment (SMD-2093).

## FORK

The workflows name their runner image and pin every action to a commit; Dependabot moves the pins and check 23 holds them (SMD-2093)

**What changed.** Every `runs-on: ubuntu-latest` (ten in `fork-checks.yml`, one in `release.yml`) is `ubuntu-24.04`, the image `ubuntu-latest` resolves to today, so nothing about the runner moves in this PR. Every `uses:` is a full commit SHA with its tag in a trailing comment, each at the current release of its current major. `actions/checkout` goes from v4 to v7.0.1, `actions/upload-artifact` from v4 to v7.0.1, the three `docker/setup-*`/`login` actions from v3 to v4, and `docker/build-push-action` from v6 to v7.4.0. `oven-sh/setup-bun` stays v2 (v2.2.0, the commit `v2` pointed at). Every one runs on Node 24, so the "Node.js 20 is deprecated" warning goes. The ticket named checkout v5, but v7 is current. Dependabot would open that PR on its first run, and none of the majors crossed changes an input or behaviour these workflows use. The changes were checkout v6's credentials file, checkout v7's refusal of fork checkouts under `pull_request_target`, build-push v7's removal of two env knobs this job never set (`DOCKER_BUILD_RECORD_UPLOAD`, the one it sets, stays), and setup-buildx v4's removal of deprecated inputs it never passed.

`.github/dependabot.yml` has one `github-actions` update over `/`, weekly, with minor and patch releases grouped into one PR and each major sent alone. Dependabot rewrites the SHA and the comment together. Its commit-message prefix is `"[fork] "`, with the trailing space. dependabot-core appends a colon to a prefix that ends in a letter, a digit, `)` or `]`, and `[fork]: Bump …` would fail commitlint's header rule, an error. The space gives `[fork] Bump …`, which passes, with only the ticket-suffix warning.

Check 23 in `scripts/check-fork-consistency.ts` holds every workflow under `.github/workflows/` to three rules:
- every job's `runs-on` names an image: no `-latest` label, and no expression it cannot read;
- every `uses:` (a step's, or a job's reusable workflow) is a 40-hex SHA with a `# vX.Y.Z` comment, a local `./` path, or a `docker://` image by digest;
- `.github/dependabot.yml` keeps its `github-actions` entry over `/`.

The structure is read with Bun.YAML. The comment, which a parser drops, is read from the value's own line. So a SHA-pinned step in flow style is refused, since its tag cannot be read, while a `uses:` line inside a `run:` body is text and is left alone.

zizmor (1.30.1, run once as the ticket asked, online audits included) reported two kinds of finding, and both are fixed. `artipacked` covered all eleven checkouts, which left the job token in the workspace. They now set `persist-credentials: false`: no step talks to the remote after checkout (the full history comes with `fetch-depth: 0`, and the repository is public). `cache-poisoning` flagged the release job's `setup-bun`, which now sets `no-cache: true`, so the Bun it publishes with is downloaded fresh. FORK.md's "Checking CI on this fork" says all of this in one paragraph, and "Files we own" lists `dependabot.yml`.

**Why.** On 2026-10-19 `ubuntu-latest` becomes Ubuntu 26 on GitHub's schedule, not ours. The Docker, compose, python3, jq and shellcheck steps all depend on what the image ships, so the switch would have landed as an unrelated red on whichever PR ran first after it. Now the move is a PR of its own, with the stack job's lines rerun. A tag is a pointer its owner, or anyone holding its owner's credentials, can move, and the release job runs five third-party actions holding `contents: write` and `packages: write`. SMD-1808 set SHA pinning aside, and a pin that nothing checks drifts back the first time someone copies a step from a README.

**Held.** Check 23's probes run on in-memory workflows. It accepts seven: a SHA pin with its tag, one quoted, one on the line after the step's name, a docker image by digest, a label list with no `-latest`, a `uses:` line inside a `run:` body, and two steps on one pin. It refuses twelve mutants with exactly one problem each, naming what broke: `ubuntu-latest`, a `-latest` label in a list, a runner by expression, a major tag, a branch, a short SHA, no ref, no comment, a comment naming no tag, flow style, a docker image by tag, and a reusable workflow by tag. It holds `dependabot.yml` to three more cases: a missing file, an npm-only entry, and another directory. On the live tree, four mutants each fail the check, and the restored tree passes: build-push put back on `@v6`, one runner put back on `ubuntu-latest`, setup-bun's tag comment deleted, and `dependabot.yml` removed.

**Measured after.** Both of the ticket's greps come back empty: `grep -n runs-on` finds no `-latest`, and `grep -nE 'uses: [^#]+@v[0-9]'` finds no match. actionlint 1.7.7 (CI's pin, with shellcheck) passes on both workflows. zizmor's default persona reports nothing, online audits included (impostor commits, known-vulnerable actions, a tag comment that does not match its SHA). The scripts typecheck and check-fork pass.

**Not taken.**
- Pinning the three `pgvector/pgvector:0.8.6-pg16` service images by digest. zizmor's pedantic persona asks for it. They are pinned by version tag, compose pulls the same tag, and moving that pin is a stack change (SMD-1860 pinned Ollama the same way), not a workflow one.
- Holding `persist-credentials: false` in check 23. It is fixed once, as the ticket asked of zizmor's findings.
- Moving to `ubuntu-26.04`. That is its own PR, as the ticket says.
