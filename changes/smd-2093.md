Every action is pinned to a full commit SHA with its tag in a trailing comment, where it had a tag its owner could move (the release job runs its actions with `packages: write`), and at its latest release, all on Node 24. `.github/dependabot.yml` moves the pins weekly, a week after a release, and check 23 refuses a tag, a SHA with no tag comment, or a `-latest` runner (SMD-2093).

## FORK

The workflows name their runner image and pin every action to a commit; Dependabot moves the pins and check 23 holds them (SMD-2093)

**What changed.** Every `runs-on: ubuntu-latest` (ten in `fork-checks.yml`, one in `release.yml`) is `ubuntu-24.04`, the image `ubuntu-latest` resolves to today, so nothing about the runner moves in this PR. Every `uses:` is a full commit SHA with its tag in a trailing comment, each at its action's latest release. `actions/checkout` goes from v4 to v7.0.1, `actions/upload-artifact` from v4 to v7.0.1, the three `docker/setup-*`/`login` actions from v3 to v4, and `docker/build-push-action` from v6 to v7.4.0. `oven-sh/setup-bun` stays v2 (v2.2.0, the commit `v2` pointed at). Every one runs on Node 24, so the "Node.js 20 is deprecated" warning goes. The ticket named checkout v5, but v7 is current, and Dependabot would open that PR on its first run. None of the majors crossed changes an input or behaviour these workflows use; every `with:` key they pass is declared in the pinned action.yml. The changes were checkout v6's credentials file, checkout v7's refusal of fork checkouts under `pull_request_target`, build-push v7's removal of two env knobs this job never set (`DOCKER_BUILD_RECORD_UPLOAD`, the one it sets, stays), and setup-buildx v4's removal of deprecated inputs it never passed.

`.github/dependabot.yml` has one `github-actions` update over `/`, weekly, with a seven-day cooldown, minor and patch releases grouped into one PR, and each major sent alone. Dependabot rewrites the SHA and the comment together. Its commit-message prefix is `"[fork] "`, with the trailing space. dependabot-core appends a colon to a prefix that ends in a letter, a digit, `)` or `]`, and `[fork]: Bump …` would fail commitlint's header rule, an error. The space gives `[fork] Bump …`, which passes, with only the ticket-suffix warning.

Check 23 in `scripts/check-fork-consistency.ts` holds every workflow under `.github/workflows/` to three rules:
- every job's `runs-on` names an image: no `-latest` label in any case or size (`macos-latest-large` moves too), and no expression it cannot read; a runner group alone names none and passes;
- every `uses:` (a step's, or a job's reusable workflow) is a 40-hex SHA with a `# vX.Y.Z` comment (`# X.Y.Z` for an action whose tags carry no `v`), a local `./` path, or a `docker://` image by digest;
- `.github/dependabot.yml` keeps a `github-actions` entry over `/` that can open a PR (not limited to 0, not ignoring `*`).

The structure is read with Bun.YAML. The comment, which a parser drops, is read from the value's line: the first unclaimed line carrying it, with block scalars (a `run: |` body) skipped. So a SHA-pinned step in flow style is refused, since its tag cannot be read, and a copy of a pin inside a run body lends a bare step nothing. The check holds a pin's shape, not its truth: a comment naming another tag, or a commit only a fork of the action holds, is zizmor's to find.

zizmor (1.30.1, run once as the ticket asked, online audits included) reported three kinds of finding, all fixed. `artipacked` covered all eleven checkouts, which left the job token in the workspace. They now set `persist-credentials: false`: no step talks to the remote after checkout (a job that reads history takes it at checkout, and the repository is public). `cache-poisoning` flagged the release job's `setup-bun`, which now sets `no-cache: true`, so the Bun it publishes with is downloaded fresh. `dependabot-cooldown` flagged the new `dependabot.yml`, which now waits seven days. FORK.md's "Checking CI on this fork" says all of this in one paragraph, and "Files we own" lists `dependabot.yml`.

**Why.** On 2026-10-19 `ubuntu-latest` becomes Ubuntu 26 on GitHub's schedule, not ours. The Docker, compose, python3, jq and shellcheck steps all depend on what the image ships, so the switch would have landed as an unrelated red on whichever PR ran first after it. Now the move is a PR of its own, with the stack job's lines rerun. A tag is a pointer its owner, or anyone holding its owner's credentials, can move, and the release job runs five third-party actions holding `contents: write` and `packages: write`. SMD-1808 set SHA pinning aside, and a pin that nothing checks drifts back the first time someone copies a step from a README.

**Held.** Check 23's probes run on in-memory workflows. It accepts eleven: a SHA pin with its tag, one quoted, one on the line after the step's name, a docker image by digest, a label list with no `-latest`, a `uses:` line inside a `run:` body, two steps on one pin, a bare copy of the pin in an earlier run body, a tag comment with no `v`, a runner group alone, and a group with a named image. It refuses nineteen mutants with exactly one problem each, naming what broke: `ubuntu-latest`, a `-latest` label in a list, with a size, in another case, and as a group's label; a runner by expression; a non-string label; a major tag, a branch, a short SHA, no ref; no comment, a comment naming no tag, and the second of two steps on one pin left bare; a bare step under a run body carrying the commented pin; flow style; a docker image by tag; a reusable workflow by tag; and no `jobs:`. It holds `dependabot.yml` to two accepted forms (`directory: /`, `directories: [/]`) and five refused ones: a missing file, an npm-only entry, another directory, a limit of 0, and an ignore of `*`. Deleting any one of the rules the review added or tightened fails a probe; nine code mutants were run, one per rule. On the live tree, four mutants each fail the check, and the restored tree passes: build-push put back on `@v6`, one runner put back on `ubuntu-latest`, setup-bun's tag comment deleted, and `dependabot.yml` removed.

**Measured after.** Both of the ticket's greps come back empty: `grep -n runs-on` finds no `-latest`, and `grep -nE 'uses: [^#]+@v[0-9]'` finds no match. actionlint 1.7.7 (CI's pin, with shellcheck) passes on both workflows. zizmor's default persona reports nothing on `.github/workflows/` or `.github/dependabot.yml`, online audits included (impostor commits, known-vulnerable actions, a tag comment that does not match its SHA). The scripts typecheck and check-fork pass.
