## Changelog

An opt-in `orchestration` compose profile runs n8n beside the brain: pinned by digest, a SQLite store of its own (measured against a Postgres 17), loopback only, a 24-hour run-history window, its owner set from the environment; `deploy/orchestration/provision.ts --init` writes the profile's secrets and a provisioning run keeps an expiring API key in `deploy/.env` that later runs revoke when replaced, loads credentials and templates, and refuses a brain key at write scope or the wrong scope; the eval kit now runs its checks against the profile as it ships, with key, pruning and egress-probe checks (SMD-2210).

## FORK

n8n as an opt-in `orchestration` profile — pinned, its own store, expiring and separate keys, a short run-history window, and the eval kit re-run against what ships (SMD-2210)

**What changed.** `deploy/compose.yaml` gains an `n8n` service under
`profiles: ["orchestration"]`, beside `board-sync` and `jev`:
- `n8nio/n8n:2.40.6` by its multi-arch index digest, on n8n's default SQLite
  in the `n8n-data` volume.
- One port, `${N8N_BIND:-127.0.0.1}:${N8N_PORT:-5678}`, in check 13's form;
  PUBLISHES lists it.
- The telemetry switches, `N8N_BLOCK_ENV_ACCESS_IN_NODE`, and
  `N8N_DISABLED_MODULES=mcp-registry`: the egress probe caught that module
  calling api.n8n.io.
- A window of 24 hours or 1,000 runs (n8n's defaults: 336, 10,000).
- The owner set from the environment at every start
  (`N8N_INSTANCE_OWNER_MANAGED_BY_ENV`, a bcrypt hash), so a fresh instance
  cannot be claimed by whoever reaches the port first.
- An entrypoint that refuses to start without the encryption key or the
  hash. Compose's `:?` would fail every `up` without the profile.

`deploy/orchestration/provision.ts` is the provisioning step, run from a
checkout; the kit imports it.
- **`--init`** writes the missing secrets into `deploy/.env`: the key, the
  owner's password and hash (single-quoted: compose mangles a bare `$`,
  measured), and the two inbound keys, `N8N_MCP_KEY` (header `x-n8n-key`)
  and `N8N_WEBHOOK_KEY` (`x-n8n-run-key`).
- **A run** signs in through `/rest/login`. It keeps an eight-scope API key
  with its id and scopes (`N8N_API_KEY`, `_ID`, `_SCOPES`), expiring after
  `N8N_API_KEY_DAYS` (90). It mints a new key when the stored one is
  refused, lacks a scope asked for, has under a week left (half its life,
  if shorter), or on `--rotate`, writing it before any deletion.
- **Every run deletes every other `ob1-provision` key**, so one a failed run
  left goes on the next.
- **It checks every template before writing**: a brain key is refused at
  write scope (the legacy `MCP_ACCESS_KEY` included), when unlisted, or at a
  scope other than its credential's declared `brainScope`, wherever in the
  credential it sits; a template naming an undeclared credential is
  refused. Then credentials are created or patched, and templates created
  or replaced, through `/api/v1`.
- **`--self-check`** runs these rules against a fake n8n in CI.

The kit's n8n (`evals/orchestration/`) is now the profile. The driver passes
`--profile orchestration` and runs the profile's `--init`, and
`compose.n8n.yaml` changes only the pruning cadence. `--with postgres` gives
n8n a Postgres 17 of its own. `--with sealed` is the egress probe: an
`internal: true` network, a tcpdump watcher owning n8n's network namespace,
a Bun HTTP front, and a probe workflow of ten fixed captures. The two do not
combine. Beyond C1–C3 and C1s, `--verify` adds three checks:
- **K**: each inbound key refused on the other's path; after `--rotate` the
  replaced key answers 401, the new one's expiry is set, and one key is held.
- **P**: two saved runs moved 25 h and 23 h back in the store; the first gone
  from the API and the store, the second kept.
- **E**: nothing asked for or dialled outside the compose network but the
  templates' hosts (DNS, TCP SYNs, UDP), and the brain seen. The judge is
  pure, and `eval-orchestration.ts --self-check` runs it in CI.

`--up` stamps the brain's build and refuses a brain that does not report the
stamp.

**Why.** SMD-1863's ADR left the store to measurement and the profile to this
ticket. The POC ran n8n on the brain's Postgres 16, which n8n calls
"compatibility support only". Its key did not expire and stayed valid after
a re-mint, one key served two paths, and nothing probed what n8n dials.

**Held.** CI's "Every published port binds loopback" step pins three things:
n8n's port to loopback, its image to a digest, and a plain `config` to
`migrate postgres server`. `provision.ts --self-check` holds the rules
above, and `eval-orchestration.ts --self-check` holds E's judge. The kit
(`--verify n8n`) holds the rest against a live profile.

**Measured after.** On the dogfood Mac (2026-09-25, podman, the host's
Ollama), one cycle each.
- **SQLite and `--with postgres`** (implementation commit, `--wait-schedule`):
  C1–C3, C1s, K and P pass. Captures took 20.4 s and 22.8 s; the schedule was
  seen after 811 s and 752 s.
- **Review pass 1's code:** the plain profile passed C1–C3, K and P, and
  sealed passed C1–C3 (the act tool refused), K, P and E.
- **Egress:** the sealed n8n asked only for `api.linear.app`, and every one
  of its ten dials went to the brain, over about 2½ minutes.

The store is SQLite:

| store | n8n | its own server | extra image | on disk |
| --- | --- | --- | --- | --- |
| SQLite | 369 MiB | none | none | 6.4 MiB |
| Postgres 17 | 404 MiB | 52 MiB | 280 MiB | 15.5 MiB |

`deploy/README.md`'s backup (`VACUUM INTO`) and restore were run as written,
over a stopped n8n and into a fresh volume. The copy came back (a marker
workflow added after it was absent), integrity was ok, and the key answered.

**Decided here.** The store: SQLite. The import pipeline's runner: a keyed
HTTP runner in the profile, a bounded write path amending decision 4, built
with SMD-2212's first import template (`docs/orchestration-tool.md`,
"Running a pipeline from a workflow").

**Review passes.**

**Not taken.** A one-shot provisioning service with no standing key (the
maintainer chose the host script and a standing, expiring key). An n8n
image with Bun and python3 for the import pipeline (OB1 would distribute
n8n). A compose one-off the workflow starts (the engine's socket in n8n).
