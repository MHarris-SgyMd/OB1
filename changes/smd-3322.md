## Changelog

The operator GUI edits, deletes and captures a thought, and acts on a worker pool: a thought's page links to an edit page, which saves through `update_thought` and refuses an edit from a stale read rather than overwriting the change, and to a delete page, which confirms first and asks again before deleting a thought other thoughts cite; a capture page saves a new thought through `capture_thought`, labelled with the GUI's own source, `dashboard`; the workers page retries a pool's failed rows and releases its stale leases. Each calls the REST core under the signed-in visitor's credential, and a read session is offered none of them (SMD-3322).

## FORK

The operator GUI edits, deletes and captures a thought and acts on a worker pool, each through its REST-core operation under the visitor's credential (SMD-3322)

**What changed.**
- **The session** (`dashboard/src/lib/server/session.ts`) keeps the operations whoami named at sign-in, by a key or the authorization server's token. A page offers a write only where they list it (`rest.ts` `may`); the REST core still decides each call. `rest.ts` `write` calls an operation under the visitor's credential and hands its answer to the form action, so a refusal is said beside the form.
- **A thought's page** links to its edit and delete pages for a session that may call `update_thought` and `delete_thought`.
- **The edit page** (`/dashboard/thoughts/<id>/edit`) saves the text through `update_thought`, sending the `updated_at` it read as `if_unchanged_since`:
  - a change made since (another tab, a connector, a worker) is refused in words, never overwritten;
  - the form keeps the stale time it posted, since the page's load reads the thought afresh after a refusal; with the fresh time in the field, saving again would overwrite the change the refusal reported;
  - the form posts as multipart, so the text goes as it is, not percent-encoded; the GUI's body limit (`serve.ts`) rises from 64 kB to 1 MB for an edit's post alone, and a capture's since PR 2 (every other request, a sign-in signed out among them, is held to 64 kB in `hooks.server.ts`: by its declared length, and one declaring none, sent chunked, refused), and a thought whose text would post past 1,000,000 bytes — its UTF-8, each line break sent as CRLF (`writes.ts` `postedBytes`) — is not offered for editing, the page saying so;
  - an empty text, a NUL and a time altered to anything but the core's time form are refused before any call; a browser's CRLF breaks are saved as one break each, as the plugin pin saves them, and the field opens with the line break a browser drops, so a text's own leading break survives.
- **The delete page** (`/dashboard/thoughts/<id>/delete`) names the thought and asks first; a delete sends the visitor to the list, which says what was deleted, once, from a flash cookie named after the listener's session cookie, never from its address. A thought that statements in other thoughts cite is refused, the page saying how many (the core's `citedBy`), with a second confirm to delete it anyway (`detach_citations`).
- **The capture page** (`/dashboard/capture`, PR 2), in the nav for a session that may call `capture_thought`, saves a thought through it under the source `dashboard` (`writes.ts` `CAPTURE_SOURCE`), so a GUI capture is not labelled `mcp`, the conversational label egress `source:` terms key on, and per-source weights will (SMD-1297, SMD-3208). It posts as the edit page does (multipart, the same size limit, empty and NUL refused) and sends the visitor to the thought's page, which says from a flash cookie what the capture did: a new thought, or the one that already held the text, into which the core merges a capture by a key that can read — its source now `dashboard`, the metadata extracted merged in — and whether this capture wrote no embedding. A write that the REST core does not answer within 90 seconds (`rest.ts` `WRITE_TIMEOUT_MS`; a capture embeds and extracts, an edit re-embeds; not longer, since a front proxy such as a Cloudflare tunnel ends a request at 100 s), or at all, is said beside the form, which keeps the text: one past the time, or whose connection was lost after it was sent, may still have been made, so the visitor is sent to look first; only one never sent (the connection refused, the name unknown) is said not to have been.
- **The workers page** (PR 3) offers, for a session that may call them, Retry on a pool with failed rows (`retry_failed`) and Release on one with stale leases (`release_stale_leases`, its stale leases alone: a live lease is the CLI's `include_live`, which names its worker), each the pool's own form, and says how many rows it moved. Neither writes a `thought_audit` row: each logs an action row for each thought it touches, under the visitor's key (`core/workers.ts`). Both are idempotent, so the page answers in place rather than redirecting.
- **The smoke** (`dashboard/smoke.ts --writes`) captures a thought of its own on the capture page, edits it as the page's multipart form posts and deletes it on its pages, and holds a read key to none of them. Its keys may come from the environment (`OB1_SMOKE_KEY` and the two beside it) rather than its command line.
- **CI**, the full-stack job's GUI step, runs the smoke with `--writes` and its keys from the environment, then reads the arm's thought's audit rows.

**Why.** The GUI was read-only: SMD-2280's write verbs went with none of its children (SMD-3307, SMD-3309, SMD-3310), and SMD-3322 took them. SMD-3064 ([OB1 PR 560](https://github.com/MHarris-SgyMd/OB1/pull/560)) went first, so a write through the authorization server is audited as the GUI's own principal, `oauth:operator+gui`, not as every connector's one name. PR 1 ([OB1 PR 564](https://github.com/MHarris-SgyMd/OB1/pull/564)) brought edit and delete, PR 2 ([OB1 PR 567](https://github.com/MHarris-SgyMd/OB1/pull/567)) capture, PR 3 worker retry and release; accept and reject wait on SMD-3338.
