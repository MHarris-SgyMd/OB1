## Changelog

Preflight dials a local model endpoint once on every start — `GET /models`, no credential, 2.5 s — and the container refuses to start on one that answers nothing, naming the profile, the two host aliases or a key as the way out; until now an address that reached nothing was `preflight OK` and the first capture failed in 7 ms. `deploy/compose.yaml` gives the server `host.docker.internal` on Linux Docker, and CI's full-stack job proves both directions on every PR (SMD-1875).

## FORK

Preflight passed a local model endpoint it never dialled — a `provider endpoint` row connects to it once by default, so the `ollama` name with no profile, the container's own loopback and a dead host alias fail the gate instead of the first capture (SMD-1875)

**What changed.** `server-portable/preflight.ts` gains one row per local
endpoint, after the credential rows: `provider endpoint` for the embeddings
base and `chat endpoint` for a chat base of its own (the same base is one
socket and one probe). The probe is `GET ${base}/models` with no body, no
credential and `AbortSignal.timeout(2500)`; any HTTP status is an endpoint that
answers, and the row says which and in how many milliseconds, with "what it
serves is checked under --deep". Refused, unresolved (`ENOTFOUND`) or silent
past the timeout is a `fail` in those words, and the remedy is the hostname's
kind: a name in `LOCAL_PROVIDER_SERVICES` "is the local-models profile's
service and exists only under it"; loopback "inside a container is the
container itself, not the host"; `host.containers.internal` is podman's alias,
`host.docker.internal` Docker Desktop's, and Linux Docker's only through
`extra_hosts host-gateway`; a private address gets the generic line. Every
remedy names the three spellings. A hosted endpoint is not dialled without
`--deep` (unchanged), and neither is a hosted name declared local by
`OB1_LLM_LOCAL=1`: the probe follows the credential rule, the hostname, as the
row's own text says. `deploy/compose.yaml`'s `server` gains
`extra_hosts: host.docker.internal:host-gateway`, a hosts entry only, so
`.env.example`'s Option B is one address per runtime and CI can put a listener
on the runner. The Dockerfile's entrypoint is unchanged: `bun preflight.ts &&
exec bun index.ts` now refuses what it used to wave through.

**Why.** Measured 2026-09-21 on SMD-1843's baseline (change 102): the container
took the code's default, `127.0.0.1:11434` — the container's own loopback —
`isLocalHostname` called it local, no credential was wanted, nothing was dialled
without `--deep`, and the stack came up `preflight OK`. `capture_thought` then
failed in 7 ms with `Unable to connect` and the server log ended at `Started
server`. Change 102 removed that trigger (compose forwards the knob and falls
back to the `ollama` service); the shape survived for every wrong local URL —
the fallback with no `--profile local-models` (`getaddrinfo ENOTFOUND ollama` at
the first capture), an OpenRouter key filled in with the URL line left
commented (preflight warned about the key and said OK), a host alias the runtime
does not provide, a typo in the port. A gate that decides "local" from a
hostname and connects to nothing certifies an address, not an endpoint.

**Held.** `test-preflight.ts` [9], 23 assertions: refused (loopback port 1)
fails with exit 1 and the container remedy; the `ollama` name and the Docker
alias fail with their own remedies (port 1, so a resolver that knows the name
still fails, refused); a key beside the fallback address fails on the endpoint
where it used to warn and pass; a stub that answers passes at 200, 404 and 500,
and saw exactly one bare `GET /v1/models` with no `Authorization` header though
a key was set; a stub that accepts and never answers fails on the timeout, in
seconds, after about 2.5 s and not the run's whole patience; a hosted `.invalid`
name with a key prints no row and no resolver error, declared local or not; a
chat base of its own is its own row, down or up, beside a live embedder;
`--json` carries the row and its remedy. The suite runs its other cases against
one stub listener, since the code's default reaches nothing in CI and the real
Ollama on a dogfood box; `db/test-search-path.ts` points preflight at a hosted
stub name, its subject being the search path, and `db/test-live.ts`'s provider
stub answers the GET. CI's "Full stack, no Supabase" job starts a Python
listener on the runner's `0.0.0.0:11434` (host-gateway is the bridge address,
not loopback), greps the server log for the `✓ provider endpoint … HTTP 200`
row, and a new step runs preflight in the built image through
`compose run --entrypoint bun` with `OB1_LLM_BASE_URL=http://ollama:11434/v1` and
no profile — exit 1, the row failed, the remedy naming the profile — then the
same run at the reachable address, `preflight OK`, so the step proves the probe
and not a broken container. actionlint 1.7.7 clean.

**Measured after.** A throwaway compose project from this tree beside the
dogfood stack (podman 6.0.2, 2026-09-23). The ticket's case, the `ollama` URL
and no profile: the server never served — every start printed the `✗ provider
endpoint … the name does not resolve` row, the profile remedy and `preflight
FAILED — 1 problem`; under `restart: unless-stopped` podman restarted it 136
times in the 25 s the run watched (no backoff — a crashloop is the design,
change 16, but that rate is a follow-up). `host.containers.internal`, the Mac's
Ollama: `up --wait` returned in 33 s with `preflight OK (1 warning)`, as
before. `host.docker.internal` through the new `extra_hosts` line under podman
machine: `HTTP 200 to GET /models in 2 ms` — the alias reaches the Mac. The
CI negative step's exact shape: exit 1, all three greps matched, the positive
rerun `preflight OK`. Suites: test-preflight 396/396 with a database (132 dry),
test-search-path 23/23, test-live green, check-fork PASS.

**Not taken.** Reading the model list for the configured models (a stack under
the profile before `ollama-pull` finishes would fail on a race; `--deep`'s
question). `depends_on: ollama` for the server (a dependency on a profiled
service errors without the profile; the server starts after `migrate`
completes, which is after Postgres is healthy, and the restart policy re-runs
preflight for an `ollama` slower than that — the profiled bring-up itself was
not measured here, this Mac holding no Ollama image). Retrying the probe
inside preflight for a slow runtime (2.5 s is the connect, not the load). `HEAD` (Ollama answers it; not every runtime does).
Honouring `OB1_LLM_TIMEOUT` (a request budget, not a connect one). Dialling a
hosted name declared local (a credential proves it; that is `--deep`). A knob
to skip the probe (an operator who needs one has an endpoint preflight should
be failing). `extra_hosts` on `compose.tiers.yaml`'s three servers (the tier
stack is this Mac's, on podman, which provides its own alias).

**Follow-ups.** SMD-2043 — under podman a failing preflight restarts the server
without backoff (136 starts in 25 s); `restart: on-failure` with a bounded
count, or a sleep in the entrypoint on failure, so a crashloop is visible and
not hot.

**Upstream status:** not sent — upstream has no preflight and no `deploy/`;
the gate is this fork's (change 16, migration plan Phase 4).
