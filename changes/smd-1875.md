## Changelog

Preflight dials a model endpoint whose hostname is local once on every start — `GET /models`, no credential, 2.5 s — and the container refuses to start on one that answers nothing, naming by the name's kind the profile, the host aliases or the stack's own service as the way out; until now an address that reached nothing was `preflight OK` and the first capture failed in 7 ms. `deploy/compose.yaml` gives the server `host.docker.internal` on Linux Docker, and CI's full-stack job holds both directions on every PR (SMD-1875).

## FORK

Preflight passed a local model endpoint it never dialled — a `provider endpoint` row connects to it once by default, so the `ollama` name with no profile, the container's own loopback and a dead host alias fail the gate instead of the first capture (SMD-1875)

**What changed.** `server-portable/preflight.ts` gains one row per local
endpoint, after the credential rows: `provider endpoint` for the embeddings
base and `chat endpoint` for a chat base of its own (the same base is one
socket and one probe). The probe is `GET ${base}/models` with no body, no
credential, `redirect: "manual"` and `AbortSignal.timeout(2500)`; any HTTP
status — a 3xx included, unfollowed — is an endpoint that answers, and the row
says which and in how many milliseconds, with "what it serves is checked under
--deep". A failure is a `fail` in its own words with what a capture would have
done there: refused, or unresolved (any `getaddrinfo` failure, the code shown
when not `ENOTFOUND`) — fails in milliseconds; silent past the timeout — waits
up to its request budget (a resolver stalled past 2.5 s reads as this kind:
on Linux Bun reports a blackholed resolver as `getaddrinfo ETIMEOUT` at about
that mark); accepted and closed with no HTTP (`ECONNRESET`, an https port
dialled as http) — in Bun's words minus its advice about `verbose`; a TLS
certificate the server would not trust — "answers, but", every capture fails
the same way, and the remedy is trust (`NODE_EXTRA_CA_CERTS`), not addresses.
When `HTTP_PROXY`/`http_proxy` (or the https pair) is set the row says the call
went through it unless `NO_PROXY` names the host — Bun routes loopback through
a proxy too, so does every call the server makes, and podman forwards the
host's proxy variables — and the remedy leads with `NO_PROXY`. Otherwise the
remedy is the hostname's kind: a name in `LOCAL_PROVIDER_SERVICES` "is the
local-models profile's service and exists only under it"; loopback "inside a
container is the container itself, not the host"; the two host aliases, which
runtime writes which; a private address the generic line — each naming the
knob and the three spellings. Userinfo in a base URL is masked on every row
(fetch never sends it). A hosted endpoint is not dialled without `--deep`, nor
a hosted name declared local by `OB1_LLM_LOCAL=1`: the probe follows the
credential rule, the hostname.
`deploy/compose.yaml`'s `server` and `board-sync` gain `extra_hosts:
host.docker.internal:host-gateway`, a hosts entry only, so `.env.example`'s
Option B is one address per runtime and CI can put a listener on the runner;
the entrypoint is unchanged and now refuses what it waved through.

**Why.** Measured 2026-09-21 on SMD-1843's baseline (change 102): the container
took the code's default, `127.0.0.1:11434`, its own loopback; `isLocalHostname`
called it local, nothing was dialled without `--deep`, the stack came up
`preflight OK`, and `capture_thought` failed in 7 ms with `Unable to connect`,
the server log ending at `Started server`. Change 102 removed that trigger; the
shape survived for every wrong local URL — the `ollama` fallback with no profile
(`getaddrinfo ENOTFOUND ollama` at the first capture), an OpenRouter key with
the URL line left commented (a warning about the key, then OK), a host alias
the runtime does not provide, a typo in the port. A credential rule that decides
"local" from a hostname and connects to nothing certifies an address, not an endpoint.
