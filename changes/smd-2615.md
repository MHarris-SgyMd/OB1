## Changelog

The authorization server answers an absolute-form request target with a 400, where one with an authority the URL parser refuses (`GET http://x:99999/healthz`) used to stop its process, and no longer answers `//x/healthz` as `/healthz`; a throw in a request is now that request's 500, not the process's end. A target holding `#` or whitespace is a 400 too, dot segments are no longer resolved (`/auth/../healthz` is a 404, not `/healthz`), and `/auth?x` is a 404, not a 500. Only a caller on the internal mesh can send an absolute-form target: the proxy rewrites it to its path (SMD-2615).

## FORK

The authorization server answers an absolute-form request target 400 instead of stopping, and a throw in a request is that request's 500 (SMD-2615)

**What changed.**
- **`deploy/auth/target.ts`** (new) holds two things.
  - `targetOf(req.url)` gives a request target's path and query the way the library reads them.
  - `serve(listener)` makes the `node:http` server with its listener guarded. A throw or a rejection from the listener becomes a logged 500, or, once an answer has started, a closed connection.
- **`server.ts`** is made by `serve` and routes by `targetOf`'s path. It used to parse `new URL(req.url, "http://auth")`.
  - It imports `node:http` for its types alone, so going back to an unguarded `http.createServer` fails the typecheck (TS1361).
  - A target that is not a path is answered `400 bad request target: send the path alone`.
  - The provider is mounted at that path and query too. It used to get the raw `req.url` minus five characters.
  - Every branch that goes async returns its promise, so a failure there reaches the guard. Before, a failure inside the token gate's `then` was an unhandled rejection.

**Why.** Bun's `node:http` hands the listener the request target as sent. Measured on Bun 1.4.0, with this file run outside compose and asked over a raw socket:
- `GET http://x:99999/healthz` made `new URL` throw in the listener. The client got an empty 200, and the process exited 1. So one request stopped the server. Compose's restart policy brought it back, with the abuse limits it keeps in memory forgotten (`limits.ts`).
- `GET //x/healthz` resolved as host `x`, path `/healthz`, and was answered `ok`. The token gate and the registration cap tested that resolved path, while the provider was handed the raw target minus five characters (`uth/token` for `//x/auth/token`), so the two disagreed.
- A throw in the listener, a rejected promise from it and a throw in a timer each ended a minimal `node:http` server with exit 1.

**Who could send it.** Measured through a throwaway Traefik v3.7.13, the stack's pin:
- An absolute-form target reaches the backend as its path alone, with the authority moved into `Host`, which this server overwrites.
- `http://[::1/…` and `http://x:abc/…` are Traefik's own 400.
- `//x/healthz` arrives as `/x/healthz`.

So through the proxy nothing changed. The server sits on the internal `mesh` network with the proxy, the MCP server, the REST core and any tier that joins it, and any of those could send either target. Refusing absolute-form departs on purpose from RFC 9112 3.2.2, which has a server accept it: only a proxy sends it, and the proxy in front of this server sends the path.

**The path rule.** The library (oidc-provider on Koa) routes on the path `parseurl` gives.
- `parseurl` cuts a target that starts with `/` at its first `?`.
- But a target with a tab, LF, FF, CR, space, `#`, U+00A0 or U+FEFF goes to Node's legacy `url.parse` instead, which turns a `\` before the query into `/`. So `/auth\token#` routes as `/auth/token`.
- `targetOf` therefore refuses a target that does not start with `/` or that holds one of those characters. It cuts any other at its first `?` and never decodes or resolves it.
- Bun decodes the target as UTF-8, so an unencoded `à` arrives as U+00E0 and is read like any other character. Only a real U+00A0 is refused.

So the token gate and the registration cap test exactly the path the library routes. Before, they tested the WHATWG-resolved path, which is not the library's: it resolves dot segments and reads `\` as `/`.

**Not here.** The guard covers the listener and the promises it returns. A callback the listener or the library hands on runs outside it: the registration branch's `finish` and `close` handlers, its request timeout, or a timer.

**Held by**
- **`bun target.ts --self-check`** (10 probes, new; CI's "Authorization server rules"):
  - the path rule on named targets, `//x/healthz` among them;
  - the refused targets: absolute-form, each reparsed character, and `\` with `#` or FF;
  - every accepted target held against `parseurl` itself. There are 20,009 targets, 14,155 of them distinct and 5,236 accepted. The fuzz runs mulberry32 over `/ ? # \ . %2e %2F`, space, tab, LF, FF, CR, U+00A0, U+FEFF and `x:99999`, and it fails unless at least 12,000 fuzzed targets are distinct;
  - the rule held against Koa's own `ctx.path`, the path the library routes. Every UTF-16 code unit is tried inside a path before a `\`, and at a path's end. Exactly the eight characters it refuses drop out, leaving 131,056 targets, and none differs. So a koa or parseurl bump that read another character another way fails here, and so does a refusal that grew. `package.json`'s comment tells whoever bumps oidc-provider to keep this check green;
  - a row showing why the refusal is needed;
  - `serve` on a real server, where a connection left open is marked as timed out rather than read as closed:
    - a throw is a 500, and so is a rejection;
    - so is a thrown or rejected value that cannot be printed;
    - a failure after the answer started gets neither a 500 nor the guard's text;
    - and the server answers the next request.
- **CI's full-stack auth step:**
  - **One new row.** Raw-socket `GET http://x:99999/healthz`, `GET http://[::1/auth/token` and `GET //x/healthz` must answer `400 400 404`; a connection held open past 3 s reads `timeout`. `/healthz` must then answer 200, and the container must be running with no restart. Run outside compose, the row reads `400 400 404 200` on this change and `200 refused refused refused` on main, which exits 1.
  - **Two rows widened.** The cap row adds `/auth/reg?ob1=1`. In the lockout row every other bad secret, the 21st among them, goes to `/auth/token?ob1=1`. Each was run outside compose with its JavaScript taken from the workflow: it passes on this change and fails on a gate that tests the raw target.
