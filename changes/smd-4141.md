## Changelog

`db/backfill-open-items.ts` no longer fails on a thought whose `action_items` isn't a list. Board-sync wrote JSON null there on ten of stable's rows, and the backfill's `--dry-run` stopped with "cannot get array length of a scalar" before it counted anything. Such a thought is passed over now, whatever plan Postgres picks (SMD-4141).

## FORK

backfill-open-items.ts passes over action items that aren't a list (SMD-4141)

**What changed.** `db/backfill-open-items.ts` reads each thought's action items once, as `items`: the array where `action_items` is one, NULL where it is anything else. The count, the element test and the element read all take `items` alone, so no plan can hand `jsonb_array_length` or `jsonb_array_elements` a scalar. A `CASE` is evaluated in order; an `AND` is not.

**Why.** The script picked its thoughts with `jsonb_typeof(x) = 'array' AND jsonb_array_length(x) > 0`. SQL doesn't promise to evaluate the left side of an `AND` first, and Postgres didn't. Running SMD-3665's Verify on a copy of stable (v2.0.0, 2026-11-07) found 10 thoughts holding `action_items: null`, all of them board-sync rows from 2026-09-24 to 2026-11-05. On the copy, the backfill's dry run failed outright. On a scratch Postgres the same predicate failed every time, on a 51-row table with and without statistics, for null, a string, an object and a number alike.

**Held.** test-rest-sql [15] adds four thoughts whose action items are null, a string, an object and a number, written before the backfill's dry run. The dry run and the run pass over them: the counts, the opened items and the second run's nothing-left are as before. With main's script in its place, [15] fails three assertions with "cannot get array length of a scalar".
