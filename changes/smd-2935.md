## Changelog

A ticket in Linear's Duplicate status is now settled, as a Done or Canceled one is: it no longer blocks what it blocks, `prefer_current` ranks it below current work (`↓ Ranked ×0.25 — duplicate`), graph-centrality counts it under `--status done`, and the stated-status label prints it as Duplicate. Migration 103 adds Linear's `duplicate` status type to node_state's two status sets, and the board-findings poster reads the same set for a closed ticket (SMD-2935). Both need the brain and the tree on the same side of 103: `db/graph-centrality.ts` refuses a brain whose sets are not its own (an older checkout against a migrated brain, or this one against an unmigrated brain), and the findings poster stays off on a brain without 103 until board-sync restarts after the migration.

## FORK

Linear's `duplicate` status type known and settled — one definition of a closed ticket (SMD-2935)

**What changed** (migration 103).
- **`node_lifecycle_types()`** gains `duplicate` after `canceled`, and **`node_settled_types()`** becomes `{completed, canceled, duplicate}`. Same signatures, still IMMUTABLE.
- **`ob1_rebuild_source_gate()` runs after them.** 071's mirror stores, per source row, whether its thought's status is a known one, and 071 asks any migration that changes the set to rebuild it. No other stored row is computed from the sets: `ob1_ticket_head` keeps the status type as written.
- **Every function that names a set is altered to the volatility it has**, a no-op that invalidates the plans built on it in every session. A reader is any function outside the system schemas whose text names a set, in any case and quoted or not, or that depends on one (a `BEGIN ATOMIC` body); on stable that is eight. A procedure is left (no ALTER FUNCTION takes one), and a function the migrating role cannot alter is named in a NOTICE and left, rather than failing the sets over a plan refresh. Replacing the sets alone did not reach every cached plan: on PG 16 a session that had called `search_thoughts_current` six times kept demoting by 058's sets after 103, while a fresh session did not. A running server's pooled connections are such sessions.
- **Refuses by name** without 058 or 071; a re-apply is a no-op.
- **The readers follow, in the same change:**
  - `db/graph-centrality.ts`: `LIFECYCLE_TYPES` and `LIFECYCLE_FILTERS.done`, which its equality check holds to the brain's sets, so it refuses a brain before 103 (and an older checkout refuses a migrated brain), naming the remedy on each side.
  - `db/board-findings.ts`: `closed()` reads `= ANY(node_settled_types())` in place of its own `('completed', 'canceled', 'duplicate')`. The step refuses on a brain without 058's set (its own statement, so a schema without 058 is told so rather than failing to parse) and on one without 103, where a Duplicate would read open, naming the remedy after an older tree's `--reapply` too.
  - `server-portable/render.ts`: `duplicate` is a demotion word, so the structured `demoted` keeps it.
  - `server-portable/stated-status.ts`: the label's fixed words gain Duplicate (test-e2e-sql [22] holds them to `node_lifecycle_types()`).
  - The `search_thoughts` descriptions name Duplicate beside Done and Canceled (rest-client regenerated).
- **Not here:** what a Duplicate duplicates stays a link (053's `duplicate_of` facet), not a status. So a Duplicate whose original is still open reads finished, as a cancel does: it no longer blocks, a note under it is demoted, and a summary naming only it is about finished work.

**Why.** Linear's Duplicate status has `status_type = duplicate`, not `canceled`, and 058 listed six types. On stable on 2026-10-19:
- `ob1_ticket_head` held 16 Duplicate tickets;
- node_state read 18 rows (those tickets and two notes filed under them) as an unknown status, `open` NULL;
- their 16 gate rows said they do not gate.

So a Duplicate blocker still blocked and counted among `unknown_blockers`, `prefer_current` never demoted a Duplicate, 077 never counted one among a thought's finished tickets, and SMD-2932's poster carried a third definition of closed.
