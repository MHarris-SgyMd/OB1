## Changelog

A work thread can be read: the `thread` operation (MCP `thread`, REST `GET /v1/thread`, read scope) returns the thoughts holding one subject in the order they were captured, by its key (`ticket:SMD-3306`, or the ticket alone) or around a thought by its id, a page at a time. A superseded thought stays in its thread and is labelled, a ticket's own row shows its status as board-sync last wrote it, and a ticket's thread names the threads its board links reach. `fetch` says, for each thread a thought stands in, the thought it continues and the one that continues it (SMD-3306 PR 7a-2a).

## Record

A work thread can be read: the `thread` operation, and fetch's continues and continued by (SMD-3306)

**What changed.**
- **`thread`** (read scope; MCP `thread`, REST `GET /v1/thread`), in `server-portable/core/threads.ts`. Exactly one of `key` or `id`:
  - `key` reads that subject's thread from its start, `limit` thoughts a page (1–100, default 20). A ticket's key may be given alone (`SMD-3306`), in any case. When more follow, the thread carries a `cursor`, passed back as `after` with the same key.
  - `id` reads each thread the thought stands in, around it: up to half the page before it, then it and those after, its `place` marked.
- **What a page carries.** Each member has its id, title, time and place (1 the first). A superseded member carries `supersededBy` and stays in the thread, which keeps its history. A board ticket's own row (its `metadata.issue` a ticket's shape) carries `ticket`: the ticket and its status as board-sync last wrote it. The row is rewritten in place, so it keeps its first place. These are the maintainer's decisions of 2026-11-06.
- **Linked threads.** A ticket's thread names the threads its ticket's board links reach (`linked`): each one's key, how its ticket stands to this one (`parent`, `child`, `blocks`, `blocked_by`, `relates_to`), and how many thoughts its thread holds. They are read from 053's `linear` links, the ticket's rows' own and the other rows' naming it. Only the first 50 are shown, with `linkedMore` set when there are more. No thread runs across a link, and `duplicate_of` and a text reference link none.
- **`fetch`** carries `threads` where the thought stands in one: per thread, its key, the thought's place, the thread's size, and the members it continues and that continue it (`continues`, `continuedBy`), each with its title and `supersededBy`. A thought in no thread adds nothing to ChatGPT's shape. A failed read gives `threads: null` and is said in the log, as the `claimed` label's is.
- **The store** has two new reads: `threadPage` and `threadPlaces`. Both read a thread from its standing subjects (111's key index), numbered in 120's order (created_at, ties by id, an undated thought last), not from 120's edges. So a thread reads whole on a brain that `db/threads.ts` hasn't linked yet.
- **A refusal**, `REFUSED_THREAD_INPUT` (400), with `problem`:
  - `key_or_id`: neither key nor id is given, or both are;
  - `key_shape`: the key is not a subject key. It is named in MCP's text, never in its value;
  - `after_needs_key`: `after` is given with an id.

  A cursor of another tool's is `REFUSED_CURSOR`. An id that no thought has is `NOT_FOUND`.
- **MCP's value** carries a ticket's, pull request's or version's key. A phrase key is the judge model's words, so it rides the text alone, quoted.
- `tools.json`, OpenAPI and `rest-client` are regenerated, and `server-portable/README.md` gains a "Work threads" section.

**Why.** Migration 120 made a thread's edges stand, but nothing read them: a thread was visible only to `db/threads.ts --status`. The maintainer cut 7a-2 in three (2026-11-06): this read; SMD-2726's relations read (7a-2b); and the unlinked-threads signal in preflight and `brain_info` (7a-2c). The `thread` read takes a thought's id or a subject key, as the maintainer chose.

**Not here.**

- The unlinked-threads signal (7a-2c).
- A thread is numbered by reading it whole, which is fine at a subject's size: stable's largest held 47 thoughts on 11-06. A brain with a phrase held by tens of thousands of thoughts would want a keyset read instead.
