# 113. `thought_audit` becomes the log of record — who from the key, the door, the ceiling on the content, stance, cites and the valid window on every write; immutable by rule; migration 046 (SMD-1730)

**Premise.** 008 made `thought_audit` the one row every capture, update and delete leaves, written by a trigger inside the mutating transaction, UPDATE and DELETE refused by a second trigger; 010 put a stable agent id beside the key's name; SMD-1541 made the five vendored servers pass an actor at all. SMD-1729 makes this table the log the rest of the program derives its views from, and for that it lacked the fields those views read and one rule. Nothing said whether the key belongs to the operator, to an agent or to an importer copying external text, so a read that wants "what the operator said" (SMD-1726) or "how far to trust this" (SMD-1724) had nothing to filter on. The door a write came through lived in `actor_context.via`, a key in the blob 008 declares "analytical only". Nothing recorded what a write claimed to rest on, its stance, or when the fact it states was true in the world. And "derived from the key, never the payload" was a sentence in the epic and nothing in the schema.

**Two columns for the two questions.** `actor_kind` is *who holds the key*; `trust` is *the ceiling on the content* — the same three words, `operator | agent | ingested`, ranked in that order. The case that settles it, from SMD-1724: the operator's key handing in an ingested web page is actor `operator`, trust `ingested`, which one column read two ways cannot say. trust is never above the kind: undeclared, it *is* the kind; declared lower, the declaration stands; declared higher, it is clamped to the kind and the attempt is recorded on the same row under `actor_context.claimed`, a key the trigger owns (whatever the envelope itself sent under that name moves under `caller_claimed`). A key of unknown kind supports no claim above the floor — only a declared `ingested`, a lowering nobody can abuse, is kept. The reader's rule, on the column's COMMENT: a row is a clamp exactly when `claimed->>'trust' IS DISTINCT FROM trust`, since a backfill that later honours a declaration made under an unknown kind leaves the mark and makes them equal. SMD-1724 and SMD-1726 are label-and-filter work on these two columns.

**The kind lives in the registry, and the function is the enforcer.** `ob1_agents` (010) gains `kind`, set by `set_agent_kind(label, kind)` — an upsert by label, so a key can be classified before its first request; `resolve_agent` then meets a known label with an unknown digest, its rotation branch, and attaches the hash. The audit trigger reads the kind by the envelope's `agent_id`, else by the key's name (`ob1_registry_kind`, the one lookup the trigger, the amendment gate and the backfill share; `ob1_trust_ceiling` the one ladder), and never from the payload. Declined: a fourth field on `MCP_ACCESS_KEYS`' `name:scope:sha256` — 010's rule is that the environment authenticates and the table records who, and a kind in the env would be a claim parsed by seven byte-identical `auth.ts` copies; a second variable keyed by name — two lists to keep aligned. NULL is the honest value for a key nobody has classified; preflight's `audit events` counts the keys that still hold a live digest and resolve by no write of their own, and the rows waiting on a kind, naming `set_agent_kind` and the backfill (the owner's call, since the pass amends the log and locks the registry). The trigger reads the registry as the writer, so SELECT on `ob1_agents` joins `ROLE_GRANTS.capture` (since 046) and preflight's `write privileges` requires it while 046's trigger body is installed; the migration grants nothing itself — a privilege lands as every one before it has: the row, the check naming it, `migrate.ts --grant`.

**`origin` is a second column, and `source` becomes one vocabulary.** `origin` is the door — SMD-1541's `via`, promoted from `actor_context` on 008's own reasoning for promoting a key; `ob1_door_of` reads it (a non-blank string, trimmed; anything else stays in the blob, visible), and the trigger strips it as 010 strips `agent_id`. `source` narrows to the row's own `metadata.source`; the trigger no longer reads an actor's `source`, which had carried three vocabularies (a transport, a worker's name, nothing). Every in-repo writer passes `via`: `server-portable` its MCP server name `open-brain` from one constant; the bio worker, `consolidate.ts` and `reembed.ts` their own. SMD-1903's `egress` record rides beside it in the blob.

**The event rides one envelope key.** `p_payload.event` on both inserting `upsert_thought` forms (the 4-argument form delegates), and a tenth, defaulted `p_event` on `update_thought` — 032's mechanism carried one form further: the older form's ACL captured, the 9-, 8- and 7-argument forms dropped, the ACL replayed, one function whatever state the file meets (`UPDATE_THOUGHT_SIGNATURE_9` in `db/config.mjs` is the retired form's one spelling). The shape, `{stance, cites, valid_from, valid_until, trust, actor_kind}`, is validated by `validate_write_event`: stance one of three words; cites UUID strings naming thoughts that exist, canonicalised as `validate_derived_from` does; trust and actor_kind one of three words; a key the shape does not have refused. A window bound is a string that begins `YYYY-MM-DD` (Postgres's own words for a time — `now`, `infinity` — refused), read as UTC when it carries no zone and as Postgres reads it when it does: `' UTC'` is appended and the cast tried first, which succeeds only for a zone-free input since Postgres refuses two zones, else the input is cast as it came, else refused — independent of the session's `TimeZone` across ninety inputs; a bare abbreviation resolves through `timezone_abbreviations`, which nothing in the fork sets (SMD-1948 decides whether to refuse one). A bad *shape* is refused as 025 refuses a bad `derived_from`; a *claim* the key cannot support is clamped and recorded. The functions validate before any lock and write `ob1.event` immediately before their INSERT or UPDATE, after every refusal; the trigger reads the setting inline once and clears it when it was set, so no later call or raw write in the same transaction inherits it. An unchanged write that declares a stance, cites or a window is an event — one row, the diff empty, the restatement SMD-1722 counts; one that declares only a trust or kind the key supports writes nothing; one that over-claims writes the clamp. `delete_thought` is not redefined — a tombstone declares nothing and the trigger reads no event on DELETE — and `thoughts_delete_clears_event`, a BEFORE DELETE statement trigger, clears the setting before any row work, so the successor rows a tombstone's `ON DELETE SET NULL` audits inherit nothing whatever the after-trigger queue's order. Both capture bodies and the trigger carry contract sentinels preflight's `atomic capture`, `write privileges` and `audit events` checks read, so a 025 or 035 body put back by hand is named.

**Immutable by rule.** `thought_audit_refuse_mutation` (008) gains the one lawful amendment: under `ob1.audit_amend = 'backfill'`, an UPDATE may leave each of `actor_kind`, `trust`, `origin` as it was or set it to what the row itself derives to (the registry's kind for its id else its name, the door its blob carries, the ladder's trust from the claim the trigger filed), must fill something, must stamp `backfilled_at` with this transaction's `now()`, every other column byte-equal; DELETE never; TRUNCATE — which fires no row trigger, a door 008 did not mean to leave — refused by the same function as a statement trigger (CLAUDE.md's guard rail now says a refusing trigger is the rule applied; SMD-1936 makes the rail mechanical). The trigger knows which change is lawful, so no grant or `DISABLE TRIGGER` has to. SMD-1723's redaction is the second named amendment and goes in this function.

**The backfill is a function.** `backfill_thought_audit_events(p_limit)` fills `origin` from the blob's `via` and `actor_kind` and `trust` from the registry by id else by name, stamping `backfilled_at` — 023's shape, callable again as kinds are set, the UPDATE's WHERE re-evaluated on the locked row so two passes at once fill each row once. It holds the registry rows FOR SHARE for the pass, so a reclassification waits rather than making the gate and the candidates disagree; a label classified for the first time mid-pass is a partial fill the next pass finishes. It resolves the registry once per distinct writer (a `MATERIALIZED` CTE over the awaiting-kind index, `OFFSET 0` the fence against the planner pushing the lookup onto the rows), joins back on hashable keys, and reads the two partial indexes — `thought_audit_awaiting_kind_idx (actor_name) INCLUDE (canonical_agent_id, actor_kind)` and `thought_audit_awaiting_door_idx` on rows whose `via` is a door — as a BitmapOr; the census reads the first index-only. The migration calls it once: every SMD-1541 row gains its origin now; no row gains a kind at apply time. Trust on a backfilled row is the write path's rule applied late — never a raise.

**Not here, said so.** MCP tool arguments for stance, cites, the window and trust: SMD-1733, SMD-1725 and SMD-1724 give them semantics and add them. Facet events: SMD-1731's derivations table. Indexes on `actor_kind`, `trust` or `origin`: no reader yet; they arrive with SMD-1724's and SMD-1726's first read. The partition key is chosen and not applied — RANGE on `created_at` by month, said in the table's COMMENT; SMD-1697's bench decides when. The census and the backfill at a million rows, and whether the start-up census needs a bound: SMD-1947.

**Version.** MINOR: the columns are additive behind `IF NOT EXISTS`, and `update_thought`'s added parameter is defaulted, so every 9-argument call resolves as before.
