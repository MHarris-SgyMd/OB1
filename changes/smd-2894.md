## Changelog

The images, compose's Bun services and CI run Bun 1.4.3 (was 1.4.0), held to one version by a new consistency check; the Alpine images' base moves with it from Alpine 3.22 to 3.24. A user and password in brain-compare's URLs or in n8n provisioning's `--url` are sent as `Authorization: Basic` on every Bun, beside their own key, and never printed: brain-compare names a brain by host and path, provisioning prints `***@` (SMD-2894).

## FORK

Bun 1.4.3 everywhere, every pin held to one version; brain-compare and n8n provisioning send a URL's user and password as Basic on every Bun (SMD-2894)

**What changed.**
- **The pins.** Every `bun-version` in `.github/workflows/fork-checks.yml` (ten) and `release.yml` (one), all twelve `FROM oven/bun:` lines in the eight Dockerfiles (server-portable, db, db/tier, deploy/auth, deploy/orchestration's runner, evals/auth, jev, kubernetes-deployment), compose.yaml's four worker tags and the forwarder's digest (the multi-arch index `1.4.3-alpine` resolves to, `sha256:629e1741…`, in compose.tiers.yaml too), the sealed n8n compose, the tier image as db/README.md and deploy/README.md describe it, the run lines in evals/README.md and three eval headers, and check-fork-consistency's own fixtures, from 1.4.0 to 1.4.3.
- **Check 33** holds them together. Every workflow step that uses `oven-sh/setup-bun` names `bun-version`, and every `oven/bun:<tag>` in a file git tracks or would track is a tag of the version `server-portable/Dockerfile`'s FROM names; a Dockerfile's FROM (in any case), a compose `image:` or a workflow's `container:` with no tag (Docker's `latest`) is refused, and one tag pinned by digest names one digest. `changes/` and `CHANGELOG.md`, which record what was, are not read. Each rule is held by in-memory probes.
- **"The stack runs the pinned Bun"**, a step in the full-stack job: that the forwarder's digest is its tag's image is the registry's fact, not the tree's, so the running forwarder and the server built FROM its tag are asked `bun --version`.
- **brain-compare** (`db/brain-compare.ts`): `splitKeyFromUrl` takes a user and password off the base with `embed.ts`'s `splitUserinfo`, now exported, and `fetchOrThrow` sends them as Basic beside `x-brain-key`, for a URL given on the command line or read from `claude mcp get`. The brain reads only `Bearer` from `Authorization`, so a front's Basic is no key to it. The label was the host and path already.
- **n8n provisioning** (`deploy/orchestration/provision.ts`): every request goes through `n8nFetch`, which takes the userinfo out of the URL and sends it as Basic beside n8n's key or session. `waitReady`'s failure and the run's last line print n8n's URL through `embed.ts`'s new `shownUrl`, `***@` where the userinfo was.
- db/README.md (`--compare`) and deploy/README.md (`--url`) say so.

**Why.** CI and every image pinned 1.4.0 while the maintainer's machine ran 1.4.3 from 2026-10-11, and the suites disagreed there: 1.4.3's fetch sends a URL's userinfo as Basic, where 1.4.0 dropped it (SMD-2885, which made the provider, jev and Telegram endpoints send it explicitly). Nothing held the pins together — eleven `bun-version` lines, twelve FROMs in eight Dockerfiles, seven compose `image:` lines and the run lines in the docs — so a bump could miss one. brain-compare and provisioning run from a checkout on the operator's own Bun, which no pin reaches, so what they sent depended on that Bun; the maintainer chose to send it on purpose, as the provider endpoints do.

**What the bump changes in the images: nothing they send.** Probed on both versions (review pass 1): 1.4.3 differs only for a fetch that sets no `Authorization` of its own; an explicit header wins over userinfo on both, and `node:http`'s `request` sends userinfo as Basic on both. Every request the images make is one of the three: the provider, jev and Telegram endpoints through `providerEndpoint` (SMD-2885); the PostgREST store through supabase-js and the Kubernetes server's provider calls, each with its own Bearer; the authorization server's fetch guard and the OpenTelemetry exporter, through `node:http`.

**What the bump changes under the images: Alpine 3.22.5 to 3.24.2** (review pass 2). `oven/bun:1.4.3-alpine` is built on a newer Alpine than 1.4.0-alpine was, so the images that add packages get that Alpine's: db/tier.Dockerfile's `postgresql16-client` is still 16 (16.15), as its build requires, and the import runner's `python3` is 3.14 — no Python emitter ships yet (SMD-2147–2150 add them, each pinned). Built here on the new bases: the tier image, jev's (`1.4.3-slim`) and the runner's.

**What else 1.4.1–1.4.3 change, read from their release notes** (review pass 3), and what in the tree each could touch:
- `sql.begin()` rejects (`ERR_POSTGRES_COMMIT_ROLLED_BACK`) where a callback swallowed a failed query and Postgres rolled back, which used to resolve. No transaction callback here catches a query's failure and carries on: brain-info's reads each run in a savepoint, the migrator's dry run throws its own rollback, the plugin role step rethrows; the other sites catch nothing.
- An already-rejected promise from `fetch()` or `Bun.write()` that nothing awaits now raises `unhandledRejection`. No such call is left unawaited.
- `fetch()` checks TLS against the URL's host, not a `Host` header (1.4.1). No fetch here sets one.
- A Postgres failure to encode a parameter or decode a value now rejects that query alone, not the connection's other pipelined queries; `node:http` and `Bun.serve` fix pipelining and abort edge cases. Narrower failures, none relied on. CI builds the server, migrator, Kubernetes, authorization and runner images, and the release workflow its two.

**Not taken.**
- Leaving brain-compare and provisioning to Bun's own behaviour: offered, and the maintainer chose explicit Basic.
- The Kubernetes server's provider calls, which always send Bearer, so a base's userinfo is never sent, and which print the base as written in their errors: the same on both versions, so not the bump's; a copy of the split would go in `integrations/_shared/`, since its image cannot import `server-portable/`: SMD-2901.
- `@types/bun` stays at 1.4.0 in the seven type-checked directories (check 18 holds them equal): npm has no 1.4.3 yet, 1.4.2 the newest: SMD-2900.
- The openclaw plugin: a Node bundle (`--platform=node`) run by OpenClaw, where fetch refuses a URL with credentials; no Bun pin reaches it.
- The "Bun 1.4.0" in comments and records that say what was measured on it: they are history, and stay.
