# 535. The MCP server stack moves to SDK 2.4.0 — three releases, one test that reused a stateless transport, and a tool list that reads the same byte for byte (SMD-4342)

**Why.** The servers were pinned at `@modelcontextprotocol/server` and `core` 2.1.0, published 2026-09-23. 2.4.0 followed on 2026-10-23, with 2.2.0, 2.3.0 and 2.3.1 between. Two of its changes bear on a server built per request, as `mcp-server/app.ts` builds one: since 2.3.0 `registerTool` no longer converts every tool's schema at registration, which a per-request server did on every request; and 2.4.0 fixes a server on a per-request transport at a modern revision answering `-32022`, which bears on serving 2026-07-28 (SMD-4345).

**What changed.**

- `@modelcontextprotocol/server` and `@modelcontextprotocol/core` are 2.4.0 in `mcp-server/package.json`, `server-portable/package.json` and `evals/auth/package.json`, each `bun.lock` regenerated. The three lockfiles change by those two packages and nothing else: both declare the dependencies they did at 2.1.0 (`zod ^4.2.0`), so `zod` and `hono` stay.
- `SERVER_V2_PINS` in `db/test-support.ts` names 2.4.0 in the same commit, so the drift guard in `integrations/test-auth.ts` never meets a mixed tree.
- `server-portable/test-plugins.ts` [9]'s SDK check builds a server and a stateless transport for each request. It had sent `initialize` and then `tools/call` through one stateless transport, and since 2.3.0 a stateless transport serves one request: the second `handleRequest` threw "Stateless transport cannot be reused across requests". The assertion is the one it was, and the suite counts 308 as before.
- `evals/mcp-clients/package.json`'s comment no longer says the probe's pin is ahead of the brain's.

**Not changed.** Which protocol revision the brain serves: `mcp-server/app.ts` stays on `WebStandardStreamableHTTPServerTransport`, the 2025-era wiring, and already builds a server and a transport per request, as `evals/auth/resources.ts` does. No tool's name, schema or answer. `@modelcontextprotocol/client` in `evals/` stays 2.1.0 (SMD-4343), and `evals/orchestration/mcp-client.ts` stays on the v1 package (SMD-2281). `docs/mcp-sdk-v2-migration.md`, `docs/one-brain-per-stack.md` and `docs/mcp-client-refresh.md` name 2.1.0 as what was measured when they were written, and stay.

**The three releases, against the tree.** 2.3.0's one server per connection and one request per stateless transport: the two servers already complied, one test did not (above). 2.4.0 treats an `outputSchema` whose root is a `$ref` into its own `$defs` as an object schema, which changes where a 2025-era client reads `structuredContent`: no tool here has one. 2.4.0's Ajv refuses a `$id` or `$ref` with an invalid URI scheme, and rejects `x-mcp-header` on a `number` parameter: no schema here has either. 2.3.0 validates `prompts/get` without `arguments` as `{}`: the brain registers no prompt.

**Held.**
- The tool list, by measurement: all 47 core tools and the 74 operations of the ten registry plugins, registered as `mcp-server/app.ts` registers them and listed once by each SDK, give the same `tools/list` result on 2.1.0 and on 2.4.0, byte for byte (503,280 bytes). All 74 output schemas have a plain `type: "object"` root, so none is wrapped on either. The script was run from `mcp-server/` and not kept.
- Mutant, the guard's teeth: with `mcp-server/package.json` put back to 2.1.0, `integrations/test-auth.ts` fails one row, naming "2.1.0 vs 2.4.0" for both packages; restored, 148 of 148.
- On 2.4.0: `mcp-server/test-mcp.ts` 195 of 195, `server-portable/test-server.ts` 1,650 of 1,650, `server-portable/test-plugins.ts` 308 of 308, the counts `main` has.
- The authorization-server proof of concept with `evals/auth/` on 2.4.0, as CI's job runs it (`eval-auth.ts --up`, `--verify` twice, `--down`, oidc-provider): 36 of 36 checks both times.
- A real connector against a stack built from the branch: a scratch compose stack (its `mcp` container holding `@modelcontextprotocol/server` 2.4.0), and a headless Claude Code 2.1.325 session at its `/mcp` with a write key. It listed 47 tools and called `brain_info`, `capture_thought` and `thought_stats`, each answered; the stack's request log shows the client's `server/discover` probe refused 400, then `initialize`, `tools/list` and the three calls, all 200 `ok`.
- The 2025-era transport's options read the same in 2.1.0's and 2.4.0's declarations, `maxRequestBodySize` among them, so no new default meets `/mcp`.
- Each of the three lockfiles installs with `--frozen-lockfile`. `./db/ci-parity.sh` passes whole (588 s), the authorization server's self-checks in it; `check-consistency`, `check-landing` and commitlint pass.
