## Changelog

With the embedding provider down, `search_thoughts` and the compat `search` answer with the thoughts that hold the query's identifiers and quoted spans — then, those matching nothing, the whole query as one text — matched exactly, and say so: the endpoint, what happened there, and that `search_thoughts_keyword` finds any word. They failed with the runtime's raw "Unable to connect" before (SMD-2891). The compat `search` with nothing found is refused `EMBEDDING_PROVIDER_UNAVAILABLE`, retryable. An empty filtered search now says when its literal is held only by thoughts outside the filter, with the provider up too. Migration 104 adds the query log's arm `literal`, and the replay gate and the live bench count a brain answering that way as failing the search.

## FORK

A search the embedding provider does not answer for is answered by its exact-literal arm, said so and logged as arm literal (SMD-2891)

**What changed** (migration 104).
- **The search operation** (`server-portable/core/reads.ts`'s `runSearch`, which both tools share): when the query's embedding call fails as an outage (`providerDown` — refused, unresolved, timed out, 5xx, 429 — SMD-2888's rule), the same hybrid function is called with no vector. `match_thoughts` finds nothing on `NULL`, so the rows are 017's exact-literal arm alone: the needles `extract_search_needles` takes and its rarity rule, under `prefer_current` (059) and `min_trust` (075) alike. No SQL function changes; the store passes `NULL::vector`. Any other failure — a 4xx, a width mismatch — still fails the search, as it fails a capture.
- **When the literals match nothing**, the whole query is matched as one text, case aside (filter and `min_trust` kept), by the store's bounded `textThoughts`: one scan that stops at the first 1,001 matching rows, the page ordered newest first, its count past 1,000 said "more than 1000" — never `search_thoughts_keyword`'s function, whose whole-set count held every pool connection for seconds on a common word (pass 8): plain words (`Kubernetes`, `sleep scheduler`), and an identifier too common to match exactly (`GitHub`) — the ticket's "fall back to keyword search", and the one answer the compat `search` can give a one- or two-word query (pass 4, the maintainer's call; pass 5, whether or not the query held a literal). Not for a query under three characters, over 64, or only words the English parser drops (`the`, `of the`, `AI`), 017's rule for a quoted span, which `literalFacts` reads. `vectorFailed.matched` says which: `literals`, `text`, or `none` (nothing could be matched, said so). The text is the query without the whitespace at its ends. A text match past the limit says its count, and a too-common literal beside it; `prefer_current` ranks no text match, and the reply says so; `literalOnly` is null for one. An empty answer whose text is held only outside the search's scope says so first; one whose sentence holds no literal says no thought contains it.
- **The facts when nothing matched.** The function reports its needle facts only on a row, and without a vector a literal too common to match yields none. The store's new `literalFacts` probes each needle for its 101st matching row exactly as 075's hybrid does (012's escaping, the `OFFSET` that plans it through the trigram index). It runs only where no literal matched an unfiltered search, so each needle is absent there or too common; a probe row still comes first in `search_thoughts`, for a literal held only outside the search's scope. The facts keep the hybrid's terms — an absent literal a needle counted 0, a common one in `commonNeedles` alone — and `literalOnly` is null then (unknown, not false).
- **The compat `search` with nothing found** is refused `EMBEDDING_PROVIDER_UNAVAILABLE` (retryable; REST 503 with Retry-After), naming over MCP the endpoint, what was matched and each literal absent or too common (REST's value is the code, the word and `matched`) — an empty list reads as "nothing stored" on a surface that shows results alone, where the outage was an error before (pass 4, the maintainer's call).
- **A literal held outside the search's scope.** An empty answer whose unfiltered probe counts a literal (a filter, `said_by`, `actor` or `min_trust` kept its thoughts out) now says "Held only by thoughts outside this search's filter, said_by, actor or min_trust: X (in N thoughts)", with a vector or without; it said nothing before.
- **The value** carries `vectorFailed: { reason, detail, base, matched }`, present only then, the base as a row prints it (userinfo masked, SMD-2885). `search_thoughts`' text leads with "Semantic search is unavailable — the embedding provider at <base> failed: <detail>. So the query was matched only by its identifiers and quoted spans, exactly — not by meaning" (or "…and then as one text", or "nothing could be matched"), names `search_thoughts_keyword`, calls each hit an "exact match" and drops the "rest by similarity" notes; its typed result carries the marker word. The compat `search` marks each title `[exact match — semantic search unavailable]` (the field every ChatGPT surface hands the model, as `[ingested]` is) and adds the marker word and a `note`. REST answers the core's value (the OpenAPI text says so); the MCP server words it as in-process.
- **The query log** records such a search as arm `literal` (104 widens 059's check; the column's comment says what it is).
- **The replay** (`db/brain-compare.ts`): a reply carrying `vectorFailed` is that brain failing the search, as it was when the search errored; literal rows are left out of a plan and counted apart in the gate, as rows with no arm are, and neither count takes a query the plan replays on another arm. `db/bench-live.ts` counts such a search degraded, not a latency sample.
- The tool descriptions, `db/tier.ts`'s docblock, `evals/utilization.ts`'s arms and `LoggedSearchRow.arm`'s type name the new arm.

**Why.** Measured 2026-10-11 on a scratch brain with a stub provider whose socket was closed (SMD-2887): `search_thoughts` answered `isError` "Unable to connect. Is the computer able to access the url?", Bun's text, though `search_thoughts_keyword` answered in the same moment and the hybrid's literal arm needs no model. The caller was not told a working search existed. The compat `search` — ChatGPT's only search, which cannot reach `search_thoughts_keyword` — failed the same way. SMD-2890 (start degraded rather than refuse) waits on this.

**Not taken.**
- **A coded refusal for every outage search** (the ticket's first option): the literal and text matches answer without a model, so only the compat `search`'s empty answer is refused; `search_thoughts`' empty answer says why in its text and facts.
- **Logging `keyword` or `hybrid`**: either would replay as something that did not run. `literal` is one value for both functions; whether `prefer_current` was asked is not recorded for it, since no replay takes the row.
- **429 as an outage** (SMD-2888's rule): a rate-limited hosted provider now degrades a search, said so, rather than failing it; nothing reads its Retry-After.
- **The text match's order**: within its first 1,001 matching rows, newest first — not `search_thoughts_keyword`'s occurrence ranking, which would need the whole set. A text in more than 1,000 thoughts shows the newest of those found first, and says so.
- **A search's wall time**: nothing bounds it, and a client's abort does not cancel its statement — so before this change, for `search_thoughts_keyword`; the outage path's statements are each bounded now.
- **The refusal's REST value** is the code, the marker word and `matched`: the endpoint and the literals are the server's words and the caller's input, which `FACTS` keeps out, as for every refusal.
- **"Exact"**: the match is the keyword arm's, case-insensitive and by substring, so `SMD-1` also matches `SMD-12` and a three-letter text (`log`) matches inside a word (`catalog`); the hybrid's own words ("Searched exactly for") are kept, and the span rule keeps out only the shortest and the stopwords.
- **A provider that hangs**: a search still waits `OB1_LLM_TIMEOUT` before it falls back, as a capture does; a shorter query deadline is SMD-2890's degraded state to decide.
- **A filtered "too common"**: a literal common across the brain but absent from a filter's scope is said too common, with a vector or without — the probe has always been unfiltered.
- **The probe's race**: the facts come from a second statement after the search, so a thought captured between the two can make "No thought contains" or "Held only by thoughts outside" stale for that one answer; one statement for both was not worth a function change.
