## Changelog

With the embedding provider down, `search_thoughts` and the compat `search` answer with the thoughts that hold the query's identifiers and quoted spans, matched exactly, and say so — the endpoint, what happened there, and that `search_thoughts_keyword` finds any word — where they failed with the runtime's raw "Unable to connect" (SMD-2891). Migration 104 adds the query log's arm `literal` for such a search.

## FORK

A search the embedding provider does not answer for is answered by its exact-literal arm, said so and logged as arm literal (SMD-2891)

**What changed** (migration 104).
- **The search operation** (`server-portable/core/reads.ts`'s `runSearch`, which both tools share): when the query's embedding call fails as an outage (`providerDown` — refused, unresolved, timed out, 5xx, 429 — SMD-2888's rule), the same hybrid function is called with no vector. `match_thoughts` finds nothing on `NULL`, so the rows are 017's exact-literal arm alone: the needles `extract_search_needles` takes, its rarity rule and its facts, under `prefer_current` (059) and `min_trust` (075) alike. No SQL function changes; the store passes `NULL::vector`. Any other failure — a 4xx, a width mismatch — still fails the search, as it fails a capture.
- **The value** carries `vectorFailed: { reason, detail, base }`, present only then. `search_thoughts`' text leads with "Semantic search is unavailable: the embedding provider at <base> did not answer (<detail>), so the query was matched only by its identifiers and quoted spans, exactly — not by meaning", names `search_thoughts_keyword` and drops the "rest by similarity" notes; its typed result carries the marker word. With nothing found and no facts it says no thought contains an identifier or quoted span of the query, if it has one. The compat `search` keeps ChatGPT's results exactly and adds the field and a `note` naming the brain's keyword tool. REST answers the same value (the OpenAPI text says so); the MCP server words it as in-process.
- **The query log** records such a search as arm `literal` (104 widens 059's check; the column's comment says what it is). `db/brain-compare.ts` leaves literal rows out of a replay plan, as it does rows with no arm, and the replay gate counts them apart: a brain whose provider answers would run them with a vector.
- The two tools' descriptions say what an outage answers.

**Why.** Measured 2026-10-11 on a scratch brain with a stub provider whose socket was closed (SMD-2887): `search_thoughts` answered `isError` "Unable to connect. Is the computer able to access the url?", Bun's text, though `search_thoughts_keyword` answered in the same moment and the hybrid's literal arm needs no model. The caller was not told a working search existed. The compat `search` — ChatGPT's only search, which cannot reach `search_thoughts_keyword` — failed the same way. SMD-2890 (start degraded rather than refuse) waits on this.

**Held.**
- test-e2e-sql [23], index and client modes, against a real Postgres through the stubbed provider: refused at the socket, both tools answer the literal's thought with no similarity and the mark; `prefer_current` and `min_trust` take their functions with no vector; a plain-words query finds nothing and says why; a 503 is an outage, a 400 still fails; arm `literal` logged, and `hybrid` again once the provider answers.
- test-server [31] (the renders), test-mcp (the forwarded values said as in-process), test-brain-compare (the plan leaves literal out; the gate counts it, alone and beside a replay), test-upgrade [20av] (104 refused without 045; every row kept; `literal` taken after, other words still refused; a re-apply a no-op).

**Not taken.**
- **A coded refusal** (`EMBEDDING_PROVIDER_UNAVAILABLE`, the ticket's first option): the literal arm answers without a model, a search that names an identifier still finds its thought, and the compat `search` has no other tool to send its caller to.
- **The whole query as one substring** for a query with no literal: a sentence occurs verbatim in no thought (017's header), so it would answer nothing while looking like a keyword search; the reply names `search_thoughts_keyword` instead.
- **Logging `keyword` or `hybrid`**: either would replay as something that did not run. `literal` is one value for both functions; whether `prefer_current` was asked is not recorded for it, since no replay takes the row.
- **A provider that hangs**: a search still waits `OB1_LLM_TIMEOUT` before it falls back, as a capture does; a shorter query deadline is SMD-2890's degraded state to decide.

**Upstream status.** Fork-only.
