## Changelog

Every `db/` script reaches its database through one module, `db/connect.ts`: one `--url`/`DATABASE_URL` resolver, one client, one close-then-exit door, and one "may this database be reset?" rule — `tier.ts --refresh` now refuses a `--to` with an empty host or with `host=`/`hostaddr=`/`service=` in its query (pg_restore follows those), and `OB1_EVAL_ALLOW_REMOTE_DB` is no longer read (use `OB1_ALLOW_REMOTE_DB=1`) (SMD-2302, SMD-2134).

## FORK

One connection module for every db/ script — one loopback rule, and no exit that skips the close (SMD-2302 / 2134)

**What changed.** `db/connect.ts` is how a `db/` script reaches its database,
SMD-2134's second cut after the flag scanner.
- `databaseUrl`, the one resolver: `--url`, else `DATABASE_URL`, else exit 2
  with the one refusal. A blank `DATABASE_URL` is none, and a URL that does not
  parse is refused too. Neither refusal prints anything of the URL.
- `openSql`, the one client: one connection unless asked (the claim workers
  ask for one per worker and a spare). A URL that does not parse throws a fixed
  message, never the client's own error, whose dump printed the URL whole.
- `resetRefusal`/`mayReset`, the one answer to "may this database be reset?",
  which prints why not. A URL passes if its host is loopback by name
  (`localhost`, `127.0.0.1`, `[::1]`, `0.0.0.0`), its query has no
  `host=`/`hostaddr=`/`service=`, and neither `PGHOSTADDR` nor `PGSERVICE` is
  set. `OB1_ALLOW_REMOTE_DB=1`, exactly, lets anything through.
  `tier.ts --refresh` and the suites' `assertThrowawayDatabase`/`dropSchema`
  both ask it.
- `closeThenExit`: runs a body that returns an exit code, closes every pool,
  flushes stdout and stderr, then exits. A code that is not an exit status
  exits 1. A throw still closes, then reaches the script's handler.

Nine scripts' URL blocks, the benches' and `measure-1288.ts`'s clients and
`tier.ts`'s nine `new SQL(...)` go through the module. `hnsw-graph.ts`,
`graph-centrality.ts` and `tier.ts --replay/--diff` exit through the door.
`evals/eval-quant.ts` reads the loopback set instead of keeping a copy. The
migrator image (`db/Dockerfile`, `.dockerignore`, `release.yml`'s paths) and the
import runner's image (`deploy/orchestration/runner.Dockerfile`) copy
`connect.ts`, since `migrate.ts`, `ingest-records.ts` and `reembed.ts` import it.

Behaviour that moved:
- `tier.ts --refresh` refuses a `--to` its old rule let through:
  - an empty host (`postgres:///db`), which Bun's client resolves through
    `PGHOST`;
  - `localhost` with `?host=`, `?hostaddr=` or `?service=`, or with
    `PGHOSTADDR`/`PGSERVICE` set. Bun ignores those and dropped the schema on
    localhost, while `pg_restore`, which is libpq, restored into wherever they
    pointed.

  It admits `0.0.0.0`, which it did not know. Its refusal, and the suites', now
  says which of these failed.
- `OB1_EVAL_ALLOW_REMOTE_DB`, the eval-local name the suites' guard also
  honoured, is no longer read, and the suites' refusal says so when it is set.
  `deploy/tier.sh` passes `tier.ts` every `OB1_*` variable in the stack's env
  file except `OB1_ALLOW_REMOTE_DB`, which it sets itself, and never for a URL
  `--to`. So a second name read by the one rule would have been a way past it.
- `hnsw-graph.ts` without a URL prints the shared refusal, not its usage line.
  `tier.ts --replay` exits 0 explicitly after closing. `tier.ts`'s messages show
  an empty host as `$PGHOST`, not `localhost`.

**Why.** Nine copies of `cli.value("url") ?? process.env.DATABASE_URL` and its
refusal, and every script built its own client. Two rules answered "may this
be dropped":
- `tier.ts`'s `isLoopback` trusted an empty host and did not know `0.0.0.0`;
- `test-support.ts`'s refused the one, admitted the other, and read a second
  override name.

And two scripts called `process.exit` inside the `try` whose `finally` closed
the pool, so the close never ran: `hnsw-graph.ts` on every run, and
`tier.ts --replay/--diff` on a missing `query_log` and on `--diff`'s verdict.

**Held.** `db/test-connect.ts` (411 checks, no database, CI's replay-gate job
beside test-cli; every child `--no-env-file`):
- **The rule, as one truth table.** Twenty-two URLs, each checked with no
  override, with `OB1_ALLOW_REMOTE_DB=1`, and with the retired name, and each
  refusal's reason checked to hold no password. The libpq variables are checked
  set and empty; `PGHOST` alone is not refused; near-values of the override are
  refused. `deploy/tier.sh` strips the one name the rule reads.
- **The refusals, run.** The suites' refusal, and `tier.ts --refresh` refusing
  an empty host, a remote host and `?host=` before it connects. Both let the
  override through and not the retired name.
- **The resolver and the client.** Unset, empty and blank are refused, as is
  every other name a client might read. Unparseable URLs are refused, and
  `openSql` throws on them, with the password printed nowhere.
- **The door, run with pools that record their close.** The order; `255` stands
  and six non-codes exit 1; a close that rejects or throws strands nothing; a
  5 MB `process.stdout.write` reaches a slow reader whole.
- **The census**, with teeth shown on the shapes a refactor would write.
  - No non-suite `db/` file reads `DATABASE_URL` (six spellings), builds a
    client or imports Bun's ambient one.
  - No `db/` or `evals/` TypeScript spells a loopback host.
  - Every `--url` goes through `databaseUrl`.
  - No door body exits (aliases included) or closes, read past strings and
    comments.

Sixty mutants of the rule, the libpq redirects, the override, the resolver, the
door, the scripts on it, both guards, `tier.sh` and the census each fail it.
test-live's refresh check reads the refusal's words: it had passed on any
throw, an unreachable `example.com` included.

**Not taken.**
- A remote guard on the workers: on the dogfood stack they reach
  `postgres:5432` by service name (SMD-1869), and the guard is for a command
  that drops a schema.
- The workers' roughly fifteen explicit close-then-exit sites each: they
  close today, and a returned code is the importable engines' (SMD-2304).
- A door that traps `process.exit`, or a call graph for a helper that exits
  inside a body: a `catch` in the body could swallow the one, and the other is
  a linter's job.
- A timeout on a close that never settles: it hung before this change too.
- `OB1_ALLOW_REMOTE_DB` set from `evals/.env`, `.env` or `deploy/.env` on a
  host run (`loadEnv`; tier.sh's container turns the files off). A file
  deciding a per-command safety answer predates this change, and so does the
  shell profile that keeps it there, so it is its own ticket.
- `config.mjs`'s `isLocalHostname`: it answers another question, whether a
  model endpoint needs a credential.
