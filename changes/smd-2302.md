## Changelog

Every `db/` script reaches its database through one module, `db/connect.ts`: one `--url`/`DATABASE_URL` resolver, one client, one close-then-exit door, and one "may this database be reset?" rule — `tier.ts --refresh` now refuses a `--to` with an empty host, and `OB1_EVAL_ALLOW_REMOTE_DB` is no longer read (use `OB1_ALLOW_REMOTE_DB=1`) (SMD-2302, SMD-2134).

## FORK

One connection module for every db/ script — one loopback rule, and no exit that skips the close (SMD-2302 / 2134)

**What changed.** `db/connect.ts` is how a `db/` script reaches its database,
SMD-2134's second cut after the flag scanner. `databaseUrl` is the one
resolver — `--url`, else `DATABASE_URL`, else exit 2 with the one refusal,
which prints nothing of the URL; a blank `DATABASE_URL` is none. `openSql` is
the one client (one connection unless asked; the claim workers ask for one per
worker and a spare). `mayReset` is the one answer to "may this database be
reset?": a loopback host by name — `localhost`, `127.0.0.1`, `[::1]`,
`0.0.0.0` — or `OB1_ALLOW_REMOTE_DB=1`, exactly; `tier.ts --refresh` and the
suites' `assertThrowawayDatabase`/`dropSchema` both ask it. `closeThenExit`
runs a body that returns an exit code, closes every pool, then exits with the
code; a throw still closes, then reaches the script's handler. Nine scripts'
URL blocks, the benches' and `measure-1288.ts`'s clients and `tier.ts`'s nine
`new SQL(...)` go through the module. `hnsw-graph.ts`, `graph-centrality.ts` and
`tier.ts --replay/--diff` exit through the door. The migrator image
(`db/Dockerfile`, `.dockerignore`, `release.yml`'s paths) and the import
runner's image (`deploy/orchestration/runner.Dockerfile`) copy `connect.ts`,
since `migrate.ts`, `ingest-records.ts` and `reembed.ts` import it.

Behaviour that moved:
- `tier.ts --refresh` refuses a `--to` with an empty host (`postgres:///db`),
  which its own rule trusted: Bun's client resolves it through `PGHOST`, so it
  is whatever the shell says. It admits `0.0.0.0`, which it did not know.
- `OB1_EVAL_ALLOW_REMOTE_DB`, the eval-local name the suites' guard also
  honoured, is no longer read, and the suites' refusal says so when it is set.
  `deploy/tier.sh` hands `tier.ts` every `OB1_*` variable in the stack's env file
  except `OB1_ALLOW_REMOTE_DB`, which it sets itself, and never for a `--to`
  given as a URL. So a second name read by the one rule would have been a way
  past the wrapper.
- `hnsw-graph.ts` without a URL prints the shared refusal, not its usage line.
- `tier.ts --replay` exits 0 explicitly after closing, where before it returned.

**Why.** Nine copies of `cli.value("url") ?? process.env.DATABASE_URL` and its
refusal, and every script built its own client. Two rules answered "may this
be dropped": `tier.ts`'s `isLoopback` trusted an empty host and did not know
`0.0.0.0`; `test-support.ts`'s refused the one, admitted the other, and read a
second override name. And two scripts called `process.exit` inside the `try`
whose `finally` closed the pool — `hnsw-graph.ts` on every run, `tier.ts`'s
`--replay/--diff` on a missing `query_log` and on `--diff`'s verdict — so the
close never ran.

**Held.** `db/test-connect.ts` (241 checks, no database, CI's replay-gate job
beside test-cli):
- **The rule, as one truth table.** Fifteen URLs: the four loopback names,
  capitals, an empty host, a socket URL, an unparseable string, a service
  name, RFC1918, the container alias, `127.0.0.2`, a `localhost.` prefix and a
  remote host. Each row is checked without an override, with
  `OB1_ALLOW_REMOTE_DB=1`, and with the retired name. Seven near-values of the
  override are refused. `deploy/tier.sh` strips the one name the rule reads.
- **The resolver.** `--url` over the environment; unset, empty and blank
  refused with the one line; a set URL printed nowhere. `openSql`'s pool size
  is checked. The suites' refusal is run with the retired name set and with the
  override.
- **The door, run with pools that record their close.** A returned code exits
  after both closes. So does a single pool. A throw closes, then reaches the
  handler. A pool whose close fails does not strand the other.
- **The census.**
  - No `db/` file outside `connect.ts` and the suites reads `DATABASE_URL`,
    builds a client or copies the refusal.
  - No `db/` TypeScript spells a loopback host of its own.
  - Every script that takes `--url` resolves it through `databaseUrl` and reads
    it nowhere else.
  - No body on the door calls `process.exit` or closes a pool itself.

Thirty-four mutants — each loopback row, the override's exactness, the retired
name honoured, `||`→`&&`, the resolver's order and blank rule, the pool size,
the door exiting inside its `try`, closing serially, closing one, exiting 0 or
swallowing a throw, an exit planted in each script's door body, the guard
removed from `tier.ts` and `test-support.ts`, `tier.sh` passing the override
on, and a script reading `DATABASE_URL`, building a client or copying the
refusal — each fail it. test-live's refresh check now reads the refusal's words
(it passed on any throw, an unreachable `example.com` included) and adds the
empty host.

**Not taken.**
- A remote guard on the workers: on the dogfood stack they reach
  `postgres:5432` by service name (SMD-1869), and the guard is for a command
  that drops a schema.
- Moving the workers' roughly fifteen explicit close-then-exit sites each onto
  the door: they close before each exit today, and folding them into a
  returned code is what the importable engines (SMD-2304) do.
- A door that traps `process.exit` inside its body: a `catch` in the body could
  swallow it.
- Moving the suites' own clients: `test-support.ts`'s `requireDatabaseUrl` and
  throwaway helpers are the suites'.
- `config.mjs`'s `isLocalHostname`: it answers another question, whether a
  model endpoint needs a credential.
