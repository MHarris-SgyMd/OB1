## Changelog

`deploy/canary.sh up` keeps a canary's database and brings it level in place, its own rows kept, where it refreshed it from stable before; `up --refresh` replaces it with stable's, and a canary with no database to keep (no volume, or a running one holding no relations) is stood up from stable by a plain `up` or `--refresh`, said (SMD-3155).
A database stamped other than `canary` in `ob1_config`, as a refresh that died before its last step leaves stable's copy, is refused naming `--refresh`; `--no-refresh` is still accepted, keeping as a plain `up` does and refused where there is nothing to keep.
**Upgrading:** a command that ran `canary.sh up` to refresh the canary from stable now upgrades it in place: add `--refresh` to it.

## FORK

`canary.sh up` upgrades a canary in place, and a refresh from stable takes `--refresh` (SMD-3155)

**What changed.**
- `deploy/canary.sh`:
  - `REFRESH` is unset until the canary's database is looked at, before anything changes. A plain `up` keeps a database that is there. It refreshes from stable where there is no `${CANARY}_pgdata` volume, or where the canary's Postgres is running and its database holds no relations. Both choices are said.
  - `--refresh` refreshes. It and `--no-refresh` together are refused, and either beside `down` or `names`.
  - A kept database is refused where it is stamped other than `canary`, naming `up --refresh`. The check is made before anything changes where the canary's Postgres is running (exit 2), and after the writers stop where it was not (exit 1, saying what is stopped).
  - `--no-refresh` keeps SMD-3154's meaning: keep, or refuse on a canary with no database to keep. Its no-volume refusal now says a plain `up` stands one up from stable. The empty-database refusal names `up --refresh`.
  - A failed refresh tells the operator to re-run `up --refresh`; once a refresh has finished, a later failure's advice is a plain `up`. Every connector message says `up --connect`, which keeps.
  - The volume list must answer: a failed one is refused rather than read as "no volume". A running database holding relations is always kept by default.
  - The header's step 3 and the flag list say all of this.
- `deploy/README.md`:
  - The canary section's examples and paragraph: a plain `up` keeps, `up --refresh` replaces, and the stamp guard.
  - The step list's step 2, and board-sync's turning on and off, which named `up --no-refresh`.
  - The note that SMD-3155 was the guard is gone.
- `FORK.md`'s soak rule names a plain `up`, which keeps since SMD-3155.
- CI's canary step:
  - The first `up` stands up the pre-SMD-2583 canary's empty database from stable, said.
  - The provider-mismatch run is `up --refresh`, which brings stable's new thought.
  - The port-move run is a plain `up`. A row only the canary holds survives it, no tier half runs, and board-sync stops "for the migration".
  - A database stamped `stable` is refused by a plain `up` and by `up --no-refresh`, the canary still answering. With its Postgres stopped when the run begins, the refusal comes after the writers stop, exit 1.
  - The refusals step's plain `up` with no canary volume says it is stood up from stable.
  - `--refresh --no-refresh` and `down --refresh` are refused.

**Why.** Since SMD-3314 every canary holds rows of its own: captures, edits and keys through its own key, and its passes' proposals. A plain `up`, the README's first example, refreshed it from stable with no prompt, so one forgotten `--no-refresh` erased them. The maintainer decided on 2026-10-26 to invert the default rather than mark a canary and refuse.

**Version contract.** `canary.sh` is maintainer tooling, outside the contract (FORK.md, "Versioning"), so the changed default is a minor, with the **Upgrading:** line above.

**Held.** CI's canary step fails:
- if a plain `up` refreshes a canary that has a database: the port-move run's "for the migration", "kept" line and canary-only row;
- if a stale stamp is migrated in place, whether its Postgres was running or stopped;
- if `--refresh` stops refreshing, or a canary with no volume is not stood up.

**Not taken.**
- `--no-refresh` as a pure no-op. The ticket allows one. Keeping its refusal where there is nothing to keep loses no caller (CI passes it on a canary with a database, and the soak rule names a plain `up` now) and keeps an explicit "keep" from turning into a refresh.
- A mark kept on the canary. The ticket's original plan; the inverted default needs none.
