## Changelog

The opt-in priority inference (`OB1_INFER_PRIORITY`, off by default) reads less of what isn't the text's own. Its prompt (v2) says whose work a level and a deadline must be about, and names what is neither: a label quoted beside another ticket, where an item ranks among others, a finding's severity, an expiry, the earliest something can happen. Two code guards drop what the model still reads that way, each only in a shape that cites or a floor's own words, never by nearness: a level quoted as another ticket's label (beside its key, on its board line, in a table row with its key, or ranking it among others), and a due phrase that is the earliest something can happen ("can't happen before 11-03"). The writer's own level and deadline stand in a personal note ("Urgent: the landlord wants an answer by Friday", "Rent payment (Urgent)", "not later than 15 November"), and so does a ticket's own "Priority:" field. Nothing ranks on these statements yet: `count_inferred` stays off until a fresh measurement clears its bar (SMD-4226).

## Record

The priority inference's prompt v2 and its guards against cited labels and floors, checked against SMD-3670's frozen labels: PR 1 (SMD-4226)

SMD-3670 PR 2 measured prompt v1 on stable's captures. The operator agreed with 0.188 of its level reads and 0.500 of its due days. Most of the rest were a label quoted beside another ticket, a ranking, an expiry or a floor. The maintainer decided the plan on 2026-11-12:
- **Two PRs:** this one fixes the inference and checks it against the frozen labels; PR 2 is a fresh registered measurement, started only if this check holds.
- **The fix:** the prompt plus a code guard, since the local 7B follows a prompt loosely.
- **PR 2's population:** stable's captures only, with the frame fixed to leave the ingester's rows out.
- **This PR's gate:** the ticket's Verify. On the frozen 120, v2 makes no level read on a session summary where the operator read none, or names each one it still makes. Its due reads exclude expiries and floors.

**What changed.**
- **`server-portable/priority-infer.ts`:**
  - `INFER_PROMPT` v2. A note's level is how much its writer says their own work matters. A note that is itself a ticket or task carries its own priority field. It names what is no level and what is no deadline.
  - `citedIn` drops a level phrase only when every place of it has a shape that cites another item:
    - a ticket key earlier in its clause, its words ending in "(", "," or a dash just before the level;
    - a key beside the level inside the phrase;
    - a table row that holds a key;
    - a board status before or after the level ("Backlog, Low", "High, Todo"), or a board field's name before it ("Owner, Urgent priority");
    - a level directly before a key;
    - a rank among items by level or priority ("the only High-priority open child", "the highest-priority open issue").

    A ticket's own export keeps its "Priority:" field, since no citing shape ends at "Priority:". Common key-shaped tokens that name no ticket ("COVID-19", "ISO-8601", "UTF-8", "GPT-4", a flight number) are passed over. A line break or a sentence's end bounds a clause. Places are found on a copy lower-cased character by character, so a text holding "İ" is read like any other.
  - `flooredIn` drops a due phrase only in a floor's own construction: a negation, up to two words, then "before", "until" or "till" (before the phrase, inside it, or split across them); "no sooner than" or "no earlier than"; "at the earliest", "or later" or "at the soonest". A deadline with a negation elsewhere stands ("not later than", "can't wait past", "do not miss").
- **`evals/eval-inferred-priority.ts`:**
  - `--run --only-fixture` runs the shipped prompt over SMD-3670's frozen texts, and `--dev` scores that run against the frozen labels. It is labelled a development check, not a verdict: the 120 were drawn from v1's calls. It counts the items where the run reads a half the gold doesn't, each half apart.
  - Each run line records a hash of `priority-infer.ts` (the prompt and its guards), and a run mixing two drafts is refused.
  - SMD-3670's report still reads its recorded verdict, and now says it gates nothing, since the shipped prompt is v2.

It took five rounds over these same 120. Three shaped the prompt and the first guards. Review pass 1 then found those guards dropping the writer's own level and deadline in ordinary personal notes ("So, urgent: …", "Rent payment (Urgent)", "COVID-19 booster is urgent", "not later than 15 November"), so they were rewritten to cite only in a shape that cites (5 level strays rose to 9). A fifth round restored three board-line shapes (6). The guards were shaped by reading these strays, so the numbers flatter v2. PR 2's fresh draw is the test. The eight strays left, named as the Verify allows:
- **Levels:**
  - "High", one place of which no shape covers;
  - "Urgent and the 11-03 date stand", a board status a sentence after its key;
  - "Urgent, due 10-17.", a board line a sentence after its key, left uncited on purpose since "Urgent, due Friday: rent" is a personal note's own;
  - "Medium priority", given as a pick's reason;
  - "This one is worth doing soon";
  - "highest value open issue", a title restating the user's question.
- **Due:**
  - "around this time tomorrow (11-07)", the earliest a tag can go on, with no floor word beside it;
  - "a week of main's runs", a window to watch.

**Review pass 1** found the first guards citing by nearness, and so dropping the writer's own level or deadline in ordinary personal notes. It found six such shapes:
- a capitalised word before a comma;
- a negation anywhere before a time;
- key-shaped tokens such as "COVID-19";
- a key within 40 characters across a sentence break, which also cost short ticket exports their own field;
- a rank word near any item noun;
- parentheses and table cells with no key.

It also found the dev check counting halves as calls, the guard switched off by "İ", and dev runs able to mix drafts. All nine were fixed; each case it gave is a row (caught: cold-read).
