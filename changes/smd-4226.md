## Changelog

The opt-in priority inference (`OB1_INFER_PRIORITY`, off by default) reads less of what isn't the text's own. Its prompt (v2) says whose work a level and a deadline must be about, and names what is neither: a label quoted beside another ticket, where an item ranks among others, a finding's severity, an expiry, the earliest something can happen. Two code guards drop what the model still reads that way. A level quoted as another ticket's label (a key's "(Medium)" tag, a board line, a table row with its key, a rank among tickets) is dropped only when an agent-kind key wrote the capture, such as a session summary: a person's capture keeps every level the prompt reads, since syntax can't tell another ticket's label from their own "fix the login ticket (urgent)". A due phrase that is the earliest something can happen ("can't happen before 11-03", "doesn't open until Monday", "starting Monday") is dropped for everyone, and a deadline stays one ("not later than 15 November", "if it's not paid before the 15th"). Nothing ranks on these statements yet: `count_inferred` stays off until a fresh measurement clears its bar (SMD-4226).

## Record

The priority inference's prompt v2 and its guards against cited labels and floors, checked against SMD-3670's frozen labels: PR 1 (SMD-4226)

SMD-3670 PR 2 measured prompt v1 on stable's captures. The operator agreed with 0.188 of its level reads and 0.500 of its due days. Most of the rest were a label quoted beside another ticket, a ranking, an expiry or a floor. The maintainer decided the plan on 2026-11-12:
- **Two PRs:** this one fixes the inference and checks it against the frozen labels; PR 2 is a fresh registered measurement, started only if this check holds.
- **The fix:** the prompt plus a code guard, since the local 7B follows a prompt loosely.
- **PR 2's population:** stable's captures only, with the frame fixed to leave the ingester's rows out.
- **This PR's gate:** the ticket's Verify. On the frozen 120, v2 makes no level read on a session summary where the operator read none, or names each one it still makes. Its due reads exclude expiries and floors.

**What changed.**
- **`server-portable/priority-infer.ts`:**
  - `INFER_PROMPT` v2. A note's level is how much its writer says their own work matters. A note that is itself a ticket or task carries its own priority field. It names what is no level and what is no deadline.
  - `citedIn` finds a level phrase every place of which has a shape that cites another item:
    - a ticket key earlier in its clause, its words ending in "(", "[", ",", ":", "·" or a dash just before the level;
    - a key beside the level inside the phrase (the key case-sensitive, so "mid-2025 high" is no key);
    - a table row that holds a key;
    - on a line that holds a key, a board status (capitalised) before or after the level ("Backlog, Low", "High, Todo");
    - a board field's name before it ("Owner, Urgent priority");
    - a level directly before a key;
    - a rank among items by level or priority ("the only High-priority open child", "the highest-priority open issue").

    A ticket's own "Priority:" field is never cited. Common key-shaped tokens that name no ticket are passed over: "COVID-19", "ISO-8601", "UTF-8", "GPT-4", a quarter ("Q4-2026") and a few airline prefixes. A line break (U+2028 too) or a sentence's end bounds a clause. Places are found on a copy lower-cased character by character, so a text holding "İ" is read like any other, and a phrase's curly quotes are straightened as the text's are. Each place reads a bounded stretch around it: 380 KB with 20,000 keys takes 41 ms, where review pass 2 measured 12.8 s.
  - `readAnswer` marks such a level `cited`, and `forWriter(reading, kind)` drops it for an agent-kind writer alone (the maintainer's choice after review pass 2). The capture's `stateInferred` reads the row's `actor_kind` only when a level is marked; a stamp it can't read counts as an agent's.
  - `flooredIn` drops a due phrase, for every writer, only in a floor's own construction:
    - a negation (the contractions too: "doesn't", "isn't", "don't") then, within two words, "before", "until" or "till";
    - "no sooner than" or "no earlier than";
    - "starting", "from" or "(only) after" just before it;
    - "at the earliest", "earliest", "or later", "at the soonest" or "onwards" after it.

    A negation reads as a deadline when the words between say so ("do not forget before Friday", "not urgent but before Friday") or a condition comes first ("if it's not paid before the 15th"). A deadline with a negation elsewhere stands ("not later than", "can't wait past", "do not miss").
- **`evals/eval-inferred-priority.ts`:**
  - `--run --only-fixture` runs the shipped prompt over SMD-3670's frozen texts, and `--dev` scores that run against the frozen labels. It is labelled a development check, not a verdict: the 120 were drawn from v1's calls. It counts the items where the run reads a half the gold doesn't, each half apart.
  - Each run line records a hash of `priority-infer.ts` (the prompt and its guards), and a run mixing two drafts is refused.
  - The run applies the agent-kind rule to every line, since the population is actor_kind agent alone.
  - SMD-3670's report still reads its recorded verdict, and now says it gates nothing, since the shipped prompt is v2.
