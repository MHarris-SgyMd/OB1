## Changelog

`recipes/brain-backup/backup-brain.mjs` and `recipes/lint-sweep/lint-sweep.js` read the brain through `compat/supabase-sql` under `bun` — `SUPABASE_URL` a `postgres://` string, the key ignored — where both paged a PostgREST the stack does not run; check 24 loses their two entries and `db/test-live.ts` [26] drives both against a real Postgres, `weekly-digest`'s entry moves to its rescope ticket as a sink, and `brain-backup`'s README names `pg_dump` as the whole-brain backup (SMD-2144).

## FORK

The two read-only recipe scripts move onto the SQL shim — brain-backup and lint-sweep read a Postgres instead of a PostgREST the fork does not run, and the live suite drives both (SMD-2144)

**What changed.** SMD-2126 sent every maintenance script onto
`compat/supabase-sql`; these two are the first to land, the class's simplest —
read-only, one file each.

1. `recipes/brain-backup/backup-brain.mjs`: `fetchPage` is
   `client.from(table).select("*", { count: "exact" }).order(…).range(from, to)`
   — the same 1,000-row pages, the count beside them — where it was a `fetch` of
   `/<table>` with `Range` and `Prefer: count=exact`. A table that is not there
   is the shim's `42P01` where PostgREST answered `PGRST205`; any other error is
   surfaced, as before. `SUPABASE_URL` is a `postgres://` string;
   `SUPABASE_SERVICE_ROLE_KEY` is read and ignored, no longer required. The
   per-page timeout stays as a race (`FETCH_TIMEOUT_MS`). Two things the port
   did not have to change but did: a table that shows `ERROR` in the summary
   exits 1 (it exited 0, and a scheduler could not tell), and the pool is closed
   at the end so the process ends on its own with the code set — after a
   timed-out page, whose query is abandoned rather than cancelled, the run
   gives the pool a few seconds and ends itself.
2. `recipes/lint-sweep/lint-sweep.js`: the REST helper becomes the shim's client
   with the two verbs the tiers use — the rows of a query, and a counted head
   query for the two exact counts — and every read is a builder. Two reads
   changed with the transport: the "most recent" samples order by `created_at`
   (ids are uuids here, so `id desc` orders nothing), and Tier 2 reads `edges`
   by the columns `schemas/entity-extraction` gives it (`from_entity_id`,
   `to_entity_id`; the script read `src_`/`dst_`, which no schema in the tree
   has). A refused read aborts the run: only an undefined table (42P01) reads
   as an optional schema's absence, only an undefined column (42703) as the
   fingerprint's — a role without SELECT on a graph table had been reported
   as the table's absence, exit 0. The key is accepted under either name and
   ignored, without the deprecation line; `--help` returns rather than exiting;
   the client is closed on both paths.
3. Both READMEs: `bun`, a checkout (the import is relative — the "copy the
   recipe out" step is gone), the connection string, the shim's refusals in
   Troubleshooting; `lint-sweep`'s names `schemas/enhanced-thoughts` as Tier 1's
   `importance` and `source_type` and Tier 3's `type` (with those two), and 016's
   `thought_entities` as what Tier 2 reads on a fork brain; `brain-backup`'s
   says `pg_dump` of the stack's database is the whole-brain backup
   (`deploy/README.md`'s line and data-migration note), the export the portable
   form, without the fork's own tables. `metadata.json` ×2, `package.json`,
   three words in `views.sql`.
4. `recipes/weekly-digest/README.md`'s fork note says why the third read-only
   script stays: a sink — thought text to Telegram — which a shim port would
   read from below the egress gate (the orchestration ADR's decision 9, written
   for templates, read to cover it); SMD-2239 carries it. Its check 24 entry says the same, under that ticket.
5. `scripts/check-fork-consistency.ts`: `POSTGREST_EXCEPTIONS` loses the two
   entries — twenty-four files with a call site — and its three comments say
   so. `docs/vendored-disposition.md`: the two rows read "on the shim
   (SMD-2144)", the digest's row its ticket, the counts 26 in 17.
6. `scripts/migrate-to-sql-shim.ts` leaves a hand port alone: a file on the
   shim without the codemod's banner has no supabase-js import to go back to,
   so `--revert`, with or without a path, names it and skips it, `--apply` of
   it says what it is, and the triage report marks it. Without
   that, CI's round-trip step (`--revert`, `--apply --all`, a clean diff)
   swapped both files' import for one they never had and stamped the banner
   in (review pass 1, run-it). `compat/supabase-sql/README.md` says so.
7. `db/test-live.ts` [26]: both scripts driven as deployed — `bun <file>` in a
   directory of their own, `SUPABASE_URL` the one variable beyond `PATH` and
   `HOME` — against the live
   database carrying `enhanced-thoughts`, `entity-extraction` and the lint
   views, 1,050 planted thoughts (a page and a partial second), a three-entity graph with
   one edge, one linked high-importance row, and a LOGIN role that may read
   `thoughts` alone. Nine assertions; the sweep's five are skipped, by name,
   on a machine that keeps a `.env`/`.env.local` in `recipes/lint-sweep/`.
8. This record. No migration; `patch`.

**Why.** Neither script could reach a brain on this fork: both spoke to
`${SUPABASE_URL}/rest/v1/…` with a service-role key, and the stack runs no
PostgREST. The class decision (SMD-2126) says a maintenance script moves onto
the shim; a cold read of the port against the schemas then found what a
transport port alone would have carried over — a column pair no schema has, and
a recency order that means nothing over uuids — and the run against a real
database held the counts to the table.

**Held.** [26]'s nine assertions hold every number the scripts print to the
planted table's SQL: `1050 total thoughts, 699 orphans-by-tag, 0 dup groups,
1050 missing-fingerprint`; `209 high-imp isolated, 1 isolated entities`; the
report's exact count, 630 low-signal rows, one over-tagged row, the
`created_at desc` scope line; the export's `thoughts` file holding exactly the
table's 1,050 ids once each and in id order, with ISO timestamps (held to the
`Z`-millisecond shape) and object metadata, the exact
count on the progress line (`1000/1050`, the one trace of `count: "exact"`),
`entities` 3, `edges` 1, `thought_entities` 1, `ingestion_jobs` and
`ingestion_items` "skipped (table not present)", `6/6`; the legacy URL name with its deprecation
line; no URL and a Supabase URL refused, exit 1, the messages intact; a role
with SELECT on `thoughts` alone refused by Tier 2 with 42501, no report. Check 24
holds the two files at zero `rest/v1` lines. Three mutants, each run through
the same drive: the page window without its offset writes 2,000 rows (the first
page twice), which the ids-once-each assertion refuses; the `42P01` branch
removed turns the two absent tables into `ERROR`, `4/6`, exit 1; the old edge
columns put back abort Tier 2 with `42703 column "src_entity_id" does not
exist`.

**Measured after.** On the planted table the sweep's Tier 1 and 2 numbers are
the SQL's to the row; the export pages 1,000 then 50 and writes 472.7 KB of
thoughts; `bigint` and `numeric` columns come out as strings — the driver's
rendering, which the shim passes through; it reshapes dates and arrays alone —
and timestamps as ISO strings, `Z` and milliseconds where PostgREST spelled
`+00:00` and microseconds (the README's Tips say so).
