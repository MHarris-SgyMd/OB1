## Changelog

`db/rebuild.ts`, the operator's door to `rebuild_derived`, is now an importable engine: `run(opts)` runs it in-process and `sweepOrphans(sql, opts)` runs its orphan sweep on a caller's client. The CLI is unchanged (SMD-2679, the first of its PRs).

## FORK

rebuild.ts becomes an engine: `run()` and `sweepOrphans()` in-process, the CLI unchanged (SMD-2679)

**What changed.**
- **`db/rebuild.ts`** now has SMD-2304's engine shape:
  - **`run({ url, sql, input, reason, fingerprints, limit, gone, force, orphans, status, dryRun, writer })`** returns the code the CLI exits with.
    - Its usage refusals come first, in the CLI's words and order, before any connection.
    - Its lines go to the `Writer`.
    - A caller's client is used and never closed.
  - **`sweepOrphans(sql, { limit, dryRun, writer, onFound })`** is `--orphans` alone on the caller's client. The sleep scheduler's re-derive pass will call it (a later PR of this ticket).
    - It returns the thoughts it read, those it touched, the rows it deleted and the calls refused as a value.
    - It also returns `windowed` when the lineage table holds more than the 10,001 rows its read takes (in no order), so finding no orphans is then not a clean table. The count and the orphans are read in one statement, so they agree. The CLI's words are main's.
    - A `limit` that is not an integer is refused rather than rounded by Postgres.
  - **`hasRebuild(sql)`** says whether 063 is there.
  - **A dry run's call is a transaction of its own** (`sql.begin`, rolled back). A bare `BEGIN`/`ROLLBACK` held only on the CLI's one-connection client; through a pool, the call could land on another connection. A transaction's handle cannot hold that transaction (Bun refuses a begin inside one), so a dry run on one is refused before a query, by `run()` (exit 2) and by `sweepOrphans`.
  - The CLI is a thin `if (import.meta.main)` block over `run()`: the scanner, the URL, `--limit`'s digits, then `run()` through `closeThenExit`.
- **`db/test-engines.ts`:**
  - `rebuild.ts` joins the census: it imports with no side effect, and its code has no exit, no listener, no argv read and no console call.
  - The census's control runs `--status` for it, since its dry run needs a mode.

**Why.** SMD-1794's order puts the re-derive pass first in a sleep. `rebuild.ts` ran at top level with `process.exit` inline, so nothing could drive it in-process; the claim workers had the same shape before SMD-2304.

**Held.**
- **test-engines:**
  - `rebuild.ts` in the census;
  - **26 refusals**, each compared with the spawned CLI on both streams, exit 2, before connecting and without the password, and each held to main's own first line. The CLI goes through `run()` now, so the two agreeing alone pinned nothing: a refusal reworded, or two swapped, changed both sides. The cases:
    - no URL, an unparseable URL, no mode, two modes, `--input` with `--orphans`, a non-UUID `--input`;
    - `--gone`/`--force`/`--fingerprints` without `--input`, `--fingerprints` without `--gone` (and `--fingerprints ","`, refused as main refused it);
    - `--reason` on the sweep, `--limit` outside `--orphans`, `--dry-run` with `--status`, a blank `--reason`;
    - eleven that break two rules at once, where main's order decides: six neighbours (run-it, review pass 1) and five pairs further apart (cold read, review pass 2).
  - A caller's client is queried and never closed, and a bad URL beside it is refused.
  - A null url is read as absent; so are a null input, reason, fingerprint list or limit, beside a client, where `--status` runs on.
  - A dry run on a transaction's handle is refused by `run()` and by `sweepOrphans`, and so is a fractional or NaN `limit`, all before a query.
- **test-live [31]:**
  - `--orphans --dry-run` reports the delete "(rolled back)" and keeps the row;
  - `sweepOrphans`' dry run on a pool of three keeps it too, the window not reached.

  Until then nothing tested a sweep's dry run: a mutant that made it delete for real passed every suite (cold read, review pass 1).
- **`windowed`'s edge, measured once on a scratch brain rather than in a suite**: false at 10,000 and 10,001 rows, true at 10,002, and the orphan found through the statement's array. The scheduler's PR, which reads it, tests what it does with it.
- **Main against the branch, run live** (run-it, review pass 1): 38 steps over every mode and 52 refusals gave the same stdout, stderr and exit codes on fresh fixtures. A dry run that commits fails three [31] assertions.
- **Unchanged, as the move promised:** test-cli's rebuild cases and test-preflight's two sweeps, which spawn the CLI, and every [31] assertion that was there before.
- **Tidied while the file was open** (no change in behaviour): the census and the sweep read orphans through one predicate, where each spelled out the four kinds, and the census bounds its read by the same `LINEAGE_WINDOW` constant.
