## Changelog

The SvelteKit dashboard (`dashboards/open-brain-dashboard`) signs in with one of the server's own access keys — sealed into an httpOnly cookie, forwarded as `x-brain-key` on every call — in place of a Supabase email/password sign-in, so no Supabase project, user table or anon key is needed and a read key gets a read-only dashboard; the two Next dashboards' examples point at the Bun-served `open-brain-rest` gateway; CI builds all three dashboards and drives the SvelteKit one against the compose stack (SMD-1801).

**Why.** The ticket's premise, corrected on reading the code: the dashboard
never read the brain over PostgREST. Its reads already went through its own
server-side proxy to the MCP server, with a key from the dashboard's env;
supabase-js served the sign-in alone — a Supabase project kept to check an
email and password before a proxy used a key the visitor never saw. The
brain's keys are named, scoped and revocable (change 64), so the key is the
credential: each visitor's key is what the proxy forwards, a read key sees a
read-only dashboard, and revoking the key in `MCP_ACCESS_KEYS` ends the
session — the shape the two Next dashboards already had (iron-session over a
REST key). The MCP server stays the data path rather than the ticket's
"one of the REST integrations": it is the reference deploy's one published
port, on the fork's default model and width, where `open-brain-rest` embeds
through OpenRouter at 1536 and needs `schemas/enhanced-thoughts`.

**Held.** `smoke.ts`, thirty-one assertions against a live server: signed
out, `/` redirects and `/api/mcp` is 401; a garbage cookie, plain base64url
JSON naming the write key, a token sealed under another secret and one
sealed under this secret two days ago are each no session (401; the garbage
one dropped by a Set-Cookie a plain-HTTP browser accepts), while a token
sealed under this secret now is; a wrong key is 401 at `/signin` with no
cookie and the page says the server refused it; the write key is 303 to `/`
with an HttpOnly, SameSite=Lax, day-long, not-Secure-on-HTTP cookie, `/`
names its scope and shows the capture button, `thought_stats` — the JSON the
first page loads — begins `Total thoughts:`, `list_thoughts` and
`search_thoughts_keyword` answer, a nameless call is 400, an unknown tool is
422 with the server's words, sign-out clears the cookie with a Set-Cookie
the same browser accepts and `/api/mcp` is 401 again; the read key signs in
to a page without the button, is refused `capture_thought` with 403 by the
proxy, and `update_thought` — which the proxy does not gate — is refused by
the server as a tool that key has not, proof the key forwarded is the
visitor's. Six drop-the-mechanism mutants (plain JSON taken, no expiry,
Secure on the set, a garbage cookie taken, Secure on the delete, an env key
forwarded) each fail one assertion by name. Green here against
`server-portable` on a throwaway Postgres with a write and a read key, and
in CI against the compose stack. The three builds in CI; svelte-check 0
errors. Check 22 holds the tree at no supabase-js import; `bun
scripts/migrate-to-sql-shim.ts` reports 0 of 28 with nothing left for a
human.

**Measured after.** Each dashboard builds in about five seconds under Bun
1.4.0 (`next build` ×2, `vite build`); installs in two to seven.
