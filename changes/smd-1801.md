## Changelog

The SvelteKit dashboard (`dashboards/open-brain-dashboard`) signs in with one of the server's own access keys — sealed into an httpOnly cookie, forwarded as `x-brain-key` on every call — in place of a Supabase email/password sign-in, so no Supabase project, user table or anon key is needed and a read key gets a read-only dashboard; the two Next dashboards' examples point at the Bun-served `open-brain-rest` gateway; CI builds all three dashboards and drives the SvelteKit one against the compose stack (SMD-1801).

## FORK

The dashboards off Supabase — the SvelteKit dashboard's sign-in is one of the server's access keys, the Next dashboards' examples name the Bun-served gateway, and CI builds the three and drives the first against the stack (SMD-1801)

**What changed.** Three commits, each green on its own (review passes follow).

1. `dashboards/open-brain-dashboard`: `@supabase/ssr` and `@supabase/supabase-js`
   removed. `/signin` takes an access key, asks the server `tools/list` under
   it, and seals `{ key, canCapture }` into one httpOnly cookie —
   `src/lib/server/session.ts`, AES-GCM under `SESSION_SECRET` (32+
   characters; refused shorter), WebCrypto and `btoa` alone so the file runs
   on Node, Bun, Vercel and an edge worker. `hooks.server.ts` unseals it into
   `locals.session`; `api/mcp/+server.ts` forwards each tool call with the
   visitor's key as `x-brain-key` (`src/lib/server/mcp.ts`; the proxy sent
   `?key=` before) and refuses `capture_thought` with 403 for a key whose
   list had no such tool, before the server is asked; the page hides the
   capture button for that key. Sign-out is a POST. Env: `MCP_URL` and
   `SESSION_SECRET`; `MCP_KEY`, `PUBLIC_MCP_URL`, `PUBLIC_MCP_KEY`,
   `PUBLIC_SUPABASE_URL` and `PUBLIC_SUPABASE_ANON_KEY` gone. `smoke.ts`
   drives the built dashboard as a browser would. `bun.lock` committed;
   README, `.env.example`, `metadata.json` rewritten; the root README's row,
   `dashboards/README.md`, two FORK.md known-issue bullets; check 22's one
   counted exception removed.
2. `dashboards/open-brain-dashboard-next` and `-pro`: `.env.example` and
   README name `http://127.0.0.1:8787` with the gateway's run line in place
   of `*.supabase.co/functions/v1/…`; -next's Step 1 `cd`s into its own
   directory; `bun.lock` committed for both. The deploy-stack job gains
   `setup-bun`, a read key in `deploy/.env` beside the write key, "The three
   dashboards build" (`bun install --frozen-lockfile`, `bun run build`,
   svelte-check) and "The SvelteKit dashboard, driven against the stack"

3. SMD-1668 on the way (its own fragment): three vendored MCP servers'
   `Access-Control-Allow-Headers` name `mcp-protocol-version` and

**Why.** The ticket's premise, corrected on reading the code: the dashboard
never read the brain over PostgREST. Its reads already went through its own
server-side proxy to the MCP server, with a key from the dashboard's env;
supabase-js served the sign-in alone — a Supabase project kept to check an
email and password before a proxy used a key the visitor never saw. The
brain's keys are named, scoped and revocable (change 64), so the key is the
credential: each visitor's key is what the proxy forwards, a read key sees a
read-only dashboard, and revoking the key in `MCP_ACCESS_KEYS` ends the
session — the shape the two Next dashboards already had (iron-session over a
REST key). The MCP server stays the data path rather than the ticket's
"one of the REST integrations": it is the reference deploy's one published
port, on the fork's default model and width, where `open-brain-rest` embeds
through OpenRouter at 1536 and needs `schemas/enhanced-thoughts`.

**Held.** `smoke.ts`, twenty-one assertions against a live server: signed
out, `/` redirects and `/api/mcp` is 401; a wrong key is 401 at `/signin`
with no cookie and the page says the server refused it; the write key is 303
to `/` with a cookie, `/` names its scope and shows the capture button,
`thought_stats` — the JSON the first page loads — begins `Total thoughts:`,
`list_thoughts` and `search_thoughts_keyword` answer, a nameless call is
400, sign-out clears the cookie and `/api/mcp` is 401 again; the read key
signs in to a page without the button and is refused `capture_thought` with
403 by the proxy. Green here against `server-portable` on a throwaway
Postgres with a write and a read key, and in CI against the compose stack.
The three builds in CI; svelte-check 0 errors. Check 22 holds the tree at no
supabase-js import; `bun scripts/migrate-to-sql-shim.ts` reports 0 of 28
with nothing left for a human.

**Measured after.** Each dashboard builds in about five seconds under Bun
1.4.0 (`next build` ×2, `vite build`); installs in two to seven.
