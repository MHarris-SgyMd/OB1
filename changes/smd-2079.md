## Changelog

rest-api answers every response with the request's CORS headers, set once on the way out of the main handler — forty-seven of its answers, every route's `200` among them, said `Access-Control-Allow-Origin: null` under `CORS_ALLOWED_ORIGINS`, so the allowlist the README tells production to set left a browser client able to read `POST /search` and nothing else (SMD-2079).

## FORK

rest-api sets the request's CORS headers once, on every response the main handler returns — under an allowlist forty-seven of its answers said `Access-Control-Allow-Origin: null`, so a browser client could read the auth refusals, the preflight, the rate limit and `POST /search`, and no other route (SMD-2079)

**What changed.** `integrations/rest-api/index.ts`: the main handler is now
`route`, and the exported `handler` is one line — `withCors(req, await
route(req).catch(internalError))`. `withCors` copies the answer's headers,
sets the four CORS headers from `corsHeadersFor(req)` over them (a header of
the same name is replaced) and returns a `Response` with the same body,
status and status text. `json(data, status)` has no third argument: it sets
`Content-Type` and nothing else, and its fourteen callers that passed `req`
(SMD-2054's five among them) pass it no longer, so `checkRateLimit` and
`proxyFetchJson` lose the `req` they threaded through to it; the preflight
`204` is bare too. `internalError` is the `500` the routing `catch` built
inline, now a function, and the `handler` applies it to what escapes
`route`'s `try` — the auth and rate-limit steps stand before it, so a
failure there was an unhandled rejection, Bun's bare `500` with no headers.
`corsHeadersFor` no longer sets `Content-Type`. The README's CORS section
says every response carries the headers and names what did not.

**Why.** `json()` built the CORS headers from the request only when handed
`req`; without it, it answered `*` when `CORS_ALLOWED_ORIGINS` was unset and
`null` when it was set. Forty-seven `return json(…)` sites passed none —
every handler's `200` and most of its errors — and the handler returned
their answers untouched. So under an allowlist, the configuration the
README's Security section tells production to use, a browser client could
read the `401`, the `503`, the `OPTIONS`, the `429` and, since SMD-2054's
third review pass, `POST /search`, and no page of `GET /recent`,
`/thoughts`, `/stats` or any other route: the allowlist broke the clients it
was set for. Found by SMD-2054's third review pass, which fixed the five
answers of `/search` it was touching and filed the rest. The ticket named
the in-repo dashboard (`dashboards/open-brain-dashboard-next/lib/api.ts`)
as a browser caller; it is not — that module is `server-only`, so its
requests carry no `Origin` and read no CORS header. The defect stands for
any browser client, which the README invites.

**Held.** `extensions/test-writes.ts`, the rest-api block, under
`CORS_ALLOWED_ORIGINS` set before the module loads: with a listed `Origin`,
a page from `GET /recent`, a page from `GET /thoughts` and the `404` for an
unknown route echo the origin, and `GET /recent` answers `null` to an
unlisted one — one assertion, nine requests in flight at once beside the
`/search` arm SMD-2054 left; a second holds the preflight `204` and the
`401`, which passed the request before (controls). Against main's file with
this suite the new arm fails, `200 null / 200 null / 404 null / null`, and
the two beside it pass. 339 assertions on a throwaway Postgres under
`TZ=America/Chicago`; `extensions/test-auth.ts`, which dials this server's
`/health`; check-fork PASS. Found reading the diff, and held by nothing:
`handleExecuteJob` passed `req` as `proxyFetchJson`'s third argument, which
had been `req` and became the timeout — a `Request` there is a `NaN` timeout,
so every `POST /ingestion-jobs/:id/execute` would have aborted at once with
a `504`. Nothing typechecks the file (SMD-2080) and nothing in the suite
drives `/execute` (smart-ingest is not on this fork; the fetch fails before
or after a zero timer, so an arm would be a race). `req` is gone from that
handler too.

**Not taken.** Passing `req` on the forty-seven sites: the shape that
regresses at the next `return json(…)`. Setting the headers on the
handler's `Response` in place: a `Response` a `fetch` returned has immutable
headers, and though no route returns one today, the copy costs four lines.
A pin that `corsHeadersFor` is called from one place: nothing bypasses the
exported handler.
