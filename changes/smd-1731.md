## Changelog

Every derived artifact — a thought's chunk set, its extraction under each key, a supersession proposal, its vector, the extractor's tags — now has a lineage row in `derivations`, written in the transaction that writes the artifact: what it was computed from (the inputs and their fingerprints), by which pass, under which recipe (model, prompt version and hash, window parameters, a `deterministic` flag); the artifacts standing before the file are backfilled and marked legacy, and preflight's new `lineage` check fails on a derived row without one (SMD-1731).

## FORK

Lineage for every derived artifact, with its recipe: the `derivations` table every producer writes in its artifact's transaction — the vector by a trigger on the row store, the windows and the tags from the write's envelope, the extraction with the fingerprint it checked, the proposal with both — and preflight's lineage check (SMD-1731)

**What changed.** Migration 061 adds `derivations` — one row per derived artifact per producing pass: `artifact_kind` (chunks, entities, proposal, vector, metadata), `artifact_id` (the thought's id, or the proposal's), `input_ids` and `input_fingerprints` (parallel arrays, no NULL element), `produced_by` (the pass), `recipe` (a JSON object carrying a boolean `deterministic` — what SMD-1732's rebuild will read — and the producer's own record), `produced_at`, 010's agent — UNIQUE on (kind, artifact, pass), the unit each producer replaces; a GIN index on `input_ids` for the forward walk; no foreign key, two AFTER DELETE triggers dropping what a deleted thought or proposal keyed. One writer, `ob1_record_derivation`, validates and upserts, refusing a bad shape; `ob1_actor_agent_id` reads the agent a write named. The five producers record in their artifact's transaction: the vector by `thoughts_record_vector_lineage`, a row trigger in 060's snapshot trigger's shape (no column list, nothing under a replay, nothing when nothing moved — every writer covered, raw and vendored); the windows and the tags by the 3- and 4-argument `upsert_thought` and `update_thought` from a lineage envelope (`p_payload.lineage`; `update_thought`'s new eleventh argument `p_lineage`, the 10-argument form dropped with its ACL carried) — no envelope, no tags' row, the windows' row from the label alone marked undeclared; the extraction by `record_thought_entities`, now seven arguments (`p_recipe`), storing the fingerprint it checked — the ADR's "half a key", closed — under its own replacement rule, with an empty-pass rule (no rows standing, no row); the proposal by `record_supersession_proposal`, now eleven arguments, both fingerprints as the row takes them. `server-portable/lineage.ts` spells every recipe once — the chunk split's parameters and the blurb model, the tag extractor's model and prompt (lifted to a constant with a version), the entity extractor's and the judge's models and prompts with their hashes, a structured pass — and the server's capture and edit, the board sync, the re-embed, the extraction worker, the structure writer and the consolidation pass send them. The backfill records every artifact standing, marked `legacy: true`: every proposal (the judge key parsed where it has 029's shape), every (thought, key) pair over the mentions and edges at the thought's current fingerprint, every chunk set, every vector; the tags are not backfilled — nothing on a row says the extractor tagged it. Preflight's `lineage` check fails on a derived row without a lineage row (the kind, the count and the first ids), warns on a producer body from before 061, and reports the legacy, undeclared, stale and untagged counts, all bounded; the capture-body ladder and the edit-signature rung gain 061's rungs; the capture role gains every privilege on `derivations`.

**Why.** docs/event-log-as-truth.md makes everything off the thought row a projection with a recorded key — "the input's fingerprint and the recipe, or the rebuild cannot be incremental" — and its projections table said what each recorded: the vector the whole key, the graph half of it (the fingerprint checked and never stored), the chunks and the tags nothing. SMD-1729's rule: an event and its lineage row commit together. SMD-1732's rebuild, SMD-1734's trust and SMD-1723's forget all read this table; the two workers' `--dump` side files were the derivation record "until a lineage table holds it".

**Measured.** The backfill on a read-only copy of the dogfood brain (1,004 thoughts, 14,778 mentions and 11,724 edges under 1,392 (thought, key) pairs, 24 proposals, 24 chunk sets, 1,004 vectors; PostgreSQL 16, width 1,024): 2,444 rows in about 75 ms — the proposals 5 ms, the pairs 26 ms, the chunk sets 2 ms, the vectors 37 ms — into a 2.4 MB table; the pairs took 2.6 s in the first shape, which grouped the join by the thought's text (the build's own run-it). Preflight on the copy: `lineage` ok — 2,444 rows, every one legacy, none undeclared, none stale, 991 thoughts tagged before the file with no tag lineage — and the capture pair, the edit signature and the write privileges rows as shipped. Behaviour on a fresh PG16: the 29-check smoke (`.planning/scratch/smoke-061.sql`) at 29.

**Held.** The five bodies carry 060's, 013's, 056's and 029's verbatim plus the lineage lines; no return shape moves; every positional caller of the old arities resolves through the defaults; a replay writes no lineage; an identical re-capture, a vector refresh and a metadata-only edit move no `produced_at`; a re-apply re-seeds nothing.
