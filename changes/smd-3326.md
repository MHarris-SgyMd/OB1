## Changelog

Consolidation's decide mode reads a tier of its own: `OB1_CONSOLIDATE_DECIDER_URL`, declared local by `OB1_CONSOLIDATE_DECIDER_LOCAL` and held to the decider's model. The shared tier at `OB1_JEV_BASE_URL`, which capture's genre facet asks, can then serve another model. Unset, decide mode asks the shared tier as before. Preflight reports decide mode's tier in rows of its own (`decide tier`, `decide egress`, and `decide decision` under `--deep`). H2O-Lightning-4B's adapter runs on the host, and `jev/h2o/com.openbrain.h2o-tier.plist.example` is a LaunchAgent that keeps it running (SMD-3326).

## Record

Decide mode reads a tier of its own, and preflight reports it in rows of its own (SMD-3326)

**What changed.**
- `server-portable/jev.ts`: `resolveDecideTier` returns decide mode's tier with the knobs a message names.
  - Its own: `OB1_CONSOLIDATE_DECIDER_URL`, local by `OB1_CONSOLIDATE_DECIDER_LOCAL`, and held to `OB1_CONSOLIDATE_DECIDER`, so an answer from another model is refused.
  - Unset, the shared tier at `OB1_JEV_BASE_URL`, with `OB1_JEV_LOCAL` and `OB1_JEV_MODEL`, as before.
  - `LocalKnob` gains `OB1_CONSOLIDATE_DECIDER_LOCAL`.
- `db/consolidate.ts`: decide mode resolves its tier through it, and every message names the knobs that apply. A one-shot run's call the tier refuses (a 409 from a tier serving another model, a 404 from a URL that is not a tier) closes on the tier's knob and model, not the chat endpoint's. With neither base set, it refuses naming both. With its own tier, the shared tier's `OB1_JEV_MODEL` no longer refuses the run.
- `server-portable/preflight.ts`:
  - The jev tier's rows are now `tierRows`, run for each tier.
  - With decide mode's own tier, the shared tier is no longer held to the decider. `decide tier`, `decide egress` and `decide decision` report the own tier, with a host process's remedy: the adapter and its LaunchAgent.
  - They do so even at the shared tier's URL, since decide mode holds that tier to the decider and reads its own local declaration.
  - Decide mode's own tier down, or not answering as the tier, **warns**: only the consolidation pass asks it. Until it answers, the consolidation pass decides nothing; `jev/h2o/README.md`, "When the tier is down", says how a follower and a one-shot run each go on. Capture and search start either way. The shared tier still fails the start, since the server's capture asks it.
  - `OB1_CONSOLIDATE_DECIDER_URL` with no `OB1_CONSOLIDATE_DECIDER` warns that nothing reads it, rather than leaving the pass in judge mode without a word.
  - The shared tier held to the decider names decide mode's own tier among its remedies, and `--deep`'s skip names the tier row as it ended, warned or failed.
  - `consolidate decide mode` says which tier it asks.
- `server-portable/jev.ts`: an answer from another model names the knob that holds the tier (`OB1_CONSOLIDATE_DECIDER` in decide mode), not always `OB1_JEV_MODEL`.
- `deploy/compose.yaml`'s `x-env`, `server-portable/root.ts`'s Env, `deploy/.env.example` and `server-portable/README.md` carry the two settings.
- `jev/h2o/README.md`: a "Deploy" section, with `jev/h2o/com.openbrain.h2o-tier.plist.example` as the LaunchAgent template. It says to fetch the weights with one start by hand first, since the template starts offline, and to unset or repoint `OB1_JEV_*` when a brain moves decide mode off the shared tier.
- Three comments said the server never decides, wrong since the genre facet started calling the tier (SMD-2323): `deploy/compose.yaml`'s jev block, `deploy/.env.example`'s tier section and `server-portable/root.ts`'s Env. They now say what asks it, and `jev.ts`'s header names its two callers.

**Why.** Before this, `OB1_JEV_BASE_URL` and `OB1_JEV_MODEL` were one setting for every caller. `db/consolidate.ts` refused a model other than its decider, so H2O for decide mode and another model for the genre facet couldn't both be the stack's tier. The maintainer decided on 2026-10-26: a tier per caller.
