## Changelog

`db/tier.ts --replay` and `--diff` reach the two brains over HTTP, each at its own MCP URL or connector name with its own key, and never their databases: stable's logged searches run on both brains and the ids each returns are diffed, so no container joins both brains' networks or holds both superuser passwords for them. `--diff` keeps its exits (0 unmoved, 1 moved or a failed step, 3 nothing compared), and `deploy/tier.sh` refuses the two verbs, pointing at `bun db/tier.ts` (SMD-2875).

## FORK

Tier replay and diff over HTTP — no container reaches both brains for them (SMD-2875)

**What changed (PR 1).**
- `db/tier.ts --replay` / `--diff` take `--from <stable>` and `--to <canary>` as each brain's MCP URL or Claude Code connector name, with a key found as `--compare` finds one (`--from-key`/`--to-key`, `OB1_COMPARE_KEY`, `?key=`, the connector's header), and run `db/brain-compare.ts`'s `runTierReplay`:
  - stable's logged searches (`list_logged_searches`: the `--since` window, else the most recent page), each on the arm that ran it and each (query, arm) once, run on both brains as a client searches, and the ids the two return are diffed;
  - the report is `--compare`'s (identity, freshness, the id-set difference, retrieval), then the window and the counts, then the verdict: `what moved: nothing — <canary> returns <stable>'s ids on …`, `what moved: N of M …`, or `nothing to compare: …`;
  - `--diff` exits 0 unmoved, 1 when a ranking moved or stable's log could not be read, 3 when nothing was compared (an empty window, or every search skipped); `--replay` exits 0 unless the log could not be read; `--json` carries the verdict as `gate`;
  - a `postgres://` `--from` or `--to` is refused (exit 2), as are two verbs, a missing side, a malformed `--since` and a `--refresh` flag.
- The Postgres replay engine (`readLoggedSearches`, `replayOne`, `diffResult`, `replayAndDiff`) and the replay's own embedder and egress gate are gone from `tier.ts`; each brain now embeds its own query. `resolveBrain`'s messages name the verb and key flags they were given to.
- `deploy/tier.sh` refuses `--replay` and `--diff` (exit 2), joins only `<project>_data` by default (no `egress`: nothing it runs embeds), and no longer hands on `OPENROUTER_API_KEY`, which only the replay's embed read.
- `db/test-live.ts` [20] keeps the refresh guards and `--promote`; the replay's cases moved to `db/test-brain-compare.ts` against its fake brains. `db/test-connect.ts` no longer requires `tier.ts` to exit through `closeThenExit`, which only the replay used.
- CI: the tier step drops its Postgres `--replay`/`--diff` runs and holds tier.sh's refusal; the canary step runs `tier.ts --diff` from stable's `/mcp` to the canary's `/canary/mcp` right after the canary's first `up` (exit 0, `what moved: nothing`), and over a window after every search (exit 3), with no key in either output.
- `deploy/README.md`, `db/README.md`, `deploy/compose.tiers.yaml`, `docs/operator-surface-tiers.md` and `docs/one-brain-per-stack.md` (row 9 and "The tier tools") say how replay and diff run now, what they measure, and that tier.sh joins `data` alone.

**Why.** `deploy/tier.sh --diff` ran `tier.ts` in one container on both brains' data networks and stable's egress, with a superuser URL for each (SMD-2872's ADR, "The tier tool joins both brains"). SMD-2872 has a brain's data network joined by nothing outside its own project. Replay and diff need no database: the read surface already answers every question they ask.

**What is measured now (the maintainer's choice).** Item 2 of the ticket offered two means: split the Postgres engine across the two projects, measuring the same thing, or move onto HTTP, measuring something else. The maintainer chose HTTP:
- the canary is diffed against stable as it answers now, not against the ids stable logged when it ran the search, so a thought stable gained since the refresh can read as a move; the report's id-set line counts what each holds that the other does not;
- `list_logged_searches` gives the query and arm, so a search replays with the tool's defaults, not its logged `match_count`, threshold, recency weight or filter;
- each brain embeds the query itself, through its own server's egress gate, where the old replay embedded it in the tool's container with the settings of the env file it was given;
- the replays are real searches, which a brain logging searches logs (`--compare`'s report says so).

**Held.**
- `db/test-brain-compare.ts`, 154 cases: a canary answering as stable passes with the window and the counts; a reordered ranking moves, exit 1, named under Retrieval; `--replay` reports it and exits 0; an empty log and an empty `--since` window are exit 3, the latter offering an earlier `--since`; every search refused is exit 3, and one refused of two claims only the other; a stable without `list_logged_searches` is exit 1 on both verbs; `--json` carries the verdict and no key; the CLI end to end against the fakes; no key names the verb's own flags; the refused grammar.
- `deploy/auth/provision.ts --self-check`: tier.sh's filter hands on `OB1_TIER` and `POSTGRES_PASSWORD`, and neither `OB1_AUTH_*` nor `OPENROUTER_API_KEY`.
- `db/test-connect.ts` 852/852, check-fork-consistency, actionlint with shellcheck, the typecheck.
