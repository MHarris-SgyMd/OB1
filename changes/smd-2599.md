## Changelog

A `--follow` run of `db/extract-entities.ts` or `db/consolidate.ts` now outlasts its database going away. It says so once, checks again after 5 s, doubling to 5 min, and resumes polling when the database answers. Before this fix, a Postgres restart or stop made it exit 1, and a compose restart policy spent its tries within a second (SMD-2599).

## FORK

A `--follow` worker outlasts a database outage — it waits and resumes, where it exited 1 (SMD-2599)

**What changed.**
- **`worker-bootstrap.ts`** has three new pieces, shared by both workers:
  - `databaseUnavailable(e)` says whether an error means the database is not answering. These are Bun's `ERR_POSTGRES_CONNECTION_*`, idle and lifetime timeouts, and the server's SQLSTATE class 08, 57P01–57P03 and 53300.
  - `outageWait(step)` is the schedule: 5 s, doubling, at most 5 min.
  - `waitOut` sleeps, then checks, until the check answers or a stop wakes it. A check that fails for another reason is thrown.
- **Each worker's `followedPass()`** runs a pass. If the pass throws a database-unavailable error, the worker:
  - says so once;
  - waits until a `SELECT 1` answers;
  - says when it answers, and polls on.

  Bun's pool reconnects by itself on the next query (measured on Bun 1.4 against a restarted and a stopped Postgres), so there is no reconnect code.
- **A worker hit mid-thought**, when the write or the judge's reads fail this way, records nothing for the thought and ends.
- **Leases returned when the database is back.** A worker's leases that could not be returned as it ended are returned at the start of the next pass. They no longer wait out `--ttl` (900 s).
- **`--limit` counts the thoughts a run takes** — claimed and not handed back unfinished — and the claims in flight. A thought an outage hands back costs nothing and counts again only if claimed again; a claim that failed took nothing; a dead worker's leftover leases are returned before the run ends where the database answers.
- **SMD-2261's heartbeat** is not ended by a pass the database failed: the follower waits it out, and an ended stamp would say so for every pass after.
- **A follower stopped during the wait** exits 0, as any stopped follower does. It says that the counts were not read.
- **Any other database error** (a syntax error, a missing function, a password refused) still ends the run, a worker's claim included when no wait mends the error (`databasePermanent`: SQLSTATE class 42 or 28, a database or schema gone); a passing one (a timeout, a serialization failure) costs that worker its poll. A run without `--follow` is unchanged.

**Why.** SMD-2424's review (run-it, scratch stack `ob1-2424r1`) found that a follower did not survive these events:
- A `podman restart` of Postgres crashed one or both followers in 4 of 9 tries (`57P03`, or `ERR_POSTGRES_CONNECTION_TIMEOUT`).
- With Postgres stopped for 30 s, both followers used all of `restart: on-failure:3` in about 1 s, and stayed exited.

The cause: a database error outside a worker's own try (`counts()`, consolidate's `enqueue_thoughts`) rejected `run()`.

**Held by**
- **test-live [10]** (9 new): an extract follower reaches Postgres through `cuttableRelay` (`test-support.ts`, a TCP relay the suite cuts and restores, which also works against CI's service container).
  - A cut while it polls: it stays up and extracts the capture made meanwhile.
  - A cut while a model call is in hand: it stays up, records nothing, and returns the lease when the relay is back. The thought ends succeeded, at attempt 1.
- **test-live [16]** (1 new): the consolidate follower stays up through a cut, and settles its row after.
- **test-worker-bootstrap** (8 new): the error shapes waited on and not waited on, the schedule, and `waitOut`'s three endings.
- **Mutants**, each caught:

  | Mutant | Fails |
  |---|---|
  | extract's `followedPass` rethrows every error | test-live 5 |
  | the next pass does not return the unreturned leases | test-live 1 (the thought stays claimed) |
  | a worker hit mid-thought classifies the error as the provider's | test-live 1 (its line; the write and release fail alike) |
  | consolidate's `followedPass` rethrows every error | test-live 5 |

**Measured after.** Against a real Postgres container (not the relay), both followers stayed up through five `podman restart`s and a 60 s stop, and exited 0 on SIGINT. Of the 15 thoughts captured across the outages, 15 were extracted and 13 judged, with none failed. Each follower said "not answering" twice and "answers again" twice; most restarts passed between polls without an error.

**Not here.** These come in SMD-2599's second PR:
- provider outages: a thought back to the pool, not failed, while a one-token chat probe waits for the model;
- a missing model while it is pulled;
- a hung provider.

A follower that starts while the database is down still exits, which compose's `depends_on` covers.
