## Changelog

`evals/eval-calibration.ts` builds an outcome ledger from what the log already holds — every confidence the fork writes, beside every resolution it records — and scores each mechanism's calibration (reliability table, Brier, ECE, skill against the base rate). On the dogfood brain: the consolidation judge said 0.80 twenty-four times and the reviewer rejected all twenty-four; the entity extractor says 1.00 on all but one of 5,881 mentions and edges and nothing resolves them; the metadata model's confidence band runs backwards (`high` right 22%, `medium` 46%, skill −2.3 against a constant); no thought carries a declared confidence, so the 17 resolved hypotheses are an outcome with nothing to score. Measurable, and every mechanism that speaks is overconfident; no control loop is built (SMD-1809).

## FORK

Was the confidence earned — an outcome ledger read from the log and a calibration score per mechanism, before any control loop (SMD-1809)

**What changed.** `evals/eval-calibration.ts`. The ledger is a read model, not a
table: one row per (mechanism, claim, the confidence it carried, the outcome it
resolved to, what resolved it), built from four places the log already has —
the metadata model's kind band and the hand kind in `fixtures/thought-kinds.json`
(SMD-1951); the judge's confidence on every `supersession_proposals` row (029)
and the reviewer's accept or reject; the extractor's confidence on every
`thought_entities` and `ob1_entity_edges` row (016), which nothing in a brain
resolves; and `metadata.confidence` on a thought — a number in [0, 1], the key a
writer can set today — resolved by the fixture's hypothesis status or by being
superseded. A row with no confidence is unscored, never a 0; a row nothing has
resolved is unresolved; the report counts both, because today they are most of
the brain. Per mechanism, over the rows with both sides: the reliability table
(each stated value or band — how many, how many held), the Brier score, the
expected calibration error, and the Brier skill against the ticket's chance
baseline, a constant at the base rate. A band maps to a nominal probability
(`high` .9, `medium` .6, `low` .3) for the Brier and ECE only; the band table
does not depend on the mapping and is the measurement. A mechanism whose
confidence takes one value is flagged as constant. Mechanisms are named by the
key each producer already writes (`judge_key`, `extraction_key`) — SMD-1731's
per-run lineage would make that per prompt version, and is not needed to read
this. `--self-check` pins the arithmetic with sets whose numbers are known by
hand and the ledger rules with probes; the portable-server CI job runs it after
the thought-kinds step. `--offline` prints the fixture-only mechanisms.

**Why.** The fork writes a confidence in three places and resolves claims in
three, and nothing compared the two; the ticket's first question is whether
calibration is measurable from the existing log at all, before anything that
would act on it (decay, SMD-1736; trust, SMD-1724) is built. The census that
opened the work (2026-09-22, dogfood brain, 348 thoughts, migration 043
deployed): 24 proposals, every one at 0.80, every one rejected on 2026-09-21;
3,187 mentions at 1.00 but one, 2,540 edges all 1.00; the kind band `high` on
318 and `medium` on 24 with the hand label right on 71 and 11; no
`confidence` key on any thought; 8 `supersedes` pointers; and the 17 resolved
hypotheses (4 confirmed, 13 refuted) with no confidence on any.

**Measured.** The report on the dogfood brain, 2026-09-22 (a re-extraction

The band runs the wrong way: `high` held 22% of the time and `medium` 46%, so
the nominal mapping is not what makes the Brier bad — reversing the mapping
would not make it good either, since both bands sit under the 24% base rate on
one side and over it on the other. The judge's number is the cleanest
over-confidence event the log holds: 0.80 stated, 0 of 24 held. The
extractor's confidence is a constant, so the column 016 sorts and de-duplicates
by (`ORDER BY confidence DESC`) carries nothing; its outcome set is
`eval-entities.ts`'s labelled captures, outside any brain, where the same model's
precision is 0.68.

**The ticket's three Verify items, answered rather than run.** *The
LongMemEval knowledge-update slice:* nothing captured carries a confidence — the
metadata extractor emits none and stores none — so "does captured confidence
predict supersession" has no predictor to test; not measurable until a writer
declares one. *A calibration-adjusted read:* over a constant (0.80 × 24, 1.00 ×
5,880) every monotone re-weighting is the identity on order, so no downstream
number can move; the review queue's `ORDER BY confidence DESC, judged_at` is an
order by time. *Is any mechanism systematically over- or under-confident:*
every one that speaks is over-confident; the one under-confident cell is the
band's `medium` (0.60 stated, 46% held), and it is under-confident only
relative to a `high` that is worse.

**Held.** `bun eval-calibration.ts --self-check`: a constant 0.80 refuted 24
times is Brier 0.64 and ECE 0.80 with skill undefined; 0.70 held 7 of 10 is ECE
0, Brier 0.21, skill 0; certainty always right is Brier 0 and skill 1 against a
coin; certainty always wrong is Brier 1; bins sort by stated value and ECE
weights them by share; over twelve distinct values the bins are deciles with
1.0 in the top one; an answer with no band is a resolved claim with no
confidence, not a 0; pending is unresolved, accepted held, rejected did not; a
declared value reads as a number or numeric string in [0, 1] and nothing else;
a stated value outside [0, 1] is refused naming the claim; the summary
partitions rows and its Brier reads only the scorable ones; the report names a
constant, a distribution, and who resolved what; the committed kinds fixture
yields the band a scorable set. In CI as "Calibration ledger arithmetic".

**Not taken.** A `calibration_ledger` table — the read model answers the
measure-first question, and a table with per-run attribution is what SMD-1730's
event shape and SMD-1731's lineage are for. Splitting the lesson digests one
claim per row (the ticket's precondition) — they carry neither a confidence nor
an outcome, so nothing measured here changes; SMD-1736/1722 own the counters
that need it. A `confidence` argument on `capture_thought` — SMD-1949's
declaration axis; this reads the metadata key so a writer can start before that
lands. A knob for the band mapping — the band table is the measurement and
needs none. Running the LongMemEval slice with an invented confidence.

constant 1.00 is SMD-1982, filed beside it. SMD-1737's
fifth column is this report's per-mechanism line.

**Upstream status.** Not upstream: upstream has no proposals, no entity
