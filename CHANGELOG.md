# Changelog

All notable changes to the OB1 fork are recorded here, newest first, following
[Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/) and
[Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html).

This page is the short companion to the fork's design record — [`FORK.md`](FORK.md),
the front door, and one file per change under [`changes/`](changes/README.md): why
each change was made, what was measured, what was declined. Changes 1–103 predate
the first release; this changelog begins at the first cut. FORK.md's "Versioning"
section has the scheme and how a release is assembled from `changes/smd-NNNN.md`
fragments.

## [1.2.0] - 2026-09-25

### Added
- `thought_changes`, a read-scoped MCP tool over `thought_audit`: what changed since a time or a cursor — every capture, edit and deletion, oldest first, who made it, the thought's id, what moved and whether it now supersedes another thought — paged by a keyset cursor that never repeats a row; migration 052 adds the SQL function both stores call (SMD-1296).
- The entity extractor's rare hedge, graded blind: every mention and edge the windowed prompt wrote below 1.00 on the dogfood brain (32) and a control of 1.00 rows (32), read against the thought's text and committed as `evals/fixtures/entity-grades.json`; `eval-calibration.ts` resolves the extractor's rows by it, so its row now scores. On a mention the hedge is a signal the prompt suppresses — 0.80 was wrong 12 times in 13, the control at 1.00 right 12 in 15 — and on an edge it marks nothing useful, while 1.00 edges hold 29% of the time (SMD-1982).
- A write-path eval: twenty fictional sessions with planted facts and planted errors run through the real server with the provider scripted, four deliverables written by a fixed reader, scored as salient survival, error catch by mechanism and citation coverage, paired per mechanism (helped / hurt, McNemar); `evals/baselines.json` gains a `write_path` floor and the data-layer job a keyless gate on it (SMD-1713).
- The ingestion adapter contract: every capture source maps to a stable identity, a byte-for-byte canonical, a clean text, typed links and structured mentions (`db/ingest-contract.ts`), with a Linear adapter (`db/ingest-linear.ts` — the board sync and the ingester now render a ticket one way, autolink markup gone from the text, cross-references, parent and relations as edges, project and labels as mentions, no model call) and a Markdown/Obsidian adapter (`db/ingest-markdown.ts`, round-trip proven, lossy cases enumerated); migration 053 adds `thought_sources` (the canonical beside the thought), the `link` facet kind written as a set, `source_thought()`, and the structured-wins rule in `record_thought_entities`; `ingest-records.ts` merges metadata, clears a moved text's vector for `reembed.ts`, reports `held` for a source item another thought already is, gains a `markdown` source and a default-nothing allowlist for external content (`--allow` / `OB1_INGEST_ALLOW`; the corpus dump's scope is `linear:corpus`) (SMD-1867).
- A Linear ticket's dated sections — `## Update 2026-09-19 (board audit)`, `## Corrected 2026-09-22 — …`, any level-2 heading carrying an ISO date — become thoughts of their own from both writers: an `observation` dated by the heading, `derived_from` the ticket's row, `child_of` it, on an identity of its own (`SMD-N#<slug>`), the section's Markdown as its canonical; the ticket's text is unchanged. The contract gains `Ingested.derived`, the ingester writes the parts in the parent's run under its scope and clock, the board sync captures them beside the head row and finds them again by identity, so the two writers converge on the parts as they do on the ticket; `test-live.ts` [23] drives both orders and an edited section (SMD-2059).
- The incremental-replay spike, measured on the dogfood brain: a projection rebuild reuses every stored vector by the `(content_fingerprint, embedding_model)` key the schema records, N edits recompute exactly N, a fresh vector equals its cached one to the last bit, and a full re-embed costs minutes where a full re-extract costs hours — the event-sourcing ADR's gate opens, with the graph named as the projection whose key and cost want the discipline first (SMD-1998).
- `db/graph-centrality.ts` reads the lifecycle board-sync stamps on every synced ticket (`metadata.status_type`, `status`, `linear_updated_at`) through one rule — a per-thought weight every count sums — so `--status open|active|done` ranks the graph as the kept tickets build it and `--decay-done` weighs a completed or canceled thought 0.25; the default is every weight 1, today's counts, and the caveat that said the graph holds no status now says where the status comes from, how fresh it is, how many thoughts carry one and how many weighed in (SMD-1994).
- `brain_info`, a read-scoped MCP tool, and `GET /health` with a read or write key answer what a brain is — version and release range, the commit the image was built from, store, tier, Postgres and pgvector versions, schema version, the ledger's highest migration against the server's own, row counts, size, HNSW parameters; preflight's version, ledger and pgvector rows read the same facts, and `initialize` reports the fork's version instead of `1.0.0` (SMD-2041).
- A typed-decision tier for the Jev spikes: `jev/serve.ts` serves Verdict v1.4 (a 151M calibrated decision model) on onnxruntime under Bun behind the `ob1-jev/1` contract, `server-portable/jev.ts` calls it through the egress gate (`OB1_JEV_BASE_URL`, `OB1_JEV_MODEL`, `OB1_JEV_LOCAL`), preflight checks it when configured, and `--profile jev` runs it beside the stack; two evals measure it beside Ollama and run the entity gate against it end to end (SMD-2050).
- The writable-projection spike, prototyped on a throwaway Postgres at 053: the write functions can append the event first and project the row in the same transaction with an empty contributor delta, the existing lock-order behaviours held, read-your-writes held and the log rebuilding every row through the same projector — while a view named `thoughts` breaks the community schemas' `ADD COLUMN`, `CREATE INDEX`, `REFERENCES` and row triggers; the event-sourcing ADR's second gate opens on option 2 (SMD-1999).
- The event-sourcing decision, recorded: `thought_audit` is designated the write-side source of truth for a thought and the `thoughts` row its projection — kept as a table with its DDL surface and its three write functions, so no vendored writer changes — with the event's shape, the three verbs as a read, every projection's snapshot key, the two clocks, deletion and forgetting, and a three-step additive path from 053 written down in `docs/event-log-as-truth.md` and the steps filed (SMD-1997).
- `deploy/tier.sh` runs `db/tier.ts` (refresh, replay, diff, promote) beside a running stack. It builds `db/tier.Dockerfile`, which is Bun plus `postgresql16-client`, and runs the checkout's `tier.ts` in it on the stack's network. It takes `--from` / `--to` as `HOST[:PORT][/DB]`, builds the URLs from `POSTGRES_PASSWORD`, and reads the env file through compose so the values match the stack's. `tier.ts --refresh` refuses a `--to` that is the `--from` database. It also marks each target it resets on the database itself (`ob1.refresh_target`), and resets only a marked, tier-stamped or empty target, or an Open Brain schema holding no thoughts. So a refresh that failed partway retries, while stable, an untiered brain and another application's database are refused. `--promote` refuses the mirror cases. The deploy-stack CI job seeds a thought and a logged search, then runs a refresh, a replay, a diff, a retry and both refusals on every PR (SMD-2036).
- The thirty PostgREST-speaking recipe scripts have one decision, recorded in `docs/vendored-disposition.md`: an import becomes an adapter of the ingestion contract, a maintenance script moves onto `compat/supabase-sql`, three whose capability the core already owns retire — fifteen tickets filed under SMD-2126 — and check 24 of `scripts/check-fork-consistency.ts` holds every `rest/v1` path, supabase-py import and postgrest-js specifier in a code file under the category directories, the twenty-eight with a call site counted per file with their tickets; twenty-one READMEs say so at the top (SMD-2126).
- The entity-gate spike, measured on 201 blind-graded dogfood mentions the deterministic gate cannot judge: Verdict v1.4 behind the typed-decision tier does not beat the deterministic shape gate by the pre-registered margin (+10.1 points of balanced accuracy, 95% interval −1.0 to +21.0), under any rubric the grades were written to, and types worse than the extractor; a diagnosis, not pre-registered, shows the labels' default decides its answer and the name barely moves it; the deterministic gate ships first, with its identifier-shape rule turned into a retype to tool, since it drops code artifacts the extractor mistyped; nothing enters the extraction path (SMD-1937).
- `db/graph-centrality.ts --startable` reads the board's `blocks` / `blocked_by` link facets (migration 053) and weighs an unsettled thought whose ticket has an open blocker 0 in every count, so `--status open --startable` ranks the graph as the tickets you could start now build it; a completed or canceled blocker does not block, a Done ticket is settled rather than blocked, a parent is not blocked by its children, and without the flag every mode renders unchanged byte for byte (SMD-2061).
- Migration 055 makes the capture event carry the payload — a capture's content and a backdating writer's `created_at`, an update's key move (`content_fingerprint` before/after) — so the log alone rebuilds every thought's text; 046's diff rule, its append and 050's two stamp arms become functions the triggers call (`ob1_thought_diff`, `ob1_append_thought_event`, `ob1_actor_stamp`, `ob1_actor_stamp_kept`); `backfill_thought_payloads()` fills the capture rows written before, under the third amendment the append-only trigger allows (`ob1.audit_amend = 'payload'`: a capture row's `diff.content` and `diff.created_at` where absent, with what the log and the row derive to, nothing else); preflight's `audit events` counts the rows still waiting and names the pass; the writable-projection prototype calls the shipped rules; step 1 of `docs/event-log-as-truth.md` (SMD-2115).
- `bun db/ingest-records.ts --source items --items <file.jsonl>` (`-` for stdin) ingests ingestion-contract items a parser in any language emitted, one JSON object per line, through the pipeline's own write path; the new `db/ingest-items.ts` validates each line in the contract's terms and a malformed line refuses the whole file with its line number and field, exit 2, before any write — so the four import recipes the class decision routes onto the contract keep their parsers and need no database client (SMD-2136).
- The orchestration POC kit: `evals/eval-orchestration.ts` stands n8n, Activepieces or Windmill up beside a throwaway brain (`evals/orchestration/compose.<tool>.yaml` over `deploy/compose.yaml`), provisions the same Linear-ingestion and MCP-server workflows from files with no UI step, and verifies them against the criteria posted on the ticket; n8n and Activepieces pass, Windmill all but the MCP-client criterion, and `evals/README.md` records the footprint, the license terms and what each needed; `docs/orchestration-tool.md` decides for n8n, as an opt-in sidecar talking to the brain through MCP only, with the licence and egress gates and the rollout (SMD-1863).
- `db/graph-centrality.ts --decay-blocked` is `--startable`'s decay: an unsettled thought whose ticket has an open blocker weighs 0.25 of its lifecycle weight instead of 0, so a blocked hub sinks in the ranking rather than vanishing, and a listed one names its open blockers in a `blocked by` column (`blockers` in the JSON); the two flags are refused together, and without it every mode renders unchanged (the JSON's `options` gains `decayBlocked: false`) (SMD-2181).
- `deploy/canary.sh up` stands a canary brain beside a running stack in one command, and re-running it brings the canary level with stable again. It runs `deploy/compose.yaml` again as the project `open-brain-canary`, with its own Postgres, volume, network and images. The server is built from the checkout and listens on `127.0.0.1:8011` with `OB1_TIER=canary`. `up` stamps an untiered stable `tier=stable`, refreshes the canary from it through `deploy/tier.sh`, and runs a smoke test that includes the vector arm. `--connect` registers the Claude Code connector. `down [--volumes]` removes that project alone and deregisters the connector (SMD-2038). `tier.ts --refresh` now copies the source's database-level settings, which the dump leaves out, onto the target. That includes migration 014's HNSW bounds, so a refreshed brain no longer walks at pgvector's defaults (SMD-2037).

### Changed
- The session capture hook fires at checkpoints: `--print-hook claude-code` prints `PreCompact` beside `SessionEnd`, and a summary captured before a compaction carries a `Checkpoint:` line that the session's end drops as it supersedes it (SMD-2012).
- The vendored servers are Bun-native: the 22 on the SQL shim and the Kubernetes deployment read `process.env` and end in `export default { port, fetch }`, the shape `bun <file>` serves; `compat/deno-on-bun.ts`, the polyfill for `Deno.env.get` and `Deno.serve`, is gone; the two recipe scripts on Deno's file, argument and exit APIs run under `bun`; and check 11 refuses `Deno` anywhere under the category directories save the seven Edge Function files still on Deno's edge runtime (SMD-1799).
- The corpus dump and the board sync write one Linear ticket row: `evals/build-linear-corpus.ts` carries each issue as the API gave it (`issue`, the adapter's `ISSUE_FIELDS`) and the build instant (`fetchedAt`), `db/ingest-records.ts --linear` maps it through the same Linear adapter the sync uses, and a record older than the row's watermark (`linear_updated_at`) — or at an equal watermark, older than the row's last write — is `stale` and writes nothing, so run in either order the second writer finds nothing to write; `test-live.ts` [22] drives both orders and a rename over the real store; a dump without `issue` is refused with the rebuild command (SMD-1958).
- Entity extraction streams every budgeted call's answer and aborts the call the moment the answer holds three copies of one item — the loop the runaways were measured to be, visible on the stream long before the answer budget — then retries under the penalty as a cut call is; on the fork's 32 stragglers a runaway is aborted a median 21 s into its call where it ran to its budget, the pass measured 1,796 s against 3,158 with a median 50 s per thought against 108 and 31 of 32 extracting — the 32nd extracts on a re-run under the shipped retry rule, so 32 of 32 is derived, not re-measured whole — and an answer that enumerates distinct ids is not a loop by the rule and still runs to the budget, which stays the bound; the penalised retry is read whole, since a penalised answer was measured to repeat an item three times and recover (SMD-1960).
- FORK.md's generated index lists the numbered changes alone and says in one fixed sentence that the `changes/smd-*.md` files are what has landed since the last release, so a PR that adds a fragment no longer edits FORK.md and a merge of `main` no longer conflicts on the index's fragments line; check 15 compares the block that renders from the numbered files, which a fragment never moves (SMD-2084).
- The SvelteKit dashboard (`dashboards/open-brain-dashboard`) signs in with one of the server's own access keys — sealed into an httpOnly cookie, forwarded as `x-brain-key` on every call — in place of a Supabase email/password sign-in, so no Supabase project, user table or anon key is needed and a read key gets a read-only dashboard; the two Next dashboards' examples point at the Bun-served `open-brain-rest` gateway; CI builds all three dashboards and drives the SvelteKit one against the compose stack (SMD-1801).
- The docs and the repo rule are off Supabase: CLAUDE.md's guard rail reads "remote over HTTP, never stdio" and names no host, `primitives/deploy-edge-function` is `primitives/deploy-remote-mcp` (the `bun <file>` run, an access key, TLS in front), every deploy section under the category directories runs its server that way and points at it, and `docs/01-getting-started.md` walks the compose stack in `SETUP.md` instead of a supabase.com project (SMD-1802).
- The fourteen extension and recipe SQL files that needed Supabase apply to plain Postgres: their `auth.uid()` policies, GRANTs to `service_role` and `authenticated`, the `REFERENCES auth.users` and the `EXECUTE 'GRANT …'` strings are gone, each cut left with a note; `migrate.ts --grant` gains `extensions` and `recipes` groups (48 tables, 15 views — lint-sweep's seven included); check 12 walks every `.sql` under db/ and the seven category directories; test-schema [50], test-live [18] and the extension tools suite apply the files with no stub and no Supabase role; the READMEs stop telling users to create `auth.*` functions first (SMD-1810).
- Fork Checks' "Schema migrations" job runs `test-schema.ts` at the default embedding width and at 768 side by side in one step, where it ran them one after the other; each run writes its own log, both are printed (a failing one open, under an error annotation), and the step fails when either run does (SMD-2092).
- The session capture hook captures one thought per episode of a session, not one per session: a transcript is cut at compactions, at moves to another branch or checkout and at new tickets, and each piece is summarised, sourced and superseded on its own (SMD-2013).
- `db/test-schema.ts` loads its three large match_thoughts fixtures ([8c], [8d], [8e]) with the walk's HNSW index dropped and builds it again afterwards, and drops it for [8e]'s emptied band. At the default width those sections take 14 s where they took 70 s, and a run takes 25 s where it took 81 s (SMD-2097).
- The session capture hook can have a local model write its summary — what was decided, what is open, what changed — instead of the derived log entry: opt-in, through the hook's own egress gate, falling back to the derived text on any failure. `capture_thought` gains an optional `metadata` argument so the summary records which model wrote it (SMD-2014).
- `db/test-live.ts` stops waiting on clocks it does not test. The deadlocks [6d], [6f], [6g] and [6i] provoke are found in 50 ms instead of Postgres's default second. [8]'s lease expiries move the deadlines back instead of sleeping them out. [9]'s stub is slow only for the runs that need it, for as long as they need it. On CI the first two took 35 s off those sections (the step 188 → 144–163 s); [9]'s cut takes about 30 s off that section: 49.3 → 17.9 s locally, its two slowed runs 40.6 → 10.4–10.8 s in CI-shaped containers (SMD-2135).
- The server's `capture_thought` refusals now carry a machine-readable code in the MCP result's `structuredContent` — `{ code, retryable, positions? }` — and the session capture hook reads it instead of parsing the server's English, falling back to the prose for a brain from before this change (SMD-1978).
- The session-capture hook blanks a secret it finds in a summary to `[redacted:<reason>]` and sends the rest, where a hit refused the whole episode — one real key in a long session cost the session its memory; the blanked text is scanned again and refused if anything remains, `OB1_CAPTURE_ON_SECRET=refuse` restores the refusal for every hit, and a rule that names a value blanks the value alone (SMD-2127).
- The egress gate no longer judges a `capture_thought` capture on its `source`: that `source` is the caller's claim (`mcp` when omitted), so a `source:` term could be dodged by naming another label or none. The handler now keeps the claim off the gate's subject entirely. A `source:` term gates a row's OWN stored label — the value the server wrote, read at an edit and at the re-embed and consolidation passes, and on `db/sync-linear.ts`'s authoritative captures — and who may capture is gated by `actor:`, which the key proves (SMD-1941).

- `recipes/obsidian-vault-import` is gone: the Markdown adapter of the ingestion contract (`db/ingest-markdown.ts` — `bun db/ingest-records.ts --url … --source markdown --markdown /path/to/vault --allow /path/to/vault`, then `bun db/reembed.ts --url …` with the embedding model declared) is the fork's Obsidian import, so the root README row points at it, the connector registry and check 24's exception table lose their rows, and the recipe's heading split with LLM distillation, its filters, secret scan, sync log and source label go with it, the ones worth having filed on the adapter's ticket and the connector's — each named (SMD-2137).

### Fixed
- Preflight dials a model endpoint whose hostname is local once on every start — `GET /models`, no credential, 2.5 s — and the container refuses to start on one that answers nothing, naming by the name's kind the profile, the host aliases or the stack's own service as the way out; until now an address that reached nothing was `preflight OK` and the first capture failed in 7 ms. `deploy/compose.yaml` gives the server `host.docker.internal` on Linux Docker, and CI's full-stack job holds both directions on every PR (SMD-1875).
- enhanced-mcp's three search tools find thoughts on this fork: `brain_search_thoughts` (both modes) and `search_thoughts_text` hand `match_thoughts` and `search_thoughts_text` the caller's `metadata_filter` alone — the `exclude_restricted` and date keys they folded into it were read as a metadata containment no thought satisfies, so every search answered no matches — and apply the restricted tier (by the column, looked up by id in semantic mode, where `match_thoughts` returns none) and the date bounds to the rows (SMD-1986).
- Three vendored MCP servers — `delete-thought-mcp`, `update-thought-mcp`, `enhanced-mcp` — admit `mcp-protocol-version` and `last-event-id` in `Access-Control-Allow-Headers`, the two headers the Streamable HTTP spec has a client send after initialize, so a browser-hosted client is no longer refused at preflight; `extensions/test-auth.ts` holds every MCP server that publishes an allow-list to naming both (SMD-1668).
- The agent-registry lookup no longer waits on a lock without limit: on the SQL store each of `resolve_agent`'s lock waits is capped at 250 ms (a ceiling — a stricter setting is kept) and a lookup that times out is retried for up to 2 s with no connection held, so a brief migration lock is still waited out while a long one no longer holds pool connections until it clears. A key the lookup still cannot confirm is refused with a retry (JSON-RPC error `-32003`; `/health` answers `ok`) rather than served, since the registry could still say revoked, and a revocation the server has already read stands through any failure until the registry answers otherwise (SMD-2072).
- The session capture hook lets a checkpoint's post land before the session's end posts, so the end supersedes the checkpoint instead of standing beside it (SMD-2035).
- rest-api answers every response with the request's CORS headers, set once on the way out of the main handler — forty-five of its sixty-two answers, every other route's `200` among them, said `Access-Control-Allow-Origin: null` under `CORS_ALLOWED_ORIGINS`, so the allowlist the README tells production to set left a browser client able to read `POST /search` and little else; an unlisted origin now gets no allow-origin header, where the literal `null` matched a sandboxed iframe's or a `data:` document's own `Origin: null`; `Retry-After` is exposed, and the preflight `204` carries no `Content-Type` (SMD-2079).
- `resolve_agent` writes a key's row only when `last_used_at` is NULL, over five minutes old or in the future, or the presented scope changed, so a lookup of a recently used key no longer waits on a transaction holding that row; `last_used_at` now means the last use to within five minutes. A revocation that commits while a lookup's write waits on it — or before a registration writes over a row another transaction inserted — is now answered REVOKED, where the lookup answered ok and the server kept that answer for its cache TTL; under a REPEATABLE READ or SERIALIZABLE default the server retries the serialization failure instead of serving the key by name (migration 054, SMD-2090).
- rest-api's `POST /ingest` and `POST /ingestion-jobs/:id/execute` proxy to the smart-ingest server at `SMART_INGEST_URL` — its root and `/execute` — and answer `503 smart_ingest_not_configured` naming the variable when it is unset; smart-ingest's extraction trigger after a write POSTs to `ENTITY_EXTRACTION_WORKER_URL`, and is skipped when that is unset. Both built the URL from `SUPABASE_URL`, the Postgres connection string on this fork, so every call handed `fetch()` the database credentials and failed — the proxy with `502 upstream_unreachable`, the trigger silently inside its timeout. An address under any scheme but `http`/`https` is refused when the server starts, the message naming the variable and the scheme and none of the value. smart-ingest reads the fork's UUID as the written thought's id, where it reported every add failed and so never triggered; the wiki compiler's `${OPEN_BRAIN_URL}/functions/v1/…` fallback is gone (SMD-2110).
- smart-ingest writes a thought through the fork's 3-argument `upsert_thought` — the vector as `p_embedding`, its model's label and the actor in the envelope, the enhanced columns beside it — where it called upstream's 2-argument form with the vector inside the payload, which the fork's function does not read, so every thought the server wrote had no vector, no label and none of the enhanced columns; `schemas/smart-ingest`'s `matched_thought_id` and `result_thought_id` are `uuid`, as `thoughts.id` is here, and `append_thought_evidence` takes one — against `bigint`, no item of a job with a match was ever persisted and no executed item recorded its thought; a revision sets the row's `supersedes` (SMD-2128).
- The entity extractor's output no longer stores a migration number, a port, an address or a type word as an entity, and a person or place that is an identifier — a ticket id, a package, a URL, a host:port, and for a place a host, a file or a branch glob — is stored as a project or a tool instead; migration 056 applies the rule at `record_thought_entities` for every extraction and once over the rows already written (on the dogfood brain: 116 entities refused, 8 moved and 4 merged into the entity of their new type; the counts are kept in `ob1_config` under `entity_name_gate_056`). A name a structured source states (a Linear label), or an entity a human curated with `merge_entities`, is not judged. The capture-time `people` facet drops a name the rule does not keep as a person, so a package name or a ticket id is no longer a person (SMD-1935).
- A role set up by `migrate.ts --grant` can run entity extraction, a structured pass, `merge_entities` and a merging `apply_entity_type_gate()`: the **extraction** group grants `UPDATE` on `thought_entities` and `ob1_entity_edges`, which `record_thought_entities` has upserted since migration 053, and a new **structure** group grants a structured pass its source row (`thought_sources`) and its `link` facets. Before, each failed under such a role with `permission denied` — every extraction since 053, every structured pass (053 added them with no grant), `merge_entities` since 016, and the gate wherever a retype merged (SMD-2216).

### Security
- rest-api's `POST /search` no longer returns restricted thoughts in semantic mode — its row filter compared a `sensitivity_tier` that `match_thoughts` never returns — and answers in text mode, where it sent `exclude_restricted: true` as a metadata containment no thought satisfies; both modes now read the tier by the column and apply the date bounds to the rows as instants; `GET /recent`, which filtered no tier at all, takes `exclude_restricted` (default `true`) as its siblings do (SMD-2054).
- Both workflows name their runner image, `ubuntu-24.04`, where they had `ubuntu-latest`, which GitHub moves to Ubuntu 26 from 2026-10-19. Every action is pinned to a full commit SHA with its tag in a trailing comment, where it had a tag its owner could move (the release job runs its actions with `packages: write`), and at its latest release, all on Node 24. The two images the release job's actions start, QEMU's binfmt and the BuildKit builder that pushes to GHCR, are pinned by digest, and no checkout leaves the job token in the workspace (`persist-credentials: false`). `.github/dependabot.yml` moves the pins weekly, a week after a release, and check 23 refuses a tag, a SHA with no tag comment, or a `-latest` runner (SMD-2093).

## [1.1.0] - 2026-09-23

### Added
- `evals/eval-calibration.ts` builds an outcome ledger from what the log already holds — every confidence the fork writes, beside every resolution it records — and scores each mechanism's calibration (reliability table, Brier, ECE, skill against the base rate). On the dogfood brain: the consolidation judge said 0.80 twenty-four times and the reviewer declined all twenty-four; the entity extractor said 1.00 on every mention and edge but one at the census, and the re-extraction running since emits 0.80 or 0.90 on under 1% — nothing resolves any of them; the metadata model's confidence band runs backwards (`high` right 22%, `medium` 46%, skill −2.3 against a constant); no thought carries a declared confidence, so the 17 resolved hypotheses are an outcome with nothing to score. Measurable, and every mechanism that speaks is overconfident; no control loop is built (SMD-1809).
- A capture-only key scope: a key that may call `capture_thought` and nothing else, for a session-end hook or an import pipeline whose credential sits in a config file; `capture_thought` takes a `source` label; migration 049 lets the agent registry record the scope (SMD-1298).
